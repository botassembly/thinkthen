# 0261: Pack Go and C++ source with one matching C archive

Status: complete. Fresh independent code review accepted `0623703b`; the coordinator integrated the local pilot. The original Go/C++ release issues remain open for final pin, runner and distribution evidence.

## Outcome and retained behavior

One local Linux x86-64 packaging invocation produces the existing versioned C archive and versioned Go and C++ source archives from one clean commit. Each source archive names the exact C archive SHA-256 it requires. A fresh isolated Go module consumer and a CMake `find_package` consumer use only unpacked source and that unpacked C archive, make successful counted loopback calls, and refuse a missing, tampered or mismatched file before they run. Keep the current `libraries/{go,cpp}/check.sh` source gates, header-derived export comparison, exact request-body fixtures, public type corpus, Go thread/error ownership and C++ parser/CMake regressions. The C header, shared library and static library travel together in the existing relocatable C archive. A local pilot does not close either release issue or claim a release-runner, registry, other target or final tag.

Use the existing `release-pack` archive/checksum helpers, `release-smoke` file scan and verdict, `installed.sh` scratch/unpack rules, and product consumer fixtures. One private, independently callable pair preflight may hold the shared file checks; the actual smoke must call that same preflight before either wrapper check. Add no product command, public runtime ABI query, test-only C export, shared framework or ADR. The [preflight](../records/0261-go-cpp-release-preflight.md) names current call paths, source inventories and the proof boundary.

## File and identity contract

`release-pack TARGET OUT c go cpp` is the explicit pilot route. It builds `part_c` once in non-reuse mode and requires that part in the same invocation before either wrapper part. Keep the existing default part list and `--reuse` behavior for established surfaces; `--reuse` refuses Go/C++ parts until a later reviewed source receipt can establish freshness of reused C bytes. A preexisting file in OUT cannot satisfy the pilot's C prerequisite. Require a clean committed tree for the same-source claim and record `git rev-parse HEAD`, host target, versions, tool versions, build command and all three outer hashes. The C build includes engine dependencies; comparing only the header or `libraries/c/` cannot establish the archive's source pin.

The final evidence commit follows the package build. The pair preflight compares one exact source-commit value across the two wrapper manifests, the archive names, target, version and C digest. It does not claim that a later checkout HEAD built the archives. The clean-commit non-reuse pack command and its recorded source SHA establish that provenance. Later source changes require another package build for a release-pin qualification.

Name the new files `thinkthen-go-$V-$TARGET.tar.gz` and `thinkthen-cpp-$V-$TARGET.tar.gz` beside the existing `thinkthen-c-$V-$TARGET.tar.gz`, each with the packer's adjacent `.sha256`. The Go archive contains the integrated `LICENSE`, `README.md`, `go.mod`, `thinkthen.go`, its two public-package test files and `examples/decide/main.go`. The C++ archive contains the integrated `LICENSE`, `README.md`, `CMakeLists.txt`, `cmake/ThinkThenCppConfig.cmake.in`, `include/thinkthen/{door,json}.hpp`. Curated gate fixtures stay in the checkout and are copied only into isolated test scratch. Each wrapper archive adds a small strict text manifest with the source commit, target, version, C archive basename and SHA-256. The packer computes this from the C file just made in the same invocation; it never accepts a caller-supplied digest. The private `sdlc/scripts/release-go-cpp-pair DIR` preflight derives `$V` and `$TARGET` from the checked checkout and host. It verifies every outer `.sha256`, the exact manifest fields, equal Go/C++ source commit and C digest, and the SHA-256 of the actual C archive before unpacking a consumer. It reads manifest bytes as fixed data, never sources or evaluates them. It rejects duplicate or malformed manifests and wrong target/version. The actual `release-smoke DIR` calls this same preflight once before it starts either wrapper consumer. This binds package files together; it is not a cryptographic signature or a runtime ABI handshake. Source provenance comes from the clean-commit build receipt and reviewed commands.

Teach `release-smoke` the two new filename patterns before its general command pattern. If either wrapper is present, call the pair preflight before the archive loop and require exactly one expected Go, one expected C++ and one expected C archive for the selected `$V/$TARGET`, plus exactly their three adjacent checksum files. Refuse any duplicate or extra `thinkthen-{go,cpp,c}-*.tar.gz` or family checksum entry, including another target/version, before any wrapper consumer starts. Keep the existing nine-family full-bundle presence requirements unchanged; a three-file directory is not a passing `release-smoke` bundle. The bounded pilot invokes the same pair preflight directly on its three-file output, then its installed Go/C++ selectors. A later full-bundle smoke uses that preflight unchanged. Go/C++ remain conditional in smoke until a separate workflow ticket promotes them to unconditional release requirements.

## Installed consumer route and exact claims

In installed-file mode only, `libraries/go/check.sh` and `libraries/cpp/check.sh` take their wrapper artifact plus the validated C archive path supplied by the smoke runner. They do not rebuild C, copy wrapper source from the checkout, or search a previous `target/` installation. The Go fixture copies the unpacked module into an unrelated consumer tree, points cgo at the C archive's own `include` and `lib/pkgconfig`, tests shared and static-C linking, and runs its external-module example. The C++ fixture configures and installs the unpacked CMake source with `THINKTHEN_C_HEADER`, `THINKTHEN_NATIVE_SHARED` and `THINKTHEN_NATIVE_STATIC` pointing into that same C archive; it compiles and runs fresh shared/static `find_package` consumers. Check the installed header's declarations against the unpacked shared library's exports using the existing port ABI helpers, and compare every installed header/library byte to its C archive member. C++ must prove shared loading from the fresh prefix and static-C independence from `libthinkthen.so.0`; Go's static-C mode does not claim a fully static executable.

The minimal positive proof is one public Go external-module call and one C++ `find_package` call with exact expected output, one independently counted loopback request and its accepted complete body per route, after both load the unpacked native bytes. Retain the existing 39-body Go and 16-body C++ matrices, 55-schema/29-applicable-case corpus, cancellation and parser plants in the unchanged source gates; repeat a larger matrix only if an installed-input change invalidates those receipts. Record source commit, all three archive hashes, unpacked C member hashes, tool versions, each consumer executable path, exit, stdout/stderr and backend count/body. No paid call or stress run.

The exact passing baseline is the three-file non-reuse pack output: `sh sdlc/scripts/release-go-cpp-pair OUT` exits 0 after finding the three expected archives and their three checksum files, and the two installed selectors then pass. Each negative plant copies that passing OUT and invokes the same preflight before either selector: remove C++ and its checksum for a named missing-C++ refusal; change one Go archive byte but retain its checksum for an outer checksum refusal; substitute a separately valid C archive and checksum with a different SHA for the wrapper-to-C digest refusal. Record the preflight exit and diagnostic, and assert zero Go/C++ consumer starts and zero loopback sends for each plant. Add one focused duplicate/extra-family inventory plant because exact cardinality is a separate boundary; it too fails before a consumer starts. A wrong header inside a changed C archive is the same mismatched-file boundary; the existing derived export and byte comparisons remain the independent ABI check. Do not manufacture an ABI identity that the runtime does not expose.

## What the build taught us

The clean non-reuse pack at `d4609b0b` produced all three archives and exact C-digest manifests; the shared three-file preflight and installed Go/C++ calls passed. The installed checks needed `-buildvcs=false` for a Go consumer outside a Git checkout and separate Go build and C++ answer caches to make the static witnesses and counted calls independent. A preflight that tied manifests to the current checkout HEAD would have invalidated the packages after this evidence commit or an unrelated later commit. The final checker instead validates the bundle's matching fixed-data source field, target, version, archive names, outer hashes and C digest; the clean build receipt pins the source that produced the files. The default full smoke still requires nine older families. Ticket 0261 proves its bounded three-file route and does not complete the original release issues.
