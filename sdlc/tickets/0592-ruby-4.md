## Outcome

`gem install thinkthen` installs a working native gem on Ruby 3.4 and Ruby 4.0 on every shipped Ruby platform.

## Evidence

- Ian, 2026-10-15: "Definitely Ruby 4." Ruby 4.0 was released in December 2025.
- Starts from `ticket/0543-final`. `libraries/ruby/thinkthen.gemspec` sets the native gem to `>= 3.4, < 4` ("Built and tested on 3.4 only. 4.x is another ABI.") and packs one `lib/thinkthen/thinkthen.DLEXT`; `lib/thinkthen.rb` loads it with `require_relative "thinkthen/thinkthen"`. Ruby 4.0 users get the fallback gem, whose `fallback/lib/thinkthen.rb` raises `LoadError` naming `>= 3.4, < 4`.
- One Ruby is pinned: `libraries/ruby/toolchain.env` (3.4.11), built by `setup-ruby.sh` and required by `check.sh`. `build.sh` compiles once with the `RUBY` that `check.sh`, `sdlc/scripts/release-container` (Linux) or `.github/workflows/release.yml` (macOS) exports. `sdlc/scripts/release-pack` `part_ruby` calls `build.sh`.
- `.github/workflows/install-check.yml` runs the `rubygems` channel on `ruby-version: '3.4.11'` only. `libraries/ruby/tests/test_package.rb` pins the 3.4 range and the fallback sentence. The site says "Ruby 3.4." in `site/src/data/catalog.mjs`, and `libraries/ruby/README-DEVELOPMENT.md` says the gem supports Ruby 3.4.
- `libraries/ruby/Cargo.toml` pins `magnus = "=0.7.1"` and `rb-sys = "=0.9.130"` in the Ruby surface's own lock, `libraries/ruby/Cargo.lock`. rb-sys 0.9.130 carries Ruby 4.0 bindings (`stable_api/ruby_4_0.rs`). Magnus 0.7.1 (June 2024) sets no upper Ruby bound but predates Ruby 4.0 and is unproven there. Magnus issue 173 reports magnus 0.8.2 building on Ruby 4.0 once rb-sys was current; magnus 0.9.0 (September 2026) states Ruby 4.0 support and drops Ruby 2.7 and 3.0. No local Ruby 4.0 exists yet, so the first build decides.
- 0543 depends on this ticket.

## Decisions

- PM decision, 2026-10-15: ship one native gem per platform that loads on Ruby 3.4 and 4.0, using the usual precompiled layout with one extension per Ruby minor version (`lib/thinkthen/3.4/` and `lib/thinkthen/4.0/`, chosen by `RUBY_VERSION` in `lib/thinkthen.rb`), and set `required_ruby_version` to `>= 3.4, < 4.1`.
- PM decision, 2026-10-15: build first against magnus 0.7.1. If it fails on Ruby 4.0, take the oldest magnus release that builds on both 3.4 and 4.0, with the rb-sys it needs, and keep the Ruby API unchanged.
- PM decision, 2026-10-15: pin the current Ruby 4.0 patch release beside 3.4.11 in `toolchain.env`, with its source hash, as 3.4.11 is pinned.
- PM decision, 2026-10-15: the fallback gem message names both supported Ruby versions.

- Checklist:
  1. Set up both pinned Rubies; `build.sh` compiles the extension once per Ruby, into separate Cargo target folders, and packs both into each platform gem.
  2. Run the installed Ruby check on 3.4 and 4.0; the routine profile runs 4.0, the release suite runs both. The published-install `rubygems` channel runs on both.

- Keeps: the Ruby API and every result shape, unchanged on both versions.

`libraries/ruby/check.sh` passes on Ruby 3.4.11 and the pinned Ruby 4.0 patch release, and the rehearsal's platform gem installs and runs on both.
