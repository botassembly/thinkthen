# 0239: Finish frame batching and call facts

Status: COMPLETE.

Opened as: 2026-10-11. for B13a and B13b.** Fresh Medium code/API review accepted corrected `0e150a2bd8ede4d4ccb07ce6ccbeb83237b9cb77`. ## Starts from

The [batching design](../issues/closed/2026-09-26-batching-design.md) says a Polars or pandas column is one library call, forms batches within that call, takes the library's eligible batch/context controls, and returns call-scoped facts. [ADR 0089](../planning/adr/0089-rust-calls-carry-facts.md) settles `Call<T>` for eager Rust results and final `Batch::facts()` after join. Landed 0212 and 0216 already plan and schedule Rust fixed-question and annotate batches; 0209 already gives typed frame columns and separate nested failure cells. Landed Python 0214 already carries `Call.value/facts/details` through column/frame reconstruction and prompt cancellation; 0233 retains label and question grammar. Quick Fix `069fe2c9` kept a legacy per-record frame fixture at explicit batch one while leaving the distinct default-Max proof in place. Do not create another planner, JSON grammar, result writer, observer history or Rust receipt API.

## Keeps

- The Rust `PolarsEngine` methods keep their existing Polars `Series` or `DataFrame` **inside** the returned value, preserving names, dtypes, caller columns, original order, nullable decide/choose and numeric score, successful empty tag versus failed null, fixed-field nested `failed` Struct and typed empty frames. A nontext/null Series, missing `on`, result-name collision or invalid set remains a pre-send Usage refusal. A started backend failure still emits one terminal error after worker join with its final facts. The borrowed `CallOptions::observe` callback still runs on the caller thread; no second retained details vector enters Rust.
- `CallOptions::batch` overrides engine/environment, then a loaded decide question's saved `batch` or an annotate set's top-level saved `batch`, then Max. Default Max, content/size/profile cuts, duplicate sharing, 413 handling, exact singleton bytes and request digest, request/token shares, context digest and ordered stop come from the existing planners. Eligible `decide_series` may take shared context; choose/score/tag Series and `annotate_frame` still refuse it through `annotate_with`. An ordinary runtime profile constrains packing. A saved calibration profile on a decide Series keeps its accepted digest/warning; a profiled choose/score/tag question cannot become a one-member set and keeps 0203's pre-send refusal. A question-set profile belongs at the top of the set, not a member. Do not silently drop a saved name or treat explicit description null as absent.
- Python's existing `Call.value` carries pandas Series/DataFrame with original index/name and typed `failed` cells. The pandas 2 fallback and pandas 3 Arrow path keep their 0122/0209 ownership and no runtime pandas or Polars import. Python Polars remains `thinkthen[polars]`; Rust Polars remains an optional crate feature. Preserve 0214's returned-error facts and completion receipt behavior without copying a receipt into Rust.

## Changes

1. Fix the one **shared annotate batch selection** in `crates/thinkthen/src/public/bulk.rs::annotate_with`: typed `CallOptions::batch`, then engine/environment setting, then `questions.0.batch()`, then Max. The core `QuestionSet` already stores the top-level JSON value and exposes `batch()`; use `core::Setting::of_json` only when that saved tier is selected. A selected invalid value returns Usage with the existing question-set shape sentence before a send. A present invalid saved value must not invalidate a call whose typed or engine setting outranks it, matching the established CLI annotate tier case. Keep the set's original JSON grammar and question digest unchanged. This single correction reaches both Rust `annotate_frame` and Python pandas `annotate(on=...)`, and also the public list annotation path; it adds no host scheduler or parser.
2. Make the five public `PolarsEngine` methods return `Result<Call<Series>, Error>` or `Result<Call<DataFrame>, Error>`. Use the existing `Batch` returned by `decide_many_with` or `annotate_with`, consume it fully on success, read its terminal `Facts` once, then convert the rows. A small private frame helper may make `Call<Vec<_>>` from that successful exhausted batch; it must use the existing crate-private `Call::new`, `Call::map`/`try_map` and `Error::with_facts`, not widen a public constructor. A failed batch returns its original error and final facts after join; an impossible missing terminal account is a safe Defect, never invented zero facts. `try_map` attaches the frozen facts to an actual post-accounting conversion error. Keep pre-validation outside that wrapper, so a genuine pre-call refusal has no fabricated account. An empty valid column exhausts with `records=0`, `requests_sent=0` and the already typed empty value. One Polars invocation stays one call, even if its planner sends several requests; never subtract process `Engine::usage()` or aggregate independent calls.
3. Migrate every direct Rust Polars trait consumer to `.value()` or `.into_value()` as appropriate. Update the trait rustdoc, `libraries/polars/README.md`, the four required-feature targets and the optional-feature compile route together. `Call` is the accepted public spelling; the wrapper changes neither Polars' pinned version nor the base library dependency graph. Search direct consumers again at implementation time, including copied or marketing-owned examples. Route any site file to its owner rather than editing it under this claim.
4. Add one bounded Python pandas listener table, with no new host scheduler/carrier unless it reveals a real defect. For both pinned pandas 2 and 3, compare a three-row Series under default Max and explicit batch one by actual captured request bodies/counts, values, original index/name, `Call.facts` and ordered details. Exercise one eligible decide context and pin changed request identity; refuse unsupported context without a send. In the same chosen listener, check an `annotate(on=...)` frame's single invocation, default packing, saved-set `batch:1`, and typed/engine overrides, original columns/index, answered/null/failed cells and final facts including a suppressed or failed logical answer. Keep existing null-input, empty frame, ownership, release, cancellation and all-column parity cases; add only the distinct boundary assertions missing from them. A saved profiled non-decide column retains its already accepted no-send Usage refusal; do not recast it as a missing context or batch selector.
