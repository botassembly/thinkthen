# 0110: Port the DuckDB surface

Status: amended after acceptance; confirmation pending. Owner: Claude.

## Outcome and authority

Port the core DuckDB extension from tag `surfaces-wave7-frozen-2026-09-24b` (`9df8bae9`) onto the public Rust API as the unpublished crate `thinkthen-duckdb` at `databases/duckdb`, in its own Cargo workspace. The loaded extension keeps eleven SQL names: `thinkthen_decide`, `thinkthen_probability`, `thinkthen_choose`, `thinkthen_score`, `thinkthen_tag`, `thinkthen_annotate`, `thinkthen_details`, `thinkthen_usage`, `thinkthen_warm`, `thinkthen_recognize`, and `thinkthen_relations`. `WHERE`, `ORDER BY`, and `LIMIT` stay the filter, rank, and find verbs. Every call reaches the real engine through `thinkthen`. Ticket 0118 adds `thinkthen_relate` on the caller's database on top of this crate. Queue item 3 of `sdlc/planning/one-line-plan-2026-09-24.md` lists DuckDB after Python and TypeScript.

Draft ADR 0047 (on the 0093 branch until 0093 lands) fixes the crate's place and its checklist. Ticket 0093 sets the workspace, lint, ratchet, and surface-rung pattern. Ticket 0095 fixes the members this binding calls. Section 3.2 of `sdlc/planning/surfaces-port-guide.md` gives the port map, and its "Shared rules" bind this ticket. Accepted ticket 0105 is the template for this ticket's shape. The 2026-09-24 design review (`sdlc/records/2026-09-24-design-review-0110.md`) found ten items. This version answers all ten. Ian ruled the split into 0110 and 0118. Ian can overturn every other decision here.

## Design and decisions

1. **Two tickets.** Ian ruled on 2026-09-24 that the port splits at the relate seam, as review finding 2 proposed. This ticket keeps the extension core: scalars, questions and `@file`, SIGINT and the interrupt predicate, warm, usage, details, recognize, relations, errors and the guard, `check.sh`, deny, lints, and conformance. Ticket 0118 takes relate on the caller's database: the kept connections, the registry, the identity probe, the reaper, the relate guard, relate from rows, the queue-wait message, the SIGINT bridge thread, and cases 51 and 52. Each ticket owns its rows, budget, and red-green record.
2. **Names.** The package is `thinkthen-duckdb`. Its `[lib]` is `name = "thinkthen_duckdb"` with `crate-type = ["cdylib"]`, so the build gives `libthinkthen_duckdb.so`. A crate that depends on `thinkthen` cannot keep a lib named `thinkthen`, and ADR 0047 item 6 renamed the C lib for the same reason. The extension stays `thinkthen`: `LOAD thinkthen` and the file `thinkthen.duckdb_extension`. DuckDB finds the entry symbol `thinkthen_init_c_api` from that name. The port keeps the tag's hand-written `#[unsafe(no_mangle)] extern "C" fn thinkthen_init_c_api` in `src/ffi/entry.rs`. `no_mangle` exports it from a private module. `check.sh` calls `vendor/append_extension_metadata.py -l target/release/libthinkthen_duckdb.so -o build/thinkthen.duckdb_extension -n thinkthen -dv v1.5.5 -evf <extension_version.txt> -pf <platform.txt> --abi-type C_STRUCT_UNSTABLE`. The unstable ABI stays because `duckdb-rs` needs it, as `sdlc/issues/2026-09-21-the-scalar-bind-surface-is-unusable-on-duckdbs-stable-c-api.md` records. The build therefore loads only in DuckDB v1.5.5.
3. **No C door underneath.** The extension links `thinkthen` by path and never links `thinkthen-c` (ADR 0047 item 1). Ticket 0094 serves as the reference for the FFI edge only: one panic guard, one error-kind table, and one module that holds `unsafe`.
4. **One `unsafe` module.** The tag holds 298 `unsafe` lines in seven files. The port moves every raw DuckDB C API call, the signal handler, and the entry point into `src/ffi/`, and only `mod ffi` carries `#[allow(unsafe_code, reason = "…")]` (ADR 0047 item 3). The rest of the crate is safe code over typed wrappers. A created logical type lives only inside one wrapper whose `Drop` destroys it.
5. **Engine and its settings.** LOAD registers the functions, the SIGINT handler, and four settings through `duckdb_register_config_option`, and it touches no wire. The settings are ADR 0017 section 5's, spelled the DuckDB way: `SET thinkthen_width = N`, `SET thinkthen_max_requests = N`, `SET thinkthen_cache = 'DIR'`, and `SET thinkthen_cache_bytes = N`. The init callback of decision 10 reads them from the caller's client context. The extension builds its engine on `EngineBuilder::from_env()` (0084, amended at `f19cf437`), so the address, key, and cache still come from the environment, and applies each setting the caller set through its setter. A setting left unset keeps the environment's value or the default. A cache folder given from SQL passes decision 10's access check against the caller's own file settings before any engine is built. A caller with `enable_external_access` off, or with the folder outside `allowed_paths` and `allowed_directories`, or with `LocalFileSystem` disabled, gets `usage` with a pinned sentence, and the engine never touches the folder. `thinkthen_cache_bytes` needs no check. `THINKTHEN_CACHE` from the environment is the operator's choice and is not checked. Engines are kept in one process-wide map keyed by the four values and built on first use. The map holds at most 16 engines and refuses a seventeenth distinct set as `usage` with a pinned sentence. `thinkthen_width` takes 1 to 32, as `EngineBuilder::width` does in 0084 and 0086 and as the command's `--jobs` does. `SET thinkthen_width = 33` and `SET thinkthen_width = 0` read `usage`. The binding passes the engine's own sentence through, and the test pins that sentence. Width is process-wide under 0077, and the README says so. SQL cannot name a backend or a key. `thinkthen_max_requests` applies per engine call, and one call covers one chunk of at most 2,048 rows. A per-statement limit needs statement-wide state, and the 2026-09-21 issue records the bind path that would hold it as broken. The README states the per-chunk reach and names that issue as the lever. The warm aggregate has no client-context accessor in the C API, so `thinkthen_warm` runs on the engine `EngineBuilder::from_env()` builds with no setter. The README pins a sentence that warm reads its cache folder and width from the environment only, and tells the reader to set `THINKTHEN_CACHE` before a warm pass. 0118's per-database connection is the lever. Ian can overturn each of these.
6. **Chunks go in bulk.** Each scalar invoke reads its chunk, drops NULL rows, dedupes texts in first-seen order, and makes one streaming call. Decide and probability use `decide_many_with`, and `thinkthen_probability` reads `Row::probability` (G4). Choose, score, and tag use `annotate_with` over a one-question set (0095, closing R2-23). Choose and tag with list members build through `Question::choose_labels` and `tag_labels` (G5). Answers map back by text, so a repeated text or a NULL never shifts a row (R1-1).
7. **Every engine call runs on a detachable worker.** Shared rule 4 makes Ctrl-C prompt for batches and single sends alike. Each engine call from a scalar, the warm aggregate, recognize, relations, and details runs on a spawned worker. The worker owns the distinct texts as `Vec<String>`, a clone of the question, and an internal `CancelToken`. It builds its own `Batch` there, since `Batch` is not `Send`, and passes the token as `CallOptions::cancel`. The DuckDB thread waits on a channel in 50 ms ticks and reads the interrupt predicate of decision 8 on each tick. On a stop it cancels the token, detaches the worker, and raises `thinkthen cancelled: ` at once. The detached worker finishes the requests already sent under 0073 and starts no retry. Until its sends end, it holds its width permits. Cost: one thread spawn per chunk and about 80 lines. This answers review finding 1 with its recommended fix. The fallback it names is not taken.
8. **SIGINT and the interrupt predicate.** LOAD takes SIGINT through `sigaction` and keeps the host's action for the chain, as at the tag. The install records the host's action before `sigaction` installs ours (R7-7). The handler bumps an atomic signal count, stores the signal time in an atomic, and chains. It never allocates, locks, or calls into `thinkthen`, since 0084 does not promise that `CancelToken::cancel` is async-signal-safe. The tag's rules in `current_cancel` (a signal inside this invoke, another call in flight, an active burst, a start within one burst window) become one predicate over those atomics. A query that is reading its chunk counts as in flight (R6-6). Each call builds its own token, so no token outlives a call (R1-21, R2-14). The tag's one-shot token and its re-arm logic leave. The port guide's map (section 3.1, the `Cancel` row) says DuckDB keeps its re-arm logic. This ticket departs from that line because the worker's internal token replaces it. The signal pipe and the bridge thread that interrupts relate connections move to 0118.
9. **Deadlines.** The ruled third argument stays milliseconds and goes through `CallOptions::deadline_millis` (ADR 0041). A NULL deadline gives a NULL row, as at the tag. `thinkthen_warm` takes no deadline argument.
10. **Question arguments and file access.** A question is plain text, `'@file.json'`, or the file grammar's JSON, read through `Question::from_json`. A `Usage` from a file's text maps to the `local` word, per 0095. The tag checked `@file` against every loaded database's settings through the kept connections, because its scalars could not name the caller's database. The port reads the caller's own settings instead, and the core needs no registry. Each scalar registers through the raw C API with `duckdb_scalar_function_set_init`. Its init callback reads the caller's client context through `duckdb_scalar_function_init_get_client_context` and copies `enable_external_access`, `allowed_paths`, `allowed_directories`, and `disabled_filesystems` into the local state through `duckdb_client_context_get_config_option`. Each `@file` path is checked against that copy before any open, with the tag's rules and sentences (R1-15, R2-3). A missing file and a refused file give the same message. The tag's cache keyed by path and modification time stays (R2-18). The warm aggregate has no client-context accessor in the C API, so `thinkthen_warm` refuses `@file` as `usage` with a pinned sentence that names DuckDB's `read_text`. DuckDB checks its own settings on `read_text`. Ian can overturn this narrowing.
    - First build step and stop rule: a spike reads all eight values through the init context in the stock v1.5.5 CLI and in the venv's module. Four are the file settings above. Four are the engine settings of decision 5, registered through `duckdb_register_config_option` and read through `duckdb_client_context_get_config_option`. The spike shows that a `SET` between two statements reaches the next query, and that init runs on each thread under `SET threads = 4`. The 2026-09-21 issue records that the scalar bind path crashes on this API. If a path fails the same way, the builder stops and re-scores. Each path has its own recorded fallback.
    - File settings fallback: every `@file` refuses until 0118's registry lands, and 0118 then restores the tag's rule. A cache folder given from SQL refuses the same way, in either the `SET` form or the `thinkthen_configure` form, and the engine uses the environment's folder only. Under this fallback the R2-3 and R2-18 plants cannot turn red, so the re-score moves both rows to 0118.
    - Engine settings fallback: the four `SET` settings leave, and the extension registers one table function in their place, `thinkthen_configure(width := N, max_requests := N, cache := 'DIR', cache_bytes := N)`. It takes named arguments, applies each given value through the matching `EngineBuilder` setter on an engine built on `EngineBuilder::from_env()`, and returns the values it applied. The settings stay process-wide, as width already is under 0077. Tests that need 8 requests in flight call `thinkthen_configure(width := 8)` in their own child process, so R2-23, R5-23 (timing), case 23, and 0118's R4-22 keep their counts. Warm then uses the configured engine as well. The README states the process-wide reach. The range and sentences stay those of the `SET` form. `thinkthen_configure(cache := 'DIR')` runs the same access check against its caller's settings, read through `duckdb_table_function_get_client_context`. The README states that the configured cache is process-wide. Each call builds a new engine and swaps it into the process-wide slot. A call in flight keeps the engine it started with, and later calls see the new one. A test makes a configure call during a held batch and checks both halves.
    - Behavior change: a database whose own settings allow a file now reads it while another database in the same process forbids files. ADR 0038 puts each call on the caller's database, and this follows it.
11. **Recognize and relations.** `thinkthen_recognize(body, kinds)` builds through `Recognize::builder` and returns a `LIST` of `(name, kind, start, end, strength)`. `start` and `end` count code points, as DuckDB's string indexing does. `thinkthen_relations(body, spec)` reads `Recognize::from_json` or the file and returns a `LIST` of `(relation, source, source_kind, target, target_kind, probability)`.
12. **Results.** `thinkthen_score` returns the position. `thinkthen_details` returns one struct from the `Details` accessors: the yes probability, the answer word, `nearest`, `model`, `question_sha256`, `requests_sent`, and `cached`. A member the verb lacks reads NULL and never 0 (R3-11). Choose and tag now fill `thinkthen_details`, because main serves them (G5). `thinkthen_annotate` returns `AnnotatedRecord::value_json`. `thinkthen_usage()` returns `requests_sent`, `cache_answers`, `input_tokens`, and `output_tokens`. Counters have no reset, and tests assert differences around a call (0095).
13. **Errors and panics.** One exhaustive `match` maps `ErrorKind::name` to the prefix `thinkthen <kind>: `. One guard function contains every callback, and the tag's three wrappers in `guard.rs` fold into it (R2-31). `thinkthen` already stops engine panics at its public methods (0086).
14. **Test hooks.** One Cargo feature, `test-hooks`, carries every test-only door: the R7-7 raise between the record and the install, the R1-10 panic trigger that replaces the tag's `test-panic` feature, and the doors 0118 adds for its retire and reaper tests. Each hook's symbol and string starts with `thinkthen_test_hook`. `default = []`. `check.sh` builds the shipped extension without the feature and fails when the shipped file holds that prefix or `ENGINE_TEST_PANIC`, or when `cargo tree -e features` shows `test-hooks` enabled in the shipped build.
15. **Site examples go to their owner.** `site/scripts/pull-examples.mjs` copies every `site/src/data/examples/*__duckdb.json` from a private deck, so a hand edit here would vanish on the next pull. The check runs every such code block (R5-24). Decision 11 changes the recognize and relations shapes, and 0118 changes relate. The builder files `sdlc/issues/2026-09-24-duckdb-site-examples-draw-the-tag-shapes.md` in this repository with both new shapes and hands the deck's owner a matching issue in the deck's repository. The check runs the ported replacement for each of the two pages and prints a divergence line that cites the in-repo issue. The divergence list is closed and lives in the check. This answers review finding 9 through its owner option.

## Shared rules

This ticket follows the seven shared rules of `sdlc/planning/surfaces-port-guide.md` on main (`446a4d6b`, with the builder wording of `6eb1303e` and the paid-backend rule of `d783ab6b`).

1. **No Docker.** The check runs offline on Linux with the pinned toolchains and no container. See the gate section.
2. **Toolchains under `~/.cache/thinkthen-toolchains/`.** The DuckDB v1.5.5 CLI and the test venv live under `~/.cache/thinkthen-toolchains/duckdb/v1.5.5/`. The one download is setup with a sha256 pinned in `tools/version.env` and a refusal on mismatch. Gates then run offline.
3. **One cache and one backend per test.** Each test sets its own temporary cache folder through `SET thinkthen_cache`, or through `THINKTHEN_CACHE` for warm, and starts its own loopback backend. The held reply that can hold again and one backend per test come from ticket 0117.
4. **Prompt Ctrl-C.** Decision 7 runs every engine call on a detachable worker. R4-22, R5-23, and case 23 meet 100 ms.
5. **A deny plant that reaches deny offline.** The plant removes one license exception. See the gate section.
6. **No test or plant reaches a paid backend.** `check.sh` unsets `THINKTHEN_API_KEY` and sets a fake key only beside a `THINKTHEN_BASE_URL` on `127.0.0.1`. It refuses to start a suite when the address is anything else. Plant: a non-loopback `THINKTHEN_BASE_URL` still starts the suites. The guard's test turns red. The seeding plant below points `XDG_CACHE_HOME` at a temporary folder, and the builder confirms that the default cache resolves under it before running that plant. The secrecy test's base URL with credentials is a loopback address. Environment seeding is proved through the cache folder, never through a request. No plant here changes the address the engine is built with.
7. **Public engine settings.** Decision 5 exposes width, `max_requests`, cache, and `cache_bytes` as DuckDB settings on an engine built on `EngineBuilder::from_env()`. Each test that needs requests in flight runs `SET thinkthen_width = 8` in its own child process and never uses a hidden hook or the default.
