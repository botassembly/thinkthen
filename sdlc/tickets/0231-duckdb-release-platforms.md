## Outcome and authority

Every advertised 0.1 DuckDB archive contains the accepted C++ extension for DuckDB v1.5.5, built from the corresponding official static inputs. An installed archive on its own target proves bind-time refusal, query lifetime, same-session warm/settings behavior and request-size behavior before that target's register 51/72 and 0149/0157 remainder closes. A target that lacks a verified archive or native installed check fails release smoke. It never falls back to the old C API package under the same release name.

Ian approved the C++ migration and the staged Linux x86-64 path in [ADR 0081](../planning/adr/0081-duckdb-cpp-api.md). Ticket 0201 owns its SQL behavior and ADR 0080 owns the query budget. The 2026-09-28 work plan prioritizes required release platforms. Ian has now authorized M5 testing at any time; its native macOS ARM64 host can supply this ticket's first platform proof. The coordinator may approve target-specific implementation details within those outcomes; Ian can overturn the supported-platform or outward release choice in ticket 0128. This ticket adds no new architecture decision and does not authorize a workflow dispatch or publish.

## What the build taught us

The official macOS ARM64 static ZIP has 21 archives, so it needs its own manifest and Apple link line. The native M5 link exposed Homebrew Rust 1.95.0 standard-library objects with macOS 26 deployment metadata even when the final extension reported macOS 15. A project-local official Rust 1.95.0 toolchain fixed that input, and the build now rejects an incompatible Rust standard library. The selected installed package passes stock-host load/refusal and the affected settings, query-budget, relation, request-size and SIGINT checks. The earlier 50 ms bridge poll missed the strict 100 ms cancellation bound on M5; 10 ms polling passed it. High review found two publication-order races in the first passing package. A sibling invoke could start after the handler's count snapshot but before its marker write and miss the signal. At the last-drop boundary, a handler could read the old interval, then publish its global count after the new query began and falsely stop that query. The first correction published one epoch-and-clock event atomically: siblings in the same live interval saw the wave, while a new interval refused an old event. The bridge Rust ceiling rose from 5,790 to 5,808 non-blank lines for that publication rule and its two-order regression test.

The landed 0212 Rust default packs multiple records into one request. DuckDB's existing shared cases 27/28 pin the prior per-record request bodies, so the DuckDB adapter selects batch 1 only for those children and checks a separate literal packed-default request. The shared settings corpus's one concurrent max-requests row now checks the transport ceiling and a successful two-record allowance; a failing multirow statement can stop before all allowed transports arrive. A raw Mach-O scan also found ring debug-map paths under the M5 builder's home that `strings` missed. The macOS build strips the raw Mach-O before restoring the verified DuckDB footer; stock-host load and selected installed signal checks passed on that exact package. The Python ceiling rose from 2,980 to 3,012 non-blank lines for the macOS-only footer validation and stripping step.

The High follow-up found that the first correction's packed `fetch_max` silently loses a new event after 2^32 idle-separated intervals or about 49.7 days in one live interval. The bounded correction keeps the signal bit in the same CAS as the live interval and uses a full-width clock for the wave. A checked 48-bit generation prevents silent reuse. One deterministic test publishes an event before both former wrap points, then another after them; it checks sibling cancellation, the wave edge and old-handler isolation. This test uses production-private helpers with local atomics, without a test-only export, flag or hook. The old max would have kept the earlier event; the two existing interleaving cases did not reach either wrap point. The bridge Rust ceiling first rose to 5,889 non-blank lines, up 81 for the split full-width publication and regression proof. I looked for duplicate signal ownership state and kept one CAS in `INVOKING`; no second interval marker was added. The exact merged source, archive hashes and bounded proof are in the build record. The same High reviewer still needs to check the correction and raised ceiling. Linux ARM64 and macOS x86-64 need their own C++ manifests, native builds and installed proof. Ticket 0128 separately owns whole-release runner rehearsal.

The same High reviewer then found a mixed old/new handler order: an old handler could advance the global time after a real new-epoch signal, extending that new query's sibling wave. The source correction samples time, validates the captured epoch is still live, then publishes time before setting the bit. A later old-epoch write carries an earlier timestamp, so `fetch_max` cannot displace the newer signal. The reader takes the bit before time; sequential consistency makes it see time already published for that bit. The deterministic mixed-order regression failed at 200 versus the required 100 before the fix and passed afterward. It protects a cancellation boundary the prior interleaving and rollover tests missed, and uses the existing private atomic helper with no test-only door. The Rust ceiling rose another 26 lines to 5,915 for that guard and regression; no duplicate interval state or dependency was added. The exact source proof and the pre-correction M5 artifact provenance are in the build record. The same High reviewer must accept this source before a native rebuild. The remaining platform and whole-release proof stays open.

The same High reviewer accepted the corrected source and withdrew an initial concern about the pre-CAS start sample after root pointed to accepted 0110 decision 8/R6-6 and 0201's QueryBegin–QueryEnd ownership; `0231-code-review.md` records the exact call path. Main's later guidance-only delta merged before the new native build. The resulting M5 archive passed stock v1.5.5 load, genuine v1.5.4 and changed-footer refusals, held/late SIGINT, bounded sibling/next-query/between-query cases, and a selected same-session warm/cache check over the merged 0228 engine. The new archive and extension hashes, footer and Mach-O checks, source revision and exact invocations are in the build record. This closes the selected build proof only after the same High reviewer accepts the artifact; Linux ARM64, Intel macOS and actual macOS 15 execution remain open, as does 0128's whole-release rehearsal.
