# 0246: Refuse a known zero-send budget before first cache binding

Status: code accepted at `63d48b96` by a fresh High reviewer and integrated. Register 10 in experiment 284 remains open. Ticket 0228 and ADR 0099 already prevent a missing key from binding an empty folder. This ticket addresses the next demonstrated local refusal without changing ticket 0065's durable before-send authority or the version-one marker.

## Outcome and limit

When a new or existing empty, unmarked write-capable folder has a successful key lookup and this call's explicit send limit is zero, return the existing `BeforeFirstSend` usage denial without creating or changing the folder. A later call at another address can bind it. A bound cache hit and exact replay still work with zero available sends. A bound mismatch, malformed marker, and legacy unmarked entry retain their gate-first refusals. The final send reservation remains the only authority for an actual attempt and counts actual attempts, not rows or prepared requests. Successful key lookup does not validate HTTP header characters; malformed-key behavior is deferred, and a zero limit may take precedence over that later refusal.

This fixes an **already-known refusal before writable admission**, not the original register's universal “every zero-send run leaves the default folder untouched.” A call can be admitted, publish a durable marker, then be cancelled, expire, fail locally, crash, or fail during transport before a listener observes it. Marker publication cannot be atomic with a separate socket send. Moving it to entry installation would allow two different-address first writers to send before either identity wins. Removing it after an unsent result can split the folder and lock inode namespace under live readers and writers. Neither change belongs in this ticket.

## Admission sequence

The existing `unbound_empty` probe is an observation, not the binding authority. For a qualifying folder, `cancel.stop()` precedes the key lookup. A failed key still uses ADR 0099's second probe. A successful key with explicit limit zero uses the same read-only second observation. If it sees a bound or newly legacy folder, retain the key locally, enter `prepare_checked_refresh`, and permit a matching hit or the normal refusal. If preparation needs a live send, cancel the permit and return `SendBudgetFirst`; cancellation and cleanup errors retain their existing precedence. If the folder remains unbound empty, observe cancellation/deadline once more, then return `SendBudgetFirst` without making it. The second observation can miss a writer that publishes immediately afterward, as ADR 0099 already allows for `NoKey`; a later call can see that writer's hit. A folder error is still a local storage refusal, never silently converted to a budget denial.

Only `Some(0)` is certain from the call's configuration. A positive process total may temporarily appear spent because `SendBudget::reserve` counts uncommitted reservations and refunds them on drop. The actual HTTP path still checks cancel/deadline, usage admission, the last remaining time, and `reserve_send` immediately before marking an attempt. This design does not consume or reserve a send earlier. A bound cache or replay lookup happens before any budget denial. Strict replay remains read-only.

## Diagnostic disposition for review

The original report asks for the bound and requested URLs plus a cure on every surface. Ticket 0065 deliberately chose a fixed, secret-safe marker and refusal. Ticket 0124 added the requested URL and cure to the command, and `specification/recording.md` explicitly says the bound URL is never named. `BackendIdentity` stores only SHA-256 of adapter and canonical endpoint; entries cannot be assumed present and do not provide a general reverse lookup. A raw-address sidecar or marker version change would expose previously unpersisted address text and cause older closed-schema readers to refuse it. It is a separate trust and compatibility ruling, not a mechanical completion of this ticket. The smaller compatible improvement is a fixed, actionable library cure that does not echo an untrusted URL, followed by a reviewed status/diagnostic disposition. Do not claim it meets the original two-address wording. Do not advise deleting only the marker: existing entries would become legacy and concurrent open folder handles could still operate.

## Prospective implementation

`crates/thinkthen/src/engine/mod.rs` can expose a private immutable-limit predicate on `Cancel`; `request.rs` carries the one early key and second observation without another scheduler or marker state. `tests/backend/cache_identity.rs` owns the outside-in default-cache table. A controlled key-closure barrier for the writer race belongs in the existing `engine/request/tests.rs` private test child; the CLI test cannot schedule a writer precisely inside its key reader. `public/error.rs` is a separate optional fixed-cure wording change after the diagnostic disposition; `specification/recording.md` and this ticket describe the precise guarantee. The root ratchet is derived metadata. No core marker, identity reader, cache lock, CLI output schema, or entry changes are proposed. Current nonblank headroom is tight in `engine/recorder.rs` and `tests/backend/cache_identity.rs`; reuse its existing probe and helpers rather than extending recorder state. Exact file claims follow accepted design review.

## What the preparation taught us

The named no-send failure is not just a missing key: an explicit zero send limit demonstrably binds a default folder before a safe local denial. Cancellation and deadline already have a pre-admission checkpoint; post-admission stops are a different guarantee. The original publish-at-install suggestion would reopen ticket 0065's paid cross-address race. A closed hash marker protects a trust boundary but cannot narrate a bound URL. The small useful repair is a certain pre-admission denial, while the literal all-zero-send and two-address language needs an explicit reviewed disposition.
