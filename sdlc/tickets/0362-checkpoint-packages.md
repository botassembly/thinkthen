# 0362: Checkpoint publishing packs the 16 missing surface packages

Status: landed. Plan: `sdlc/planning/issue-priorities-2026-09-30.md` batch C4, lane claude-3. Issue: `sdlc/issues/closed/2026-09-30-checkpoints-publish-no-source-wrapper-packages.md`.

## Outcome

`surfaces --publish TAG` publishes a package for each of the 16 surfaces the release QA team could not test after checkpoint `2026-09-30-1`: Ada, COBOL, C++, C#, Dart, Go, the JVM languages (Java, Kotlin and Scala share one package), Objective-C, PHP, R, the Rust crate, Rust Polars, Swift and Zig. Rust Polars is the crate's `polars` feature, so the one `.crate` file serves both Rust surfaces. Its manifest row names `libraries/rust`, and its `how_built` names `libraries/polars`; QA finds Polars there. Each new file sits in the published folder with its line in `SHA256SUMS` and its row in `manifest.json`, which names its surface. The newest-three pruning is unchanged.

## Evidence

- Starts from: checkpoint `2026-09-30-1` published 9 files: the command, the C library, Python, TypeScript, Ruby, SQLite, DuckDB, PostgreSQL and the first-run sample. The QA team's round 1 report (`2026-09-30-qa-round-1-checkpoint-surfaces-2026-09-30-1.md` in the thinkthen mailroom) skipped 160 language cells for the 16 surfaces and asked for Go, the JVM languages, C# and Rust first. `release-pack` already has parts for Go, C++, C#, the JVM, Swift, Zig, PHP, Dart, Flutter, Ada, Objective-C and COBOL (tickets 0261 to 0264 and 0271). Each part names the C archive packed in the same call, by file name and digest. `release-smoke` already checks each pair with `release-go-cpp-pair` and runs each wrapper's `check.sh` against its archive. `--reuse` refuses these parts. The R check already runs `cargo package --locked --offline --no-verify --package thinkthen` and `libraries/r/tools/make-tarball.sh` from a `git archive` tree, and installs both with no network. ## What the build taught us

- The installed JVM release check had been stale since ticket 0304 slice 1. No sweep reached it, because only `release-smoke` runs a wrapper check against its archive, and the sweep never packed the wrappers. The first focused smoke here failed it. Expect more stale installed checks wherever a release path runs only in the release workflow.
- Focused run on lane claude-3 at the branch head, writing only under the scratch folder: `release-pack --reuse` with `c`, the 11 wrappers, `crate` and `r` packed 14 files. The five `release-go-cpp-pair` modes passed. `release-smoke` on the C archive and the 11 wrappers printed `surfaces: pass` for libraries/c, ada, cobol, cpp, csharp, dart, go, objective-c, php, swift and zig. JVM passed after the fix above. Its only failures were the eight expected `DIR holds no file` lines for the default files. The `$HOME` scan inside every archive, the nupkg, the three jars, the crate and the R tarball found nothing. The unpacked crate built offline with the pinned toolchain. The R tarball installed offline with an empty cargo home and loaded. Five publishes under a scratch root wrote 14 files plus `SHA256SUMS` and `manifest.json` each, `sha256sum -c` passed, the manifest named 14 rows with their surfaces and no `$HOME`, and pruning kept the newest three and left a planted folder. Refusals: `crate` and `r` in a dirty tree exit 1, and a wrapper without `c` under `--reuse` exits 1.
- A crate unpacked outside the checkout builds with the default toolchain unless `RUSTUP_TOOLCHAIN` names the pinned one, since a `.crate` carries no `rust-toolchain.toml`. QA's Rust consumer needs Rust 1.95.0, the crate's `rust-version`.
