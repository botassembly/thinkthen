# 0265: Pack Ada, GNU Objective-C and COBOL source with one matching C archive

Status: complete within the local Linux package scope after final fresh code review accepted `88d23f97`. The installed host slice `de2d24a4` and final packaging delta have both passed the same independent reviewer. Original release criteria remain open.

## Outcome and retained behavior

One local Linux x86-64 invocation packs the integrated source-only Ada, GNU Objective-C and COBOL bindings beside one separately built versioned C archive from the same clean committed source. A strict fixed-data preflight checks exact archive cardinality, outer checksums, version/target/source fields and the actual C archive SHA before any installed consumer starts. Each source wrapper compiles a real public five-text Max consumer from its unpacked files and loads the unpacked C shared library from a separate installed prefix. This is local file qualification, not a release-runner or public distribution result.

Retain the [0249 accepted source integration](../records/0249-integration-closure.md), current source-mode `check.sh` matrices, J1 cases, source privacy and cancellation probes, and the [0260 accepted three-host forwarding proof](../records/0260-ada-objc-cobol-host-proof.md). That proof already supplies three short public callers and the shared literal body oracle. It does not prove a shipped wrapper archive because each controller currently copies product source from the checkout. The [preflight](../records/0265-ada-objc-cobol-release-preflight.md) names those paths. No new scalar matrix, runtime/API change, generic packaging framework or registry account is needed.

## File and provenance contract

The opt-in pilot command is `release-pack x86_64-unknown-linux-gnu OUT c ada objective-c cobol`. Preserve its existing default parts and `--reuse` behavior for unrelated families. For these three wrappers, refuse `--reuse`, a dirty checkout, a missing C part or C ordered after a wrapper. Build C once in fresh release mode and stage all three source wrappers from that same committed tree, never by reading a prior OUT archive. Record the source commit, Cargo lock/toolchain pin, actual GNAT/GCC/GnuCOBOL tools, output command and exact artifact hashes. The C archive keeps one header, shared library with soname link, static archive and pkg-config file. It remains separate: no wrapper contains a native binary.

The exact outer basenames are `thinkthen-ada-$V-$TARGET.tar.gz`, `thinkthen-objective-c-$V-$TARGET.tar.gz`, `thinkthen-cobol-$V-$TARGET.tar.gz`, plus `thinkthen-c-$V-$TARGET.tar.gz`. Each has the packer's ordinary adjacent `.sha256`. Each wrapper has exactly one `THINKTHEN-PACKAGE-INPUTS` containing five fixed data lines: `source_commit`, `target`, `version`, `c_archive`, `c_sha256`. The packer computes the C digest from the archive it just made. The three wrapper manifests must be byte-identical and match that C file. They are data, never sourced shell text. The clean build receipt establishes provenance; the preflight proves bundle consistency and does not compare an older manifest commit to a later notes-only HEAD.

Curate only these wrapper members, plus the manifest, with no build output, copied native library, test fixture or checkout path:

Ada currently has no such JSON manifest; its `.gpr` and the wrapper's five-field input manifest are the local source-package contract. Do not invent an Ada registry manifest for this pilot. Compare Objective-C's shipped `Sources/thinkthen.h` byte-for-byte with the unpacked C header. Ada compiles its binding and links the separately unpacked C library; COBOL uses the unpacked C header and library. Check the derived exports for all three. Matching header bytes alone do not prove unchanged engine dependencies. It may ignore other valid language families in a full bundle, as the earlier pair modes do. Require safe exact member names before scratch unpack, including no extra files or symlinks in source wrappers. `release-smoke` conditionally invokes this same preflight before backend startup when any of the three families appears, then routes each wrapper and the checked C path to its installed selector.
