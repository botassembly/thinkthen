# 0112: Port the Ruby surface

Status: design and its 2026-09-24 amendment accepted. Owner: Claude. Depends on the 0084 builder amendment and 0117.

## Outcome and authority

Port the Ruby binding from tag `surfaces-wave7-frozen-2026-09-24b` (`9df8bae9`) onto the public Rust API as the unpublished crate `thinkthen-ruby` at `libraries/ruby`, in its own Cargo workspace. `require "thinkthen"` keeps the ten verbs as `ThinkThen` module methods, plus `decide_many`, `details`, `question`, `set`, `usage`, `with_tick`, the six error classes under one `ThinkThen::Error` base, and `ThinkThen::Cancel`. Every call reaches the real engine through `thinkthen`. Queue item 3 of `sdlc/planning/one-line-plan-2026-09-24.md` lists Ruby among the remaining surfaces.

Draft ADR 0047 (branch `ticket/0093-first-binding-crate`) fixes the crate's place and its checklist. Ticket 0093 sets the workspace, lint, ratchet, and surface-rung pattern. Ticket 0095 fixes the members this binding calls, and 0098 builds them. Section 3.2 of `sdlc/planning/surfaces-port-guide.md` gives the port map. Its "Shared rules" section (main, `bced9c4d`, with the width rule rewritten at `446a4d6b`) binds every surface ticket, and this ticket follows all six. Ticket 0105, with its 2026-09-24 amendment, is the accepted template. Ticket 0117 supplies the backend arms beyond 0092. The design review (`sdlc/records/0112-design-review.md`) found seven items, and this version answers them. Ian can overturn every decision below.

## Design and decisions

1. **Magnus over the public Rust API.** Ruby does not build on ticket 0094's C door. It keeps its magnus extension over `thinkthen` for three reasons. First, the rows this ticket carries (R1-20, R2-15, R3-5, R4-2, R5-9) all test the tag's `cross`: the wait with the interpreter lock released, the unblock function, `rb_thread_check_ints` under `rb_protect`, and blocked signals on the call's thread. A Fiddle call releases the lock with no unblock function. The port would then rewrite that design in Ruby and re-open closed rows. Second, `thinkthen_call` returns JSON text only. Ruby would parse every result back and lose the typed batch path. Third, Fiddle leaves Ruby's default gems after 3.4, and the `ffi` gem is a new dependency. From 0094 this binding takes the FFI edge pattern of ADR 0047 item 7: one panic guard, one error table, and one `unsafe` module. It also takes 0094's closure of R7-1. Both link the same ureq resolver. Cost: the build needs Ruby's headers and libclang for rb-sys. Decision 13 places both. Ian can overturn this in favor of the C door.
2. **Engine.** Every call uses `thinkthen::default_engine()`. The tag's `Native::Engine` value and its connector line leave. The environment variables that `Engine::from_env` reads configure the engine. A public engine value carries the ADR 0017 section 5 settings (decision 14). The module functions call the same methods on one lazy value that wraps `default_engine()`.
3. **Every call runs on a detachable worker.** This follows the shared rule on Ctrl-C. The binding does not use `CallOptions::interrupt`. That check runs on the engine's calling thread and would have to take the interpreter lock there. That lock re-take is the R4-2 crash shape. Each verb reads its inputs into Rust (decision 8) and spawns one worker that never touches Ruby. The worker owns `&'static Engine`, a clone of the question, the texts as `String` values, and a clone of the call's own `CancelToken`. It blocks asynchronous signals (`pthread_sigmask`), builds its own `CallOptions`, and runs the verb. For `decide_many`, `filter`, and `annotate` it builds and drains the `Batch` on its own thread. `Batch` is neither `Send` nor `Sync` (0084). It stops at the first `Err`, drops the batch, and returns that error. A call returns all of its results or raises.
4. **Interrupts are prompt.** The Ruby thread waits in 50 ms slices with the lock released and an unblock function set. Between slices it holds the lock in ordinary frames and makes three reads. It runs `rb_thread_check_ints` under `rb_protect`. It reads the caller's `cancel:` token. It reads the call's own token. A raising tick fires that token (decision 6). A trapped signal that raises nothing and a spurious `Thread#wakeup` leave the call alone, as at the tag. On any stop, the Ruby thread fires the call's own token, detaches the worker, and raises at once:
   - Ctrl-C raises `ThinkThen::CancelledError`, and its `cause` is the `Interrupt`. This matches the shared rule and 0105's `KeyboardInterrupt` rule.
   - Any other raise (`Thread#raise`, a raising trap) surfaces unchanged. `Thread#kill` resumes through `rb_jump_tag`.
   - A fired caller token raises `CancelledError`.
   - A raising tick raises the tick's own error.

   The detached worker's sent requests finish under 0073, no retry starts, and its result is dropped. The worker ignores a failed send on the closed handoff and does not panic. When the handoff closes with no result, the Ruby thread raises `DefectError`. The tag raised only after the in-flight request finished. The 0105 review and the shared rule ask for the prompt return. Ian can overturn the prompt return and the Ctrl-C class.
5. **The detach cost, stated.** A detached call keeps the width slots of its sent requests until each one ends. A single call holds one slot. A batch holds up to W, the engine's width. Each request ends within the engine's 30-second request timeout. Until then, the next call in the process can wait at the width gate. ADR 0017 says "Zero threads outlive a call", and a detached worker outlives its call by that long. The Ruby section of ADR 0047 records the departure, its cost, and Ian's two levers. One is an engine member that abandons sent requests. It changes 0073. The other is joining the worker. It gives up the prompt Ctrl-C. A test proves that a following `decide` answers once the held replies go.
6. **The watchdog runs ticks only.** `with_tick` keeps the tag's watchdog thread, one row per in-flight call, the tick on `Thread.current`, and the 0.1 s cadence. The caller-token relay moves into the slice (decision 4). A tick that raises stores its error in the row and fires the call's own token. The call's next slice reads the token and raises the tick's error within 50 ms. It does not wait for the crossing to return.
7. **Deadlines.** `deadline:` goes through `CallOptions::deadline_seconds` after the binding refuses a non-number and a boolean. `nil` and `-1` mean none. `0` is spent. Any other negative, NaN, infinity, or a budget above 4,294,967,295 seconds raises `UsageError` (ADR 0041). The tag's own conversion leaves.
8. **Inputs.** The binding reads a whole `Enumerable` into Rust before the first send. A `String` crosses unchanged. Any other value crosses as its JSON text. Its `to_s` form never crosses. `nil`, invalid UTF-8, and a NUL byte raise `UsageError` naming the item's index (G11).
9. **Questions.** `ThinkThen.question(...)` composes the question-file object and calls `Question::from_json`. Keywords and files then give one digest. A `Range` threshold becomes the file's band string. `ThinkThen.set(path)` calls `QuestionSet::load`, and keywords go through `from_json`. A broken rule from keywords raises `UsageError`, and from a file raises `LocalError` (0095, Q16). Choose and tag with runtime labels go through `Question::choose_labels` and `tag_labels`. A scalar `choose` or `tag` calls `details` and reads `value()` with no added send (G5). `filter` on a banded question raises `UsageError` before any request.
10. **Results.** `decide` returns `true`, `false`, or `nil`. `decide_many` returns an `Array`. `decide_many_with_probabilities` returns `{answer:, probability:}` pairs from `Row::probability` in the same call. `score` returns the position. `score_with_level` reads the position and the nearest level from one `details` call. `tag` returns labels. `filter` returns the passing records. `rank` and `find` wrap each text in one binding `Evidence` type holding its index. They keep the tag's `Ranked(index, record, probability)` and `Found(index, unit, probability)`. `find` returns `nil` fields when nothing is selected. `annotate` parses `AnnotatedRecord::value_json` per record and keeps the tag's symbol keys, its `on:` merge, and its failed marker. `details` returns `JSON.parse` of `Details::to_json`, equal to the command's `--details` document. `usage` returns `requests_sent`, `cache_answers`, `input_tokens`, and `output_tokens`.
11. **Recognize and relate.** Keyword forms compose the `recognize @FILE` object and the version-one relate file, then call `Recognize::from_json` and `Relate::from_json`. `Entity` becomes `(name, kind, start, end, strength)`. Offsets count Unicode scalar values, and a Ruby UTF-8 string indexes the same way. `Relation` and `Edge` become `(relation, source, target, probability)` with `Entity` ends. `relate` takes `[name, kind]` pairs, hashes with `name` and `kind`, or `Entity` values. The tag's `id`, `text`, record-number ends, and `kind_field` leave.
12. **Errors, panics, and registration.** One exhaustive `match` maps `ErrorKind::name` to the six classes. The binding's own refusals raise the same classes. One panic guard wraps the worker's body and turns a shim panic into `DefectError`. `thinkthen` already stops engine panics at its public methods (0086). All conversion back to Ruby runs under the tag's `protected` wrapper. The native half registers its functions by hand under a private `ThinkThen::Native` module. A Ruby test compares the loaded module's public names with one pinned list.
13. **No Docker, and a pinned toolchain in its own cache.** Claude decided on 2026-09-24 that a surface check must not depend on Docker. The gate ladder runs on any developer machine with the pinned toolchains. A container adds a daemon and an image nobody pins. The shared rules on main (`bced9c4d`) record the same rule for every surface. Toolchains live under `~/.cache/thinkthen-toolchains/`. They never live in the product's answer cache `~/.cache/thinkthen`. `status` measures that folder (`specification/recording.md`). The one-time download of the public Ruby and libyaml source archives is setup. No gate runs it. It needs no further authorization. Three conditions make it setup: every archive is pinned by SHA-256 in the repository, the setup script refuses a mismatch, and every gate runs offline afterwards. The record logs the fetch with its URLs, sizes, and hashes. Ian can overturn each of these three.
14. **`ThinkThen::Engine` carries the section 5 settings.** The shared rule at `446a4d6b` has every surface expose the ADR 0017 section 5 settings on its engine value, and tests set width through that public setting with no hidden hook. This follows 0105 decisions 11 and 12.
   - *Spelling.* `ThinkThen::Engine.new(base_url: nil, model: nil, width: nil, max_requests: nil, cache: nil, cache_bytes: nil)`. Keywords are how Ruby spells the other settings here (`deadline:`, `cancel:`, `on:`). Each keyword maps to one 0084 `EngineBuilder` member: `base_url`, `model`, `width`, `max_requests`, `cache_at`, and `cache_bytes`. `cache: false` maps to `no_cache`. An omitted keyword stays omitted, so an omitted width stays implicit under 0077. There is no `api_key:` keyword. ADR 0017 section 5 gives libraries the key from `THINKTHEN_API_KEY` alone, and that keeps the key out of Ruby objects and their `inspect`.
   - *The environment.* `Engine.new` calls `EngineBuilder::from_env()` from the 0084 amendment at `f19cf437`, then applies each given keyword as a setter. The environment's address then holds unless `base_url:` overrides it. An error from it maps through the one kind table.
   - *Checks.* A boolean or non-integer `width:`, `max_requests:`, or `cache_bytes:` raises `UsageError`, as decision 7 checks `deadline:`. `width: 0` and `width: 33` raise `UsageError` from the builder (0086, R4-12). A second explicit width that differs from the process cap raises the 0077 conflict through the kind table.
   - *Methods.* An `Engine` value has the ten verbs, `decide_many`, `details`, `usage`, and `with_tick` as methods with the module functions' signatures. It wraps `thinkthen::Engine`. That type is `Clone + Send + Sync`, and each worker takes a clone. One implementation serves both spellings.
   - Ian can overturn the class spelling, `cache: false`, and the missing `api_key:` keyword.
15. **Amendment of 2026-09-24: no test or plant can reach a paid backend.** The shared rule on main at `d783ab6b` forbids it. Decision 14's seed test had a plant that started from `EngineBuilder::new()`. That plant ignores `THINKTHEN_BASE_URL` and sends to the built-in address, the paid vendor's endpoint. The test and its plant leave, and the cache-folder test under "Other acceptance" replaces them, following 0105 change 13.
   - *The key.* `check.sh` unsets `THINKTHEN_API_KEY` before its first step. `cargo test --lib`, the conformance runner, and the slide sample therefore never see the real key. `tests/backend.rb` builds each child's environment from that scrubbed one. It sets a fake `THINKTHEN_API_KEY` only together with the loopback `THINKTHEN_BASE_URL` of the child's own backend.
   - *The address.* Every test and plant that builds an engine has a loopback address. It comes from `THINKTHEN_BASE_URL` through `EngineBuilder::from_env()` or from an explicit `base_url:` keyword. A Rust unit test builds no engine that sends. A plant that changes how the engine is built keeps a loopback `base_url:`. The test counts its sends on the loopback backend.

## The toolchain

Observed by command on 2026-09-24 on this Linux machine (Ubuntu 24.04, glibc 2.39): no `ruby` on `PATH` and no sudo without a password. Later the same day `/usr/bin/ruby` 3.2.3 appeared from a system package (amended 2026-09-24, change 1). Rust 1.93.1 is installed, matching the root `rust-toolchain.toml`. `clang`, `llvm-18-dev`, and `/usr/lib/llvm-18/lib/libclang.so.1` are present. So are `build-essential`, `libssl-dev`, `zlib1g-dev`, `libffi-dev`, `libreadline-dev`, and `libgmp-dev`. `libyaml-dev` is absent. Every crate in the tag's Ruby lock is in the cargo cache.

**Pins.** One file, `libraries/ruby/toolchain.env`, holds both URLs and both hashes. `setup-ruby.sh` and `check.sh` both read it.

- Ruby 3.4.11: `https://cache.ruby-lang.org/pub/ruby/3.4/ruby-3.4.11.tar.xz`, SHA-256 `f79c6e789ce4f30f77c88a40b23b93e2547c512a843dc17db27ab1f5cc66f4e4`. The hash comes from the official Ruby image's metadata (`RUBY_DOWNLOAD_SHA256` in the retired builder image). Before the first fetch, the builder checks it against the 3.4.11 release page on ruby-lang.org.
- libyaml 0.2.5: `https://pyyaml.org/download/libyaml/yaml-0.2.5.tar.gz`. This release tarball ships a `configure` script. libyaml publishes no checksum file. Experiment 256 fetched the archive into `~/.cache/thinkthen-toolchains/ruby/archives/`. The hash `c642ae9b75fee120b2d96c712538bd2cf283228d2337df2cf2988e3c02678ef4` matches buildroot's `package/libyaml/libyaml.hash`, and experiment 256 verified it. The builder also pins the SHA-512 from Alpine's `APKBUILD` for the same file, and setup checks both. A disagreement stops setup.

**Setup.** `libraries/ruby/setup-ruby.sh` runs by hand, once on each machine, with the network. No rung runs it. The built prefix is tied to its path and to the host's glibc, so it never moves between machines.

- It stores the two archives in `~/.cache/thinkthen-toolchains/ruby/archives/` and refuses either on a hash mismatch.
- It refuses to overwrite a complete prefix at `~/.cache/thinkthen-toolchains/ruby/3.4.11/`.
- It builds in a temporary folder beside the prefix with `--enable-shared --enable-load-relative --disable-install-doc --with-libyaml-source-dir=…`. Building libyaml from source avoids sudo. Psych needs it for `gem build` and for the bundled minitest gem.
- It fails when `ruby -rpsych -rzlib -ropenssl -rminitest -e1` fails. Ruby's configure skips a missing extension with only a warning. Fiddle is left out, because the binding does not use it.
- It writes the stamp `thinkthen-toolchain.stamp` with both hashes and the configure line. It renames the folder into place only after these checks pass.

**The check's probe.** `check.sh` uses only that prefix and never a `ruby` found on `PATH`. It compares the stamp with `toolchain.env` and checks that `ruby -v` names 3.4.11. It runs the pinned-Ruby guard of amendment change 1 and puts the prefix's `bin` first on `PATH` for rb-sys. It sets `LIBCLANG_PATH` to the newest `/usr/lib/llvm-*/lib` holding `libclang.so.1`. It puts the prefix's `lib` on `LD_LIBRARY_PATH` for the shim's unit tests. A missing or mismatched prefix, a missing libclang, or a missing crate prints "not run" and never "pass" (R6-2). The line names the one command to run on this machine, once, with the network: `libraries/ruby/setup-ruby.sh` or `cargo fetch --locked --manifest-path libraries/ruby/Cargo.toml`. On a host other than Linux, `check.sh` prints "not run: Linux only at 0.1".

**Options weighed.**

- (a) Chosen: the source-built Ruby above. Cost: one fetch per machine and one script. No Docker, sudo, or network in any gate.
- (b) Ubuntu's packaged Ruby through apt. Ubuntu 24.04 ships Ruby 3.2, below the gemspec's `>= 3.4` floor, and the install needs sudo. Rejected.
- (c) Keep the Docker builder image. Decision 13 rules it out. It also fails three checks. Its base tag `ruby:3.4-trixie` floats (R1-29). The image pins its own Rust toolchain apart from the repository's (R4-8, R7-10). The check would start a container on every run. Rejected.
- (d) Copy Ruby out of the cached image. It was built on Debian trixie, whose glibc 2.41 is newer than this host's 2.39. Rejected.
- (e) A prebuilt `ruby/ruby-builder` tarball. It needs no compile, but it has no published checksum. Rejected.
- (f) `ruby-build`. It does the same work as (a) and adds a tool. Rejected.

## How the tests run

These follow the shared rules.

- **One backend and one cache per test.** One helper, `tests/backend.rb`, starts a fresh 0092 backend from the binary the rung builds. It gives each test its own `THINKTHEN_BASE_URL` and a new `THINKTHEN_CACHE` folder under `Dir.mktmpdir`. `default_engine()` reads both once per process, so a test that calls the engine runs its calls in a child `ruby` from the pinned prefix. One `release` never reaches another test.
- **Arms from 0117.** Held tests use 0092's held arm with 0117's `round` and `wait N` lines. A timed release uses 0117's delay arm. Every "once the count reads N" step is `wait N`. That line prints within 5 s. A plant then fails an assertion and never waits out the file's bound. This ticket adds no arm and opens nothing under `conformance/`.
- **Counts.** "Counted" means the test's own backend's `count` line. A zero-send assertion compares the count before and after the call.
- **Width.** A test that needs parallel requests builds `ThinkThen::Engine.new(width: 8)` in its child and reads W from that setting. No test relies on the default width or a literal 4. An open issue asks whether the default should drop to 3.
- **Workers.** No test hook counts workers. A test reads the child's thread count from `/proc/self/task`. Linux gives that folder. A detached worker has ended when the count is back to its value before the call.
- **Bounds.** `check.sh` runs each test file under `timeout 120` as a backstop.
