# 0319: Build and prove the command-line release on this host

Status: ready for ticket review. Plan: `sdlc/planning/cleanup-2026-09-30.md`, step 8. Issue: `sdlc/issues/2026-09-25-release-and-install-for-0-1.md`, items 1, 2, 11 and 13.

## Outcome

One offline command builds this host's command-line release files and proves them the way a user meets them. The files are the static command archive, the first-run sample, and a `.sha256` beside each. The proof checks each checksum and the version line. It installs through `install.sh` from a loopback server into a clean prefix. It runs the README's no-key replay block against the installed binary and sends nothing to any backend. Nothing is tagged, released, or published.

## Evidence

- Starts from: `origin/main` at `ccf40bfb7`. Ticket 0128 landed `install.sh` and its loopback edge table (`installer-test`), `release-pack` with the `command` and `first-run` parts, `release-smoke`, and `release-workflow installer-smoke`. Four gaps remain. `release-smoke` demands all nine families, so it cannot prove a command-only folder. - Keeps: the nine-family `release-smoke DIR`, `--source-packages`, the `surfaces` rung call, `release.yml` and its workflow checks, `install.sh` and its site copy, `installer-test`, version `0.0.1`, and ticket 0128's outward-step rule.
- Changes: `release-smoke --command DIR` requires exactly the command archive for this host's musl or Darwin target, `thinkthen-first-run.tar.gz`, and their two `.sha256` files; anything extra or missing fails by name. That mode checks both checksums, scans the unpacked release binary for `$HOME` and the panic probe, runs the command check, then runs `release-workflow installer-smoke DIR`. The command check reads the README's no-key block, the first fenced block holding `--replay recording`. It replaces the block's one sample line with unpacking the sample and entering its folder. Today that line is `cd demos/27-test-with-no-network`; after the release it is a `curl` line. The block must hold exactly one of the two (proposal for review). New `sdlc/scripts/release-smoke-command-test`, run from `lint`, feeds planted folders with a fake `thinkthen`. The build record lists one real run of `release-pack x86_64-unknown-linux-gnu OUT command first-run` and `release-smoke --command OUT`, with both archive SHA-256 values.
- Proof: the planted table pins the exit code and message of each case: a good folder, a missing sample, an extra file, a wrong checksum, a binary reporting another version, a README with zero sample lines, one with two, a first-run answer other than `true`, a home path in the binary, and a block that reaches the loopback backend. Each failing case fails on its own fault. The good case fails against today's `release-smoke`. The real run prints `thinkthen 0.0.1` from the loopback install and `true` from the README block, with zero backend requests. Focused checks: the new test, `sh -n` on each changed script, and `lint`.
- Defers: Linux ARM64 and both macOS targets, which need their runners or the M5. A command-only mode in `release.yml`. The README install section naming the download script and Homebrew, which lands with the release commit so no page names a missing install. The version bump. The tap formula. Tagging, the draft release, and publishing, each needing Ian's authorization under ticket 0128.
