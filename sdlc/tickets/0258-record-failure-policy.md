# 0258: Let annotate finish after an isolated missing pointer

Status: proposed design for fresh Medium review. [ADR 0104](../planning/adr/0104-record-failure-policy.md) defines the bounded contract. No source, public page or original issue changes are approved by this candidate. The coordinator may accept routine details within Ian's recorded outcome; Ian can overturn them.

## Outcome and bounded build

An explicit `annotate --jsonl --details --batch 1 --on-error continue` streams a separate `thinkthen.record-error/1` JSON row when one record lacks a question-set `on` pointer, then judges later records. Its row names the missing pointer and input position without printing evidence or a fabricated judgment. The complete run exits 7 and reports the skip count once. Default ordered-prefix stop, partial logical failure exit 6, later terminal failure precedence and actual-send accounting remain. A question name that shadows an input member works in `--details` while preserving the input under `input`; bare mode still refuses it. The annotate page explains shared-group partial failure, wholly failed group stop, request economy and group edit/rerun cost.

The flag belongs only to annotate and only to the exact JSONL/details/batch-1 combination. A malformed record, a failed group, any whole failed batch and every other record verb keep current stop behavior. This ticket completes original register 65 and 66, plus register 68's page criterion. It addresses register 43 for a concrete isolated local poison record, but **does not close register 43**: broader malformed-record and backend/batch isolation remain explicit work. The accepted [preparation](../records/2026-09-28-record-failure-preparation.md) retains all four original register criteria and their local evidence.
