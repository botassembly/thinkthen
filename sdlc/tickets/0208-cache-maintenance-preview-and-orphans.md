# 0208: Preview cache maintenance and remove abandoned partials

Status: proposed for fresh design review; no runtime or public output change is accepted by this draft. Owner: Codex Sol Medium, codex-5. A fresh independent reviewer decides whether this contract is ready to build.

## Outcome and authority

Give an operator a read-only preview of explicit `cache prune` selection, and let explicit prune reclaim dot-prefixed temporary entries left by an interrupted writer. Keep a current writer's temporary name and every valid final entry safe under the existing folder gate. Report temporary storage without calling an in-flight file an orphan. Register 47 and 98 in local experiment 284 motivate this batch; ticket 0124 deferred preview, and ticket 0163 expressly excluded temporary files. Neither register's proposed fix is an accepted rule. This ticket proposes one for review.

## Evidence

- **Starts from:** main `13febe404838a7bd6a6ab2bfcd83fdffd72ffcd2`; register details `experiments/284-issue-register/47-*` and `98-*`; landed tickets 0124 and 0163; [preflight](../records/0208-cache-maintenance-preflight.md). `recorder.rs::prepared_write` creates `.<pid>.<attempt>.<digest>.json` while it holds a shared folder gate. `WritePermit` cleans on ordinary completion, cancellation and drop, but process death cannot run that cleanup. `cache_prune.rs::scan` ignores every non-digest name. `run_at` has selected final entries before deleting them; `status` calls the same scan.
- **Keeps:** `cache prune DIR` is explicit and currently commits immediately. Age and reply-model selectors form a union, then allocated-size trim removes the oldest modification time first, digest name breaking ties. The alias and unknown-model refusals run before any deletion when at least one good final entry exists; an empty good set retains today's no-refusal behavior. Bad digest-named entries stay in place and get name-only diagnostics. An active digest lock is skipped. Valid final-entry counts and bytes exclude temporary files. No automatic expiry, new parser, provider call or implicit prune is added.
- **Changes:** Propose `--dry-run` for a read-only selection report. A normal explicit prune also removes recognizable, regular temporary files after the gate excludes cooperating writers; it reports their count and allocated bytes separately. `status` reports recognizable temporary files even when one may be live. These outward-facing forms remain subject to design review.
- **Proof:** After acceptance, existing `default_cache/prune.rs` and `status.rs` CLI helpers, a held loopback writer, and one planted content-bearing temporary file establish exact preview, committed cleanup, live-writer preservation, final-entry bytes, sorted name-only output and no send by maintenance. Keep the existing alias, unknown-model, union, ordering, bad-entry and late-failure checks. No test-only hook, repeated race or broad port suite.
- **Defers:** Model freshness 09/23/105, backend binding 10, usage-lock wait 31 and folder authority 40. This design does not claim any of them fixed.

## Proposed behavior for review

1. `thinkthen cache prune DIR --dry-run` takes the same `--older-than`, `--answered-by-other-than` and `--max-size` arguments as prune. It scans and validates once under the existing exclusive folder gate, applies the same model refusals, selector union and size trim, and writes no file or lock name. It reports selected valid entries before digest-lock skips, because another process can change a lock before a later committed run. Its first stdout line is `selected N entries and B bytes; K entries and C bytes unselected`; `N/B/K/C` cover valid final entries only. It then prints `selected NAME` for each selected digest name, in current deletion order. When temporary candidates exist, it adds `selected T temporary files and U bytes` and `selected temporary NAME` lines in lexicographic name order. Diagnostics about bad final entries remain sorted, name-only and on stderr after a successful preview. A refusal prints no success or bad-name lines and changes nothing. A preview is a snapshot, not a transaction token or promise that a later prune will remove the same names.
2. Without `--dry-run`, `cache prune DIR` retains its current immediate final-entry deletion and exact first summary line. After final-entry selection it removes recognizable temporary files and adds `removed T temporary files and U bytes` only when `T > 0`; temporary names use `removed temporary NAME` lines, sorted by name. A temporary-file removal or directory-sync error is a local failure and can leave a deleted prefix, like today's final-entry failure. The design review should decide whether to print names on committed cleanup or keep that output count-only; no private file content enters either form.
3. A recognizable temporary name has exactly the writer's current shape: a leading dot, decimal PID, decimal attempt, 64 lowercase hex digest, and `.json`. PID and age are *syntax*, never abandonment evidence. Only an immediate regular file of that name is a candidate; symlinks, directories, other dot names and `.locks` are ignored and never followed or removed. Count its allocated bytes by the same host-specific `allocated` helper used for final entries. It need not parse as a completed recording; an interrupted write can be empty or incomplete. The exclusive folder gate is the abandonment proof for cooperating writers: every current writer holds the shared gate from preparation through cleanup, and process death releases it. A hard-linked partial left after a final install may share the final inode; unlinking its temporary name leaves the final name and bytes intact. The tool makes no claim against a separate process that changes a named folder without taking this gate.
4. `status` keeps its shared, read-only gate and adds `cache_temporary_entries` and `cache_temporary_bytes` in text and `cache.temporary_entries` and `cache.temporary_bytes` in JSON. These count recognizable regular temporary files, whether in flight or abandoned. Zero means none in an existing folder; absent cache path follows the current nullable cache-count shape. It does not name them or read their contents. It does not call them orphans. Existing `cache_bad_entries`, `entries` and `bytes` retain their meanings. The page and status tests change with the code if this shape is accepted.

## Safe ordering and limits

The selected final-entry list is computed only after the full digest-entry scan and existing alias/unknown-model guards. Temporary candidates do not change that list, its model guard, or the max-size calculation. A preview makes no temporary or final deletion. A committed prune takes the exclusive gate before scanning and holds it through final and temporary unlinks and directory sync. The shared gate in `Recorder::gate` covers `prepared_write`, live work and `WritePermit` cleanup. Existing digest locks still protect final-entry deletion; they are not a substitute for the folder gate. A status shared gate can overlap a live writer, so its temporary count is observational only.

This mechanism depends on the current process-wide directory lock already required on each supported host. Do not substitute `/proc`, PID existence or an mtime delay; PID reuse, suspended work and host differences make them unsafe. Existing 0163 no-follow/nonblocking `open_entry` protects final-entry reads on Unix and uses a reparse-point flag on Windows; that helper is not a general proof of identity for temporary unlinks. The accepted `cache_prune` scan already trusts the named folder against other writers, and this ticket cannot promise safety against hostile external renames. If a supported host cannot provide the existing shared/exclusive gate reliably, stop implementation for that host and return a concrete design question; do not silently delete there.

## Decisions pending independent review

1. Is additive `--dry-run` enough for register 98 now that the unknown-model guard landed, or should default `cache prune` become preview plus an explicit commit flag? The latter changes ticket 0124 and the settled recording page's immediate explicit-prune behavior, so this draft recommends additive `--dry-run` and leaves the stronger confirmation choice open. Do not mark register 98 closed from this design alone.
2. Approve the temporary name grammar, the gate-based abandonment rule and count/byte/status labels. Decide whether committed cleanup prints each temporary name or only its count. Exact strings above are proposed, not already implemented.
3. Does a folder with an unsafe object under an exact temporary name need a separate diagnostic/count, or should it remain an ignored unknown name? This draft leaves it untouched and uncounted, matching current treatment of non-digest names, but no cleanup claim should cover it.

## What the preparation taught us

The 0163 follow-on memo correctly grouped hidden partials with prune preview but was written before 0163 and the cache-setting Quick Fix landed. It called C's off switch absent and treated accepted source as pending; current C settings already accept `false`, and 0163 landed at `f7a56989`. More importantly, a PID or old mtime looked like a cheap orphan test in register 47, while the existing shared/exclusive folder gate is the actual safety mechanism for cooperating writers. Preparation now names every parent/adapter file and measures 463/500 and 441/500 headroom before a code estimate. A preview must state that selected counts precede active digest-lock skips and later runs rescan, or its output would promise more than the current algorithm can deliver.
