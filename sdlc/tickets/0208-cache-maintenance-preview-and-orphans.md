# 0208: Preview cache maintenance and remove abandoned partials

Status: revised proposal for independent design review after `debf2159` returned REVISE; no runtime or public output change is accepted by this draft. Owner: Codex Sol Medium, codex-5. Ian must accept the new fields and destructive cleanup rule before implementation.

## Outcome and authority

Give an operator a read-only preview of explicit `cache prune` selection, and let explicit prune reclaim dot-prefixed temporary entries left by an interrupted writer. Keep a current writer's temporary name and every valid final entry safe under the existing folder gate. Report temporary storage without calling an in-flight file an orphan. Register 47 and 98 in local experiment 284 motivate this batch; ticket 0124 deferred preview, and ticket 0163 expressly excluded temporary files. Neither register's proposed fix is an accepted rule. This ticket proposes one for review.

## Evidence

- **Starts from:** main `13febe404838a7bd6a6ab2bfcd83fdffd72ffcd2`; register details `experiments/284-issue-register/47-*` and `98-*`; landed tickets 0124 and 0163; [preflight](../records/0208-cache-maintenance-preflight.md). `recorder.rs::prepared_write` creates `.<pid>.<attempt>.<digest>.json` while it holds a shared folder gate. `WritePermit` cleans on ordinary completion, cancellation and drop, but process death cannot run that cleanup. `cache_prune.rs::scan` ignores every non-digest name. `run_at` has selected final entries before deleting them; `status` calls the same scan.
- **Keeps:** `cache prune DIR` is explicit and currently commits immediately. Age and reply-model selectors form a union, then allocated-size trim removes the oldest modification time first, digest name breaking ties. The alias and unknown-model refusals run before any deletion when at least one good final entry exists; an empty good set retains today's no-refusal behavior. Bad digest-named entries stay in place and get name-only diagnostics. An active digest lock is skipped. Valid final-entry counts and bytes exclude temporary files. No automatic expiry, new parser, provider call or implicit prune is added.
- **Changes:** Propose additive `--dry-run` for a read-only selection report. A normal explicit prune also removes recognizable, regular temporary files after the gate excludes cooperating writers; committed cleanup reports count and allocated bytes only. `status` reports recognizable temporary files even when one may be live. Unsafe temporary-shaped nonregular objects remain untouched and uncounted. These outward-facing forms await Ian's ruling after design review.
- **Proof:** After acceptance, existing `default_cache/prune.rs` and `status.rs` CLI helpers, a held loopback writer, and one planted content-bearing temporary file establish exact preview, committed cleanup, live-writer preservation, final-entry bytes, sorted name-only output and no send by maintenance. Keep the existing alias, unknown-model, union, ordering, bad-entry and late-failure checks. No test-only hook, repeated race or broad port suite.
- **Defers:** Model freshness 09/23/105, backend binding 10, usage-lock wait 31 and folder authority 40. This design does not claim any of them fixed.

## Proposed behavior for review

1. `thinkthen cache prune DIR --dry-run` is additive and takes the same `--older-than`, `--answered-by-other-than` and `--max-size` arguments as prune. The engine shares one scan/selection plan between preview and commit. Preview takes the exclusive lock on the already-open folder, but bypasses `try_acquire`, `opened_lock`, all lock-file creation, all unlinks and every directory sync. It applies the existing model refusals, selector union and size trim. It reports selected valid final entries **before** active digest-lock skips: first `selected N entries and B bytes; K entries and C bytes unselected`, then `selected NAME` for each chosen digest name in current deletion order. `N/B/K/C` cover valid final entries only. When `T > 0` recognizable temporary files exist, it adds `selected T temporary files and U bytes`, then `selected temporary NAME` in lexical order. `U` is their allocated byte total, separate from `B/C`. When `T = 0`, it prints no temporary line. Bad-final diagnostics remain sorted, name-only and on stderr after a successful preview. A refusal prints no success or bad-name line and changes nothing. Selection is a snapshot, not a promise that a later committed run will remove the same names.
2. Without `--dry-run`, `cache prune DIR` retains immediate final-entry deletion and its exact existing first stdout line: `removed N entries and B bytes; K entries and C bytes remain`. After final-entry deletion, it unlinks recognizable temporary names in lexical order. When `T > 0` were actually unlinked, it adds only `removed T temporary files and U bytes` as a second stdout line; no removed temporary names are printed. When `T = 0`, the entire successful stdout stays as it is today. Success is emitted only after the required folder sync completes. A late unlink or sync failure is Local, emits no success line and may leave a deleted prefix, as today's prune can.
3. A recognizable temporary name has exactly the writer's current shape: a leading dot, decimal PID, decimal attempt, 64 lowercase hex digest, and `.json`. PID and age are *syntax*, never abandonment evidence. After the final-entry scan and alias/unknown-model refusal, but before the first unlink, classify exact-shape names with no-follow metadata. A name gone at inspection is ignored; any other inspection error that prevents classification is Local and stops all deletion. Only an immediate regular file is a candidate. Symlinks, directories, other nonregular exact-shape objects, other dot names and `.locks` remain untouched and uncounted. Count candidate allocated bytes with the same host-specific `allocated` helper as final entries. A candidate need not parse as a completed recording; an interrupted write can be empty or incomplete. The exclusive folder gate is the abandonment proof for cooperating writers: every current writer holds the shared gate from preparation through cleanup, and process death releases it. A hard-linked partial left after a final install may share the final inode; unlinking its temporary name leaves the final name and bytes intact. A candidate that disappears **after** classification but before unlink is a late local failure under the existing prefix rule; the tool does not silently claim it removed that file. The tool makes no claim against a separate process that changes a named folder without taking this gate.
4. `status` keeps its shared, read-only gate and adds `cache_temporary_entries` and `cache_temporary_bytes` in text, adjacent to `cache_bad_entries`, and `cache.temporary_entries` and `cache.temporary_bytes` in JSON. These count recognizable regular temporary files, whether in flight or abandoned, using allocated bytes; unsafe nonregular objects remain uncounted. Zero means none in an existing folder; absent cache path follows the current nullable cache-count shape. A name gone at inspection is ignored; another inspection error that prevents classification is a local status failure. Status does not name temporary files or read their contents, and it does not call them orphans. Existing `cache_bad_entries`, `entries` and `bytes` retain their meanings. The page and exact status tests change with the code if Ian accepts this shape.

## Safe ordering and limits

The selected final-entry list is computed only after the full digest-entry scan and existing alias/unknown-model guards. Temporary discovery/classification follows those guards and precedes **every** unlink. Temporary candidates do not change final selection, model refusal or the max-size calculation. Preview takes only the existing directory gate and never enters the digest-lock or mutation path. Commit deletes selected final entries in accepted modification-time/digest order, skipping active digest locks as today, then deletes classified temporary files in lexical order and syncs the changed directory before returning success. The shared gate in `Recorder::gate` covers `prepared_write`, live work and `WritePermit` cleanup. Existing digest locks still protect final-entry deletion; they are not a substitute for the folder gate. A status shared gate can overlap a live writer, so its temporary count is observational only.

This mechanism depends on the current process-wide directory lock already required on each supported host. Do not substitute `/proc`, PID existence or an mtime delay; PID reuse, suspended work and host differences make them unsafe. Existing 0163 no-follow/nonblocking `open_entry` protects final-entry reads on Unix and uses a reparse-point flag on Windows; that helper is not a general proof of identity for temporary unlinks. The accepted `cache_prune` scan already trusts the named folder against other writers, and this ticket cannot promise safety against hostile external renames. If a supported host cannot provide the existing shared/exclusive gate reliably, stop implementation for that host and return a concrete design question; do not silently delete there.

## What the preparation taught us

The 0163 follow-on memo correctly grouped hidden partials with prune preview but was written before 0163 and the cache-setting Quick Fix landed. It called C's off switch absent and treated accepted source as pending; current C settings already accept `false`, and 0163 landed at `f7a56989`. A PID or old mtime looked like a cheap orphan test in register 47, while the existing shared/exclusive folder gate is the actual safety mechanism for cooperating writers. Preparation named every parent/adapter file and measured 463/500 and 441/500 headroom. Review of `debf2159` found that it still left three public choices open, did not require preview to bypass `try_acquire` and lock-file creation, and had not fixed temporary classification before the first unlink. The revised proposal now sets one public form, makes selected counts explicitly precede active digest-lock skips, and requires an actual partial-exists assertion at the held-writer event. Ian's acceptance and host-specific proof still remain before implementation.
