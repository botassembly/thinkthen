# 0248: Skip an unchanged retry-sidecar replacement

Status: COMPLETE.

Opened as: 2026-10-11. **accepted and integrated after fresh High code review of `557d01a7`**. The [build record](../records/0248-build.md) gives focused proof and retained limits. The independently reviewed [timing record](../records/0248-timing.md) closes the original measurement and safe-skip request with explicit limits.

## Outcome and boundary

For an ordinary usage delta that changes no retry count, keep an already validated retry sidecar untouched, or keep it absent for a clean zero-retry month. Persist the changed five-member legacy monthly base exactly as today. A retry increment still writes and directory-syncs that base **before** writing and directory-syncing the changed retry sidecar. This narrowly amends [ticket 0235](0235-usage-compatibility-and-transient-backend-failures.md)'s sentence “for each ordinary new current-month delta ... then do the same for the retry sidecar”: the sidecar step is conditional on a changed absolute retry total **after** all validation, checked arithmetic and required migration. It does not amend the schema, file modes, old-reader compatibility, historical snapshots, migration order, warning/corruption policy, or the accepted possibility of interrupted retry undercount. Ian or the coordinator may overturn this conditional-write choice.

The [filed issue](../issues/closed/2026-09-28-usage-file-write-adds-50-ms-per-command.md) asks to measure the per-process write and decide whether work can be skipped or deferred without losing counts. The reported 50 ms is a whole-command observation on an older named build, not this change's promised saving. Ticket 0248 addresses a source-demonstrably redundant operation. The later bounded comparison in the timing record supplies that observation; the coordinator closes the original Asked criterion while retaining the older 50 ms and concurrent observations as unverified by this experiment.

## Design

Keep `storage::update`'s sequence through `scan(path)`, `old`, `total`, `next = old.checked_add(delta)` and prospective aggregate checked addition. Directory and `.lock` creation may precede arithmetic refusal, as current source already allows; **month and sidecar mutation must not**. Under the stable exclusive lock, `scan` still opens and verifies every recognized month and sidecar, rejects malformed, foreign, future, orphan, unsafe or inconsistent state, and distinguishes clean missing sidecar from contaminated missing sidecar. Migrate **all** contaminated months sidecar-first and old-reader-base-second, including prior months. Then do the current-month initial lock/directory sync where required and atomically replace/sync its legacy base. Only if `next.retries != old.retries`, atomically replace/sync its retry sidecar. Do not infer unchanged from its bytes alone before validation. Do not skip migration or a sidecar needed by a contaminated month merely because this delta has zero retries.

| Validated state at this update | Ordinary sidecar action | Reason |
| --- | --- | --- |
| Clean month, sidecar absent, `old.retries = next.retries = 0` (including a new month) | Leave absent | The current reader reads zero; old reader ignores sidecars. Base still changes and syncs. |
| Clean month, sidecar present, unchanged retry count (zero or positive) | Leave same file/inode | `scan` has verified its identity, mode, schema and value. A retry count is not re-earned by an unrelated base delta. |
| Any current month with an increased retry count, including a retry-only delta | Base first, then sidecar, with each temp-file sync, rename and directory sync | Preserve 0235's interrupted-write and old-reader rule. Do not skip the base when only retries changed. |
| Contaminated current or prior month, with no sidecar or a matching transitional sidecar | Perform every needed migration first; then apply the ordinary rule to the current delta | Retry-extended source remains authoritative until its projection; an absent sidecar is not a clean zero. |
| Invalid, unsafe or conflicting recognized file; current or aggregate overflow | Refuse before any month/sidecar mutation | Preserve the exact fixed error/warning and existing bytes. Directory or lock creation may already have happened. |

An immutable old writer can run only after this writer releases `.lock`; it advances the five-field base and does not touch a retained sidecar. The next new writer scans both again. A crash before base directory sync may leave the prior base or the new complete base; the untouched validated sidecar keeps its prior retry total. After a no-retry base directory sync, the new base is durable and the unchanged sidecar already represents the final retry count, so no second commit point is needed. A changed-retry write keeps 0235's base-first/sidecar-second crash table and possible retry undercount. A failed base replacement keeps the old durable state and warning; a changed-retry sidecar failure after base sync keeps the durable base, warns once and latches persistence failure. An omitted unchanged-sidecar write cannot silently suppress a corrupt-sidecar warning because `scan` runs before the omission.

The selected file identity is the verified path and object observed by `scan` while the cooperative stable lock is held; retain its verification and private-folder trust assumptions. The skip does not authorize ignoring a sidecar that appears in the recognized name set, unlinking a lock, or repairing externally changed bytes. A party with direct write access to the folder can change trusted answers/counts outside this lock, as the existing trust model already states; this ticket makes no new cross-process authority claim.

## Build and proof

1. Begin red: in an isolated private fixture, a clean no-retry update currently creates `retries-YYYY-MM.json`; a positive-retry sidecar currently changes `(dev, ino)` after an unrelated no-retry delta because `replace` renames a fresh temporary inode over it. Assert both the new absence and stable identity. The old code must fail. Check base counts and exact retry count alongside the inode, so the test cannot pass by skipping the whole update. Use Unix `MetadataExt`; do not add a production hook or assume byte equality proves no write.
2. Pass with a small branch around the ordinary `write_retry` call in `storage.rs`, after the existing migration and base write. Keep `replace` and `scan` unchanged. A retry increment, including a retry-only test delta, must still create or replace the sidecar and report exact counts. A second no-retry update must preserve a positive sidecar's identity. Test a transitional current month and a contaminated older month so the optimization cannot suppress migration.
3. Migrate the nearest existing usage tests deliberately. `usage/tests.rs` is 480/500 nonblank lines; put new cases in a private child module and keep edits to the parent small. Its existing directory-count assertion expects a zero-retry sidecar; change it to assert the intended absence. Its migration setup removes sidecars created by zero deltas; make those removals conditional or seed a retry only where a sidecar is part of the intended setup. Its aggregate-overflow and strict-sidecar fixtures must deliberately seed a positive retry sidecar so they still test unchanged bytes and unsafe sidecar refusal. Its generic `Stage::RetryWrite` case must mark a **retry**, while other stages keep their own failing boundary. Preserve the existing real corruption, sidecar-failure and overflow regressions. `storage.rs` is 282/500 nonblank; `usage.rs` is 412/500. Measure the source ratchet after the build and account for any growth.
4. Reuse experiments 346/347's immutable pinned reader and exact disposable sequence: a contaminated 100 requests/7 retries → new call 101/7, which **migrates and creates** the sidecar → old call 102/7, which leaves that sidecar alone. Verify old `status` reads the five-field monthly file and new `status` retains seven. Separately, on an already clean month with a validated positive sidecar, a no-retry new update must retain its inode. The accepted raw bytes in local experiment 347's `transcript.json` are expectations, not files to rewrite. Exercise a clean first no-retry call, later retry, all-month migration, corrupt/unsafe sidecar refusal, current and aggregate overflow, and injected base/changed-sidecar failures with isolated 0700/0600 folders. A no-retry update with an armed `RetryWrite` fault should succeed **only after** `scan` validates all recognized state; a changed-retry update should still hit that fault and warn. Keep the strongest existing tests; do not duplicate the entire 0235 matrix.

Run focused `cargo fmt --check`, the selected usage unit cases and closest CLI/default-cache status cases, repository policy and measured ratchet. A Unix inode assertion is a local filesystem proof, not an estimated latency benefit. After functional correctness and a reviewed build, one bounded isolated before/after observation may compare clean first write, existing sidecar and lock-contention setup on exact binaries. Report its raw operation/timing conditions; do not run a saturation campaign or infer a 50 ms gain. No provider call, shared user folder, paid ledger or broad surface suite is needed.

## Stop and routing

Stop and return to design review if skipping the sidecar requires bypassing `scan`, a new marker/journal, a weaker file or directory sync, a changed old-reader shape, an unjoined writer, or a new public setting/dependency. If the inode proof cannot distinguish the old path on the selected filesystem, use another real filesystem observation rather than a test-only production hook or a byte-only assertion. Root grants the runtime claim after High design ACCEPT. A new independent code review checks the final source, test-boundary proof, retained 0235 protocol and any raised ratchet before landing. Root owns the issue's priority, closure and plan count.

## What the build taught us

Two outside-in filesystem cases first failed on the previous code: a clean zero-retry call created a sidecar, and an unrelated call reached the retry-write fault despite an unchanged retry total. The conditional after the synced base write makes both pass without bypassing scan or migration. Existing tests had assumed every zero-retry update created a sidecar; their fixtures now assert absence or seed a real retry where they test sidecar identity, corruption or fault behavior. A separate update refusal proves an invalid sidecar is still examined before a no-retry base mutation. Keep fixture setup aligned with the actual persistence rule rather than weakening the named assertion.

The focused proof is recorded in [the build record](../records/0248-build.md): 18 usage unit cases and six status integration cases pass, including changed-retry, migration, overflow, unsafe-state and injected-failure paths. The immutable old reader and current binary, against one loopback fake in an isolated folder, retain the accepted 100/7 → 101/7 → 102/7 sequence. This establishes file and old-reader behavior, not a current command-latency gain. The original timing question remains open.
