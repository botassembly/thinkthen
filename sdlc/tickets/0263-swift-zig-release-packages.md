# 0263: Pack Swift and Zig source with one matching C archive

Status: design candidate for fresh independent review. This ticket authorizes the bounded local package build only after design acceptance. The original Swift and Zig release issues remain open.

## Outcome and retained behavior

One clean, committed Linux x86-64 source pin produces a fresh versioned C header/shared/static archive and versioned SwiftPM and Zig source archives in one local `release-pack TARGET OUT c swift zig` invocation. Each wrapper archive names the exact C archive SHA-256. A strict preflight checks the three outer files, adjacent checksums, fixed-data manifests and exact selected-family inventory before either installed consumer starts. Fresh installed consumers compile public wrapper calls using only the two unpacked wrapper packages and matching unpacked C archive, then make three captured requests per host with the accepted five-text portable batch corpus. The existing source-mode gates, Swift 30-body and two-consumer receipts, Zig 42-body four-consumer receipts, J1, cancellation, package and privacy plants remain intact. This local proof does not publish an asset or qualify a release runner or another platform.

Use the existing `release-pack` staging/checksum functions, fixed-mode `release-go-cpp-pair` preflight, conditional `release-smoke` routing and `installed.sh` scratch rules. Add one literal `swift-zig` preflight mode, not another validator or generic package framework. Keep the default pack part list and `--reuse` behavior for established parts unchanged. Swift/Zig refuse `--reuse`, a wrapper-only command and a preexisting OUT C file as a substitute for a freshly built C part earlier in that same invocation. A clean committed tree and the pack receipt establish the source pin; a later checkout HEAD need not equal a valid archive manifest.

## Exact archive and identity contract

The C file remains `thinkthen-c-$V-$TARGET.tar.gz` with its current header, shared library/soname, static archive and pkg-config member. Name the wrapper files `thinkthen-swift-$V-$TARGET.tar.gz` and `thinkthen-zig-$V-$TARGET.tar.gz`, each with the packer's adjacent `.sha256`. The Swift archive contains exactly the integrated `LICENSE`, `README.md`, `Package.swift`, `Examples/main.swift`, `Sources/CThinkThen/module.modulemap`, `Sources/CThinkThen/include/thinkthen.h`, `Sources/ThinkThen/ThinkThen.swift`, and `Tests/TypeCase/main.swift`, plus `THINKTHEN-PACKAGE-INPUTS`. The type-case file is a declared SwiftPM target and must travel with the manifest. The Zig archive contains exactly `LICENSE`, `README.md`, `build.zig`, `build.zig.zon`, `examples/decide.zig`, `src/thinkthen.zig`, plus that manifest. Gate scripts, fixtures, ratchets, targets and caches remain checkout-owned tests, not product archive members. The Swift vendored C header must equal the freshly packaged C header byte for byte before packing; later installed checks recheck that relation. Preserve Zig's `build.zig.zon` path allowlist and its explicit `-Dnative` contract.

The packer writes the existing strict five-line manifest (`source_commit`, `target`, `version`, `c_archive`, `c_sha256`) into each wrapper stage. It calculates the C digest from the archive built in this invocation, not caller input. Extend `release-go-cpp-pair DIR swift-zig` to derive current version and host target, require exactly the selected three names and three sidecars, reject links and extra Swift/Zig/C family entries, verify exact outer checksum lines, require one manifest per wrapper, and compare the complete manifest as fixed data with the actual C file digest and common source commit. Check the exact expected wrapper member inventories and Zig package version before installed compilation. Other pair modes accept a full bundle containing Swift/Zig and vice versa. The helper neither evaluates manifest contents nor treats the digest as a signature or runtime ABI handshake. The build receipt records the source SHA, tool versions and exact inner/outer hashes.

`release-smoke` detects either Swift or Zig family before starting its backend, calls that same preflight mode, and routes each exact archive pattern before the broad command pattern. It gives each selected check both the wrapper artifact and validated C archive path. The established nine-family full-bundle requirement stays unchanged. A three-archive directory is a passing direct preflight baseline, not a passing full `release-smoke` bundle; Swift/Zig remain conditional in smoke until a later workflow ticket.

## Installed consumers and smallest proof

Add an installed-file selector to each `libraries/{swift,zig}/check.sh`, leaving its source-mode branch and full matrices unchanged. In installed mode, unpack both passed archives into fresh scratch, derive the current C exports from the unpacked header and shared library, compare the Swift vendored header with that C header, and check every loaded/linked native member against the archive member. Do not build debug C, use `libraries/c/target`, or copy wrapper product source from the checkout into the consumer. The checkout may supply only test-authored fixtures, accepted corpus and loopback backend. Swift first runs `swift build --package-path` on the unpacked package with the unpacked C prefix, then compiles its existing `Tests/fixtures/portable_batch.swift` against unpacked `Sources/CThinkThen` and `Sources/ThinkThen`. This validates SwiftPM's manifest and all declared targets while reusing the typed fixture for the public call. Zig builds its existing `Tests/portable_batch.zig` from a fresh test project whose local dependency points to the unpacked Zig package and whose `-Dnative` points to the unpacked C prefix. Keep the configured Swift/Zig executable paths through compilation and execution. Run with isolated caches and no source-tree fallback. The accepted `portable_batch.py` runners already compare the three captured raw UTF-8 request bodies with literal `portable-{1,2,3}.request.json` files as a multiset and count three sends; adapt their package/native path inputs rather than copying the oracle or writing another scalar consumer. Their typed returns expose five values but no per-row digest; the accepted C-door corpus remains the direct digest oracle. Existing mixed-answer host tests cover output permutation separately.

The positive baseline is a clean non-reuse pack of exactly C, Swift and Zig, its direct preflight and both installed selectors. Record archive hashes, C member hashes, unpacked product and compiled-consumer paths, actual tool versions, process exits, five returned values and the three complete captured bodies and send counts per host. Prove a missing Swift archive and sidecar, one corrupted Zig archive with unchanged sidecar, a separately valid but differently hashed C archive and sidecar, and one extra Swift family entry on copies of the passing baseline. Each invokes the same preflight before any selector starts and names its refusal. Route the missing-file plant once through actual `release-smoke` to show the preflight runs before backend startup. Do not infer measured zero sends from a script that never started a listener; record zero consumer starts there, or add a counted listener if claiming zero sends. Retain existing source matrices unless changed product/native input invalidates their accepted receipts.
