# 0214: Batch Python calls and return their run facts

Status: Proposed design for independent review. No runtime file is claimed or changed. Accepted 0212/ADR 0089 is an unlanded Rust design; 0209 is separately reviewed frame source. Owner: Codex.

## Outcome and authority

Deliver Batch G B12c after B12a: automatic maximal batching where the Rust planner permits it, a Python `batch` selector and shared `context` on eligible multi-record calls, and per-call facts on every Python verb without a second provider call. A one-record request with no context keeps its exact existing body and digest. Preserve the six Python error classes, stop precedence, `None` for an unsure answer, failed annotate markers, ordered partial results, and the existing pandas/Polars value schema and index. Ian's [batching](../issues/2026-09-26-batching-design.md) and [run-facts](../issues/2026-09-26-every-surface-should-give-back-run-facts.md) rulings govern the outcome. Accepted ADR 0089 governs the Rust carrier and bounded observer. [Proposed ADR 0091](../planning/adr/0091-python-call-facts-after-an-early-stop.md) isolates Python's early-stop receipt; it needs review before a runtime claim. J5's Enum, Literal, typed annotate and optional Pydantic work is later.

## Proposed Python contract

1. `tt.Engine(batch=...)` supplies the engine/environment tier, and each eligible call accepts `batch=`. Accept `"max"` or a positive non-bool integer, including 1; reject zero, negatives, floats and unknown strings as `UsageError` before a send. The typed call overrides the engine/environment tier, then a loaded decide question's batch, then `max`, exactly as `specification/settings.md` and 0212 define. `context=` is nonblank text supplied on one eligible many-record text call; it enters request digest as shared evidence, not question digest. A Series or frame is eligible when its Rust question path actually supports shared context; do not infer eligibility from the Python container alone. Refuse context on a single document, `recognize` or `relate`, or any other path the accepted Rust API refuses. Do not silently read a context file or apply it to an unsupported method. `batch=1` with no context preserves old recordings.
2. A Python `Call[T]` exposes `.value`, `.facts`, `.details` for **every** successful `Engine` method and matching module function except `question()` (a local constructor) and `usage()` (a process counter read). `.value` holds exactly the old return value: bool/None, choice/None, score, tags, list, rank/find dictionary, recognized object, edges, Series or frame. `details()` returns `Call[dict]` whose inner dictionary keeps the existing `thinkthen.result/1` shape. `decide_many`, `filter` and list `annotate` remain eager in Python; no new public iterator is needed merely because Rust internally yields `Batch<T>`. A Python caller can read the final Rust `Batch::facts()` only after consuming it fully or its terminal error. No Python `Call` pretends that a partial iterator is final.
3. `.facts` has `records`, `requests_sent`, `cache_answers`, optional `input_tokens` and `output_tokens`, `seconds`, and optional `model`. It is scoped to the one call, including filtered rows and in-flight attempts/replies joined at stop. Missing usage or model stays absent, never zero or guessed. `.details` is a read-only ordered sequence of dictionaries copied from ADR 0089's completed logical `Question` observations. Every entry has `index`, `question_sha256`, `requests`, `requests_sent`, `cached`, `failed_questions`, `url`, and either typed `answer` or typed `failed` cause; optional `member`, `stage`, `position`, `probabilities`, `confidence`, `usage`, and `model` appear only when the corresponding observation supplies them. `index` is zero-based input position, including a suppressed `filter` row. Annotate member and recognize stage/position distinguish multiple questions of one row. The sequence has no entries after an ordered stop, but `.facts` still includes actual later in-flight sends/replies through the join. Frame results carry these observations on `Call`, not as new frame columns; 0209's typed answer and separate `failed` column remain unchanged. The Python adapter may own a details collection proportional to the eager input; Rust keeps only bounded observer state.
4. A started ordinary failure raises the same `ThinkThenError` subclass and carries final `.facts` plus completed `.details` after Rust joins. A pre-call validation error has neither. Python's outer fast cancellation is distinct: proposed ADR 0091 gives `Cancelled.completion`, whose final facts/details become available after the detached worker exits. It retains the under-100-ms held-call stop and releases imported Arrow batches later. Do not claim final accounting at the early raise. The binding must not catch a signal handler's `SystemExit` as cancellation. Error `kind`, `retryable` and messages stay as today.
5. Adapt `Engine` and every module free function together. `rank(top=)` trims only `.value`; the call facts and details cover all judged candidates. `find(None)` remains a valid inner value, not an absent `Call`. `_column` rebuilds the Series **inside** `.value` and preserves pandas index/name and Polars dtype. `annotate`/`recognize` frame constructors likewise rebuild inside `.value`; the pandas `failed` column stays the fixed 0209 type. Where an eager Python invocation currently makes several Rust calls, particularly frame `each_named`, combine their **call-scoped** facts without a process-counter delta: sum records/sends/cache, sum tokens only when every relevant live reply reports usage, keep model only when one model is known for the whole invocation, and time the whole invocation. Include completed earlier calls and the failing Rust call's facts if a later row fails. Preserve final ordered detail and only one Python error. All Python and Rust extension constructors return the same wrapper, including `details` and error paths. Update the stub and README in the same build. No new Python runtime dependency; J5 adds optional Pydantic later.

## Dependencies, files and boundaries

The [preflight](../records/0214-python-batching-preflight.md) pins main `70875015`, accepted but unlanded 0212 `14cbd4b5`, frozen 0209 `d7d87adf`, and separate 0149/0157 work. B12a must land or a same-candidate Rust API branch must be integrated before Python source can compile against `Call<T>`, `Facts`, observer and `Batch::facts()`. 0209 should land before changing the frame adapter to avoid a second merge of its `failed` representation. 0149/0157 settings are separate: use the Rust public batch/context settings from B12a, then refresh every Python constructor against the landed configuration API. No public library setter is inferred from unlanded 0157.

Prospective Python files are `libraries/python/thinkthen/{__init__.py,__init__.pyi}`, `libraries/python/src/{engine,frame,worker,lib,input}.rs`, and perhaps a small carrier child registered in `src/lib.rs` if file headroom demands it; `asked.rs` only if question-file batch metadata needs binding exposure. Documentation is `libraries/python/{README,NOTES}.md` and the Python cells of `specification/settings.md`. Proof touches existing `libraries/python/tests/{conformance,test_stopping,test_release,test_door,test_pandas,test_inputs}.py` selectively, with any shared case or listener fixture claimed before editing. Exact source claims and file-size budgets require a refresh after B12a and 0209 land. No runtime claim follows from this design ticket.

## Small outside-in proof

Use the existing loopback conformance listener and Python door tests. One three-row `decide_many`/`filter` table checks default one-batch versus `batch=1` exact request bodies/digests, duplicate sharing, output order, filtered detail, request and token shares, and `.facts.records` independent of kept count. Reuse a current single-record captured fixture to pin byte identity; no paid call. One `choose` unsure and one failed named annotate member ensure null differs from failure in list and 0209 frame values while both expose the corresponding question detail. One Polars Series, pandas Series with nondefault index, and a frame test show facts outside the value and stable dtype/`failed` schema. An existing held-call stop case checks immediate `Cancelled`, no later send, a live completion receipt until release, then exact final facts, one terminal error and Arrow release. Existing Python conformance case 17 and the smaller affected port cases prove the same public answer and digest shape; no full port or load campaign per slice. Retain unaffected 0209 proof. Use strict relevant Rust/Python lint, policy/size, pages/tickets/diff after code; run only affected focused checks.

## Evidence

- Starts from: Main `70875015` binding paths and accepted but unlanded Rust design `14cbd4b5`/ADR 0089; the [preflight](../records/0214-python-batching-preflight.md) pins the distinct 0209 frame source `d7d87adf`.
- Keeps: Existing scalar, list, index, frame, null, failure, stop, cache and exact `batch=1` request identity contracts.
- Changes: Python gains eligible batch/context arguments and a result carrier with per-call facts and complete ordered detail; proposed ADR 0091 handles facts after an early stop.
- Proof: Selected shared cases, one exact listener-backed batch table, the existing door/index tests, and one held-call completion/Arrow-release boundary.
- Defers: J5 typing/Pydantic, other ports' result shapes, SQL facts, and any provider or load campaign outside a separately approved scope.
