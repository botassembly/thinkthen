# 0369: The release workflow's four smoke jobs pass

Status: landed. Lane claude-2. Branch `ticket/0369-release-smoke`. Plan: `sdlc/planning/cleanup-2026-09-30.md`. Parent: ticket 0128, phase 3b.

## Outcome

Each `smoke` job of `release.yml` gets past the four failures of rehearsal run 36853575250, and no surface reports "not run" for a missing host tool, toolchain or pin:

1. The x86 Linux language tools step loads an AppArmor profile that lets the pinned `/usr/bin/bwrap` make user and network namespaces, when the runner's kernel restricts them and the plain probe fails. The probe still runs `--unshare-net`, so the installed consumers' "no network" sandbox stays the same.
2. On every target the installed Python, PostgreSQL and SQLite checks find what they need: uv's cache holds the pins for the Python the check picks, both Linux jobs fetch the pinned PostgreSQL server package for their CPU and the SQLite amalgamation, and the macOS check accepts the version line of the pinned Homebrew bottle.
3. On both Macs the SQLite check runs under Homebrew's Python, whose `sqlite3` module can load extensions. No test is skipped.
4. `smoke-bundle` reads the DuckDB archive's member list once, so `tar` no longer writes into a closed pipe.

## What the build taught us

- A runner image can carry a tool and still refuse to run it. Ubuntu 24.04 ties user namespaces to an AppArmor profile, so a probe that passes on a host with `bwrap-userns-restrict` fails on a host without it. A copy of `/usr/bin/bwrap` at another path reproduces the runner's exact message locally: `loopback: Failed RTM_NEWADDR` for `--unshare-net`, and `setting up uid map: Permission denied` for the consumers' `--share-net` form. The new profile compiles with `apparmor_parser -Q -K` without root. Loading it needs root, so the next rehearsal proves the load.
- A seed must match the reader. Locally, with a fresh uv cache and a fresh `XDG_CACHE_HOME`, a `python3.12` seed reproduced the runner's line for run 36853575250's x86 wheel: `not run: libraries/python: uv's cache lacks a pin of requirements-dev.txt`. A seed through `host.sh`, which picked uv's 3.13.5 here, made the same wheel pass. On the M5, a seed for the Homebrew-formula Python 3.14.7 made run 36853575250's macOS ARM wheel pass `release-smoke`.
- The installed-file checks were asking for build tools. Inside `bwrap` with `/usr/bin/pg_config` masked, with `cargo-pgrx` off `PATH` and a toolchain folder that `setup.sh` had just filled, `release-smoke` passed run 36853575250's x86 PostgreSQL archive (53 of 55 shared cases pass, 2 not run by design) and its SQLite archive. Main's `runtime.sh` in the same setting stops at `not run: cargo-pgrx is missing`, the ARM job's line, and with cargo-pgrx back it fails on the masked `pg_config`.
- `setup.sh` accepted the cached amd64 file. With `uname -m` shimmed to `aarch64` it fetched the arm64 file into a scratch toolchain folder and matched the full pin. A planted wrong pin was refused and left no file and no scratch folder. `riscv64` reported no pinned package.
- A fake Homebrew `pg_config` on a shimmed Darwin: `PostgreSQL 16.15 (Homebrew)` passed the version line and stopped at the next check, a planted `brew list` of 16.14. `16.14 (Homebrew)`, a bare `16.15` and `16.15 (Other)` stayed "not run".
- The M5's `/usr/bin/python3` is 3.9, and its Homebrew-formula Python 3.14.7 links SQLite 3.53.4 and can enable extension loading. With `THINKTHEN_PYTHON` naming it, the SQLite installed-file check passed run 36853575250's macOS ARM SQLite archive (53 of 55 pass, 2 not run by design), on macOS 26.4 rather than the runner's 15.
- With SIGPIPE ignored, as on the runner, main's `smoke-bundle` printed `tar: stdout: write error` on run 36853575250's x86 files, and the branch printed nothing and copied the same files. A DuckDB archive cut to 3 MB fails both. Main reported a missing marker, and the branch says it cannot list the archive.
- `lint` in full, the four release self-tests, `workflows --self-test` (68 of 68), `policy.py` and `tickets` pass. `lint`'s one `Killed` line comes from `surfaces --registry`'s planted time-limit test and is expected.
- A landing script deleted this ticket's branch before the merge reached main. The commit survived, and the landing went through. Delete a branch only after confirming its commit is on `origin/main`.

The code review returned two: the host-setup self-test passed only on a machine without `/usr/bin/python3.14`, and `runtime.sh` ran its pin lookup twice and matched the URL loosely. Both were fixed, then ACCEPT at `ba6aa2341`.
