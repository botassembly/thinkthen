# 0667: Thin Zig calls onto run-call and packet answers

Status: OPEN.

Milestone: 0.2.1

Phase: 3

Depends on: 0666
Depends on: 0688, 0727

## Outcome

- Changes: `libraries/zig/src/blocking.zig`, `libraries/zig/src/thinkthen.zig`, `libraries/zig/src/calls_generated.zig`, `libraries/zig/src/results_generated.zig`, `build-tools/results/templates/zig.py`, `build-tools/results/legacy/zig.txt`, `conformance/library-surface/zig.json`, `libraries/zig/README.md`, `libraries/zig/README-PUBLIC.md`, `libraries/zig/examples/`, `libraries/zig/Tests/session.zig`, `libraries/zig/Tests/session_consumer.zig`, `libraries/zig/Tests/request_fixture.zig`, `site/examples/functions/*/zig.zig`.
- Named calls go through `thinkthen_run_call`. `CallResult` reads value and probability from the answer fields of the canonical Call JSON that `thinkthen_call_result_json` returns.
- `completeNamed` in `blocking.zig`, its packet drain loop and its private closed, reader and producer error text are deleted.
- The projection section of `build-tools/results/templates/zig.py` and the `NamedCallResult` projection it generates in `results_generated.zig` are deleted. Failure facts come from `thinkthen_call_error_facts_json` without per-field copying.
- Errors are a Zig error set plus a retained failure record, as the contract table describes.
- `build-tools/results/templates/zig.py` leaves this language's exception file `build-tools/results/legacy/zig.txt`.
- The public surface change updates the Zig entry in `conformance/library-surface/zig.json` (`CallResult`, `Result`, `Failure`) in the same change. The README, README-PUBLIC, `examples/` and the ten site function samples change with the error shape. The test consumers change only enough to compile; 0716 replaces them.

### Proof

- On the M5 through `pm job run --machine m5 0667 SHA --memory 8 -- sh libraries/zig/check.sh`, an outside Zig project depending on the unpacked package runs the examples and the existing installed consumers pass. 0666 adds darwin-arm64 to Zig's `check_platforms`, so this ticket follows it.
- `python3 build-tools/results/answer_rules.py` passes with the Zig template exception removed. Before the change it fails on that file.
- The Zig packet dump and its 0642 oracle comparison belong to 0716.
- linux-arm64 and linux-x86_64 run at the 0619 container checkpoints.

## Evidence

- After 0727 lands, this language's answer-rule exceptions live in `build-tools/results/legacy/zig.txt` and its surface entry in `conformance/library-surface/zig.json`. This ticket edits only those two files, so it does not collide with other languages' call tickets.
- `completeNamed` in `libraries/zig/src/blocking.zig` starts a session through `tt.session.startNamed`, drains packets with `session.next()`, and copies failure facts field by field with `inline for` over `ImmediateFacts`.
- Each function's value and probability come from the generated `NamedCallResult` projection in `results_generated.zig` (6,987 lines), generated by `build-tools/results/templates/zig.py`. That is another copy of the per-function rules. The 0637 answer-rule check lists that template in `LEGACY_FILES` in `build-tools/results/answer_rules.py`.
- 0638 landed `thinkthen_run_call` with independent `thinkthen_call_result` and `thinkthen_call_error` owners. Each call in `calls_generated.zig` returns `tt.Result(...)`, a union of `.ok` and `.failed`.
- Zig commits kept restoring generation and sessions after core changes: 1ddcaf267 "Restore Zig generation and check every target" and 557bd6e30 "Restore Zig native owned sessions and typed settings".
