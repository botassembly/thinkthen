# 0367: Refuse before the first send when a count or an answer cannot be kept, and bound every retry wait

Status: landed. Lane claude-1. Branch `ticket/0367-refuse-before-send`. Source: release QA round 2 (items 1 and 2) and the site owner (item 3). Ian can overturn the two coordinator decisions named below.

## Outcome

- A malformed or zero-byte month file in the usage folder refuses the first send with exit 5, and nothing is sent, whether or not the folder holds `.lock`. `thinkthen status` shows the month and total counts as `unavailable` and prints the sentence on standard error, as `specification/recording.md` already says. Every surface built from the environment gets the same refusal, because they share one engine check.
- A run whose answer cache folder cannot be written refuses before its first send with exit 5, and nothing is sent. This covers the platform default cache under a read-only `XDG_CACHE_HOME`, a `THINKTHEN_CACHE` or `--cache` folder, `--record`, and a read-only `thinkthen.sqlite`. Coordinator decision; Ian can overturn it.
- A retry wait a server asks for is still a minimum. When it is longer than the cap the doubling wait uses, `min(timeout, 60 s)`, the request stops retrying and fails at once with the status error it would give after its last retry. Coordinator decision; Ian can overturn it. Every retry wait, and every wait for one server floor, is then bounded. `check` sends one request at a time, so at `--timeout 90` it ends within 2,340 seconds, plus at most two seconds for another process's usage lock (one before the first send, one when the counts are written).

- Changes: the usage read, the store's open, the retry loop and gate, and four specification pages.
  - `engine/usage/storage.rs` `read`: when `.lock` is missing, scan the recognized month files without taking the lock instead of returning zero. A writer makes `.lock` first and installs a month only by rename, so the scan sees each month whole or not at all. A failure is the existing `RecordingStorage` error.
  - `engine/pipeline/send.rs`: the worker runs the probe once per call, keeping its result, just before the first send. A failure fails that request's inputs unsent. A call that stops at a failure stops there; one that continues past failures fails each later request the same way. A send total or token cap that is not zero is charged inside the transport, after the probe, so an unwritable folder outranks such a cap refusal; `recording.md` says so.

## What the build taught us

- The first design opened the store in the coordinator's dispatch. Ticket review found that it ran before the worker's zero-limit, key and usage refusals, so a refused run would make the cache file and report the wrong error. A probe in the worker, after those checks, keeps their order. Because the probe makes no store file, `status` and `cache convert` never meet an empty, schema-less store after a failed run; an earlier draft left one, and `recordings::a_failed_exchange_is_never_recorded` caught it.
- Measuring the gate bound from the waiting request's own cap would fail a sibling that was already waiting when another request closed the gate with an allowed wait. Measuring from now avoids that. It bounds each wait for one floor, but parallel siblings can chain floors, so the ticket defers a single bound for that case.
- `check` worst case at `--timeout 90`, with the cap C = min(90, 60) = 60 s: 16 attempts × 90 s = 1,440 s; 4 probes × 3 retry waits × 60 s = 720 s; 3 waits between probes × 60 s = 180 s; total 2,340 s (39 minutes), plus up to 2 s for another process's usage lock. Before this ticket a header wait had no bound. The no-header case stays 16 × 90 + 4 × 7 + 3 × 8 = 1,492 s.
- The rate-limit sentence still says "after the allowed attempts; try again later or change --max-retries" when a long server wait ends the retries early. The coordinator asked for the existing error, and the sentence stays accurate enough. A sharper sentence is left for a later ticket.
- Focused runs on the lane: library unit tests (398 passed), the `backend` test binary (750 passed), `library`, `public_controls`, `public_batches` and `public_estimated`, `policy.py` and `lint`. Full `test`, `spec` and `surfaces` wait for the coordinator's checkpoint. The C door's own usage test was not run; it reaches the same engine check.
- The ratchet rose by 537 lines in all, mostly edge-table and loopback tests. The probe, the retry tests and the no-lock usage tests went to their own files to stay under the 500-line cap.
