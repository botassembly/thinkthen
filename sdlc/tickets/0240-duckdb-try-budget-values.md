# 0240: Keep DuckDB try-details answers when its request total is spent

Status: COMPLETE.

Opened as: 2026-10-11. after fresh independent High code/artifact-review ACCEPT `706a133c`. The coordinator integrated the unchanged repair with cache 0238 and reran the affected native boundary and split-model checks. This restores the accepted ADR 0080/0149 try-value contract; other B13c platform gaps remain open. Owner: Codex.

## Outcome and retained behavior

`thinkthen_try_details` returns a safe failed Usage JSON value for a send-budget denial before the first send **or before a retry**. The value has `status: "failed"`, no `details`, and `error: {"kind":"usage","message":"check the row's question and arguments, or raise the process request total when it is spent","retryable":false}`. Answered members keep their full details and original SQL positions. A SQL `NULL` input remains SQL `NULL` and sends nothing. An unresolved answer remains `status: "answered"` with `details.value: null`. Ordinary scalar and warm calls retain their spent-total statement error. Genuine Cancelled, Deadline and Defect remain statement errors. The transport admits no attempt past the process total and final facts count every attempt actually started, including joined in-flight work.

ADR 0094's recoverable native carrier preserves good members beside a failed request or failed logical member. Its fatal list names Cancelled, Deadline and Defect; it did not repeal ADR 0080's DuckDB try-value budget rule. Ticket 0222's final follow-up prose and `b13c_try_details_total_one_stops_the_vector` instead assert a fatal tagged denial. They document what that review tested, not the controlling contract. Keep that historical proof with an explicit supersession note in ticket 0222 and its build record; replace the contradictory test assertion and README sentence when building this ticket. Neither a newer test nor its acceptance changes the earlier approved try-value outcome.

## Smallest partial-outcome path

1. Keep `core::Batcher`, the shared one-split adapter, actual-attempt `SendBudget`, and DuckDB C++ `Decide` grouping and original-slot map. In `engine/facade/split.rs`, reserve outer fatal errors for Cancelled, Deadline and Defect. Return a tagged denial as the single, left or right half's owned result. For a denied left, the native `after_left` callback stops before right; for other recoverable left outcomes it still sends right. The B12a stopping callback already stops on any failed left and must retain its existing prefix and send count. A denied right cannot erase an answered left.
2. In the private native carrier, convert each tagged denial to failed Usage with `retryable:false`, independent of the denial's ordinary public kind. A small internal outcome holds the ordered member rows and a `denied` terminal marker; it is not a new public error, result variant or C ABI. A denied single batch fills only that batch's slots. A denied left fills its slots and the unsent right slots without a transport attempt. A denied right keeps decoded left rows and fills only right slots. Recoverable nonbudget request/member failures continue under ADR 0094. True Cancelled, Deadline and Defect stay outer errors with final joined facts.
3. Extend the existing `workers::ordered` loop with one caller-thread terminal-result predicate, exposed privately through `facade::native_batch`. Its current `ordered` wrapper uses an always-false predicate for other callers. Check the marker when a worker result is received, before feeding another item. Halt new admission on a denial, drain all already-admitted results in input order, and join every worker. Do not stop ordered delivery at the denied item: an in-flight later-index success may already exist. Continue receiving after the denial: an admitted worker's later genuine Deadline or Defect must override the safe result, even if its SQL index follows the denied item. Join and account every started worker before returning that fatal error. After a nonfatal bounded drain, fill only the unadmitted suffix with safe Usage failures and check that the final result count equals the input count. No denial marker means a short result is Defect, not fabricated success. The outer `Call` freezes actual joined facts through the existing `Stop::run_call` path.
4. In the DuckDB bridge, map a residual typed `BeforeFirstSend` or `BeforeRetry` at the explicit try boundary to the same safe Usage value. Do this before kind-based fallback because `BeforeRetry` otherwise has public Backend kind. Accept only a full native vector, frame each value at its copied slot, and let C++ map those slots to original SQL rows and NULL positions. Keep the fixed safe advice text, not raw backend/error detail. Leave ordinary scalar/warm error mapping untouched.

The worker marker is an admission stop, not a second budget authority. A worker can finish or begin a reserved send before another worker's denial becomes visible; the atomic budget still prevents any extra actual send. Do not infer admission from listener arrival order. The partial outcome retains every already answered member, including a later-index result held by ordered delivery when the denial arrives.

## What preparation taught us

Removing the bridge's fatal-denial guard alone would turn the whole native outer error into failed rows and discard already answered members. The shared split helper also throws a denied right half before returning its answered left half. A denied left needs separate proof because it must prevent a right send and safely fill both halves. `workers::ordered` joins but currently stops delivering at the first error, so a later-index in-flight success can be lost even though its send was counted. A private terminal marker plus ordered drain is the narrow correction; fresh design review also required a fatal-after-denial race because the drain must never turn an already-admitted genuine Defect or Deadline into safe Usage. The existing atomic budget remains the authority over actual sends. The newer fatal-total test and review were real observations of the regressed artifact, but the unchanged original test and accepted ADR 0080 settle the desired SQL value.

## What the build taught us

The build kept the public native result shape and C++ mapping unchanged.
