# 0356: Binding tests wait on events

Status: COMPLETE.

Opened as: 2026-10-11. Lane claude-4. Pays Debt 029, `../issues/closed/2026-09-30-binding-tests-still-time-stops-and-wait-on-short-bounds.md` (pre-0.1 item 20). Also closes area 3 item 1 of `../planning/grading-2026-09-30/03-send-limits.md`. Plan: `sdlc/planning/cleanup-2026-09-30.md`.

## Outcome

No binding's routine surface check depends on how fast the machine runs. Every binding test that timed a stop, or waited a short bound for an event, now proves order with an event: a counted request, a file the child or backend writes, a pipe line, or a call that has returned. Each millisecond promise runs only under `THINKTHEN_TEST_PROFILE=stress`. The two command-level rate tests prove spacing with a bound that load cannot break.

## Exceptions

Go's two held cancel cases keep a margin. A cancelled context reaches the call's token through a goroutine, and no outside event marks the fire. The release waits 1 s after `cancel()`, so a failure needs that goroutine stalled for the whole second. An unexported hook in the Go package could mark the fire, but it would put a test branch in shipping code, which area 3 item 5 of the grading counts as a weakness. Ian can overturn this.

The held deadline case on every C-door binding now uses a 1 s deadline instead of 25 to 150 ms. The deadline must outlast the request's send, or the call ends before the backend holds anything and the arrival never comes. No outside event marks the send before the deadline starts, so a failure needs a stall of the whole second before the send. The loaded proof's second round failed Go this way at 25 ms.

## What the build taught us

- A C-door cancel lets the sent request finish, so firing the token and then releasing the reply already proves order. The real races sat in the deadline cases, and in Go, whose context reaches the token through a goroutine.
- A held deadline must outlast the send as well as end before the reply. At 25 ms, a loaded machine let Go's deadline fire before the request left, so the arrival never came. A 1 s deadline keeps the margin wide.
- A host that runs its matrix in one thread still marks "the call returned": its next request reaches the backend only afterwards. The PHP and COBOL release workers wait for that arrival.
- A count that stays still for 100 ms is not an event. R's old `settled` let the bulk-verb rows stop at two sends under load; waiting for the eight held sends the throttle allows fixed it. Main had the same race.
- A rate test measured from the launch has a lower bound that load cannot break, because the pacer's first slot comes after the launch.
- Comment lines count toward each binding's line ratchet, so a change across 14 bindings moves 21 ratchet files.
- Three loaded rounds ran, each peaking at a one-minute load near 40. Round 1 failed R's bulk rows and round 2 failed Go's 25 ms deadline; both are fixed above. Round 3 passed the rate tests and the Ruby, TypeScript, Go, R and JVM checks.
- Code review caught the Dart alpha consumer, a copy of bravo that kept the old 100 ms pause.
