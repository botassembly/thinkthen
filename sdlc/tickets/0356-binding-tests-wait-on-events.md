# 0356: Binding tests wait on events

Status: in progress. Lane claude-4. Pays Debt 029, whose header reads `Debt: 027`, `../issues/2026-09-30-binding-tests-still-time-stops-and-wait-on-short-bounds.md` (pre-0.1 item 20). Also closes area 3 item 1 of `../planning/grading-2026-09-30/03-send-limits.md`. Plan: `sdlc/planning/cleanup-2026-09-30.md`.

## Outcome

No binding's routine surface check depends on how fast the machine runs. Every binding test that timed a stop, or waited a short bound for an event, now proves order with an event: a counted request, a file the child or backend writes, a pipe line, or a call that has returned. Each millisecond promise runs only under `THINKTHEN_TEST_PROFILE=stress`. The two command-level rate tests prove spacing with a bound that load cannot break.

## Evidence

- Starts from: ticket 0352 (`9e33cd639`), its Rules, and its "What the build taught us". It fixed the Rust rung, `spec`, and the Python, DuckDB and SQLite surfaces, and filed Debt 029 for the rest. The grading summary (`sdlc/planning/grading-2026-09-30/README.md`) still lists area 3 item 1 as open: `tests/backend/backoff.rs` and `tests/backend/named_backends/rate.rs` need 400 ms of a 500 ms spread between request arrivals, so a first send that leaves late fails them.
- A fact from the C header shapes the C-door fix. A fired token lets a sent request finish (`libraries/c/include/thinkthen.h`, lines 19 to 28 and 177 to 183). A held call on Go, JVM, C#, Zig, Swift, C++, Dart, PHP, Ada, Objective-C or COBOL therefore returns `cancelled` only after its reply is let go. `thinkthen_cancel` sets the token before it returns, so firing and then releasing already proves order, and the 100 to 250 ms pause between them proves nothing. A deadline is different: it ends the call within one tick while the reply is held. A test that pauses 25 to 200 ms and then releases can let the reply win on a stalled machine.
- Keeps: every cancellation, deadline, interrupt, throttle, fork, receipt and no-later-send regression. Each assertion that a stopped call sent nothing more keeps its pause, since load only makes it pass more easily. The 0352 rule list holds unchanged. A test that waits for something that must not happen keeps its pause: the Ruby tick-thread 0.5 s, the TypeScript throttle 300 ms, the R count checks after `round`, and the PHP "still held after 250 ms" check. The deadline settings case (`timeout-ends-a-slow-attempt`, a 1 s timeout on a 2 s delay) stays. So does the HTTP pool test's 1.2 s idle in `engine/http/tests.rs`, a lower bound that load cannot fail; area 3 item 1 named it, and its subject is the idle time itself.
- Changes: binding tests, their fixture backends and check scripts, and two Rust command tests.
  - Ruby: `tests/backend.rb` gains `STRESS`. The single and batch interrupt tests check their 150 ms and 1,000 ms promises only under stress. The thread-kill join, the settled-thread wait, the fork reader, the settings-case read and the completion read wait 30 s. `check.sh --stress` runs both interrupt files beside `test_flood.rb`.

The pacer gives its first slot no earlier than that moment, and slot six five intervals later, so the span cannot fall below five intervals however late any send leaves. At 300 a minute the routine bound is 1 s. An unpaced run on a quiet machine sends all six well inside it.
