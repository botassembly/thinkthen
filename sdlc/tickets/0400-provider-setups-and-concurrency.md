# 0400: One setup format per provider, local servers and Clef documented, and a default throttle of 8

Status: in progress. Slices A, B and C landed: provider setups work and the shared default is 8. Slice D waits for accepted provider measurements.

Milestone: 0.2

## Outcome

1. Slice A. ADR 0117 fixes the reviewed provider setup format and starter reporting table. The table distinguishes official published facts, retained measurements and unknown compatibility. The evidence record preserves dates and limits. This slice adds no executable configuration example or public settings row that the parser still refuses.
2. Slice B. The read-only configuration file's `backends` entry accepts the reviewed setup fields: relative path, key variable, model, rate, atomic caller-price pair, inline existing backend profile and BothSides for added entries. The selected setup's prices/profile apply on every configuration-reading surface under ADR 0117's accepted precedence. The public specification and runnable examples land with the parser. Existing entries preserve their behavior.
3. Slice C. Every unset surface inherits a default throttle of 8. Explicit settings still win and the range stays 1 through 32. Mapping tests use a distinct explicit value so removing the mapping still fails. Published defaults and retained measurement labels are truthful.
4. Slice D. Local-server and Clef pages publish only accepted measured rows, with checked commands and dated evidence. Direct Workers AI remains unverified unless separately authorized proof establishes its route and reply compatibility. Documentation introduces no new built-in or image carrier.

## Design notes

The accepted [ADR 0117](../planning/adr/0117-provider-setups-extend-the-backend-entry.md) controls the full precedence and proof contract. Slice B additionally proves all legal nonempty built-in field subsets, exact canonical posting-URL matching including paths, price/profile-only built-in inheritance, named settings retained at explicit address/model overrides, and explicit/set-up/top-level price provenance independent of setter order. No accepted API scope changes in this amendment.

- The shape, accepted in slice A and implemented in slice B. One entry is one provider setup. An added entry:

  ```json
  {
    "schema": "thinkthen.config/1",
    "backends": {
      "perplexity": {
        "requests_per_minute": 600,
        "usd_per_million_input": "0.04",
        "usd_per_million_output": "0",
        "profile": {"schema": "thinkthen.backend-profile/1", "name": "perplexity", "max_questions": 128}
      },
      "clef-local": {
        "url": "http://127.0.0.1:8080/v1",
        "path": "systemone",
        "key_env": "CLEF_LOCAL_KEY",
        "model": "clef-flash",
        "both_sides": false,
        "profile": {"schema": "thinkthen.backend-profile/1", "name": "clef-flash", "max_request_bytes": 96000}
      }
    }
  }
  ```

  Slice B implements the price/profile fields in this example; its current merged checkpoint passed. The local Clef entry illustrates the format and establishes no compatibility.

  The entry keeps everything that decides where the key and the evidence go, and the owner-only file rule guards it. The profile keeps what the backend accepts, in the shape every surface already parses. The price sits beside the rate, because both describe the account, not the wire. This reuses both existing mechanisms and adds one parser call, three fields and one precedence step.
- The rejected shape: a profile file that also names the address, path and key variable. It would break ADR 0032's rule that a profile selects no address or key, and `--profile FILE` names files that the owner-only rule never checks.
- Slice C changes the common fallback constant. Most of its work is moving surface tests off an explicit 8 so their plants still fail.

## Relation to ticket 0377

- 0377 gives each binding and SQL extension a `backend` setting in code. Today every surface already reaches any built-in or configured entry through `THINKTHEN_BACKEND` or the configuration file's `backend`, because each builds over `EngineBuilder::from_env`. So 0400's setups and its throttle default need nothing from 0377, and new-model day runs on the command.
- 0377 belongs in lane 2, after 0399 and after this ticket. 0399 changes the unknown-name sentence that 0377's corpus case 5 pins, and adds key variables its marker set should cover, so 0377 should pin the final five-name sentence once. Slice C moves throttle tests in the same binding test files 0377 edits, so running them together would collide. 0377 is a 0.2 milestone item but is not in the list of what 0.2 ships with, so it can also fill whichever lane frees first after this ticket.
