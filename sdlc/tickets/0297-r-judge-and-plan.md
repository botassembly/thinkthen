## What the build taught us

The accepted 0288 threshold review prevented the judge from capturing a numeric-only representation: direct, omitted-input, and `purrr::partial` now share `.tt_bind`, which passes both numeric and string bands through the existing core grammar. The 0288 raw-JSON lesson also applied: a saved question is validated before `jsonlite::fromJSON`, and the new plan bridge calls `Question::from_json` on its raw text. Omitted input needed one new distinction from explicit `NULL` and `NA`: only an absent argument constructs a function; explicit missing values keep the eager no-work answer. These facts were useful in the first installed proof and did not require a new parser or experiment.

The existing direct-call body was extracted into `.tt_execute` so a judge binds a checked question and batch/context once. The first candidate `74c547359` made a false identity claim: execution captured `bound` in the closure, while `tt_plan` read a separate mutable `thinkthen_bound` attribute. Fresh High review changed each copy independently and observed one planned request against two actual sends, then the reverse; a class-and-attribute forged function also passed plan's old check. The correction keeps one locked environment binding for both paths. Plan checks the function body, formals, environment, binding and plain bound shape before reading it; it never invokes a supplied function or active binding. Plan-time batch/context overrides now fail Usage, because those settings belong to judge construction. A separate installed test was necessary because the backend marks its capture overflowed after three bodies; a plan count alone cannot prove actual sends. The bounded identity test compares the plan with three captured bodies, listener counts and facts. A small native `plan.rs` still wraps `Engine::plan_with`; the shared-settings FFI check remains in `ffi/settings.rs` to keep `ffi.rs` below 500 nonblank lines. The public plan returns records, prepared requests, exact known body bytes, a lower/upper token band, an upper-bound flag, and the first body. The dbplyr snapshot preserves `thinkthen_decide` in generated SQL without a database.

No prior R test was deleted. The two new tests retain direct, judge, and partial parity; numeric and string bands; all four judge verbs; original NA positions and probability; grouped mutate; and zero-send refusals including the old deadline sentence and raw duplicate-file Local error. Existing 0288 facts, secrecy, cancellation, and ownership cases remain separate. The example corpus adds a zero-send plan example. `dbplyr` and `purrr` are suggested test/idiom packages, not mandatory runtime imports. Source ceilings rise from 2049 to 2299 R nonblank lines and 2215 to 2277 Rust lines; the two functional proofs and small native helper account for the growth. I checked the existing `.tt_settled`, `.tt_call_settings`, `calls` and `ffi` paths before adding helpers; no second threshold/settings parser or copy of the core planner was added. The next Judge host must not put its planner metadata beside a separately captured closure value; it must compare planning with actual bodies and sends under bound settings.

The original SQL/data-frame issue remains open for other bindings, full package and release qualification, and any provider or load work. DuckDB packs its vector calls; PostgreSQL's scalar dbplyr spelling sends once per row, so its keyed many function is the packed route.
