# 0210: Refuse a backend address that contains the configured key

Status: implementation and corrected source accepted by the same fresh High reviewer at `e6462d04`; ready for coordinator landing. Owner: Codex. Ian approved the optional-key snapshot at `a2c9057a`. Register 106 remains open until the reviewed implementation lands. [Build evidence](../records/0210-build.md), [code review](../records/0210-code-review.md), and the [post-settings preflight](../records/0210-post-settings-preflight.md) record the source and proof.

## Evidence

- Starts from: Register 106 in `experiments/284-issue-register/106-token-in-base-path-in-recordings.md` and the independent review recorded in [the preflight](../records/0210-path-secrecy-preflight.md). Main `a09ceb8f` preserves arbitrary base-path bytes. A configured key appearing verbatim in those bytes therefore enters the resolved URL, every successful recording entry for it, plan and status output, and some `Debug` lines. Existing secrecy proofs use a key different from the address and miss the collision.
- Keeps: Legitimate gateway path routing, the complete URL's request digest and folder identity, exact replay checks, `THINKTHEN_API_KEY` as the key channel, and keyless loopback. Do not strip, rewrite, or redact the transport URL or stored entries. Existing recordings made with a collided key remain sensitive; this ticket cannot erase them.
- Changes: when a nonblank effective key occurs as exact contiguous UTF-8 bytes anywhere in the resolved endpoint URL, refuse with one fixed usage sentence before the backend URL reaches a plan, status line, result, digest, folder access, key send, or network request. The sentence is `the backend address contains the API key; keep the key out of the address`. Do not include URL or key in the error or its `Debug`. This sentence also fits Rust's explicit `api_key` setter. Compare bytes exactly; no shape, length, prefix, percent-decoding, Unicode normalization, or path-segment heuristic. Checking the entire URL also covers the same known-key collision in a host or appended `/systemone`. A short key may match an otherwise innocent address; that conservative refusal is part of the accepted public rule. An absent or blank key does not cause this refusal and keeps existing no-key behavior. The rule protects disclosure **through the backend URL and URL-derived identities**, not arbitrary evidence, question, model, or caller-controlled text that happens to contain the same bytes.
- One effective key: the CLI resolves the final endpoint, snapshots `THINKTHEN_API_KEY` once, checks the collision, and retains that value for any later live send. The retained `KeyReader` returns the snapshot; it never rereads the environment. This makes the pre-digest check and sent key the same value, even if the process environment changes afterward. The snapshot is optional: a keyless dry run or replay stays valid, and a missing key at a non-loopback live send still has its existing failure. A replay hit never calls `KeyReader`, so the snapshot check must precede replay's folder and digest work. A Rust `EngineBuilder` already captures its environment key; an explicit `api_key` overrides that captured value. Check only the final effective key and final resolved endpoint in `build`, regardless of setter order. The pure `Backend::resolve` reads no environment. Other language and database doors use the public builder; verify each constructor before source claims. This deliberately changes the CLI's send-time environment-read timing to a per-invocation snapshot.
- A `Debug` value formed before the key is known cannot promise safety by comparison. Withhold URL bytes from `Debug` for raw URL holders (`Url`, CLI arguments/configuration/environment, and the public builder) and later values (`Details` and recognize plan among them). Keep explicit public result URL fields only after the guard. Do not expose a rejected address through a wrapped error. This is separate from changing the transport address.
- Proof: Use a synthetic key/address collision at the compiled command and public builder boundaries. Check no printed sentinel, listener request, recording file or marker; retain exact safe gateway plan, digest, recording and replay behavior. The focused proof is detailed below.
- Defers: Arbitrary token-like path segments not equal to the configured key remain a documented hygiene risk. Old files containing a collided key require separate operator handling; no automatic migration or fixture scan belongs to this design.

## Approved dry-run decision

Before 0210, `--dry-run` read no key and emitted the exact resolved URL and request digest. A run that does not read the key cannot determine whether independently supplied URL bytes equal it. With arbitrary gateway paths and exact URL plans, it cannot simultaneously keep that rule and guarantee that the configured key is never printed or hashed *through the URL*. **Ian approved an optional snapshot of `THINKTHEN_API_KEY` for this comparison** at `a2c9057a`, without requiring a key, constructing an Authorization header, making a call, or changing a safe plan's bytes. A collision receives the same fixed refusal before the plan or digest; a safe or keyless plan remains byte-for-byte the same. The choice is settled and implemented in the reviewed candidate.

This is a wider compatibility amendment than the one backends sentence. Update `specification/backends.md`'s dry-run and before-key planning sentences, `specification/recording.md`'s replay-reads-no-key table, folder-mismatch-before-key rule, and temporary-write-before-key rule, the CLI `--dry-run` help in `cli/args.rs` and other affected help, and the executable `spec/check.md` dry-run claim. Preserve the operational distinctions: dry-run and replay still **need no key**, make no key-bearing header, and open no connection; replay still uses exact unchanged URL/request identity; a folder mismatch still occurs before a send and keeps its established local exit and message when no collision exists; a writing mode still creates its temporary entry before a **send**, though now after optional key inspection. The new collision refusal wins over a folder mismatch to prevent that mismatch message from repeating the key-bearing URL. Status derives both its collision check and `api_key_set` field from the **same optional checked snapshot**, replacing the current separate `Environment::api_key_set` read. This rule enforces the credential promise for the backend URL and URL-derived identities only. It does not detect a caller who deliberately puts the same bytes in evidence, a model name, a question, or other content; existing content-disclosure rules still apply. Arbitrary other path tokens remain a documented hygiene limit.

The CLI snapshot is per invocation, not a process-global key cache. A key change after the snapshot does not change the value sent by that run. The public builder's captured or explicit key is likewise fixed at `build`. These rules avoid the old two-read gap; they do not claim to detect a different key that another process later writes into its own environment.

## Proof and bounds

Use synthetic configured keys only, with distinct benign evidence, question and model text so the proof isolates URL disclosure. An existing compiled-command edge table covers normal `--record`/`--cache`, `--replay`, `--dry-run` for ordinary, recognize and relate plan shapes, `check --dry-run`, and `status` human/JSON. For each door assert the exact fixed refusal, no URL-derived sentinel in stdout/stderr or later `Debug`, no listener request, and no new entry, marker, or temporary file. The status case also pins `api_key_set` to the checked snapshot, including absent and present safe keys. First prove raw argument/config/environment/builder `Debug` withholds URL bytes even before validation, then prove later `Details` and recognize-plan `Debug` withhold them. The match table uses a path key, a short key in the host or appended `/systemone`, exact multibyte Unicode, and a percent-encoded spelling that must **not** match the unencoded key. The builder table covers an explicit key, an environment-captured key, and an explicit key overriding a colliding captured value (safe final key must work). A valid gateway prefix that does not contain the effective key keeps its exact planned URL, request digest, entry URL, replay, and result output. Keyless dry-run and replay remain accepted; a post-snapshot environment change cannot alter the sent key. Keep one proof per distinct boundary and reuse local listener/scratch helpers rather than copying the whole table into every command. Focused tests and strict relevant lint, format, policy, and measured ratchet suffice; no paid or broad stress run.

The preflights name source, test, spec, and documentation claims plus source file-size headroom. Main claimed the free paths, then transferred the 0203/0220 overlaps after their work landed. Register 106's arbitrary path-token hygiene remains separate: the code cannot infer other secrets, and `specification/backends.md` and `specification/recording.md` already warn about that limit. The work plan's old “strip the token before a recording is written” wording is not this accepted behavior.

## What the build taught us

The accepted exact-byte rule needed one effective key snapshot at the CLI boundary; a late second environment read would make the check and send disagree. The initial source inventory missed raw Check Debug and public Details Debug, so both files transferred after their owners landed. Fresh High review found two later raw-URL Debug carriers in recognition plans and HTTP exchanges; the inventory must follow URL values through plans and transport. The page inventory missed settings, relate and executable check wording. A single outside-in table covered the command doors without copying a planner or listener. Existing safe gateway digest and replay cases remained the preservation proof. The full measured growth and focused checks are in the [build record](../records/0210-build.md).
