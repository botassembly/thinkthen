# 0074: Bind SIGINT to cooperative cancellation

Status: implementation and integrated local gates accepted; landing pending

## Outcome and authority

The command catches the first SIGINT, fires ticket 0073's private token, and prevents attempts whose attempt-start check observes cancellation. It finishes attempts already started, flushes completed output and the existing stopped-at line, then restores normal SIGINT termination. A shell observes 130. A second SIGINT delivered after the first handler arms default behavior terminates immediately. Outside an active command entry, the installed CLI handler emulates the normal default. Ian ruled this behavior in ADR 0017 and the approved SIGINT issue; ticket 0073 deliberately left CLI signal ownership for this follow-up.

## Current fact and design

The command currently installs no SIGINT handler. `Environment` already owns one run token, and every request path observes it, but `EngineError::Cancelled` still maps to a defect placeholder. Standard-output lines flush at the write boundary; stopped failures already carry ordered counts and render the stopped-at line.

Add one private process-lifetime CLI interrupt state with one shared cancel token, one `default_armed` atomic flag, and one `active` atomic flag. Initialize it once and register four actions in this order: conditional default on `default_armed`; set cancellation; conditional default on `default_armed` again; set `default_armed`. The second default check closes a race where finalization arms between the first check and the cancellation store. Outside entry, `default_armed` is true, so SIGINT emulates the normal default. Initialization success or failure is sticky; a partial prefix is never registered again, and its armed first action preserves default behavior.

After environment construction, entry claims `active`, resets cancellation, installs a clone of the process token into that mutable environment, then stores `default_armed = false`. That final store is the activation linearization point. Every request in each sequential entry therefore observes the same reset process token. SIGINT before disarm defaults normally; the first signal after it fires cancellation and arms the default. A later SIGINT delivered after arming defaults immediately. Overlapping deliveries that both entered before arming are outside that ordering promise. A concurrent loser returns `thinkthen: defect: another command entry is already active` with code 70 and never resets, disarms, runs, or finalizes the owner's state.

An RAII activation guard first stores `default_armed = true`, then reads cancellation. The handler's second conditional-default action catches a signal that passed its first check just before this store. If cancellation was observed, normal finalization calls `signal_hook::low_level::emulate_default_handler(SIGINT)` before releasing `active`; an unexpected emulation error releases the claim and returns fallback 130 without another diagnostic. Without cancellation, finalization releases the claim and returns the computed code. The guard's unwind drop uses the same arm-before-release order and emulates an already-observed cancellation; if emulation unexpectedly returns, it still releases the claim.

A red subprocess proof shows that process-directed SIGINT interrupts `ureq` when it lands on a thread waiting for a response. `ureq` abandons that response on `EINTR`; retrying would issue a second paid POST and cannot finish the current attempt. Thread placement alone is insufficient because process-directed SIGINT may select any unblocked worker.

On Unix, activation uses `nix`'s safe signal-mask API to save the caller's mask and block SIGINT before any request worker starts. It spawns one short-lived CLI signal-carrier thread that inherits the blocked mask, explicitly unblocks SIGINT, acknowledges readiness, and waits for finalization. The activation linearization point is still the later `default_armed = false` store. Every engine worker created after activation inherits a blocked SIGINT mask, while the carrier is the only eligible thread created by this command entry, so sent engine HTTP attempts cannot receive `EINTR` from SIGINT. Finalization arms default behavior, handles cancellation, tells the carrier to block SIGINT and exit, joins it, restores the caller's original mask, and only then releases `active`. Unwind uses the same cleanup order. In the command process, a pending SIGINT while its threads are briefly blocked is delivered after the caller's mask is restored with default behavior armed. A multithreaded host may have pre-existing eligible threads outside this entry; their masks and possible `EINTR` remain host-owned, while engine attempts stay on protected threads. Non-Unix uses the accepted process-state protocol without claiming mask affinity or Unix status. A hidden test-only `THINKTHEN_TEST_SIGINT_ACK` path may be read with the other hidden test setting. When named, the normal carrier thread polls its stop channel at the existing 50 ms cadence and attempts acknowledgment only after it observes the cancellation flag; it repeats that check before honoring stop/block/exit, so join guarantees an observed cancellation was acknowledged or a seam failure was recorded. Acknowledgment exclusively creates a new regular file, writes exactly one non-secret byte at most once, and never truncates or follows an existing final-path symlink. No file I/O occurs in the signal handler. Acknowledgment failure is recorded for tests but changes no product output, diagnostic, exit precedence, or signal behavior. Tests use a unique named path, wait for its byte as the phase boundary, and remove it on success or failure without printing the path.

Expose only crate-private token reset and atomic-flag access from the engine. Add typed `Failure::Cancelled`: bare cancellation writes no diagnostic and carries fallback code 130; a stopped run with that cause skips the cause line and prints the existing stopped-at line. Other stopped causes and diagnostics remain unchanged. Environment/configuration failure precedes signal-state initialization. Registration failure leaves `default_armed` true and returns exactly `thinkthen: defect: SIGINT handling could not be installed` with code 70 before `run`, input, key, or backend work. Unix mask, carrier spawn, or readiness failure arms default behavior, signals any started carrier to block and exit, joins it, then attempts to restore the original caller mask before releasing `active`. It reports exactly `thinkthen: defect: SIGINT routing could not be activated` with code 70 before `run`; if that restoration also fails, `thinkthen: defect: SIGINT routing could not be restored` wins. No carrier remains after either outcome, and the active claim is released only after restoration was attempted. A mask-restore failure after normal output reports `thinkthen: defect: SIGINT routing could not be restored` and code 70; after observed cancellation, default emulation remains prior and authoritative. The unwind path makes a best effort to restore before releasing `active`, with default behavior armed throughout.

## Scope and exclusions

Allowed: crate-private token reset/flag access, one process-lifetime CLI SIGINT state, Unix caller masking and one short-lived signal-carrier thread, active-entry exclusion, typed CLI cancellation rendering, end-of-entry default emulation, the target-Unix `nix` 0.29 dependency with only its `signal` feature, the hidden named SIGINT-ack test seam, exact subprocess tests, one channels specification sentence, exact ratchet, and ticket/issue/queue/record updates. Production may touch at most five Rust files and add at most 360 nonblank Rust lines. Tests may add one backend module and focused failure/interrupt-state tests, with total added nonblank Rust lines at most 900.

Excluded: changes to engine scheduler/request/lock/transport semantics, extra request workers, changes to the public Rust type surface, other signals, recorder `SIGXFSZ`, deadlines, width, fork recovery, cache/recording semantics, changing detached or blocking input ownership, workflows, surfaces, site, paid calls, and publication. The existing public `entry()` gains process-safe serialization because its CLI signal disposition is necessarily process-wide. This ticket promises cooperative handling after the command has entered a cancellable engine path. A later SIGINT after the first handler arms default behavior remains the escape from a blocked host read or shutdown.

## Acceptance

- On Unix, a spawned `--jobs 1` record run with record 1 held on a synchronized local listener receives SIGINT, then the test waits for the carrier's named cancellation acknowledgment before releasing the reply. This controlled ordering proves no later request starts, the first row completes and prints, and stderr contains exactly the stopped-at line for record 2 with correct finished/recording counts and no cancellation defect line. The cache entry is complete. `ExitStatusExt::signal()` is `Some(SIGINT)`, from which a shell derives 130.
- SIGINT while an ordinary or annotate scheduler waits for the next input request returns through the stopped path without another input request. Existing engine tests remain the authority for internal stop metadata.
- On Unix, a sent single-document `decide` and a sent aggregate `find` each finish their answer on their existing path, flush it, and then terminate by SIGINT. Each case waits for its unique carrier acknowledgment before releasing the reply, and each listener observes exactly one POST. A retry-wait case makes exactly one connection before termination.
- Signal-routing tests prove the caller blocks before spawning the carrier, the carrier alone unblocks and acknowledges readiness before activation, spawned request workers inherit the blocked mask, and normal/error/unwind cleanup arms default behavior, stops and joins the carrier, restores the original caller mask, then releases `active`. Injected mask/spawn/readiness/restore failures, including activation plus restoration failure, prove cleanup, carrier join, exact precedence, and diagnostics.
- A seam test proves acknowledgment occurs before an already-queued stop, exclusively creates a regular file with exactly one byte once, refuses an existing file/symlink without truncation, records failure without changing product behavior, and is absent from help and ordinary output. Subprocess fixtures remove the unique path on every outcome and do not print it.
- A dedicated Unix child harness receives the first SIGINT, polls the shared atomic state, acknowledges that `default_armed` is true, then receives a second SIGINT and terminates without another release. Overlapping signal-handler deliveries before that acknowledgment are not claimed.
- Unit tests prove `EngineError::Cancelled` maps structurally to `Failure::Cancelled`, bare cancellation writes nothing with fallback 130, stopped cancellation prints exactly one stopped-at line, and non-cancellation stopped causes retain their cause line and code.
- Interrupt-state tests prove all four actions in order, the interleaving where finalization arms between the two conditional-default checks, first-signal arming, activation at the disarm store, active-entry exclusion, default-armed state outside entry, and unwind arm-before-release behavior. A concurrent loser cannot mutate the owner's state. Two sequential activations prove that the second mutable environment receives the same reset process token rather than retaining its freshly constructed token.
- A deterministic sticky-initialization seam fails each of the four registration positions in turn and proves every retained prefix defaults safely, later entries repeat the exact `thinkthen: defect: SIGINT handling could not be installed` with code 70 without registering again, and no `run`/input/backend work starts. An emulation-error seam returns 130 without another diagnostic and releases `active`.
- Unix owns subprocess signal/status proof. Production still compiles through the repository's all-target gates; the ticket makes no claim that Windows exposes Unix signal-derived status.
- No test depends only on elapsed time: listener events, input-request events, atomic-state observations, and child-process state establish each phase; generous timeouts guard deadlock. Tests make no external or paid call and never expose a key or evidence in diagnostics.
- Focused subprocess/unit tests, policy, exact ratchet, formatting, Clippy, and `git diff --check` pass before code review. The coordinator runs the four local gates sequentially after acceptance. Actions remains disabled.

## Dependencies

Ticket 0073 is landed on main through `7ec6f82`. `signal-hook` 0.3.18 is already accepted and contains the safe flag registration, conditional-default, and default-emulation APIs. Its registry explicitly does not restore the prior disposition after unregistering the last action, which requires the process-lifetime design. Rust's standard library and `signal-hook` expose no safe per-thread signal-mask API. Add optional `nix` 0.29 under the Unix target with `default-features = false` and only its `signal` feature, selected by the crate's existing `cli` feature; it provides the safe `SigSet`/`pthread_sigmask` wrapper and is established beyond the repository's seven-day dependency floor. The implementation adds no unsafe code. Independent design and code review must inspect the dependency, target gating, lockfile, license, and source-ceiling increase, and the commit message must name why the standard library cannot do the job.

## Review

Independent design review rejected the scoped unregistering guard because `signal-hook` does not restore the prior/default disposition and found an end-of-entry delivery race, imprecise failure precedence, an overbroad send claim, and missing Unix proof boundaries. The first revision kept one process-lifetime CLI handler armed outside entry, fixed exact failures and fallback, narrowed attempt claims, serialized entry, and confined signal-derived status proof to Unix. Re-review found a delivery race between separate handler actions plus missing unwind and sticky-initialization rules. The second revision used four ordered actions with a second conditional-default check, named both linearization points, required an RAII unwind guard, protected owner state, and stored initialization once. Re-review found that later environments still created unrelated tokens and that overlapping handler deliveries cannot support an absolute second-signal claim. The accepted revision binds the shared token into each winning environment, proves sequential reuse, and limits immediate forced termination to a later signal sent after an atomic armed-state acknowledgment. The same reviewer accepted the four-action process-lifetime design and confirmed the level-3 route. Red subprocess implementation then disproved the assumption that sent direct requests finish on the calling thread: SIGINT interrupts `ureq`, which abandons the response, and retry would send a second paid POST. The first amendment proposed an engine-owned scoped worker only around direct single-document and `find` execution. Review rejected it because process-directed SIGINT may select any unblocked worker. The current amendment adds Unix signal affinity instead: the caller and inherited request workers block SIGINT while one short-lived CLI carrier alone unblocks it. This requires the safe target-Unix `nix` signal-mask wrapper because the standard library and `signal-hook` expose none. Engine scheduling, request, and transport code remain unchanged. Re-review narrowed the carrier claim to threads created by entry, required `nix` to be optional under the Unix target and selected only by `cli`, opened the dependency policy, and fixed restoration precedence during partial activation. The same reviewer accepted the signal-affinity amendment and independently approved the dependency, target/feature gating, failure precedence, budgets, and retained level-3 route. A later broad run exposed nondeterministic record-test ordering: default width allowed either row to send first, and `kill` acknowledged queuing rather than handler completion. The final test amendment fixes `--jobs 1` and adds a hidden path that the normal carrier writes only after observing cancellation, so every reply release follows a deterministic phase boundary. Initial seam review required acknowledgment before queued stop, exclusive one-byte regular-file creation, non-product failure recording, cleanup, and exact hidden-surface documentation. The current seam includes each requirement. Final re-review required moving interrupt-state tests into an opened `cli/interrupt/tests.rs` submodule to preserve the 500-nonblank-line file ceiling; the split is accepted for implementation.

Independent code review rejected the first implementation because routing began before the shared token reset, the ratchet and production budget failed, routing-failure proofs were absent, cleanup ordering was incomplete, and sticky initialization used no real signal. Remediation reset and bound before routing, injected every routing failure, observed ordered cleanup, delivered SIGINT to every retained registration prefix in child processes, and consolidated tests. A second rejection found all-target Clippy failures in test helpers. The final remediation returned errors from integration helpers and flattened the child harness. The same reviewer accepted the result. Focused tests, all-target Clippy, policy, exact ratchet `37600/37600`, formatting, and whitespace pass. The change adds 350 net nonblank production Rust lines across five files and 899 net nonblank Rust lines in total. Every Rust file remains at or below 500 nonblank lines.
