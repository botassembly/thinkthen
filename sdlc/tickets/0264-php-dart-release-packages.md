# 0264: Pack PHP and Dart source with one matching C archive

Status: fresh independent design review accepted `b6869e87`; host-side implementation is in progress. The shared release helpers remain with ticket 0263 until its reviewed changes land. The [preflight](../records/0264-php-dart-release-preflight.md) cites current main `39f36f12` and the accepted 0249, 0260, 0261 and 0262 proofs.

## Outcome and retained behavior

One local Linux x86-64 invocation builds the existing versioned C archive and packs the integrated PHP and Dart source from the same clean commit. Each wrapper archive names that exact C archive by basename and SHA-256. A PHP 8.3 FFI caller and an independent offline Dart pub consumer load only unpacked package source plus the matching unpacked C library, each make the existing shared five-text Max call, and compare five values, three actual sends and three complete literal request bodies. The package route refuses missing, changed, mismatched or extra selected files before either consumer starts. This is a local direct-file pilot. It does not publish Composer, Packagist, pub.dev, a Flutter wrapper, native assets or a release bundle.

Keep the current `libraries/php/check.sh` source gate, Composer package identity `botassembly/thinkthen`, PHP >=8.3 with `ext-ffi`, absolute-library-path FFI contract, named failures, copied facts and pre-fired/native-deadline limit. Keep `libraries/dart/check.sh` source gate, pub name `thinkthen_dart`, `ffi` dependency, explicit native-library path, existing Dart and Flutter matrices, cancellation and Linux Flutter app proof. Preserve the accepted C header, shared and static member layout, default release parts, Go/C++ and C#/JVM pair modes, and full smoke's nine established required families. No runtime or public API change is needed.

The Flutter wrapper is **not** a second Dart package file in this pilot. `libraries/dart/flutter/pubspec.yaml` is private (`publish_to: none`) and depends on `thinkthen_dart` with `path: ..`; its example depends on both source folders with `path:` entries. The accepted 0249 source gate proves a real Linux embedder at its recorded pin, while the 0260 `Door.many` case covers the reexported Dart FFI conversion, not an installed Flutter package. This ticket's Dart archive and consumer cannot close the original issue's Flutter release requirements. A later bounded Flutter route must install the wrapper and app against matched native bytes, replace path dependencies before any publication claim, rerun the real embedder on its supported target, and keep other platform archives and hosts explicit.

## Local file and identity contract

The explicit pilot command is `release-pack x86_64-unknown-linux-gnu OUT c php dart`. It starts from a clean committed checkout, builds `part_c` once in non-reuse release mode, and requires that freshly built C part earlier in this invocation. Wrapper-only, reordered, `--reuse`, and an old C file already in OUT refuse. Record the source commit, host target, version, actual PHP/Dart/Rust tools, command, C member hashes and all three outer hashes. Engine dependencies are part of the C input; header equality alone cannot pin the native bytes. The final evidence commit may follow the build; the archive manifest pins the built commit rather than a later HEAD.

Name the new outer files `thinkthen-php-$V-$TARGET.tar.gz` and `thinkthen-dart-$V-$TARGET.tar.gz` beside `thinkthen-c-$V-$TARGET.tar.gz`, each with the existing adjacent `.sha256`. The PHP archive contains exactly `LICENSE`, `README.md`, `composer.json`, `autoload.php`, `src/ThinkThen.php`, `examples/direct.php`, and `THINKTHEN-PACKAGE-INPUTS`. It includes no C binary. The Dart archive contains exactly `CHANGELOG.md`, `LICENSE`, `README.md`, `pubspec.yaml`, `pubspec.lock`, `lib/thinkthen_dart.dart`, `lib/src/{allocator,door,typed}.dart`, and the manifest. The lock records the current hosted `ffi` 2.2.0 resolution for this local offline file; it is not a promise about future pub.dev publishing. Neither archive carries fixture logs, `.dart_tool`, pub cache, a copied native library, the private Flutter folder or an app build.

Reuse the strict five-line fixed-data `THINKTHEN-PACKAGE-INPUTS` format from 0261: `source_commit`, `target`, `version`, `c_archive`, `c_sha256`. Extend the one existing private `release-go-cpp-pair` validator with a literal `php-dart` mode after the 0263 shared-helper owner releases it; do not build another validator. The mode verifies the exact three selected family names and three sidecars, outer SHA lines, one manifest in each wrapper, equal source commits, target/version and each wrapper's C digest against the actual C archive. It rejects another PHP, Dart or C version/target entry, including a second sidecar. It treats manifest bytes as data, never shell input. The clean non-reuse build receipt establishes source provenance; the manifest alone is not a signature or proof that a later checkout HEAD built the files.

Teach `release-smoke` to invoke that same mode if either PHP or Dart family is present, before backend startup or an installed selector. Route both family names before its broad command archive pattern, pass `THINKTHEN_ARTIFACT` plus the selected `THINKTHEN_C_ARTIFACT`, and preserve its existing required-family list. A three-file pilot passes the pair preflight and installed selectors directly, not the full-bundle smoke. PHP/Dart remain conditional until separate reviewed workflow wiring makes them required. Do not dispatch a workflow, change site copy, add registry credentials or publish anything here.
