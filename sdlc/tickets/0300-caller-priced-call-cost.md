# 0300: Caller-priced cost in call and run facts

Status: Core, CLI, C and narrow SQLite refusal are built as a source candidate for fresh High code review. Fresh High design/API review accepted `5bde09bb5aa1f266ae358a56df38dc293cfed724` on 2026-09-29. The queue owner approves [ADR 0108](../planning/adr/0108-caller-priced-call-cost.md) within Ian's authorized pre-release API work. Strict readers and other typed hosts still need their separately claimed batches; no umbrella criterion is closed by this source slice.

## Outcome

Let a caller who knows its own USD input and output token prices see a whole-call or whole-command **estimated** cost next to final facts. Preserve every existing value, token field, request count, failure kind, C symbol and count-only month. The opt-in pair is engine scoped; CLI gets it from the configuration file. There is no provider tariff lookup, bill guarantee, price-based admission or new paid call. Token admission 0299, backend timing/IDs and durable non-CLI status have separate owners.

A concrete use: put `"usd_per_million_input":"0.042"` and `"usd_per_million_output":"0.168"` in a private `thinkthen.config/1` file, run `thinkthen decide ... --facts`, and read the final `estimated_cost_usd` string. A native caller supplies the same pair at engine construction and reads `call.facts().estimated_cost_usd()`. A replay reports zero new priced spend. No cost appears without both prices.

### Added public declarations

```text
fn Engine::estimate_reported_cost(&self, u64, u64) -> Option<String>
fn EngineBuilder::prices_usd_per_million(self, &str, &str) -> Result<EngineBuilder, Error>
fn Facts::estimated_cost_usd(&self) -> Option<&str>
```

## Contract to implement

- Use two exact decimal **strings**, `usd_per_million_input` and `usd_per_million_output`, in the CLI configuration and closed C/native settings JSON. Rust offers one `EngineBuilder::prices_usd_per_million(input: &str, output: &str)` setter; no per-question or per-call override. The selected engine pair applies to every live attempt it owns even if a question selects a different model; callers with different tariffs use separate engines. A mixed-model call cannot be billed faithfully by model from one pair, and this estimate says only what the caller's selected pair yields. No price environment variable or CLI flag is added.
- Both strings are required together. Omitted pair disables cost; exactly one, explicit JSON null, wrong type, sign, exponent, whitespace, nonfinite spelling, more than six fractional digits or a value over USD 1,000,000 per million tokens is Usage before any send. Accept ASCII digits with optional single dot and one to six following digits; at least one integer digit, leading zeros allowed, and `0`/ `0.000000` valid. Canonicalize to integer micro-USD per million in one pure parser; C uses the public builder bridge, never a copied private core parser. Existing lower-tier malformed configuration retains its current validation order; the setter replaces a valid pair on a builder. Configuration-file unknown keys remain refused.
- `estimated_cost_usd` is an optional **fixed six-decimal string** in public Rust `Facts` (`Option<&str>` getter), C owned facts JSON and borrowed started-error facts, all migrated typed host facts, and the final CLI `thinkthen.run/1` `--facts` line. It is absent without the pair; explicitly priced zero work returns `"0.000000"`. It is never JSON null or a float. Multiply each complete reported `u64` input/output total by its own integer micro-USD-per-million price using checked `u128`, add, divide by one million and round half up once to a micro-USD. The stated price maximum and two `u64` totals fit `u128`; checked operations still refuse malformed internal overflow as a defect before publishing a cost, never wrap or saturate money. A tiny positive result may round to `"0.000000"`; `requests_sent` still distinguishes it from no work, and the string is never an admission authority. No money enters per-row `meta`, recording identity, `status`, `thinkthen.usage/1` or its retry sidecar.
- Complete cost requires **both token kinds from every actual started attempt** **and a valid exact token sum**, independently. `CallFacts` compares its own sent attempts with usage-bearing replies and latches token-sum validity when `Usage::checked_plus` rejects an addition; retain its current public optional-token behavior. The separate CLI `RunSnapshot` compares command send marks with usage-bearing replies **and** carries a private `token_sum_valid` flag in `engine/usage/facts.rs::State`, initially true and latched false when `Counters::tokens`/`Counters::add` cannot commit a token delta to `Queue.totals` (including `Counts::checked_add` failure). Set/check the flag under the same queue lock as the token addition; a failed durable month write alone does not invalidate an otherwise committed process sum. A lock failure that drops a token update also cannot yield cost. Keep the existing response-presence rule for reported partial usage, but make `usage_known` false when token arithmetic is invalid so stale process token totals are **omitted**, never emitted as complete or replaced with zero. Cost has the additional all-started-attempts rule; neither predicate is inferred from `Some` totals. This covers retries, splits and later ordinary requests. A failed first attempt followed by a usage reply may retain reported tokens but omit cost; two complete replies whose `u64` total overflows must also omit cost, even when send/reply counts match. A logical failure after all attempts supplied complete, exactly summed usage may carry cost in copied failure facts; pre-start refusals have no facts. No live sends, including empty work and cache/replay-only calls, means known zero if priced.
- **Pre-freeze compatibility choice:** amend the existing closed `specification/result.schema.json` `facts` definition and `specification/result.md` to allow exactly this one optional member; keep `callSuccess`'s outer two keys, all old members and old strict unknown-key refusals. Extend the existing `thinkthen.run/1` contract with the same optional member. With no price configured, existing result bytes and readers keep their behavior. A priced producer intentionally breaks older strict facts validators, including installed Ada, Objective-C and COBOL binaries; older tolerant readers may silently drop the cost. A new matching package must update and prove its decoder before advertising priced support. Do not claim that editing a schema upgrades an installed binary. A separate `facts/2` envelope or new C symbol adds a second result path and more migrations while still requiring caller selection; decline it before 0.1. This is a reviewed pre-release conditional break, not universal backward compatibility.

## What the build taught us

The first slice confirms that complete replies and an exact accumulated token sum are separate facts. `CallFacts` and the CLI process queue each need their own validity latch: the latter can retain stale totals on overflow, while a durable month-write failure after a committed process addition does not invalidate cost. A valid configuration price pair had to be classified as Usage on malformed input at the command conversion boundary; ordinary pre-existing configuration errors keep their prior class. The C crate reaches the one core decimal parser through `EngineBuilder`, and SQLite now refuses both newly core-valid keys explicitly until host adoption. Public `Facts`, private prices and C failures redact money from `Debug`. The C driver requires two fields even for its facts getter, a fixture detail caught by the focused failure-copy proof. `public/settings.rs` and `public/options.rs` exceeded their source caps during wiring, so environment capture and the existing private diagnostic tests moved to cohesive child modules; their behavior and prior tests remain. The additive public inventory holds exactly the three new reviewed declarations. No old test was retired: the new price tables reuse the existing public/compiled-command/C loopback fixtures, and the existing unpriced facts receipt remains the byte-shape oracle. Python/R aggregate overflow and copied strict readers stay for separately claimed batches; the source-only results here do not qualify their packages.
