# 0354: deep records name their limit, and `find` returns its probability at the C door

Status: in progress. Lane claude-3. Branch `ticket/0354-deep-records-and-find-probability`. Plan: `sdlc/planning/cleanup-2026-09-30.md`. Serves two issues that block 0.1: `../issues/closed/2026-09-30-deep-json-record-refused-as-not-valid-json.md` (slice A) and `../issues/closed/2026-09-30-find-returns-no-probability-in-c-interface-languages.md` (slice B). Both slices land in one merge.

## Outcome

Slice A. A JSON record nests at most 127 levels of arrays and objects. `specification/records.md` names that limit. A deeper record is refused with its own sentence, `the JSON nests more than 127 levels of arrays and objects, the most this tool reads`, in place of `the record is not valid JSON`. The command, the Rust library and the C door read JSONL records, annotate documents and annotate `on` records through the one parser, so each gives that sentence. Edge-table rows pin 127 levels as accepted and 128 as refused.

Slice B. The C door's `find` value is `{"index":N,"unit":TEXT,"probability":P}` for the selected unit, or `null` when `none` wins. That is the shape Python, TypeScript and Ruby already return, with a zero-based index. The 13 languages on the C door read the door's value as host JSON, so they return the probability with no binding code. The shared type corpus case `18-find-second` expects the new value, so every C-door port proves it.

## Evidence

- Starts from: main `d3fd19419`.
  - Slice A. Release QA found on main `f0308dd9d` that a `--jsonl` record 127 levels deep is accepted and 128 levels deep stops the run at exit 2 with `the record is not valid JSON`. At record 1 the typed-JSONL hint is added. The lane reproduced both on `d3fd19419`. `Json::parse` in `crates/thinkthen/src/core/json.rs` calls `serde_json::from_str`, whose recursion limit refuses the 128th open bracket. `Json::parse` turns every error it does not name into `JsonError::Syntax`. `records.rs`, `question_file.rs`, `question_set.rs`, `settings.rs`, `backend_profile.rs` and the library's annotate `on` reader (`public/bulk/annotation.rs`) all parse through `Json::parse`. `annotation_record` reads a whole document that fails as `Syntax` as plain text. The command's whole-document `annotate` (`cli/annotate/asker.rs:371`) and the library's annotate `on` reader both call it. So today a document or annotate record 128 levels deep becomes text, and an `on` question then fails with the text-has-no-members sentence. Python, TypeScript, Ruby, R and the SQL extensions reach the same library reader. The C door's `relate` reads each record with its own `serde_json::from_str` in `libraries/c/src/door.rs:200` and refuses a 128-level record as `a relate record is not JSON`. `cli/mod.rs:215` adds the typed-JSONL hint only for `JsonError::Syntax`. The C door passes `records` and `units` as strings, and its annotate reply holds named answers only, so no host parser reads a deep record back.
  - Slice B. `specification/types.md` lists the `find` answer as "Selected unit" and the header (`libraries/c/include/thinkthen.h`) as "the selected unit or `null`". `specification/find.md` covers only the command. The command prints the unit and gives every probability under `--details`. The Rust library's `Found` holds each candidate's probability. Python returns `{"index","unit","probability"}` or `None`, TypeScript returns `Found {index, unit, probability}` or `null`, Ruby returns `Found(index, unit, probability)`, and R returns `place`, `unit` and `probability`. The C door's `call.rs` writes `found.value().selected()`, the unit alone, so the door drops the probability. The 11 C-door port folders (Go, C++, C#, the JVM family of Java, Kotlin and Scala, Dart with Flutter, PHP, Swift, Zig, Ada, Objective-C, COBOL) hold no `find` wrapper. Each passes the door's value through as host JSON, as ADR 0112 requires. Their type-corpus runners check each value against the generated schema's `find` definition and against the corpus response. Their own matrix tests check `find` as the string `"find-one"`. Every native runner (Rust, Python, TypeScript, Ruby, R) already derives the selected probability from `conformance/cases.json`'s `operation.probabilities`; the C door's `tests/door/cases.rs` checks the unit alone.
- Keeps: every other refusal and its sentence, including `the record is not valid JSON` for malformed JSON, the typed-JSONL hint on a syntax failure at record 1 (a too-deep record at record 1 gets the depth sentence and no hint, since depth is not a framing mistake), the whole-input sentence with its line and column, and the duplicate-name and non-finite sentences. No input byte appears in any message. The command's `find` output and its `--details` object are unchanged. Every other door value, the C ABI and its symbols, every request body, and the Python, TypeScript, Ruby and R `find` shapes are unchanged. The existing 16 MiB record limit and its refusal stay.
