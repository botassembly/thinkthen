# 0109: Port the SQLite surface

Status: revised after review; confirmation pending. Owner: Claude.

## Outcome and authority

Port the SQLite extension from tag `surfaces-wave7-frozen-2026-09-24b` (`9df8bae9`) onto the public Rust API as the unpublished crate `thinkthen-sqlite` at `databases/sqlite`, in its own Cargo workspace. `.load ./thinkthen` keeps the eight functions (`thinkthen_decide`, `_choose`, `_score`, `_tag`, `_annotate`, `_details`, `_usage`, and the `_warm` aggregate) and the two table-valued functions (`thinkthen_recognize`, `thinkthen_relate`). Every call reaches the real engine through `thinkthen`. Queue item 3 of `sdlc/planning/one-line-plan-2026-09-24.md` lists SQLite among the surfaces after C.

Draft ADR 0047 fixes the crate's place and its checklist. Ticket 0093 sets the workspace, lint, ratchet, and surface-rung pattern. Ticket 0095 fixes the members this binding calls. Ticket 0105 is the accepted template for a surface port. Section 3.2 of `sdlc/planning/surfaces-port-guide.md` gives the port map. The guide's "Shared rules" section (main at `bced9c4d`) binds every surface ticket, and this ticket follows all six. Ticket 0117 owns the loopback backend arms that the tests below need. The 2026-09-24 design review (`sdlc/records/2026-09-24-design-review-0109.md`) found fourteen items. This version answers all of them. Ian can overturn every decision below.

## Design and decisions

1. **The Rust API.** The extension links `thinkthen` by path and calls the public Rust API through `rusqlite`, as the tag does. It does not load `libthinkthen.so` from ticket 0094. The C header gains no interrupt symbol (0094). The C door would also add a second shared library to every install and a JSON round trip to every row. This ticket builds on 0094 as the reference FFI edge (ADR 0047 item 7): one panic guard, one error-kind table, one `unsafe` module, and an exported-symbol check. 0094's churn probe covers R7-1 for the engine both crates link.
2. **Engine and width.** Every call uses `thinkthen::default_engine()`, configured by what `Engine::from_env` reads. SQL cannot name a backend or a key. `default_engine` omits width, and the process runs at the fallback width 4. The frozen contract's one width setting is `EngineBuilder::width(self, value: u8)` (0084). Under 0077 the first engine built with an explicit width sets the process cap, and engines with no explicit width follow it on their next call. The extension carries its own copy of `thinkthen`. Only code inside the extension can set its cap. The shared rules give a host with no engine object a test hook for this. Here the hook is the SQL function `thinkthen_test_width(n)`. It is registered only when the crate's test-only Cargo feature `test-width` is on. It builds `Engine::builder().width(n)?.build()`, drops that engine, and returns `n`. It sends nothing and reads no environment variable. A different later `n` raises 0077's `usage` sentence. A test that needs parallel requests calls it in its own child process before any other call. The shipped library builds without the feature, and the package content check refuses the hook's name (gate section). The public surface stays at eight functions. The coordinator decided on 2026-09-24 that SQL users get no public width setting in this ticket. A public setting can be its own ticket if a user needs one. ADR 0017 says the request limit earns its place in the databases. SQL cannot reach `max_requests` or a cache cap at 0.1 either. This ticket adds neither. Ian can overturn each of these.
3. **Cache.** The tag's saved-answer map (`Saved`, `SavedAnswers`, and the hit counter) retires. The engine's bounded disk cache (0062) replaces it. Warmed answers now outlive the process, as `sdlc/planning/databases/sqlite.md` asks. `thinkthen_usage()` returns `Engine::usage()` as `{"requests_sent","cache_answers","input_tokens","output_tokens"}`. The `'reset'` spelling keeps its refusal sentence. With the cache off, a warm pass still judges every row, and the queries after it send again. The README says so and names the switch `from_env` honors. If 0086 lands with no cache-off switch in `from_env`, the README drops that sentence, and the cache-off test goes with it.
4. **Questions.** Plain text builds `Question::decide(text)?.cut()`. Text that starts with `{` goes to `Question::from_json`. `'@name'` reads the named file through the tag's `named_file` (one `O_NONBLOCK` open, a regular file of at most 1 MiB, symlinks followed, one refusal sentence for every cause) and then calls `from_json`. `from_json` returns `LoadedQuestion`. A `Question` goes to every function. A `Banded` question goes to `thinkthen_decide` and `thinkthen_details` only. `score`, `choose`, `tag`, and `warm` refuse it with `usage` naming those two functions, before any send. `thinkthen_annotate` reads its set through `QuestionSet::from_json`, with the same `'@name'` form. A broken rule in a file maps to `local`, and in an argument to `usage` (0095, Q16). The tag's question and question-set caches stay: 4,096 entries each, oldest out first, re-read when a file's modified time or size changes.
5. **Results.** `decide` returns 1, 0, or NULL. `choose` and `tag` call `details` and read `value()` with no added send (G5). `choose` returns the label or NULL, and `tag` returns a JSON array. `score` returns the position as REAL. `annotate` returns `AnnotatedRecord::value_json`, with a failed member as `{"failed":{"kind":…,"cause":…}}`. `details` returns `Details::to_json`, equal to the command's `--details` document. A SQL NULL text returns NULL and sends nothing (branch case 81). A BLOB argument, or text with a NUL byte or invalid UTF-8, raises `usage` before any send (G11).
6. **Every call runs on a detachable worker.** This follows the shared rule on Ctrl-C and 0105 decision 6. The engine's interrupt check does not run during one blocking send, and a send may hold for the 30-second request timeout. The CLI's Ctrl-C calls `sqlite3_interrupt`, so a user would wait for the reply. Design: every function body that can send runs on a spawned worker that never touches SQLite. That covers the six scalars, `thinkthen_recognize`, `thinkthen_relate`, and each flush of `thinkthen_warm`. The worker owns an `Arc` of the parsed question or spec, its texts or entities as owned values, and a clone of an internal `CancelToken`. It builds its own `CallOptions` with that token and the call's deadline. It builds any `Batch` itself. `Batch` is neither `Send` nor `Sync` (0084). The calling thread waits on a channel with a 50 ms timeout, so a finished call returns at once. On each tick it reads `sqlite3_is_interrupted` on the calling connection. On an interrupt it cancels the internal token, detaches the worker, and returns `thinkthen cancelled`. The engine enforces the deadline inside the worker, blocking send included (0076). The detached worker finishes the requests already sent and starts no new one. The worker ignores a closed channel. A channel that closes with no result returns `defect`. The extension keeps the tag's `RTLD_NODELETE` pin. A detached worker's code then stays mapped after the loading connection closes. The binding passes no `CallOptions::interrupt` check. It needs no wrapper for the connection handle. Cost: about 70 lines and one thread spawn per call or flush. This design retires the tag's shared watcher thread, its registry, the `pthread_atfork` handler, and the fork generation.
7. **The detached worker is the known exception to ADR 0017.** ADR 0017 says zero threads outlive a call. A detached worker outlives its call until its sent requests end, at most the 30-second request timeout. It holds its width permits until then. A cancelled warm flush can hold as many permits as the width. The README and the ADR 0047 SQLite section record this exception, as 0105 does for Python.
8. **Warm.** `thinkthen_warm(question, text)` groups rows by question in first-seen order with the tag's hash index. It flushes each group at 256 rows through `decide_many_with` on the worker. The next flush starts only after the last one returns. Equal pairs in one pass are asked once. Warm takes a decide question only. Any other kind raises `usage` naming `thinkthen_decide`. It returns the count of distinct pairs judged.
9. **Deadlines.** Each scalar keeps the three-argument spelling. The last argument is milliseconds. An INTEGER goes unchanged to `CallOptions::deadline_millis`. That member applies ADR 0041 whole (0095): `-1` is none, `0` is spent and sends nothing, and another negative or a value above 4,294,967,295,000 is `usage`. A REAL is accepted only when it is finite, whole, and inside the `i64` range. The binding then passes it as an `i64`. A REAL outside those limits, TEXT, BLOB, and NULL are `usage`. The message names the value as SQL gave it. The binding computes no deadline instant of its own. SQL has no boolean, and `TRUE` is the integer 1. A boolean deadline cannot reach the binding (R5-8).
10. **Recognize.** `thinkthen_recognize(text, kinds)` keeps its eponymous table-valued shape and hidden arguments. `kinds` is a comma list, a JSON recognize section, or `'@name'`. The binding composes the recognize JSON. It reads that JSON with `serde_json` before `Recognize::from_json`. `Recognize` has no public getter for relation rules. A `relations` member therefore raises `usage` naming `thinkthen_relate` before any send. The binding adds no grammar. The columns become main's `(name, kind, start, end, strength)`. The tag's `text` column is renamed `name`. Offsets count Unicode scalar values, and SQLite's `substr` counts the same way (case 68).
11. **Relate reads entities.** Main's relate takes entities with a name and a kind (`specification/relate.md`). The tag's call over body text has no meaning there. The new call follows the database relate issue (`sdlc/issues/2026-09-23-relate-in-a-database-kinds-new-rows-and-the-cache.md`, item 1) and ADR 0047 item 9: `thinkthen_relate(table, id_column, name_column, kind_column, rule, …)` with one to four rules. Each rule is `NAME`, `NAME=SOURCE:TARGET`, `either:NAME`, or `either:NAME=SOURCE:TARGET`, or a single JSON relate section or `'@name'`. The binding composes the version-one relate file and calls `Relate::from_json`. The nested read-only `SELECT` of the tag's `read_records` stays, with quoted identifiers. It runs on the calling thread before the worker starts. It dedupes rows by name and kind in first-seen order. It stops reading at the 256th unique pair and raises `usage` naming the 255 limit. A NULL or blank name or kind raises `usage` naming the row's id. The worker owns the `Vec<Entity>`. The output is `(relation, source, target, probability)`, and `source` and `target` carry the id column's values. Each edge is emitted once for every pair of rows holding its two endpoints, so the result joins back to the table by id. The tag's `name` output column is renamed `relation`, as in `Edge`.
12. **Direct-only and volatile.** Every function keeps `SQLITE_DIRECTONLY`, and both modules keep `VTabConfig::DirectOnly`. None carries `SQLITE_DETERMINISTIC`. The load-time check keeps the 3.50.0 floor and its refusal sentence. Below 3.50.0 a CHECK constraint in an untrusted database reaches a volatile function. The host's `is_interrupted` comes from its own API table through the tag's `ApiRoutines` tail. `libsqlite3-sys` 0.38.2's loadable bindings stop at 3.34.
13. **Errors and panics.** One exhaustive `match` maps `ErrorKind::name` to the message prefix `thinkthen <kind>:` and a SQLite result code. It keeps the tag's codes: `cancelled` is `SQLITE_INTERRUPT`, `usage` is `SQLITE_CONSTRAINT`, `local` is `SQLITE_CANTOPEN`, and the rest are `SQLITE_ERROR`. A retryable failure keeps ` (retryable)` after the kind. One guard wraps every function body, vtab callback, and worker body and turns a binding panic into `defect`. `thinkthen` already stops engine panics at its public methods (0086).
14. **Test isolation.** Each test gets its own loopback backend and its own product cache folder (shared rules). Ticket 0117 supplies one backend per test, a held reply that can hold again, and a fixed delay. This ticket adds no arm and designs none. Every test child sets `THINKTHEN_CACHE`, `XDG_CACHE_HOME`, and `XDG_CONFIG_HOME` to fresh temporary folders. The engine cache, the usage totals, and the configuration file then never cross tests or reach the user's own. Every wait for a `count` reading has a 5 s bound. Every held test arms a release timer 2 s after its signal. A planted run then fails on its assertion and does not wait for `timeout 300`. The rung's shared port serves only unheld, uncounted cases.
15. **Toolchains.** The SQLite 3.50.0 amalgamation and the host library and CLI built from it live under `~/.cache/thinkthen-toolchains/` (shared rules). They never go in the product's answer cache or the repository. `databases/sqlite/setup.sh` is the one-time setup. It copies the amalgamation from a folder the user names, or fetches the zip from sqlite.org once. It then checks two SHA-256 values pinned in the repository and refuses on a mismatch: `sqlite3.c` `76d2bc5ce0038e5805f420f4ce6abde81ab880aac122b930923f4411dd84aaec` and `shell.c` `ab201c205a3adf299faec65732f18815174df64e398e6c376e42ca7954509cb1`. The zip's own hash is not measured here. `check.sh` never fetches.

## Where the check runs

The tag's check ran and passed at the freeze, on its second run.
