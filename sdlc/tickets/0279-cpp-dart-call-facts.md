# 0279: Return owned facts from C++ and Dart typed calls

Status: prepared for fresh design/API review. Source pin: `origin/main` `a4de0ab02`. Ian's every-library-call ruling and the accepted 0255 C facts contract authorize this pre-0.1 wrapper migration; ADR 0106 is the reviewed Go/PHP precedent, not an edit claim here. Root owns implementation approval and issue closure.

## Outcome and exact routes

Migrate the existing public typed `decide`, `many` (decide-many), `recognize`, and `relate` methods in **both** wrappers to their corresponding C `*_with_facts_opts` symbol. Each method makes one native operation and returns its former typed value together with **that operation's final, owned facts**, without a setting, process-total substitute or second asking call. The native call may itself send multiple provider requests. Preserve answer order, probabilities, recognition/edge values, arguments, deadlines and cancellation, six failure kinds, and old C ABI. Keep C++ `tt::call` and Dart `Door.call`/`ask` JSON envelopes, and the already copied started-failure facts (`tt::Failure::facts`, `DoorFailure.facts`) unchanged. No bare-success typed alias is added. This is three verbs plus decide-many bulk, not four separate verbs.

| Existing method | C++ success | Dart success |
| --- | --- | --- |
| `tt::decide` / `Door.decide` | `CallResult<Judgment>` | `CallResult<AnswerValue>` |
| `tt::many` / `Door.many` | `CallResult<std::vector<Judgment>>` | `CallResult<List<AnswerValue>>` |
| `tt::recognize` / `Door.recognize` | `CallResult<Json>`; existing `recognizeTyped(result.value)` still decodes | `CallResult<Recognition>` |
| `tt::relate` / `Door.relate` | `CallResult<Json>`; existing `relateTyped(result.value)` still decodes | `CallResult<Relations>` |

Use public `CallResult<T>{value,facts}` and `CallFacts` in each host's style: C++ member names `value`, `facts`, `records`, `requestsSent`, `cacheAnswers`, `seconds`, `inputTokens`, `outputTokens`, `model`; Dart has the same lower-camel names and final fields. Required facts are nonnegative integral `records`, `requests_sent`, `cache_answers` and finite nonnegative `seconds`. Optional input/output tokens are nonnegative integers and model is a string; absence stays `std::nullopt`/Dart `null`, while a **present null or wrong type is invalid**, including on required keys. Accept the C facts object's named fields without fabricating price, request IDs, digests, full per-row details or server time. C++ can use its existing `Json::get<size_t>()` exact-integer boundary (integers beyond 2^53 are refused by its parser rather than rounded); Dart uses `int` with explicit presence and type checks. Successful native return with malformed/missing facts is a host decode failure, never factless success.

## Ownership and failure boundary

In `libraries/cpp/include/thinkthen/door.hpp`, keep the result types and one shared facts decoder in that installed header; no new header or JSON parser is needed. Each C call initializes independent result/facts output slots, calls the matching facts `_opts` once, takes every returned `char*` immediately into `OwnedString`, validates all slots, decodes/copies both objects, and lets RAII free native strings on every throwing path. `many({})` still invokes C with facts slots and returns an empty vector with `records=0`, zero sends and absent optional usage. On nonzero C return, no value or success facts escape; verify unchanged sentinels and copy the borrowed failure slot on the **same calling thread** before any later native operation. Returned facts survive later calls, failures and engine reset. C++ callers must still join worker/canceller threads before token or engine destruction; do not claim new synchronization or engine lifetime guarantees.

In `libraries/dart/lib/src/door.dart`, replace the four old FFI lookups with exact `_with_facts_opts` signatures; put `CallFacts`/`CallResult<T>` and strict decoding in `lib/src/typed.dart`, exporting them from `lib/thinkthen_dart.dart`. The `structured` helper must carry the same result/facts pair (or become private with its current direct fixture caller migrated), while `recognize`/`relate` keep their typed value decoders. Allocate result, facts pointer and length slots with the existing `_OwnedPointers`; initialize distinct sentinels. Copy/decode both C-owned strings by their returned lengths, free each with `freeString` in `finally` even when the other decode throws, then release Dart-allocated slots in the outer `finally`. Read borrowed failure facts before another native call; pre-start refusal has none. Preserve the current isolate join-before-free rule. A Dart isolate launch alone is not proof of overlapping native calls.

## Evidence

- Starts from: The [every-call ruling](../issues/2026-09-26-every-surface-should-give-back-run-facts.md), accepted [0255](0255-typed-c-call-facts.md) owned C outputs, current C++/Dart old-symbol calls, and ADR 0106's reviewed pre-0.1 Go/PHP return precedent.
- Keeps: Frozen C ABI and old symbols, JSON Call envelopes, former typed values/order, same-thread started-failure facts, host cleanup and lifetime rules, and existing no-send/cancellation boundaries.
- Changes: Four direct typed routes per host return owned value plus strict final facts from one C `_with_facts_opts` call, with migrated C++/Dart/Flutter direct callers and no bare alias.
- Proof: Focused counted four-route, omitted-usage, empty-bulk, decoder-refusal, typed started-failure/later-call/close and held-overlap cases; matching C exports and selected installed-source C++/Dart/Flutter consumers.
- Defers: Fresh design/code review, clean final-pin release archives and actual runner, other wrappers, full detail/cost/vendor timing/IDs, and held SQL/DataFrame work.

## What the build taught us

Preparation found the existing Dart public `structured` helper and Flutter facade are direct typed callers that the source-only door migration must include. It also found that C++ can keep the new public types in its already installed `door.hpp`; adding a new header would need explicit CMake and release-pack inventory work. Build evidence and measured growth belong here after implementation, not in this preparation status.
