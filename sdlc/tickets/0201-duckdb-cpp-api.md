# 0201: Move the DuckDB extension to the C++ API

Status: accepted design, 2026-09-27. The reviewed design is `c7000a4a`; `sdlc/records/0200-0201-design-review.md` records the paired review. Owner: Codex. The DuckDB proof lane is active; the full product port has not passed review.

## Outcome and authority

A DuckDB query using a ThinkThen scalar gets a usable bind step and a real query lifetime. A constant invalid question fails before any backend request. A signal that arrives after the last engine call belongs to the ending query, so the next query answers normally. Ticket 0200's DuckDB query deadline uses the same lifetime across chunks and expressions. The extension is built through DuckDB's C++ API, while the one Rust engine still makes every judgment.

Ian directed Batch I3 and the C++ migration. `sdlc/planning/work-plan-2026-09-27.md` places this after the SQL error and budget design. This ticket implements both open issues, not merely a comparison or spike. The coordinator owns its runtime lane after the 0200 design settles. Ian can overturn the bridge, key, and packaging choices in ADR 0081. The C++ migration itself is his direction.

Relate still sees committed data through its separate connection, with its present row and plan guards. A C++ API opportunity to see temporary tables does not silently change that contract.
- Keep the stock-host v1.5.5 target and the rule that a release package loads without a Rust toolchain. No paid or live call enters a gate.

### Proposed read-only database amendment, pending review

The C++ bind has the caller's `ClientContext::db`, so it can select the correct database directly. The old random identity probe was necessary for the C API bridge, but it prevented relate on a read-only database because the probe could not attach. The proposed 0201 behavior allows relate on a read-only database through its own connection while retaining one committed-only, read-only `SELECT`, the 255-row and holding-plan guards, caller settings and file permissions, cancellation, and no writes. A focused stock v1.5.5 child created a file database with two staff rows, reopened it with `read_only=True`, loaded the C++ candidate, and returned two edges after one loopback send. This is a new supported case, not proof that the old refusal was retained. The coordinator must review the contract change before acceptance.

If accepted, replace the probe and read-only sentences in `databases/duckdb/README.md` and `sdlc/planning/databases/duckdb.md`, amend ADR 0038's historical C API explanation, and replace the obsolete probe tests in `databases/duckdb/tools/databases_suite.py` and their `source_checks.py` expectations with direct database-identity and read-only witnesses. The old `r4_4` forged-probe and `r5_26` minted-identity cases cannot prove the C++ route, because no identity probe exists there. Keep the two-file and attached-`USE` routing proofs, closed-file lock release, and caller-permission cases.

## Change and ownership

1. Pin DuckDB C++ v1.5.5 source and the C++ extension template. Build one C++ extension binary linked to a Rust static library. Export only a small C ABI from Rust. The C++ side owns DuckDB registration, bind, vectors, settings, file access, table and aggregate functions, and statement state. Rust owns question parsing and calls to the public engine. Neither side unwinds, retains a borrowed buffer, or frees the other's memory across the bridge. The first proof fixes typed row/result encoding and ownership, including nested lists and structs, before porting a verb.
2. Add bind callbacks for all scalar overloads. For the nine ordinary scalars, validate foldable constant questions, question sets, member lists, relation rules, and deadlines at bind. Store validated values in copyable `FunctionData`. Permit nonconstant arguments and validate every row of an ordinary scalar's chunk before that chunk sends a request. Bind sends nothing. A bad constant on an ordinary scalar raises the classified error with zero requests. `thinkthen_try_details` follows ADR 0080's row recovery instead: bind stores a bad foldable question as typed failure data without raising, and invoke emits a safe failed JSON value for its non-`NULL` rows. Nonconstant questions are handled independently per row. Its usage, local, and backend failures do not abort later good rows; host interrupt, cancellation, deadline, and defect stay fatal. Register all ten with their settled result types and volatile marking.
3. Install one per-connection `ClientContextState` as the statement owner. Capture the signal sequence and one monotonic I2 expiry at query begin. `SET thinkthen_query_budget_ms = n` follows ADR 0080: `-1` means none, `0` means spent, and positive representable milliseconds set the budget. Share it across all scalar expressions and chunks. A state installed during its first bind initializes that active query once, since it missed `QueryBegin`; the first-use fallback starts late and does not claim to bound earlier SQL work. At query end, clear the owner and spend a late signal. A newly begun query snapshots a fresh sequence. The Rust call receives the remaining query time and any smaller trailing deadline. An expired budget refuses before send. Query deadline and host cancellation remain statement errors.
4. Port all ten scalars, the usage table, warm aggregate, and relate to C++ DuckDB host calls. Remove the raw DuckDB C API dependency, registration, and metadata ABI mode in the same landing change. Keep the process-wide Rust engine registry, throttle, and counters, including I2's resident-engine and retired-counter rule. Update `check.sh`, setup, source checks, package metadata, the policy plants, ratchets, pages, and the two issue dispositions with the behavior that actually passes.

The accepted prerequisite proof at `981c686d` showed a caught Rust panic still printed its payload twice to stderr. The bounded correction at `a464ad12` was independently accepted. It installs a delegating hook once, keeps the direct bridge panic payload out of stdout, stderr, and the SQL error, preserves an unrelated thread's prior hook, and checks a successful next query. The bind and owner proof at `769fa79e` was also independently accepted for API mechanics. These proofs do not establish product inference, host cancellation, or worker panic secrecy. Every Rust export, including free, and every C++ callback must keep unwind or exceptions on its own side of the ABI.

### Proposed internal panic diagnostic boundary for separate review

The product bridge installs its direct-call hook at DuckDB extension load, before bind or any Rust export can panic. Add one private, process-wide delegating diagnostic hook and a thread-local, nesting-safe engine scope in `crates/thinkthen/src/engine/workers.rs`. The hook emits no payload when the current thread is inside that scope and otherwise delegates to the hook it replaced. Install it once before entering the first engine scope. A drop guard restores the previous depth during unwind, including nested engine calls and worker teardown. `crates/thinkthen/src/public/options.rs::guarded` enters that same scope around its existing catch. The `on_worker` and `scoped_observed` worker closures enter it on their own threads before `send`, `begin`, or `work`; a caller-thread marker alone cannot cover them. Keep the current fixed `Error::Defect` text and non-retryable classification. Do not add a public panic API, a product fault switch, or a per-call process-hook swap.

Host interrupt checks must still fire, stop workers, and resume their panic payload unchanged after joining. The private scope temporarily delegates to the previous hook while `Stop::interrupted` calls the host check. `Cancel::checked` also invokes a host check directly; its one invocation in `crates/thinkthen/src/engine/mod.rs` must use the same temporary delegation. That is the only 0201 edit to `engine/mod.rs`; ticket 0155 landed before this file transferred. This preserves the prior hook for direct public-engine callers. A check invoked from DuckDB remains inside the outer bridge marker, so that bridge guard may suppress its diagnostic even while the panic propagation stays unchanged. `engine/mod.rs` already exposes `workers` within the crate, so no module export is needed. The DuckDB bridge keeps its separate load-time guard for bind and FFI code that can run before the public engine is called. The engine hook can then delegate to the bridge hook for an unrelated host thread. Neither hook can prevent a host from replacing the process-global hook after initialization or make concurrent hook registration atomic. Those limits concern host replacement; a panic emitted by ThinkThen's marked direct or worker code must not expose its payload under the installed hooks.

The smallest negative proof uses a child process and distinct synthetic markers. A key/evidence marker in a panic from `workers::on_worker`, reached through the real public `guarded` path, must appear in neither stdout, stderr, nor the returned error; the error retains fixed defect kind and non-retryability, and a later normal call succeeds. A separate marker from the `scoped_observed` spawn closure must also stay out of diagnostics. A direct public-engine host-interrupt callback panic through `Stop::interrupted` must instead reach the prior host hook and resume with its original payload only after its workers join. Exercise the direct `Cancel::checked` callback path separately with another marker and the same hook, payload, and join assertions after the transferred call-site edit. An unrelated host thread must still reach the prior hook. The fixture lives in private tests, with no public fault hook and no model calls. The existing direct-bridge child proof remains; an in-bridge host callback may still be suppressed by DuckDB's outer marker as stated above. Fresh High review accepted the design at `3d368d59`; fresh Sol High code review accepted the shared guard at `7d4b4b74` against `26ae542e`; the product candidate still needs its integrated boundary proof before full 0201 acceptance.

No secret type enters this ticket. The key channel stays as in the retained behavior. A secret type would change configuration and persistent-storage behavior and needs a separate decision. No upstream DuckDB report is sent under this ticket.

## What the build taught us

The accepted design's C++ bind and statement-owner callbacks worked in the pinned stock v1.5.5 host. The bounded proof established prepared, failed, multi-expression, first-use, and 2,049-row ownership before the product port. Current main still ships the C API extension; the branch's C++ candidate has not replaced it.

Catching a Rust panic returned a fixed error but let the default hook print its payload. A one-time direct bridge hook fixed only its own thread. Engine worker threads required a separate private diagnostic scope in both worker routes, and direct host interrupt callbacks needed temporary delegation to preserve their original hook and panic payload after worker join. The design amendment and child proof exposed these requirements before the full port. A host that replaces a process-global hook after load remains outside ThinkThen's control.

The first product slice found that the repository policy expects raw-pointer code in a named FFI module. Moving the bridge ABI to `ffi.rs` preserved its behavior and made that boundary explicit. The stock-host verifier then caught a local test environment without DuckDB's pinned Python module; installing `duckdb==1.5.5` restored the focused check. The grouped decision and probability paths now reuse validation and first-seen deduplication, with real loopback sends. The caller-file-system slice showed that `FileSystem::GetFileSystem(ClientContext)` already supplies the client opener; passing a second opener refused an allowed file. The focused absolute, missing, denied, malformed, home-directory, and size cases now pass. The cache-folder probe reuses the same caller file system and the existing Rust registry. It required a copied UTF-8 folder in the by-value bridge settings while C++ retained its backing string through each synchronous call. Allowed, invalid-relative, and denied-by-settings paths now pass in the stock host; broader permissions remain to check. Remaining scalar, table, aggregate, full file-permission, signal, query-budget, and package proofs stay in this ticket; none is a completed product claim.

The listed `choose`, `score`, and `tag` path uses a checked private result codec because DuckDB owns its SQL list values and Rust owns the engine's annotated records. The stock-host loopback proof now catches a bad foldable list at bind and a bad later list before any chunk send. It also checks nullable rows, first-seen repeated evidence, values, and SQL types. Splitting the C++ statement owner from the scalar entry kept each source under the 500-line policy cap as the listed path arrived. Remaining scalar, table, aggregate, full file-permission, signal, query-budget, and package proofs stay in this ticket; none is a completed product claim.

Annotate exposed an arity assumption in the C++ bind path: treating every kind numbered four or higher as listed made the two-argument annotate bind access argument two and trigger a DuckDB internal error before any send. The correction names the three listed kinds explicitly. A parameterized NULL-row host check binds the current scalar signatures, including annotate with and without its deadline, and confirms their result types without model requests. Recognize and relations now use a separate scalar registration and bind path with their exact signatures. A private typed byte codec carries complete entity and relation fields from the public engine into DuckDB lists of structs. The family-level stock-host check covers bad foldable and later-row arguments, NULLs, allowed and refused rules files, and actual nested outputs. It also caught no new arity alias after the explicit bind split. Usage, warm, relate, host interruption, full file permission, and package proofs still remain before the product extension can replace the shipped C API surface.

The usage table now reads four process counters from the existing Rust registry through a fixed-width private export. A stock-host child sees `requests_sent` advance after one real decision while the usage query itself sends nothing. The new export lives in a separate named FFI module and shares the panic-safe reply boundary. Warm, relate, host interruption, full file permission, and package proofs still remain.

The warm aggregate needed a state that survives DuckDB partial-group updates and combines. The focused host check uses a 2,049-row input with only one live final row, so it crosses the vector boundary without thousands of requests. Legal files from DuckDB third-party source and all resolved Rust registry crates now accompany the package.
