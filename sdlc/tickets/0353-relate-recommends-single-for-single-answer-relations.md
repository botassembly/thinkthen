# 0353: relate recommends `single` for single-answer relations

Status: landed. Lane claude-4. A fresh ticket review accepted it after one round of fixes; a fresh code review accepted it after two. Serves issue `../issues/closed/2026-09-30-relate-pair-planner-loses-precision-on-the-beatles-bench.md`, whose decision run passed its bar on 2026-09-30. Plan: `sdlc/planning/cleanup-2026-09-30.md`. The decision run settled this default; Ian can overturn it.

## Outcome

`"single": true` is relate's recommended form for a relation where each source has at most one target. The relate page says so in its rule paragraph. Its Precision section states the menu's measured figures beside the pair planner's, including the recall the menu gives up and the tie on solo sets at the tuned cut. The page keeps the way to ask per pair: a rule without `single` asks yes/no pairs as today, and the page recommends pairs for a many-answer relation or where recall matters more than precision. It still points to `recognize --relation` for relations a text states. A replayed fixture from the decision run proves the none-of-these figures with no key and no network. ADR 0057 records that the decision run settled the default. The precision issue closes.
