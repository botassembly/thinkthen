# 0339: An `ollama` built-in backend, and descriptions each backend accepts

Status: landed. Design: ADR 0115, which amends ADR 0114. Ian asked for it on 2026-09-30. Build after 0304 slice 4 lands, because the dialect reaches `cli/asking/judged.rs`, `engine/facade/recognize.rs` and `engine/prepared_request.rs`, which slice 4 edits.

## Outcome

`--backend ollama` reaches Ollama 0.35 at `http://localhost:11434/v1` with model `nimble` and no key. `thinkthen check --backend ollama` against a server that refuses object descriptions reports no critical finding and warns about the lost detail. Per Ian's ruling of 2026-09-30, `ollama` alone sends each description as text, a temporary workaround for an Ollama bug tracked as debt. `typesafe`, `liquid`, configured entries and the unnamed path send descriptions exactly as authored. With no backend named, every command's bytes stay today's.

## What the build taught us

- The premise held on main after 0304 slice 4 (`02750a206`): descriptions were written as authored in `request.rs`, `guard` compared every built-in host, and the loopback rule in `engine/facade.rs` already sent no `Authorization` header for a missing key. The ticket's three slice 4 files each build plans from the backend's model, and each now takes the backend's description form beside it.
- The plan carries the form beside the model, and `Plan::new` takes it as a required argument, so the compiler finds every place a plan is built. Tests use `Plan::authored`. `Backend::asked()` hands the model and the form together to the quoted planners, which were already at the six-argument limit.
- `Text` renders inside the encoder, at the JSON level, before each wire question is built. Under `Authored` the renderer returns each description unchanged, so the other backends' bytes are today's by construction. An edge table pins both forms for every description shape, and the check fixture and the 0334 tests pin the rest.
- The mixed probe sends `{"what":"It arrived when promised"}`, which loses no field. The ticket still expects a warning on `mixed`. So the warning fires when the text form turns any nonempty object or list into text, which is also exactly what Ollama refuses.
- `--plan` prints the sentence from four places: `check`, the asking commands, `annotate`, and `recognize`. `find` and `relate` carry no descriptions a user writes.
- Recordings live in the ADR 0111 store now, not in digest-named files. The cache proof compares the store's question keys: the object question under each form keeps different keys, and the string-only question keeps the same two keys.
- A question whose only object description holds `what` and nothing else becomes the same question as its string form under `ollama`. The first cache test used such a pair and saw the second run answered from the cache, which is correct.
- `policy.py` holds vendor words behind the adapter, and the debt issue's file name holds two of them. Only the adapter's backend table and encoder name the issue path; other comments point there.
- Adding `OLLAMA_API_KEY` to the 0334 marker set widened the count arrays. The builder test that counts captured keys now expects five.
- `core/backend.rs` passed the 500-line cap, so its tests moved to `core/backend/tests.rs` unchanged.
- Manual check, 2026-09-30, against the Ollama already running on this machine (version 0.15.5-rc1, no `nimble` pulled, not the 0.35 that serves System One). `thinkthen check --backend ollama` in a scratch home connected with no key and reported `critical endpoint: the backend answered with status 404: nothing answers at this address`, `critical 1, warning 0`, exit 4. It shows the default base and the keyless loopback path. It does not show Ollama accepting the text form or an object `state`; that waits for a user with Ollama 0.35.
- A fresh read-only review accepted the branch with two non-blocking findings: the ADR's warning trigger and the CHANGELOG's note on a configured entry already named `ollama`. Both are recorded.
