# 0228: Keep a missing key from binding a new cache folder

Status: complete after fresh independent High code review accepted `10ae3238`. Fresh Medium review accepted the technical design at `be0a2336`; Ian approved the narrow before-key exception in the work plan. Source base `76a3bc7c`. [The five-finding survey](../records/2026-09-28-cache-followup-preparation.md) separates it from model-version identity. Ian may overturn the accepted admission rule. The coordinator opened an independent build lane after 0212 landed.

## Outcome and exact limit

For a new or existing **empty, unmarked** cache/recording folder, a nonloopback request with no usable key returns the existing no-key failure before the tool creates the folder, marker, lock file or temporary entry. A second address may then use that folder. An existing bound folder still checks its identity before looking up a key or sending. A cache hit and strict replay still work without a key. A legacy unmarked folder with a digest-shaped entry still refuses write-capable use before key lookup; strict replay remains read-only. A permitted first writer still publishes the marker before sending, so concurrent different-address writers cannot both send. The entry and its digest remain unchanged.

This narrows the settled ticket 0065 and accepted ADR 0035 rule, which deliberately binds an empty folder **before** key lookup (`0065-bind-a-recording-folder-to-one-backend.md`, Design; `0035-recording-folders-bind-to-one-backend.md`, Decision; `specification/recording.md:47`). [Accepted ADR 0099](../planning/adr/0099-cache-binding-admission.md) records the exception; its timing exception is accepted. This build amends ADR 0035, settled ticket 0065 and the settled page. It changes no marker schema. Register 10's literal “every zero-send run leaves the default folder untouched” is wider: cancellation after writable preparation, an HTTP admission/budget refusal, and a failed transport can still leave a marker. This ticket does not claim those paths are side-effect-free. Nor can the current digest-only marker reveal the bound address. The current CLI sentence truthfully names the requested address and a cure (`cli/failure/recording.rs:112-124`); the public library's fixed sentence omits the address (`public/error.rs:221-223`). A generic sentence would remove information without meeting the register's two-address criterion, so no diagnostic change is proposed. Register 10 remains open after this bounded fix unless the remaining criterion receives a separate reviewed design.

## Accepted admission rule

Before `prepare_checked`, ask the recorder whether this request names a write-capable **unbound empty** folder. The probe is read-only: a missing path qualifies; an existing folder qualifies only after the default-cache privacy check, an absent marker, and a scan showing no digest-shaped final entry. A present marker, including a malformed one, or a legacy digest-shaped entry goes through the existing `gate` first, preserving its refusal precedence. A path or folder inspection error remains a local storage failure. The probe does not set `Recorder::checked` or create a directory. If it qualifies, check `cancel.stop()`, make exactly one key lookup through the existing closure, and hold the result locally. A valid key proceeds through the unchanged `prepare_checked`, which rechecks identity under the folder gate and publishes the marker before send. If another writer wins meanwhile, the loser receives the existing mismatch refusal and sends nothing. If the winning writer installed the matching answer, the loser may replay it; an early key lookup in this race is allowed, but no duplicate send is.

If the early key fails, recheck the folder read-only before returning that error. If another cooperating writer has published its marker in the meantime, run the original gate and entry lookup to allow a matching in-progress writer to finish and provide a keyless hit. A mismatch or newly present legacy entry keeps its existing refusal. If preparation then needs a live send, cancel its permit and ordinarily return the saved key error; cancellation or permit-cleanup failure can take precedence as today. When both probes observe an unbound empty folder, return the key error without creating a folder or marker. The probes are observations, not an atomic snapshot: a writer may publish only after the second probe, so this caller may return `NoKey` even though a later call finds an answer. No keyless hit that was visible to either probe is silently converted to a missing-key refusal.

All other paths keep current ordering: strict replay and an existing cache hit do not read a key; a bound wrong-address folder and an unmarked legacy folder refuse before key lookup; a cache miss in a bound folder still prepares and then reads the key. Count one key inspection whether it occurs in the early qualified path or the existing live arm. Keep the HTTP attempt, cancellation/deadline checks, send reservation, usage count and per-digest lock behavior where they are. The read-only probe is an optimization of **admission ordering**, not a second authority: `gate` remains the sole binding decision. External deletion/replacement of a marker between probe and gate is outside cooperating-writer guarantees; the gate still validates before send. No total “zero sends implies no filesystem side effects” promise follows from this rule.

## What the preparation taught us

The earlier survey correctly found the marker publication boundary, but “zero sends” was too broad to design from directly. The concrete absent-key path permits an early read-only admission check without replacing the folder gate. Accepted ADR 0035 and ticket 0065's explicit before-key rule must be amended rather than described as an accidental implementation detail. The existing two-address test protects concurrency, while a new missing-key edge pins the first local refusal and folder names, then the second address's accepted request. Its listener cannot observe the first address.

## What the build taught us

The read-only probe must distinguish a missing path from a dangling symlink. `metadata` alone follows the link and reports `NotFound`, which would turn a storage failure into a missing-key refusal. A compiled-boundary symlink case now pins the local storage failure. The existing legacy and malformed-marker cases run without a key, proving their refusal still wins over key lookup. The absence/present-empty table pins folder names and a later accepted request at a second address. The key closure is consumed at most once; the original folder gate still decides binding after an early successful key or a competing writer. The merge also left four public JSON test calls on the old result shape and one unused import. The build repairs those consumers without changing their comparisons. Register 10 remains open for admitted-but-unsent paths, binding status and unbind guidance.
