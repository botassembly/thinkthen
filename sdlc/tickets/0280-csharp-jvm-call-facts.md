# 0280: Return owned facts from C# and JVM typed calls

Status: complete. Fresh High code review accepted `3b74fa121` after the required cache-answer and elapsed-facts proof correction. The implementation and focused source/copied-consumer evidence are recorded below. The broader every-call issue remains open for its other criteria.

## Outcome and public shape

Migrate the existing four **direct typed** calls in place: C# `Engine.Decide`, `DecideMany`/`DecideManyWithOptions`, `Recognize`, `Relate`; JVM `Door.decide` (both overloads), `decideMany`, `recognize`, `relate`. Each makes exactly one existing C `*_with_facts_opts` invocation and returns its old successful value plus separately owned, final facts. No bare typed compatibility alias, mutable last-success slot, second native/provider call, new C symbol or C ABI edit. Preserve arguments, old value types, ordering and bytes, zero-count bulk, nullable/unsure outcomes, six failure kinds and started-failure carriers. C# `Call`/`CallTyped` and JVM `call`/`ResultEnvelope.value` keep their current JSON string/envelope behavior; the seven JSON-only verbs need no new typed route.

| Host | Proposed return | Facts |
| --- | --- | --- |
| C# | `TypedResult<Answer>`, `TypedResult<Answer[]>`, or `TypedResult<string>` with immutable `Value` and `Facts` properties; retain the unrelated JSON `CallResult(JsonElement Value, JsonElement Facts)` | Immutable `Facts` with required `ulong Records`, `RequestsSent`, `CacheAnswers`, `double Seconds`; optional `ulong? InputTokens`, `OutputTokens`, `string? Model`. |
| Java door | `Door.TypedResult<Door.Answer>`, `Door.TypedResult<Door.Answer[]>`, or `Door.TypedResult<String>` records with `value()` and `facts()` | `Door.Facts` record with required nonnegative `long` counts, finite nonnegative `double seconds`, optional boxed `Long` tokens and nullable `String model`; refuse a C count outside Java's signed range rather than truncate it. |
| Kotlin/Scala facades | Forward the door's typed result for synchronous and async `decide`; preserve their `call` string routes and join-before-close behavior | Read through the same immutable Java facts record. |

The C facts JSON requires `records`, `requests_sent`, `cache_answers`, `seconds` and may omit `input_tokens`, `output_tokens`, `model`. A missing, null, negative, fractional or wrong-type required member is a wrapper decode defect, never zero/default success; absent optional tokens/model stay absent. Validate finite nonnegative seconds. A successful C return with malformed facts publishes no success. Native failure facts remain the existing copied nullable C# `Failure.FactsJson` and JVM `Door.Failure.factsJson`; pre-start refusal has none. A started backend/deadline/cancellation failure copies the borrowed slot immediately on the same native calling thread, before any later native call could replace it. No invented cost, server timing, request ID, digest or row detail.

## What preparation taught us

C# has a separate `CallResult` for JSON `CallTyped`, so the typed carrier needs a different name. Java's `ResultEnvelope` already parses and validates facts members for JSON calls; using its reader for typed facts avoids a second decoder. Kotlin and Scala return `Door.Answer` directly and also expose asynchronous decide handles, so changing only `Door.java` would leave copied public signatures stale. Existing source matrices already count wire bodies but their concurrent calls are not proven overlapping; the held marker can supply the missing ordering witness without a new backend framework. The old C source and installed proof establish exports, while wrapper archives must still be built with matching native bytes.
