# 0334: Named backends on the command, the configuration, and the Rust builder

Status: landed 2026-09-30. A fresh read-only code review accepted it after one round of fixes. ADR 0114's open questions are settled as coordinator defaults Ian can overturn. Design: ADR 0114, accepted.

## Outcome

`--backend NAME`, `THINKTHEN_BACKEND`, the configuration file's `backend`, and `EngineBuilder::backend` select a named backend. The built-ins are `typesafe` and `liquid`. The configuration file may name more backends by URL, key variable name, and model. Each named backend sends only its own key. With no backend named, every command and the Rust builder behave as today, except for the `status`, `check`, and help changes listed under Keeps.

## What the build taught us

- Every configuration refusal exits 5. The ADR and this ticket first said 2 for the new ones; both now say 5.
- The builder reports a missing key at the first live call, as it did before. The build itself still succeeds.
- The first review found that a trailing dot or a percent-encoded host passed the section 5 check. Hosts are now compared as DNS reads them.
- The first review also found that a shared configuration file could point any secret variable at any host. Such a file may no longer hold `backends`.
- The test listener's `requests()` drains. A test that reads it twice must assert the difference.
- The surface checks need a running loopback backend on a real port. Port 0 gives connection-refused reds that look like regressions.
- Dev builds need their own target folder while surface checks run on the shared one, or each rebuild invalidates the other.
- `status --json` version 2 adds fields only. The spend-guard paths under `.usage.total` stay where version 1 had them.
