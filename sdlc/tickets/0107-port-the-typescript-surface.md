# 0107: Port the TypeScript surface

Status: design accepted 2026-09-24, owner Claude.

## Design and decisions

Port the Node binding from tag `surfaces-wave7-frozen-2026-09-24b` (`9df8bae9`) onto the public Rust API as the unpublished crate `thinkthen-typescript` at `libraries/typescript`, in its own Cargo workspace. `import * as tt from "thinkthen"` and `require("thinkthen")` keep the ten verbs, `decide_many`, `details`, `question`, `usage`, and `ThinkThenError` with `kind` and `retryable`. Every call reaches the real engine through `thinkthen`. Queue item 3 of `sdlc/planning/one-line-plan-2026-09-24.md` puts TypeScript after Python.

Draft ADR 0047 fixes the crate's place and its checklist. Ticket 0093 sets the workspace, lint, ratchet, and surface-rung pattern. Ticket 0105 is the accepted template for a host binding, and this ticket copies its gate and review shape. Tickets 0095 and 0098 fix the members this binding calls. Section 3.2 of `sdlc/planning/surfaces-port-guide.md` gives the port map, and the guide's shared rules bind this ticket. They landed on main at `bced9c4d`, and `446a4d6b` rewrote the width rule. The design review (`sdlc/records/2026-09-24-design-review-0107.md`) found nine items. This version answers all nine and takes the coordinator's change of 2026-09-24: ADR 0017 section 5's engine settings become public (decision 3). Ian can overturn every decision below.

1. **Over the Rust API, beside the C door.** The addon is a napi-rs crate that depends on `crates/thinkthen` by path. It does not load `thinkthen-c` (0094). ADR 0047 item 1 forbids a binding that depends on another binding, and item 7 forbids a shared helper crate. The C door builds only `cdylib` and `staticlib`, so no Rust crate can link it. Node has no built-in foreign-function loader. A loader package would be a runtime dependency, and `sdlc/planning/libraries/javascript.md` rules those out. 0094 still serves as the reference for the FFI edge: one panic guard, one error-kind table, and one module that allows `unsafe`. 0094's `deadline_millis` choice for a host that counts milliseconds carries over too.
2. **One door, JSON inside.** The native module exports `call(engine, op, spec, payload, deadlineMs, done)`. It returns a `CallHandle` with one method, `detach()`. The payload crosses as one string. The result comes back through `done` as one envelope string, `{"ok": value}` or `{"err": {kind, retryable, message}}`. `index.js` parses it once. `details`, `annotate`, `recognize`, and `relate` values come from 0095's `Details::to_json`, `AnnotatedRecord::value_json`, `Recognized::to_json`, and `Edge::to_json`. The remaining values (a decide word, a choice, a position, labels, kept indexes, `{index, probability}` pairs, a found index or null, and the four counters) are built with `serde_json` inside the envelope. The envelope is private to this package. Its bytes need not match the command.
3. **Engine and its settings.** ADR 0017 section 5 gives every library surface the engine settings on its engine value, and the shared width rule (main at `446a4d6b`) holds each surface to it. The package exports `tt.Engine`. `new tt.Engine({ baseUrl, model, width, maxRequests, cache, cacheBytes })` takes one options object, spelled in camelCase like `deadlineMs` and `relationThreshold`. The constructor starts from `EngineBuilder::from_env()`, added by the 0084 amendment at `f19cf437`. It reads the environment as `Engine::from_env` does, and each given key then overrides through one 0084 `EngineBuilder` member: `base_url`, `model`, `width`, `max_requests`, `cache_at`, and `cache_bytes`. `cache: false` maps to `no_cache`, and a string to `cache_at`. A missing `cache` calls no setter, so a folder the environment set stays in force (amendment change 3). A missing key keeps what the environment set, or the builder's default. The key stays in `THINKTHEN_API_KEY` only, as the section's table and the repo's credential rule say, so the options take no key. Any other key, a wrong type, or a value the builder refuses throws `ThinkThenError` of kind `usage` from the constructor. A second explicit width that differs throws 0077's pinned sentence. Construction sends nothing. An engine value carries the ten verbs, `decide_many`, `details`, and `usage` as methods. The module-level functions keep calling `thinkthen::default_engine()`. Width follows 0077 for both: an engine built with `width` activates the process width, and the default engine follows it. A `worker_threads` worker that loads the addon shares the one process width. The native module holds one `NativeEngine` class that wraps a `thinkthen::Engine`. `call` takes it, or `null` for the default engine, and the worker clones it. No hidden hook exists.
4. **A detachable worker per call.** The shared rules require one. `call` spawns a named `std::thread` with Rust's default stack of 2 MiB (amendment change 2). The thread owns the question, the texts as `String` values, and a clone of a per-call `CancelToken`. It builds one `CallOptions` with that token as `cancel`, calls the matching `Engine` `_with` form, and hands the envelope to `done` through a napi `ThreadsafeFunction`. The threadsafe function stays referenced while the call runs, so a pending call keeps Node alive as any pending I/O does. The binding passes no `CallOptions::interrupt` check, because the token already reaches every engine poll. The libuv pool no longer carries any call. The tag's `AsyncTask` and `Task::compute` leave. A thread that cannot start rejects with `local` naming the OS error, and nothing is sent. Cost: one OS thread per call in flight. Ten thousand concurrent single calls start ten thousand threads, and most wait at the width gate. `decide_many` is the lever for volume, and `javascript.md` says so.
5. **Prompt abort.** An abort settles the promise at once on every verb, and Node can exit right after. The engine's token alone cannot settle a call during one blocking send, because a sent attempt finishes under 0073. Design: `invoke` races the worker against the signal. On abort it calls `handle.detach()`, removes its listener, and rejects with `ThinkThenError` of kind `cancelled`, `retryable` false, the pinned sentence "the call was cancelled by its AbortSignal", and `cause` set to `signal.reason`. `detach()` fires the per-call token and aborts the threadsafe function. The aborted function releases its hold on the event loop. The worker finishes its sent request. Its late envelope meets a closed threadsafe function and is dropped in Rust. A signal already aborted rejects before any crossing. If Node exits first, the process ends the thread, and the backend sees a closed connection. A `worker_threads` worker that ends closes its calls' threadsafe functions the same way. Cost: about 15 lines of `index.js` and 20 of Rust. Until its send ends, a detached worker holds one width permit. The engine's 30-second request timeout bounds it. No change to `thinkthen` is needed.
6. **Deadlines.** `deadlineMs` follows ADR 0041. `null`, a missing key, and `-1` mean no deadline. `0` is spent. `index.js` keeps the host rule: a bool, a string, an array, or any non-number is `usage` before the crossing. The addon takes an `f64` and refuses, before any cast, a NaN, an infinity, a fraction, a value below `-1`, and a value above 4,294,967,295,000. The refusal is `usage` with one sentence: "deadlineMs VALUE is not a deadline; use -1, null, or a whole number of milliseconds from 0 to 4294967295000". VALUE is the number as JavaScript's `String()` prints it: `NaN`, `Infinity`, `-2`, `0.5`, `1e+300`, or `1.7976931348623157e+308`. The addon writes a value of 1e21 or more in exponent form with a plus sign, and a magnitude below 1e-6 in exponent form, as `String()` does. The R1-11 test pins `1e-7` as well. Every value it accepts is whole and in range, so the cast to `i64` is exact, and `CallOptions::deadline_millis` gets it. New here: a fractional budget is refused. `Math.max(0, end - Date.now())` is always whole, and a `performance.now()` budget needs `Math.ceil`. The tag's own negative check in the addon leaves.
7. **Inputs.** A record list is an array of strings. A non-string item raises `usage` naming its index (G11). A string that fails `isWellFormed()` raises `usage` naming its index, because Node-API would replace a lone surrogate silently. The same checks apply to a single evidence text.
8. **Questions.** `tt.question(...)` and the verbs spell the question-file JSON and call `Question::from_json`, so parts and a file give one digest. A band `[low, high]` becomes the file's `"low:high"`. `annotate` takes a set path (`QuestionSet::load`), set JSON text, or a set object (`from_json`). A broken rule from arguments raises `usage`, and from a file raises `local` (0095, Q16). Scalar `choose` and `tag` call `details_with` and read `value()`, with no added send (G5). The last-object rule of 2026-09-21 stays: `options`, `labels`, `levels`, and `top` ride beside `signal` and `deadlineMs`, and any other key is `usage` naming it.
9. **Results.** `decide` resolves `true`, `false`, or `null`. `decide_many` resolves a list of those. `score` resolves the position, and the nearest level moves to `details`. `tag` resolves a list of labels. `filter` resolves the passing texts. `rank` wraps each text in one binding `Evidence` type holding its index and resolves `{index, record, probability}` objects, cut by `top`. `find` resolves `{index, unit, probability}`, or `null` when nothing is selected (0095, Q16). This aligns `find` with Python. `annotate` resolves one object per record from `value_json`, with `null` for unsure and the failed marker `{failed: {kind, cause}}`. `details` resolves `JSON.parse` of `Details::to_json`, equal to the command's `--details` document and to Python's `tt.details`. `usage` resolves `{requests_sent, cache_answers, input_tokens, output_tokens}`. A bulk call that meets an error rejects whole, and partial rows are dropped, as at the tag.
10. **Recognize and relate.** `recognize` spells the `recognize @FILE` object of `specification/question-file.md` from `kinds`, `relations`, `threshold`, and `relationThreshold`, and calls `Recognize::from_json`. `relate` spells the version-one relate file from `relations`, `either`, and `threshold` and calls `Relate::from_json`. `relate` takes `{name, kind}` objects or `[name, kind]` pairs as `Entity` values. The engine refuses more than 255 entities or an exact duplicate before any send. The wrapper converts every `start` and `end` from Unicode scalar values to UTF-16 code units (0095, Q13), in entities and in relation endpoints. `text.slice(start, end)` then gives the name.
11. **Errors and panics.** The envelope's `kind` comes from `ErrorKind::name`, the one kind table. One panic guard wraps the worker's body and turns a binding panic into `defect`. `thinkthen` already stops engine panics at its public methods (0086).
12. **Files and build.** The crate moves from `addon/` to `libraries/typescript/Cargo.toml` with `src/` and `build.rs`, where 0093's checks scan. The tag's `[profile.release] lto = true` leaves. ADR 0047's profile check requires the root `[profile.release]` copy exactly. `build-addon.sh` runs `cargo build --release --locked --offline` with the `$HOME` remap and copies the library to `thinkthen.node`. `@napi-rs/cli` leaves the dev dependencies. The 308-line generated `loader.cjs` and `loader.d.ts` give way to a hand-written `loader.js` of at most 20 lines. `index.mjs` is written by hand, and the tag's name generator retires. A test compares the names exported by `index.js`, `index.mjs`, and `index.d.ts`. Platform-named binaries and packages belong to the release ticket (queue item 4).
13. **Node version.** `engines` becomes `>=22`. The check runs only Node 22.22.3 from the toolchain folder. The tag claimed 18 untested.

## The shared rules

`sdlc/planning/surfaces-port-guide.md` on main (`6eb1303e`) sets six rules for every surface ticket. Main's `d783ab6b` adds a seventh, applied by amendment change 1. This ticket follows each one.

1. **No Docker.** The check needs Node, npm, cargo, and cargo-deny. None runs in a container.
2. **Toolchains under `~/.cache/thinkthen-toolchains/`.** `libraries/typescript/setup-toolchain.sh` fetches `node-v22.22.3-linux-x64.tar.xz` once from nodejs.org into `~/.cache/thinkthen-toolchains/node-v22.22.3-linux-x64/`. It checks the archive against the sha256 pinned in `libraries/typescript/node.sha256` and refuses on a mismatch. The builder copies that sum from nodejs.org's `SHASUMS256.txt` on a networked machine, and the record names it. `check.sh` puts that folder's `bin` first on `PATH` and never uses another Node. A missing folder reports "not run" and names the setup command. The fetch is setup. The gate stays offline.
3. **Own cache and own backend per test.** `tests/backend.mjs` gives each test a fresh `mkdtemp` folder as `THINKTHEN_CACHE` and starts its own backend. The fixed-delay arm, a held reply that can hold again, and one backend per test come from ticket 0117.
4. **Prompt Ctrl-C through a detachable worker.** Decisions 4 and 5. An `AbortSignal` is Node's cancel gesture. Singles and batches both reject with `cancelled` at once, and the worker finishes the sent requests.
5. **A deny plant that reaches deny offline.** The gate section uses the reviewer's `file://` git plant, with its pinned diagnostic.
6. **Width through the public setting.** The rule as rewritten at `446a4d6b`. The two tests that need parallel requests, R3-25 and the batch abort, each run in their own child process. Each child builds `new tt.Engine({ width: 4 })`, calls through it, and pins 4 as a literal. No test relies on the fallback, and no hidden hook exists.
7. **No paid backend.** Amendment change 1.

## Other acceptance

- Prompt abort, single, and a prompt exit. A child script sends one `decide` on the held arm. The parent reads the count, and once it reads 1 it tells the child to abort. The promise rejects with `cancelled` and the pinned sentence within 100 ms of the abort. The child's script then ends, and the child exits within 500 ms of the abort while the reply is still held. The parent releases after the child exits, or at a 2 s timer. After a 500 ms settle the count reads exactly 1. Plant one: drop the race. The rejection waits for the release, and the 100 ms assertion turns red. Plant two: leave the threadsafe function referenced in `detach()`. The child exits only after the release, and the exit assertion turns red.
- Prompt abort, batch. A child builds `new tt.Engine({ width: 4 })`, and a 200-text `engine.decide_many` waits on the held arm. The child aborts once the count reads 4. The promise rejects within 100 ms. The test then releases, and after a 500 ms settle the count reads exactly 4. Plant: race without firing the token. After the release the batch keeps sending, and the count passes 4.
- A deadline during a held send. One `decide` on the held arm with `deadlineMs: 300` rejects with `deadline` by 450 ms with one counted send. 0086's acceptance line "Public calls preserve 0085's controls" proves the engine ends a call at its deadline during a blocking send, and 0076 on main enforces whole-call deadlines. If the engine returns only after the send ends, this test fails, and the builder stops for a decision.
- Case 18 of the branch (cancel mid-batch) is the batch abort test above. It uses 0092's held arm.
- A detached worker does not leak into the next call. After the single abort test releases, a new `decide` on the same backend resolves.
- Case `41-offsets-past-an-accent-and-an-emoji` returns `start` and `end` in UTF-16 units, and `text.slice(start, end)` equals each name. Plant: skip the conversion. The emoji case turns red.
- Case `40-decide-counters` asserts differences in `usage()` around a call.
- A lone surrogate at index 2 of a record list rejects with `usage` naming index 2 and zero counted. Plant: drop the `isWellFormed` check. The call sends, and the count turns red.
- A child process started after the parent's first call answers its own call. A `worker_threads` worker that loads the addon answers, and the parent's `usage()` shows its send.
- The name test: `index.js`, `index.mjs`, and `index.d.ts` export the same sixteen names, `Engine` among them. `index.d.ts` types each engine option and method.
- Engine settings, each in its own child process. The environment seed is proved through the cache folder (amendment change 1). `THINKTHEN_CACHE` names folder A, and `HOME` and `XDG_CACHE_HOME` name a scratch folder. `new tt.Engine({ width: 4, baseUrl: <the child's loopback> })` decides the same text twice. The backend counts 1, and folder A holds the answer file. Plant: start from `Engine::builder()` in place of `EngineBuilder::from_env()`. The engine ignores `THINKTHEN_CACHE`, folder A stays empty, and the test turns red. The plant writes only into the scratch folder, and its sends are counted on the same loopback listener. `baseUrl` naming a second backend sends there, and the first backend counts none. `maxRequests: 2` refuses a three-record `decide_many` with `usage` and zero counted. `cache` naming a folder writes one answer file there, and a repeat call counts no new send. `cache: false` writes nothing. `cacheBytes: 0`, `width: 33`, an unknown key, and `width: "4"` throw `usage` from the constructor with zero counted. A second `new tt.Engine({ width: 8 })` after width 4 throws `thinkthen: width 4 is already active for this process; use width 4 or drop the width argument`. After `new tt.Engine({ width: 4 })`, a module-level call follows width 4. Plant: drop the `maxRequests` mapping. The three-record call sends, and the count turns red.
- The addon holds no hand-written `unsafe`. `#[napi]` items live in one module, `src/node.rs`. Only that module carries `#[allow(unsafe_code, reason = "…")]`, for the macro's output, and the reason text avoids the word. A `check.sh` step runs `grep -rnP '\bunsafe\b' src` and fails on any line it prints. The pattern does not match `unsafe_code`, because `_` is a word character. Plant: add an empty `unsafe {}` block. The step fails.
