# 0281: Owned call facts for Swift and Zig typed methods

Status: Corrected after fresh High design/API review findings; awaiting recheck and root's exact code claim. No implementation is approved by this ticket alone.

## Outcome and retained behavior

Migrate `decide`, `decideMany`, `recognize`, and `relate` in each pre-0.1 wrapper in place. Every successful typed call returns its old value and its own final facts from **one** existing C `*_with_facts_opts` operation. There is no setting, second operation, bare-success alias, mutable last-success accessor, or new C symbol. This applies the [every-library-call ruling](../issues/2026-09-26-every-surface-should-give-back-run-facts.md) and accepted [ADR 0106](../planning/adr/0106-typed-wrapper-call-facts.md); ADR 0101's bare-symbol exception is for old C ABI callers only. Preserve old answer values and bulk order, recognize/relate JSON value bytes, six failure kinds, options/cancellation, pre-start versus started-failure facts, JSON `call`, C ABI, and current engine/thread and ownership promises. Swift's recognize/relate methods have no options arguments: pass `THINKTHEN_NO_DEADLINE` and nil cancel to their facts `_opts` calls without changing their signatures. Zig retains its current `Options` on all four methods. JSON `call` already returns a `value`/`facts` envelope for all ten verbs; the seven JSON-only verbs get no new typed methods here.

| Method | Swift success | Zig success |
| --- | --- | --- |
| `decide` | `CallResult<Answer>` | `Result(CallResult(Answer))` |
| `decideMany` | `CallResult<[Answer]>` | `Result(CallResult([]Answer))` |
| `recognize`, `relate` | `CallResult<String>`; `.value` is existing result JSON string | `Result(CallResult([]u8))`; `.value` is owned existing result JSON bytes |

Swift `public CallResult<Value: Sendable>: Sendable` has `value` and typed `facts`. Zig keeps its existing `Result(T)` union and `.failed` branch; only `.ok` becomes an owned `CallResult(T)` with `value` and typed `facts`. This is a deliberate pre-0.1 source migration: Swift callers use `result.value.outcome`, `result.value[i]`, or decode `result.value`; Zig callers switch on `.ok`, read `success.value`/`success.facts`, and release the success. Update every direct source/example/installed consumer in the same change. Do not describe the wrappers as covered by C's old-symbol exception.

`CallFacts` in each host represents required `records`, `requests_sent`, `cache_answers` as unsigned counts and `seconds` as finite nonnegative number; optional `input_tokens`, `output_tokens`, `model` are absent when C omits them. Swift uses `UInt64`, `Double`, and optional `UInt64`/`String`; Zig uses `u64`, `f64`, and optional `u64`/owned `[]u8`. Reject missing, JSON null, boolean, negative, string, or fractional values for required counts; reject missing/null/boolean/non-number/nonfinite `seconds`; reject a present null or wrong type for an optional key. Do not decode malformed required facts to zero or invent usage. The C facts object does not supply cost, server time, IDs, digests, or full per-row detail.
