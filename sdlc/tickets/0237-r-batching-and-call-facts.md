# 0237: Batch R calls and return their call facts

Status: the same independent High reviewer accepted corrected design `e24f2c29`, and the coordinator approved implementation within B12f/J6. The implementation has a source-installed, focused offline candidate proof from merged main `930dbbf7`; it awaits fresh independent High code review and landing. Owner: Codex. The [preflight](../records/0237-r-batching-preflight.md) names the native path and consumers, the [design review](../records/0237-design-review.md) records acceptance, and the [build record](../records/0237-r-batching-build.md) names the actual proof and its limits.

## Outcome and retained behavior

Complete B12f and the R half of J6 under the approved batching, run-facts and type contracts. Every asking `tt_` verb returns its former R value together with final call-scoped `facts` and ordered, owned question details without a second model call. Expose an engine `batch` setting, per-call batch on eligible record calls and shared text `context` only where Rust accepts it. Preserve default Max packing already inherited from Rust 0212, the current six named R error conditions and retry flags, actual R Ctrl-C behavior, one-based inclusive recognition offsets, `NA` for a not-sure R value and a distinct failed annotate member. A success does not infer per-call counts from `tt_usage()` deltas. A pre-accounting refusal does not invent zero facts; an accounted terminal error keeps final facts, including a genuine zero-send account.

## Proposed R contract for review

1. Give each successful asking verb a `thinkthen_call` list with `$value`, `$facts` and `$details`. `$value` retains the previous logical/scalar/vector/list/frame shape. `$facts` has `records`, `requests_sent`, `cache_answers`, optional `input_tokens` and `output_tokens`, `seconds`, and optional `model`; an absent provider field remains absent, never zero. `$details` is an input-ordered owned list of Rust `RecordObservation::Question` data: zero-based **original R input** index, optional member or stage and position, question digest, typed answer or failed cause, probabilities, optional confidence, model, URL, request digests, attempt/usage shares and cached flag. Retain `tt_details(... )$value` as the current `thinkthen.result/1` list. `tt_usage()` is a process counter read and `tt_question()` a local constructor, not asking calls. No `print` method should emit raw input or detail by accident. R's numeric counters have the existing exact-integer range limit below 2^53.
2. `tt_engine(batch =)` accepts `"max"` or a positive whole number, over `EngineBuilder::from_env`; absent uses `THINKTHEN_BATCH`, question-file batch, then Max. Each eligible per-call `batch =` overrides the engine value. `context =` is one nonblank UTF-8 string, never an implicit file read; it changes request identity and `meta.context_sha256`, not the question digest. Refuse invalid values as `thinkthen_usage` before any worker or send. Accept both controls on record-column `tt_decide`, `tt_choose`, `tt_score`, `tt_tag`, `tt_filter` and `tt_rank`; accept only batch on `tt_annotate`. A one-element column is still a record-column call. Reject these controls explicitly on `tt_find`, `tt_recognize`, `tt_relate` and scalar `tt_details`, where Rust does not support them. `tt_question` and `tt_usage` retain their own grammar. Every added keyword must reach native options or an explicit refusal; no silent R argument swallowing.
3. `tt_choose`, `tt_score` and `tt_tag` use dynamic runtime labels, so their many-record path must use landed `Engine::details_many_with` on the loaded `Question`, not a compile-time `Choice`. This path also handles saved profiled questions that the current one-question `QuestionSet` cannot carry. Preserve ordered choice `NA`, numeric score and label-list outputs. A profile can legitimately prevent one-request packing, but the host must not silently discard its batch or context controls. Keep `tt_annotate` on `annotate_with` and its per-member failed markers. `tt_find` remains one bounded selection and `recognize`/`relate` remain their current unbatched plans.
4. Accept the complete native question-file JSON value grammar at the R constructor: question text may be a string, object or array; descriptions for decision sides and labels may be a string, object, array or explicit JSON null. Add public `true =` and `false =` descriptions to `tt_question(decide = ...)` only. Use `missing(true)` and `missing(false)` at that public entry: omitted means no key, explicitly supplied `NULL` means a present JSON-null key. An explicit side on another question kind or beside `file =` is usage, including explicit `NULL`. A structured `{what, not_for, examples}` object is one instance, not the whole grammar. Label sets accept an ordered unnamed character vector or ordered named list; a named character vector is a convenient all-text map. Validate duplicate/blank names, missing `NA`, unsupported R types, encodings, and array/map intent before coercion or `jsonlite` can erase them. Preserve single-element arrays with explicit array wrappers, use list-preserving indexed assignment for present-null object members, and pass `null = "null"` as well as `na = "null"` to `jsonlite::toJSON`; the latter alone currently writes a nested `NULL` as `{}`. Test nested array, object and null values through `.tt_json` and the production parser. Do not call `as.character(...)[[1L]]`, `strip`-like normalization, file I/O or `file.info` on unchecked input and allow a bare base-R condition. A bad native encoding remains a named usage condition. Built question files retain production parser authority and exact bytes.
5. R's `NA` input column cells still skip sends and yield not-sure values where currently allowed; `NULL` is a legitimate JSON description and an absent argument remains distinct. `tt_filter`/`tt_rank` still refuse missing records. Preserve original caller record identity for filter, rank and find results, and the input data frame in annotate; use validated UTF-8 text copies only for Rust evidence. Carry the `which(!is.na(...))` map into native results: an observation's zero-based index names its original R column position, never its compacted live-vector position. This includes `tt_decide`, choose/score/tag, and per-text `tt_recognize`; skipped `NA` cells have no invented question event. Filter facts and observations include dropped rows; rank `top` trims only `$value`. Distinguish `NA` choose from an annotate failure marker. Keep one-based R places and offsets in `$value`, and zero-based original indexes in `$details` as named metadata.
   An empty or all-`NA` permitted column currently returns in R without crossing the native call. After valid local setup it must return a successful host-accounted zero-record, zero-send result with measured elapsed time, absent model/tokens and no question details, while preserving its prior `NA`/empty `$value`. This factual host no-work state is distinct from an unaccounted pre-validation refusal; do not fabricate a Rust `Call::facts` that never existed.
6. Rust's `CallOptions::observe` runs on its caller thread. In R, that caller is the native worker, not R's main thread. Copy each borrowed observation into Rust-owned plain data on the worker; convert to `Robj` only after the main-thread wait succeeds. Collect lazy `Batch` to its terminal `None` or error and read final `Batch::facts()`; retain `Call::facts()` before `into_value()`. For failures, carry optional `Error::facts()` and completed observations across the native boundary and attach them to the existing named R condition, without converting a failed call into `NA`. Account starts at Rust `Stop::begin` for an actual core call, not worker spawn; preserve pre-accounting absence and post-accounting zero-send presence.
   `tt_recognize` currently invokes `recognize_with` once for each live text inside one R call. Build one R-call account across every completed subcall and the terminal failing subcall when it has facts. Add `records`, `requests_sent` and `cache_answers` with checked integer arithmetic; any overflow is a named defect, not wrapping or a rounded R double. Sum token fields only when **every** accounted subcall reports them; if one is absent, the R-call field is absent. Report one `model` only when all reported models are present and equal; otherwise leave it absent while each observation retains its model. Measure outer elapsed wall time once from the first accounted work through the final join/error, including gaps between subcalls; do not sum per-call `seconds`. A later pre-accounting error retains the accounted prefix and completed observations; a later accounted error adds its final facts. No subcall after the terminal error starts. A valid all-`NA` call uses the host no-work state above. Apply the same aggregation rule to any other R verb that must invoke several core calls, including retained scalar fallback if it remains.
7. Keep the current prompt R interrupt. `R_CheckUserInterrupt` remains inside `R_ToplevelExec` on the main thread; `.tt_call`'s guarded checks and `.tt_interrupt` continue raising R's own `interrupt`. Because that real condition is generated after the binding returns, an exception-attached Ruby-style receipt cannot reliably carry later worker facts. Offer an optional caller-owned R completion handle for a caller that needs final post-interrupt facts: `tt_completion()` creates an opaque handle, an asking verb accepts `completion =`, and `tt_completion_read(handle)` returns a state/value list. Freeze four states: `unused` at construction; atomically `claimed` on the R main thread **before** question validation and `.tt_call`'s first interrupt check; `running` only after worker spawn; `terminal` after the original worker has exhausted/joined core work and published exactly one Rust-owned snapshot. `tt_completion_read` returns `list(state = "unused")`, `list(state = "claimed")` or `list(state = "running")` before completion, then a fresh copy of the same terminal kind/facts/details each time. A second call with an already claimed or terminal handle is `thinkthen_usage` before any work; an invalid handle is refused without changing another handle. Local validation/first-check exit settles a claimed handle with the actual usage/local/interrupt kind and absent facts. Worker-spawn failure settles it as a defect with absent facts. Accounted terminal error keeps its real final facts; a caught panic with lost accounting marks facts unavailable, not zero. Only the R main thread converts the snapshot to R values. The worker owns only Rust `Arc` state and must never touch an R object or run an R finalizer. Dropping the caller's handle during a held send releases its reference, never the running worker; the worker still cancels on caller interrupt, finishes sent work and drops its Arc. Without a supplied handle, interruption retains exactly today's prompt R condition and no guessed final count; `tt_usage()` remains only the process total. A selected held-send proof must check no further admission, later final account, repeat reads, reuse refusal, collection during hold and an ordinary R `tryCatch(interrupt=...)` handler. Keep deadline errors separate from host interrupts.
