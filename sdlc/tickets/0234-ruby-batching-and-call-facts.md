# 0234: Batch Ruby calls and return their call facts

Status: Design ready for independent review. Batch G B12e is an approved outcome; this ticket does not claim implementation. Source checked at main `79244123`. Owner: Codex. The [preflight](../records/0234-ruby-batching-preflight.md) maps the actual host paths, inherited behavior and eight installed conformance failures.

## Outcome and retained behavior

Give every asking `ThinkThen::Engine` method and matching `ThinkThen` module delegate a result with its former value, final call-scoped facts and owned ordered question detail, without a second model call. Add an engine `batch:` setting, per-call `batch:` on eligible many-record calls and `context:` only where the landed Rust planner accepts shared text. Default packing already reaches Ruby's current bulk calls through 0212; preserve it. `batch: 1` without context retains exact prior one-record request bodies and digests. Ian's batching and run-facts rulings, ADR 0089 and the landed 0230 dynamic-details bridge govern the outcome. The accepted Python early-stop principle informs Ruby's truthful completion receipt, but Ruby's GVL, exceptions and owned worker inputs determine its implementation.

Keep original Ruby values inside the result, original record identity and order, `nil` for an unsure judgment or unselected find, and a distinct `{"failed":{"kind","cause"}}` annotate member. Keep six named error classes, retryability, cancellation and interrupt precedence, prompt caller return, and the worker's cleanup after already-sent requests. Do not infer per-call facts from process `usage` deltas or call a scalar endpoint once per list item.

## Public Ruby contract for review

1. `Engine.new(batch:)` accepts `"max"` or a positive integer other than `true`/`false`; omitted means the `THINKTHEN_BATCH`/configuration tier selected by `EngineBuilder::from_env`, then the saved question, then maximal default. An explicit engine setting overrides the environment. A per-call `batch:` overrides the engine setting. Invalid values raise `UsageError` before any send. `context:` is nonblank UTF-8 text shared by one eligible many-record call; it changes the request digest, not the question digest. It is text, not an implicit file read. The binding must validate input before worker start and pass controls through `CallOptions`, without inspecting or storing a Ruby object on the worker.
2. Accept `batch:` and `context:` on `decide_many`, `decide_many_with_probabilities`, `filter`, `rank`, and new eager `choose_many`, `score_many`, `tag_many`. Accept `batch:` on `annotate`, but reject `context:` because Rust `annotate_with` refuses it. Reject both keywords before sending on scalar `decide`, `choose`, `score`, `score_with_level`, `tag`, `details`, `find`, `recognize`, and `relate`; `find` is a bounded single selection, not a record planner. `question`, `set`, `usage` and `with_tick` are not asking calls and retain their own argument grammar. Apply this classification to every engine method and module delegate; no offered keyword may be silently ignored. `rank(top:)`, `find(none:)`, `annotate(on:)`, `cancel:` and `deadline:` retain their current meaning.
3. Add eager `choose_many(question, records, options: nil, ...)`, `score_many(question, records, levels: nil, ...)`, and `tag_many(question, records, labels: nil, ...)`, plus module delegates. Use the landed `Engine::details_many_with` for runtime `Question` labels and descriptions and collect its stopping iterator to a final result. Its `Evidence + Serialize` bound preserves the complete owned Rust input; the Ruby adapter must separately retain each original Ruby object for `.value`, since current `text_of` turns non-strings into JSON text. Rust typed `Choice` cannot represent Ruby runtime labels. Keep ordered `nil` choose outcomes, numeric scores and ordered tag lists; a terminal failed row raises once after joined work, rather than becoming `nil` or an empty list.
4. A successful asking call returns a `ThinkThen::Call` with `.value`, `.facts` and `.details`. `.value` is exactly the old value: scalar, array, `Ranked`, `Found`, `Recognized`, edge list, or annotate hashes. `decide_many_with_probabilities` retains its row hashes. `details(...).value` is the current `thinkthen.result/1` hash. `rank(top:)` trims only `.value`; facts and observations cover all judged candidates. Filter facts and observations include dropped rows. `Facts` contains `records`, `requests_sent`, `cache_answers`, optional `input_tokens`/`output_tokens`, `seconds` and optional `model`. Missing provider usage and model remain absent. `.details` is an ordered, recursively immutable snapshot of Rust `Question` observations: zero-based input index, optional annotate member or recognition stage/position, question digest, typed answer or failed cause, declared probabilities, optional confidence, model, URL, request digests, per-question usage/attempt share, cache flag and failed-question count. It records no event after ordered stop, while final facts include actual later in-flight attempts joined by Rust. The result's inspection must not print original evidence or raw detail.
5. Account start is Rust's accounting boundary, not Ruby worker creation. A returned Rust failure after that boundary keeps its six-kind Ruby exception and frozen final `.facts` and `.details` after the worker has joined, including truthful zero-send facts; a pre-accounting refusal has no facts even if Ruby started a worker. `rank_with` checks kind and input limit before `Stop::begin`, `details_with` checks kind before its accounting path, and `Batch::failed` has no facts. Preserve those absences rather than fabricating zero. A caught worker panic that loses accounting becomes safe `DefectError` with unavailable facts. Conversion failure after a completed Rust call retains its frozen account on the applicable error. Preserve the current short wait and same-tick stop precedence. On caller-token cancellation, Ctrl-C or another raised Ruby exception while a worker is held, cancel that call and surface promptly. Attach a completion receipt to the surfaced exception when a worker started; once that same worker exits, it exposes final facts if Rust produced them, ordered details and returned failure identity without another request. Preserve Ctrl-C's `Interrupt` cause and `Thread#raise`/raising tick's original exception; `Thread#kill` can end the caller without a returned exception, but must not leak worker ownership. A deadline returned by Rust carries final facts only when accounting began. A receipt before completion must report pending, not partial totals.

## Routing and build lessons to preserve

The Ruby half of J6 already accepts ordered arrays or hashes with string or structured descriptions through `question`, `set`, `keyed` and `recognize_spec`. Case 17-partial preserves unsure `nil` beside a distinct failed member; the six error classes already expose named kinds. Add focused parity proof for structured descriptions and failure markers, not another type framework. R remains a separate owner. Direct `ThinkThen` calls in `site/examples/` will require `.value` migration under the existing marketing-owned [site samples and pages issue](../issues/2026-09-25-site-samples-and-pages-after-the-surfaces-land.md), section 9. Do not claim that site change from this Ruby source ticket or create a duplicate issue.

The native-package pass correctly exposed inherited default Max through the installed Ruby adapter; path hygiene work did not fix its full conformance. The eight fixture failures had been classified before design, but the first preparation checked only `test_interrupt_batch.rb`'s eight-send cases and missed its sibling/wakeup case with 16 held sends and bare `.size`. Fresh design review also caught the false assumption that worker start means Rust facts exist. This correction traces accounting validation before `Stop::begin` and every asserted held-send/count consumer in the affected Ruby tests. Compare these predictions with the eventual build and review under `## What the build taught us` before landing; no speed or closure claim follows from preparation.
