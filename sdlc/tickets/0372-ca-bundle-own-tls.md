# 0372: The CA bundle library test serves its own TLS and runs on macOS

Status: in progress. Plan: `sdlc/planning/cleanup-2026-09-30.md`, lane claude-1. Issue: `sdlc/issues/2026-10-01-ca-bundle-test-needs-openssl-3.md`.

## Outcome

`crates/thinkthen/tests/library/ca_bundle.rs` no longer runs the `openssl` command. It reads fixed test certificates from files in the test folder and serves each HTTPS reply from a `rustls` server on a test thread, as ticket 0371 did for the fork probe. The file is no longer limited to Linux. Its three tests pass on Linux and on the M5 (macOS, arm64) with `/usr/bin/openssl` (LibreSSL 3.3.6) first on `PATH`. No other test in the repository runs the `openssl` command.

## Evidence

- Starts from: ticket 0371 (landed as `91c3acec2`). On the M5, LibreSSL 3.3.6's `s_server` refuses `-naccept`, prints its usage and exits, so nothing listens. Its `req` and `x509` work. 0371 replaced the same generator and responder in `conformance/consumer/fork-probe/tests/fork.rs` with committed certificates and a `rustls` responder, and the case passed 10 of 10 runs on both machines. This file carries the same `openssl` generator and `s_server -naccept 1` responder. Its first line, `#![cfg(target_os = "linux")]`, keeps it off macOS, so nothing runs it on the M5 now. The test-suite grading (`sdlc/planning/grading-2026-09-30/12-test-suite.md`, cleanup item 3) also records one failure of `genuine_tls_trust…` at load 22. The responder reserves a port, drops it, starts `s_server` on it, and polls every 10 ms for the bind.
- Keeps: every property the three tests prove, with the same assertions.
  - `genuine_tls_trust_replaces_default_and_keeps_hostname_verification`: four rows. No bundle refuses the test CA's `localhost` leaf. The test CA's bundle trusts it, with exit 0, `true` on stdout, and exactly one `POST /systemone`. A wrong CA with the same subject name refuses it. The right CA refuses a leaf for `other.invalid`. Each refusal exits 4, says "the TLS connection or certificate check failed", and sends no `POST /systemone`. No row prints the key.
  - `bounded_bundle_refusals_precede_send_and_replay_folder_work`: every refusal row, the `--plan` check, and the zero-connection count on the listener stay as they are. The `too-many.pem` row repeats the test CA 257 times.
  - `public_environment_and_explicit_builder_share_the_loaded_roots`: the environment and explicit builder modes each send exactly one `POST /systemone`, and the explicit mode sends model `local-2` after its CA file is removed.
  - The product code is unchanged.
- Changes: four parts change.
  - New test fixtures in `crates/thinkthen/tests/library/tls/`: `ca.pem` and `wrong.pem`, two P-256 test CAs that share the subject `CN=thinkthen-test-ca`; `localhost.pem` and `localhost.key`, a leaf for `DNS:localhost` signed by `ca.pem`; `other-host.pem` and `other-host.key`, a leaf for `DNS:other.invalid` signed by `ca.pem`. All are valid for 100 years. The keys are test-only and guard nothing. The CA keys are not kept. 0371's committed set has one CA and one leaf and no CA key, so it cannot supply the wrong CA or the second leaf. A comment above the constants in `ca_bundle.rs` that include the files gives the `openssl` commands that made them. The PEM files hold only their blocks, because the product's bundle rule refuses other text. Each test copies the CAs it needs into its temporary folder, so `public_tls_child` removes a copy and the tracked files stay unchanged.
  - `crates/thinkthen` gains `rustls` as a dev-dependency: `version = "0.23.45", default-features = false, features = ["ring", "std"]`, the same line as `fork-probe`. Every crate rustls needs is already in the root lock at the same versions. The root lock gains no package. Its one changed line lists `rustls` among `thinkthen`'s dependencies. `sdlc/scripts/policy.py` adds `rustls` to the accepted development dependency set for `thinkthen`, with a comment naming this ticket.
  - The `openssl` generator, the `openssl` helper and the `s_server` responder in `ca_bundle.rs` are replaced by one in-process TLS responder. It takes the leaf name and the reply. It binds its listener before it returns the address and holds it, so no port is reserved and then dropped, and nothing polls for a bind. It accepts one connection, writes the fixed reply once the request's head arrives, and returns every byte the client sent. A client that refuses the certificate ends the handshake, and the responder returns what it read, which holds no request. It waits at most 60 seconds for the connection and 60 seconds for each read, then fails the test, so a broken client fails the test and does not hang it.
  - The file's `#![cfg(target_os = "linux")]` line goes.
- Proof: real runs on both machines and the repo checks.
  - Linux: the library binary's `ca_bundle` tests pass with `--locked --offline`, 10 of 10 runs.
  - M5 at the branch's code commit, with `/usr/bin/openssl` (LibreSSL 3.3.6) first on `PATH`: the `ca_bundle` tests pass 10 of 10 runs.
  - `git grep -n openssl` over test and fixture files finds no command that runs `openssl`. The certificate comment in `ca_bundle.rs` and the one in `fork.rs` remain.
  - `git diff --stat origin/main -- Cargo.lock conformance/consumer/Cargo.lock` shows only the one root line. `sdlc/scripts/lint` and `CARGO_NET_OFFLINE=true python3 sdlc/scripts/policy.py` pass.
- Defers: the other `openssl` uses in the repository are not test fixtures and run no `openssl` subcommand except `version`. `libraries/ruby/check.sh`, `libraries/ruby/setup-ruby.sh` and `sdlc/scripts/release-workflow` check the pinned Homebrew OpenSSL 3 series that Ruby links against. `sdlc/scripts/release-container` fetches pinned OpenSSL 1.1.1k headers for the Linux release image. `sdlc/scripts/workflows` fakes that `version` reply in its own test. Each pins a library the Ruby build links, by design, so none needs an issue.
