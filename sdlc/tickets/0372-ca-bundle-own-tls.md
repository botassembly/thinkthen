# 0372: The CA bundle library test serves its own TLS and runs on macOS

Status: COMPLETE.

Opened as: 2026-10-11. Plan: `sdlc/planning/cleanup-2026-09-30.md`, lane claude-1. Issue: `sdlc/issues/closed/2026-10-01-ca-bundle-test-needs-openssl-3.md`.

## Outcome

`crates/thinkthen/tests/library/ca_bundle.rs` no longer runs the `openssl` command. It reads fixed test certificates from files in the test folder and serves each HTTPS reply from a `rustls` server on a test thread, as ticket 0371 did for the fork probe. The file is no longer limited to Linux. Its three tests pass on Linux and on the M5 (macOS, arm64) with `/usr/bin/openssl` (LibreSSL 3.3.6) first on `PATH`. No Rust test or fixture runs the `openssl` command.

## Evidence

- Starts from: ticket 0371 (landed as `91c3acec2`). On the M5, LibreSSL 3.3.6's `s_server` refuses `-naccept`, prints its usage and exits, so nothing listens. Its `req` and `x509` work. 0371 replaced the same generator and responder in `conformance/consumer/fork-probe/tests/fork.rs` with committed certificates and a `rustls` responder, and the case passed 10 of 10 runs on both machines. This file carries the same `openssl` generator and `s_server -naccept 1` responder. Its first line, `#![cfg(target_os = "linux")]`, keeps it off macOS, so nothing runs it on the M5 now. The test-suite grading (`sdlc/planning/grading-2026-09-30/12-test-suite.md`, cleanup item 3) also records one failure of `genuine_tls_trust…` at load 22. The responder reserves a port, drops it, starts `s_server` on it, and polls every 10 ms for the bind.
- Keeps: every property the three tests prove, with the same assertions.
  - `genuine_tls_trust_replaces_default_and_keeps_hostname_verification`: four rows. No bundle refuses the test CA's `localhost` leaf. The test CA's bundle trusts it, with exit 0, `true` on stdout, and exactly one `POST /systemone`. A wrong CA with the same subject name refuses it. The right CA refuses a leaf for `other.invalid`. Each refusal exits 4, says "the TLS connection or certificate check failed", and sends no `POST /systemone`. No row's stderr contains the API key.
  - `bounded_bundle_refusals_precede_send_and_replay_folder_work`: a missing CA is refused as `Local` before replay, its message names `THINKTHEN_CA_BUNDLE`, and no replay folder is made. A relative path is refused as `Usage`. Each bad bundle row is refused as `Usage`, and no refusal names the bundle path. The `too-many.pem` row repeats the test CA 257 times. `check --plan` with a missing bundle exits 5, prints nothing on stdout and names `THINKTHEN_CA_BUNDLE` on stderr. A live `decide` with no key does the same before it reads the key or opens a socket, and the listener counts no connection.
  - `public_environment_and_explicit_builder_share_the_loaded_roots`: environment mode trusts the CA through `THINKTHEN_CA_BUNDLE`. Explicit mode's `.ca_bundle()` overrides an invalid relative `THINKTHEN_CA_BUNDLE`. Each mode sends exactly one `POST /systemone`, and explicit mode sends model `local-2` after its CA file is removed.
  - The product code is unchanged.
- Changes: six parts change.
  - New test fixtures in `crates/thinkthen/tests/library/tls/`: `ca.pem` and `wrong.pem`, two P-256 test CAs that share the subject `CN=thinkthen-test-ca`; `localhost.pem` and `localhost.key`, a leaf for `DNS:localhost` signed by `ca.pem`; `other-host.pem` and `other-host.key`, a leaf for `DNS:other.invalid` signed by `ca.pem`. Both leaves have the subject `CN=localhost`, as the current test makes them, so the `other.invalid` row proves the client checks the certificate's DNS name and ignores its subject. All are valid for 100 years. The keys are test-only and guard nothing. The CA keys are not kept. 0371's committed set has one CA and one leaf and no CA key, so it cannot supply the wrong CA or the second leaf. A comment above the constants in `ca_bundle.rs` that include the files gives the `openssl` commands that made them, with `-subj /CN=localhost` for both leaves. The PEM files hold only their blocks, because the product's bundle rule refuses other text. Each test copies the CAs it needs into its temporary folder, so `public_tls_child` removes a copy and the tracked files stay unchanged.
  - `crates/thinkthen` gains `rustls` as a dev-dependency: `version = "0.23.45", default-features = false, features = ["ring", "std"]`, the same line as `fork-probe`. Every crate rustls needs is already in the root lock at the same versions. The root lock gains no package. Its one changed line lists `rustls` among `thinkthen`'s dependencies. `sdlc/scripts/policy.py` adds `rustls` to the accepted development dependency set for `thinkthen`, with a comment naming this ticket.
  - The `openssl` generator, the `openssl` helper and the `s_server` responder in `ca_bundle.rs` are replaced by one in-process TLS responder. It takes the leaf name and the reply. It binds its listener before it returns the address and holds it, so no port is reserved and then dropped, and nothing polls for a bind. It accepts one connection, writes the fixed reply once the request's head arrives, and returns every byte the client sent. A client that refuses the certificate ends the handshake, and the responder returns what it read, which holds no request. It waits at most 60 seconds for the connection, then fails the test. Each read waits at most 60 seconds, then ends the responder, so a broken client cannot hang the test.
  - The file's `#![cfg(target_os = "linux")]` line goes.
  - The issue moves to `sdlc/issues/closed/` at landing.
  - The file shrinks by 45 nonblank lines, so the ceiling in `sdlc/ratchet.json` falls from 108908 to 108863.
- Proof: real runs on both machines and the repo checks.
  - Linux: `cargo test --locked --offline -p thinkthen --test library` passes once, and the same command filtered to `ca_bundle` passes 10 of 10 runs. The library-only build, `cargo test --locked --offline -p thinkthen --no-default-features --features bundled-sqlite --test library ca_bundle`, compiles the file without its `cli` tests and passes once with no warning.
  - M5 at the branch's code commit, with `/usr/bin/openssl` (LibreSSL 3.3.6) first on `PATH`: `cargo test --locked --offline -p thinkthen --test library ca_bundle` passes 10 of 10 runs.
  - `git grep -n -i openssl -- crates conformance` finds only the certificate comments in `ca_bundle.rs` and `fork.rs`.
  - `git diff --stat origin/main -- Cargo.lock conformance/consumer/Cargo.lock` shows only the one root line. `sdlc/scripts/lint` and `CARGO_NET_OFFLINE=true python3 sdlc/scripts/policy.py` pass.
- Defers: two gaps stay.
  - The held listener removes the port race the grading found, by design. This ticket does not run the tests under load near 22; a load run belongs in `test-stress`. The full `sdlc/scripts/test` waits for the coordinator's next checkpoint, as `CLAUDE.md` asks.
  - The other `openssl` uses in the repository are not test fixtures. `libraries/ruby/toolchain.env` pins the OpenSSL series Ruby links against. `libraries/ruby/check.sh`, `libraries/ruby/setup-ruby.sh` and `sdlc/scripts/release-workflow` run only `openssl version`, to check that pin. `sdlc/scripts/release-container` runs no `openssl` command; it checks the image's `openssl-libs` package and fetches pinned OpenSSL 1.1.1k headers. `sdlc/scripts/workflows` runs a fake `openssl version` script in its own test. Each serves the Ruby build by design, so none needs an issue.

## What the build taught us

- 0371's committed set could not be reused. It has one CA and one leaf, and its CA key was not kept, so it cannot sign a second leaf or stand in for a wrong CA. This ticket commits its own six files.
- Both leaves keep the subject `CN=localhost`, as the old generator made them. The `other.invalid` row then proves the client checks the certificate's DNS name and ignores its subject. The two CAs share one subject, so the wrong-CA row proves the client checks the signature and not just the issuer's name.
- The held listener removes the old responder's port race. The old responder reserved a port, dropped it, started `s_server` on it and polled every 10 ms for the bind.
- Clippy's nesting and type limits refused a direct copy of 0371's responder. The responder's loop moved into its own `serve` function, and a `leaf` function replaced a table of tuples.
- The file shrank by 45 nonblank lines, so the ratchet ceiling fell from 108908 to 108863.
- Nothing must be installed on the M5. The tests pass with `/usr/bin/openssl` (LibreSSL 3.3.6) first on `PATH`.
- Reviews: the first ticket review returned seven findings and a second, parallel review returned six; all were fixed. A recheck asked for three more kept checks, which were added, and a fresh recheck returned ACCEPT. Code review returned ACCEPT with one note: a 60-second read limit ends the responder and does not itself fail the test. The ticket now says so.
- Proof run: on Linux at the branch's code commit `01f635d54` (tested as `3bdedb68f` before a rebase that touched none of this ticket's files), the whole `library` test binary passed (66 passed, 1 ignored), `ca_bundle` passed 10 of 10 runs, the library-only build passed its `ca_bundle` tests with no warning, and Clippy on the binary was clean. `sdlc/scripts/lint` and `CARGO_NET_OFFLINE=true python3 sdlc/scripts/policy.py` passed. `git grep -n -i openssl -- crates conformance` finds only the certificate comments. On the M5 (macOS 26.4, arm64, Rust 1.95.0, LibreSSL 3.3.6 first on `PATH`) at the same code, `ca_bundle` passed 10 of 10 runs; it had also passed 10 of 10 at the earlier code commit `836f8ab3c`, tested as `6a17b4c9f`. The M5 run used a scratch folder under `/tmp` that was removed afterwards.
