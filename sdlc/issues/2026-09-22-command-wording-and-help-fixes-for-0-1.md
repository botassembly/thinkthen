# Command wording and help fixes for 0.1

Status: Open. For the build team, lane A1. One ticket takes the whole list.

This merges sixteen wording issues filed between 2026-09-19 and 2026-09-21. Each source file is closed and points here. The source is named on every item so the reproduction stays reachable. Ticket 0057 landed some help work on 2026-09-21, so the ticket checks each item against the current binary before it writes a fix.

1. **Rule the third and fourth outcomes first.** The deck says "not sure" and "an error". The help and ten specification pages say "unresolved" and "broken". Pick one pair before any other item is written, because the words below depend on it. The product side recommends the deck's words. From `2026-09-21-the-third-and-fourth-outcomes-have-two-names`.
2. **The first screen of `thinkthen --help` opens "Put a decider model in the shell".** Ian ruled the pitch as semantic commands. Suggested: "Semantic commands for the shell: if, grep, and sort that understand meaning". From `2026-09-21-the-help-first-lines-and-the-public-words`. Implemented and independently reviewed in ticket 0066: the root doc-string now reads "Semantic commands for the shell: if, grep, and sort that understand meaning". **Marketing output-change note:** the first line of `thinkthen --help` (and of the help printed when the tool runs with no arguments) changed; any capture of the old line is stale.
3. **Each verb's first line says what it does with the text, never "print", "return", or "set the exit code",** because the same line serves Python, SQL, and C. That source carries a suggested first line for all eight verbs.
4. **The command list order is decide, choose, tag, score, filter, rank, find, annotate.** Every talk and page teaches decide, filter, rank, then choose, find, then score, then tag and annotate. Same source.
5. **`tag -h` and `annotate -h` print two example lines above the description** where the other six open with the description. One layout for all eight: description, usage, examples. Same source. Implemented and independently reviewed in ticket 0066: both verbs now open with the description and print their unchanged examples under an `Examples:` heading after usage and options, in short and long help. **Marketing output-change note:** the `-h`/`--help` text of `tag` and `annotate` changed layout; captures of the old layout are stale.
6. **The shipped help, the README, and three how-tos break six approved fixed words:** label for option, document for text, row for record, judgment for question or answer, failed for broken, rating for level. Add `find`'s "unit" for line or record, and `filter`'s "the mark" for threshold. The vocabulary table itself needs the option fix on the marketing side. From `2026-09-21-the-shipped-help-breaks-the-approved-fixed-words` and `2026-09-21-the-help-first-lines-and-the-public-words`.
7. **`--threshold` help never states the default cut of 0.5.** A user checking the exit code against an assumed 0.9 gets a yes from 0.5. From `2026-09-21-the-help-hides-the-defaults-a-user-assumes-wrong`.
8. **`--jobs` help never states the default of 4,** so a user assumes one. Same source.
9. **Short `-h` omits `--url`, `--model`, `--record`, `--replay`, `--cache`, `--timeout`, `--jobs`, and `--max-retries`.** Show `--url` at least, because without it every run reaches the default vendor address. Same source.
10. **`find --help` documents no exit codes and never mentions exit 3 or the empty standard output when `--none` wins.** A user reads the silence as a failure. Same source.
11. **`--timeout 0` was accepted and failed at once with `timeout: global` at exit 4.** Refuse 0, or say that 0 times out at once. Ticket 0057 may have closed this; confirm before writing. Same source.
12. **The help of every record-capable verb prints the single-document exit contract with nothing scoping it,** and a record run exits 0 whatever its records answer. `thinkthen decide 'Is this safe?' --lines < rows && deploy` runs the deploy after a hundred noes. Add the `channels.md:63` sentence to each record-capable verb's help. From `2026-09-21-record-mode-always-exits-0-and-the-help-never-says-so`.
13. **The `decide` help's `set -e` warning names only a no.** Exit 3 ends the script the same way. Name both outcomes. From `2026-09-21-the-set-e-warning-names-only-no`.
14. **`rank --help` promises "in input order" three times and `rank` sorts.** The `--jobs` claim is true and worth keeping; the four words after it are what break it. Give `rank` its own wording, ending "in the order `rank` prints". From `2026-09-19-hands-on-test-pass-two`, finding 3.
15. **The `--field` long help on `filter` and `rank` describes a "without `--jsonl`" mode neither verb has,** because both require `--lines` or `--jsonl`. Drop that sentence from those two copies. Same source, finding 6.
16. **`--input` naming a directory blames standard input** (`standard input could not be read: Is a directory`) and adds `stopped at record 1` although no record was framed. Carry the `--input` path through to the read, and skip the record line when nothing was framed. Same source, finding 2.
17. **A record that is not UTF-8 is reported as "the evidence",** which under `--field` is smaller than the record. Say "the record is not valid UTF-8". Same source, finding 10.
18. **The stopped line prints the recording clause on runs with no recording flags:** `0 records from a recording`. Omit the clause when no recording flag was given. From `2026-09-21-several-messages-cannot-be-parsed-by-a-stranger`, row 3.
19. **`the JSON at line 1 column 2 is not one` has no noun.** Name the thing: "is not a systemone response", "is not a recording entry". Same source, row 1.
20. **`the CSV record has 1 fields; its header has 2` breaks the plural.** Same source, row 2.
21. **`--record DIR` on a regular file says `the recording folder could not be read or written: File exists (os error 17)`.** Say that DIR is a file and ask for another name. Same source, row 4.
22. **The dotted-key refusal states a naming rule that appears in no help page.** Put the rule in `question-file.md` and point the message there. Same source, row 5.
23. **`evidence is text, not white space` reads as a claim that there is text.** Name the real condition, that the evidence is empty or blank. The exit code 2 is right, and the fix belongs to the evidence case alone in `crates/thinkthen-core/src/text.rs`. From `2026-09-21-the-empty-evidence-refusal-names-the-rule-backwards`.
24. **A single question file holding the verb plus an extra key is told `a question file holds one of decide, choose, tag, or score`.** Name the offending key, the way the question-set path already does. From `2026-09-21-question-file-refusals-name-the-wrong-thing`.
25. **A question set missing its `questions` wrapper is told it holds no key named after the user's first question.** Name the missing wrapper. Same source.
26. **Status 400 carries no fixed phrase,** so a misspelled model name prints a bare code. The two sources disagree on the fix and the ticket picks one: `2026-09-21-statuses-400-and-500-carry-no-phrase` asks for one fixed phrase in the `backends.md` table and forbids the body, and `2026-09-21-a-refused-request-hides-the-backends-reason` asks for the backend's own message, trimmed and without headers. The no-body rule exists because a backend can quote the evidence back.
27. **A refused exchange is not recorded,** so the vendor's own message cannot be read afterward either. Record a refused exchange like an answered one, body only. From `2026-09-21-a-refused-request-hides-the-backends-reason`.
28. **A slow backend, a backend that never answers, and a dead connection all print `the backend could not be reached: timeout: global`,** the HTTP client's own kind string. Name the event, the seconds elapsed, and the `--timeout` lever. From `2026-09-21-transport-failure-messages-paste-the-http-clients-own-words`.
29. **The probability-total refusal prints the tolerance as `0.010000000000000444`.** The page sells the rule as one hundredth. Print `0.01`, or one more digit. From `2026-09-21-the-probability-total-refusal-prints-float-noise`.
30. **`--dry-run` accepts `--jobs 1` on a single document and the live run refuses it at exit 2.** A dry run refuses what the real run refuses. From `2026-09-21-a-refused-request-hides-the-backends-reason`.
31. **`records.md:107` says codes 6, 7, and 8 are unused while `channels.md:58` gives 6 to `annotate`'s partial failure, and the code follows channels.** `annotate.md:47` also says a failure ends the run, which the preserved-failure story contradicts. Two page edits, no code change. From `2026-09-21-exit-6-and-partial-failure-are-told-two-ways`.
32. **`annotate.md:88` says empty evidence succeeds and prints nothing; the binary refuses it at exit 2.** The page meant an empty record stream. From `2026-09-21-four-spec-sentences-promise-what-the-binary-refuses`, row 1.
33. **`filter.md:49` and `rank.md:47` say an empty record stream exits 0, and empty CSV input exits 2.** Qualify the sentence to line and JSONL streams, or point at the `records.md` CSV rule. Same source, row 2.
34. **The trailing sentence of `threshold.md:59` says `choose` with no threshold returns the winning label on an exact tie.** `choose.md` and the binary both give `null` at exit 3. Drop or rewrite it. Same source, row 3.
35. **Two examples are wrong as printed:** `result.md:99` shows a `rank --details` row with `"value":true` where `rank.md:43` fixes `null`, and `tag.md:25` omits the `schema` and `meta` fields `result.md` fixes as always present. Same source, row 4.
36. **`result.md:28` reads as if `value` on a `filter` row is the record.** It is the boolean the cut produced, and it is the only field saying whether the row was kept. One row on `result.md`. From `2026-09-19-hands-on-test-pass-two`, finding 7.
37. **A `rank` plan's `from` map carries `threshold`, a setting `rank` does not take,** and it can only ever read `default`. Leave it out on `rank`, and say on `channels.md:100` that `from` names only the settings the verb takes. Same source, finding 8.
38. **Every `filter` and `rank` `--details` row reports `question.verb` as `decide`,** so rows from two runs cannot be told apart. The reading is arguable, so the fix is one sentence on `result.md` saying `question.verb` names the question's kind and not the command. Same source, finding 9.
39. **`demos/README.md` says only `decide`, `choose`, and `score` are built,** three rows above three green pages that run `filter` and `rank`. The sentence becomes a list of the verbs still unbuilt. Same source, finding 4.
40. **`README.md:13` tells a newcomer the landed code speaks an earlier grammar,** and all three commands printed directly above it run as written. Drop the clause or narrow it. Same source, finding 5.
