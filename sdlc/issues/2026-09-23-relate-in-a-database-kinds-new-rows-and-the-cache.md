# Relate in a database: kinds, new rows, and the cache

The product side found these on 2026-09-23 while planning the Beatles graph (`experiments/239-beatles-graph`) for the database surfaces. The planner is in `sdlc/planning/relate-design.md`. Ian can overturn any line.

1. **Every surface takes a kind column.** The planner needs name plus kind. SQLite and DuckDB take a table or query with an id, a name, and a kind column, plus the rules. Polars takes a frame and the column names. Python and TypeScript take a list of (name, kind) pairs. Every surface returns edges as rows: relation, source id, target id, probability, joinable back to the entity table. The planner lives in the core, so all surfaces behave the same.
2. **New rows against old rows.** A table grows. Adding ten songs should not re-ask about the 184 already linked. Relate needs a way to mark which entities are new, so it asks only questions that touch a new entity. Between kinds, that is a choose for each new song. Within one kind, it is H over the pairs that hold a new entity. This is the two-set form the earlier issue asked for, under a narrower name. It is the most likely thing a database user needs after the first run.
3. **A new option bills every old question again.** A choose question carries its options, so adding one album changes every song's question and misses the cache for all of them. Say so in the manual. Measure whether "new rows" plus a yes/no for each old song against only the new album keeps the bill in step with the change.
4. **Links to a known entity table.** Mapping a name that recognize found ("Lennon") to a row in the user's own table ("John Lennon") is relate between two kinds, mention to person. When the table passes the option ceiling, the H fallback is too costly at scale. A cheap first cut (the `find` family, or a plain text match on the name) that narrows the candidates is needed there. It is not needed for 0081.
5. **Graph queries stay in the host.** Paths and neighbors are a recursive query in SQL or a join in Polars. ThinkThen returns edges and adds no graph function.
