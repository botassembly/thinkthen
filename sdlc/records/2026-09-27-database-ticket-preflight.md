## 0149: SQL settings and per-send total

The [attempt-accounting preflight](2026-09-27-attempt-accounting-preflight.md) isolates item 4's final-check/count/transport gap before exact 0170 facts. A count after response return would miss in-flight sends; a count moved behind the deadline check while it still starts the usage writer would make the existing slow-hook no-send test fail. The record compares a prepared counter guard with these alternatives. It does not change the accepted SQL budget or host behavior.

The 0154 builder confirmed that public `Engine::with_model` really calls `Backend::resolve` in `engine/facade.rs`, but today's public engines all keep the 96,000-byte default and CLI request-size overrides do not traverse that reconstruction. It is not a demonstrated 0154 runtime defect. Ticket 0157 must carry any future nondefault public request size through `with_model` when it adds that setter; prove the model change retains the configured size before landing 0157.

- **Authority and code.** The accepted ticket and `sdlc/records/0149-design-review.md` live on `origin/ticket/0149-sql-settings`; they are not landed runtime. Main `crates/thinkthen/src/public/settings.rs` lacks `profile_json`, and `engine/http.rs::post_observed` has no typed `SendBudget` reservation. DuckDB `src/engines.rs::within_total_typed`, SQLite `src/settings.rs::remaining`, and PostgreSQL `src/call.rs::Call` enforce totals before a call, so a retry can cross the cap. DuckDB warm's environment resolver also misses its session setting. Experiment 253 D1–D5 supplies stock-host caller setting and file-access evidence.
- **Integration trap and prework.** Land 0155's retry accounting first. The accepted design places a final stop/deadline check and atomic budget reservation at each live send, including retries, with typed first-send and retry denial. Hosts map that marker to their existing spent-total usage refusal; they do not infer it from shared counter deltas or error text. SQLite's 0200 connection budget and PostgreSQL statement timeout remain separate boundaries. Coordinate DuckDB warm with 0201's C++ aggregate owner. A process-global or kept relate connection is not a substitute for the caller session.
- **Smallest proof.** One loopback 503 followed by a denied retry proves one send and the typed marker before each host's mapping. A direct zero-cap `SendBudget` check proves `BeforeFirstSend` with zero sends. SQLite SQL rejects total zero; exhaust a positive SQL total first, then count zero additional sends on its next call. DuckDB and PostgreSQL permit SQL total zero in current source, but retain each host's setting semantics in its boundary proof. One DuckDB same-session warm then scalar proves shared cache, and a second session proves isolation. Run selected host settings checks after a rebuilt extension, with the single related-batch integration checkpoint later.

## 0207 and SQL find: distinct missing operations

- **SQLite recognize relations.** Main `databases/sqlite/src/tables.rs::Recognizer::ask` rejects a `/recognize/relations` spec. The separate `Relater` sees row ID/name/kind, not the original text. `sdlc/records/0206-prove-equivalent-conformance-paths.md` measured two generic relation request bodies with no original text, versus the one captured case-42 relation body; it did not prove equivalent answers. Public `Engine::recognize_with` and `Recognized::to_json` already exist in `crates/thinkthen/src/public/recognize.rs`. The proposed 0207 ticket and `sdlc/records/0207-design-review.md` require a fresh decision on SQL name, full spec and `@file` grammar, wrong types, NULLs and result shape. One public engine call can make several backend requests. The appendix in 0207 maps the exact prework; keep all nine skips until each captured arm passes.
- **Grouped find.** Main's three SQL conformance runners skip `18-find-second` and `19-find-none`. `specification/find.md` sends one bounded ordered unit set and can select none; `ORDER BY` probability plus `LIMIT` asks separate row questions. The active 0201 ticket acknowledges this. The SQL-find issue owns a reviewed feature design. Evaluate an ordered array or aggregate form against each host's existing public find API, NULL/empty/tie behavior and original indexes before settling SQL spelling. B13 batching only changes scheduling and does not close this contract. The issue records the smallest closure proof.
