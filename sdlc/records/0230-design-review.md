# 0230 C JSON batching design review handoff

Status: review requested for [ticket 0230](../tickets/0230-c-json-batching-and-facts.md) and its [preflight](0230-c-batching-preflight.md). This record reports no acceptance or implementation. Review against B12b in [the batching issue](../issues/2026-09-26-batching-design.md), accepted ADR 0089 on the 0212 branch, `libraries/c/include/thinkthen.h`, `libraries/c/src/{call,ffi,failures,settings}.rs`, and the shared result schema/corpus at main `cbaa5fbd`.

The central public choice is the success JSON shape. Automatic `{"value":<old JSON>,"facts":...}` satisfies facts on every successful asking call but changes the present bare JSON response. The recommended failure route keeps `NULL`, code, message and retryability, and adds a borrowed facts JSON accessor on the same thread/engine last-failure slot. ADR 0089 explicitly provides facts on started eager failures and terminal lazy errors, including joined attempts; dropping them in `Failure::from(Error)` would violate the inherited contract. A non-NULL error envelope breaks current pointer-as-success checks. Assess whether these two proposed shapes and the separate `"call"` object for per-call batch/context are the smallest justified public changes. If the outward JSON choice is not entailed by accepted B12b, identify it for Ian before implementation. The C accessor is a second **local read**, not a second model call; check its pointer lifetime, absent-facts behavior and additive ABI impact.

The first review found that 0212's `choose_many`/`tag_many` need compile-time `Choice`, while C's JSON labels/descriptions are runtime values; typed bulk rows also lack full `Details`. Check the proposed **new** `Engine::details_many_with` stopping bridge: `DetailQuestion` includes a dynamic `Question`, `Batch<Row<_,Details>>` retains input and final facts, and answered members reuse one profile-aware `Details::of_member` conversion with exact request identity. `records` plus `details:true` yields an ordered array of full detailed objects for decide/choose/score/tag; a failed middle row yields `NULL` and failure facts with no partial JSON. Proposed ADR 0094 at `fb58010a` shares a potential member-details helper but its recoverable SQL continuation is unimplemented, pending Ian and incompatible with the C stop rule. Treat the public Rust bridge as a separate reviewed prerequisite; do not silently add it to accepted 0212 or borrow the SQL failure policy. Check one dynamic-label, exact-detail-identity and failed-middle-row outside-in case plus shared schema/corpus rows.

Check ten output shapes, null versus failure, tag `[]`, annotate failure marker, details nesting, `{"usage":true}` exception, constructor/env/question precedence and exact `batch 1` bytes. C arrays are materialized before Rust iteration; do not settle 0212's pending caller-owned iterator choice by analogy. Verify proposed source claims include closed schema, shared valid/invalid corpus, old rejection replacement and actual C consumers. Return ACCEPT or concrete findings. No code, package or paid proof has run for 0230.
