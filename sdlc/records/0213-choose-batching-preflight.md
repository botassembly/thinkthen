| Boundary | Source fact and integration trap |
| --- | --- |
| Arguments and tiers | Main `cli/args.rs::ChooseArguments` has no `Batching`; `cli/judge.rs::choose` sets `Asked.batch=None`; `cli/asked.rs::choose` keeps only the `QuestionFile` and discards `read_top`'s batch value. `Tiers::setting` already settles flag, `THINKTHEN_BATCH`, file, default, but no choose call reaches it. `core/question_file.rs::parse_top` removes `batch` only from `decide`, so choose files still reject it. Inspect `cli/args/command.rs` and `cli/mod.rs` when changing the argument carrier. |
| Dynamic question | `cli/asking.rs::Asks::FromRecord` builds `Question::Choose` using `Record::choices` at a pointer. `cli/asking/batched.rs::run` currently rejects every non-`Fixed` ask. `core/batch.rs::Batcher` keeps one question and keys duplicate records only by selected JSON line. Two JSONL rows with the same `/note` but different `/codes` therefore cannot use the current path: they would share a wrong answer if only the defect guard were removed. Deduplication must compare both selected evidence and complete ordered question. The content-cut hash still uses selected JSON alone. |
| Wire and splits | `core/batch.rs::Batcher::built` uses the template question for its singleton plan; `joined`, `quoted` and byte sizing also assume the template; `halves` takes one question for both halves. Per-record options need the row's actual question in all four places. The existing `Plan` accepts a vector of questions and `backend/batching` captures exact bodies; reuse those. `specification/fixtures/systemone/batch-choose.request.json` pins the fixed-options batched shape. Do not substitute ADR 0055's fixed evidence sentence, which is only for yes/no batching. |
| Context and rows | Landed 0172 adds `cli/asking/context.rs::for_run`, `RowContext`'s raw-byte SHA-256, typed refusal mapping, context-aware `Batcher`/halves and batch-one `meta.batch`. The choose extension must reuse this source, not rebuild its file read or introduce a second result initializer. `cli/asking.rs::row_of` already produces input-order JSONL and empty raw lines for not sure. Its current question argument is the digest/detail source, so a batch must pass each row's question. |
| Stop and facts | `cli/asking/batched.rs::answer_rows` allocates per-row token/request shares and stops at a missing outcome. `engine/schedule.rs::Completed` counts finished and replayed records; 0170 `cli/mod.rs` checks the final stop after usage flush. A 413 half records its refused attempt and first-half rows. Choose must reuse that path and keep each half's option lists, rather than count rows from output or treat a valid tie/null as a failed answer. `backend/facts.rs` and `backend/batching/too_large.rs` supply existing proofs. |
| Warning and identity | 0171 `Mismatch::with_batch`, `batch_meta::Description` and `Run.batch_warning` already handle command record warnings. Choose's file tier must reach them. `core/digest.rs::question_sha256_with_profile` includes ordered option descriptions and the threshold, excludes batch/context; request digest hashes the encoded body and address. A generic JSON reserialization of a captured fixture can reorder members and invalidate an identity proof. |
