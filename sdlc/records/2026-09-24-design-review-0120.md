# Design review of ticket 0120: build the Rust Polars surface

Date: 2026-09-24. Each round ran a fresh, read-only Claude Opus reviewer on the ticket at the commit named. Author: Claude. Verdict: ACCEPT at `18c14091`, before this record and the status change.

## Round 1 at `2f9482bc`: findings

1. The script changed `HOME` before it looked for the toolchain, so it could never pass. The scratch `HOME` hid `~/.cache/thinkthen-toolchains` and cargo's crate cache. Fix: read the real `HOME` first, or leave `HOME` alone.
2. The throttle tests shared one process, against the shared rule that puts each in its own. The held-arm test holds all 8 permits, so the other tests would flake. Fix: one test binary per throttle test.
3. The failed-marker test compared the door's output with the value the door itself used. Re-serializing a parsed member through a sorted map puts `cause` before `kind`. Fix: pin the literal marker, lift member text unchanged with `RawValue`, and take widened number and array text the same way.
4. Nothing said what choose, score, and tag over a Series do with a failed row. Fix: state the rule and test it.
5. The wrong-kind refusal had no sentence and no test, and `decide_series` cannot read a kind through the sealed `DecisionQuestion`. Fix: pin a sentence with a zero-request plant, and say decide relies on the engine's refusal.
6. The no-paid-backend plant could not turn red, because the next line overwrote the sentinel with the fake key. Fix: plant a change that lets the real key through.
7. R2-12's plant cannot be written in safe Rust, and R1-4's plant could stay green. Fix: fold R2-12 into R1-3, and give R1-4 a plant that changes type or metadata.
8. "Not run" was not tied to its one real cause. Fix: one probe step, `cargo fetch --locked --offline`, is the only failure that maps to "not run".
9. The README doctest would send requests and called three cache setters that override each other. Fix: `no_run` and one cache setter.

Confirmed: the answer that Python Polars does not need Rust Polars matches 0106. The trait signatures match 0084 and 0095, and `CallOptions<'_>` fits `decide_many_with` and `annotate_with`. The cancel departure is justified. The Evidence section passes `sdlc/scripts/tickets`. The five-method surface is the smallest that meets Ian's ruling.

Answered in `bcec50cd`.

## Round 3 at `d6f80b39`: findings

The answers to both earlier reviews were correct. Six new findings:

1. The shared-case test could not be built as written. It named every decide, choose, score, tag, and annotate case, including the fault injections 20 to 25 and the text and file questions 29 and 30. A binding has no public fault hook, and skipped cases must be reported as not run. Fix: list the cases run and the cases not run with reasons, and name the mid-batch cancel proof.
2. The cancel test guarded nothing the deadline test missed. `CallOptions` has no getters, so the only way to drop the token is to drop the whole value, which is the deadline plant. Fix: delete the cancel test and record that one pass-through test covers deadline, cancel, and the interrupt check.

4. The column contract with 0106 needed settling before 0106 is built. The tag's Python writer used `f64` display and the stand-in's marker serializer, and "follows 0106" could overturn this ticket. Fix: file the table and the `value_json` source as an issue against 0106 now, and let whichever door lands first write the ADR 0047 Polars item.
5. A typed `ChooseQuestion<C>` or `TagQuestion<C>` cannot reach `choose_series` or `tag_series`. Fix: record it as a decision Ian can overturn, and show the typed path through `annotate_frame`.
6. The R2-28 plant deleted the installed toolchain, and `Debug` claimed a row number that no refusal carries, with no test pinning `Debug`. Fix: run with an empty scratch `HOME`, drop "row number", and assert `Debug` beside each refusal.

## Round 5 at `0632106e`: findings

Review 4's finding was answered correctly. `18-annotate-two-groups` is the only case with `on` pointers, and it now sits in the not-run list with a reason that matches 0084. One new finding:

1. The door cannot read a set member's `on` pointer. `QuestionSet::members()` gives only name and kind pairs, so the fallback refusal the ticket asked for needs a getter in `crates/thinkthen`. The private parser also gives every member without `on` the empty pointer, so a naive check would refuse every set. Fix: if the engine does not refuse such a set, the builder stops and files an issue, and the door adds no refusal the public API cannot support.

Answered in `18c14091`.

## Round 6 at `18c14091`: ACCEPT

The answer to round 5 matches 0084 and 0095. Under 0084, reading JSON pointers stays command-only, the public builder cannot set `on`, and `members()` returns only name and kind. 0095 rules that a member the library cannot honor is `Usage`, so the engine will probably refuse such a set itself.

Builder note: the R1-24 deadline row uses 200 distinct texts, because the engine asks once for equal texts in one call. The ticket now says so.
