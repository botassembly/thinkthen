## Existing count assertions and smallest installed-host proof

The original source audit includes each affected assertion, not merely the new total case. Keep independent historical boundaries at explicit `SET thinkthen_batch = 1` in their fresh child/session; then pin packed bodies from a separate fixed fixture. `cpp/verify_decide.py`'s repeated two-text decision/probability counts, `tools/verbs_suite.py`'s two-distinct-text decide/probability and banded warm counts, `tools/conformance.py`'s old exact multi-row exchange cases, and the held eight-send listed-vector case in `tools/signal_suite.py` need this baseline. `tools/settings_suite.py::an_annotate_set_spends_one_request_per_text` remains B10's separate behavior until 0216 settles its metadata and implementation; do not recast it as a B13c success. `cpp/verify_tables.py`'s one-distinct warm, `NULL`/mixed-question refusal, boundary singleton, file permission and zero-total cases retain their counts without a batch override; `cpp/verify_interrupt.py`'s held calls also use one input. `tools/settings_suite.py`'s ten-row scalar total and retry-total checks must be reviewed against packing: use batch `1` for their original row/attempt evidence, then a separate forced two-packed-request total-one proof for the new rule. `tools/site_examples.py` and executable README samples keep their drawn output; if a changed default alters an asserted send count, use an independently pinned packed oracle for that exact sample rather than a planner-computed expectation. Do not change unrelated relate/recognize assertions.

The historical `cpp/verify_decide.py` and `cpp/verify_tables.py` are not invoked by `check.sh`; they are proof inputs, not locations for new gated assertions. The routine rung invokes `tools/verbs_suite.py`, `tools/settings_suite.py` and `tools/conformance.py`, so put the selected new cases there. A prepared invalid foldable `try_details` question plus a good sibling belongs in the invoked verbs suite, as does a failed packed request followed by an independent good request. Neither failure may cause extra model calls to isolate members. The invoked settings suite must pin warm query budget zero as the exact Deadline error with zero listener sends; cancellation remains separate. A fixed cap-three canonical loopback fixture with no earlier content cut must answer good/failed/good members in one reply and a later good member in another request, pin exact JSON slots, both bodies/digests and two attempts. A separate whole-request failure fixture covers request-wide recoverable mapping. An internal width-two worker witness holds the oldest request using the existing acknowledgement/barrier pattern, lets the later request return outer fatal Deadline or Defect, checks that a third request is not admitted, then releases the oldest and checks ordered join. This is one deterministic boundary case, not a churn campaign. The shared private `ask_record_batch_with_one_split` prerequisite must use `core::batch::halves_with_questions` after an eligible 413 or `max_tokens_exceeded`. It sends left once, then calls private `after_left(&Batch, &Result<Answered, Error>) -> SplitDecision` **before** any right send. The stopping B12a callback returns `Stop` for a recoverable left request error or any failed logical member in an answered left reply, preserving only the valid ordered prefix under ADR 0051. The native callback returns `SendRight` for those recoverable outcomes, retaining safe failed left slots. Both send right after an all-good left; fatal Cancelled, Deadline and Defect bypass the callback and stop. A fixed four-member, cache-off/retries-zero table pins: original refusal plus two answered halves = three sends and four finished records for both callers; failed left request = two sends/zero records and no right for B12a versus three sends/four returned native values; first left member good and second failed = two sends/one finished prefix record for B12a versus three sends/four returned native values. Pin exact original/half bodies and digests, listener requests and frozen facts; no recursive or per-member resend. If the original succeeds without splitting, B12a still stops at its first failed request/member while native maps recoverable failures and continues. If the right fails, the same caller-specific stop versus safe-value rule applies. Current `ask_batch` alone does not provide splitting; `cli/asking/batched.rs::split_answered` currently does. This prospective shared helper is not installed B12a code, and its separate caller-owned iterator pause question does not change SQL vector-edge closure. The installed-artifact branch currently invokes conformance only; it must also run `verbs_suite.py b13c_try_details_members b13c_try_details_prepared` and `settings_suite.py b13c_warm_zero_budget` with `THINKTHEN_DUCKDB_EXTENSION` set to its unpacked path. `tools/harness.py::main` already selects named cases, but must reject unknown names so a typo cannot yield a false pass.

The selected new stock-host proof loads a just-built Linux x86-64 package on pinned DuckDB v1.5.5, with `SET threads = 1` and fixed input order. Reuse `tools/harness.py`, selected invoked `tools/verbs_suite.py`, `tools/settings_suite.py`, `tools/conformance.py` and the existing loopback arm. Historical C++ verifier cases can be migrated into those invoked suites. Pin full exact bodies/digests and native row types for short duplicate/`NULL`/listed/context vectors and a warm group; compare batch `1`, default and changed context. Force two independent two-member packed requests at cap 2 and total 1 with cache off and retries zero. An unlimited run supplies both exact bodies; a fresh limited run sees exactly one attempt whose body is either pinned request, spent-total Usage and no completed result from that evaluated vector/group. A 503 retry-denial remains separate. One prepared bind with a changed executing-session batch value and one permitted/denied named file with zero refusal sends cover the C++ ownership and permission seam. Reuse one cross-vector query-budget/held-SIGINT boundary and the installed artifact's stock v1.5.5 acceptance/v1.5.4 refusal; do not rerun every port or stress. ## What preparation taught us

The final review of `25947051` found that an always-send-right split helper would violate ADR 0051 for stopping B12a. The caller now decides before the right send; the bounded proof distinguishes recoverable request failure from a failed logical member, exact attempts from finished rows, and stopping from native continuation. The boundary review of `cedcbab2` found that a fatal result hidden inside a worker success envelope could admit a third request while the first was held, and that `ask_batch` has no one-time split. The correction names fatal outer-error classification, a shared private split-aware implementation prerequisite and a deterministic admission witness. Main `5261cb93` raised `public/results.rs` to 474 lines and changed its saved-profile constructor and shared JSON/digest writer; the proposed member constructor now follows that source. The second review of `2e271917` accepted the warm ABI and routine-rung corrections but found that a private engine carrier was unreachable from the separate bridge crate, and that a whole-request failure test missed member-level recovery. Proposed ADR 0094 now names the public Rust method, private reused engine path, native group ABI and one-reply mixed-member proof. Installed mode also needs explicit selected-suite invocation against its unpacked binary. The first independent review caught three misses: a permanent row-isolated `try_details` exception would leave accepted `max` vector behavior unfinished; warm budget authority was named without its absent ABI path; and the cited C++ verifier scripts are not rung-called. The private vector outcome frame, explicit `Remaining`/bridge argument and invoked-suite locations now make those obligations inspectable. The earlier SQL designs could reuse a many-record host adapter, but DuckDB already has several grouping layers: C++ deduplicates vector rows, Rust still asks per text, and warm sorts aggregate evidence. Reading `StatementOwner` separates one statement budget from per-group trailing deadlines. Reading the actual tests exposed held-send counts and old exact exchanges that a default-packed implementation would invalidate. The three other platform packages have their own C API path and cannot inherit Linux C++ results. Compare this inventory with implementation and fresh review; correct any missing constructor or count before widening claims.
