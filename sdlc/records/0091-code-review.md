## Non-blocking notes

- Stand-in limits. Every token of a name got the same `IN` probability, so the cases cannot tell min, mean, or first-token strength apart. Probabilities sit far from the thresholds except 0.55 and 0.6693. The stand-in read main's own question wording to pick its answer, so the synthetic cases cannot show that the wording asks the backend the right thing. Only the deferred captured re-record can show that. The README and provenance already say "synthetic". Consider one relation case with an edge probability just under `relation_threshold`.
- `conformance.rs` (`self.id.as_str() >= "26"`) compares strings. An ID such as `100-...` sorts below `"26"` and would escape the provenance rule. Parse the leading number instead.
