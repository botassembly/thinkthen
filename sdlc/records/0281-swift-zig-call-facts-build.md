Date: 2026-09-29. Branch: `ticket/0281-swift-zig-call-facts`; approved design on main `260b75457` (High ACCEPT `494d59f1`). Candidate awaits fresh High code review and root landing.

## Change and retained contract

All four typed methods in each wrapper now use one corresponding existing C `*_with_facts_opts` operation and return the old value plus owned `CallFacts`. Swift returns `CallResult<Value>`; Zig returns `.ok = CallResult(T)` and requires `deinit` with the original engine allocator. Swift recognize/relate still have no options arguments and pass no deadline/token to C. Zig retains all `Options`. The C header/ABI, JSON `call`, six failure kinds, token and caller-joins-before-close rules, and the old scalar/bulk/JSON values remain. Required unsigned counts and finite nonnegative seconds are strict; optional usage stays absent, including when the model is reported. Swift frees native result and facts outputs independently on success and throw, and asserts that nonzero C returns leave both the old value and new facts slots untouched. Zig duplicates every returned string into its allocator and frees partial allocations and both native strings on failure. Started-failure borrowed facts are copied before any later native call.

The direct Swift fixtures, example and README, and Zig fixtures, example and README use `.value` and Zig `success.deinit(allocator)`. Zig's landed installed producer still copies `portable_batch.zig`; `Tests/public_types.py` and `check.sh` remain untouched. No new C symbols, schema, settings or JSON route were added.

## What the build taught us

Preparation correctly found the eight bare typed routes, existing owned C calls, copied Zig input and the one-reply cache unit. The old repeated bulk input was different, so it could not prove a cache hit; the identical replay added the missing zero-send witness without changing the full ledger. A strengthened recognize assertion initially expected one send from one logical record; the live fixture exposed two sends, and the corrected assertion pins that distinction. Host numeric decoding needed an explicit unsigned boundary in Zig, and a successful scalar still needs Zig `deinit` when facts own a model. The separate four-arrival modes kept overlap, no-usage and copied-failure lifetime proof concrete without bloating the exact 30/42 body inventories. Copied installed builds had to be reassembled after source/examples changed; older archives could not prove this candidate.
