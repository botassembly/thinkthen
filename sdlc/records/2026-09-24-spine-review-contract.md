## Blocking findings

**B1. 0084: `rust.md` still shows the old fallible `Evidence`.** The 0084 branch diff of `sdlc/planning/libraries/rust.md` keeps `fn evidence(&self) -> Result<&str, tt::Error> { Ok(&self.text) }`. The inventory now says `fn evidence(&self) -> &str`. 0084's own acceptance says its records agree, and they do not. Smallest change: make the example return `&self.text`. The same page also says "Scoped threads run a batch at width and vanish when it ends". Change that to say a `Batch` joins its workers when it finishes or drops.

**B2. 0095: the public API grows with no ADR record beyond the interrupt check.** `rust.md` says "A check fails when the public API grows without an ADR", and Ian's 2026-09-20 ruling limits each library to the functions, question setup, and supporting forms. The proposed ADR 0017 amendment on the 0084 branch records only `CallOptions::interrupt`. `deadline_seconds`, `deadline_millis`, `QuestionKind`, `LabelBuilder`, `members`, `Recognize`/`Relate::from_json` and `load`, `Row::probability`, `ErrorKind::name`, and the four JSON methods have no ADR line. Smallest change: add one paragraph to the 2026-09-24 amendment. The paragraph names these members as supporting forms that bindings need, cites 0095, and says Ian can overturn it. Add the ADR path to 0095's `opens`.

**B3. ADR 0047 item 1: workspace membership pulls every host toolchain into the root gate.** A root-workspace member puts pyo3, napi, pgrx, the DuckDB and SQLite system crates, and the R and Ruby build scripts into the root `Cargo.lock`, into `policy.py`'s dependency tables, and into every `--workspace` lint, clippy, and test run on yellow. pgrx then needs `pg_config` on the gate host. The branch avoided this with a separate `[workspace]` in each binding. For example, `libraries/c/Cargo.toml` says "A workspace of its own, so the root workspace's gates and profile stay untouched". R's offline tarball also needs a standalone crate (R4-7, R5-38). Smallest change: each binding is its own Cargo workspace with its own lock and a path dependency on `crates/thinkthen` with default features off. The Rust examples crate may stay a root member because it needs no host toolchain. 0093's lint checks then scan `libraries/*/Cargo.toml` and `databases/*/Cargo.toml` directly and do not rely on workspace membership.

**B4. ADR 0047 item 3: the lint change as written cannot work, and it touches an accepted policy table.** The root `Cargo.toml` sets `unsafe_code = "forbid"`, and `policy.py` pins that value in `ACCEPTED_RUST_LINTS`. A member that inherits workspace lints cannot lower `forbid` for one module. pyo3's and pgrx's generated `#[allow(unsafe_code)]` also fails to compile under `forbid`. The repo `CLAUDE.md` says "Do not weaken the lint or policy tables". Smallest change: `thinkthen` keeps `#![forbid(unsafe_code)]` in `lib.rs`, where it already sits, and the root table stays as it is. Each binding's own workspace (B3) declares `unsafe_code = "deny"`. Only the FFI module allows it, with `#[allow(unsafe_code, reason = "…")]`. `policy.py` gains one accepted binding lint table and one planted failure: `unsafe` outside the FFI module fails.

**B5. ADR 0047 item 2: the library name `thinkthen` collides with the name of its own dependency.** The crate `thinkthen-c` sets `[lib] name = "thinkthen"` and depends on `thinkthen`. The branch crate-type list includes `rlib`, so in a shared target folder two artifacts named `libthinkthen.rlib` and `libthinkthen.d` collide, and Cargo warns about the collision. The C crate's own tests also cannot name the engine crate. Smallest change: a separate workspace (B3) fixes the shared folder. Also drop `rlib`, or name the lib `thinkthen_c` and let 0094's release step name the files `libthinkthen.so` and `libthinkthen.a`. 0094 adds a red-first build test for this.

**B6. ADR 0047 item 5 changes an Ian ruling, and the route to Ian does not exist.** Ian accepted ADR 0017, whose §2 says "One width gate for the process". 0077 cites "Ian's later one-process ruling". Item 5 limits that cap to one loaded copy. The ADR says items 5 and 6 appear in the "Needs Ian list of the 2026-09-24 spine design pass". No such list exists on main, on any 0084 to 0095 branch, or in `notes/todos/`. Smallest change: write one `notes/todos/` entry. It gives the options (prevent a second copy, a cross-copy primitive, or a per-copy cap stated on every page), the cost of each, and the recommendation, and the ADR points to it. Item 5 stays a draft until Ian answers.

## Answers to the five questions

1. **Nine surfaces.** With 0095, each surface binds through the public API alone. G1: `interrupt`. G2: 0089. G3: the churn test in 0086. G4: `Row::probability` plus one-question `annotate`. G5: `LabelBuilder`. G6: `from_json`, `kind`, `members`. G7: `deadline_seconds` and `deadline_millis`. G8: the four JSON methods. G9: ADR 0047 (B6). G10: 0092's loopback binary. G11: infallible `Evidence`. Questions 1 to 16 each have a sound answer. Follow-ups F3, F4, F6, and F7 cover the gaps.
2. **Contract changes.** Each one is correct and necessary, and each matches main. The old `Batch<I::Item>` at `007a9b14` had no lifetime and no `'static` bound, so it could not hold a borrowed iterator between pulls. Any external crate can implement the infallible `Evidence`, and no external crate can build an `Error`. The refused oversized deadline matches the branch ADR 0041 amendment ("a budget too large is refused on every door"). `both_ways` with two kinds matches `relate.md`, where `"either"` sits on a rule with a source and a target. Width 1 to 32 matches `args.rs` (`range(1..=32)`) and 0077. 0086 line 49 carries `width(0)`, `width(33)`, and `Duration::MAX`.
3. **ADR 0047 against ADR 0017 and ADR 0037.** No layer split is published, so ADR 0047 is consistent with ADR 0017 §1 and §8 step 2 and with ADR 0037. The conclusion about the separate crate is right. The reason is incomplete. The main reasons are ADR 0017 §8 step 2 and 0084's rule of no public C symbol. A Cargo feature also cannot add a `cdylib` crate-type. The `unsafe` ban is a third reason. Its mechanism is wrong (B4).
4. **Acceptance and the character limit.** 0084 has 27 characters of headroom. Its "Changes on reopening" paragraph repeats 0095's "Why 0084 changed" section. Replace it with one pointer sentence to free about 550 characters for B1 and F1. "The block parses as the fixture generator's input" cannot be checked before 0086 builds the generator. Use `rustfmt --check` on the extracted blocks of 0084 and 0095 instead. The red-first proofs sit in 0085 and 0086, and they cover the changes except F5.
5. **Ian's rulings.** B6 (one-process width) and B2 (library shows only functions and setup) are the only conflicts. The port guide's Python row still says "Python, with pandas", which Ian's 2026-09-21 Polars ruling removed (F9).

## Follow-ups (non-blocking)

- F1 (0084): The free `filter`, `decide_many`, and `annotate` return `Batch`, not `Result`. State that a `default_engine` build failure comes back as the first item. Also state that `Batch` is neither `Send` nor `Sync`, so the worker-thread pattern builds the batch on the worker thread.
- F2 (0086 text): Line 46 says "No panic crosses a public engine method". 0095 and 0085 resume a panic raised by the interrupt check, which PostgreSQL's interrupt check can raise through pgrx. Change the line to "No engine panic crosses…; a panic from the caller's interrupt check resumes after the join".
- F3 (0095): A binding that reads an `@file` itself (PostgreSQL `open_beneath`, the SQL `'@refund.json'` form) and calls `from_json` gets `Usage`, where the command reports `Local`. State that such a binding maps that `Usage` to its host `Local`.
- F4 (0095): With infallible `Evidence`, a streaming host that meets a bad row mid-stream ends its iterator, keeps the host error, and raises it after the batch drains. Name this as the one pattern every binding uses.
- F5 (0086): Add fixtures for two things. First, `Relate::from_json` with `"either":true` on two kinds equals the `both_ways` builder, including the digest. Second, `Recognize` and `Relate` report `from_json` as `Usage` and `load` as `Local`.
- F6 (0095, Q15): `default_engine` may be built in the PostgreSQL postmaster through shared preload, and a child then inherits it. Say "built lazily in the child, or inherited and rebuilt by 0078's guard".
- F7 (0095, G8): `rank`, `find`, and `filter` have no JSON method, so each JSON door writes that JSON itself. Say so, or narrow "no second serializer". Record mode (`"input"`) also stays with the command.
- F8 (0095 and 0086): Branch ADR 0041 is not on main. Add "0041 ported to main" to 0086's start conditions. Also define which call wins when a later deadline call follows an earlier one, and whether `-1` clears an earlier deadline.
- F9 (main): Correct the port guide's "Python, with pandas" row to Polars.
- F10 (ADR 0047): Item 5 says "cache coordination" holds per copy. `cache_lock.rs` uses `File::lock`, which is flock on Linux and macOS. Those locks already coordinate across copies in one process, so drop "cache coordination". "Use `CallOptions::interrupt`" contradicts 0095's "worker pattern stays legal", so change "use" to "may use". ADR 0037 declares `unsigned long deadline_ms`, while ADR 0041 and `deadline_millis` use a signed 64-bit value. 0094 records which one the header uses.
