On key success with zero limit it re-observes the folder and stop state before returning the existing `SendBudgetFirst` when the folder remains unbound empty. If a writer appeared, the unchanged gate and lookup decide a hit or mismatch; a live permit is cancelled before the zero-limit denial. The final HTTP `reserve_send` still controls every attempted send. No positive-limit precheck or reservation was added.

The new public default-cache case runs in an isolated child environment at two folder states: absent and present-empty. Each first call returned `Usage` with `Some(BeforeFirstSend)`, counted zero listener requests, and observed an absent path or the same empty folder before any second call. A second address then bound the folder and sent exactly once; its repeated answer at zero budget returned one cache answer and zero sends. A companion table proved an already bound wrong address, a legacy final entry, and a malformed marker keep their local refusal rather than becoming budget errors. It asserted the malformed marker text never appears in the error. A private request test invoked a competing writer inside the outer key closure: a same-address complete answer replayed and a different-address marker refused, with only the winning writer's one send closure reached.

## What the build taught us

Placing a local budget check at writable preparation is too late: even a certain zero limit then leaves marker and lock artifacts. The existing early-key path is the useful seam because it can refuse before the folder gate without making cache hits depend on a send budget. The second observation matters because the key closure can run long enough for another writer to publish a useful answer. Strict lint caught a real readability regression in the first implementation and led to one small private extraction, rather than another state machine.
