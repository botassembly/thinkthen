## Current source and archive routes

`release-pack` stages one fresh C archive with `part_c`, adjacent SHA-256 through `pack`, remapped builder paths, and a source commit from `git rev-parse HEAD`. Existing Go/C++ and C#/JVM parts require clean committed source, non-reuse mode and `c` in the same invocation; `c_built` prevents a stale OUT file from satisfying that requirement. Swift/Zig are absent from its parts and default list. `release-go-cpp-pair` has literal Go/C++ and C#/JVM modes; each selects three archives, rejects extra selected-family names, checks six archive/sidecar files and compares strict five-line manifests with actual C bytes. `release-smoke` calls those modes before `backend_start`, routes their exact archive names before the broad command pattern, and still requires nine older families for a full pass. Add one literal Swift/Zig mode and the corresponding two dispatch patterns; no new validator or changed default is needed. `installed.sh` supplies fresh scratch/unpack helpers, and smoke treats exit 77 as a failure.

SwiftPM declares `ThinkThen`, `ThinkThenExample` and `ThinkThenTypeCase` in `Package.swift`. Its current local archive helper lists eight source files: `LICENSE`, `README.md`, `Package.swift`, `Examples/main.swift`, `Sources/CThinkThen/module.modulemap`, the vendored `include/thinkthen.h`, `Sources/ThinkThen/ThinkThen.swift`, and `Tests/TypeCase/main.swift`. The declared type-case target explains the test source in a complete source package. The helper currently writes a checkout-derived ZIP and a debug C tar inside `target/artifacts`; neither is a release archive. Zig's `build.zig.zon` allows `build.zig`, `build.zig.zon`, `src`, `examples`, `README.md`, `LICENSE`; its local tar helper names exactly those six source files and a debug C tar. `build.zig` accepts an absolute unpacked native directory through `-Dnative` and validates the header version/layout and selected library. These helpers and source gates establish useful local behavior but cannot supply a clean-commit release/C digest manifest by themselves.

Both `check.sh` scripts currently build debug C from the checkout in normal source mode. Swift copies it to `target/native` then compiles package and fixture sources from `libraries/swift`; Zig copies it to its own `target/native` and builds from `libraries/zig`. They run their original J1, 30/42-body, cancellation, privacy and isolated-local cases. Preserve that route. Their new `THINKTHEN_FOCUSED=portable-batch` paths bypass the debug build when given `THINKTHEN_NATIVE_ROOT`, but Swift's Python runner still compiles `Sources/ThinkThen/ThinkThen.swift` and module map from checkout, while Zig's `Tests/build.zig.zon` resolves `.path = "../"` to the checkout package. Merely passing an unpacked C root would therefore be false installed wrapper proof. In installed mode, first build the unpacked SwiftPM package with its declared targets and the unpacked C prefix, then pass that package root to the existing typed runner; for Zig, copy the test-owned fixture project into fresh scratch and set its local package dependency to the unpacked Zig root, as the accepted source `Tests/installed.py` already does. Test-authored fixture source and corpus may stay in the checkout, but every product compilation input must come from the archive. Keep isolated build/cache output outside the package and compare the Swift vendored header to the unpacked C header. The Zig build already checks the C header version, not export completeness; the installed selector must also run the existing header-derived shared export check and compare loaded native bytes with archive members.

`portable_batch.py` for both hosts already starts the repository's counted conformance backend, invokes the typed public bulk call on five accepted texts, compares the raw UTF-8 capture multiset to three independent literal request files and requires three sends. The Swift `@main` fixture and Zig test-owned `portable_batch.zig` can be reused unchanged. The five equal answers do not prove output permutation; accepted mixed-answer host tests do. The typed APIs do not return row digests, so [0260's C-door oracle](0260-portable-batch-identity-build.md) is the direct digest proof. This is the smallest installed call that proves the archive wrappers' actual text conversion and native link without another scalar test or the retained 30/42-body matrices.

## Input provenance, refusal and tool boundary

The package builder must run from one clean commit and rebuild C in the same invocation. The C archive includes engine dependencies outside `libraries/c`, so matching header bytes or file timestamps alone cannot establish source identity. Record the exact source SHA, target/version, command, Swift/Zig tool paths and versions, C header/shared/static member hashes and all outer hashes. The wrapper manifests bind C file bytes and agree on source SHA; they are fixed data, not attestation. A later checkout HEAD may differ from an older valid package. Inspect exact wrapper member lists and the Zig `.zon` package version after unpacking, and keep build output out of each wrapper archive. Compare installed native bytes with the verified C archive rather than to another copy of themselves.

The direct three-file baseline needs the existing pair helper's Swift/Zig mode, then two installed selectors. A full `release-smoke` on only those three files fails the unchanged nine-family requirement, so test actual smoke integration with a missing-file plant that reaches the preflight before backend startup. Other focused plants corrupt Zig without changing its sidecar, substitute a separately valid differently hashed C file and sidecar, and add another Swift family name. Require distinct missing/checksum/C-identity/extra diagnostics before any consumer starts. These are file-boundary proofs, not measured zero network sends unless a listener runs. In a full bundle the preflight must ignore other wrapper families while policing Swift/Zig/C exactly.

## Design scope and remaining issue boundary

The proposed executable claim is only `sdlc/scripts/{release-pack,release-go-cpp-pair,release-smoke}`, `libraries/{swift,zig}/check.sh`, their existing portable runners and minimal test-project path support, relevant README, exact derived ratchets and ticket/build records. No native/engine or wrapper product source/API, `installed.sh`, other adapter, workflow, registry or site change follows from this audit. The original issues still need a final release pin, actual `ubuntu-24.04` Actions build/release, checked public assets and direct installation; Swift also needs macOS consumer proof, and Zig needs another host. A local source archive and Linux loopback result cannot close those criteria.
