The conformance backend's listener is the send-count authority: count exact received body bytes/multiset for real calls, including cache/replay behavior; a plan's planned-request count comes from its independent prepared-body fixture before cache/splits/retries. A `--plan` document alone does not prove zero sends. P1's literal and 120-byte length are independent static expectations; no SQL host has run it yet. An empty output is not a failure-code proof: pin exit status and sentence. `specification/fixtures/examples/` holds **one** shared corpus, while each host checks conversion and installed artifact. Source-matched packages, copied installed consumers and final release/runner artifacts have distinct receipt meanings.

The saved spike branches/logs under experiment 2038 (`probes/sqlite-batching-and-cache-bc.out`, `sqlite-json-parse-cost.out`, `sqlite-keyed-join.out`, `pg-named-args.out`, `pgrx-argument-names.out`, `duckdb-macro-named-args.out`, `duckdb-macro-registration.out`, and functional Polars probe outputs) support design choices; they are not current build passes. The 100,000 distinct-record baseline in ADR0105 is 154 requests, 0.61 seconds and 15 MB RSS on its pinned loopback setup; preserve it as a measured baseline, not a promised universal performance bound. Routine checks use bounded functional witnesses. Opt-in stress uses `test-stress --run`, with host load and churn recorded separately.
