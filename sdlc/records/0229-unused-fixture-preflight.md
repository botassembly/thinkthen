# 0229 unused-fixture preflight

Status: proposed design at main `e182b546`; no runtime, specification, site or accepted-decision file changed and no build ran. `experiments/284-issue-register/107-no-way-to-find-unused-fixtures.md` asks for a folder report after a complete fixture run. The original architect [issue](../issues/2026-09-26-architect-review-09-record-replay-testing.md) lists the missing tool. A full run's stale entries cannot be inferred from modification times: `specification/recording.md:107` says hits do not refresh them.

Current `specification/recording.md:97` promises that each detailed result's `meta.requests` contains the digest naming the requested entry. `core/result.rs` stores those digests; `engine/cache_prune/scan.rs:84-150` already validates final names against parsed entry bytes and refuses symlink or identity changes. `engine/cache_lock.rs:28-34` gives a shared lock on the existing directory without creating a lock file. `cache prune --dry-run` is read-only but selects by age, model and size, not usage (`cli/cache.rs:12-58`, `engine/cache_prune.rs:138-181`). There is no per-entry access journal or `cache unused` command (`cli/args/command.rs:278-309`). The gap is real.

A one-command replay with `--details` can provide a complete manifest for **that one command**, as in demo 27. A whole suite's ordinary saved outputs cannot: `tests/backend/keeping.rs:262-287` proves `filter --details` prints only kept records although dropped records were judged, and bare or quiet results carry no printed `meta.requests`. Recognition may make later requests after its first stage. A suite runner must supply a complete list of every digest it actually used. This ticket does not claim to derive that list from arbitrary outputs or an expected fixture inventory. The copied Beatles Bench under `site/examples/beatles/bench` is not the upstream suite runner, so site files cannot establish that bench's completeness or retention policy here.

## Smallest boundary

Propose `thinkthen cache unused DIR --used DIGESTS`, where DIGESTS is a UTF-8 file with one 64-character lowercase hexadecimal request digest per line. Blank lines and duplicates are harmless; any other nonblank line is a usage refusal before the folder is opened. `DIR` is explicit. The command uses a shared directory gate and the existing safe final-entry scanner. It reports valid final entry names absent from the supplied set, in lexical order, and a total. It does not label unknown names, temporary files or bad digest-named objects as unused. Bad digest-named objects cause the existing generic local entry refusal with no partial success report, so a damaged folder cannot print a misleading clean result. Extra manifest digests are not a missing-fixture claim: they may belong to another folder, and the caller must still certify the manifest is complete for this folder. No deletion, marker creation, `.locks` creation, directory sync, provider call, key lookup, default-cache resolution or usage-ledger access belongs to this command. Its shared lock excludes cooperating prune while it scans; an external noncooperating writer can still race, as the current prune contract says.

Prospective source inventory after a runtime claim: `cli/args/command.rs` (404 nonblank lines) for the subcommand and arguments; `cli/args.rs` for re-export; `cli/mod.rs` for dispatch; `cli/cache.rs` (151) for manifest parsing and output; `engine/cache_prune.rs` (440) for one gated comparison using its existing scanner, with a private child only if the measured parent would exceed 500; `tests/backend/default_cache.rs` (350) and a small `default_cache/unused.rs` child for outside-in proof; `specification/recording.md` and `settings.md` for the additive read-only interface; ratchet and build/review records. `engine/cache_prune/scan.rs` (187), `engine/cache_lock.rs`, request/facade/public accounting and site files are read-only evidence unless review proves a necessary seam. This avoids 0212's held engine/public paths and a second entry parser. These are **prospective holds**, not current edit permission.

The focused proof copies two known valid entries into a scratch unmarked replay folder, captures fixed expected digest names independently from the tool's report, and runs one exact `decide --details --replay` for only one entry with no key. It extracts that result's one `meta.requests` digest into DIGESTS, asserts it equals the independently pinned used name, then expects exactly the other entry from `cache unused`. A duplicate manifest line leaves the result unchanged; an invalid line refuses before folder access. A bad digest-named sibling refuses without declaring all clean. Snapshot names and bytes, file type, mode and modification times before/after; do not assert access time. Assert no marker, `.locks`, default-cache folder, request send or usage file appears. Reuse existing replay/prune fixture helpers where they preserve these independent expectations; no new test-only product hook. This proves a complete **one-run** manifest route and read-only comparison, not suite-wide coverage. Focused format, strict affected Clippy, ratchet, pages/tickets/diff follow source work. No provider, whole suite or stress run.

## Contract and preparation lesson

`specification/recording.md:107` and ADR 0017 section 5 reserve `cache prune DIR` as the only **removal** surface. A read-only unused report preserves that rule and the explicit-folder policy. Ticket 0208 already established a read-only cache-maintenance preview, but it does not authorize this new public command by itself. The proposed wording adds a separate read-only report, not a new eviction policy, marker format or replay identity. The coordinator should route the outward syntax through fresh design review and decide whether Ian or a new ADR is required before runtime; this preparation reserves no ADR number.

What preparation taught us: `meta.requests` is an exact request identity where it is emitted, but output retention is not usage retention. A dropped filter row is the counterexample to treating saved result rows as a universal access journal. The design therefore accepts a manifest only from a caller that owns the whole run and proves its completeness, and it keeps the external bench integration and any automatic deletion separate. The scanner's existing safe open and shared gate are reusable; a lexical filename-only diff would bypass accepted bad-entry and symlink protection. A no-write claim must include directory names and stable metadata after the command, not only unchanged entry bytes.
