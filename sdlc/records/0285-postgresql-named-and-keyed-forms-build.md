# 0285 PostgreSQL named and keyed forms build

Status: Work in progress on the ticket branch. The selected source-matched package check below is not full installed-host or release qualification.

The first slice replaced the scalar judgment registrations with pgrx `DEFAULT NULL` named parameters, added jsonb keyed many rows and a native jsonb plan, and kept PostgreSQL's raw `json` bytes for duplicate-aware shared settings parsing. It moved old array, context and warm implementation out of the compiled extension and retained plain Usage refusals where their old signatures are distinct. The engine's existing `SendBudget` reserves actual sends; the host no longer pre-refuses a call solely because its total is spent, which allows a send-free cache answer. A nonempty interactive `thinkthen.api_key` assignment now warns without entering the engine key path. The server statement helper sets `statement_timeout='30s'` before each selected query.

Source proof so far: offline four-job Clippy passed; pgrx 0.17.0 built a PostgreSQL 16.15 package from matching headers. The staged library matched the just-built module byte for byte (`495166ec054ec92063204c5729b7e1f5efa9afcefcf38d957c493d489999dc93`). Generated SQL named `input`, all optional defaults and native `json`/`jsonb` types. An owned server and loopback backend loaded the staged archive; the selected `plan_and_named` case passed with `1 passed, 0 failed`. It pinned P1's literal 120-byte body, 61–109 token band and zero sends; unknown and repeated settings keys and named/settings threshold collision also sent zero. A named threshold call sent one request; a two-key jsonb table returned both keys and one independently written exact packed body in one request. This is selected source/package proof, not a full package gate.

The prior array and warm implementation modules and their internal tests were removed because those entry points are retired. The new installed-host cases replace their input packing and one-send witness; retained cancellation, file, privacy and failure checks still need migration to the new signatures before final review. The prepared 0283/0289 dependency language was stale at build launch; both public APIs were on main. The pgrx raw JSON datum bridge was required because `Json` decodes into `serde_json::Value` and erases duplicate names before the shared parser can reject them.

The current measured Rust total is 2649 nonblank lines, up 39 from the starting 2610 after removing the obsolete array/context/warm source and extracting the new scalar/forms/keyed paths; the largest live source file remains under 500. I checked the existing `Given`, `Call` and public `Settings`/`Engine::plan_with` paths before adding a narrow raw-datum bridge. The Python total remains 633; the statement-timeout additions replace existing launcher command construction.

## What the build taught us

PostgreSQL function defaults and generated argument names work through pgrx 0.17 on the pinned host. A `jsonb` input has already normalized duplicate keys, while the `json` settings datum retains them only through the raw byte reader. A selected compiled case is valuable early, but the old check script still carries retired array and warm expectations; those must be reconciled without discarding unrelated cancellation, privacy or file proofs. Later work must preserve native plan, positive cap, warning source classification, copied consumers and grants together.
