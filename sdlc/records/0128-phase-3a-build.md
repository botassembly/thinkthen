Status: candidate on `ticket/0128-release-workflow-phase-3a`, begun from main `0e46f68d` and merged with main `0759bb46`. This record covers local implementation and focused proof only. No workflow was dispatched, release drafted, tag pushed, registry contacted, or package published. Fresh read-only release-safety review and the Phase 3b four-runner rehearsal remain.

## Resulting route

`.github/workflows/release.yml` has only `workflow_dispatch` with `rehearse` and `release` modes. `resolve` checks one commit and the version. Four native target builds feed wheel, gem, npm and crate aggregation, then four installed smoke jobs. Only after smoke may the workflow create a draft. Registry, tap and final-publication jobs require release mode and the `release` environment. Each checks that environment's `RELEASE_ARMED=true` variable as its first step, before checkout, download, or outward work. The six outward jobs remain gated separately. A fresh release review caught the earlier job-level `if` on this environment variable: GitHub evaluates it before the job starts, so the intended jobs would skip. The first-step guard fixes that timing without weakening dispatch or approval. `sdlc/scripts/release-workflow` holds the local job operations; `sdlc/scripts/workflows` checks the graph, permissions, inputs and pinned actions.

Tracing the existing `release-smoke` into its installed checks corrected an initial setup miss before dispatch. Python's installed check requires Python 3.12 or later, `uv`, `maturin`, `sha256sum`, and a populated cache for its hash-pinned `requirements-dev.txt`; Python 3.10 alone only builds the abi3 wheel. Build jobs now keep Python 3.10, while smoke jobs select Python 3.12, install pinned `maturin` 1.15.0 and `uv` 0.9.17, seed the exact requirements with hash checking, and install GNU coreutils on macOS for that check's current `sha256sum` call. The RubyGems publish job selects Ruby 3.4.11 through a SHA-pinned action and asserts RubyGems 3.6.9. This is workflow preparation, not proof those packages run on every target.

The Linux ARM64 route uses the official digest-pinned `manylinux_2_28_aarch64` image, native Rust target, Node 22.22.3 arm64 archive, maturin and libclang wheels, and PGDG 16.15 ARM RPMs. The x86-64 route retains its existing image and pins. Both routes now build Ruby 3.4.11 from `libraries/ruby/toolchain.env` inside the target image. The inspected official `rbsys/x86_64-linux:0.9.130` image had Ruby 3.1.7 and 4.0.2 but no 3.4, and glibc 2.31; it could not satisfy the accepted ABI and glibc floor. The pinned manylinux image has `openssl-libs-1.1.1k-17.el8_6` but no headers. `release-container` now checks that exact installed RPM, verifies the matching AlmaLinux `openssl-devel` RPM against the official [ALSA-2026:38503 hashes](https://errata.almalinux.org/8/ALSA-2026-38503.html), and unpacks its headers and linker names as the calling user. That RPM is a Ruby build input, not a library bundled in the gem. The full installed-artifact smoke must still prove no undeclared runtime dependency.

On macOS, `databases/postgresql/runtime.sh`, `check.sh` and `package.sh` select the pinned Homebrew PostgreSQL 16.15 keg, refuse missing or mismatched toolchains before building, and start a temporary no-TCP cluster with the loopback key. The [official Homebrew formula API](https://formulae.brew.sh/api/formula/postgresql@16.json) lists the arm64 Sequoia bottle and the x86 Sonoma bottle selected for Intel Sequoia; the runner must still establish that fallback and its dependencies. `libraries/ruby/setup-ruby.sh` builds the SHA-pinned Ruby 3.4.11 source for each Mac chip against OpenSSL 3.6.4 with deployment target 15.0. `check.sh` selects only that stamped prefix. The official isolated Rust 1.95 sysroot is required because the M5's Homebrew Rust standard library advertised a macOS 26 minimum. SDK selection, deployment target and Rust sysroot are checked separately.

The native M5 Ruby build exposed two packaging defects: `build.sh` exported path-remapping `RUSTFLAGS`, which replaced `.cargo/config.toml`'s Darwin dynamic-lookup flags and made `_rb_*` symbols fail at link; then Rust gave the copied extension an absolute builder-path `LC_ID_DYLIB`. `build.sh` now carries the lookup flag alongside remapping and gives the packaged extension `@rpath/thinkthen.bundle` as its install name. The direct build route, not just the release workflow, gets the correction. The M5's Zerobrew OpenSSL had an invalid local install name; a local `install_name_tool` repair of the isolated test Ruby's `openssl.bundle` enabled this host probe. GitHub's Homebrew host route has not been inferred from that local repair.

## Focused evidence

- After the environment-gate correction, `workflows --self-test` passed 17/17 planted cases, including missing and late guards. Plain `workflows`, shell syntax checks and `git diff --check` passed.
- `crate-smoke` installs the unpacked crate with `--offline` and runs its replay binary under fresh `HOME` and XDG folders, a controlled `PATH`, and the inherited linker search values. A fake packed-crate fixture with contaminated parent `THINKTHEN_CACHE`, key, base URL, batch and `HOME` passed: the child saw none of those settings, saw the fresh paths, and read the absolute replay folder. This proves isolation, not a four-runner native crate install.
- Local `resolve rehearse refs/heads/main` emitted the current SHA and rehearsal name. Release-mode resolution from a branch refused; release-mode resolution from a tag name and `versions --tag` succeeded. Missing Darwin PostgreSQL and Ruby prefixes returned 77 before a build, both with fake `uname` and on the actual M5.
- A local four-platform fixture exercised `npm-assemble` and `verify-family`: the aggregate tarball held all four distinct `.node` files. `cargo package --locked --offline --package thinkthen --list` passed. These are assembly checks, not four native packages.
- The TypeScript installed check originally named its Linux x64-only Node folder on every host, so setup-node alone could not pass Mac/ARM smoke. Its one-file installed-mode correction retains that folder for Linux x64, otherwise selects native Node v22.22.3 on PATH and compares `process.platform`/`process.arch` with the actual host target. The source-mode gate and `setup-toolchain.sh` are unchanged. Focused PATH shims produced 77 for missing Node, failure for v99.0.0, and failure for a v22.22.3 binary that reported Linux x64 on a simulated Darwin arm64 host. Native installed conformance still awaits the runners.
- Reviewed 0231 now routes Apple Silicon DuckDB packaging through the C++ path, while its Linux ARM64 and macOS Intel C API fallbacks remain. `release-workflow smoke-bundle` refuses either old archive before installed smoke or draft by requiring the C++ package's distinct license, notice and dependency files. A local old/new archive fixture failed/passed that boundary. This is a routing guard, not a substitute for the remaining 0231 native implementation and proof.
- On M5 arm64 with official isolated Rust 1.95, the Ruby 3.4.11 toolchain built with Mach-O minimum 15.0. The corrected `build.sh` compiled the native extension and built `thinkthen-0.0.1-arm64-darwin-25.gem`. A fresh gem folder installed it; `require "thinkthen"` loaded `thinkthen.bundle` from that folder and reported `ThinkThen::VERSION == "0.0.1"`. `otool -L` on the bundled extension listed its relative ID and only system libraries. Raw-byte searches of the extension and gem found no `/Users/ian`, `/opt/zerobrew`, or `/Library/Developer` path. This proves the current M5 host path, not macOS 15 or the eventual version 0.1.0.
- A user-owned x86-64 probe inside the digest-pinned manylinux image verified the exact AlmaLinux RPM hash, built Ruby 3.4.11 with its OpenSSL extension, and loaded Psych, zlib, OpenSSL and Minitest. It reported `OpenSSL 1.1.1k FIPS`. `readelf -d` on that **build toolchain's** `openssl.so` lists `libssl.so.1.1`, `libcrypto.so.1.1` and a `/home/openssl/usr/lib64` runpath. That Ruby binary is not packaged; the Phase 3b installed gem check must still prove that no such local runpath or undeclared library enters the final native extension. The official ARM image, macOS Intel, macOS PostgreSQL load, four-runner smoke, draft and publication have not run.

## Boundaries for the next phase

Phase 3a cannot claim release readiness from static checks or M5 source compilation. The first Ian-dispatched Phase 3b rehearsal must build every target from the same resolved SHA, hash each artifact, inspect exact target/ABI/minimum OS and raw bytes, install each package into a fresh prefix, run every surface with zero not-run, and prove the packed crate and no-key first run. Native DuckDB 0231 and SQLite 0232 remain separately owned and unreviewed here; their results must be integrated without replacing their accepted package criteria. In particular, the macOS 15 runner must load the intended DuckDB C++ and SQLite packages and the Homebrew PostgreSQL bottle. The ARM runner must demonstrate the entire native package graph.

The original Phase 2/3 line estimates were written before ARM plumbing, OpenSSL header discovery and native host-route correction. `release-container` and Ruby setup now exceed their old estimates; this record rescores them against the retained four-target proof rather than reducing outcomes. The installed smoke and final release rules stay unchanged. Local `publish = false` never established crate registry state: the [crates.io API](https://crates.io/api/v1/crates/thinkthen) and [sparse index](https://index.crates.io/th/in/thinkthen) show 0.0.1 already exists. Phase 4 needs the real owner's trusted-publisher configuration, not a new-crate bootstrap.
