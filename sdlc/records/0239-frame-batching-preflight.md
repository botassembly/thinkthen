# 0239 frame batching preflight

Status: Prepared from main `299df9ef` for independent design review. Read-only source inventory and one earlier offline observation are in the [accepted audit](2026-09-28-frame-batching-completion-audit.md). This record grants no runtime claim and counts neither B13 row done.

## Source and accepted boundary

`crates/thinkthen/src/public/frame.rs` has five `PolarsEngine` entries returning bare `Series`/`DataFrame`. `decide_series` collects `Engine::decide_many_with`; `single` and `annotate_frame` collect `Engine::annotate_with`. All consume the same 0212/0216 planners, so a missing Polars-specific host selector does not mean a missing packer. Current collectors lose `Batch::facts()` after success. `crates/thinkthen/src/public/results/call.rs` already exposes crate-private `Call::new`, `map`, and `try_map`; `try_map` attaches its facts to an `Error` using crate-private `Error::with_facts`. `Batch::facts()` is available after exhaustion or its terminal error, and the terminal error already carries frozen joined facts. A local collector returning `Call<Vec<_>>` is sufficient; no new public `Facts` or `Call` constructor is justified. Collect before converting, keep the batch alive through the final account read, and attach that account to any returned conversion error. A Rust `Call` covers one column/frame invocation even when the planner starts multiple HTTP requests. No R-style aggregation of several independent core calls exists in this path. There is no detached Rust host worker receipt to copy from R or Python.

The existing Rust `column::texts` rejects nontext and null before a request. `annotate_frame` rejects missing `on`, reserved/colliding names and nontext/null before collection. `QuestionSetBuilder` rejects profiled choose/score/tag members under reviewed 0203; `decide_series` accepts a saved decide profile and 0203's case pins its digest and warning. For ordinary questions, `CallOptions` reaches `selected_batch`: typed, engine/environment, saved decide file, Max. A runtime backend profile still applies size/question limits. `annotate_with` rejects context; `decide_many_with` permits eligible context. For the result, 0209's `frame/column.rs` already writes fixed types and nested `failed` cells and `hstack` keeps input columns. Empty columns currently return typed empty values and no request, but not a facts-bearing carrier. Preserve the original input; no NA dropping or index rewriting belongs in Rust Polars. On Python pandas, `__init__.py::_column` and `annotate` rebuild with the original index, and `src/frame.rs` keeps `Completed` through Arrow/pandas conversion. A null input is a zero-send Usage refusal; no row is silently removed. The existing JSON question/description grammar stays native and closed; distinguish absent metadata from present null exactly as 0233 corrected it.

## Preparation risks to review

The accepted `Call` constructor is crate-private and already usable from `public/frame.rs`, so no public API beyond the five necessary return signatures is proposed. The conversion-error path is currently difficult to trigger through valid public inputs; requiring a synthetic failure would weaken the outside-in proof. Review the source transition and any reachable real case instead. Verify the existing observer fires on the caller thread after the helper collects, and does not gain a second history. Check copied examples before claiming all consumers compile. Keep the saved-profile member refusal and Python null-input behavior visible beside default-Max packing, so a green request-count case cannot hide a grammar or validation regression. A fresh design review and then independent code/API review are required before either B13 row closes.
