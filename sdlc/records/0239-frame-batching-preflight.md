## Source and accepted boundary

`crates/thinkthen/src/public/frame.rs` has five `PolarsEngine` entries returning bare `Series`/`DataFrame`. `decide_series` collects `Engine::decide_many_with`; `single` and `annotate_frame` collect `Engine::annotate_with`. All consume the same 0212/0216 planners, so a missing Polars-specific host selector does not mean a missing packer. Current collectors lose `Batch::facts()` after success. `crates/thinkthen/src/public/results/call.rs` already exposes crate-private `Call::new`, `map`, and `try_map`; `try_map` attaches its facts to an `Error` using crate-private `Error::with_facts`. `Batch::facts()` is available after exhaustion or its terminal error, and the terminal error already carries frozen joined facts. A local collector returning `Call<Vec<_>>` is sufficient; no new public `Facts` or `Call` constructor is justified. Collect before converting, keep the batch alive through the final account read, and attach that account to any returned conversion error. A Rust `Call` covers one column/frame invocation even when the planner starts multiple HTTP requests. No R-style aggregation of several independent core calls exists in this path. There is no detached Rust host worker receipt to copy from R or Python.

The reviewer found one real shared selector omission: `core/question_set.rs::parse` stores the top-level `batch` JSON without eagerly rejecting an invalid value, and its `batch()` accessor exposes it. `public/bulk.rs::selected_batch` already gives single questions typed option > engine > saved question > Max, validating the saved value only if selected. But `annotate_with` currently chooses only typed option > engine > Max. Both Rust `annotate_frame` and Python pandas `annotate(on=...)` inherit that missing tier. The smallest shared fix is in `public/bulk.rs::annotate_with`, using `questions.0.batch()` and `core::Setting::of_json` after typed/engine selection; a selected invalid set value becomes `Error::refused(core::QuestionSetError::Shape { path: "batch", wanted: "takes max or a whole number of at least 1" })` before a send. An invalid saved value under a valid typed or engine override remains unselected and must not be rejected. `cli/annotate.rs::batch_setting` and `tests/backend/annotate/batching/tiers.rs` already pin that exact selected/overridden distinction on the command; reuse its core accessor and spelling, not its CLI parser or a new JSON parser. The closest public API integration home is `crates/thinkthen/tests/public_batches/contracts.rs`, beside its existing annotation cases. A separate host selector would leave list annotate wrong, so fix the public entry once.

The existing Rust `column::texts` rejects nontext and null before a request. `annotate_frame` rejects missing `on`, reserved/colliding names and nontext/null before collection. `QuestionSetBuilder` rejects profiled choose/score/tag members under reviewed 0203; `decide_series` accepts a saved decide profile and 0203's case pins its digest and warning. For ordinary questions, `CallOptions` reaches `selected_batch`: typed, engine/environment, saved decide file, Max. After the shared fix, annotate follows the same tiers using the set's top-level batch. A runtime backend profile still applies size/question limits. `annotate_with` rejects context; `decide_many_with` permits eligible context. For the result, 0209's `frame/column.rs` already writes fixed types and nested `failed` cells and `hstack` keeps input columns. Empty columns currently return typed empty values and no request, but not a facts-bearing carrier. Preserve the original input; no NA dropping or index rewriting belongs in Rust Polars. On Python pandas, `__init__.py::_column` and `annotate` rebuild with the original index, and `src/frame.rs` keeps `Completed` through Arrow/pandas conversion. A null input is a zero-send Usage refusal; no row is silently removed. The existing JSON question/description grammar stays native and closed; distinguish absent metadata from present null exactly as 0233 corrected it.
