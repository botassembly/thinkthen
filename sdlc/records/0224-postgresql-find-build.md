## Change and retained boundaries

`databases/postgresql/src/find.rs` validates an ordered `text[]` without sorting, deduplicating or discarding NULL members. It carries each original index in a private `IndexedEvidence`, constructs a plain `Question::find` and optional `offering_none`, calls public `Engine::find_with` once in the established `call::run` worker, and maps the completed `Found` to JSONB. A selected none has null index/value and its own probability; every candidate remains in input order. Top-level SQL NULL and an empty array return SQL NULL before settings or transport. Invalid unit count, NULL member, blank text and combined text over 16 MiB raise Usage before a send; PostgreSQL rejects wrong SQL types at binding. Find uses the existing backend GUC snapshot, one deadline, cancellation polling, atomic send budget, SQLSTATE mapping, cache and recording authority. It adds no parser, context slot, scalar deadline or public Rust API. `lib.rs` registers the two parallel-restricted overloads. README, the runnable examples inventory and the PostgreSQL settings cells describe their actual contract.

`runtime.sh::bcapture` reads the existing backend's bounded JSON body capture. `tests/runner.py` routes only literal `18-find-second` and `19-find-none` to `/capture/v1`, compares the complete observed body to the independent corpus body, computes the recording digest from the **observed body plus actual served URL**, compares it to a separate corpus-body/served-URL digest, and checks one listener send and the full typed result. This is distinct from a raw body SHA. `tests/find_cases.py` reuses SQLite's existing counted `ConditionalBackend` for duplicate-second, first-real tie, none tie, 255-unit and 254-unit-with-none results. Its installed invalid table checks SQL NULL/empty, one or excess units, NULL/blank member, blank question, >16 MiB text, wrong SQL type, deadline zero and spent request total with zero listener sends. Existing held-call PostgreSQL helpers check statement cancellation after one admitted find send. `check.sh` registers these cases in its installed-artifact route; no test-only product hook or new HTTP server was added.

## What the build taught us

The established `call::run` and public `Found` path supported PostgreSQL without another scheduler or accessor. The crucial host distinction was validating the full array before entering that worker, because the decision array intentionally drops or deduplicates members. The generated package and actual installed role/grant check proved both overloads, which a successful Rust compile alone would miss. The shared capture selector can safely include numeric ID 18 because only an explicit capture route records bodies; the PostgreSQL runner still names full find IDs to avoid confusing annotation case 18. An inherited `sccache` execution fault required a wrapper-free retry, while the unchanged code passed both source-loaded and archive-loaded checks. Fresh review should inspect pgrx NULL ownership, private index mapping, result publication after completion, and the actual captured-body/digest path. Other SQL hosts and scalar throughput remain separate.
