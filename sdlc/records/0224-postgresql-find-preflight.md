## Current source and exact prospective claim

`databases/postgresql/src/lib.rs` registers pgrx functions, reads GUCs on the backend thread through `call::read`, and runs owned inputs through `call::run` on one detachable worker. `src/array.rs` packs distinct evidence in first-occurrence order for decisions. Find must not use that deduplication: its duplicate strings are separate indexed candidates. `src/warm.rs` also merges distinct pairs and cannot preserve find positions. `src/lib.rs::question` takes the question-file grammar and drops NULL array members for other verbs; find instead constructs `Question::find` from literal text, treats `@` literally, and rejects any NULL unit. `Question::from_json` cannot parse find. Current public `Engine::find_with` returns `Call<Found<T>>`; `into_value`, `Found::selected`, `Found::candidates`, and `Candidate::{input,probability}` provide the answer. `Evidence` only requires `evidence(&self) -> &str`, so a private `IndexedEvidence { index, text }` in a new `src/find.rs` can retain every original position without a public Rust change.

Root's exact prospective PostgreSQL runtime claim is `databases/postgresql/src/{lib,find}.rs`, `databases/postgresql/tests/runner.py`, `databases/postgresql/runtime.sh`, `databases/postgresql/check.sh`, `databases/postgresql/README.md`, `databases/postgresql/examples.json`, `databases/postgresql/{ratchet.json,ratchet.py.json}`, the PostgreSQL cells in `specification/settings.md`, and this record plus `sdlc/records/0224-postgresql-find-build.md`. The examples inventory lists each installed verb and currently has no find entry. The pgrx-generated `thinkthen--*.sql` is build output staged by `databases/postgresql/package.sh`, not a tracked source edit. Its generated two- and three-argument functions and the packaged SQL must be checked. Read-only dependencies are `src/{call.rs,call/settings.rs,ffi.rs}`, the shared corpus and capture selector, public find/results, and `specification/find.md`. Request any further exact file claim from root before editing. Find consumes existing GUCs but adds no setting or per-call deadline argument.

The two `#[pg_extern(parallel_restricted)]` overloads are `thinkthen_find(question text, units text[])` and `thinkthen_find(question text, units text[], none boolean)`, each returning `jsonb`; omitted none means false. A caller constructs an ordered group with `array_agg(unit ORDER BY ordinal)`. Top-level SQL NULL in any supplied argument and a valid empty array return SQL NULL before parsing the question, reading settings, or sending. Validate every nonempty member in array order, count 2–255 units or 2–254 with none, reject a NULL member, blank question/member and combined unit UTF-8 text over 16 MiB before `call::run`. Use checked byte addition. PostgreSQL type binding rejects wrong SQL argument types; there is no JSON collection parser or find question-file form. Construct the plain find question, optionally call `offering_none`, then invoke `Engine::find_with` exactly once with owned indexed units and existing `CallOptions`. Convert the completed result to JSONB with zero-based selected `index`, original `value`, selected `probability`, and ordered `{index, probability}` candidates; offered none has null index and comes last. A selected none returns a non-NULL object with null index/value. Preserve exact original positions in equal strings and ties.

## Small installed proof

Run the installed Linux extension against only shared `18-find-second` and `19-find-none` on `/case/ID/capture/v1`. These cases have different full request bodies, 336 and 274 UTF-8 bytes in current corpus. Case 18 selects original index 1 of three at probability 0.8; case 19 selects none at 0.7 with null index/value. The shared capture selector landed at main `2f274076`; it opts in numeric IDs 18/19 as well as 42–50, but only an explicit `/capture` route records a body. PostgreSQL's runner uses literal full find IDs, so ordinary `18-annotate-two-groups` cannot be mistaken for find. `runtime.sh` already has the backend fd and `bcount()`; add a bounded `capture` reader beside it and let `tests/runner.py` route only these two cases through capture. Compare the one observed complete body byte-for-byte with `exchanges[0].request`. Derive the observed recording digest from that body and the actual served capture URL, and compare against a separate digest of the pinned corpus body and the same URL. Do not mistake a raw body SHA for the recording digest or infer transport bytes from the SQL result. Assert exactly one listener send, selected index/value/probability, every candidate probability in original order, and a distinct trailing none candidate. The runner's current `skipped()` explicitly skips find; remove only those two skips after the installed path works. The existing `check.sh::conformance` runs selected cases with a fresh server/cache/backend per arm and counts pass/fail/not-run; its installed-artifact mode includes conformance.

Use the existing installed `check.sh` loopback and SQL helpers for one compact PostgreSQL edge table: the second of equal strings wins; a real top tie keeps the first original index; a none top tie chooses none; `ARRAY[]::text[]` returns SQL NULL with zero sends; a single member, 256 members, 255 with none, a NULL member, blank question/member and over-16-MiB units raise Usage 22023 with zero sends. Include the 2/255 and 254-with-none accepted boundaries. A wrong SQL type must fail at PostgreSQL binding, not be mislabeled as a ThinkThen Usage refusal. Reuse the existing held-call cancellation and `thinkthen.deadline_ms = 0` paths for one find call each. Verify actual attempts under `thinkthen.max_requests_total`, including a refused zero total and a completed send; row count is not an attempt count. Preserve genuine backend 38000, local 58030, cancelled/deadline 57014 and defect XX000 mapping. A failed find never publishes a partial winner. Check that each generated overload is extension-owned, PUBLIC cannot execute it by default, a specific administrator grant works, and the existing grant and update path remain intact. Inspect staged `package.sh --reuse` SQL for the signatures before calling an installed result proven.

## Boundaries and lessons

The old shared preflight predates landed 0217 and lists older source counts and an array path that has since gained first-occurrence packing. That path is still wrong for find because it deduplicates. PG `call::run` already supplies one worker, one GUC deadline snapshot, cancellation polling, transport attempt budget and SQLSTATE conversion; preserve those rather than inventing a scheduler or scalar deadline slot. Its ordinary scalar paths sometimes parse a question before a NULL evidence return, but ADR 0096 explicitly requires top-level NULL short-circuit for find. Validate and own the complete set before worker creation, and publish JSON only after the worker returns. The public `Found` type already exposes the necessary candidate distribution when each private input carries its original index.

The remaining ticket requires SQLite's installed 18/19 and edge proof, PostgreSQL's installed package proof, and DuckDB's Linux C++ plus three C API platform implementations and installed checks. The SQL scalar throughput issue and other-host criteria stay open independently. No provider call, broad host matrix or stress run belongs to this preparation.
