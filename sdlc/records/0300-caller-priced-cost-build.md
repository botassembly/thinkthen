# 0300 caller-priced cost: core, CLI and C source build

Status: candidate for fresh High code review. Base was merged `origin/main` `1e493eee8` on `ticket/0300-caller-priced-call-cost`, carrying accepted [ADR 0108](../planning/adr/0108-caller-priced-call-cost.md) and the 0300 design. This record covers the first source slice only. The every-surface facts issue and the later strict-reader/typed-host batches remain open.

## Built boundary

- `core/price.rs` is the one decimal parser and checked integer cost calculation. Both caller price strings select one pair atomically; C passes through the public builder. The chosen pair is engine scoped, while CLI obtains it from the closed read-only configuration. No price variable, flag, tariff lookup or admission rule was added.
- Every eager public `Stop` attaches its engine's pair before work, including lazy bulk and native batch paths. `CallFacts` counts sent attempts and replies and latches checked token-sum validity independently. `Facts` exposes an optional six-decimal estimate; C's existing owned success and borrowed error JSON serializer copies that member without a new ABI symbol.
- CLI process facts keep a private validity latch under the same queue lock as token addition. An uncommitted token delta suppresses both printed token totals and cost; a later month-write failure after a successful process addition does not. All started attempts must have usage before cost appears. The month and retry formats remain count-only.
- The shared C constructor reader validates the closed price pair before its host conversion, and the C constructor invokes the same public setter. SQLite's unmigrated price keys explicitly fail as Usage and leave its earlier selected configuration intact; PostgreSQL and DuckDB source belongs to their own builders.
- `specification/settings.md`, `specification/result.md`, the closed facts schema, and demo 28 state the conditional priced-reader rule. Three additive declarations are independently pinned in the accepted ticket and public inventory. No old C symbol or unpriced result member changed.

## Focused proof and retained checks

- Pure parser edges: two `core::price` tests pass for ASCII grammar, maximum, zero, leading zeros, and one combined half-up round. Public loopback tests pass for the same combined round, explicit zero price, cached zero new spend, unpriced absence and pre-send Usage refusals. The arithmetic-only `Engine` bridge is pinned with literal token inputs.
- Public call loopback passes a status-then-usage retry with reported tokens but absent cost; a logical reply failure with complete usage retains priced copied facts after engine close. A native two-request call with two usage-complete replies over `u64::MAX` omits cost and tokens, and a fresh call recovers. All sends are counted at the listener.
- Compiled CLI loopback passes configured exact cost, invalid pair with zero listener requests, status retry partial usage, two complete replies whose sum overflows, and a clean next process. The priced durable-write-failure case still reports the committed process sum and cost. Existing unpriced run-facts and month-shape cases are retained.
- Source-linked C driver with AddressSanitizer passes paired constructor, owned success cost, missing/null/number/over-limit Usage refusals with no extra send, and borrowed logical-failure cost. The frozen C header and exported functions were not edited. The local SQLite release build plus its selected transactional settings fixture passes on the pinned SQLite 3.50.0 host with a fake key and local loopback. These are source fixtures, not copied installed packages or release archives.
- `cargo fmt`, focused root and C Clippy, offline policy, `pages`, `tickets`, the settings page checker, exact ratchets and `git diff --check` pass. The public API inventory checks 510 independent declarations and refuses all four mutation plants. ## Size, reuse and remaining boundary

Measured derived ceilings are root Rust `102705 → 103309`, C Rust `3858 → 3926`, SQLite Rust `2757 → 2762`, and SQLite Python `2017 → 2020`; the unchanged C source counter stays as it was. Growth buys the parser, two independent validity owners and selected loopback regressions. I checked the existing decimal/budget helpers, `Stop`, the one C facts serializer and existing public/CLI/C fixtures before adding code: no second price algorithm, copied C parser, listener framework or test-only callback was introduced. `from_env` and the existing diagnostic tests moved to child modules to keep the 500-nonblank-line ceiling; no distinct old regression was deleted.

The result is source and local-host proof only. Existing strict Ada, Objective-C and COBOL consumers reject the new priced facts key until their matching decoder batches are built; tolerant old consumers may drop it. Python/R aggregate overflow, other typed host settings/facts, installed/release source identity, real runner qualification and the rest of the facts umbrella remain separate. SQLite intentionally refuses price keys until its host migration. No provider bill is inferred from this estimate.

## What the build taught us

The parser belongs in pure core, but the C crate needs the public setter bridge; the CLI and public calls have distinct facts owners, and they must check both reply presence and exact token accumulation. Keeping price validation inside the established closed configuration and constructor readers exposed a command error-kind boundary and one unmigrated SQLite field mapper. The byte-preserving route is an optional field, not a new envelope. `Debug` needed redaction after the new optional money string was added. The existing C driver requires two fields for a facts query, so the focused borrowed-failure case supplied its unused second field rather than changing the driver. The selected demo scanner can fail on unrelated built help before it executes this page; a direct saved-recording replay is the bounded functional receipt while that help wording is owned elsewhere.
