# DuckDB bounded file admission design proposal

This proposal uses revision `ec9580145528656502244889a38a340875a214c6`. Its contract is [0470](../tickets/0470-duckdb-file-admission-bounds.md), [0503](../tickets/0503-narrow-json-session-interface.md), [0495](../tickets/0495-adopt-request-duckdb.md) and [ADR 0129](../planning/adr/0129-owned-json-sessions.md). It proposes no product code. Fresh design review must settle the shared interface additions below before an implementation developer changes ownership. The subsequent code review requires High review of unsafe ownership.

## Source evidence

`databases/duckdb/cpp/src/complete_files.cpp::CompleteFileInputs` opens authorized handles, advances each native reader and appends every descriptor to `records`. It then calls `thinkthen_cpp_complete_file_records` to rebuild one input document. `cpp/src/complete.cpp::Complete` invokes this accumulator before it resolves a saved question or calls native declaration admission. Path-byte bounds in `files_manifest.cpp` do not bound retained record content.

`bridge/src/ffi/complete/ffi.rs::complete` prepares the question, admits it through the imported `databases/sqlite/src/complete/request.rs`, constructs the configured engine and merges call settings with SQL session settings. It passes context, batch, deadline, attempts and process budget through borrowed `CallOptions`. Its detached worker receives owned values; the bridge polls the DuckDB stop callback on the calling thread. This producer cannot call the existing blocking complete export while also feeding a session.

`crates/thinkthen/src/public/request/session.rs` already provides `Engine::request_session_with_surface(Request, Surface)`, `RequestSession::try_push`, `try_push_json`, `try_read`, `finish` and `cancel`. The descriptor owns `RequestItem` and optional `SourceLocation`. `RequestSessionPush` returns the original descriptor on Full or Closed. `RequestSessionRead` returns Result, Pending or End. The JSON push variant checks capacity before decoding and retains no host range. `session_queue.rs` owns the input cell, output cell, cancellation token and terminal cells. Drop closes the receiver without joining the worker. The worker exclusively owns its engine clone and observer/sink closures. The C session exports in `libraries/c/src/ffi/session/ffi.rs` wrap these same public types.

The shared SQL executor defaults nonincremental input to `RequestFeed::eager()` and uses `with_all_filter_results()` for complete filters. `RequestFeed::session` currently fixes eager, image declaration and all-filter projection to false. `execution.rs::feed_projection` accepts all-filter projection only for composed-record feeds. `AdmittedRequest` exposes no public setter that changes these facts. These are concrete missing interfaces, although the session and queues themselves exist.

The existing reader bridge returns native `Error` diagnostics for framing, UTF-8, limits and I/O. `RequestSession::finish` only accepts `RequestReaderFailure`, whose three variants become fixed transport messages. Replacing every native reader error by InvalidInput would discard its kind and diagnostic. This proposal requires preserving native reader failures rather than accepting that loss silently.

The fresh review found a second accumulation point: `execution.rs::execute_request_sink` collects every eager row before `dispatch`. Selecting eager session input alone therefore leaves the unread-suffix defect in the native layer. Rank and rank-set reach `Engine::try_within_admission` only after this collection; find and relate also reach their bounded count and byte admission too late. The disposition is the shared 0503 execution change below. The DuckDB producer cannot repair this order with a host counter.

## Ownership and shared interface

DuckDB uses the native Rust session directly through its existing private bridge. The bridge already links the Rust library; adding a dependency on the separate C library is unnecessary. An opaque private ABI pointer identifies the existing `RequestSession` allocation. It does not identify a new session wrapper, worker, queue, engine registry or cancellation family. All operations delegate to the existing session. The bridge's existing synchronous reader owner remains separate and stays on the DuckDB calling thread.

The proposed shared addition belongs to 0503: one owned feed configuration accepted before the worker starts. The following names are proposed for review, not claims that these declarations exist:

```rust
pub struct RequestSessionFeedOptions {
    pub eager: bool,
    pub image_inputs: bool,
    pub all_filter_results: bool,
    pub record_reading: Option<RecordReading>,
}

Engine::request_session_with_feed_options(
    &self,
    request: Request,
    surface: Surface,
    feed: RequestSessionFeedOptions,
) -> Result<RequestSession, Error>
```

Existing constructors keep their current defaults and delegate to this constructor. The worker applies the owned controls to its existing `RequestFeed::session`. Shared admission validates the supported combinations before starting a worker. All-filter projection remains restricted to filter and an owned native feed; it must not become a general bypass for arbitrary borrowed feeds. Both final outcome selection and `session.rs::publish_rows` must honor the same projection. Image declaration enables the existing native route refusal before the first content read. Reuse native preparation for this refusal; do not write a DuckDB route validator or use a synthetic attachment. If synchronous native route preparation cannot be reused, 0503 must supply an explicit admitted-readiness handshake before DuckDB opens content.

The owned `RecordReading` override retains SQL's explicit `reading.context_schema`, which has no corresponding `RequestOptions` field. Parse it through the existing native `RecordReading` and declaration validators before opening files. Use this value in shared session composition instead of projecting the original in the host. Preserve SQL's precedence: supplied reading replaces the prepared fallback; omitted reading retains the fallback. Reject competing Request projection controls rather than applying both. Refactor the existing shared SQL reading parser into one reusable helper if needed; do not copy its grammar into DuckDB. No authored Request schema field or generic second semantic validator is proposed.

The second shared addition preserves a typed error produced by a native reader. Propose a Rust-only `RequestSession::finish_native_reader_error(Error) -> Result<(), Error>` that accepts only reader Usage/Local errors without invocation facts. It stores the owned error in the existing terminal-input cell and delivers it after accepted descriptors. EOF, transport failure and native reader failure use one shared finish-state comparison and precedence rule. The JSON/C transport finish retains its closed `RequestReaderFailure` grammar; foreign diagnostics cannot claim backend failure, final facts or cancellation. This addition needs the 0503 owner's review because ADR 0129 currently specifies only the transport enum. If the owner rejects it, the reviewer must approve a concrete error-preserving alternative before implementation.

The configuration and native-error finish add no queue or C handle family. They touch shared public ownership and require explicit coordinator allocation of the shared files. The same ThinkThen queue owner can accept these details within 0503's approved outcome. A shared 0503 slice should precede the DuckDB 0470 implementation. No external owner's permission is required. DuckDB must not copy `session_queue.rs` to work around either gap.

## Admit owned feeds before eager retention

For `FeedContents::Session`, remove the collection between composed-row validation and function dispatch. Detect this feed before `environment` moves into composition. Pass the fallible iterator through unchanged, including its unknown length. Keep the effective eager flag and `controls.eager_inputs = eager && sink.is_some()`. The session worker always supplies its existing sink and no release callback. Retain the other input paths' existing dispatch and retention contracts; this prerequisite does not redesign borrowed eager feeds, inline arrays or CLI release behavior. It adds no public admission API beyond the owned feed constructor above.

The owned route is queue decoding, native composition and `inline::validate_composed`, followed by the function's existing admission owner. Each function must retain the following path:

| Function | Native admission while consuming the owned feed | Execution after admission |
| --- | --- | --- |
| Decide, choose, tag, score, filter | `request::pull::dispatch` calls `complete_stream`; dynamic choose calls `dynamic_choose_stream`. Each prepares a row and its asks, then `admit_prepared_stream` calls `try_within_admission` when eager. | The existing pulled scheduler emits ordered packets. All rows and asks pass eager admission before it starts. |
| Annotate | `request::pull::dispatch` calls `annotate_stream`, which prepares each row and its member asks before `admit_prepared_stream`. | The existing annotation scheduler emits ordered packets after eager admission. |
| Rank | `request_rank_records_complete_with`, with no release callback, calls `try_rank_records_complete_with`; its `try_within_admission` consumes the fallible composed rows. | `rank_records_complete_with` performs its existing whole-set preparation and execution, then returns the aggregate. |
| Rank-set | `request_rank_set_records_complete_with`, with no release callback, calls `try_rank_set_records_complete_with` and its `try_within_admission`. | Existing set preparation and execution return the aggregate. |
| Find, including an applied saved find definition | `try_find_records_complete_with` applies `Find::maximum`, prepares each unit, charges `SourceBudget::find`, and then checks the engine count through `try_within_admission`. | Existing `find_complete_inputs` validates the complete candidate set and sends only after admission. |
| Relate | `try_relate_records_complete_with` calls `complete::relate::records::collect`. That owner prepares each record and charges `SourceBudget::relate`, checks the engine count, checks located record counts, and admits the entity set. | Existing `relate_admitted_complete` runs only after the whole set is admitted. |
| Recognize | The non-CLI session calls `try_recognize_records_complete_with`. It prepares each recognition input and checks its profile before `try_within_admission`. | The existing stages run after eager first-stage admission and retain their existing aggregate and failure facts. |

For eager sessions, the independent row families must enter `request::pull::dispatch`, as the current sink dispatch already requires. Do not redirect them to `atomic` or the annotation/dynamic-choose branches that collect rows before their complete calls. Conversely, do not send rank, find, recognize or relate through a row scheduler to obtain earlier closure. Their existing whole-function return and prefix contracts remain authoritative.

Do not wrap every function with an extra `check_record_limit` pass. `try_within_admission` checks cancellation before and after pulling, resolves the pulled row's error, and then checks the engine count before retaining it. Find and recognize prepare within that iterator; relate preserves the equivalent order in its own collector. An outer count guard would change which error wins on the first excess row. Preserve those native orders, their diagnostics and record ordinals. A reader, composition or function-preparation error on a consumed row retains its native precedence; errors in an unread suffix cannot replace an earlier admission refusal. This deliberately removes the old accumulator's ability to let a later file error hide that refusal. Eager means validate the supported whole input before backend work, not finish reading an already refused input.

Reuse `SourceBudget::find` and `SourceBudget::relate` in their current owners. Their byte source remains `core::MAX_RECORD_BYTES`, and JSON charging uses `RawRecord::retained_bytes`, including the original outside a selected field. Generic rank and rank-set retain their engine record limit through `Engine::check_record_limit`; the native path/source rank byte budget in `SourceBudget::rank` has a different scope. The existing DuckDB file accumulator becomes a located record feed, so location alone must not activate a new source-rank byte cap. Add no semantic constants, count cap or byte check to DuckDB or session transport. Public Request source and preview budgets keep their current owners.

Keep `Queue::next` and the framing decoder's `reader_admission` checks while waiting or consuming descriptors; these enforce cancellation and the started deadline during eager intake. Every composition error already closes intake. A refusal raised farther down the native admission path must return directly to the worker's failure handling and `Queue::settle`, without another input pull or output-dependent wait. Admission failure sends nothing and has no invented started facts. `settle` closes intake and wakes the producer; close through the same gate before any future failure path that could wait on output. Reader finish cannot overwrite the native refusal. Cancellation uses the existing token and queue closure, and the worker publishes actual terminal facts only after native settlement.

The native admission owner may inspect the first excess record to preserve error precedence. While it inspects that record, the producer may already fill the existing input cell and hold one unaccepted descriptor. A suffix sentinel must lie beyond those distinct allowances. No additional read follows the producer's observation of Closed. Queue capacity does not make the exact first excess file unread, and a source read counter must distinguish native consumption, accepted waiting input and the one producer-held retry.

## Declaration and reader order

For each non-null SQL row, parse the verb, inputs and settings without opening content. Preserve current SQL NULL behavior before settings or file work. Prepare inline declarations with the existing SQL question helpers and build the owned Request. Resolve saved question references through DuckDB authorization before opening evidence files. A saved question may require its own authorized read; static declaration refusal must precede evidence content access. Do not pass an unresolved pathname as a native Request source or let Rust reopen a saved question.

Validate reader controls through the existing native file-plan helpers, validate projection controls through shared Request admission, and validate effective call controls before file opens. Obtain the engine through `engines::engine_for`, preserving configured cache/record/replay probes. Move effective batch, context, deadline, attempts and process budget into `RequestOptions`, using the existing call-versus-session precedence in `complete/ffi.rs`. Own the parsed definition and every setting. The worker must retain no `BridgeSettings` range, question selection pointer, `ThinkThenStop`, `ClientContext`, file handle or reader callback. Do not retain a caller-side engine clone that could join a usage writer when freed.

Keep the authorized manifest's current ordering, duplicates, expansion and metadata rules. Check interruption before each open and before reader advancement. Open each file through DuckDB's current FileSystem and regular-file check. Reader construction, advancement, callback execution and destruction all occur on that same thread. Destroy the Rust reader before closing its borrowed DuckDB handle.

The physical reader already returns text or image originals and locations; the framed reader already decodes JSONL, CSV and TSV with native grammar. Change the reader's output conversion to canonical `RequestSessionDescriptor` content. Use `RequestItem::from_record_descriptor` for the existing item grammar and `SourceLocation::new` for coordinates. Keep JSON originals ordered and distinguish JSON from literal text. Send decoded originals with Document framing so a CSV row is not decoded a second time. Request projection and declaration validation happen once in native session composition. Preserve annotation document handling and the supplied `reading` selectors through the owned native reading control.

## Producer, output and cancellation

Replace the accumulator with one calling-thread loop. Drain available session packets before advancing the reader and after every push attempt. Hold only the current unaccepted descriptor. Accepted transfers ownership; Full retries that same descriptor after draining output and a short interruption-aware wait. Closed disposes of it and stops all reader advancement and subsequent file opens. Do not send an empty synthetic descriptor to probe intake. Runtime closure may race one already-read unaccepted descriptor, as ADR 0129 allows. Buffered native reader and scheduler read-ahead retain their existing contracts; this design does not promise zero underlying bytes read after an unobserved runtime stop.

At EOF call `finish(None)` once, then drain to the actual terminal packet and End. On a native reader failure, finish with that owned reader error after the accepted prefix. On host authorization/open/read failure, use the existing safe Local classification and owned transport failure, without forwarding SQL hints or host path-bearing diagnostic text. Finish must work with a full input cell. Do not cancel an otherwise admitted prefix merely because its reader failed. The shared admission path above closes intake on whole-set refusal before consuming the remaining suffix, subject to its stated read-ahead allowances, and preserves zero sends. Whole-set candidates, eager validation and caller-retained results retain their established memory contracts.

DuckDB interruption calls `cancel`, destroys the reader and file handle on the calling thread, drops the session endpoint and propagates the existing host interrupt. Cancellation cleanup does not wait for terminal facts or join a blocked provider. Check interruption during output-only waits after EOF as well as input backpressure. The worker holds only independent native state until its provider/deadline cleanup settles. A normal retained session drains completed packets before terminal; host abandonment may discard unread packets under ADR 0129. Do not invent final counts on prompt host cancellation.

Keep the SQL complete carrier and generated typed projections. A pure bridge renderer consumes owned Row, Aggregate, Observation and Terminal packets in their native order and produces the existing `native` and `observations` fields, ordinals, find selection and completed-prefix failure fields. Retaining returned rows and observations is the caller's existing output contract, not another bounded queue. Do not collect input descriptors in this renderer. Use native serializers and existing SQL projection helpers; do not synthesize events from selected rows or infer facts from them. Terminal supplies actual final facts and failure. Successful empty input still consumes terminal. Complete filters retain rejected rows, including false values in the existing table fixture; ordinary selected-filter sessions keep their current behavior.

Nonincremental SQL calls retain eager validation before sends through the shared owned eager control and function-specific admission above. Incremental row calls retain completed prefixes; whole-function calls retain their native aggregate contracts in either mode. Both modes stop intake on native refusal. This bounds transfer queues, not eager retained input, whole-set candidates, results, process memory or provider cleanup. Eager calls validate their supported whole input and stop when native admission refuses it. No new hard record cap or rank contract belongs here.

## Claimed implementation files

The DuckDB producer claims `databases/duckdb/cpp/src/complete_files.cpp`, `complete_files.hpp` and the small invocation change in `complete.cpp`. The private bridge claims `databases/duckdb/bridge/src/ffi/complete_files/ffi.rs` and `ffi/complete/ffi.rs`. Declare private counted operations next to their caller using the existing bridge types; do not add public SQL functions. Delete the file-record accumulator exports only after their last caller is removed. Keep ordinary record and binary-image calls on the existing executor until their separate migration is authorized.

The shared prerequisite claims `crates/thinkthen/src/public/request/session.rs`, `session_queue.rs`, `execution.rs`, `composition.rs` and the public re-export in `public/request.rs`. Its admission repair calls the existing owners under `public/options/admission.rs` and `public/complete/`; no new limit implementation belongs in this slice. The reading parser extraction claims only `databases/sqlite/src/complete_native/inputs.rs` and its extracted helper if needed; its existing callers must retain their behavior. Reuse one feed-projection validator and one finish state. No C header/schema change is needed for Rust-only feed configuration, native reading override or native reader failure. The coordinator must allocate this narrowed shared claim before code work.

Implement the shared 0503 constructor, owned reading/error controls and session dispatch repair first, with the focused session cases below. Then implement the 0470 private bridge and calling-thread producer against that reviewed shared revision, and run the focused installed cases. Keep this order because a producer built against the current eager collector would reproduce the review finding. The implementation needs no additional design framework, queue, scheduler or external owner decision.

Select the existing complete function, file, image refusal, `finite-all-before-send`, `stream-staged-batch` and `cancellation-held-call` cases from that runner. Do not create another parity harness. Shared session regressions belong in `crates/thinkthen/tests/request_session.rs` and its existing framing fixture.

Add `owned_eager_admission_closes_before_finish_and_leaves_suffix_unconsumed` in that session fixture. Exercise the row families, rank, rank-set, find, relate and recognize with a tiny engine record allowance and a counted producer; use located descriptors for the SQL whole-set routes. Include find and relate with their own native set-count boundaries and tiny text rows, without a tighter engine allowance. Drain output while retrying only the same Full descriptor. Assert closure and the native count error before producer EOF, zero provider requests, truthful absent admission facts, and no suffix consumption beyond the native excess row, queued descriptor and one unaccepted retry. The current eager collector must fail this case because it waits for the refused suffix or EOF instead of closing.

Add `owned_eager_admission_keeps_native_error_precedence` using an invalid first excess row and a later sentinel. Compare the native diagnostic and ordinal with the corresponding fallible complete method; include per-record context refused by find/relate preparation and an invalid recognition input. Add `owned_eager_late_invalid_input_sends_nothing` with a supported prefix below the count limit and a later invalid record, including dynamic choose. Retain `reader_failure_follows_owned_completed_rows_and_observations` for incremental failure, `whole_set_requests_publish_one_aggregate_then_truthful_terminal` for aggregate shape, and `empty_success_and_idle_producer_deadline_keep_actual_native_facts` for deadline settlement. Extend the existing held-provider cancellation and framing stop cases to the owned eager controls without adding a new listener or timing harness.

The routine count and precedence cases use tiny descriptors and the existing loopback counter. Source tracing verifies that find and relate charge their shared byte budgets before retention and before the engine count check; a synthetic smaller byte cap would restate the production rule. Keep large aggregate-byte evidence in the existing release family, including `public_batches/ranks.rs::release_only_find_complete_set_stops_at_aggregate_byte_limit_before_any_send`; do not run it or create large-input fixtures for this design or prerequisite. No new runtime byte-bound proof is claimed by this record.

Add one small deterministic installed admission case in `databases/duckdb/tools/files_suite.py`. Use incremental input, a native engine request budget and a loopback provider with a held reply. Place a forbidden or invalid sentinel file after a valid prefix longer than the permitted transfer/native scheduling read-ahead. Coordinate stop and observation through events rather than a timing or memory threshold. Assert the completed prefix, actual request count, terminal error/facts and that the sentinel remains unread. Account for exactly one already-read unaccepted descriptor and existing scheduler behavior. It must fail on the accumulator because the accumulator reaches the sentinel before native admission. Where a true open/read count cannot be observed through installed DuckDB, add a narrowly scoped counting fixture to the existing private reader bridge test seam; do not infer reads from RSS or request counts.

Cover Full retry without advancing, output draining while input is full, reader failure with a completed prefix, static declaration refusal with zero content opens, eager late-invalid input with zero sends, false complete-filter rows, whole-set overflow before the suffix and cancellation while the provider stays held. The held listener must remain held until host cancellation returns, then be released and joined by its owner. This distinguishes prompt host return from eventual native cleanup. Add no load campaign, full parity matrix or release build to the design review.

## Structural risks and review decisions

Truth restated: native admission, controls, descriptor grammar, framing, projection and packet serialization keep their shared source. The adapter only owns authority and SQL transport. Fixing one copy: shared feed configuration and finish semantics must also retain default behavior for existing Rust and C sessions. Unshared state: one caller owns every reader; one worker owns its engine clone; native queues alone synchronize transfer. Leaky tests: reuse the current child environment and owned loopback fixture. Proof heavier than code: one focused installed stop case and retained regression fixtures suffice; no separate evidence ledger or status file is proposed.

The fresh reviewer must decide the owned feed and reading controls, native reader-error seam, pre-read image readiness, SQL carrier projection and function-specific eager admission order. Reject an implementation that stages input ahead of admission, defaults away eager validation, adds a generic count guard ahead of native preparation, omits false filter rows, exposes DuckDB storage to a worker, joins cancellation cleanup, replaces native reader diagnostics without approval, or claims a total-memory bound. The implementation developer must cite the accepted design revision and confirm these interfaces before coding.
