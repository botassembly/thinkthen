## Current path and the narrow change

`cli/args/command.rs` owns audit help; `cli/audit.rs::AuditArguments` owns `write: Option<PathBuf>`. `grade_all` rejects `--write -`, `--threshold` and non-question `--by` before reading results/key, parses and grades them, then calls `cli/audit/write.rs::bars`. That function reads the named question, parses single questions, sets, recognize and relate specs, validates every applicable saved digest and splices steady threshold/model/batch values through `core/measure/splice.rs`. Only at its end does it call `std::fs::write(path, new)` if bytes changed. `cli/measure.rs::Cause` gives an invalid file or failed write exit 5 and a digest mismatch exit 2; `cli/audit.rs::run` prints no audit rows if grading/write fails. `rank`/`find` skip the digest check and leave the bar unchanged. A new destination must share this calculation, not recalculate a digest from the output after threshold moves.

The proposed paired form is `audit RESULTS KEY --write QUESTIONS --write-to OUTPUT`. `--write-to` alone and `--write-to -` are usage exit 2 before file reads; the missing-source check precedes dash if both occur. The existing `--write` validation then keeps its current precedence. The new writer always publishes a valid output, including an exact source copy if no bar changes. No file is written in the new form until all grading and digest checks pass. Its per-bar report is identical to `--write`; only a rare post-publication temporary-cleanup warning adds a line. Source bytes are never written by this branch.

The final output entry must not exist. Do not canonicalize a missing path or use a check-then-rename sequence. A single `hard_link` from a complete create-new temporary file in the target directory to the final name supplies no-replace publication. `AlreadyExists` covers a same-path target, ordinary or empty existing file, directory, final symlink including dangling, hard-link alias and another writer winning after grading. An unavailable parent or unsupported hard links fails without publishing. On failure remove the temporary name; if that cleanup itself fails, return a distinct fixed error so a leftover is not hidden. After a successful final link, a failed temporary unlink cannot be reported as if publication failed: keep exit 0 and print a fixed warning about the leftover. No mode changes to old in-place `--write`, hidden overwrite, fsync promise or adversarial parent-directory guarantee belong here. The old specification's objection to a user-unnamed temporary path describes its in-place form; the temporary file in this additive form belongs to an expressly named new output and is removed normally.

`sdlc/scripts/policy.py` currently treats `cli/audit/write.rs` as the sole measure writer and allows only fully qualified `std::fs::write(path, ...)`. It denies `File::create_new`, `hard_link`, `remove_file`, `rename` and `OpenOptions` there, and denies writes in the other measure modules. A build must add exact-path allowances for create-new, hard-link and remove **only in that file**, preserve existing and new planted refusals for alias imports and every broader write, and keep other measure files read-only. `engine/recorder.rs` and `engine/recorder/identity.rs` already use create-new plus hard-link for no-replace publication; they are read-only design precedents, not dependencies for a CLI audit writer.

## Smallest discriminating proof

Use the existing `tests/support/measure.rs` command runner and `tests/fixtures/measure/write/` input. A new `tests/audit_output.rs` keeps the near-ceiling `audit_refusals.rs` unchanged. One single-question case starts with the CRLF source containing escaped `\u0074hreshold: 0.9`, asserts exit 0, the existing `wrote threshold 0.59` report, source bytes unchanged, and **literal** destination bytes with the escaped key at 0.59 and `"model": "jev-1.13.0"`. Parse the destination as a question file and show its new digest by a later saved-row read or an exact retained helper. One set case checks the full literal destination against the source except `questions.correct.threshold: 0.54`, with no added model; parse it as a set. A no-bar case writes an exact copy rather than a hard link and retains its keep report. These are distinct single/set splices already exercised in-place, so the new proof centers on destination publication and source preservation.

The refusal table checks `--write-to` alone, `-`, an old-result digest mismatch after a prior tune, same input/output path, pre-existing empty output, symlink to source (and dangling symlink), hard-link alias, and a missing parent. Pin exact exit/stdout/stderr; snapshot source and any existing destination bytes, directory entries and temporary names before/after. The old-result case must use the original digest-bearing result lines and a newly tuned input, so it reaches `Cause::Digest` rather than an earlier JSON or key refusal. One child sets a loopback address and canary key while auditing and asserts zero accepted connections and no canary in either output stream. Existing `tests/audit_write.rs`, `audit_model.rs` and `audit_refusals.rs` retain exact old in-place and secrecy behavior. Inspect the final `hard_link` call for the race guarantee; a two-process stress loop is unnecessary. If the publisher factors out an error mapper, a tiny private unit case may inject an unsupported link error and post-publication cleanup error without a shipping fault switch. Do not weaken the outside-in case to a unit-only copy of the writer.

## Preparation lesson

The safe destination is not merely a new argument to `std::fs::write`: that would make a partial new output visible and could overwrite an existing alias. The current policy checker and settled audit page explicitly encode the old one-write rule. Reuse the writer's digest and byte-splice decisions, but review publication, policy and the normative contract together. A successful output with a failed temporary cleanup must be reported differently from a failed publication so the CLI never tells a user the candidate is absent when it is already present. This caught specification dependency should have been in the first prospective file claim.
