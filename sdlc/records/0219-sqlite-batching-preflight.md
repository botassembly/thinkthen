## What preparation taught us

Runtime correction: the inventory's default slide row assumed packed warm answers would satisfy later singleton scalar cache lookups. Its own original five-send assertion now fails with six observed sends. B0's complete-request cache identity makes that assumption unsafe because packed co-members can change an answer. The retained WIP source and [build record](0219-sqlite-build.md) keep the failing assertion visible while the cache lane coordinates the design boundary. The copied DuckDB fatal-denial instruction was also wrong for SQLite: ADR 0080 retains a safe `try_details` Usage value on spent total, and the old scalar before-call refusal stays in `worker::run`.

The preparation miss was an identity assumption, not a missing test count: it assigned the slide a new packed listener oracle while preserving its post-warm scalar cache-hit claim. Source tracing now shows the recorder's full-request digest is the lookup key, and the scalar cannot supply the warm cohort. The build record pins legacy, packed and same-context digests and separates identical warm replay from singleton lookup. At main `fcf7bbef`, the coordinator resolved this under existing ADR 0048/B0: the public legacy recipe selects batch one before engine creation and keeps its no-later-send assertion; default packed warm can reuse only an identical complete cohort. The stale handoff table above remains historical. No row cache or singleton projection was added.

Inspecting every SQLite registration exposed the deadline/context position that the PostgreSQL brief cannot supply. Inspecting `WarmState::step` and `settings::remaining` exposed both the prior-send effect and the invalid row-equals-attempt shortcut. The existing helper proves a failed aggregate has no returned count through `fetchall()`; it does not establish transaction rollback or prevent earlier scalar rows from being observed by a stepping host. Fresh review of `c2c5b0f4` exposed a second proof-preparation miss: retaining a test name did not preserve its expected send count under a new default. The inventory now assigns all affected warm count assertions to explicit batch `1`, unchanged distinct-group/singleton counts, or independently pinned packed bodies. These exact boundaries will make the later build comparison useful if the final B12a scheduler or 0157 setter differs.
