## Verdicts

- 0085 real engine facade: REJECT. The design is sound. The budget is too small for its scope, and it routes the build to the wrong vendor.
- 0086 public Rust API: REJECT. Two acceptance lines contradict 0095 and 0092/ADR 0047. The churn test cannot show that it would catch the crash. The budget does not fit its scope.
- 0093 Rust examples and ADR 0047: REJECT. The pattern leaves the workspace choices the other eight surfaces need unstated, and it assigns one row wrongly.
- 0094 C interface: REJECT. The ticket says it ports the header "unchanged in meaning", but main's relate and engine construction cannot keep that meaning. The JSON door cannot avoid owning some parsing and serializing.

## 0093 and ADR 0047

- F9 (pattern others cannot copy). Rust examples have no FFI, no host toolchain, and no `unsafe`. A host binding needs four things the ticket leaves unstated.
  1. Workspace membership. The branch kept each surface as its own workspace "so the root workspace's gates and profile stay untouched." ADR 0047 makes surfaces members but does not set `default-members = ["crates/thinkthen"]`. Without that, root `cargo clippy/test --workspace` needs pg_config, R, Ruby, and Python.
  2. One shared `Cargo.lock`. pgrx, pyo3, and duckdb pins would move `thinkthen`'s resolved versions. ADR 0047 should say which it accepts.
  3. Lints. `forbid` cannot be relaxed by `allow`, and `lints.workspace = true` cannot take an override. A binding needs its own lints table, and main's lint rung compares lint tables against accepted copies. Smallest change: ADR 0047 says "the workspace table with `unsafe_code = "deny"`, and `#[allow(unsafe_code)]` on one FFI module only". 0093 adds that as a lint check.
  4. The check contract. Each `check.sh` gets the loopback port and runs offline. A missing host toolchain reports "not run" and never "pass" (R6-2). Heavy Docker checks stay out of `test`.
  Also name 0094 as the reference for the FFI edge: the guard, the error table, and the unsafe module.
- F10 (ratchet). `sdlc/ratchet.json` counts `directory: "crates"` only, and `ratchet.mjs` is the shared reader used in every repo. Code under `libraries/` escapes it. Smallest change: 0093 names the mechanism. Either add a `directories` list to the shared reader and note the other repos that use it, or keep a second ratchet file for `libraries` and `databases`.
- F11 (wrong row). R2-32 is the dependency audit of serde_cbor (PostgreSQL) and paste (R). It has nothing to do with Rust examples. Replace it with the rows this surface owns (R2-28), and move R2-32 to the PostgreSQL and R tickets.
- F12. ADR 0047 is consistent with ADR 0017 §1 and §9 and with ADR 0037 because nothing new is published. Its items 5 and 6 are rightly listed for Ian. Add the `default-members` and lockfile decisions from F9 to the Decision section.

## 0094

- F13 (header meaning). `thinkthen_engine_new(void)` takes no arguments and returns NULL with no error channel. "A width outside 1–32 is the usage kind" therefore cannot happen, and main reads no width variable. Smallest change: drop the width line. If the door needs width, record an ADR 0037 amendment that adds a checked `_opts` constructor. The library team owns the C ABI under Ian's ruling.
- F14 (relate and recognize JSON change). The header promises edges `{name, source, target, probability}`, a relate spec with `kind_field` and bare names, and recognize replay against "recordings". Main's relate edge is `{"relation", "source":{name,kind}, "target":{...}, "probability"}` (`specification/relate.md:41`). 0095 makes a non-default `fields` pointer `Usage`. Smallest change: replace "unchanged in meaning" with a symbol-by-symbol diff table (kept, changed, dropped). Amend ADR 0037 and the header comments to match. Update the examples' expected output. State who maps records to entities.
- F15 (JSON door). The door cannot "hold no parser or serializer of its own." The `thinkthen_call` envelope (`decide/evidence/records/annotate/details/usage/rank`) is door grammar. 0095's `to_json` set also has no bare value for `filter`, `rank`, `find`, scalar `choose/score/tag`, or `usage`. Smallest change: either 0095 adds bare-value serializers for those results, or 0094 owns an envelope parser and a small serializer checked byte-for-byte against the command's `result.md` output on the shared cases.
- F16 (build). The crate `thinkthen-c` with lib name `thinkthen` depends on the package `thinkthen`, whose lib is also `thinkthen`. On the branch it had its own `[workspace]` and depended on `thinkthen-contract`, so no names collided. As a workspace member, the uplifted output files can collide. Smallest change: make the first red step a build that shows no output filename collision warning. If a collision appears, drop the `rlib` crate type or exclude the crate from the root workspace.
- F17 (R7-1 run count). "At least 104 runs" detects a 1–2% crash rate only about 65–88% of the time. Name the probe (`t7a/churn/R4-1-churn.c`, or its port) and its parameters. Run at least 300 times, and first show on the tag build that the probe fails (as in F6).
- F18 (size and records). The branch `src/lib.rs` has 1,473 nonblank lines in one file. The 1,100-line budget is realistic only if the stand-in glue goes and the code splits into files under 500 lines. Say so. Also fix ADR 0037's stale `unsigned long deadline_ms`, since the header uses `int64_t`. Keep R2-26's SONAME check in the acceptance lines, because it is a link-time property of this crate. List 0086, 0092, and 0095 as direct dependencies. The memory and ownership rules port soundly: one freer per pointer, a borrowed per-thread message, and slot rows R1-9, R2-7, R2-16, and R3-24.
- F19. DESIGN §3 says partial rows are "deferred until the engine exposes them." The 0085 facade now exposes completed outcomes. Record whether the frozen ABI keeps "no rows" (recommended, since changing it needs a count argument) and delete the deferral line.
