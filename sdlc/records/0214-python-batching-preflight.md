No paid call, stress, full port rung or duplicate inventory is needed for design proof.

The real public choice is early Python cancellation: the current worker raises while requests remain held, whereas ADR 0089 promises final facts after Rust joins. Proposed ADR 0091 recommends an immediate exception carrying a completion receipt with eventual final facts and details. A frozen final `Cancelled.facts` at the immediate raise is impossible without waiting or lying about later replies. Design review should assess that tradeoff before source work; Ian can overturn the under-100-ms guarantee or the receipt spelling. A separate question is whether B12a's final API includes a many-text recognize batch for frames; until that source lands, this design preserves one call per text there and aggregates facts explicitly rather than asserting R7 is complete.

## Preparation lesson

The Python wrapper has no public lazy iterator even though its Rust calls can be lazy. The first call map could have mistaken one Python frame invocation for one Rust call; `each_named` currently loops over `recognize_with`. Inspect the concrete constructor and transport boundary before claiming one run's facts or batching. The outer worker's fast cancellation is a distinct API boundary from Rust's joined terminal error. Use landed 0209 source and check both the inner frame schema and outer `Call` carrier; testing only the frame's cells would miss the new public result shape.

## Corrected boundary inventory and proof

The initial design missed eager `choose_many`, `score_many`, `tag_many` methods, module delegates and stubs; scalar `ask` is not a list route. It also treated mutable dictionaries as immutable, and stopped tracing after engine completion. Final facts must survive `frame::answered` value JSON and failure-cell parsing, `Stop::Said` mapping, Arrow write, column helpers, and Python pandas/Polars reconstruction. A private terminal carrier should cross the worker/Rust/Python boundary; post-call faults use the same final facts/details, with a suitable existing six-kind exception and original conversion cause. Pre-start faults remain without facts or receipt. `each_named` must aggregate completed per-text calls and the failing call, including a zero-send started failure, with no process counter subtraction. The details tuple recursively freezes nested mappings/sequences; no mutable dictionary escapes under a read-only guarantee.

A small table should prove all three new list verbs through method/delegate with null and typed values. One deterministic post-engine malformed value/failure marker or Arrow conversion boundary and one Python reconstruction failure should show final facts on the error; do not add a test-only export. The held worker boundary must observe prompt raise, no later send, final facts for terminal success/returned error, safe Defect with unavailable facts for unaccounted panic, `result(timeout=0)` retryability, unchanged `SystemExit`, and eventual Arrow release using existing listener/door infrastructure. Actual host tests decide which narrow cases are feasible; no broad campaign follows from this design.

ADR 0089 freezes returned Rust `Call`, `Batch` and `Error` facts but explicitly lets observer panic unwind after join. A panic before freeze is not a returned `Error`; the Python `caught` boundary sees `None`. Do not infer final facts from process counters or an unfinished observer buffer. A frozen account survives a later conversion error carried in `Result`; `caught` discards it on any worker panic, so the safe Defect receipt exposes `facts=None` and `details=None`. A wider promise would need separately claimed call-owned send/reply/ordered-row accounting that survives unwind, which is outside this bounded Python adapter design.

The receipt is the sole public decision still for Ian after review: prompt raise with eventual terminal account versus waiting to raise with immediate final facts. ADR 0091 now specifies the recommended receipt and its timeout/signal semantics. Refresh source and file headroom again after B12a lands; current main contains 0209 but 0149/0157 remain separate.
