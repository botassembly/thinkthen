## Confirmed current mechanism

`crates/thinkthen/Cargo.toml` selects `ureq = 3.4.2` with default features off and `rustls` on. `Cargo.lock` includes rustls, rustls-pki-types and webpki-roots. ureq's `TlsConfig::default` uses rustls and `RootCerts::WebPki`, a bundled Mozilla set. `crates/thinkthen/src/engine/http.rs::Client::new` sets timeouts, no redirect and pool limits, but no TLS override. `SSL_CERT_FILE` is not read by this path. ureq's local `tls/mod.rs` exposes `RootCerts::Specific`, `RootCerts::PlatformVerifier`, `TlsConfigBuilder::root_certs`, `Certificate` and `parse_pem`; `config.rs::ConfigBuilder::tls_config` installs the selection. `Specific` is a replacement root set, and rustls adds parsable certs to an initially empty store. ureq's rustls `PlatformVerifier` arm requires its separate `platform-verifier` feature; without it that arm panics. The candidate must not select it without the feature and policy review. ureq's PEM certificate wrapper parses PEM into DER but does not itself prove DER is an acceptable trust anchor.

The finding's diagnostic half is already landed: `engine/http.rs::transport` recognizes `ureq::Error::{Tls,Rustls}` and HTTPS opening-phase `Io(InvalidData)` as `TransportKind::Tls`; `cli/failure.rs` and `public/error.rs` use fixed certificate-trust sentences. 0155's local OpenSSL 3.0.13 self-signed localhost handshake produced command exit 4 with that sentence and no key/body leak. Its fresh review accepted the limit that a synthetic unrelated HTTPS opening-phase `InvalidData` can share that category. This is a retained classification, not a new 0211 implementation item or a reason to edit 0172-held `cli/failure.rs`.

## Proof and gaps for the builder

Use 0155's ephemeral OpenSSL localhost proof as a mechanism, not as a retained fixture. A later executable check needs a controlled CA plus CA-signed localhost leaf, a different-host leaf, an untrusted CA, fixed reply and HTTP request counter. It must establish genuine TLS validation and no request body/key on failed trust, not just a parser result. Host prerequisite: a pinned OpenSSL generator (0155 observed 3.0.13), or a reviewed equivalent available in the gate. Nothing here proves macOS/Windows platform verifier semantics. An invalid DER trust anchor may be parsed as PEM but rejected by rustls at handshake; for pre-send semantic certificate validation the builder would need a direct rustls dependency or equivalent capability, with policy claim. No silent fallback is permitted.

The existing source headroom is narrow in `cli/edge.rs` (27), `cli/asking.rs` (16), `cli/failure.rs` (4), `cli/failure/tests.rs` (7); the last two are held by 0172 and unnecessary under this proposal. `engine/facade_tests.rs` has 69 lines to the 500 nonblank cap; use its existing settings helper instead of repeating a fixture. These are measured file headrooms, not an aggregate growth estimate. Measure complete source and ratchet only after exact implementation claims. A fresh review must settle whether named roots replace or augment Mozilla, whether env plus explicit Rust setter is enough surface reach, and whether replay-only engines should validate an unused CA file. The ticket recommends replacement/env-plus-Rust/early validation but none is accepted yet.

The config-owner build taught the prep to separate authority from diagnostics and avoid a fake cross-user proof. Here, read the named CA file before key/send, never put it or key material in an error, and prove a real TLS handshake locally. It also taught us to check fixture-host capabilities before promising an outside-in test and to leave another lane's exact policy entry untouched.
