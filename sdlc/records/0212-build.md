The first test run exposed a real boundary: the old public throttle test used a synchronous iterator and expected at most `throttle + 1` records read ahead. With default `Max`, the planner read 999 records before the first row while seeking a close. The old test now explicitly selects `batch 1` to retain that precise per-record guarantee, and a separate `Max` response/window proof is still required. An ordinary caller-owned, non-`Send` iterator cannot report that its `next()` is idle while `next()` blocks. A 50 ms timed pause therefore needs an explicit reviewed contract decision rather than an arbitrary record cap or a silent exception. The coordinator is preparing the ADR amendment and Ian choice.

Local refusal also exposed an ordering correction. `Batcher::push` may close earlier work before refusing a later record. The adapter queues those closed batches, then uses `Batcher::finish` to close the remaining valid prefix as `Closed::End`, and only then emits the local error. An early invalid context or first invalid record sends nothing. The command's existing split route lives in `cli/asking/batched.rs`; `facade::ask_batch` itself does not halve a 413. This source must not imply otherwise.
