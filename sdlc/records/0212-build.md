# 0212 Rust batching build record

Status: first source slice in progress. The accepted design remains [ticket 0212](../tickets/0212-rust-library-batching.md) and [ADR 0089](../planning/adr/0089-rust-calls-carry-facts.md). This record distinguishes a passing explicit `batch 1` bridge from the unresolved default `Max` iterator boundary. No facts, uniform `Call<T>`, native outward migration or register closure is claimed.

The first source pass added a public `BatchSetting` and borrowed call context, retained the parsed question-file batch tier in every `Question` constructor, and made `decide_many` and `filter` call a private `core::Batcher` adapter. The adapter sends exact closed `core::Batch` requests through `facade::ask_batch`, keeps fatal worker errors outside `Completed`, and handles one eligible 413 with two rebuilt halves and no isolation request. Annotate still uses its existing single-record stream. This source has not had final design or code review. The eventual call-scoped send observer must count the refused attempt and both half sends at the actual transport boundary; `Answered` alone cannot prove that count.

The file tier stays raw until a call selects it. An explicit `CallOptions::batch` wins even if the unused file tier is invalid; a selected invalid file tier fails before a send. The first parser attempt validated every file tier at load time and violated that precedence. The corrected outside-in case proves both sides of the selection.

The first test run exposed a real boundary: the old public throttle test used a synchronous iterator and expected at most `throttle + 1` records read ahead. With default `Max`, the planner read 999 records before the first row while seeking a close. The old test now explicitly selects `batch 1` to retain that precise per-record guarantee, and a separate `Max` response/window proof is still required. An ordinary caller-owned, non-`Send` iterator cannot report that its `next()` is idle while `next()` blocks. A 50 ms timed pause therefore needs an explicit reviewed contract decision rather than an arbitrary record cap or a silent exception. The coordinator is preparing the ADR amendment and Ian choice.

Local refusal also exposed an ordering correction. `Batcher::push` may close earlier work before refusing a later record. The adapter queues those closed batches, then uses `Batcher::finish` to close the remaining valid prefix as `Closed::End`, and only then emits the local error. An early invalid context or first invalid record sends nothing. The command's existing split route lives in `cli/asking/batched.rs`; `facade::ask_batch` itself does not halve a 413. This source must not imply otherwise.
