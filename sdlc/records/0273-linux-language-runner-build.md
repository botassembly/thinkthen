Status: implementation candidate after 0272 landed at main `546a05a0`, 2026-09-29. Design was accepted at main `0a92e366`. This is static proof only. No Ubuntu package or SDK body was downloaded or installed, and no compiler, consumer, container, backend or Actions job ran. The x86 runner and installed consumers remain unqualified.

The landed 0272 workflow already checked exact managed tool versions and retained source, C, managed and package receipts. This change adds one x86-only selection step after host setup and before managed assembly in build, and one after host setup and before installed tool probes in smoke. Draft and other targets acquire nothing new. Both steps call `sdlc/scripts/release-language-tools.py` with `managed|smoke JOB_DIR EXPECTED_SHA --acquire`, where `EXPECTED_SHA` is `needs.resolve.outputs.sha`. The helper refuses a different checkout, accepts only Linux x86, owns its output directory, and writes its selected package/tool record to `selection.json` there. GitHub supplies `GITHUB_ENV` and `GITHUB_PATH`; the helper appends the four existing selectors, selected `JAVA_HOME` and `JAVACMD`, and the selected JDK `bin` path for later steps of that job. `release-workflow managed-build` binds those Java variables again immediately before invoking 0272's exact probes and the Kotlin/Scala launchers.

The helper first checks the exact installed Debian package versions. For missing inputs, its opt-in acquisition path verifies the accepted SHA-256 of each Noble base, updates and security `InRelease` from Ubuntu snapshot `20260923T150000Z`, writes a job-owned deb822 source restricted to main and universe in that snapshot with the Ubuntu archive keyring, and gives apt an isolated list directory. It requests explicit root and companion package versions, records apt's selected plan, installs only from that source configuration, and checks the installed exact versions and `libncurses-dev` provider. The managed build asks only for the JDK package set; smoke also asks for the pinned Ada/GNU Objective-C/COBOL, GCC and bubblewrap inputs. This code path awaits a real runner check of apt's selected closure and package ownership. It does not establish installation success from metadata.

For .NET 8.0.131, Kotlin 2.4.20 and Scala 3.9.0, an exact installed executable, version and required runtime layout can be reused. Otherwise the helper requests only the accepted official versioned URL, checks its accepted SHA-512 or SHA-256 before extraction, refuses linked or escaping archive members, unpacks into the job-owned directory, and probes the selected executable and runtime member. An explicit invalid selector fails instead of silently selecting another tool. JDK `java`, `javac` and `jar` must resolve to the pinned 21.0.12.1 package owners. Smoke checks the literal `gprbuild`, `gnatmake`, `gcc`, `cobc`, `cc` and `/usr/bin/bwrap` paths, banners, relevant owners and namespace operation before 0271's retained GNU Objective-C link probe and installed callers. The selected JDK is passed to both Kotlin and Scala version launchers through `JAVA_HOME`, `JAVACMD` and `PATH`; an inherited unrelated Java is overridden.

The focused static fixture uses selected home layouts with real Kotlin/Scala runtime member names and the accepted package, URL and digest pins. It observes command arguments and environment outside the checked helper. Positive managed and smoke cases require every pinned package version and selector. Negative cases refuse a wrong package/provider, invalid literal selector, wrong selected Java, missing Kotlin runtime, missing bubblewrap, changed digest before extraction, and escaping archive member. It checks that a wrong inherited Java never drives either managed launcher. `sdlc/scripts/workflows` now checks the x86 step order and resolved SHA, registers that fixture, and plants missing build and smoke setup steps. The fixture uses temporary files and observers, so routine workflow checks require no Linux installation or network on another host.
