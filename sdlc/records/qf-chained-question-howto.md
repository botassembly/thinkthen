# Chained-question how-to

Status: candidate for fresh independent review. Base main `a15332d2`. The [open issue](../issues/2026-09-28-a-chained-question-hides-a-better-pipeline.md) and [tuning review](2026-09-28-tuning-value-review.md) ask for a runnable two-call host sequence before 0.1, plus audit guidance. The original experiment is `experiments/297-gepa-loop-tests/`, especially `DEV-BRIEF.md`, `LESSONS.md`, `pipeline.py`, and `runs/pipeline/`. The brief's second displayed command omitted its options and hardcoded the first answer's album. This Quick Fix supplies the actual option lists and passes the first choice into the second call through a shell lookup. No engine sequencer, selector, repeated-run command, cost output or recording migration was added.

## Replayed path and provenance

`demos/47-split-a-chained-question/run.sh` asks which album first included a song, checks the first `choose --raw` exit code, maps its option to the album description, and passes that album as the complete text input to a second `choose` with eight explicit year options. `I Me Mine` returns option `d`, maps to `Let It Be`, then returns `1970`. `It Won't Be Long` has a tied first-hop distribution of 0.41 and 0.41, so `choose` exits 3; the script prints a review message and runs no second hop. Both cases use `--replay recording/`, an explicit model alias and backend address, with no live request or key.

Before copying, I inspected all three raw version-one envelopes. Each contains only `schema`, `adapter`, the public System One URL, request and response. The requests name public songs, albums and years; responses hold those answers and usage, no key or private customer data. The two first-hop entries were copied byte for byte from the public MIT-licensed `beatles-bench` run `results/runs/2026-09-26-thinkthen-jev/recording/` and match the same files in experiment 297. Their entry names begin `3c4e3fa4` (completed) and `05d08c40` (tie), and their copied file SHA-256 hashes are `0beeb264e13358d2c7c53ea5a2a8a60ed759036acef985d7a5e634e1fc173abe` and `593b4fdcbcb84f183b86fc4fd1e0551344c02c36c7232a17aba2a30c5ae488a3`. The second-hop entry `f18802b6` came from experiment 297's `recordings/`, where `pipeline.py` made the exact album-year request; its copied file hash is `fd4b83c9ec3223ef78f0f2c748925d4d51952a0d4747ed08e1cf9060eb87a8ad`. The experiment ledger shows its pipeline case 001 reused that entry with `cached=true` and `requests_sent=0`. The files remain immutable saved exchanges; no response or request was manufactured.

The how-to and both catalog rows are green. `specification/audit.md` now tells readers to audit the direct and split final-answer sets against the same key before tuning a chained question's wording, while retaining the full cohort's not-sure first hop. The evidence gives direct 22/60, first hop 48/60, and pipeline 51/59 completed second hops; counting the one tied first hop as wrong gives 51/60 over the source cohort. Experiment 297's repeated album-year hops were cache hits in its retained state. Neither its near-equal cost nor its accuracy gain is a cold-run or cross-domain promise. The other tuning proposals remain deferred by the independent value review.

## Focused proof and limits

With the existing compiled command at `target/debug/thinkthen`, `PATH="$PWD/target/debug:$PATH" mustmatch test demos/47-split-a-chained-question/README.md` passed both assertions. The same page passed the green-demo form and vocabulary checker through a one-page ignored `target/codex-chain-check` root: `demos: 1 green, 0 red`. `python3 sdlc/scripts/pages` reported `1 coming, 23 green`, and `mustmatch test spec/audit.md` passed eight blocks. `git diff --check` passed. The first-run proof checks exact printed song, intermediate album and final year; the tied case checks exit 3 and the review message. Since the demo recording has no second-hop exchange for that tied case, an accidental second replay would fail instead of satisfying the asserted exit. No provider, full demo suite or site build ran.

## What the build taught us

The experiment's full-cohort summary and saved audit use different denominators because the tied first hop has no second result row. The example therefore needs a branch that records that case as not sure before the second call, and the guidance must name both 51/59 and 51/60. Request identity was the other risk: the old first-hop exchange and experiment's second-hop exchange replayed under the current binary only after the exact original option descriptions, model alias, address and evidence were retained. The short brief omitted second-hop options; its displayed shape alone was not replayable. A focused green-page checker run caught the page's vocabulary rule without running unrelated demos.
