## One independent 0.1 brief: current recognition manual guidance

**Priority source:** scale/shape items 7–8 and the surviving R8 manual outcome in the recognize-design issue. This is a bounded documentation implementation, not a recognition algorithm change. The actual defect is incomplete user guidance: `specification/recognize.md` explains `--threshold`, `--relation-threshold` and `--kind KIND=DESCRIPTION` separately, but never maps a dropped name, a noisy result or a missing custom kind to the appropriate dial and its limit. It also does not state the categories in `core/recognize/questions.rs::step_one_words`' fixed generic question when no kinds are given. The old issue's “news document” wording no longer exists.

**Smallest counterexample and proof:** a reader of the current page sees that lowering `--threshold` can keep a found name but must piece together that it cannot restore a step-one miss or a step-two `none of these` decline. That distinction is already executable in `core/recognize/bilou.rs`, `core/recognize.rs::settle`, `engine/facade/recognize.rs` and the `--details` contract. Add one concise symptom-to-dial table to the recognize manual, with those boundaries, relation-cut behavior and description-only-at-step-two behavior; add one sentence on the current fixed generic wording and its measured coverage. Cite the already retained 0147/experiment-288 figures only with their exact provenance; claim no new provider performance. The smallest verification is the exact page text/source comparison plus `sdlc/scripts/pages` and `sdlc/scripts/tickets`; no new runtime fixture is warranted for unchanged code. Keep R8 open for its later R7 cost gap and any long-text measurement criterion.

**Required decisions before other builds:** the coordinator may approve this routine manual brief within the accepted outcome. Register 35's `unclassified` output, any new deterministic remedy for 109's accepted errors, 115 relation evidence windows and R7's multi-stage batch form require separate reviewed contract/design decisions. None is blocked by the SQL/DataFrame hold. No test, build, provider call or new measurement was run for this preparation; no plan or product status changes follow from it.
