## Cause and correction

The existing `libraries/jvm/tests/public_types.py` built an isolated child environment without a locale. On this Linux JDK 21, that gives Java `native.encoding=ANSI_X3.4-1968` even though `file.encoding=UTF-8`. The case's exact UTF-8 command argument `{"version":1,"recognize":{"kinds":{"person":"A person's name."}},"threshold":0.5,"relation_threshold":0.5,"evidence":"Le café 😀 Maria Chen arrived."}` arrived in `TypeCase` with replacement characters. A local capture of the first backend request showed `caf�� ���`, 12 questions and 6,569 body bytes rather than the checked-in seven-question, 3,839-byte first exchange. Its SHA-256 was `bf6195bc167a0e7c0aca9dd9d898f07d125cc846cc738d9a0b3d5fd07b69ebcc` instead of `23c6d69036b5435b9010db2575b9647fd9bce7816aef55698e33a0d756861381`. The case arm refused the unmatched body; Java returned `{"error":"backend"}` after four observed requests. The byte mismatch precedes any recognize offset conversion. This does not establish the regression's age.

The runner now sets `LC_ALL=C.UTF-8` in each JVM runtime child. It retains a one-case selector for focused J1 replay; ordinary `check.sh` still invokes the entire corpus without an argument. No product/JAR/native source, fixture, expected result, request, or backend rule changed. No test was added or deleted: the existing case 41 outside-in oracle now serves as the regression, while the other parser, invalid-input and request cases remain distinct. The Python ratchet rises **614→617** nonblank lines for the selector, locale choice and explanation; Java **843**, Kotlin **86**, Scala **94** remain exact. I checked the existing runner and shared case oracle before adding code; the selector reuses both rather than introducing a second fixture or listener.

## Limits and What the build taught us

This proves one current-source J1 case through source JARs, a matched local C copy, and the local backend, not the other 28 runtime cases, installed/release archives, another locale/OS, or a full package gate. The problem belonged to the test child environment: Java's native argument decoder can use an ASCII locale while its ordinary string encoding reports UTF-8. Exact backend byte matching made that distinction visible; the case name alone was not evidence of an offset bug. A narrow selector let the retained shared oracle prove all three facades without a full package campaign.
