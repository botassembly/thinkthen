# 0301 build: omit null noul descriptions at the shared encoder

Source base: `ticket/0301-noul-criteria-compatibility` after the landed 0283 planner at `cac3d07ec` and the accepted design at `46925b681`. Fresh High code review accepted `8286b99d7d063ada9e7b0374ab80da1000a3f343`. No provider call or release package was made.

## Change and retained contract

`crates/thinkthen/src/core/adapters/systemone/request.rs` now uses one `NoulCriteria::described` rule for Decide and expanded Tag. It omits only explicitly null noul description members and omits the criteria object when neither side has a non-null description. Question-file parsing, the canonical question digest, choice null keys, score null levels, response decoding, and the exchange hash algorithm are unchanged. The fixed check request loses its `,"false":null` member; the other three bodies retain their bytes. `specification/fixtures/check/requests.jsonl`, the three affected specification pages and two executable pages now state and prove those bytes and the 1,568-byte, 809–1,424-token four-request plan.

R `facts.R` keeps its explicit-null input JSON and independently expects the new full body and digest. TypeScript `verbs.test.mjs` keeps `true: null` at input and the structured false description, then expects a false-only noul criteria object. No provider recordings, shared conformance goldens, public APIs or cache lookup behavior changed. Explicit-null and absent-side questions can have distinct canonical digests yet identical wire and exchange digests at one URL; an existing absent-side cache entry may therefore be hit. That is exact-byte identity, not a measured equivalence of provider answers.
