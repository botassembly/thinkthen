# Recognition snippet width

This change starts from `7d8f7b4281c89b094e1dbe13bbb93295c9d6b0d3` under the accepted reversible unknown-route and strict encoded-byte assumption. It does not settle the model-window criterion in 0461.

The native declaration adds `RecognizeBuilder::snippet_pieces(u32) -> Self`, `Recognize::with_snippet_pieces(u32) -> Result<Self, Error>` and `RecognitionReading::snippet_pieces() -> u32`. The builder validates platform representation during `build`. Shared `RequestOptions::snippet_pieces` is `Option<u32>`; saved declarations use `recognize.snippet_pieces`; CLI uses `--snippet-pieces`. Zero is admitted. Omission resolves to six and retains existing serialized bytes. Explicit six normalizes to that same reading. Wider values clip through saturating arithmetic and remain subject to existing actual encoded-byte admission. Batch grouping is unchanged.

The pre-change compiled command refused `--snippet-pieces 0` as an unknown argument with exit 2. The kept outside-in tests exercise clipping and generated request identity through counted loopback requests. The existing request schema helper also retained a 20-kind maximum after size-based recognition admission landed; removing that stale schema constraint brings declaration admission into agreement with the native parser.

Five counted command cases pass, including default request bodies, zero and maximum widths, both stages and edge candidate descriptions, invalid saved/CLI zero sends, exact plan/body digests and question keys, recorded replay and cache reuse.

The first compiler pass exposed an assignment added to an unresolved options scope; it now checks representation there and assigns only to the resolved recognition declaration. The first command cases exposed two oracle mistakes: the shared listener drains captured requests, and a width that covers one central token need not cover edge tokens. Counts now use each capture and identical-window identity uses a width covering every piece. The central clipping case still checks width eight explicitly. These corrections changed no product semantics.

The shared compatibility default now lives once in the recognition declaration and supplies native, saved and question rendering defaults. The lesson is to compare complete generated windows for cache equality, rather than infer equality from one central snippet. Existing encoded-byte admission remains authoritative; host adapter adoption and model-window capacity remain separate work.

Saved zero and maximum widths agree with native decoding; negative, fractional and overflow widths agree on refusal. The same table admits 256 caller kinds. All eight shared request contract cases pass after regenerating the existing schemas. The initial mismatch remains recorded in owned test output.
