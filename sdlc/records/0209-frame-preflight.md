## Completion adapters and representation

- Rust Polars: `public/frame.rs` owns input collision checks, preserved columns, and final `hstack`; `frame/column.rs` owns typed per-kind Series. Add the `failed` output once at `annotate_frame`, not once per question. A question named `failed` and an existing `failed` input column must refuse before `annotate_with`. `QuestionSet::members()` already exposes names and kinds. The pinned `polars` 0.55.2 optional `dtype-struct` feature is needed for the nested native column. Its `polars-core` 0.55.2 `StructChunked::from_series` constructor sets outer validity to `None`; child nulls alone do not make the parent null. `StructChunked::with_outer_validity(Some(bitmap))` is public and explicitly sets the parent validity, including for zero rows. Confirm the resulting successful cells are null with row extraction in the focused proof. Measure the feature and lock effect during implementation. Series verbs continue to use `column::answered` with `Shape::Series`; their all-failed error remains.
- Python Polars: `src/frame.rs::answered` can build typed `Cells` and one failure vector from the already-collected `AnnotatedRecord`s. `src/arrow/write.rs` owns `Cells` schema, arrays and frame append; its `frame_out` takes a vector of named cells. `src/arrow/mod.rs` maps pandas dtypes and must handle the new cell variant. The existing writer supports nullable `Bools`, `Numbers`, `Texts` and `Lists`; a nested failure struct is the one new cell shape. Its outer Arrow StructArray must carry a validity bitmap with zero bits for all-success rows; nullable child arrays do not establish a null parent. Emit the full `question -> failed -> {kind,cause}` hierarchy and typed zero-length arrays with the same schema for empty frames. `src/arrow/write.rs` is 540 nonblank lines before J2. Move its existing `SchemaNode` and metadata-copy code to a private `src/arrow/write/schema.rs` sibling, register that module, and then add the failure cells through the remaining writer. This is one coherent extraction, not a second Arrow exporter or Python Polars import.
- Python pandas: `_annotate_column` currently returns question `(values,dtype)` pairs; `thinkthen/__init__.py` constructs each Series with the caller's index. Add one `failed` `object` Series of dict-or-None with that same index. `_on` already rejects question-name collisions; it must also reject reserved `failed` and an input frame's `failed` column before a send. `asked::QuestionSet::_names()` supplies ordered names. The list/record `annotate` path stays unchanged.
- For all doors, use `Annotated::Failed` and the existing `AnnotatedRecord::value_json()` marker to avoid a second failure-cause table. In the Polars struct, names are fixed by the set while row failures are nullable nested `failed` children; in pandas, each dictionary contains only failed names. The fixed-key Polars row exposes null sibling names and requires Ian's explicit choice. No generic C door or result-schema edit is needed.
