## Preparation corrections and limits

- The handoff heading says six spikes but lists eight. Saved branches/logs are evidence only; 2038 `HANDOFF.md` and `spikes/BOUNDED-RUNS.md` give exact identities. SQLite row reuse is a **connection-scoped eight-slot LRU** with Arc-shared rows and a pointer/length/byte fast path, freed at disconnect, not a statement-only cache. PostgreSQL conveniences use `DEFAULT NULL`, and its query proof uses server `statement_timeout='30s'`. DuckDB macro registration uses `CreateMacroInfo` with `info.internal=true`. R plan belongs to 0297, not 0288; expression deadlines in 0295/0298 apply per morsel.
- The old forecast's demo16 lint blockage and its dated R/Polars file-claim assumptions are stale. Current source and the coordinator's Lanes table win. Correlated SQLite and `EXISTS` proofs stop at 1,000 rows; aggregate-once packed joins may use 100,000. RSS/load/churn are opt-in, not routine ticket entry checks.
- `0283` touches near-cap Rust files: `cli/args.rs` 473/500 nonblank, `public/settings.rs` 470/500, `cli/args/command.rs` 430/500, `core/batch.rs` 458/500 and `engine/facade.rs` 468/500; `engine/prepared_request.rs` is 177/500 and `core/plan_document.rs` 127/500. The current C schema lives in `libraries/c/src/settings.rs`; `thinkthen_engine_new_with` calls it from `libraries/c/src/ffi.rs`. `core/batch.rs::Batcher::{push,finish}` makes content/size/configured cuts, while `engine/prepared_request.rs::PreparedRequests::with_profile` and `engine/facade.rs::split` apply non-batch split/profile limits. CLI previews currently split across `cli/asking/plan.rs` (one record), `cli/asking/batched.rs::planned` (first closed batch), `cli/find.rs`, `cli/annotate/plan.rs`, `cli/recognize/dry_run.rs`, `cli/relate/dry_run.rs` and `cli/check.rs`; `cli/cache.rs` is a deliberate exception. 0283 proposes new pure `core/plan_summary.rs` over those prepared bodies; 0289 wraps it rather than copying an estimator. Remeasure before build.
- The SQL plan return shapes are JSON text (SQLite), `jsonb` (PostgreSQL) and `STRUCT` (DuckDB). Each uses the same summary and the independent P1 no-send fixture in the corpus. 0291 begins with an additive C `thinkthen_plan_json` route and binding-author guide, then exposes public `plan` on **all fourteen** other doors. It cannot repurpose the closed `thinkthen_call[_opts]` JSON grammar or change its `{value,facts}` return. C `ffi.rs` measures 499/500 nonblank, so that first family proposes a private extraction. C export/header copies and exact archive member lists are required implementation inputs.

## What preparation taught us

An accepted settings key can precede implementation only as independent schema data; the public C/SQL configure path must wait for 0289's active cap. F1 and F2 need one green landing even though they have distinct proof owners. The old package and forecast receipts identify useful regressions, but their dates and old lint state do not establish current runtime results. Exact request expectations must be captured at the wire boundary, since packed inputs and cached responses are not record counts.

Fresh High review of the first preparation commit `f35bb5826` caught three preview ownership omissions: a first-record CLI plan is not a full-input plan; merely naming a SQL `thinkthen_plan` did not register and prove its native return; and fourteen remaining doors still need a public plan surface. The correction gives 0283 one pure summary over existing batch/split boundaries, 0289 the public wrapper, each SQL ticket a native return and P1 conversion proof, and 0291 an additive C bridge plus all host methods. P1's 120-byte request and 61–109 band are static independent fixture expectations, **not an executed SQL or C receipt**. No new runtime, provider or package check was run in this review correction.
