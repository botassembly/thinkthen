## Actual current path

`Engine#initialize` in `libraries/ruby/lib/thinkthen.rb` accepts base URL, model, throttle, limits, cache, timeout, retries, record, replay and profile, then `Native.engine`. `src/ffi.rs::new_engine` reads those keys into `src/lib.rs::Settings::build`, which begins with `EngineBuilder::from_env`; it reads `THINKTHEN_BATCH`, but Ruby has no explicit constructor batch key. Every asking Ruby method reaches `Engine#crossing(verb, subject, input, cancel, deadline)` and the six-argument `EngineValue::call`, which converts Ruby-owned inputs on the Ruby thread. `src/call.rs::run` constructs only `CallOptions::cancel` and optional deadline. `decide_many_with`, `filter_with`, `rank_with` and `annotate_with` therefore inherit the 0212 engine/question/Max default without another Ruby scheduler. `find_with` is a bounded selection and rejects context. `annotate_with` supports a batch selector but rejects context. `details_many_with` in `crates/thinkthen/src/public/bulk/details.rs` is landed 0230's stopping dynamic-question route for Ruby's future runtime-label many verbs. Its `Evidence + Serialize` bound keeps whole owned Rust input in record detail. Today Ruby converts non-string records to JSON text before Rust; the adapter retains the original Ruby list separately to preserve outward values. Typed Rust `choose_many_with`/`tag_many_with` require compile-time `Choice` and are not a Ruby runtime-label route.

Current output loses the account at several edges. `src/call.rs` maps eager `Call<T>` to `.into_value()` and lazy rows to `Vec`, without reading final `Batch::facts`; `filter` keeps only positions, `rank` keeps ranked positions/probabilities, and `annotate` keeps JSON values. A Rust observer is needed for suppressed filter rows and individual annotate/recognize questions. `src/ffi.rs::output` converts only bare `Output`. `Fault` in `src/lib.rs` retains kind, safe message and retryability but drops `Error::facts`. `EngineValue::usage` returns process counters, not a call account. `Engine#decide_many` maps the probability variant, `filter` maps kept positions to original Ruby objects, `rank(top:)` maps all Rust results then trims, `find` builds `Found`, `choose`/`tag` and `score_with_level` select fields from one details call, `details` parses JSON, `annotate(on:)` merges answers into original hashes, and `recognize`/`relate` build Ruby structs. Every conversion must keep one account through its final public result. `ThinkThen` delegates the same verbs to one lazy default engine; `question` and `set` are local constructors, while `usage` is a process read.

The worker owns cloned question and text/record data, no Ruby `Value`. `src/lib.rs::Handoff` has an `Arc` slot and `start` catches binding panics. `src/ffi.rs::cross` waits with the GVL released, checks pending Ruby interrupts and caller/own tokens before a ready answer, cancels and returns promptly, then the detached worker finishes already-sent work. `lib/thinkthen.rb::crossing` converts Ctrl-C to `CancelledError` with the original cause and gives a raising tick precedence in `ensure`. A completion receipt must retain the worker's result/account independently of the caller and never execute Ruby conversion on that worker. Once the worker ends, the Ruby caller may copy final Rust facts and observations through protected conversion. Worker start does not imply facts: `public/bulk.rs::rank_with` validates kind and input count before `Stop::begin`; `public/engine.rs::details_with` validates kind before judging; `public/batch.rs::Batch::failed` carries an error but no facts. A pre-accounting error retains absent facts even if a worker was created. A post-accounting zero-send error has final zero-send facts. The receipt must distinguish those outcomes. `Thread#raise` and a raising tick keep their original class; a pre-start refusal has no worker receipt; `Thread#kill` still releases the caller even if no exception object survives. Preserve these boundaries while choosing the smallest Ruby-owned completion API in review.
