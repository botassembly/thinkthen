First, the C README and accepted ticket had missed the existing `thinkthen_engine_new_with("{\"cache\":false}")` path: `libraries/c/src/settings.rs:104` already calls `no_cache`, landed with 0148. The survey had followed the environment constructor but had not traced the JSON settings constructor. The C implementation is unchanged; no C port rebuild was used to prove a README correction.

Second, `symlink_metadata` before `File::open` left a check-to-open interval. A replacement symlink to a FIFO could be followed and block before the inode check. `cache_prune.rs::open_entry` now uses the existing Unix `nix::libc` constants with `OpenOptionsExt`: `O_NOFOLLOW` rejects a final symlink at the actual open, and `O_NONBLOCK` prevents an opened replacement FIFO from waiting for a writer. On Windows it requests `FILE_FLAG_OPEN_REPARSE_POINT` through standard `OpenOptionsExt`, so a replaced reparse point is opened as the point itself. The pre-open regular-file check, opened-handle identity check and final path identity check remain. Other non-Unix/non-Windows targets keep the prior open behavior; no such target or Windows toolchain was installed here, so the cross-platform branch has source review but no host proof.

The deterministic outside-in boundary remains `default_cache::prune::prune_names_a_digest_shaped_symlink_without_following_it`: its link names a second digest-valid recording, status counts one good and one bad, prune leaves the link, and the outside bytes stay exact. A new static symlink or FIFO row would pass under the old pre-open check and would not reproduce the check-to-open race. Planting that exact interleaving without a test-only hook or a churn campaign is not deterministic, so no mirrored test was added. As additional compiled Linux evidence, a single `status --json` over the unchanged demo 21 recording folder exited 0, and `strace -f -e trace=openat` showed all three digest-entry opens with `O_RDONLY|O_NONBLOCK|O_NOFOLLOW|O_CLOEXEC`. This shows the kernel received the guarded flags on the actual scan path; it does not claim a reproduced race or a Windows run.
