## What the design taught us

The existing row observer is borrowed and caller-thread, while HTTP attempts happen on workers; reusing it by adding an enum variant would change separately compiled exhaustive consumers. The first draft treated all CLI `--details` verbs as sharing one writer; source tracing confirmed only six ordinary judgment verbs converge there, while four separate pipelines remain. The current CLI details document is one answered row, not a complete run trace, so a row-only timing display cannot honestly close failed-run visibility. The first draft also missed that split assembly's parent `Err(Error)` retains only a send count; copying only child events would lose the very 413 diagnostic while existing counts still looked right. The C JSON `details` flag changes answer form and is unavailable on most verbs; a separate opt-in key is needed for a per-attempt result. Objective-C's exact two-member outer check is distinct from its facts-key check, and a direct C fixture cannot qualify typed wrappers. A printable allowlisted server ID may still echo the configured key, and `get` can select one of duplicate values, so allowlisting and syntax alone are insufficient. A real send-mark ordinal is necessary even when the body digest is already available.
