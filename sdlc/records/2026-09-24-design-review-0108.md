## Findings

1. **R5-38 is dropped.** The index row reads "R's make-tarball script vendors dependencies into an empty, gitignored CARGO_HOME, so a fresh offline checkout fails". The port guide's R line names "R4-7, R5-38". Neither the tables nor the retired list names it. Fix: make the row "R4-7 and R5-38" with R4-7's re-proof and plant, and say "twelve cross-surface rows".

2. **The interrupt plants cannot turn red if the child exits.** In the batch test, an uncaught interrupt ends the R child. The detached worker dies with the process, so the "skip `token.cancel()`" plant still leaves the count below 200. The single call's "count stays at exactly 1" has the same gap. Fix: each child catches the interrupt with `tryCatch(interrupt = ...)`, prints the catch time, and stays alive until after the +3 s read. The parent then reads the count while the child lives.

3. **`unsafe` would sit outside the FFI module.** ADR 0047 item 3 lets only the FFI module carry `allow(unsafe_code)`. The tag's text and deadline crossing uses `unsafe` for `STRING_ELT`, `Rf_getCharCE`, `R_CHAR`, `Rf_translateCharUTF8`, `REAL_ELT`, `INTEGER_ELT`, `R_NaInt`, and `R_IsNA`. The interrupt check uses `R_ToplevelExec` and `R_CheckUserInterrupt`. The ticket puts "text and deadline crossing" in its own file, apart from the FFI module. Fix: put every R API call in the FFI module, or make the crossing file a child module of it. Then state that `unsafe` appears in that module alone and that `policy.py`'s planted failure covers the rest of `src`.

4. **ADR 0042 is only partly re-proved.** The ADR sets three check points: before a call, at each tick, and before and after every `.tt_call`. Its 2026-09-24 amendment makes this ticket re-prove "the tick and the three residual windows". The ticket names only the tick check. It re-proves two windows and leaves out the blank line on standard error. It also does not say whether `tt_interrupt_pending`, `tt_cancel_active`, `.tt_cleanup`, and the `ACTIVE` slot stay. The 0.5 s bound is five ticks, so it does not prove "up to 100 ms". Fix: name the three check points and keep or retire each of the four pieces with a reason. Add a test for the blank-line window: `interrupt_hook.sh` captures standard error for the plain child and the held child, and asserts one extra blank line. Keep 0.5 s if load needs it. Record the measured signal-to-condition time in the ADR amendment, and name the bound as tick plus the child's slack.

5. **`cargo vendor` lacks `--offline`.** Decision 12 says `cargo vendor --locked`. The R4-19 step fails on any `cargo` call in `make-tarball.sh` without `--offline`, so the ticket fails its own check. Fix: write `cargo vendor --locked --offline`. Also give `cargo package` its flags: `--locked --offline --no-verify`, plus `--allow-dirty` when it runs inside a checkout. Or state that it always runs inside the `git archive` tree.

6. **The jsonlite claim is wrong, and the floor can fail the check.** jsonlite 2.0.0 is in the user library under the home directory, not the system library. The system library holds 1.8.8. A run whose library path lacks the user library, such as a scrubbed environment or another account, fails `Imports: jsonlite (>= 2.0.0)` at install. Fix: correct the line. Have `check.sh` test `packageVersion("jsonlite") >= "2.0.0"` on the library path the install uses, and report "not run" with the `install.packages("jsonlite")` fetch when it is short. Or set the floor at the lowest tested version and test it.

7. **The `paste` exception needs a fuller reason and a lever.** The reason is sound. paste is a compile-time proc macro, so no paste code ships in `thinkthen_r`. RUSTSEC-2024-0436 is "unmaintained" with no vulnerability. extendr-api 0.8.2 depends on it directly, and no cached extendr release drops it. The ticket gives only "marks it unmaintained". Also, root `deny.toml` applies to the root lock, which has no paste. The root run then prints a "no crate matched advisory criteria" warning on every `lint` (observed with cargo-deny 0.19.4; exit 0). Fix: the entry's `reason` names the compile-time-only use, the direct extendr dependency, this ticket, and the lever: remove the entry when an extendr release drops paste. The ticket states that the root run's warning is expected. Or it gives the binding its own deny config that extends the root one, if 0093's checks allow it.

8. **The rename misses two build files.** `document.rs` calls `thinkthen::get_thinkthen_metadata()`. Under decision 2 that becomes `thinkthen_r::…`. With `extendr_module!` inside the FFI module (decision 11), the function also needs a `pub use` at the crate root. `Makevars.in` names `STATLIB = $(LIBDIR)/libthinkthen.a` as well as `-lthinkthen`. Fix: list `document.rs` and both `Makevars.in` lines as edited. Say where `get_thinkthen_metadata` is exported.

9. **Small fixes.**
   - The ratchet files. ADR 0047 item 4 puts `ratchet.json` beside the binding's `Cargo.toml`. The ticket puts it in `libraries/r`, three levels up. That place keeps it out of the tarball. Say so, and say how `lint` finds it: the registry entry names it, as it names the manifest.
   - The unit tests need R installed, since extendr-ffi's build script runs R and the binary links `libR.so`. Write "need R installed but not running".
   - Add 0105's worker note as a unit test: when the caller has left after an interrupt, the worker ignores the failed channel send and does not panic.
   - The R1-13 step should count call expressions. Otherwise the `extern` declaration of `R_CheckUserInterrupt` counts as a second site.
   - The R package budget has 11 lines of room (639 of 650). Name it as tight. The stop rule covers it.
   - The root table denies `allow_attributes_without_reason`. The tag's `#![allow(missing_docs)]` then needs a reason.

No private member is used.
- **Direct binding over the C door.** The three reasons in decision 1 are sound, and the lever is named.
- **Dependencies.** Versions are named for extendr, paste, jsonlite, and the Suggests packages. Deny runs with `sources` and a git-source plant. The forbid-level lint probe and its stop rule are in place, and the second-review line is present.
- **Offline without Docker.** Every tool and crate the check needs is present, except the jsonlite caveat in finding 6. The tag's `check.sh` already handles `gtimeout`.

- **Writing and names.** The writing rules hold. No private project, customer, or home path appears.

## Final check

REJECT

Read 0108 at `e0503f06` (the remote ref matches) as a diff against `57f1e2e9`. Also read the shared rules at `446a4d6b` and the `Engine` and `EngineBuilder` declarations in 0084 on its branch (`9d43692a`).

The confirmation's blockers are fixed as written. The hidden `thinkthen:::` hook is gone. `tt_engine(width =)` is public and has a test and a plant that can turn red: drop the width, and the count stops at 4. Both stop clauses about a missing width setting are gone. Decision 17 cites `446a4d6b`. The note on the self-signal tests moved into the Review section for the code reviewer. Nothing else in the ticket changed.

New findings:

1. **`tt_engine` as designed drops the environment settings, so the width tests would leave loopback.** In 0084, `Engine::builder()` starts empty. Only `Engine::from_env()` and `default_engine()` read `THINKTHEN_BASE_URL`, `THINKTHEN_API_KEY`, and `THINKTHEN_CACHE`. The builder has no way to start from `from_env`'s values. So `Engine::builder().width(8).build()` gives an engine with the built-in address and the default cache. The batch interrupt test and the R2-23 tests would then send to the non-loopback built-in address. That breaks the loopback rule and the per-test cache. It also breaks for users: `tt_engine(width = 8L)` would silently drop a user's `THINKTHEN_BASE_URL`. Decision 4 says these settings "stay on their environment variables", which is true only for the default engine. The shim could read the three variables itself. That repeats the engine's environment rules in a second place, against ADR 0047 item 7's rule that host-neutral pieces live in the public API. Fix, recommended: make 0108 depend on the 0084 amendment that adds a builder starting from the environment, and build `tt_engine` on it. List it under Dependencies with 0098. State that settings `tt_engine` does not name come from the environment, as the default engine's do. Add an acceptance test: a child sets `THINKTHEN_BASE_URL` to the backend, calls `tt_engine(width = 8L)`, and the backend counts the requests. Plant: build from the empty builder, and the count reads 0.

2. **Shared rule 6 at `446a4d6b` asks for every section 5 setting, and the ticket defers most of them.** The rule reads "Every surface exposes the engine settings in ADR 0017 section 5, width included, on its engine value." Section 5 puts on the engine value: the address, the model, the width, `max_requests`, the cache folder (with no-cache), and `cache_bytes`. Only the key is environment-only. Decision 4 exposes width alone and leaves the rest to "a later ticket … when a demo needs them". Once finding 1's builder exists, each extra argument is one builder call. Fix: give `tt_engine` `base_url`, `model`, `max_requests`, `cache` (a folder, or `FALSE` for no cache), and `cache_bytes`, each defaulting to `NULL` for "from the environment". Add one refusal test per argument with a count of 0, and one test that a set `base_url` wins over the variable. Or record a named exception to rule 6 in the ADR 0047 R section with its reason, and have the coordinator accept it. The recommended fix avoids an exception.

3. **Small points for the text.**
   - Say what `tt_engine` does after a verb has already run on `default_engine()` at the omitted width. Under 0077 the rule may differ from the "second `tt_engine`" case. Pin that case with a test.
   - Say that `tt_usage` reads the engine in the slot once `tt_engine` has run. Otherwise the counters of two engines could split.

Should 0108 depend on the 0084 amendment? Yes. Without it, `tt_engine` has two options. It can ignore the environment, which breaks the tests and users (finding 1). Or it can re-read the variables in the shim, which duplicates the engine's rules in every binding. The amendment is small and host-neutral, and every surface that meets rule 6 needs it. Ordering 0108 after it costs only the wait.

ACCEPT once findings 1 and 2 are applied. Item 3 can be applied at build time.

Two notes for the code reviewer, neither blocking:
1. The engine-environment plant builds from the empty builder. That engine targets the built-in non-loopback address. The ticket relies on "no network and no key" to send nothing. The record should show that the engine refuses before any send when the key is missing. If it does not, the plant should set `base_url` to a closed loopback port in place of the empty default.
2. The `model = ""` refusal assumes `EngineBuilder::model` refuses an empty string. If it accepts one, the R type check must refuse it, and the test still pins `thinkthen_usage`.
