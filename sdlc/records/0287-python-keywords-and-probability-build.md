## What changed

The eight decide, choose, score and tag scalar/many methods and filter pass their applicable question keywords through the landed Rust `Settings` parser. `true` and `false` replace `true_` and `false_`; choose, score and tag take descriptions inside their member map. Recognition retains its own `descriptions=`. Unknown, wrong-verb and repeated question keys refuse at the public boundary. A built `Question` keeps its identity. Explicit null description fields still reach the shared parser, rather than disappearing in Python's default filtering. The old `deadline=` spelling has a plain rename refusal. Every public call uses `deadline_ms` at its numeric boundary; the worker and frame recognition preserve one deadline for a whole call. `Engine(max_requests_total=)` forwards a checked full-range unsigned value, including zero, to the existing atomic reservation machinery.

The owned `Call` gains `.probability`: yes probability for decide, selected option probability for choose, `None` for an unresolved choice, and `None` for score/tag and other routes. A vector gets aligned probabilities; pandas columns retain missing positions as nullable `Float64`. The binding reads its own immutable observations after the one engine operation; there is no second request, provider lookup, pricing copy or caller-text error classification. Existing `.value`, `.facts`, `.details`, cancellation and failure kinds remain. The Python stub, module wrappers, native constructor and README reflect the accepted spellings. The original private Arrow ownership fixture passes its required token argument and reads the native `Call.value`; the production carrier was not rolled back.

## What the build taught us

The source report's frame-schema failure mixed a genuine new `failed` column with an unproven inference that every answer failed. The generic backend and weighted-score code supplied independent expected values; the corrected test pins both values and the null failure marker. The original cap and held tests counted groups as requests although the default planner packs short rows. A three-row exact body pair and eight independent held groups test the intended properties without changing packing or weakening counts. The Python beta was the Pydantic mismatch; a reused venv must prove its own interpreter identity before its green cases count. The core settings parser admits explicit null description fields, so a wrapper may not discard them or call them invalid just to simplify a refusal table. The existing owned observations already carry probability, and the existing process reservation already owns the cap; no second send or local counter was needed.

The full `check.sh` package campaign, pandas 2 lane, stress/RSS campaign, release wheel, other platforms, provider acceptance and later Judge/Stream work remain unrun. This candidate does not close the broader clean-package issue or claim those qualifications.
