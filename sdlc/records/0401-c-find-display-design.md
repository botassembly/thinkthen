## Source facts that constrain the implementation

`cli/find.rs::read_units` directly iterates `edge::Chunks::new(source, true)`. It does not call `edge::numbered`, `Reading::skips` or shared Intake. Chunks yields each physical LF-terminated line, including blank lines, and a final nonempty line without LF. A trailing LF creates no phantom line. Reading strips LF and an immediately preceding CR for record content. An unpaired final CR survives.

Find does not skip blank lines. A blank or whitespace-only text line reaches Evidence::new and refuses as blank evidence through the existing stopped diagnostic. Blank JSONL refuses through the existing JSON parser. Preserve that behavior under all new flags. Do not silently adopt Intake's blank skipping. A line number can therefore use the direct physical chunk ordinal plus one. For every admitted candidate, first and last equal that line number. Source ordinal is zero, file is the original optional path's lossy display string, and stdin file is null. Do not change the original PathBuf used to open the source.

`read_units` checks count overflow before it adds the next chunk's original bytes, then checks the aggregate original-byte bound before record/evidence decoding. Its `stopped` position is the candidate count plus one, and finished remains zero. Retain that ordering, diagnostic and classification for runs without around, including ordinary runs with line numbers or scores. There is no earlier per-record send to preserve or prefix to print.

`core::Find::select` chooses the first real input index at an equal highest probability. A strict none lead or any highest tie involving none returns selected None. Its details pick can still name the first wire leader in a none tie. Derive display score and position from selected(), never pick text or the provider's choice field. Duplicate evidence strings remain separate generated candidates. Never search for the winning text to locate its row.

All valid find candidates already enter its aggregate request. A neighboring valid line may already be a candidate. Around must add no neighbor bytes, fields or candidates to that request. The request must remain identical to the ordinary aggregate request. JSONL unselected fields stay absent from pointed evidence, even when those bytes appear in displayed context. An invalid neighbor prevents the whole aggregate request before sending, under the existing parsing rules. C cannot adopt B's later-record failure semantics or claim that valid neighbor candidates are absent from find's request.

## Immutable snapshot and original bytes

Only around activates a new bounded snapshot. Open the same single source once through edge::source. Expose Snapshot::prepare at pub(crate) visibility and pass one `(optional PathBuf, opened reader)` occurrence. Reuse its retained Arc-backed cursor as the input to find::read_units and retain the Snapshot on Display. Do not invoke Intake, reread the path, use file metadata as proof or create a spool file.

Snapshot preparation reads original bytes before candidate parsing. Exactly MAX_RECORD_BYTES, 16,777,216 bytes, passes; the next byte refuses at exit 2 with `--around reads at most 16 MiB across all input sources`. Count original CR, LF, blanks and every source byte before trimming or decoding. The existing snapshot's one remaining budget plus overflow byte and constant-state interval scan already implement the needed bound. Read errors retain Failure::Input. Snapshot overflow and invalid flag conflicts send zero requests and print zero stdout. Find's existing aggregate checks still run over the snapshot cursor.

Around deliberately adds an earlier full-source bound. On an oversized source with an early blank or count overflow, its new snapshot refusal can precede the existing content/count refusal. That precedence applies only to around and is the ticket's new view bound. Ordinary, line-number and scores-only runs keep the existing lazy chunk reads, early count/error order and FindTooLarge diagnostic. Do not replace their bound or error path. Since find ordinarily retains all admitted candidates before its one request, this change adds no ordinary source immutability requirement.

A file rewritten after the aggregate request reaches the listener must not change selected bytes, line location or neighbor output. Both candidates and context use the prepared immutable bytes for around. The ordinary path already retains each unit's original bytes, so selected bytes must remain identical under the same mutation without around. Never reopen a named file after the answer returns. Snapshot holds at most 16 MiB of original bytes; find's existing candidate/record/evidence allocations remain, so total process memory is larger than the snapshot cap. Retain constant-state source scanning rather than adding a line-offset table.
