## Source and literal proof

The recipes use `thinkthen_choose` because a stored answer is a label or `NULL` for a choice below the cut or an exact tie. Input-`NULL` behavior depends on the host and argument. Current source pins the shown calls: `databases/postgresql/src/lib.rs::thinkthen_choose` takes `(question, evidence, options text[])`; `databases/duckdb/src/scalars.rs` registers `(text, text, list(text))`; `databases/sqlite/src/scalars.rs` registers two or three arguments, with the choose members in its question JSON. The SQLite JSON form is already exercised in `databases/sqlite/tests/test_values.py`. The function calls in the pages were source-checked, not run here. Literal-only SQL isolates the host constraint from ThinkThen and any backend.

Disposable files and the PostgreSQL cluster live under `target/codex-builds/qf-sql-answer-constraints/`; its Unix socket used `target/pg-j7-sock` because the first longer socket path exceeded PostgreSQL's 107-byte limit. ## What the build taught us

The existing SQLite extension marks its functions direct-only, so the recipe checks a stored value rather than calling ThinkThen inside a schema CHECK. The initial PostgreSQL socket path under the build folder was too long; a short socket path under `target` preserved the isolated cluster. The pinned host tools were already available, so no extension rebuild or new test framework was needed. The source review prevented copying one host's `choose` argument form to another: SQLite carries options in the question JSON, while DuckDB and PostgreSQL take a separate list or array. Independent review caught an omitted `choose` case: an exact tie is not sure even above the cut. The first correction and its review guidance generalized SQL `NULL` input propagation too broadly. PostgreSQL parses its question first, so a `NULL` question raises `usage`, while `NULL` evidence with a valid question returns `NULL`. This was incomplete host-contract guidance, not solely a builder miss. The recipes now state only the stored-answer rule and defer other input-`NULL` behavior to each function's contract. The literal host proof remains valid and was not rerun for this prose correction. The exact SQL function calls remain unexecuted in this Quick Fix; the existing surface tests own their behavior. No unrelated J1 type or neighboring settings rule changed.

`python3 sdlc/scripts/tickets` reported zero evidence failures; `python3 sdlc/scripts/pages` reported one coming and 21 green; `git diff --check` passed. A read-only local Markdown link pass over the six changed pages and records checked 16 relative links and anchors with zero failures, including all three new recipe links.
