## 0108 (R), decision 18: REJECT

1. Rule met? The key and address parts hold. The real key is removed, the fake key `tt-test-not-a-key` is set only in `with-backend.sh` beside the loopback URL, and a host guard refuses non-loopback addresses before R starts. The empty-builder plant is gone. Every remaining plant keeps `from_env()` and a loopback address.
2. Can it fail? Yes. The `cache_at(<default folder>)` plant moves the entry out of folder A, and the loopback count stays 1 in both runs. The guard test expects a refusal. No plant is named for it, but deleting the guard turns it red.
3. Nothing lost? Yes. The removed acceptance line and the removed empty-builder note are the intended removals. Address seeding through `tt_engine` is still covered by the width test and the `base_url` over variable test.
4. Consistent? **No. This is the blocker.** Decision 18 says `check.sh` "runs every step ... with `HOME` and `XDG_CACHE_HOME` pointed at a scratch folder. That covers the tarball install, the conformance runs, and every child." Other parts of the ticket depend on the real `HOME`:
   - Decision 10 and decision 17: the R library path starts with `~/.cache/thinkthen-toolchains/r-library`, and jsonlite 2.0.0 lives in the user library `~/R/x86_64-pc-linux-gnu-library/4.3`. R derives the default `R_LIBS_USER` from `HOME`. With a scratch `HOME`, R finds only the system jsonlite 1.8.8, and `library(thinkthen)` fails in every child, the seed test's two runs included.
   - The R4-7/R5-38 row and decision 17: `cargo vendor` runs "from the builder's own cargo home", and the cargo cache test runs "against the builder's cargo home". `CARGO_HOME` and `RUSTUP_HOME` default under `HOME`, so offline builds, `cargo test --lib`, and the rustup proxies lose their cache and toolchain.
   - The deny plant reads the local advisory database under the cargo home.
   Under decision 18 as written, those steps fail or report "not run" for the wrong reason. Fix: limit the `HOME` and `XDG_CACHE_HOME` redirect to the R test children, or have `check.sh` first export absolute `CARGO_HOME`, `RUSTUP_HOME`, the R library list (`R_LIBS`/`R_LIBS_USER`), and the toolchain root from the real `HOME`. The seed child needs the same R library export.

Notes that do not block:
- `XDG_CONFIG_HOME` is not isolated. A user who exports it could supply a configuration-file `url`. `THINKTHEN_BASE_URL` or `base_url` is set in every child, so the only risk comes from a child that omits both. 0109 decision 14 sets it to a fresh folder, and 0108 should do the same.
- The guard accepts `localhost`, and `/etc/hosts` can remap that name. Accepting only `127.0.0.1` and `[::1]` is stricter.
- `cargo test --lib` builds nothing that the ticket says must stay offline. Nothing checks that a unit test never builds a sending engine on `Engine::builder()`. The same note applies to 0109 and 0112.

## 0109 (SQLite), decision 16: ACCEPT

1. Rule met? Yes. `check.sh` unsets the key, and the helper removes it again from every child. Each child gets a loopback `THINKTHEN_BASE_URL` and a fresh `XDG_CONFIG_HOME`. SQL has no address or key setter (decision 2). Only the secrecy test sets a sentinel key, beside its loopback URL. The planted run counts 1 on loopback.
2. Can it fail? Yes. In the seed plant, the entry misses A. In the helper plant, the child reads the sentinel.
3. Nothing lost? Yes. The second-backend plant is replaced, and the rest of the diff is additive.
4. Consistent? Yes. It follows 0105 change 13, and the decision 14 isolation it relies on already exists.

Notes that do not block:
- "The backend counts 1 in both runs" assumes the empty `Engine::builder()` caches by default. 0084 lists `default_cache()` as a setter, which suggests the empty builder might start with no cache. In that case the planted run counts 2 and writes nothing to the scratch folder. The test still turns red because A stays empty. The builder should record the observed count.
- The plant copies `THINKTHEN_BASE_URL` into `Engine::builder()`. It should refuse, not fall back to the built-in address, when the variable is missing.

## 0112 (Ruby), decision 15: ACCEPT

1. Rule met? Mostly. The key is unset in `check.sh`, and `tests/backend.rb` sets the fake key only with the child's loopback URL. The `EngineBuilder::new()` plant is gone. The new plant keeps a loopback `base_url:`.
2. Can it fail? Yes. On `Engine::builder()`, `THINKTHEN_CACHE` is ignored, and the entry misses A.
3. Nothing lost? Yes. The seed test and plant were rewritten. The width, max_requests, cache, model, and base_url tests are unchanged.
4. Consistent? Yes. The `Engine::builder()` wording matches 0084. Decision 15's reference to `EngineBuilder::new()` describes the old plant.

Notes that do not block:
- The rule requires the planted run's send to be "counted on the loopback listener". 0112 says only "any send lands on the loopback count". Pin the number (1 or 2 depending on the empty builder's default cache, as noted under 0109), and have the record show it.
- Decision 15 names the slide sample and the conformance runner as key-free. It does not say where their address comes from. The conformance runner uses the 0092 case arm. The slide sample should also run under `tests/backend.rb`, or `check.sh` should refuse a missing or non-loopback `THINKTHEN_BASE_URL` before that step, as 0108's guard does. Without either, a missing variable sends an unauthenticated request to the built-in vendor address.
- As in 0108, `XDG_CONFIG_HOME` is not isolated.
