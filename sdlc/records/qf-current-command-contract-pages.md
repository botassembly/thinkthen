## Contract reconciliation

`rank @FILE` now describes both saved question kinds. A `decide` file and a plain question retain yes/no ordering. A saved `score` file supplies ordered levels, descriptions, model, field selection and its file batch tier; typed yes/no meanings are refused before a send. Graded rank uses the score command's normalized weighted value, puts the highest first with input-order ties, and applies `--top` only after judging every record. Score itself continues to print record values in input order. At equal framing, field, context, batch, model and backend settings, rank and score use the same graded requests. Details retain each original input and show `question.verb: score`, `answer.kind: score`, numeric `value` and null threshold; ordinary rank still shows a yes/no answer with null value. The command-only route changes no library rank behavior, question-file grammar, result schema, optional weights or fusion method.

The five pages promised by 0223 are updated together: `rank.md`, `score.md`, `question-file.md`, `result.md` and `records.md`. The specification command index and root function table no longer imply that all command rank calls are yes/no. The existing executable `spec/result.md` and the yes/no rank examples remain accurate for the questions they ask. The library READMEs and source examples still describe their unchanged library rank behavior. The site tutorial and reference page describe ordinary yes/no rank; their broad reference row still says rank is always most likely yes first, a marketing-owned claim for its owner to reconcile.

Register 52 asks both cache and recording guidance to state the exact-byte rule with line-ending and JSON-spelling examples. `specification/recording.md` explains the shared digest and gives both cases; the root README's answer-cache section now links to it and repeats the practical misses. The digest is of adapter name, URL and encoded request body, rather than every raw input byte. One-document text retains `hello\n` versus `hello\r\n` and literal `{"a":1}` versus `{"a":1.0}` as different evidence. Record framing can strip line terminators or parse and re-encode JSON before the digest. Recordings should be transferred for the same encoded request and settings. No canonicalization behavior or whole-input byte claim was added. The separate marketing cache section in `site/src/pages/reference.astro` still lacks this criterion and is outside this lane; register 52 should not be declared fully closed until its owner resolves that remainder or rules the two repo-owned pages sufficient.

## What the build taught us

The held 0223 handoff named five pages but the command index and root table also carried yes-only summaries. Auditing those summaries prevented a stale entry point. Register 52's original examples cannot safely be described as arbitrary input-file byte differences: the input edge normalizes some framing before the adapter encodes a request. Consumer ownership matters here: the repo contract and root cache guide can be corrected in this lane, while the marketing reference section remains a distinct follow-up.
