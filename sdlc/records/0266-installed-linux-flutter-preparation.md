The Flutter SDK and Linux engine are host tools; the app's wrapper and Dart product files come only from archives. ## Pairing and smoke dependency

The existing private release helper's five-line wrapper manifest binds source commit, target/version and C archive digest. Flutter needs to name the Dart archive digest too, because its retained sibling `path:` dependency must resolve a corresponding versioned source package. A Flutter-only seven-line manifest with `dart_archive` and `dart_sha256` after the C fields is a bounded fixed-data extension. The packer must build C then Dart then Flutter from one clean source commit, stage no previous OUT file, and reject reuse for this pilot. The validator checks C/Dart/Flutter outer sidecars, exact selected family cardinality, Flutter member inventory and private metadata, shared source/target/version, Dart's existing C manifest, and Flutter's actual C and Dart digests. A later checkout HEAD need not equal an older valid manifest; the clean build receipt establishes provenance, and neither digest is a signature.

0264's smoke rule will call `php-dart` when it sees Dart. A three-file C+Dart+Flutter pilot has no PHP, so simply adding a Flutter mode would fail for missing PHP before it reached that mode. The new rule must call `dart-flutter` for Flutter, `php-dart` for PHP or Dart alone, and both for a full bundle with PHP and Flutter. This preserves an isolated Dart-only missing-PHP refusal and lets the direct Flutter pilot use three archives. Both selected modes remain conditional; the existing nine-family full-bundle presence requirement is unchanged. A missing-Dart plant with C+Flutter can exercise the actual smoke entry and demonstrate the Flutter preflight runs before `backend_start`. Other pairs and the 0265 three-wrapper mode must remain intact after their branches land.
