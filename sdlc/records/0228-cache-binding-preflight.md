# 0228 cache-binding preflight

Source `76a3bc7c`; notes only. [Ticket 0228](../tickets/0228-cache-first-use-binding.md) and [proposed ADR 0099](../planning/adr/0099-cache-binding-admission.md) describe one admission-order correction for the missing-key first use. Neither is accepted yet, and neither implements or closes register 10.

The critical sequence is `facade::ask` / `ask_batch` → `request::ask_prepared` → `Recorder::prepare_checked` → `Recorder::gate` → `identity::check` → `key()` → HTTP admission/send. The marker is published before the key closure today. `Recorder::of_private` at engine construction checks only whether a path is a file and does not bind it. A cache hit in a previously bound folder bypasses the key; strict replay creates no marker. An unmarked folder containing a digest-shaped entry is legacy and cannot be treated as empty. Cancellation at the gate can prevent publication; cancellation after it does not undo a published marker. The HTTP layer can refuse before a send after preparation, so this slice does not promise all no-send paths are clean.

The smallest proposed code path is a read-only empty/unbound probe in the recorder and one optional early key lookup in `request.rs`. The original gate rechecks and publishes before any send. An early key is spent if another same-address writer installs a hit between probe and gate; the answer still replays. On early missing-key failure, a second read-only observation notices a newly published marker and sends the caller through the original gate: a matching writer's in-progress digest can become a keyless hit, while a different-address winner is refused. If the second observation still sees empty/unbound, `NoKey` returns without a write. A marker published after that observation may yield a hit only on a later call; no atomic snapshot is promised. No marker schema, model identity, replay bytes, error kind or public API changes.

## What the preparation taught us

The old issue asks for a total zero-send invariant and a bound-address diagnostic, but the accepted marker and pre-send accounting boundaries do not support either from a missing-key-only adjustment. A technically reviewed ADR is needed to narrow 0065's before-key admission rule; a digest-only marker cannot disclose an address. The proposed slice is useful only if the review agrees that first-use absent-key binding deserves its own completed behavior while the broad register remains open.
