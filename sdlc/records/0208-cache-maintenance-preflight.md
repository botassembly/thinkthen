## Confirmed code and why the gaps remain

`crates/thinkthen/src/engine/recorder.rs:123-159` takes a shared folder gate per operation. `prepare_checked` retains it in `WritePermit` while an answer is in flight. `prepared_write` at 377-412 creates `.<pid>.<attempt>.<digest>.json` before send; `finish`, `cancel` and `Drop` attempt cleanup at 260-292 and 440-446. `complete` writes and syncs the temporary file, then hard-links a new final name or atomically replaces a damaged one; a process death between those actions can leave a private partial, sometimes with full judged bytes. The partial name's PID/attempt components are not an ownership ledger. `cache_lock.rs` provides shared and exclusive locks on an already-open directory handle; process death releases its OS-held gate. That gate, not PID existence or age, distinguishes an in-flight writer that follows this protocol from a leftover name. `recorder.rs::install_or_compare` may leave a partial hard-linked to a valid final; unlinking only the partial name leaves the final name.

`engine/cache_prune.rs:105-196` obtains an exclusive folder gate, scans all digest-named final files, applies the alias/unknown-model guards, forms the age/model union, trims by allocated bytes in modification-time/digest order, then attempts a nonblocking digest lock for each selected final. It can skip an active digest and report fewer removed entries than selected. The scan at 221-239 skips all dot names. `inspect` uses the scan under a shared gate, so `status` can observe a live temporary file when the scan is extended. The 0163 `open_entry` at 290-307 guards final reads against a replaced Unix symlink/FIFO; its cross-platform identity helper is weaker off Unix. No existing helper authenticates an arbitrary temporary-file name against hostile external mutation. Named-folder writer authority remains a separate gap.

Register 98 predates the landed unknown-model guard: `cache_prune.rs:112-120` now refuses both an alias and a MODEL no good reply names before removal. A selector naming a model that at least one reply names may still select many older entries; age and size can also remove every valid entry. `cli/args/command.rs::PruneArguments` has no preview flag; `cli/cache.rs::prune` calls `run` immediately and prints only committed counts. The 0124 deferred paragraph proposes `--dry-run` but did not accept a changed default. `specification/recording.md:94-96` preserves explicit immediate prune, exact union/order, bad-entry handling and unknown-name ignoring. Those are retained until a reviewed contract says otherwise.

`tests/backend/default_cache/prune.rs` already proves alias and unknown refusals, exact final-entry counts, model selection, bad-name sorting and no secret disclosure. `engine/cache_prune.rs` unit tests prove strict age, selector union, size boundary, active digest skip and deterministic oldest-prefix behavior after a late error. `tests/status.rs` pins the closed JSON/text status shape. `tests/backend/cache_locking.rs` has held loopback requests and a bounded rendezvous; use that pattern for one live-writer gate proof. Plant a valid final request digest before changing a response property, as learned in 0163; a malformed-name row must be separate. A held writer's temporary file is created before its request is observed. A planted complete-byte partial is stronger for content cleanup than a kill before the backend reply, and neither should be mislabeled as a reproduced kill during `write_all`.

## First slice and focused checks after acceptance

Freeze the public output rule first. Add a read-only preview path through the existing scan/selection, then make a one-case CLI preview red/green with two valid final entries and exact unchanged bytes. Next add exact-name temporary collection under the same gate and a single outside-in table for abandoned, live and unsafe names. Reuse `allocated` for bytes, name-only diagnostics, and the existing status shape helper. Keep partial selection independent of final model/age/size choice and evaluate model refusals before any deletion. No new dependency, portability promise, parser, test-only hook or full suite is needed for a design pass.

After implementation, proportionate checks would be `cargo fmt --all -- --check`, `python3 sdlc/scripts/policy.py`, a measured ratchet/file-cap check, `cargo clippy --locked --offline -p thinkthen --all-targets --all-features -- -D warnings`, `cargo test --locked --offline -p thinkthen --test backend default_cache`, `cargo test --locked --offline -p thinkthen --test status`, and changed specification/settings checks with verified unchanged command provenance only where relevant. Direct heavy commands take `flock -o` on `$THINKTHEN_HEAVY_LOCK`; rungs self-lock. These are proposed validation commands, not checks run for this draft.

## Open design questions and preparation value

Independent review must settle additive `--dry-run` versus default preview with a commit flag; whether committed cleanup prints each temporary name; and whether an exact-shape unsafe object needs a separate diagnostic. The ticket recommends additive preview to preserve the accepted immediate explicit prune. It proposes temporary fields rather than `orphan` fields because shared-gate status can overlap a live writer. A separate process writing to the folder without the gate remains outside the proof; ADR 0084 is not needed unless review changes the settled lock architecture or default-prune meaning.

Preparation saved a possible false orphan rule by finding the folder gate and the write permit's drop order. It also caught the 463/500 parent limit and the already-landed unknown-model refusal, so the next build need not discover them while coding. It did not measure implementation growth or validate the proposed public strings; design review and a later outside-in build must do those jobs.
