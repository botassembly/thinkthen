## Prepared paid measurement

`probes/choose/job.sh` calls `measure.py` only through `sdlc/scripts/live`. The helper pins experiment 262's 200 IDs and the selected question/input/options/truth digest. They form 153 complete-question groups, 147 singletons. The exact-question default and batch-10 arms therefore need at least 153 and 156 planned requests, not experiment 262's 20 uniform-width requests. Each arm permits at most 600 actual starts after a single eligible split and `--max-retries 0`; the 16-row largest-group context arm permits at most 48. The helper writes a named result with build, records, score, attempts, input and output tokens, combined tokens, answer and request identity hashes, and exact context hash. It retains progress and a context recording under ignored `target/choose/`. Each group is a separate command in a fresh home per arm. After each command the helper requires reported input and output usage on every result, exact row-share agreement with process totals, expected rows and context identity, then stops before another group at 180,000 combined reported tokens. Missing usage, mismatched totals, missing items, or a changed fixed sample refuse. A 250,000-token reservation is proposed for all three arms. `sdlc/scripts/live` precharges that amount but cannot cap a held request. The 135/200 comparison is reported, never an execution stop or product gate. The context group has 16 rows, so it has no 135/200 comparison. The original task is preserved; its mostly-singleton grouping limits any batching inference. The seven local command cases prove behavior that this paid sample does not exercise well. The helper's synthetic usage and grouping self-test passed without a provider call. Paid execution waits for fresh review and coordinator budget choice.

## What the build taught us

The accepted schema/parser/negative-test inventory prevented a schema divergence. The corpus runner initially gave the new file-batch cases one document, which ignores saved batch; it needed a stream only for those cases. The first proposed late-refusal case mistook a soft request-size cut for a hard singleton limit. Ticket 0154's edge table and ADR 0051 preserve the soft-cut singleton exception; the corrected local refusal uses an explicit profile. The paid fixture review exposed another hidden assumption: experiment 262 contains 153 question-and-options groups, while the CLI has one question text per invocation. Keeping its original questions requires grouped commands and honest request counts. The source cap also required a coherent framing helper move after the planner extraction. None of these findings changes the accepted outcome.
