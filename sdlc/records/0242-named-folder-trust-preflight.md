# 0242 named-folder trust preflight

Status: factual preparation and proposed design at main `a0a552d7`; no runtime, provider or user-cache mutation. Fresh design review is pending. The local original finding is experiment `283-serious-issue-analysis/40-folder-writers-decide-answers.md`, despite older cache-preparation records calling it experiment 284. The issue's done criterion is writer-authority pages plus a decision on the writable-folder check; ticket 0163 landed the pages and expressly deferred the warning. Register 40 also mentions optional keyed integrity, which this ticket does not claim.

`engine/recorder.rs::gate` enforces `identity::require_private` only for the platform default, then opens the shared folder gate and checks its backend marker before `prepare_in` can trust an entry. `Entry::replayed` checks adapter, URL and request bytes, not authorship. Current `specification/recording.md` and `SECURITY.md` disclose that folder writers decide answers; no named-folder warning exists in code. `cli/asking/folders.rs::of` resolves explicit `--cache`, `--record`, `--replay` and active `THINKTHEN_CACHE`; `cli/asking.rs::engine` is the common engine construction path for the asking verbs and already emits 0238's fixed live-refresh warning before a request. `config.rs::writable_by_another` checks file ownership and world write, intentionally tolerating an ordinary file's group-write bit; a directory needs a distinct `0o022` test. Existing Unix default-cache mode `0700` refusal stays separate. The 0238 lock file is retained across successful and failed writes and unlinked by selected-entry prune under its exclusive folder gate; this ticket does not enter that path.

The chosen preflight is a read-only metadata observation of the selected existing final folder. Unix owner mismatch or group/other write warns once before judgment; absent folder, owner-private folder and modes with no other write stay quiet. Metadata lookup errors do not create a second error taxonomy or print the path; current folder admission retains authority. Non-Unix ACL permissions cannot be inferred from `std::fs::Metadata::permissions().readonly()`, so there is no automatic permission-specific warning there. ACLs, parent swaps and races make the Unix signal advisory too. Rust library and binding APIs retain their output contract and already carry the writer-authority prose. The proposal does not add unsolicited library stderr or a new public result member.

The focused proof uses a valid planted entry, not an invented malformed object, so the warning must precede a real cache/replay hit. The table pins private versus `0770` and `0777`, option versus environment folder selection, keyless replay, one no-key record failure, exact warning count, zero loopback sends on hits, and unchanged replay bytes. A small pure owner/mode table covers foreign uid without privileged test setup. Existing `default_cache.rs::replay_locks_a_read_only_directory_without_changing_it` and `an_existing_wide_default_cache_is_refused_without_changing_its_mode` retain the separate no-write and default-refusal contracts. Proposed source growth is 25–35 nonblank lines; test growth 80–110. The exact ratchet follows code, not the estimate.

Alternatives considered: refusing every writable named folder would break an expressly user-selected shared cache; warning every named folder would bury useful signals for private directories; printing from the engine or changing public result JSON would broaden library and binding contracts. The fixed CLI warning is the smallest observable response to the filed command-option criterion. Documentation ticket 0241 owns shared page cleanup; coordinate its recording and security page edits only after this design is accepted.
