## What the build taught us

DuckDB scalar `:=` remains positional in the pinned host; only an internal catalog macro gives real named binding. `typeof(NULL)` reaches the native function as the quoted type name `"NULL"`, and a NULL optional settings argument must use defaults instead of dropping the row. The cache answered the second six-song form from the first form's exact packed request, so a distinct fresh scratch cache was needed to compare both emitted bodies. A score with generic fixed probabilities 0.9 and 0.1 has weighted position 0.1, as the existing engine formula specifies. The shared settings parser, not the old literal-context validator, supplies the new blank-context sentence. The binding policy accepts unsafe C entry code in files named `ffi.rs`; the implementation moved those boundaries there and removed obsolete entries rather than weakening the checker.

A static check of the selected installed route found three budget case names defined in `verbs_budget.py` but not registered in `verbs_suite.py`. The existing cases are now registered; all 32 named selectors across the four selected suites resolve. This repairs selection reachability without replacing or rerunning the retained budget tests.

The 0289 planner's public output made P1 a direct bridge conversion, while its active reservation kept planning independent of actual spend. Keyed SQL names remain text (including numeric-looking keys), and the shared visitor detects duplicate names before `serde_json::Value` can erase them. DuckDB's statement owner clears its resolved file cache at query end; its retained selected permission/open proof still passes after C retirement. Landed 0299's `max_estimated_input_tokens_total` constructor key is not a DuckDB per-call setting; an installed Usage/zero-send refusal proves this host does not advertise an inert new setting. Future host adoption needs its own scope. The remaining qualification is four-platform release archives, package installation, full conformance and other runner hosts. Linux source and copied-extension receipts do not establish those outcomes. No package, full test/spec/surfaces gate, SQL server, provider, live wrapper or Actions ran.

The High review found that `typeof(NULL::VARCHAR)` alone cannot tell a NULL placeholder from a non-NULL settings object after the macro has shifted arguments; the macro must carry the NULL distinction into the native guard. The earlier test checked native list and JSON settings separately, so the I9 explicit typed NULL boundary earned one edge table. A shared settings conflict checker must compare keys stored outside question fields; the reviewed core correction was merged before the host's exact batch collision proof. DuckDB catalog errors can carry multiple lines, so an error suffix appended after the entire exception is absent from the first displayed SQL line. The formatter now places it before that host hint. The published ADR 0105 error sentence and plain-removal exception resolved the formatting discrepancy without a new design.
