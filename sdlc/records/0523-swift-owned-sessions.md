## What the build taught us

The earlier review rejected unsafe SwiftPM linker flags for a versioned dependency. The supported C bridge and bundled resource replaced them. It also rejected an archive call that installed the native header under the wrong loader-header path; the archive now carries each header at its intended path. Those repairs remain in the installed package.

The closure review found that a fixture named for byte images actually passed file descriptors. The same defect existed in the C++ fixture and its consumer. Both now use generated byte descriptors with base64 and media for byte cases, while source paths remain native file readers. This was a missing input-form check, not a demonstrated SDK image failure. The correction uses the existing shared assertions and adds no proof framework.

Absent shared context must stay absent. An explicit null selected from a record must be read through the native field/context-field rules, preserving the canonical refusal and zero sends. The fixtures now preserve these distinctions rather than translating them into a different contract.
