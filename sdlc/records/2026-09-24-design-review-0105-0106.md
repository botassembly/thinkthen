### 0105: REJECT

All eight first-round findings are fixed, and I checked each one against the text. The pandas check runs first with its own pinned sentence, so the R1-6 plant now turns its test red. The six cross-surface Python halves are listed with plants. The R1-10 trigger is a unit test. The single-call Ctrl-C test now ends: SIGINT at 0.2 s, reply released at 0.5 s. `lint` adds deny and the rule on forbid-level lints. Versions and the second-review line are named. `--offline` is stated for cargo and maturin. The small fixes landed. Two problems remain.

1. **New: the deny plant cannot turn red.** Main's `lint` runs `cargo deny --offline check advisories bans licenses`, and the ticket copies that set. A git-sourced dependency is refused only by the `sources` check (`deny.toml` `[sources] unknown-git = "deny"`), and that check is not in the set. Fix: add `sources` to the binding's deny call, or plant a crate whose license `deny.toml` does not allow. Also name how the call reaches the root `deny.toml` from `libraries/python`, for example with `--config`.
2. **Decision 6 (Ctrl-C waits for the in-flight send, up to 30 s): restore a prompt interrupt now.**
   - *Why.* R4-23 was filed as a MED defect when the tag took 4.3 s to answer Ctrl-C. Up to 30 s reopens a closed row on the surface people use most interactively: a REPL, and Jupyter's interrupt button, which sends SIGINT. Only single-send calls regress. Batches already stop within one 50 ms tick through `CallOptions::interrupt`.
   - *The public API allows it.* 0095's text says "The worker-thread pattern stays legal for a host that prefers it", and ADR 0047's checklist allows it too. `default_engine()` returns `&'static Engine`, and `Engine` is `Send + Sync`. `CancelToken` is `Clone + Send + Sync`. Questions are `Clone`. A detached worker can own a clone of the question, the text as a `String`, and a clone of the token, and build its own `CallOptions` inside the thread. No change to `thinkthen` is needed.
   - *Design.* Every single-send verb (`decide`, `choose`, `score`, `tag`, `details`, `recognize`) runs on a spawned worker that never touches Python. The calling thread releases the interpreter and waits on a channel in 50 ms ticks. On each tick it re-attaches and runs `check_signals`. On a raise, it cancels the token and raises `Cancelled` at once, or raises the stored error unchanged. The detached send finishes under 0073, and no retry starts because the token is cancelled. `decide_many`, `filter`, `annotate`, `rank`, `find`, and `relate` keep the interrupt check.
   - *Cost.* About 50 lines, within the 1,200 budget. One thread spawn per single call, which is small next to one HTTP round trip. Until its send ends, a detached send keeps a width permit and one request in flight. The count already assumes that, since the send happened either way.
   - *Test and plant.* Hold one `decide` and send SIGINT at 0.2 s. Assert `Cancelled` by 0.3 s. Then release, and assert the count stays at exactly one. Plant: run single calls on the calling thread, and the 0.3 s assertion turns red.
   - *Also fixed.* Today a single call raises plain `KeyboardInterrupt` while a batch raises `Cancelled`. Under this design both raise `Cancelled`.

ACCEPT once items 1 and 2 are applied.

### 0105: ACCEPT

- The deny finding is fixed. The call is now `cargo deny --offline --manifest-path libraries/python/Cargo.toml check --config deny.toml advisories bans licenses sources`, and `[sources] unknown-git = "deny"` refuses the planted git dependency. The flags sit where cargo-deny expects them: `--manifest-path` and `--offline` before `check`, and `--config` after it.
- The Ctrl-C finding is fixed by decision 6 and the split R4-23 rows.
- **No second send.** The worker's `CallOptions` carry only the internal token as `cancel`. When SIGINT cancels that token, 0095's rule applies: "nothing new starts, sent attempts finish". So no retry and no second attempt can begin. The engine's retry wait observes cancel (0076). Nothing on the path sends again.
- **No leaked worker.** The detached worker ends when its one send ends. The engine's 30 s request timeout bounds that. The worker holds no Python object, so interpreter shutdown cannot touch it. In the test, releasing the reply ends it, and the count stays at 1.

Three notes for the builder, checked at code review. None blocks the design.

1. **Race in the single-call test.** SIGINT at a fixed 0.2 s can land before the worker's send is counted. The internal cancel then stops the call before its first send, so the count reads 0 and "exactly one" fails intermittently. Fix: send SIGINT only once the backend's `count` line reads 1.
2. **A token cancel during a send still waits.** The calling thread's 50 ms tick runs only `check_signals`. A caller's `token.cancel()` from another thread reaches the worker only through its interrupt check. That check does not run during one blocking send. Fix: the calling thread's tick also reads the caller's token. If the token is cancelled, it cancels the internal token, detaches the worker, and raises `Cancelled`. That matches the SIGINT path.
3. **The worker's two edge cases.** When the caller has left, the worker ignores the send failure on the closed channel and must not panic. When the worker's end of the channel closes with no result, the calling thread raises `DefectError`. The engine already stops panics at its public methods, so this covers only a shim panic in the worker.

### 0106: ACCEPT

- The held-arm finding is fixed by decision 10, the `/arm/delay/<ms>` arm.
- **It fits 0092's design.** The path picks the arm, as for every 0092 arm. It answers by the generic rule. A bad value gets the distinct drift 5xx and a line on standard error, as 0092 rules for drift. The listener already spawns one thread per connection (`listener.rs:328`).
