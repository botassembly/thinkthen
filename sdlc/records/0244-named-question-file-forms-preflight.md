# 0244 named question-file forms preflight

Status: design-only snapshot of main `c2db47e9`, 2026-09-28. No runtime edit, provider call, broad build or case-30 execution was made for this design. Ticket [0244](../tickets/0244-named-question-file-forms.md) is proposed for fresh review.

The [open shared issue](../issues/closed/2026-09-27-shared-conformance-skips-need-equivalent-boundary-proofs.md) has three remaining `30-local-question-file` skips: C `tests/door/cases.rs::SKIPPED`, TypeScript `tests/cases.mjs::NOT_RUN`, and Ruby `tests/conformance.rb::NOT_RUN`. R now passes selected case 30 through its public file loader. The old equivalence map's Q4 and pending-0207 sentences predate those landings. DuckDB Q5 covers member-question files and has no matching shared case; it remains separate. The original issue's closure also requires exact 0205 coverage mapping, so removing these three skips alone does not close it.

`specification/question-file.md` makes a malformed named file Local and typed invalid JSON Usage. Shared case 30 supplies `{"decide":"   "}` in a file; case 29 supplies invalid typed content. `public/question.rs::Question::from_json` implements the shared grammar. Its `Question::load` reads without a size cap, so each new host edge must bound actual bytes before calling the parser. DuckDB's existing caller-file cap supplies the 1 MiB precedent; this design does not change DuckDB.

The C typed door accepts inline JSON or bare text in `src/door.rs::question`. `src/ffi.rs::typed` uses the engine's guarded per-thread failure slot, and the header requires all outputs unchanged on failure. Owned success strings use `thinkthen_free_string`. A public validated-JSON loader can fit that ABI without another result struct. The C driver and `tests/door/main.rs` check actual exports and owner disposal. TypeScript `index.js::question` stores a frozen JSON specification; `specFrom` currently parses and stringifies branded values again. Its native `src/door.rs` already has a Local failure envelope, so `index.js`, ESM and declarations can expose one file-aware value. Ruby `ThinkThen.question(**keywords)` builds one question, while `ThinkThen.set(path)` loads a set. Native `src/ffi.rs::question` already returns `QuestionValue`; a file-only variant can return the same type without reinterpreting Ruby strings.

The smallest later proof uses one independently captured shared success request and selected case 30 through each public form. It checks exact body/digest, Local/non-retryable/no-send on the malformed file, and C's unchanged outputs/free-once rule. One TypeScript rich-description capture protects source order. A small local-refusal table covers missing, unreadable and over-cap files; it does not duplicate the full corpus. The three existing runners' case-25 internal guard and other intentional skips remain.

The Ruby source ratchet is already red on tracked main, independent of this design: `node sdlc/scripts/ratchet.mjs libraries/ruby/ratchet.rb.json` measures 2,122 nonblank tracked Ruby lines in `lib` and `tests` against a 1,778 ceiling. The local `.rb` inventory has no untracked/generated contributor. Commit `43508cf8` added batching/call-facts files without updating that ceiling; `c513b98a` added more focused work. `sdlc/scripts/surfaces --registry` enforces the port ratchets. Repair this baseline by a small separately reviewed Quick Fix with measured accounting before treating a future 0244 Ruby gate result as a feature regression. Do not silently raise its ceiling or fold unrelated extraction into 0244. The general 500-line policy scanner covers `crates/` and `conformance/`; it does not erase the binding ratchet failure.

Prospective exact source, test, header, README and NOTES claims are in the ticket. Documentation consumers matter: Ruby README currently describes only keyword questions and set files; C's header owns the output lifetime promise; TypeScript's CommonJS, ESM and declaration exports must agree. No new source claim follows from this preflight.
