## Current source path and loss points

`databases/duckdb/cpp/src/thinkthen.cpp::Decide` forms compatible groups, deduplicates first-seen texts, saves each original SQL row's `(group,position)`, skips NULL and later maps the framed native values back to those slots. Keep that layer. `databases/duckdb/bridge/src/ffi/scalar/ffi.rs::TryGroup` copies valid texts and writes fixed safe JSON for blank evidence; its outer error catch excludes `send_budget_denial()`, so either typed denial raises. `BeforeRetry` is public Backend kind, so simply removing the guard would also produce the wrong safe kind. More seriously, an outer native error gives the bridge no partial answers to frame.

`crates/thinkthen/src/public/native_batch.rs::read` explicitly returns both typed budget denials as outer errors. `NativeRun::decode` has already decoded a left half when a denied right propagates through `?`, discarding that left. `engine/facade/split.rs::fatal` throws either tagged denial before its owned split outcome can reach the native caller. `engine/workers.rs::ordered` halts admission when it receives an error, but its ordered drain stops at the first error and discards a later-index successful result already completed or in flight. `engine/facade/native_batch.rs` is a thin facade over that scheduler. The native public method only returns `Call<Vec<RecoverableDetails>>` after `Stop::run_call`; an outer error may retain final facts but no success vector. The ticket's private terminal marker and all-admitted-result drain fix all four loss points without changing the public carrier.

`engine/facade/split.rs` is also used by `public/batch/planned/answer.rs`: that B12a caller's `after_left` stops on every left request/member failure and its right-error branch retains an answered left prefix as a stopped `Completed`. It must continue to do so if split's fatal classification narrows to Cancelled, Deadline and Defect. Native `try_details` instead sends right after an ordinary recoverable left failure, but stops before right on a tagged budget denial. The current native callback always sends right; this is the precise caller distinction to change. The SendBudget reservation in transport remains authoritative after backoff/throttle/final stop check and before actual send, so a denied reservation opens no transport.

## Preparation lesson

The bridge guard is the visible exception, but three earlier native loss points prevent a safe blanket catch. A terminal budget denial has two effects that belong together: its own and unstarted SQL slots need safe Usage values, and the scheduler must stop feeding while it drains results already started. The existing atomic budget, not the order in which loopback sockets arrive, determines whether a transport attempt was admitted. The reviewed final artifact proves the regression and remains valuable historical evidence; it does not outrank ADR 0080 or repair the loss of already answered rows.
