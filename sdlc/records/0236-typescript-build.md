## What the build taught us

The first prep underestimated default Max's effect on an old request-count test. A body fixture must say `batch: 1` locally, while new packing tests should inspect actual listener bytes. The native score grammar sends bare levels as strings but explicit null descriptions as empty objects; a host normalization would have lost the difference. The generic response test helper also had to answer score-list criteria by numeric positions, matching the established conformance backend. Recognition accepts a structured kind description but its token-position request names the kind without quoting that description, so the proof checks the body and digest it actually sent. A started Node worker is not proof that Rust accounting began: a pre-account usage refusal has absent facts, while a failed sent request has one send and zero completed records. The observed receipt needs stdin closed in the child proof so an otherwise finished process can exit. Extraction kept the per-file source cap without another adapter or scheduler.
