The prior `counting()` helper ran a detached accept loop and read an atomic zero immediately after a command or child. A connection queued in the kernel could leave that count at zero. ## What the build taught us

A zero read from a background accept counter is weaker than a synchronous socket check after the call. Even a synchronous check proves nothing if its listener binds a different address from the command's resolved destination. The earlier `127.0.0.2` probe had both weaknesses. The short `127.1` spelling and runtime resolution assertion reuse the accepted portable direction from the missing-key Quick Fix; the code review must still judge this fixture on the changed command path. This closes a test observation gap only. Legitimate raw-wire, arrival, held-reply and synchronous quiet-socket assertions remain.
