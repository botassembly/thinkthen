Status: complete product implementation, accepted by fresh independent High code/API review at source `ed566d69`, integrated candidate `b5d61215`. This record tracks focused release evidence without repeating the 0212 matrix or other port suites.

The approved public prerequisite is `Engine::details_many[_with]` over runtime `DetailQuestion` and `Evidence + Serialize` items. The extra serialization bound is necessary for a full structured `input` when `Evidence::evidence` selects only one field. It reuses the fixed-question planner and its stopping, joined-facts stream. `Member` retains one bounded answered row independently of `CallOptions::observe`; `Details::of_member` uses the shared result writer for profile-aware digest, exact request list, batch share, warning and context metadata. A failed row still ends the iterator. The split regression was red because the old writer serialized only the answering half's digest while the typed accessor retained the refused parent too. Passing the complete request list to the shared writer made the same regression green.

The C JSON door accepts a closed `call` object for eligible many-record batch and context overrides, and four runtime judgment verbs accept `records`. The old successful value now sits under `value` with call-scoped `facts`; `{"usage":true}` stays direct. `thinkthen_error_facts_json` borrows the final report from the established engine/thread failure slot after a started failure, and is null when none exists. C materializes each input array, exhausts the Rust stopping stream before reading final facts, and returns `NULL` on any failed member without exposing a partial array. The header, schema, type corpus, C documentation and settings table state these changes.
