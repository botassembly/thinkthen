## Current boundary, corrected from the filing snapshots

`public/results/call.rs::Facts.seconds` and `cli/facts.rs::seconds` are elapsed wall intervals. `CallFacts::sent` counts started attempts, including retries and failed attempts; `CallFacts::live_reply` only sees a received response body and sets missing usage when that body omits it. `request.rs::ask_prepared` resolves cache/replay before transport and calls `usage.live_reply` only for a live body, including one whose logical answer then fails decoding. `http.rs` may return a retryable status, transport failure or terminal status without a usage body. Thus a call with one reported reply and one failed attempt can retain **partial** `Facts.input_tokens`/`output_tokens`: the current optional fields do not certify that every sent attempt has reported usage. A replay or cache answer sends nothing; its saved usage must not become current spend. The old facts issue's claims of missing `Call` carriers, reduced DuckDB details and unchecked conformance usage/confidence are historical. C JSON and new `*_with_facts` routes, Go/PHP, C#/JVM, C++/Dart, Swift/Zig and the current Rust/native carriers have focused receipts, while old bare C symbols retain ADR 0101's explicit exception. Landed 0282 adds Ada `libraries/ada/src/thinkthen.adb::Decode_Run_Facts`, Objective-C `libraries/objective-c/Sources/ThinkThen.m::facts_decode` and `TTJSON.c::tt_json_call_value`, and COBOL `libraries/cobol/src/tt_decide.cob` with `tt_shape.c::tt_cobol_facts`. The 0282 build record reports selected source and copied-consumer passes for all three, distinct from unrun clean release targets. SQL per-call facts are explicitly deferred.

`engine/http.rs::HttpAnswer` holds body and requests sent, not per-attempt headers or timing. The only read response headers today are retry controls. The compiled adapter is System One; the old timing issue's Chat body-derived `server_s` row describes a historical alternate and is not a present implementation route. `Facts.seconds` cannot be relabeled server or per-request time. Recordings remain body-only. Concurrent exchanges overlap, so subtracting the **sum** of exchange durations from run wall time can be negative and cannot prove command CPU time.

`cli/edge.rs` owns `Counters::new(config::usage_path())`; `public/settings.rs` builds native engines with `Counters::new(None)`, inherited by frame and SQL engines. `engine/usage/storage.rs` already writes checked count-only `thinkthen.usage/1` months and a retry sidecar under a stable lock with atomic replace/sync; old readers accept the month and ignore the sidecar. `cli/status.rs` only reads that store. `engine/facade.rs` rebuilds fresh counters after fork; `Counters::Drop` joins its async writer, whereas the CLI explicitly calls `finish()` and emits a safe warning. A write failure disables later persistence in that process but must not change a judgment. The documented DuckDB warm and concurrent-send fixes are real; PostgreSQL's pool multiplies a per-backend cap by design, and cache-off repeats are real sends. None makes `status` account-wide. The Git common-directory paid-experiment ledger is never product usage storage.

## Priority 1 — settle caller-priced money before the API freezes

**Recommended contract for the facts owner.** One optional price pair on the engine/configuration, `usd_per_million_input` and `usd_per_million_output`, applied to **reported live tokens** under the caller's chosen prices. Both absent means no money field; exactly one present is Usage before send, never an implicit zero. Explicit zero is a valid price. Use decimal text, at most six fractional places and a bounded nonnegative value (proposed maximum USD 1,000,000 per million tokens per side), parsed once to integer micro-USD per million; reject negatives, nonfinite/exponent forms, excess precision and overflow. Multiply each `u64` token count by its price in checked `u128`, sum, divide by one million and round half up to one micro-USD. Emit optional `facts.estimated_cost_usd` as a fixed six-decimal **string** to avoid binary-float and JavaScript safe-integer drift. This is a caller-priced estimate, not a provider bill, a dollar admission limit or a price lookup; a mixed-model call still uses the price the caller selected for that engine. Keep the existing input-only `crates/thinkthen/transforms/cost.jq` as a printed-row estimate, not this whole-call total.

Only compute that total when **all started attempts report both input and output usage**, independently for a library `CallFacts` and a CLI `RunSnapshot`; neither two `Some` token totals nor the current CLI `usage_known` bit certifies completeness. Track completeness privately beside `engine/call_facts.rs::{State,Snapshot}` using `requests_sent` versus `live_replies` and missing usage, and separately beside `engine/usage/facts.rs::{State,Snapshot}` using `usage/attempt.rs::PreparedAttempt::mark` counts versus `live_with_usage`/`live_without_usage`. `cli/facts.rs::Line` must use that stronger CLI predicate for any money field without silently redefining existing token-presence behavior. A failed status/transport attempt has a send mark but no `live_reply`; never turn unknown into zero. A priced call with no live sends, including empty input and cache/replay-only work, has known `"0.000000"` even though current token fields are absent. A logical failure after a received complete usage body may have money in its copied failure facts; a pre-start error has no facts; a partially failed call with any sent but unreported attempt omits money while retaining existing reported-token facts. With no configured pair, even no-work money is absent. The proposed field is **not** automatically additive for existing readers: `specification/result.schema.json::$defs.facts` and `callSuccess` both close member sets. Before any producer emits it, a reviewed next ticket must choose and document either a coordinated pre-0.1 schema/reader migration that explicitly breaks older strict validators or a versioned result/facts envelope that preserves the old reader contract. Preserve existing fields and `thinkthen.usage/1`; check absent/present-null/wrong-type handling under the chosen shape. Updating the schema alone does not update an installed validator.

## Priority 2 — design per-attempt timing/ID carrier before the API freezes

**Recommended contract for the timing owner.** Scope observations to one public `Call` for libraries and one command run for CLI; neither scope creates a durable/global ID. Allocate a monotone, scope-wide attempt ordinal at the actual send mark in `engine/http.rs::post_marked_with_retry`, shared across ordinary requests, retry children, splits and concurrent workers. The allocation/mark order is send-start order, **not** listener arrival or completion order. Key the observation within its scope by that ordinal and retain the request digest as a separate correlate; the same URL/body digest can recur for identical no-cache calls and retries. Measure `wall_ms` around each actual transport attempt with the engine clock. From System One responses read only `x-envoy-upstream-service-time` as optional nonnegative integer `server_ms` and `x-typesafe-request-id` as optional bounded printable ASCII `request_id` (propose at most 128 bytes, no controls); missing or malformed allowlisted values stay absent. A transport failure retains measured wall with no fabricated server/id. Capture the allowed headers on success **and** error/retry responses before bodies are consumed; never store the full header map, key, address text or error body. Cache/replay has no new live attempt observation. `Facts.seconds` remains the existing overlapping call wall interval, not a sum of attempts. `server_ms` is server time, not proven model-only time; `wall_ms - server_ms` is not a calibrated network measurement. No active Chat adapter makes the issue's `server_s` row a current source claim.

First design the in-memory public attempt carrier and CLI `--details` shape through `crates/thinkthen/src/{engine/http.rs,engine/request.rs,engine/call_facts.rs,engine/usage/{facts,attempt}.rs,public/results/{call,observation}.rs,cli/asking/batch_meta.rs}` and `specification/{result,recording,backends}.md`; map one C JSON/owned-facts edge through `libraries/c/src/{call.rs,failures.rs}` and the same host decoder families as above only after the carrier is fixed. Keep attempts distinct from logical rows and their even token shares. The old issue additionally asks `command_ms` and a digest-keyed recording sidecar. Recommend **no sidecar or `command_ms` implementation in the first carrier slice**: sidecar retention/permissions/atomicity and whether replay exposes historical observations require an explicit privacy/durability decision; a nonnegative exclusive command interval would need the union of overlapping exchange intervals and still would not measure command CPU. Root should record the disposition of these original asks before calling the issue done. Recording body bytes and digest identity stay unchanged; replay must never present historical time as current.

One small loopback table supplies success with both allowlisted headers, absent/malformed headers, a retry with distinct IDs, a terminal status and a transport failure; plant a forbidden header carrying a sentinel and assert it appears in no result, recording, sidecar, diagnostic or `Debug`. Pin distinct ordinals for two identical no-cache requests with the same digest and a retry, including an independently observed send count; a controlled overlap may complete in reverse order without renumbering starts. Pin positive wall interval, optional fields and zero live observations on replay. Reuse existing `engine/http/tests.rs`, `tests/public_size_retry.rs`, `tests/backend/recordings.rs` and `backend/facts.rs`; no provider or timing benchmark is needed. Sidecar gets its own later privacy/durability and old-reader proof if approved.

## Priority 3 — decide durable non-CLI status writes, implement after the carrier work

**Recommended ADR choice for the status owner.** Prefer an explicit public `usage_store = platform` opt-in over default persistence for library/SQL/frame engines. CLI keeps its current default writer. The opt-in resolves the same platform `config::usage_path()` once at build; if no safe path exists, refuse the opt-in before send rather than silently running volatile. With no opt-in, `status` truthfully remains command-only; with it, say `status` includes this machine's command sends **and opted-in engines using that store**, not every library, pool or account. An all-surface default would add writes, locking, exit latency and warning policy to every native call and needs a separate reviewed ruling. No arbitrary user path, new price fields or schema version enters the first slice. The source of truth is the single core `Counters::prepare_attempt/mark` per actual transport, not a sum of host `usage()` snapshots; one call must not be counted twice when a wrapper and its Rust engine share it. Fork creates a child-owned counter pointing to the selected store, with only child sends appended. `RESET` of a request/token cap does not clear usage history.

Reuse the existing private count-only month, retry sidecar, stable lock, checked aggregate, atomic replacement and old-reader migration. Keep a malformed recognized month a refusal for both `status` and writer; never repair or overwrite it by guess. Persistence stays advisory: failed async writes disable later writes in that engine, never change judgment or public `Facts`, and a safe fixed health/flush observation should let an opting-in caller discover the loss without logging a path, key, body, model or URL. The CLI's `finish()` warning cannot simply be copied to library stderr. Root must choose the public flush/health spelling and when an opting-in engine waits at close; `Counters::Drop` currently joins the writer and only its lock acquisition has a bounded wait, not arbitrary filesystem I/O. This write/durability ADR matters before exposing the option; implementation may follow 0.1 if `status` stays honestly scoped.

Later exact source claim: `crates/thinkthen/src/{public/settings.rs,public/engine.rs,engine/facade.rs,engine/usage.rs,engine/usage/{attempt,storage,tests}.rs,config.rs,cli/status.rs}` plus `specification/{settings,recording}.md`; touch `config.rs` only if the shared path API genuinely needs a bridge. Host opt-in settings and copied constructors follow 0283/0289 in separate claims; SQL/session and frame evaluation ownership must be explicit. One isolated XDG loopback proof sends one CLI and one opted-in Rust/native call, then reads `status`; a non-opted engine changes no store. Add two processes/fork, retry/status failure, cache hit/replay, absent usage and injected writer/corrupt-month cases. Pin listener count versus month/sidecar deltas, unchanged judgment on writer failure, safe health result, zero duplicate writes and old-reader byte compatibility. Reuse `engine/usage/tests.rs`, `tests/status.rs` and `tests/backend/default_cache/usage.rs`; no provider or whole SQL host matrix.

## What preparation taught us

The old facts issue's missing-carrier table and the old status issue's three leak title are filing evidence, not today's defect count. Reading `CallFacts` beside the HTTP status path showed that `Some(tokens)` can still be partial after a failed retry; a type alone did not prove complete billable usage. The first preparation missed the now-landed strict Ada/Objective-C/COBOL facts validators and the CLI `RunSnapshot` completeness path. A reply with usage after a failed send can make `usage_known` true without covering every started attempt; the distinguishing two-send fixture must test both CallFacts and the CLI line. Identical uncached bodies also repeat a digest, so the timing identity needs an ordinal at the real send mark within an explicit call/run scope. The 0283 lesson applies across crates: share the pure rule through a public bridge or the caller's returned facts, never by importing private `core` directly into C. Local send counts, configured caps, observed usage, caller-priced money and durable store totals have different owners and lifetimes.
