# 0253 cache binding status and recovery preflight

Status: design preparation at main `4fc01f408b9a40162af65e35b434907635d45bdd`; no runtime, test, issue or public documentation edit. Source issue: [a run that sends nothing binds the default cache](../issues/2026-09-26-a-run-that-sends-nothing-binds-the-default-cache.md), filed from experiment 273/06 I-2. It remains post-0.1. Its **Done when** is a status indicator relative to the current address and a refusal that teaches how to clear an existing binding. This is distinct from experiment 284/register 10's retired universal no-touch and two-address criteria ([reviewed disposition](2026-09-28-cache-binding-criterion-disposition.md)). The reported no-key first-use reproduction is fixed by 0228; 0246 and 0250 cover explicit zero and CR/LF first-use refusals. None adds the status comparison or clearing instruction.

## Source path and compatible design

`cli/status.rs::gather` resolves the selected backend with `Backend::resolve(None, environment.base_url(), ...)`, then runs the existing key-in-address check. It reports the resolved endpoint and counts from `cache_prune::inspect`; it does not compare the marker. `Environment::cache()` selects the named or platform path; `named_cache() || default_cache_enabled()` controls whether commands use it. A disabled default may still have historical files, which status currently counts. Status needs no usable key and opens no socket. `cache_prune::inspect` checks directory type/privacy, opens one shared folder gate, verifies the opened inode against the path, then scans final and temporary entries. `recorder/identity.rs::read` independently bounds and validates the marker and checks file identity before/after; `BackendIdentity::new` hashes the canonical adapter and resolved endpoint. Marker publication is atomic before send. A read-only comparison must reuse that exact parser/hash, never interpret entry URLs or marker bytes as a printable address.

Add a closed comparison value to the cache inspection while its **existing shared gate** is held. A small `engine/cache_prune/binding.rs` classifier can take the marker comparison from a narrowly exposed read-only `recorder/identity.rs` helper and the already scanned good/bad entry counts. `cache_prune::inspect` receives the selected resolved URL only when cache use is enabled, returns the comparison with existing counts, and does no second independent folder scan or writable gate. `cli/status.rs` prints `cache_binding VALUE` after `cache_path_source` and adds `cache.binding` in JSON. Values below describe one observation, not a promise about a later command: the recorder's gate still rechecks before any send. An external process replacing a folder outside the cooperating lock protocol remains a bounded filesystem race; the inspector must keep its existing path/opened-inode check and fail closed on detected replacement. Status must never unlink a path: moving it while another process holds a folder or digest lock can split the lock inode namespace.

| Selected state | Exact proposed `cache_binding` / `cache.binding` | Read behavior |
| --- | --- | --- |
| Default disabled by config and no named override, even if historical folder exists | `disabled` | Keep existing counts if a path is inspectable; do not imply this command uses its binding. |
| Cache enabled but no usable absolute platform path | `unavailable` | Keep current null path/count behavior; do not create a folder. |
| Selected path absent | `missing` | Counts remain zero as now; no folder, marker or lock is created. |
| Existing valid folder, no marker or digest-shaped final entry | `unbound` | Read only; a later writer may bind it. |
| Existing folder, no marker but a digest-shaped final entry (including a bad entry) | `legacy` | Do not call it free to bind; existing writable gate refuses legacy state. |
| Valid marker equals selected adapter/endpoint digest | `matching` | Never recover or print the bound URL. |
| Valid marker differs from selected adapter/endpoint digest | `mismatched` | Do not require a key or send; selected endpoint is already reported by status. |
| Malformed, oversized, symlinked, nonregular, replaced or unreadable marker; unsafe/unreadable folder | **No binding value printed**; existing fixed `StatusState` at exit 5, empty stdout | Do not convert unsafe state to `unbound`/`mismatched`, print marker bytes or attempt repair. |

The fixed failure line is `thinkthen: status could not read the local cache or usage state; check its permissions and contents` (with one trailing newline). For an enabled named cache, the same comparison applies even if config has `cache:false`: the named override already sets `cache.enabled=true`. A valid folder with only marker/lock/temporary artifacts is `matching` or `mismatched` by marker, otherwise `unbound` if no final entry. A writer publishing concurrently may move an observation from `unbound` to `matching` just after status returns; this is why status is advisory, not admission. Cache entry counts are a separate scan result and cannot infer the backend binding. The existing strict reader may return one storage error for malformed versus unreadable marker; no finer public diagnosis is needed.

`thinkthen.status/1` is currently an exact closed JSON object in `tests/status.rs`, and ADR 0034 says human and JSON report the same facts. Prefer one **additive** `cache.binding` field under the existing schema, retaining all existing field names, types and meanings. Ticket 0163 added `cache.bad_entries` under the same unreleased schema, and 0124 renamed prune-target fields without a schema bump. Update exact-shape tests; strict consumers that reject unknown fields must update, so this is a bounded additive compatibility change, not byte-for-byte identical JSON. A human-only line would break the same-facts rule.

## Fixed recovery wording and limits

Replace only the platform-default mismatch sentence in `cli/failure/recording.rs`; keep Local/exit 5, the safely checked **requested** endpoint, empty stdout, and no send. Proposed exact sentence: `the default cache is bound to a backend address other than \`URL\`; stop every process using the cache, move the entire cache folder shown by thinkthen status aside to preserve it, then retry; or set THINKTHEN_CACHE to a new folder`. Moving the **whole** folder aside after all users stop preserves entries and marker together; the next write-capable use can create a fresh folder at the original platform path. It is an operator action, not a new mutating command or an automatic cleanup. The current `--no-cache` workaround may remain if the sentence stays clear, but it does not clear the old binding. Do not advise deleting only `.thinkthen-backend.json` from a nonempty folder, running prune to unbind, or moving a folder with active lock holders. The named-folder refusal and library's fixed cure stay as accepted; the latter cannot clear a caller-selected path for them. No bound URL or raw marker value is printed, stored or inferred.

Later public wording, when marketing's hold ends: in `specification/recording.md`, state `status` reports `cache_binding` / `cache.binding` relative to the displayed resolved URL; `missing`, `unbound`, `legacy`, `matching`, `mismatched`, `disabled` and `unavailable` mean the table above. State that status does not change the folder and that a mismatch recovery requires stopping all folder users and moving the **entire** old cache folder aside before retrying (or choosing a fresh folder); preserve old contents and never delete only the marker. Update the exact default mismatch sentence there. The existing site/reference copy can link to that contract after marketing merges. No page edit is in this claim.
