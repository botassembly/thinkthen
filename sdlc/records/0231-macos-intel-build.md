## What the build taught us

The actual translated shell's `uname` value is the supported selector input, while `sysctl.proc_translated` distinguishes Rosetta from native Intel. Isolated x86-64 Python, Rust and DuckDB hosts were required for a meaningful target build; a universal CMake wheel alone did not make an ARM64 Python process Intel. The first offline package attempt lacked an all-target `wasi` crate needed by `cargo metadata`, though the target-specific bridge build had passed. A locked all-target fetch into only this lane's Cargo cache resolved that preparation gap without a source change. Removing the final old C API route left `vendor/append_extension_metadata.py` with no non-document caller; deleting it restored the real vendored-script inventory without a dummy reference or exception. The Python ratchet rose by four lines for explicit Intel selection and older-host verification; the existing per-tool selectors have distinct duties and do not justify another shared platform helper. The accepted lazy planner also made the old eight-held-sends signal fixture false reassurance; count actual listener sends in retained cancellation proofs.
