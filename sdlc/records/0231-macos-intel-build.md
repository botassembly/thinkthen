## What the build taught us

The actual translated shell's `uname` value is the supported selector input, while `sysctl.proc_translated` distinguishes Rosetta from native Intel. Isolated x86-64 Python, Rust and DuckDB hosts were required for a meaningful target build; a universal CMake wheel alone did not make an ARM64 Python process Intel. The first offline package attempt lacked an all-target `wasi` crate needed by `cargo metadata`, though the target-specific bridge build had passed. A locked all-target fetch into only this lane's Cargo cache resolved that preparation gap without a source change. Removing the final old C API route left `vendor/append_extension_metadata.py` with no non-document caller; deleting it restored the real vendored-script inventory without a dummy reference or exception. The Python ratchet rose from 3,411 to 3,420 nonblank lines for explicit Intel selection, older-host verification and the held-signal correction; it then rose by 105 to 3,525 for one shared footer parser and a four-field test at the actual packer boundary. I checked the existing strip parser and package verifier for duplication: the strip step now calls the common parser, while the package verifier still exercises stock host refusal, a different boundary. The target-specific archive selectors retain distinct purposes. The accepted lazy planner also made the old eight-held-sends signal fixture false reassurance; count actual listener sends in retained cancellation proofs. The reuse path needed its own footer gate even when the original build and stock-load proof were valid.
