## Changed behavior and ownership

- C# `Engine.Decide`, `DecideMany[WithOptions]`, `Recognize` and `Relate` now return immutable `TypedResult<T>` with the old value and owned `Facts`. JVM `Door` returns nested `TypedResult<T>`/`Facts`; Kotlin and Scala forward that shape for synchronous and asynchronous typed decide. Each typed route invokes one existing C `*_with_facts_opts` export. The JSON `Call` routes and bare C probe registrations, including `thinkthen_decide_opts` for `ProbeDoor.java`, remain.
- Required counts are strict unsigned C# or nonnegative in-range Java integers; seconds allow finite nonnegative fractions. Missing/null/wrong-type required members fail decoding. Optional input/output tokens and model are independent: a response without usage still retains its reported model; an empty bulk call has absent model. C# and JVM copy successful output and facts before returning and free both owned native allocations on managed exceptions. Native failures copy the borrowed error slot on the same calling thread before a later call; existing cancellation, close, and host threading rules remain.
- Existing source matrices now assert four typed values plus facts, empty bulk, no-usage, typed started-failure snapshots retained through later calls and close, and two held typed calls whose backend arrival markers both exist before either is released. The JVM fixture reuses `post-failure-recovery`, so its exact 60-arrival inventory stays unchanged. C# adds one `no-usage` request, giving 33 exact arrivals. No new test-only hook or general fixture framework was added. The old direct-value assertions were migrated into these stronger outside-in checks, not deleted.
- Actual compiled `thinkthen-door.jar` gained `Door$Facts.class` and `Door$TypedResult.class`; the exact release pair validator and its planted self-test now require both. Existing package source lists already include the edited files.

## What the build taught us

The facts slots must be separately freed when managed decoding throws, and JVM nested records are release-visible class members despite requiring no build-script source-list change. C facts can report a model when usage is absent, so optional facts cannot be treated as one group. An overlapping future/task launch alone proves nothing; existing backend hold markers supplied the two-arrival barrier. The matched C artifact and installed-source checks distinguish wrapper correctness from release-artifact qualification without repeating the broad package campaign.

## High review correction: required-facts proof

Fresh High code review found that the host fixtures asserted neither typed `cache_answers` nor typed `seconds`; a zero-filled decoder could have passed. No production ownership, ABI, threading, or package defect was found. The first tightened checks incorrectly treated a changed repeated-record bulk request as a cache hit. That failed on both hosts. An identical second three-record bulk request was then tried with an expected count of three; it also failed. [Recording](../../specification/recording.md) defines the cache key from complete encoded request bytes and counts a decoded cached response as one cache answer. ADR 0089 item 3 and `engine/request.rs` count each replay reply once at `usage.cache_answer()`/`cancel.cache_answer()`, while `CallFacts.records` counts finished records separately. The exact expected facts for the identical packed replay are therefore `records=3`, `cache_answers=1`, `requests_sent=0`; no additional backend arrival occurs. The different repeated-record group retains its existing live request and value/order check.

The C# source matrix and Java matrix now pin that one-reply cache count plus unchanged three values. Existing controlled held calls in C# `Program.cs` and Java `Concurrent.java` assert typed `seconds > 0` only after both backend arrival markers have been observed before release. This detects a decoder hardcoding zero without promising a general minimum latency. JVM `ResultEnvelopeTest` already checks synthetic fractional `0.125` seconds; no duplicate parser fixture was added for C#.
