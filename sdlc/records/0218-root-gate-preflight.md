The Linux `getrlimit(2)` / `prlimit(2)` rule exempts real UID 0 and processes with `CAP_SYS_ADMIN` or `CAP_SYS_RESOURCE` from `RLIMIT_NPROC`. `RLIMIT_FSIZE` instead sends `SIGXFSZ` on file growth; when the signal is handled or ignored, the write returns `EFBIG`. [Linux man-pages, `getrlimit(2)`](https://man7.org/linux/man-pages/man2/getrlimit.2.html) describes both. Therefore a capability drop alone does not make the nproc case bind a real UID 0. A nonroot real UID that retains either exempting capability is also outside the supported full-gate boundary.

## Bounded local proof

The host's `id -u` returned 1000. A temporary five-byte fake ledger and child-only `prlimit --fsize=5:5` wrapper ignored `SIGXFSZ`, then used Python `os.open(O_WRONLY|O_APPEND)` and `os.write`. The child exited 1 with `OSError: [Errno 27] File too large`; the fake ledger remained five bytes. The same raw-write probe in the already present local Docker image, UID 0, `--network none`, read-only filesystem and a temporary `/tmp`, also returned `EFBIG` without growing its fake ledger. An initial buffered `open().write` root probe did not flush, so it was not evidence; the raw-write rerun is the relevant result. These probes did not execute the repository's `live` script.

The host ordinary UID under `prlimit --nproc=1:` could not start a Python thread (`RuntimeError: can't start new thread`). In that same local root container a thread did start under the identical nproc limit. The available image and tools required no installation, privilege change or host mount. This establishes the kernel boundary for ticket design, not a pass of the `thinkthen` interrupt test or a complete full gate.

The reviewed routine-gate design uses `/usr/bin/python3`, already needed for the copied `live` script, as a child wrapper. It sets `resource.RLIMIT_FSIZE` to the scratch ledger's current byte length, ignores `SIGXFSZ`, and `os.execv`s the copied script with its original arguments. A five-byte local ledger probe of that `setrlimit`/`execv` sequence returned `EFBIG` and preserved `b'seed\n'`; it was not a run of the repository script. The limit and ignored signal apply to that child command, not the rest of `sdlc/live-test`. The builder should verify the exact wrapper under both UIDs. Any `SIGXFSZ` termination instead of the existing warning fails the proof. This keeps `prlimit` out of the routine gate's new prerequisites.

## Preparation limits and next proof

No `sdlc/live-test` root result or revised full-gate preflight exists yet. The `test-full-cases` script has no current privilege or tool guard. A small Linux-only check can read `CapEff` from `/proc/self/status` and reject UID 0 or effective capability bits 21 (`CAP_SYS_ADMIN`) and 24 (`CAP_SYS_RESOURCE`); a missing or malformed capability field should refuse rather than imply coverage. `command -v prlimit` must also succeed before the heavy lock or Cargo. Keep `--list` readable under root, and leave non-Linux behavior unchanged. The builder should test the check with a UID 0 container and a real capability-free UID, plus a capability-free UID with `prlimit` hidden from `PATH` to prove the named missing-tool refusal. A capful nonroot check is useful only if locally available without changing host privileges. All heavy focused Cargo proof must use `flock -o "$THINKTHEN_HEAVY_LOCK"`.

The issue's item 2 is already closed by `qf-flaky-gate-tests`. Its old 20-run done-when instruction predates the current work plan's opt-in ruling for repeated and load campaigns. This ticket does not reopen that work or count a campaign as a completion criterion.

## What the build taught us

This is a preparation record, so it records no build result. Inspecting the gate selectors avoided conflating a routine ledger failure with a full-gate interrupt failure. The ledger's regular-file validation ruled out a directory fixture as proof of the intended append branch. A raw child write was necessary to observe the file-size error; a buffered Python write could exit before flushing. The local root proof confirmed that UID 0 remains exempt from `RLIMIT_NPROC`; a capability-only adjustment is insufficient. Fresh design review exposed a missed tool dependency: the full-gate interrupt case executes `prlimit`, while the first proposed guard considered privileges only. The corrected preflight checks that tool, and the routine fixture uses its existing Python runtime. The next review must decide whether the proposed early full-gate refusal is preferable to provisioning a separate nonroot runner, without weakening the no-send witness.
