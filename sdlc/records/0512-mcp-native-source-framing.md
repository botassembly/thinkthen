# Forward native source framing through MCP

The change starts from `c6421005c44383e14ef4f439f44f77fb60e8e419`. MCP source arguments lacked the framing field introduced on native RequestSource. MCP now carries optional typed RequestFraming, forwards it to RequestSource, and derives its advertised framing property from the committed Request schema. The existing generic presence carrier rejects explicit null exactly as native RequestSource does. Native admission and readers own combinations, table headers, decoding and physical source positions. MCP retains flat unit and window fields.

The caller behavior cases were named before implementation: discovery exposes the native framing property; CSV and TSV execute logical rows while preserving object originals and physical line positions; malformed headers and mismatched physical controls refuse without backend sends; empty, null and wrong-shaped framing refuse.
