## Readers, builders and no-key paths

The command has two production reads of `THINKTHEN_API_KEY`: `cli/edge.rs::key` reads it lazily for `cli/asking.rs::engine` and `cli/check.rs::run` `Settings.key` closures; `cli/edge.rs::Environment::api_key_set` reads its presence again for `cli/status.rs::gather`. `Environment::read` captures base URL, batch and other settings but does not capture the key. `engine/request.rs::ask_sent` prepares replay/cache work before `key()` on the live branch, so checking only the send callback is too late for URL-derived digest, folder access and plan output. `cli/status.rs::gather` inspects cache and usage state before `Backend::resolve`, and then uses the separate presence read. One optional invocation snapshot must feed the URL collision check, both live `KeyReader` closures and `status.backend.api_key_set`, with collision refusal before any URL-bearing output, digest or folder access. The implementation must preserve no-key replay/dry-run and the existing safe URL/folder-mismatch result.

`public/settings.rs::EngineBuilder::from_env` already captures a key once; `api_key` can override it. `build` resolves the final backend, clones the final key and installs a lazy callback. Guard the final effective key and final endpoint there, after override precedence and before `storage()` or `Engine::from_settings`. `engine/facade.rs::with_model` re-resolves the same URL and now preserves 0157's nondefault request size; it must retain the guard invariant without a second environment read. `engine/facade.rs::key` turns `NoKey` into an empty key only for proven loopback, so a keyless local live call remains valid. A nonloopback live call with no key keeps its existing failure; a keyless dry-run or replay still needs no key. The guard compares only a known nonblank effective key with the resolved URL; it cannot infer a different path secret or scan caller question/evidence/model content.

Native door construction converges on that public builder: Python `libraries/python/src/engine.rs`, TypeScript `libraries/typescript/src/door.rs`, Ruby `libraries/ruby/src/lib.rs`, R `libraries/r/thinkthen/src/rust/src/lib.rs`, C `libraries/c/src/settings.rs`, DuckDB `databases/duckdb/src/engines.rs`, PostgreSQL `databases/postgresql/src/call.rs`, and SQLite `databases/sqlite/src/settings.rs` use `EngineBuilder::from_env` then setters/build. The Rust bare builder is `Engine::builder`; `from_env` captures the configured key. Verify each final constructor and any direct `Engine::new(Settings)` host before claiming its public guard. The current direct CLI `Settings` constructors are asking and check; test-only or audit-only `Settings` constructors are separate, not new production key readers for this URL rule.
