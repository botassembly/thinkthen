# Annotate help: approved record vocabulary

Status: Quick Fix candidate from main `9159e7c0c`, for fresh Medium review. Scope is the two annotate command-help comments and the build-side residual in the existing documentation issue. No command behavior, option, scanner, page or other host changed.

## Change and proof

The old built command `148ac1d524b1` said “safe row” in the long description and “error row” in `--on-error` help. It yielded the previously recorded vocabulary failures at `annotate -h:9` and `annotate --help:3,13`. The two comments now say “safe error record” and “error record.” They still name a missing question-set `on` pointer, require `--jsonl --details --batch 1`, stop for other failures, distinguish completed exit 6 from skipped-record exit 7, and retain all examples. `header row` in the CSV/TSV options remains the scanner's explicit exception.

An offline two-job incremental command build under the codex-2 lane lock produced `target/debug/thinkthen` SHA-256 `f37203fb17e7ea3e530770f42813234d0f5af92f03a186c2bed0722d200b7598`. Both `annotate -h` and `annotate --help` ran under an explicit minimal environment and show only the two allowed `header row` occurrences when searched for whole-word `row` or `rows`. The unchanged `sdlc/scripts/demos` built-help scanner also passed from a page-free staging root under `target/codex-builds/qf-annotate-help/help-only`; it reported `0 green, 0 red` because that invocation checked help and no page. The root Rust ratchet remains exactly `103393/103393`; changed comments replace one nonblank line each. `command.rs` has 433 nonblank lines and `annotate.rs` has 32, both below the 500-line cap.

The selected runner needs a directory containing a demo subfolder: passing `demos/28-what-a-run-cost` directly reports `0 green, 0 red`, so that invocation alone proves no page ran. I staged only a symlink and tiny index under `target/codex-builds/qf-annotate-help/selected` and ran `sdlc/scripts/demos` against it with the matching binary, scratch HOME/cache/config and no key or backend settings. It reached the page and stopped on a separate existing ADR 0016 rule-1 failure: `28-what-a-run-cost/README.md` measures **129 lines** against 120 and **940 words** against 900. The runner stops before its help scan at that point, so this is not a whole-runner green receipt. Direct `mustmatch test demos/28-what-a-run-cost/README.md` passed **6 assertions** with the same binary and saved replay. The priced replay behavior was already separately proved by 0300; no provider or network call occurred here.

The help source changed no Rust execution path, so the prior 0300 pricing/parser/host receipts remain tied to their original source. `cargo fmt --all -- --check`, focused binary Clippy with warnings denied, offline policy (189 packages), `pages` (23 green, one coming), `tickets` (zero evidence failures), exact root ratchet and `git diff --check` passed. ## What the build taught us

The help scanner exempts `header row`, so changing the two actual annotate descriptions fixes the vocabulary mismatch while preserving the CSV/TSV term. A runner argument that points at one page folder can exit successfully without executing a page. A selected staging root made the page count honest and exposed the independent length/word-limit failure. The direct executable page still proves the saved replay, but it cannot stand in for a green ADR 0016 runner receipt.
