## Proposed native C observation contract

This design builds on `8e2e8e516`. The Rust engine already owns live observation and explicit finalization, but the owned-session C interface cannot expose either without sending a legacy JSON utility request. Add two engine operations beside the session interface. Language engines can call them directly; the compatibility JSON utilities remain unchanged.

```c
int thinkthen_engine_usage_persistence_v1(
    const thinkthen_engine *engine,
    thinkthen_complete_usage_persistence_v1 *out_state,
    thinkthen_complete_utf8_v1 *out_advice);
int thinkthen_engine_finish_usage_status_v1(
    const thinkthen_engine *engine,
    thinkthen_complete_usage_persistence_v1 *out_state,
    thinkthen_complete_utf8_v1 *out_advice);
```

These declarations show the installed header's engine spelling. Rust implementations take `*const Door` and the existing generated carrier types; cbindgen produces the declarations. No new status handle, schema, registry, callback or JSON grammar is needed. The generated `thinkthen_complete_usage_persistence_v1` and its named constants already represent all native states. A small exhaustive projection maps the Rust enum to those generated constants; it calculates no state. Advice comes from `UsagePersistence::advice()`, never an adapter-owned sentence or an operating-system error.

The first operation calls `Engine::usage_persistence()` once and never waits for the usage writer, queue mutex or filesystem. The second calls `Engine::finish_usage_status()` once. It may wait for pending writes under the existing usage-lock deadline; other filesystem work has no bounded completion promise. Neither operation creates an engine state, sends a model request or infers persistence from earlier call facts. Native process ownership, failure precedence and the failure latch remain unchanged. Written means only that this engine's currently observed deltas have drained, including the native initial state with no pending deltas. It says nothing about subsequent calls or other engines.

On `THINKTHEN_OK`, both outputs are assigned from the same native observation. A persistence failure is a successful observation with the Failed state, not a nonzero operation return. Failed carries a counted UTF-8 view of native fixed advice. Other states carry `{NULL, 0}` advice. The advice bytes have static library lifetime, contain no trailing-NUL requirement and require no free; they remain readable after engine destruction while the library remains loaded. The caller owns the two copied output values. The complete persistence-observation carrier is deliberately not reused: its `observed_at` member describes a facts snapshot, whereas these methods report live state.

The engine must be live for the whole call. Observation and finalization may run alongside other operations, subject to native synchronization; engine destruction must wait for all callers. Both output addresses must be nonnull, correctly aligned, writable and nonoverlapping. Check null outputs and exactly equal addresses before dereferencing the engine or finalizing. Remaining extent, partial-overlap, forged-pointer and concurrent-free obligations belong to the caller, as in the existing session contract. Null engine or invalid required outputs returns `THINKTHEN_EUSAGE`. Every nonzero return, including contained panic, leaves both outputs unchanged and records the existing calling-thread session diagnostic. No panic crosses the ABI. Successful observation, including Failed, preserves that diagnostic slot and any earlier successful answer.
