# 0262 C#/JVM local release-package preflight

Status: design-only source audit at clean main `e81770f1`. No executable change, package build, loopback run, workflow dispatch or publication occurred. This record supports [ticket 0262](../tickets/0262-csharp-jvm-release-packages.md) for fresh design review. The original C# and JVM issues remain open.

## Present build and installed paths

The accepted [0249 C#/JVM build](0249-csharp-jvm-build.md) integrated real Linux x86-64 source packages and exercised their installed consumers. C# `check.sh` currently rebuilds debug C, checks the header-derived exports, copies that `.so` to `target/scratch/lib`, writes a separate debug-native tar, calls `dotnet pack ThinkThen.csproj`, runs its 30-arrival matrix, and calls `tests/isolated_consumer.py` twice. That fixture copies `target/scratch/managed/Botassembly.ThinkThen.0.0.1.nupkg` and `target/artifacts/thinkthen-c-0.0.1-x86_64-linux-gnu.tar.gz` from fixed checkout paths into unrelated bwrap roots. The latter is a local debug build, not the `release-pack` C archive. Its test-authored `Installed.cs` makes a scalar `consumer-csharp` call and a JSON-envelope `consumer-json` call, checks a spent token without sending, and currently asserts only two arrival names/attempts, although `tests/backend.py` captures complete wire bodies in `barrier/wire-requests.jsonl`. The release selector must inject the unpacked nupkg and C paths and compare the captured bodies, or it could pass while using old target files or a changed request shape. `tests/package_check.py` likewise reads fixed debug/checkout paths; keep it in source mode rather than presenting it as installed-release proof.

JVM `check.sh` also rebuilds debug C and checks exports, copies `target/native/libthinkthen.so`, calls `build.sh` for the three JARs, validates their compiled members and then calls `tests/installed.py`. That outer fixture copies product-built JARs and the debug shared library from fixed `target/` paths, but also copies `kotlin/KotlinCaller.kt` and `scala/ScalaCaller.scala` product source from the checkout into its isolated consumer project. Its `consumer-run.py` compiles the product source and drives the complete matrix, cancellation and planted cases: 60 arrivals per Java, Kotlin and Scala installation. That is valuable retained source evidence; repeating 180 arrivals for a release-file selector adds cost and leaves a checkout-source fallback. A short branch in the existing bwrap/backend route can compile only test-authored consumers against unpacked JARs and load the unpacked C member. The Java 21 FFM door takes an absolute `-Dthinkthen.library` path, and Kotlin/Scala facade classes already compile into their own JARs. This allows one distinct call per language without changing product code.

`release-pack` already builds a fresh release C archive and stages Go/C++ wrappers only when explicitly requested. Its default part list remains the older nine families. `release-smoke` verifies adjacent SHA files, scans unpacked tar bytes, calls the Go/C++ pair preflight before backend startup when needed, routes recognized archives, treats exit 77 as failure and still requires all nine legacy families. The private `release-go-cpp-pair` checks exact selected family cardinality and fixed five-line manifests against the actual C archive digest, but only for Go/C++. A literal second C#/JVM mode reuses its scratch, checksum, safe-data manifest and refusal path; a second validator would duplicate the boundary. Each selected mode should allow the other pair in a full bundle and reject extra files in its own pair or C family. The bounded three-file pilot calls that same mode directly because the full smoke cannot pass without the nine older families.

## Proposed exact input and tool boundary

C# product inputs are `libraries/csharp/ThinkThen.csproj`, `src/ThinkThen.cs`, `LICENSE`, `README.md`; the `.nuspec` in the source tree is not the `dotnet pack` entry point. `net8.0` and `Botassembly.ThinkThen` come from the csproj. Its nupkg's expected relevant members are `Botassembly.ThinkThen.nuspec`, `lib/net8.0/ThinkThen.dll`, `README.md`, `LICENSE`, with no native `.so` or `.dylib`. JVM product inputs are `libraries/jvm/build.sh`, `door/thinkthen/{Door,ResultEnvelope}.java`, `kotlin/KotlinCaller.kt`, `scala/ScalaCaller.scala`, `pom.xml`, `LICENSE`, `README.md`; `build.sh` outputs exactly `thinkthen-{door,kotlin,scala}.jar`. The POM is metadata for the local direct file; this ticket does not run Maven or resolve a registry. The separately built C archive contains both library modes and the same public header, though C#/JVM installed consumers need only its shared `.so`. The fresh C build's complete source tree includes engine dependencies, so `libraries/c/` and header equality alone do not justify reuse.

The accepted local tool receipts are .NET SDK 8.0.131, JDK 21.0.12.1, Kotlin 2.4.20, Scala 3.9.0, Rust 1.95.0, Python 3.12.3 and bubblewrap 0.9.0. Read-only version commands on this lane reported those exact values. The product `toolchains.py` files resolve C# `THINKTHEN_DOTNET` and JVM `THINKTHEN_{JDK,KOTLIN,SCALA}_HOME` or matching executables, and reject missing paths. JDK 21 uses `--enable-preview` at compile/run and `--enable-native-access=ALL-UNNAMED` at run. `dotnet pack` needs an isolated local restore/feed; no NuGet or Maven network source is necessary. No `inputs/toolchain.json` is presumed universally available. The builder must record actual resolved binaries and versions, not just this older host receipt.

## Proof boundary and lessons from 0261

The strict baseline is `release-pack TARGET OUT c csharp jvm` from one clean commit, producing only the C, C# and JVM outer archives plus sidecars, followed by the shared pair preflight in `csharp-jvm` mode and two artifact-selected installed checks. Pin exact inner and outer hashes and C header/shared/static member hashes. The C# fixture must compare both captured JSON bodies to independent literals; the three JVM consumers each use a different evidence state and compare three captured full bodies to three literals, not just state counts. The backend and installed bytes are observations; hashing only an expected body is not proof. A native symbol pass derives the current declaration set from the unpacked header and compares it with `nm` exports from the unpacked shared library. Compare separately installed native copies to archive members, not a file to itself.

The negative plants remove JVM, corrupt C#, substitute a differently hashed valid C archive with its updated sidecar, and add a second C# family entry. Each calls the same preflight and must stop before selector/backend startup; an actual smoke missing-file plant proves the preflight call path precedes backend startup. The script structure gives zero sends without a consumer invocation; if claiming a measured zero-send count, run a counted listener and report that observation explicitly. Do not describe mere package load as panic injection or other-platform proof. Like 0261, a manifest's commit is a fixed-data assertion shared by the managed pair, not a demand that current HEAD match an older artifact. The clean non-reuse command and receipt establish source provenance. The 0261 fixture failures counsel early checks for isolated cache paths, actual loader paths, tool resolution and package input byte comparisons before broad matrices.

The C# source gate's two local installed consumers, JVM's three 60-arrival suites, public J1 corpus, cancellation and package plants remain in place. A later product/native input change can invalidate those prior receipts and require focused reruns, but this design does not broaden them. Final release commit, Ubuntu Actions execution, checksummed public assets, NuGet/Maven or direct distribution, Java 21 preview limits and other hosts remain outside this local pilot. The existing [release preparation](0249-release-preparation.md) and [0261 build](0261-go-cpp-release-build.md) distinguish local file proof from public-release criteria.
