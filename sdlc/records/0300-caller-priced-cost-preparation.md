## Source findings that constrain the contract

- `crates/thinkthen/src/engine/http.rs::post_marked_with_retry` marks every actual send, including retries. `engine/request.rs::ask_prepared` resolves cache/replay before transport and calls live-reply accounting only for a received body. `engine/call_facts.rs` retains sent and reply counts; `engine/usage/facts.rs::run_snapshot` separately sets `usage_known` when any live reply supplied usage and no received reply omitted it. Thus a failed status followed by a successful usage reply yields two sends but one reported reply; the CLI bit may be true and both owners must independently omit money. Do not infer completeness from `Some` token totals. Current `Facts.seconds` is call wall time.
- `specification/result.schema.json::$defs.facts` and `callSuccess` are closed. Ada `libraries/ada/src/thinkthen.adb::Extract`, Objective-C `Sources/TTJSON.c::tt_json_call_value` and `ThinkThen.m::facts_decode`, and COBOL `src/tt_shape.c::tt_cobol_facts` reject an extra facts key; Objective-C/COBOL cap the count at seven. C++ `libraries/cpp/include/thinkthen/door.hpp::decodeFacts` and tolerant hosts drop fields they do not expose. 0282's build record reports selected copied installed source consumers for Ada, Objective-C and COBOL, not clean release qualification. A priced old strict consumer must fail until migrated; the unpriced path must retain old bytes. New matching consumers require type/absence and selected copied-package proof. No blanket unknown-key tolerance.

## Build-ready route and limits

Core/CLI/C first, then strict readers, then the other disjoint host batches in ticket 0300. The cost setting cannot land as an inert accepted option: the first slice must return a computed call/run field and prove actual sends. The strict-reader batch makes the priced C producer usable through newly copied typed consumers. Each later wrapper batch exposes the field in its own carrier and tests one absence/zero/valid case plus its existing failure copier; the core loopback ledger is reused, not repeated in every language. Old release archives are not relabeled. Separate runner qualification stays with root.

Measured nonblank lines at this source pin: Rust `config.rs` 400/500, `public/settings.rs` 470/500, `public/results/call.rs` 123/500, `engine/call_facts.rs` 131/500, `engine/usage/facts.rs` 82/500, `engine/usage/attempt.rs` 88/500, `engine/facade.rs` 468/500 and `cli/facts.rs` 67/500; C `ffi.rs` 499/500. A pure price parser in one private core module plus a public builder method avoids duplication and keeps near-cap files within policy. Source changed by 0283 or 0289 needs a fresh measurement before building; those owners currently claim the shared parser/CLI and request/usage/facade paths. Accepted 0299 uses the latter after 0289. Root should sequence the first cost build after these collisions or source-match their landing; price arithmetic itself is independent of 0299.

Use the existing `demos/28-what-a-run-cost/README.md` as the user workflow: retain its prior input-only `cost.jq` transform, add a configured input/output `--facts` receipt and zero-send replay example after code. It is a green ADR 0011 demo, so its selected demo check is required; marketing `site/` is not this claim. Keep the result/settings pages with code. The cost issue remains open for timing/IDs, full detail and separate SQL/frame criteria. No provider, package sweep, benchmark, paid ledger write or release runner is part of this design.

## What preparation taught us

The accepted accounting note correctly found partial usage but its first draft missed CLI `RunSnapshot` and strict 0282 readers; the corrected note made them separate proof owners. This design adds the CLI configuration compatibility consequence: an old closed config reader also refuses a priced file. One selected old/new validator boundary is more honest than saying a schema change is additive everywhere. Price arithmetic is feasible with integer fixed point and a bounded pair, but a computed estimate does not become a provider bill or spending cap. No runtime proof was run for this design.
