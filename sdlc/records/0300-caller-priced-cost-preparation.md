## Source findings that constrain the contract

- `crates/thinkthen/src/engine/http.rs::post_marked_with_retry` marks every actual send, including retries. `engine/request.rs::ask_prepared` resolves cache/replay before transport and calls live-reply accounting only for a received body. `engine/call_facts.rs` retains sent and reply counts; `engine/usage/facts.rs::run_snapshot` separately sets `usage_known` when any live reply supplied usage and no received reply omitted it. Thus a failed status followed by a successful usage reply yields two sends but one reported reply; the CLI bit may be true and both owners must independently omit money. Do not infer completeness from `Some` token totals. Separately, `engine/usage.rs::Counters::tokens` calls `add`; its `Queue.totals = totals.unwrap_or(queue.totals)` keeps stale process tokens on `Counts::checked_add` overflow while `live_reply` still advances `live_with_usage`. Two otherwise complete replies can therefore look complete and price an old total. `core/result.rs::Usage::checked_plus` makes the call path omit overflowed token totals, but cost needs an explicit latched arithmetic-validity predicate separate from reply completeness. A private CLI facts flag must be set under the queue lock for a rejected token delta. Keep the old response-presence rule for partial usage, but suppress CLI token fields when arithmetic is invalid instead of publishing stale totals or inventing zero; cost also requires all attempts reported. Current `Facts.seconds` is call wall time.
- `specification/result.schema.json::$defs.facts` and `callSuccess` are closed. Ada `libraries/ada/src/thinkthen.adb::Extract`, Objective-C `Sources/TTJSON.c::tt_json_call_value` and `ThinkThen.m::facts_decode`, and COBOL `src/tt_shape.c::tt_cobol_facts` reject an extra facts key; Objective-C/COBOL cap the count at seven. A priced old strict consumer must fail until migrated; the unpriced path must retain old bytes. New matching consumers require type/absence and selected copied-package proof. No blanket unknown-key tolerance.

## Build-ready route and limits

Core/CLI/C first, then strict readers, then the other disjoint host batches in ticket 0300. The cost setting cannot land as an inert accepted option: the first slice must return a computed call/run field and prove actual sends. The strict-reader batch makes the priced C producer usable through newly copied typed consumers. Each later wrapper batch exposes the field in its own carrier and tests one absence/zero/valid case plus its existing failure copier; the core loopback ledger is reused, not repeated in every language. Old release archives are not relabeled. Separate runner qualification stays with root.

## What preparation taught us

The accepted accounting note correctly found partial usage but its first draft missed CLI `RunSnapshot` and strict 0282 readers; the corrected note made them separate proof owners. This design adds the CLI configuration compatibility consequence: an old closed config reader also refuses a priced file. High review also caught a second, independent cost prerequisite: two received usage replies can overflow the CLI process token sum, leaving stale totals while the reply counter looks complete. Python frame aggregation has unchecked additions; R already checks its aggregate before commit. The bounded overflow/reset fixture and the checked host bridge prevent stale, wrapped or rounded partial totals from becoming money. One selected old/new validator boundary is more honest than saying a schema change is additive everywhere. Price arithmetic is feasible with integer fixed point and a bounded pair, but a computed estimate does not become a provider bill or spending cap. No runtime proof was run for this design.
