Status: bounded proof only. The product DuckDB runtime is unchanged. The full 0201 migration is not accepted.

The first proof at `981c686d` used pinned DuckDB v1.5.5 source, official release static archives, and the stock CLI and Python module. It proved loadable C++/Rust linkage, copied nested values with Rust-owned free, prepared caller settings changing from 7 to 13, and two independent sessions reporting 11, 29, 11. A forced Rust panic returned tagged error 4 but printed its payload twice to stderr.

The second proof at `a464ad12` installed one delegating panic hook and suppressed the direct bridge payload. A fresh, read-only High review accepted that bounded correction. A child process supplied a synthetic key/evidence marker in a forced panic. The marker appeared in neither stdout, stderr, nor the SQL error; the next query succeeded, and an unrelated thread reached the prior host hook. That review did not accept the full runtime port. The process-global hook may be replaced after load or race another registration. Engine worker threads do not inherit the SQL caller's thread-local bridge marker. The public engine returns a fixed defect message, but a worker's first panic may reach the hook before that catch. Product integration must prove that boundary separately.

The next proof uses the same pinned stock host. It installs the Rust hook at extension load. A foldable bad constant is refused at scalar bind with zero proof callback sends. The try probe keeps a bad constant in bind data, returns a usage failure for that row, and lets a later good row answer with one callback send. Direct first use reports the late registration path. Prepared executions each report a fresh `QueryBegin` generation. Two expressions in one statement share that generation. A failed execution reaches `QueryEnd` and leaves the next query fresh. A synthetic signal changed after the last owner call is consumed at `QueryEnd`. One 2,049-row statement crosses the 2,048-row vector boundary with one generation and no model requests. These are host callback and ownership proofs; they do not claim actual inference sends or SIGINT recovery. `databases/duckdb/proof/0201/verify_bind_owner.py` checks them through the stock Python module.
