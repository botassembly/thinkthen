## What changed

`PolarsEngine` now returns lazy `decide_expr`, `choose_expr`, `score_expr`, and `tag_expr` from owned engine/question/`PolarsExprOptions` state. Each Polars evaluation morsel invokes the existing eager column door, with the existing batch splitter, same wire encoding, a fresh deadline, shared cancel token, and real `Tally`. Decide/choose probability returns a `Struct{value, probability}`; score/tag probability refuses Usage before a send. A caught panic becomes a Polars compute error. Eager methods, default Max packing, source/null positions, and core accounting are reused. README and specification name the per-morsel deadline and filter/head pushdown hazard.

The manifest enables only pinned Polars 0.55.2 `lazy` and `streaming` features. Offline lock resolution adds 166 transitive packages, about 2,058 lock-file lines. The matching policy feature assertion retains optional/no-default pins. The all-feature metadata paths are `thinkthen -> polars -> polars-utils -> flate2 -> zlib-rs` (Zlib), `thinkthen -> polars -> polars-arrow -> zstd -> zstd-safe` (BSD-3-Clause), and then `zstd-sys` (BSD-3-Clause). Policy names each crate rather than widening its global license list. Cargo deny's existing BSD allowance covers the active zstd pair; adding zlib-rs to deny.toml yielded an unmatched-exception warning, so no new exception remains there. The active deny license check passes without warnings. The named crates' license notices remain required when distributing their code. The negative policy plant now names a distinct unclaimed license instead of the newly approved zlib-rs metadata member.

The three old package failures retain distinct cases. `polars_cases` selects batch one for recorded singleton requests, including annotate. `polars_deadline` uses three held singleton score rows and proves Deadline, two actual arrivals and no third send. `polars_throttle` starts three distinct singleton calls at a barrier, pins two held arrivals under throttle two, releases the listener and sees the third arrival, across slice, decide Series, and score Series. Its 200-row campaign stays ignored. The separate default-Max body witness remains selected.

## What the build taught us

Polars streaming can split the same in-memory column into different evaluation morsels from eager collection. The first red test incorrectly expected identical packed bodies; the first pushed candidate then incorrectly treated its observed two streaming morsels as universal. Fresh review's `POLARS_MAX_THREADS=1` run failed that assertion because one morsel packed both rows. The corrected outside-in test selects batch one at the streaming call boundary, pins each literal singleton body, and preserves the independent default-Max packed witness. The first throttle rewrite held one lazy batch, whose input scheduler admitted only one request before waiting; concurrent distinct singleton calls are the minimal actual two-slot witness. The original 20-record/300 ms throttle and 200-record deadline scale assumptions were retired; the optional 200-row equality stress test remains ignored. The new lazy test combines parity, nullable positions, typed result, refusal, cancellation, and listener evidence; the small panic unit stays because it alone forces the private unwind boundary without a production test hook. No accounting algorithm or separate batch planner was duplicated.

Root Rust source/test ceiling grows from 104,401 to 105,066 nonblank lines (+665, including ten lines for controlled batch selection and a shared value assertion). The new `frame/lazy.rs` has 235 nonblank lines, the outside-in lazy consumer has 311, and `frame.rs` has 450. The growth is the four feature-gated expressions and their independently observed Polars consumer; the three older package fixtures were shortened to bounded work. The normal full `libraries/polars/check.sh`, other-platform compile, packaged/archive consumer, RSS/load/churn, and release checks remain unexecuted here.
