# Frame batching completion audit

Status: Source audit on main `2b388453`, with one offline observation. This proposes disposition for B13a and B13b; it does not close either row. The criteria are [batching design B0 and B13a/B13b](../issues/closed/2026-09-26-batching-design.md), including the common rule that a library result carries per-call facts. Landed 0209, 0212 (`f9d9d128`), 0214 (`dfc1b5fb`), 0233 (`8faa901b`) and the frame-fixture Quick Fix (`069fe2c9`) supply the existing value, batching and consumer contracts.

## B13a: Rust Polars

**Packing is implemented.** The optional `polars` feature's five [`PolarsEngine` methods](../../crates/thinkthen/src/public/frame.rs) each read one Series or one frame `on` column, then call `decide_many_with` or `annotate_with` once over its rows with the caller's `CallOptions`. Those are the landed 0212/0216 planners, so default Max, explicit batch one, request/profile limits, ordered output, duplicate sharing, stop and joined worker semantics are inherited. `decide_series` accepts eligible shared context through the fixed-question planner; the other Series methods and `annotate_frame` reach `annotate_with`, which refuses unsupported context before a send. A saved decide question reaches its question-file batch tier unless the typed option or engine tier wins. A saved calibration profile is retained on that decide route; the [Polars profile case](../../crates/thinkthen/tests/polars/door.rs) proves its digest/warning and one send. Choose/score/tag Series use a one-member set; the accepted 0203 rule refuses a saved profile on a set member rather than losing its name. The Python version pins that refusal. An ordinary engine runtime profile still limits packed requests. Do not silently reinterpret that established saved-profile refusal as a new packing defect.

**The public result remains incomplete under B0.** The trait currently returns bare `Result<Series, Error>` for four columns and `Result<DataFrame, Error>` for `annotate_frame`; it consumes the `Batch` and discards its final `facts()` when collecting. The returned success has no per-call facts. A caller can still use the existing borrowed `CallOptions::observe` callback for question events; this audit does not demand a second stored detail history. The bare return is unlike the accepted [ADR 0089](../planning/adr/0089-rust-calls-carry-facts.md) uniform `Call<T>` rule; that ADR explicitly left the frame adapter's outward shape for its later port row. A post-collection Series/frame conversion error also needs an honest frozen account once work has started. B13a therefore needs a focused product/API correction, not another batch planner. The return shape should retain the existing Series/DataFrame as `Call.value()` with call-scoped facts; the public shape and required-feature consumers need fresh review. Ordinary pre-send type/null/collision refusals retain their no-send meaning; started backend failures retain joined final error facts.

Existing [Polars door tests](../../crates/thinkthen/tests/polars/door.rs) cover all four typed Series values, sliced/chunked input, null/nontext and collision zero-send refusals, preserved frame columns, typed nested failures, empty Series/frame and saved decide identity. [Shared case adapter](../../crates/thinkthen/tests/polars/cases.rs) checks value parity. None pins a multi-row default listener body/count and final facts at the Polars trait boundary. The four `polars_door`, `polars_cases`, `polars_deadline` and `polars_throttle` targets are gated by `required-features = ["polars"]` in the crate manifest; [0212's build record](0212-build.md) documents their successful affected-feature compile after the `Call<Details>` migration. [0209's record](0209-frame-preflight.md) retains selected functional/strict-lint and optional `polars-core` dependency evidence, not a later B13a packing/facts proof. The optional feature is off in the base library graph.

## B13b: Python pandas columns

**No new scheduler or carrier is indicated.** [`Engine.decide`/`choose`/`score`/`tag` and `decide_many`](../../libraries/python/thinkthen/__init__.py) route a pandas Series through [`ask_column`](../../libraries/python/src/frame.rs), which reads its one Arrow or pandas fallback stream, applies `batch=` and eligible `context=`, calls the same Rust many planners, and rebuilds the answer Series inside `Call.value` with the caller's index/name. A pandas frame `annotate(on=...)` calls `_annotate_column` once over the selected column, then rebuilds the typed fields and `failed` with the same index. It accepts `batch=`; shared context is refused by the accepted annotate route. The same code covers pandas 2's fallback and pandas 3's Arrow export. `Call.facts` and immutable `Call.details` survive conversion; returned started failures, completion receipts and rebuild errors have the 0214 account rules. The [0209 frame proof](0209-frame-preflight.md) covers typed null versus failed cells and empty/index behavior in both pinned pandas lanes. The [0214 build](0214-build.md) and [0233 integration proof](0233-python-types-build.md) cover the Python carrier and current native rebuild.

The historical [pandas test setup](../../libraries/python/tests/test_pandas.py) explicitly sets `batch=1` so its per-record value/count, null, empty, index and throttle assertions remain meaningful. The [0214 list listener](../../libraries/python/tests/test_call.py) proves default three-row packing, exact batch-one bodies/digests, suppression, context and facts, while its column/frame case proves values and facts but does not count the column requests. A single read-only offline observation on this audit's warm pinned Python 3.13.5 extension, using the existing conformance backend and no product/test edits, gave a three-row pandas `string[pyarrow]` Series: **one listener send, `facts.records=3`, `facts.requests_sent=1`, three details**. The same observation gave the same four numbers for a Python Polars Series. This resolves the named uncertainty about default column packing at that build; it does not replace a retained outside-in regression for pandas 2, all column verbs or frames.

Pandas needs **distinct focused proof**, not a product change on present evidence: one counted offline listener table should exercise a default multi-row Series and one `annotate(on=...)` frame, compare explicit batch one, pin per-call facts/details and typed/indexed outputs, and show eligible decide context changes request identity. Use the existing listener and cases; include both pinned pandas 2 and 3 routes without a broad matrix. Existing empty Series/frame and null-input zero-send checks remain; pin facts where a started return supplies them and do not invent facts for a genuinely pre-worker refusal. File-backed profiled choose/score/tag columns hit the accepted one-member-set Usage refusal before a send, as [0203](0203-post-settings-preflight.md) and [`test_saved_profile_details_and_column_refusal`](../../libraries/python/tests/test_surface.py) already fix. Saved decide and ordinary runtime-profile routes should be distinguished in the focused proof, with the existing question-file batch precedence preserved. The completed 0233 optional Pydantic/typed labels work does not change this packing boundary.
