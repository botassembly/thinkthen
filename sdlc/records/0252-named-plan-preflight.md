## Current parser and boundary facts

The shared public `Recognize::from_json` and `Relate::from_json` validate the settled plan grammar and canonical identity. They also enforce library restrictions: recognition reads one whole text, so a nonempty `on` is refused; relation entities carry `/name` and `/kind`, so other file pointers are refused. Their public `load` methods call unbounded `read_to_string` and forward `error.detail().message()` as Local. A parser error can include an unknown file-supplied key, so those methods are **not** the proposed host boundary. Keep the existing 0244 bounded file pattern: open under the caller process, read at most 1 MiB plus one byte, reject oversized or invalid UTF-8 input, validate with the appropriate public `from_json`, and map named-file failures to fixed path-free and content-free Local categories. The same malformed JSON passed inline remains Usage.

TypeScript's `src/door.rs::question_file` already has the bounded read and safe envelope, `src/node.rs` exports it, and `index.js::questionFile` checks a nonempty well-formed string with no NUL. Ruby's `src/ffi/question_file.rs::read` has the analogous bounded read and fixed categories; `ThinkThen.question(file:)` normalizes a valid UTF-8 path. Reuse those host patterns without treating their scalar parser as a plan parser. No symlink ban or custom path namespace exists in the current host contract. A path is read with the caller process's ordinary file authority at invocation. It is not an immutable snapshot across later separate calls.

Likely implementation claims after design acceptance: TypeScript `libraries/typescript/{index.js,index.d.ts,src/door.rs,src/node.rs}`, one coherent private loader child if the door approaches its cap, and selected `tests/{verbs.test.mjs,types.test.ts}`; Ruby `libraries/ruby/lib/thinkthen.rb`, `src/ffi.rs`, coherent `src/ffi/question_file.rs` or adjacent private child, and `tests/{test_surface.rb,test_errors.rb}`. Review README and NOTES consumers for both hosts, the shared-conformance issue and derived port counters after implementation. Current nonblank source sizes are TypeScript `index.js` 402, declarations 331, door 340, node 134; Ruby `lib/thinkthen.rb` 566, `src/ffi.rs` 461 and file-loader child 28. These are measurements, not permission to exceed a policy cap. No C, R or SQL source change is proposed.

The smallest meaningful public proof is one real temporary recognition file and one relation file per changed host. Enrich **both** files with distinct saved models and profiles and nondefault thresholds; recognition also needs a nondefault relation threshold. Give the engine a different default model, then compare every captured request's effective model, canonical body and question digest to independent fixed expectations. The recognition stages and relation route must separately retain their file metadata, including ordered descriptions and relation reads. These are the same two valid cases per host, not extra cases. One file with a deliberately unknown private key, one unreadable path, oversized and invalid UTF-8 content, and an invalid UTF-8 path at Ruby's edge must be Local or Usage by origin, non-retryable and zero-send, with no file key, path, evidence or URL in diagnostics. Keep an inline equivalent as Usage, a literal `@` string in its existing meaning, and no mixed file-plus-inline overrides. Retain one existing recognition/relation answer-shape case; no full 54-case or multi-host matrix is required for this design.
