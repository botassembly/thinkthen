## What the first memo missed

It correctly rejected secret-shape inference and recording-only stripping. It missed the exact known-key collision: `Backend::address` preserves path bytes, while `cli/edge.rs::key` and `public/settings.rs::EngineBuilder` know the configured value but never compare it with the resolved URL. `core/recording.rs::Entry::of` stores the URL literally; `Exchange::digest` and `core/recording_identity.rs::BackendIdentity::new` hash it; `Entry::replayed` requires exact equality. `core/plan_document.rs`, `cli/recognize/dry_run.rs`, `cli/relate/dry_run.rs`, `cli/status.rs` and `cli/check.rs` print the URL. `public/results.rs` retains it. `core/text.rs::text_value!` derives `Url` Debug, and `core/recording.rs::Exchange` Debug includes it. `cli/edge.rs::Environment`, `config.rs::Config` and `public/settings.rs::EngineBuilder` derive Debug over raw optional base URL strings. The CLI argument structs also carry raw `--url` strings. A collision exposes the configured key *through the URL* in plans, results, recordings and logs even though the path itself was user-supplied. Existing `engine/facade_tests/contract_tests.rs::no_key_reaches_a_result_an_error_a_recording_or_a_count` uses a separate key and URL.

`specification/backends.md` says dry runs read no key; `cli/asking`, `annotate`, `find`, `recognize`, `relate` and `check` have keyless planning branches. `cli/status.rs` already asks `Environment::api_key_set`, which reads key presence. A dry run may hash the resolved URL while preparing request digests. The combination of no key read, an arbitrary exact URL plan, and a guarantee against disclosing the effective key *through that URL* is impossible for a configured key that happens to equal path bytes. The ticket proposes one explicit compatibility amendment for Ian; no decision has been made. This URL rule cannot detect the same bytes deliberately supplied as evidence, model or question text.

The first design draft missed timing as well as scope. `engine/prepared_request.rs` hashes the URL before `engine/request.rs` invokes `KeyReader`; `engine/recorder.rs` may open a folder or temporary entry before that callback, and replay never invokes it. Two reads cannot guarantee that the checked value is the one sent, nor undo a hash or folder access if the environment changes. Production CLI `Settings.key` closures occur in `cli/asking.rs` and `cli/check.rs`; both currently call `edge::key` lazily. A production search of `KEY_VAR`, `THINKTHEN_API_KEY`, `api_key_set()`, `edge::key()`, and `Settings.key` found the remaining CLI side read in `cli/status.rs::gather`: it calls `Environment::api_key_set`, whose implementation in `cli/edge.rs` calls `read(KEY_VAR)` again. The checked snapshot must supply both that status field and the collision check; remove the separate accessor from this production path. `cli/conformance_tests` uses synthetic key literals for tests, not a production reader. Public `EngineBuilder::from_env` captures its environment key, and its `api_key` setter overrides that field before `build`; Python and the other supported library/database doors ultimately use that public builder, subject to final constructor audit. The corrected design has the CLI snapshot an optional effective key once after final URL resolution and use that same value in its later `KeyReader`. Replay and dry-run inspect that optional value but never require one. This changes key-read timing, not the accepted safe URL or request identity.

The first draft also named only the backends dry-run sentence. `specification/recording.md` promises replay reads no key, folder mismatch precedes key access, and a temporary entry precedes key access. `cli/args.rs` help promises no key read for dry-run and replay; `cli/args/command.rs` says the same for check; executable `specification/check.md` says check dry-run reads no key. `specification/backends.md` says request chunks are encoded and digested before key access. All need a coherent amendment if Ian approves early optional inspection. Preserve keyless execution, no connection, existing safe folder-mismatch exit/message, and temporary write before send. The collision refusal must precede a mismatch because that error embeds the resolved URL.
