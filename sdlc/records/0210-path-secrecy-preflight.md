## What the first memo missed

It correctly rejected secret-shape inference and recording-only stripping. It missed the exact known-key collision: `Backend::address` preserves path bytes, while `cli/edge.rs::key` and `public/settings.rs::EngineBuilder` know the configured value but never compare it with the resolved URL. `core/recording.rs::Entry::of` stores the URL literally; `Exchange::digest` and `core/recording_identity.rs::BackendIdentity::new` hash it; `Entry::replayed` requires exact equality. `core/plan_document.rs`, `cli/recognize/dry_run.rs`, `cli/relate/dry_run.rs`, `cli/status.rs` and `cli/check.rs` print the URL. `public/results.rs` retains it. `core/text.rs::text_value!` derives `Url` Debug, and `core/recording.rs::Exchange` Debug includes it. `cli/edge.rs::Environment`, `config.rs::Config` and `public/settings.rs::EngineBuilder` derive Debug over raw optional base URL strings. The CLI argument structs also carry raw `--url` strings. A collision of the configured key with URL bytes contradicts the no-key-in-plan/result/recording/log rule even though the path itself was user-supplied. Existing `engine/facade_tests/contract_tests.rs::no_key_reaches_a_result_an_error_a_recording_or_a_count` uses a separate key and URL.

`specification/backends.md` says dry runs read no key; `cli/asking`, `annotate`, `find`, `recognize`, `relate` and `check` have keyless planning branches. `cli/status.rs` already asks `Environment::api_key_set`, which reads key presence. A dry run may hash the resolved URL while preparing request digests. The combination of no key read, an arbitrary exact URL plan, and an absolute no-key-output/hash promise is impossible for a configured key that happens to equal path bytes. The ticket proposes one narrow contract amendment for Ian; no decision has been made.
