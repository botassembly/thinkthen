## Current product path and failure mechanism

`databases/duckdb/cpp/build.sh` builds `bridge/Cargo.toml` as a Rust `staticlib` without `test-hooks` and links `libthinkthen_duckdb_bridge.a` into the C++ extension. [The DuckDB README](../../databases/duckdb/README.md) identifies this C++ route for Linux x86-64, Linux ARM64, Apple Silicon and Intel macOS. The old `databases/duckdb/src/errors.rs` guard serves retained C API sources and its 0226 child does not exercise this bridge. `databases/duckdb/proof/0201/src/ffi.rs` explicitly calls itself a proof, not the product bridge; its historical plain-panic result and hook fix do not establish opaque-payload disposal in current `bridge/src/ffi.rs`. The bridge Cargo package declares `test-hooks`, but `cpp/build.sh` supplies no such feature and DuckDB's source checks reject it in a shipped extension.

`bridge/src/ffi.rs::install_hook` installs one delegating Rust hook. `BRIDGE_DEPTH` is thread-local and `BridgeDepth::drop` restores its previous value. `in_bridge` increments depth around its call. The current catches instead wrap `in_bridge(call)`. On unwind, `BridgeDepth` restores the prior value, normally zero at a top-level export or worker entry, before `catch_unwind` returns `Err(Box<dyn Any + Send>)`. Each caller discards that opaque box through `unwrap_or`, `unwrap_or_else`, `map_or` or an ignored `Result`. Rust must drop it at that point. A payload whose own `Drop` panics does so after the owned scope has ended. The prior host hook can print that second payload, an `extern "C"` route can abort rather than return its fallback, and a detached worker can disconnect before sending its fixed defect. This is a source-confirmed conditional path; no production panic or credential disclosure has been observed. ADR 0098 already accepts forgetting an opaque caught payload **inside** a marked native scope, with one retained allocation per panic and a possible retained private byte string in process memory.

| Catch at `bridge/src/ffi.rs` | Current consumers and fallback to retain | Ownership point |
| --- | --- | --- |
| `guarded` | `thinkthen_cpp_free`; fixed `thinkthen defect: the bridge panicked`, though free ignores it | Returned error's payload is discarded after `in_bridge` restores depth |
| `reply_boundary` | Scalar, find, listed, nested, complete-listed, warm, relate, usage and validation exports in this file and FFI children; status 4, null bytes, length zero | C++ `bridge.hpp::ReplyText` maps a null error buffer to `thinkthen defect: the bridge returned no error buffer` |
| `thinkthen_cpp_init` | Extension load; 4 on panic | Hook installation and signal setup sit in the catch, but without a marked bridge scope |
| `thinkthen_cpp_query_begin` | Statement signal owner; null on panic | Owned `Invoke` is constructed inside `in_bridge` |
| `thinkthen_cpp_query_stopped` | Statement interrupt check; 1 on panic | Caller retains the scope pointer; the catch discards its payload outside `in_bridge` |
| `thinkthen_cpp_query_end` | Statement cleanup; void on panic | `Invoke` is dropped inside `in_bridge`, then a caught payload is ignored outside it |
| `run_detached` worker closure | All model-call groups, find, warm and relate; fixed `thinkthen defect: the engine worker panicked` | The worker enters its own bridge depth. It must dispose of payload before it sends the error over its channel |

`bridge/src/errors.rs` maps public `thinkthen::Error` to `RowError` and safe try-values; it has no panic catch. The C++ interrupt predicate in `cpp/src/bridge.hpp` is `noexcept` and catches its own exceptions. Engine `workers.rs` installs its separate diagnostic scope on public/worker calls and can nest under the bridge scope; a caller thread's TLS depth is not inherited by the bridge's detached worker. These are reasons to preserve the existing hook and explicit worker entry rather than add a process-global replacement or alter host callback policy. A later host hook replacement remains the accepted coexistence limit. No current source evidence warrants a new DSO-retention or unload rule.

## Build handoff and evidence boundary

The only necessary production Rust file is `databases/duckdb/bridge/src/ffi.rs` plus one coherent safe private child such as `bridge/src/ffi/panic.rs`. The parent has 496 nonblank lines against its 500-line cap; moving the hook/scope/catch implementation to the child creates room without expanding a shared framework. The DuckDB Rust ratchet measures both `databases/duckdb/src` and `bridge/src`; current `databases/duckdb/ratchet.json` is 6,497. The existing `bridge/src/errors.rs`, legacy `src/errors.rs`, C++ `bridge.hpp`, bridge Cargo feature policy and packaging scripts are read-only unless implementation uncovers a distinct dependency. An unsafe export belongs in a file whose basename is `ffi.rs` under current policy; the proposed `panic.rs` needs no export. A test-only linkage symbol, if required, needs its own permitted `ffi.rs` path and an exclusion check on the release artifact.

The smallest new test is one child in a private bridge test file.
