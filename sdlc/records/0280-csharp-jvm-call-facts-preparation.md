## Smallest discriminating proof and limits

Use the existing controlled replies and exact wire-request inventories, not a second J1 corpus. One four-route value-plus-facts table per host checks a scalar, ordered bulk, recognize and relate, with required `records`, `requests_sent`, `cache_answers`, `seconds` and optional model/tokens. A zero-count bulk has empty value and `records=0` with zero arrivals. A reply with no `usage` checks nullable/absent optional token fields; missing or null required counts must fail decoding rather than become zero. Each C route is statically one facts `_opts` call, and the external listener count checks that no second model request occurred. Do not assume `facts.records` equals relate input entity count or `requests_sent` equals bulk row count.

For each host, use **typed** `decide` on a started 401, read its copied `requests_sent=1`, make another native call/failure, close, then compare the first copied facts; pin a pre-start refusal as factless. This specifically fixes the 0277 proof gap where a JSON failure did not cover the newly migrated typed path. For concurrency, start two typed calls against distinct existing `hold-*` states, require both `arrived-*` markers before releasing either, then assert each result's own values/facts survive later activity. Existing future/task launch alone does not prove overlap. C# retains active-call close waiting; JVM requires join-before-close and makes no concurrent-close promise. Retain the current deadline/cancel output-sentinel tests. Counted result/facts pointers must both be freed if either copy or decoder throws; a focused local invalid-facts fixture can exercise that error path without a production hook or provider.

Run focused source matrix/host compilation, one matching installed-source consumer per host, current C header/export check, measured ratchets, applicable child guard for edited Python helpers, and policy/pages/tickets/diff. Do not start full `surfaces`, J1, portable-batch, release container, Actions, provider or package campaign in preparation. Linux source proof and installed NuGet/JAR proof are distinct; neither proves another runner or registry publication. The broader issue's richer detail, cost, vendor timing/IDs, other wrappers and held SQL/DataFrame contracts remain open.

## What preparation taught us

The C# JSON `CallResult` name is already occupied; a typed `TypedResult<T>` avoids changing that route. JVM `ResultEnvelope` validates required members but currently returns only JSON value bytes, so a narrow facts accessor can reuse its parser. Its release pair checker pins exact nested class names; a source-only edit to `Door.java` would make the later package checkpoint fail even if Java source tests pass. Both backends already have held-request markers, which supply real overlap proof without a new listener framework. Header declarations, Rust exports and 0255 installed receipts agree, but the old wrapper archives do not establish that newly migrated managed calls work.
