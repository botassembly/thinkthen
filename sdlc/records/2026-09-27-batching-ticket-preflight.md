## Boundaries to preserve

- **Counts and refusals.** `engine/request.rs` installs `Counters::attempt_sent(retry)` as the HTTP attempt hook, but main `b7efdcc9` `engine/http.rs:160-168` invokes it before `cancel.remaining()?` and `send`. `remaining()` observes the deadline alone; expiry during the hook can charge an unsent attempt. `engine/deadline_tests.rs::accounting_that_outlasts_the_budget_sends_nothing` already proves no request is sent in that interval, but omits a usage assertion. Add a counter assertion there or in an equivalent bounded case. Accepted [0149 SQL settings](https://github.com/botassembly/thinkthen/blob/2999814e/sdlc/tickets/0149-sql-settings.md) design item 4 owns final stop, reservation, count and transport ordering. That narrow send-boundary correction must precede exact 0170 facts, even if the rest of SQL settings waits. `Counters::add` takes a mutex and may start its writer; the current hook is not wait-free. `Counts` in `engine/usage/counts.rs` gives `retries` a default in the old `thinkthen.usage/1` schema. `cli/asking/batched.rs::answered` divides successful batch usage and attempt counts among rows; facts report whole-run totals. Main `engine/schedule.rs::Completed.replayed` is Boolean and `Run::drain` adds all `completed.records` or none; a split batch with one replayed and one live half needs a per-batch replay count. The 0154 builder is correcting that private representation. Recheck it on landed main before 0170. Distinguish rows, logical requests, actual attempts and replayed records in the proof. The runtime remains uncorrected in this preparation.
- **Listener helper semantics.** In main `b7efdcc9` `conformance/backend/src/listener.rs:298-303`, `Listener::requests()` collects from `try_iter`, draining the recorded channel. Repeated calls do not return a cumulative list. `Listener::count()` at lines 272-275 reads a persistent atomic total. Capture bodies once for body assertions, then use `count()` for later totals. The 0154 builder discovered this while checking a four-case filter and is rerunning that focused proof; no runtime outcome follows from the earlier assertion failure.
- **Stops.** `cli/failure.rs::Failure` now includes `ModelsDiffer` and `UsageOverflow` from 0169, plus wrapper forms `Stopped` and `BatchFailed`. `cli/mod.rs::told` can replace a failure after a signal. A single cause mapping must cover the final, transformed error, then the facts line must follow the usage warning and precede signal completion. The 0169 printed-after-stop and missed-conversion findings are the reason for this check.
- **Row metadata.** `core/result.rs::RequestMeta` and `Meta` serialize nested result metadata. `result_json.rs::decision` builds command details; the same result type also serves the library. Add optional batch, warning and context members only under their accepted predicates. A default batch-one row without context must remain byte-identical. Check typed nested fields, not broad string replacements. This applies the 0152 and 0204 schema incidents.
- **Size and digests.** Main `core/batch/tests.rs:388-425` proves three 20,000-byte records fit one 96,000-byte request, whereas three 40,000-byte records form two then one. Pending 0154 corrects its fixture to 40,000. `specification/fixtures/systemone/batch-context.request.json` pins wire bytes for 0172. Generated recording names derive from `Exchange::digest`; inspect actual request bodies before changing fixtures. The 0154 arithmetic and 0152 digest incidents motivate this check.
- **Value domains.** `Batching::batch` accepts positive integers or `max`; `Tiers::setting` handles typed, environment and file values. A batch-one row can omit `meta.batch` even in a larger batched run. That is the accepted 0171 ambiguity, not an absent implementation to repair. A `--context` file is valid only on decide/filter/rank streams under 0172. Unlike 0149 SQL, these tickets do not introduce a SQL NULL or budget setting; do not transplant SQL zero/NULL fixtures into their proofs. The 0149 host-range correction motivates this explicit boundary.
- **Complete paths.** For 0170 follow parsed `Common` and `FindCommon` through `cli/mod.rs::run` and every asking verb's ordinary, dry-run and error return into `entry`'s report, usage flush, facts line and signal finish. For 0172 follow parsed `Batching::context` through `cli/judge.rs::Asked`, `cli/asking.rs::run`, exact file read, `Batcher::new`, then both `planned` and the live `Former`/`answered`/result path. These are the bounded call-graph inventories that the 0154 missing-adapter incident calls for.
- **Measurement parser.** `core/measure.rs::json_lines` already yields typed `Json` lines. `cli/audit.rs::grade_all` retains those lines through `write::bars`; `cli/diff.rs::compare_all` currently turns each side into `Answer` values before warning output. Read nested `meta.batch.setting` from the original lines where possible. A design that instead adds this field to `core/measure/answer.rs` needs a new file claim before editing. Either way, preserve literal option names, applying the 0152 porter lesson.
