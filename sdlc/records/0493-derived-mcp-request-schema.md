# Derive MCP admission and schemas from Request

The design starts from `840d420c19e9a0ee18703df7c018cac40841c380`. MCP repeats question preparation, option applicability and native dispatch. `Request::admit` and `Engine::execute_request` already own those behaviors. MCP should translate its established carriers into typed Request values, delegate admission and execution, and retain protocol IDs, cancellation, framing and response presentation at the edge. The generated `specification/request.schema.json` supplies structural input schemas without adding a production schema dependency.

## Preserve retained attachment admission

The shared execution path currently reads attachments through ordinary native readers. `RequestEnvironment` supplies controls and a feed, but supplies no transport attachment allowance. Inline admission also clones and validates byte values before execution receives that environment. An execution-only allowance would arrive too late. Routing MCP through that path would remove the before-allocation protection established by [ADR 0128](../planning/adr/0128-mcp-retained-attachment-bound.md).

Add a crate-private `TransportAttachmentLimit` containing a positive byte ceiling and a crate-private `Request::admit_for_transport(self, limit: TransportAttachmentLimit) -> Result<AdmittedRequest, Error>`. Store the optional limit on `AdmittedRequest`. Keep public `Request::admit` unchanged with no transport limit. MCP supplies `mcp::protocol::MAX_MESSAGE`; canonical request JSON, native defaults and cache identity acquire no setting.

Admission preflights the aggregate original inline byte lengths with checked subtraction before any existing inline clone or pixel decode. This preflight establishes whether the header can retain its supplied originals. It does not consume the execution allowance. Composition starts one allowance at the same ceiling and accounts each caller attachment occurrence once, in caller order, before retaining its original. Inline composition subtracts its original length before cloning. File composition uses the existing `SourceItems::bounded_images` reader with the remaining allowance and adopts the reader's remaining count after success. Explicit finite collections preflight completely before any sends. Sources account cumulatively as their existing iterator advances and retain admitted-prefix behavior. Exhaustion stops before later evidence or attachment paths.

Repeating a caller descriptor charges every occurrence. Internal immutable `ImageInput` handle clones reuse the existing shared bytes and incur no new charge. Do not subtract inline lengths during both admission and composition from one mutable allowance: admission checks a total and composition owns the actual accounting. Temporary validation copies, pixel scratch, protocol carriers and result representations remain separate memory costs. This ceiling bounds original compressed bytes; it does not bound process RSS. Ordinary native image limits remain stricter where applicable.

The proposed shared file claim is `crates/thinkthen/src/public/request.rs`, `public/request/admission.rs`, `public/request/composition.rs`, `public/request/execution.rs` and the descriptor seam below. `public/request/inline.rs` belongs in the claim only if its validation needs the admitted limit. `public/input_files.rs` needs only removal of the existing bounded reader's CLI feature guard if library-only compilation requires that entry point. Shared ownership must transfer from the SQLite developer before those edits. Candidate `771468210` adds composed `RequestFeed` records, eager admission and explicit image route admission; reviewed landed code should supply those APIs. No unreviewed candidate merge or second composition implementation belongs in this work.

## Compose descriptors before their allocations

Fresh review identified a missing carrier: an MCP descriptor may select exactly one whole text file and attach images to its resulting located original. `RequestOriginal` carries text or JSON, and `RequestFeed::from_records` receives rows after their attachment allocation. Passing those rows through execution cannot protect the earlier reads. The proposed stored allowance therefore also governs shared descriptor composition before any MCP descriptor reads or decodes images.

Add crate-private `TransportDescriptor { item: RequestItem, source: Option<RequestSource> }` in `public/request/transport.rs`. An inline descriptor uses `item.original`; a whole text-file descriptor uses `source` and leaves `item.original` absent. An image-only descriptor leaves both absent. Shared header admission rejects simultaneous inline and source originals, validates the same RequestItem metadata and image controls, and restricts descriptor sources to explicit whole text files. Source resolution must produce exactly one item, retaining native physical location. This is a native transport carrier, without serialization or a new canonical filesystem variant.

Add crate-private `AdmittedRequest::admit_descriptor_feed(&self, name: String, descriptors: Vec<TransportDescriptor>) -> Result<RequestFeed<'static>, Error>`. This validates every descriptor header and preflights cumulative inline attachment lengths before any reads, clones or decodes. It constructs an opaque descriptor feed with eager finite semantics and image-route declaration derived from its descriptors. Its name must match the request's existing Feed selector. `FeedContents` receives an internal `Descriptors` variant; callers cannot mark these rows as already composed. Feed admission uses the request's stored limit without storing another allowance on the feed. Existing public item and composed-record feeds retain their contracts.

Shared Request composition consumes that descriptor feed with its one remaining allowance. Move the existing descriptor behavior from `mcp/inputs.rs::Descriptor::compose` into this shared seam and reuse the canonical attachment reader, authored reading, context declaration and projection helpers. For each descriptor, check cancellation, resolve and charge attachments first, then open or compose its original, then apply its explicit context and options. This preserves refusal before a later evidence path after attachment exhaustion. Compose the entire finite descriptor collection before any sends. Pass its already charged immutable image handles directly to the existing native execution path; do not convert them back into byte descriptors or invoke attachment reading and accounting again. The composed-feed validation path may check image routes, declaration admission and native limits without charging the originals a second time.

MCP only decodes its established descriptor aliases into `TransportDescriptor`, admits the complete feed through Request and supplies it in `RequestEnvironment`. Remove its descriptor composition, question preparation and execution copies after integration. No MCP-owned composer, callback that opens files before the shared allowance, second byte budget or caller-controlled exemption remains. Canonical finite items and top-level sources use the same attachment reader and accounting helper in Request composition. Source iterators retain prefix behavior; finite descriptor feeds retain whole-call preflight.

## Map the MCP surface

Preserve literal, file, name and reference question selectors. Preserve evidence, records, sources, ordered input descriptors and ordered image paths. Translate transport field aliases to Request fields and keep initial cancellation and reserved proxy refusal at the protocol edge. Shared Request admission owns ordinary question, option and item validation. Shared execution owns question resolution, native preparation and judgment dispatch. Response mapping preserves existing scalar versus row results, failed members and joined prefix failures.

Project advertised structure from the generated canonical schema and retain only the transport alias and carrier transformations in MCP. The canonical schema currently describes structural decoding rather than all semantic applicability: its RequestOptions definition includes every function's controls. Function restrictions must follow shared admission facts rather than acquire another MCP table. Recognition stage controls from 0478 and 0479 remain an explicit adoption gap; this migration must not advertise or duplicate their future logic.

## Behavior checks

Extend the existing installed MCP boundary cases with cumulative inline admission, exact and over-ceiling collections, ordered duplicate paths, mixed inline and file attachments, and exhaustion before a later path. Include whole text-file descriptors with attachments and preserved locations, exhaustion before that descriptor's missing evidence path, and a later finite descriptor failure with zero sends. Count loopback requests to establish zero sends for finite failures and retain a source-prefix case. Check that already charged image handles execute at the exact ceiling without a second charge. Keep native compatibility and the installed saved-response suite as the owners of ordinary execution. Preserve malformed-envelope IDs, cancellation, EOF, local file selectors and framing through their existing cases. Run policy before review and the required lint, test, specification and installed MCP checks under the lane's existing bounded build scopes.

The source inspection and review taught two concrete lessons: an execution-only allowance cannot protect admission that already clones inline bytes, and a composed-record feed cannot protect attachment reads that precede it. Carry the allowance on the admitted request and move unresolved descriptor composition behind that allowance without changing native or serialized controls.

## Implementation lessons

Fresh design review accepted the corrected descriptor seam in `236db588`; the shared Request claim transferred after the reviewed SQLite native-feed bridge landed. MCP now constructs typed Request carriers, delegates ordinary admission and execution, and projects structural schemas from the committed canonical JSON. Shared `RequestFunction::allows_option` supplies applicability to admission and schema projection. The old MCP composer, dispatcher and ordinary control wrappers were removed. Protocol cancellation, reserved proxy refusal, IDs and scalar versus row response presentation remain at the edge. Native public admission, the ABI and canonical settings remain unchanged.

The first integration checks exposed lost inline error ordinals, changed explicit question-file errors, singleton image response shape, object context selection and implicit primitive threshold promotion. The fixes preserved the established transport behavior through shared owners and direct typed Request construction. An initial hypothesis that canonical DynamicChoose required options was an unverified inference. Concrete canonical-schema validation disproved it, so the generator change was dropped. The retained installed regression admits dynamic choose and refuses malformed selectors and inapplicable controls without sends.

The first full lint exited 101 on Clippy nesting and length findings. Extracting selector, bounded source-reader and descriptor-composition responsibilities fixed those findings without splitting by line count. The first full test exited 100 because the new source-prefix fixture named a missing tail; manifest inspection correctly refused it during admission. The corrected fixture uses an existing corrupt tail and explicit batch one. It admits successfully and asserts one completed decision and exactly one counted loopback request before the repeated second attachment exhausts the allowance.

Stable-source lint passed. The next full test exited 100 in the unchanged CLI relation concurrency fixture: its final leg observed four sends instead of three. That fixture assumes 300 ms and 600 ms reply ordering under load. The CLI still calls `Engine::relate` directly; neither that path nor the fixture changed. One exact isolated reproduction passed, then one full retry passed all 1,830 workspace tests, 360 library-only tests and 23 consumer tests, plus doctests, live tests and binding smokes. The failed run had 1,313 passes and 516 cases left unrun by fail-fast; it did not qualify those cases. Required specification checks passed, including 24 demos.

Five duplicate helper tests were removed after their behavior remained covered by existing installed cases for carrier kinds, source ordering and locations, source-unit constraints, image ordering and malformed descriptors. The rank reader callback regression moved to the shared reader owner. New focused tests cover inline preflight, mixed inline/file exact bounds, attachment-first refusal and counted source prefixes. No functionality or unique behavioral coverage was removed. Existing library-only unused imports, policy file-size notices and unmatched dependency license exceptions remain warnings. Recognition stage controls await 0478 and 0479; native Windows qualification and explicit stress checks remain outside this migration.

The required installed canonical suite then exposed nine genuine integration defects after 249 passes. Eight declaration refusals lost their safe native diagnostic through serde conversion; saved selectors also need their existing Local class. A crate-private `RequestDefinition::from_authored_json` now reuses the existing parser and retains those diagnostics without exposing serde text. Annotation document text had been composed as a string record before the native annotation JSON preparation. Shared admission and composition now retain the document carrier when no explicit projection applies. Existing canonical fixtures own all nine regressions and their counted send expectations; none of their expectations changed. The earlier passing root checks qualify the earlier source only.
