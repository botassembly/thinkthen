`catch_unwind` invokes the hook before it returns. The existing C/SQLite/old DuckDB guards independently copy payloads. Each caught payload is arbitrary `Any + Send`, and its destructor may panic: forget it inside the marked scope in every `Err` arm, including C `built`. This trades one retained allocation per caught panic for containment and may retain sensitive bytes in process memory. It needs no extra catch site. Host hook state is global **within a linked Rust runtime**; a once-installed wrapper delegates for unrelated threads, but later host `set_hook` or concurrent registration can bypass it. Per-call hook swapping is rejected. A representative packaged Linux C `.so` at source `22f36d00`, SHA-256 `87771200742859af05ec2f6e161db01d6b9cdbb16c1d65d3a74762fdb2a09b29`, has local `std::panicking::HOOK` BSS, no `NODELETE` flag and no separately linked Rust runtime. Bounded workspace experiment `298-thinkthen-native-hook-loader-probe` called its exported no-network error function on a joined thread, closed the sole `dlopen` handle, and observed the DSO unmapped in `/proc/self/maps`. A main-thread call remained mapped after close, plausibly due to live TLS; the probe does not establish that cause. Thus unconditional C self-retain and moving SQLite's existing post-registration worker pin before failed load are **not** proposed. This is historical Linux evidence, not changed-source or macOS proof. Refresh built artifact symbols/linkage, flags and loader results; if hook state resides outside unloadable code on a supported artifact, stop for an explicit reviewed lifetime choice. Pinned DuckDB v1.5.5 loader source uses `dlopen` with no `dlclose` in its extension tree; validate each shipped target. Current C pointer calls, SQLite C interrupt predicate and old DuckDB atomic SIGINT predicate expose no Rust host callback to mask. C++ exceptions stay on the C++ side.

## Preparation lesson and refresh trigger

The 2026-09-27 issue predates the landed Linux C++ package; its DuckDB row means the retained C API. Tracing only callback guards missed detached workers and SQLite's separate load entry. The first review found three more preparation gaps: opaque payload Drop can re-panic, Linux SQLite package proof does not cover macOS or necessarily check an exact failed load, and “process-global” alone does not establish cross-DSO hook lifetime. The historical Linux artifact and bounded unload probe refuted an unconditional self-pin premise, while leaving changed-source and macOS proof open. Before implementation, refresh main ancestry, exact claims and package targets; compare built child, symbol/linkage and installed package evidence with this inventory.
