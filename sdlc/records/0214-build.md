## Implementation

The Python extension now returns `Call.value`, `Call.facts` and owned immutable `Call.details` from every asking route, including scalar, eager list, Series, frame, `details()` and module delegates. Rust observations supply question detail; the existing planner supplies per-call facts. Eligible `batch` and `context` controls reach the Rust path, and new eager `choose_many`, `score_many` and `tag_many` use 0230's dynamic-question bridge. The account stays with Arrow/frame conversions and aggregated per-text recognition; a returned post-call conversion error keeps it. A caught worker panic has no invented account.

ADR 0091's approved completion receipt lets `Cancelled` and a signal handler's `SystemExit` raise promptly while the existing worker finishes. The receipt owns one terminal state, supports a retryable timeout, and returns final facts/details after joined success or returned failure. It does not return a value discarded by cancellation or perform another request. Six existing exception kinds, pandas index/name, Polars dtype, and 0209 frame columns remain the value contract.

`libraries/python/src/result.rs` contains the carrier and snapshot conversion. Private `engine/{settings,operations}.rs` and `frame/{names,recognition,stop}.rs` children keep each edited Rust file under 500 nonblank lines; they extract settings, planner dispatch, recognition and frame worker failures instead of copying the scheduler. ## High review correction

The retained High reviewer examined integrated source `c9579b02` and found three gaps. First, an Arrow `Series` could be validated after worker start and return `Stop::Said` with no account. `on_worker` now supplies a final elapsed zero-send account only for its returned unaccounted `Stop::Said`; genuinely pre-worker refusals and caught panics remain without one. The existing `test_what_the_door_refuses_sends_nothing` case asserts zero records, zero sends and empty immutable details for a numeric Polars column while its listener count remains zero. It failed before the correction because `UsageError.facts` was absent.

Second, the completion receipt kept only outcome/facts/details. The worker now retains the returned error's safe kind, message and retryable flag, including frame `Stop` errors, and exposes them on the frozen `Completion`. The held returned-error case asserts the exact cancelled kind/message/false retry signal after release; it failed before the correction because those properties did not exist. It still checks prompt cancellation, one send and a retryable receipt timeout.

Third, the three-row listener case counted sends but did not pin filter suppression or request identity. One local HTTP listener now captures the actual packed request and three explicit batch-one requests. The same case compares each batch-one body byte for byte with the old singleton shape, computes digests from captured bodies and endpoint URL, checks the suppressed duplicate row's ordered detail, and sums request token shares back to call facts. No test-only product export or second layered proof was added. This case exposed a test setup error first: Python's configured base URL is the `/v1` parent of the `/systemone` endpoint; the fixture now names both explicitly.
