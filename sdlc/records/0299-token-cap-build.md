## Changed

`SendBudget` remains the single process reservation owner and now retains an atomic estimated-input sum. Each engine selects its optional finite estimate limit at admission. The exact final encoded `Exchange.body` charges `ceil(bytes × 908 / 1000)` for every live attempt, including retry and split child. The checked reservation drops without charge before transport if a later gate refuses or marking fails; a started send commits even if its reply, decode, timeout or cancellation fails. Unset engines still count. Fork resets both sums. Neither reported usage nor the plan preview settles the admission sum.

Rust `EngineBuilder`, the asking CLI including find, and the C closed JSON constructor actively select the new limit. Core JSON validation rejects wrong types and repeated keys; C retains null as unset. `EstimatedInputDenial` has separate InitialRequest, AdditionalRequest and Retry statuses. Public errors expose that typed reason and safe message; CLI prints the reviewed exact `thinkthen usage:` sentence with exit 2; native batch treats the refusal as a recoverable Usage failure. The C header and specification settings, backend and preview pages describe the source behavior and its limits. No C symbol or result shape changed.

## What the build taught us

The 0289 preparation lesson about a process counter versus a process-wide setting applies to estimates too: a limit belongs to the attempt, and the retained sum belongs to the shared owner. A final body, rather than planned bytes or observed usage, is the only safe admission input. The separate public, CLI and native-batch error conversions were all material. The C header had an older incomplete constructor-key list and was brought into agreement with the closed parser. The host-by-host setting rollout remains explicit; this source candidate does not close the 0299 issue, qualify an archive or claim a provider-side cap.
