## What the build taught us

The scheduler's held flag served both admission and failure wording, so bounding only the CLI winner vector would leave completed batches unbounded behind a stalled earliest request. The private flow value split those responsibilities without changing streaming or uncut rank. A winner sink that drops an invalid row would otherwise hide the old end-only defect; one marker preserves it without keeping the full row. The acknowledged listener case detects the old unbounded dispatch behavior in a small fixture, while the source invariant carries the general bound. Strict Clippy forced a small helper, and the existing core ranking and listener utilities avoided another planner or fixture. The independent reviewer confirmed the record-count bound and its proof, while keeping byte/RSS and speculative-send limits explicit. This distinction is part of the completed guidance, not an unresolved implementation step.
