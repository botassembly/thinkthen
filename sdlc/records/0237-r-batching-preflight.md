## Actual route and inherited behavior

`libraries/r/thinkthen/R/thinkthen.R` owns `tt_question`, ten asking verbs (`tt_decide`, `tt_choose`, `tt_score`, `tt_tag`, `tt_filter`, `tt_rank`, `tt_find`, `tt_annotate`, `tt_recognize`, `tt_relate`), supporting `tt_details`, process `tt_usage`, and `tt_engine`. Each asking function crosses `.tt_call` into generated `R/extendr-wrappers.R`, then `src/rust/src/ffi.rs`. `calls.rs::call` copies arguments to an owned fresh worker, adds cancel and optional deadline to `CallOptions`, then waits in 100 ms main-thread ticks. `ffi.rs` alone touches the R C API; `R_ToplevelExec` catches `R_CheckUserInterrupt`'s jump. `calls.rs::Stop` cancels on wait exit, while a sent attempt still finishes. `lib.rs::Settings::build` begins at `EngineBuilder::from_env`; `THINKTHEN_BATCH` already reaches eligible Rust planners, although `tt_engine` and calls cannot set it directly.

`calls.rs::judged` calls `decide_many_with`; `filter` calls `filter_with`; `rank` calls `rank_with`; `annotated` calls `annotate_with`. Each therefore inherits 0212 Max when no engine/env/file setting intervenes. Ordinary choose/score/tag columns make a one-member set and call that annotate path. When its set builder rejects a saved profile, `one_by_one` calls scalar `details_with` for each row. `find`, `recognize` and `relate` use their own bounded/native paths, not the record planner. This is a partial already-shipped default, not full B12f. `calls.rs` discards `Call::facts` with `into_value`, never reads `Batch::facts`, and passes no observer. The current R results have no call-scoped account except separate scalar `tt_details`; `tt_usage` is process-wide. `tt_decide` and `tt_recognize` skip `NA` rows before crossing; an all-`NA` or empty input can return from R without any Rust account. After valid local setup, return an honest host no-work account with zero records/sends/cache hits, measured elapsed time and absent tokens/model while retaining its old no-send value. This is not a fabricated Rust `Call::facts`; a pre-validation refusal remains unaccounted.

The first High review caught a separate aggregation miss: `relate.rs::recognize` maps each live text to its own `engine.recognize_with`, then `into_value`, inside one native worker. A later text may fail after earlier successes. The R call needs checked sums of all subcall `records`, `requests_sent` and `cache_answers`, including a terminal `Error::facts()` when present; missing token usage in any accounted subcall makes the corresponding total absent, and a single model is reported only if every subcall has the same present model. One outer monotonic elapsed interval covers the entire native worker through the last join or error; summing per-call seconds omits inter-call time. A later pre-accounting error preserves earlier complete facts/details without inventing facts for that failing text. These rules also cover `one_by_one` until its scalar fallback is replaced. Neither one `Call::facts` nor a process-usage delta describes the R call.

The landed `public/bulk/details.rs::details_many_with` accepts runtime `Question` and `I::Item: Evidence + Serialize`, so it supplies the profiled and dynamic-label many-record route, with full original Rust input in its detail document. R must retain its original caller object separately before string conversion. Compile-time `Choice` cannot express R runtime label maps. `CallOptions::observe` invokes a borrowed callback on the native caller thread, which is R's worker; only Rust-owned copies may cross back. `public/batch.rs::Batch::failed` has no facts before accounting; `public/error.rs::Error::facts` exposes final facts after an accounted failure. A worker spawn is not the accounting boundary. `public/batch/planned.rs` makes batch one interactive and pulls one row before yielding; it cannot support an eight-held-send width assertion. Keep the captured old fixtures on batch one and use batch two plus enough input for the separate held-width proof.

## R-specific type and ownership seams

`R/thinkthen.R::.tt_body` starts with `stats::setNames(list(text), kind)` and currently `as.character(...)[[1L]]` erases structured question text before serialization. It turns members into `I(as.character(members))`, losing named descriptions, nested arrays, objects and explicit null. `.tt_json` sets `auto_unbox = TRUE`; single-member arrays and `list(NULL)` require explicit shape proof. The actual `specification/question-file.schema.json` allows a question text string/object/list and description string/object/list/null; `{what, not_for, examples}` is one structured instance. An ordered named list can represent arbitrary description values; a named character vector covers simple text maps. Add `true =`/`false =` on public `tt_question(decide = ...)`, with `missing()` distinguishing omitted from explicitly supplied `NULL`, and reject either side on another kind or beside `file =`. Validate `NA`, type, encoding, duplicates and empty names before `as.character`, indexing, `file.info`, or a JSON writer can raise a bare R condition. The existing native `ffi.rs::charsxp_text` already checks UTF-8/Latin1 and refuses NA and bytes with named usage; keep that boundary. An explicit `NULL` JSON description differs from an absent argument; R's `$<- NULL` deletes a member, so construct with list-preserving indexed assignment. Local `jsonlite` 2.0.0 proof: `toJSON(list(options=list(a=NULL,b="x")), auto_unbox=TRUE, na="null")` emits `{"options":{"a":{},"b":"x"}}`, while adding `null="null"` emits `{"options":{"a":null,"b":"x"}}`. The current `.tt_json` emits the former. Use both `null="null"` and `na="null"`, preserve array intent explicitly, and compare a single-element list, nested object and null through `.tt_json` and the production parser. Retain production question-file parser validation rather than creating a second type grammar.

Current `tt_decide` yields logical `NA` for an unsure band or missing input; `tt_choose` yields character `NA`; `tt_tag` yields an empty character vector for no labels; annotate uses `list(failed = list(kind, cause))` for a failed member and widens a column. `tt_filter` and `tt_rank` call `as.character(records)` and return those converted texts, so they lose factors or class identity. `tt_find` similarly returns a converted unit. Prepare UTF-8 evidence separately from the original R input and index the original in public `$value`. `tt_annotate` must preserve the data frame and `on` column identity while reporting member observations. `tt_decide`, choose/score/tag and `tt_recognize` compact live `!is.na` cells before native work. Carry the original one-based positions through that compaction; convert native zero-based observation indexes back to zero-based **original R input** positions before publishing details. A column `c("first", NA, "third")` must have question indexes 0 and 2, never 0 and 1, with no event for the missing cell. R recognition uses one-based inclusive offsets, confirmed by shared non-BMP case 41. `lib.rs` packs six named kinds and retryability already, but `.tt_error_condition` becomes `simpleError` for malformed packing; newly added validation must call `.tt_usage`/`.tt_local` directly and not leak a base condition. A terminal Rust error can carry facts; current `carry` drops them.

## Prompt interrupt and smallest completion contract

`.tt_call` clears/restores R's error hook around two interrupt checks and the native crossing. A pending interrupt makes native `wait` return its packed marker; `.tt_interrupt` then signals the process so the caller's `tryCatch(interrupt = ...)` sees R's own interrupt. Its synthetic fallback has the same class. An error condition from the worker cannot serve as a reliable completion receipt for that real interrupt: it is replaced by R's signal condition, and the worker remains detached after prompt return. A global last-call slot would mix concurrent or nested R calls and would pin sensitive details after a caller left. A caller-owned external-pointer handle is justified only for someone asking for final stopped-call accounting; ordinary callers need no extra argument and still get their normal R interrupt.

The High reviewer accepted the handle as appropriate for real R interrupts but found its first draft under-specified. Freeze `tt_completion()` to create one opaque caller-owned handle and `tt_completion_read(handle)` to inspect it. The state transitions are `unused` → atomically `claimed` before **any** question validation or `.tt_call` precheck → `running` only on worker spawn → `terminal` exactly once after the original worker exhausts/joins Rust work. Every asking verb and `tt_details` accepts optional `completion = NULL`. A second claim of a claimed/running/terminal handle is named usage before work; an invalid handle is refused without mutating any other handle. `tt_completion_read` returns a state list for unused/claimed/running, then a fresh R conversion of the same immutable Rust-owned terminal kind/facts/details snapshot on every read. Thus caller mutation of one R read cannot change the next. Early R validation, question file refusal, or the first interrupt check settles a claimed handle with the actual kind and absent facts; worker spawn failure is defect with absent facts. An accounted zero-send error retains its real facts. The R main thread alone converts the snapshot. The worker holds its own `Arc`; the external-pointer finalizer drops only the caller's reference. Collection of a caller handle while the backend holds a sent request neither runs R on the worker nor cancels/joins it; the worker finishes, publishes into its remaining Arc and drops it. The handle supplies later facts only when the caller retained it; ordinary callers still receive R's prompt native interrupt with no extra setup. No global last-call slot or guessed account is allowed. A held-case proof must cover repeat reads, rejected reuse and collection during the hold. No caller-token semantics are added.
