# 0255 typed C facts design record

Status: candidate for fresh High design review. Source pin: main `e920ae28`; no runtime, header, test or public-page changes were made. Original criteria: `sdlc/issues/2026-09-26-every-surface-should-give-back-run-facts.md` asks that every library result carry facts without a setting or second call. ADR 0089 and ticket 0230 are accepted prerequisites. Experiment 273's Zig direct C call, experiment 294's Swift installed package and experiment 295's Objective-C wrapper establish existing typed consumers; they are retained consumer evidence, not proof that a new symbol is in any installed package.

## Source trace that drives the choice

`ffi.rs::typed` settles each typed result under the panic guard and writes only on success. `door.rs::decide` unwraps `Call<Details>` before extracting the decision and yes probability. `decide_many` collects its lazy rows and drops the batch before reading final facts. `recognize` and `relate` keep facts in their return tuple; their FFI closures drop that tuple member. `failures.rs::facts_json` already writes the accepted JSON names from a completed `Facts` and `thinkthen_error_facts_json` stores started failures per engine and calling thread. No success receipt exists. The current `thinkthen_answer` has two fixed fields, and all old C examples and consumers link by the existing symbol names. The JSON door's `value`/`facts` wrapper from 0230 remains usable but is not the same typed ABI.

The proposed new `*_with_facts` exports put facts into a separate owned JSON buffer during the same asking call. Their success boundary can share one private conversion and publication helper. The normal typed value paths should return value plus `Facts` internally; old exports retain value-only writing, while new exports publish the same value and serialized facts. A result array is not published until batch exhaustion and joined final facts. Result and facts strings are allocated before any output pointer is written; all failure paths leave sentinels alone and keep the accepted error slot. `thinkthen_free_string` frees every transferred string, and a completed result's facts cannot be changed by a later thread or call. The ADR compares the borrowed-success-accessor and JSON-door alternatives and marks the old eight names as a proposed compatibility exception rather than a resolved original criterion.

## Boundary and review risks

The header must state pointer validity, alignment, disjoint output ranges, lengths excluding NUL, null refusal and pairwise exact equality refusal among every output slot, including each length slot. Check `count * sizeof(char *)`, `count * sizeof(size_t)`, `count * sizeof(thinkthen_answer)` and every text byte length against `PTRDIFF_MAX` / Rust `isize::MAX` before raw slices, `add` or sends. The caller still owns proper allocation, alignment and nonoverlap; no implementation can safely discover arbitrary invalid C pointers or partly overlapping ranges. It must not write part of a caller's array before an ordered bulk failure or one JSON output before a later conversion failure. Capture final `Call` facts before conversion and final `Batch` facts before comparing the number of rows. Ordinary post-reply conversion/count errors become defects with those facts in the existing failure accessor. A private facts-aware guard can hold an `Option<Facts>` outside its existing `in_door`/`catch_unwind` closure and use it if conversion panics after completion, preserving the current hook and payload behavior. A panic before facts exist retains the inherited factless defect limit; the final output commit contains no fallible work. A missing usage member does not become token zero. The C soname may remain, but old archives do not contain the new symbols; Linux, Linux ARM64 and each macOS package need their own final archive/header/export qualification before advertising them. The source cap requires a coherent nested `ffi.rs` unsafe child, not eight copied schedulers or a policy exemption.

The smallest new proof is one installed-header C driver covering the eight new exports, exact listener arrivals, one packed and one batch-one many case, an absent-usage reply, null/alias/no-partial refusal, a started failure, a second thread, and owned-pointer disposal. Retain 0230's installed JSON-door facts and error accessor proof and the existing old typed parity. Count actual sends, not rows. The exact source/test/ratchet claims and deferred limits are in [ticket 0255](../tickets/0255-typed-c-call-facts.md). No paid run or package build was used to prepare this design.

## What preparation taught us

The facts already exist in public Rust calls; the loss is at the typed C return conversion. A stable ABI cannot make the old two-field result own new fields without a reviewed compatibility decision. The successful JSON door and typed C symbols must be checked as different carriers. An accessor avoids a second model request but creates a new mutable receipt and a second C getter. The review should reject any closure claim that confuses those facts.
