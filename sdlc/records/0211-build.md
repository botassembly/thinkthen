## What the build taught us

The policy-restricted package boundary matters even for a private helper: `ureq` stays in `engine/http.rs`, and CLI callers reach it through `engine::facade`. The original combined loader and first split both failed the policy check; the final module split passes it. The selected SQLite process shows environment reach without adding SQL syntax. Platform-specific trust behavior remains unmeasured because the feature uses rustls replacement roots, not an OS verifier. The outside-in trust matrix supplies the missing boundary proof while retaining 0155's message and redirect coverage.

The first High review found that `from_env` called the validating setter before a caller could override an invalid relative environment path. It also found that the bare-builder test did not demonstrate an environment conflict, a dry-run could not prove ordinary live-key ordering, and a model change did not prove fork reconstruction. The correction stores the environment path without early path validation; the selected path is checked at the explicit setter or at build. The corrected public child forces the conflict, the live CLI row counts zero TCP connections without a key, and the selected real-fork consumer sends after the source file changes. The real-fork proof needs a CA-signed leaf; a self-signed server certificate was rejected by rustls during the initial red fixture. The final fixture uses the same trust shape as the original local TLS proof. No runtime TLS or error behavior changed beyond override precedence.
