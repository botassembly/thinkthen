## W1: use the existing safe registration

Keep the four-action sequence and its shared atomics. In the Windows arm of `Action::ConditionalDefault`, call `signal_hook::flag::register_conditional_shutdown`. Pass 130 for SIGINT and 143 for SIGTERM. Every other action remains unchanged. Unix still calls `register_conditional_default`. The fallback for other non-Unix targets stays unchanged.

At rest, `default_armed` is true, so the first conditional action exits with the selected code. While a command runs, both conditional actions see false on the ordinary first signal, the cancellation flag fires, and the final action arms immediate shutdown. The command finishes its existing cleanup and returns the signal code. If finalization arms between actions, the second conditional action terminates instead of losing the signal. A later signal encounters the armed first action. Preserve the current registration failure, activation exclusion, token reset, Drop cleanup and restoration diagnostics.

No new callback dereferences a Rust state pointer. No callback borrows stack state, allocates, locks, formats, writes a file, panics or calls `std::process::exit`. The new action uses the already reviewed dependency's atomic check and async-signal-safe termination path. Registered closures retain their existing `Arc` ownership. There is no newly registered `SetConsoleCtrlHandler` pointer, carrier thread or DLL unload lifetime to manage. Library-only builds still install no signal handler. Calling the process-owning CLI entry retains its existing process signal ownership; this slice creates no new promise that such an entry can be unloaded from a host DLL.

`signal-hook-registry` documents a Windows CRT registration and re-registration race. Very closely overlapping signals can reach the CRT default before the dependency restores its handler. The refinement neither introduces nor closes that dependency limitation. Native second-signal proof must order the first delivery through an acknowledgment. Do not claim that arbitrary overlapping signals always return 130. If the native ordered proof fails, return to a separately reviewed console-handler design rather than layering an unreviewed callback into this patch.

## W2: keep configuration and usage policies distinct

Add a private Windows module outside `core`. Its safe interface owns files and returns typed results; callers never receive an unowned native pointer. Two small FFI leaves may separate security descriptors from file creation and identity if one file would exceed the 500-line cap. Limit production unsafe code to the exact reviewed paths `src/windows/security/ffi.rs` and `src/windows/files/ffi.rs`. Other Windows code remains safe Rust.

For both policies, obtain the current process token user with `OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY)` and `GetTokenInformation(TokenUser)`. A usage object's owner must match that user SID. A readable configuration file with a foreign owner is shared; its top-level settings remain readable with the command warning, and its named `backends` are refused. Foreign configuration ownership alone is not an unreadable-file failure. LocalSystem `S-1-5-18` is an admitted service identity for access grants. Administrator groups and every other identity are ordinary foreign principals for these leaf policies. Elevation does not make an Administrators-owned object user-owned. Do not discover usernames, log SIDs or infer group membership. Usage ownership and admitted access grants deliberately match B's private-child trust rule. Configuration retains its separate warning and named-backend contract. The design makes no claim of administrator resistance.

Read security information from the handle being used, through `GetSecurityInfo` with owner and DACL flags. A descriptor owns its returned allocation until its RAII owner calls `LocalFree`. Borrowed owner, DACL, ACE and SID views cannot outlive that owner. Check every API return, absent pointer, descriptor validity, ACL validity, ACE count, ACE size and SID bounds before reading. Use checked integer conversions and aligned buffers for token and native output structures. Reject malformed or unsupported access structures conservatively. Never call `SetSecurityInfo` to fix existing state.

Every successful native file handle transfers exactly once into `File` or `OwnedHandle` through the reviewed FFI leaf. Invalid and null handles never transfer. After transfer, Rust drop owns closing; no separate `CloseHandle` can close the same value. A handle borrowed through `AsRawHandle` stays inside the file owner's lifetime. Token handles use `OwnedHandle`; the `GetCurrentProcess` pseudo-handle is borrowed and never closed. Security allocations use `LocalFree`, not `CloseHandle` or the Rust allocator. Early returns release only owned resources, and no native view escapes through a public API.

An absent or null DACL grants unrestricted access. It is unsafe; an empty DACL is distinct and grants nothing. An empty list normally prevents opening the object, which is an unreadable-state failure. Deny ACEs cannot make a foreign allow grant trusted. This conservative rule avoids pretending to compute effective access for every possible group and conditional ACE. Audit-only ACEs confer no access. An unsupported allow or conditional ACE cannot silently pass.

### Usage objects

The existing usage root, stable `.lock`, `.update.tmp` and every recognized `YYYY-MM.json` must be owned by the token user when their operation opens them. Their access lists may grant access only to that user and LocalSystem. Read-only access for another identity still violates usage privacy. Apply the rule to explicit and inherited allow ACEs, including grants intended for children. The generated files contain only the existing five aggregate counts. Preserve the current admission boundary: the pre-send reader checks the root, an existing lock and recognized months; the writer checks `.update.tmp` before truncation. An unsafe temporary file discovered after a good start remains a best-effort write failure and does not change the judgment's exit code.

Inspect the leaf through a native handle opened with `FILE_FLAG_OPEN_REPARSE_POINT`; directories also use `FILE_FLAG_BACKUP_SEMANTICS`. Refuse every reparse attribute and the wrong file or directory type before reading bytes or truncating a temporary file. Do not assume `Metadata::is_symlink` recognizes every Windows reparse kind. Obtain identity through `GetFileInformationByHandleEx(FileIdInfo)` and compare volume serial and the full 128-bit ID with a fresh no-follow handle to the current name at the existing identity checkpoints. Refuse an unavailable identity API. Keep the checked directory handle alive throughout the operation and omit delete sharing on retained usage handles. Readers and writers still share the stable lock using the existing standard-library locking code.

Create each missing usage directory and file with its owner and protected DACL supplied in `SECURITY_ATTRIBUTES` to `CreateDirectoryW` or `CreateFileW`. The DACL grants full access to the user and LocalSystem. Directory inheritance supplies only those identities; each created file also receives its explicit protected descriptor. This closes the exposure interval that a create-then-repair sequence would introduce. Convert the token SID through the native SID-string API for the generated SDDL, and keep that descriptor allocation alive for the complete creation call. Existing objects ignore the creation descriptor and must pass inspection without mutation. Capture last-error immediately where the creation API distinguishes a new object from an existing one.

The creation helper recurses only over missing components of the already resolved platform path. It never changes an existing platform folder's owner or permissions. Existing `thinkthen` parent folders can continue serving cache and usage. A collision at a leaf is opened without truncation and checked. `.lock` still uses exclusive creation with an existing-object fallback. `.update.tmp` is verified before its existing `set_len(0)`. Rename, synchronization, count parsing, missing-month behavior and the Windows directory-sync omission remain as they are. The native fixture must hold the directory without delete sharing while the real writer closes its temporary file and replaces a child month file. It must prove that successful child replacement retains that directory handle and the exact next counts. A separate attempted replacement of the retained directory or an open child may fail through Windows sharing rules. The fixture must inspect the actual result and bytes; it cannot assume the replacement occurred or report an identity-mismatch proof from a refused rename. These are prepared proof requirements, not Windows execution results.

These checks cover the named leaf objects and their identity checkpoints. This slice does not add a whole-drive ancestor ACL policy, prohibit every ancestor junction, or promise safety against another process running as the same user. A leaf junction, symlink or other reparse object refuses. General hardening of hostile or replaced ancestors is a deferred gap, as it is outside the admitted leaf contract. Do not describe these checks as an atomic filesystem transaction or power-loss durability.

Existing wrong-type and changed-identity error categories remain. Windows ACL and reparse privacy failures use `PermissionDenied` so the existing read failure prints unsafe-state advice rather than telling the user that valid totals have invalid contents. Native API failures remain private `io::Error` causes. They never print a raw Win32 error, SID, config value or credential.

### Configuration

Keep the Unix `Config::read` path and `writable_by_another(&Metadata)` behavior intact. Add a Windows-only read path that opens the configuration once without following a leaf reparse point, checks that handle, reads from the same file, verifies its named identity, and then parses the existing closed JSON. A missing file still means no configuration. An unreadable security descriptor, malformed descriptor, reparse leaf or identity change returns the existing unreadable configuration failure. A failed check can never be treated as trusted.

A readable file is shared when another identity owns it, its DACL is absent or null, or a foreign allow ACE can modify its data, append data, change its attributes, delete it, change its DACL or take ownership. Include the generic write and all-access masks. The token user and LocalSystem are trusted writers. Read-only foreign grants do not make configuration shared. Ignore an inherit-only ACE for the file itself. Unsupported allow semantics mark it shared conservatively. The file remains read-only from ThinkThen's perspective.

Shared top-level settings retain the warning behavior. Named `backends` remain refused before credentials can be routed through their variable names. Libraries retain the same values without writing a warning. Add a Windows sentence that describes ownership and access permissions. Keep the Unix warning and `SHARED_BACKENDS` constant text byte-for-byte unchanged under the Unix arm.

Do not change the shared `writable_by_another(&Metadata)` function to a path-based Windows implementation. Its current callers include `cli/asking/folders.rs` and `public/settings/server.rs`. Extending it here would silently change named cache warnings, SQL refusals, cache creation and their mode-based advice. Those policies remain unchanged in C. Documentation must still say that the named answer-folder check is Unix-only. Windows answer-cache privacy beyond current behavior remains outside this slice.

## Outside-in native proof

The Windows event proof needs an isolated console, not a mocked callback or `raise(SIGINT)` alone. Spawn the real command or a subprocess-only test child with `CREATE_NEW_CONSOLE`. Do not use `CREATE_NEW_PROCESS_GROUP`, which disables Ctrl-C for the child. Run a separate bounded injector subprocess. It detaches its inherited console if present, attaches to the child's console, ignores Ctrl-C in the injector only, calls `GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)`, and detaches before exiting. This avoids sending Ctrl-C to the test runner. It also avoids the unsupported assumption that a nonzero group ID targets a Ctrl-C event. Native API failure fails the fixture; a timeout kills and reaps only owned children.

Use the existing ignored-child pattern from `cli/interrupt/tests.rs` for initial idle, active, finished and second-signal states. Emit readiness after actual registration or activation, flush it, then wait. Idle-before-activation and idle-after-finish each exit exactly 130 after a real console event. A first active event keeps the child alive, sets the real cancellation flag, and emits an acknowledgment from an ordinary child thread. Releasing the child returns 130. A second acknowledged event exits 130 promptly while work remains held. An ignored subprocess helper may produce markers but must not expose new CLI flags or release-visible test variables.

For the actual command, serve canned replies from a counted loopback listener. Hold one admitted request, inject Ctrl-C, wait for the existing debug-only cancellation acknowledgment, and release the reply. Prove completed output and exact stopped/facts order, no later request, code 130, and usage flush. Extend the existing `THINKTHEN_TEST_SIGINT_ACK` routing on Windows only when a debug build supplies the path, using an ordinary bounded acknowledgment carrier; it does no work in a release build and changes no signal callback. Retain exclusive one-byte creation and the failure plants. Exercise retry cancellation with one counted request. The release binary must also pass an actual console-event interruption case with its normal attempt timeout and no hidden-variable dependence.

SIGTERM has no required console-event mapping. Use a synchronized child that calls the safe `signal_hook::low_level::raise(SIGTERM)` to prove 143 at rest, after cooperative finish, and as the acknowledged second signal after SIGINT. Preserve Unix subprocess signal assertions and their OS signal termination status. Do not reinterpret Ctrl-Break, console close, logoff or shutdown as SIGTERM.

Native ACL fixtures create only disposable local objects. They must execute actual public CLI/API behavior and inspect independent native owner, DACL and file bytes before and after. Use PowerShell/.NET only to plant descriptors; product Rust performs the check. Feed only fake keys and canned loopback answers. No fixture changes a profile, real configuration, global permissions, registry or execution policy.
