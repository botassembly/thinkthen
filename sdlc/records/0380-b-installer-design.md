## Retained behavior and scope

Add `install.ps1` beside `install.sh`. Support Windows x86-64 with Windows PowerShell 5.1 and PowerShell 7. Use the installed .NET libraries, with a small runtime-specific helper for creating directories with their private access rules already applied. No winget, Scoop, module installation, administrator elevation, new product dependency or Rust change is needed. Refuse other hosts before downloads or filesystem mutation. Preserve `install.sh`, its site copy, every Unix fixture and all release target family counts.

The script accepts `-Version X.Y.Z` or `-Version vX.Y.Z`; omission selects latest. Versions contain exactly three decimal components, with no whitespace, signs, separators, suffixes or path characters. Reject versions below 0.2.0 with a sentence explaining that Windows archives start with 0.2. Defaults use the existing GitHub repository and public API. Keep `THINKTHEN_INSTALL_BASE`, `THINKTHEN_INSTALL_API` and `THINKTHEN_INSTALL_DIR` for mirror and loopback fixture compatibility. Validate URL bases before requests: HTTPS without user information, query or fragment; HTTP is allowed only on a numeric loopback address for offline fixtures. Never attach authentication, inspect a credential file or print response bodies.

Latest selection uses the API's ordered releases and selects the first non-draft, non-prerelease release with a valid version at least 0.2.0 and both exact Windows asset names. Do not silently fall back to a 0.1 archive or a prerelease. If none exists, report that no Windows release is available. An API failure reports failure with explicit-version advice; it does not guess from the latest Unix release. This differs intentionally from the Unix redirect fallback because Windows availability starts later.

Downloads use bounded streaming and finite request timeouts. Set limits of 1 MiB for release metadata, 4 KiB for the checksum, 128 MiB for the ZIP and 128 MiB for its sole expanded member. Reject oversized Content-Length and stop streaming at the limit even when no length is supplied. Bound every redirect and apply the same transport checks to its destination. Release asset redirects to HTTPS storage are allowed; loopback fixtures cannot redirect to a remote HTTP endpoint. Retry only transient transport failures with a small fixed attempt count. Never execute a response as PowerShell.

## Archive and executable boundary

Verify the ZIP's SHA-256 before opening it. A sidecar has exactly one nonblank record containing either 64 hexadecimal digits alone or those digits followed by the exact archive name, optionally prefixed with `*`. Reject wrong names, nonhex digits, extra records and mismatches.

Open the ZIP read-only with `System.IO.Compression.ZipArchive`. Its central inventory must contain exactly one entry whose full name equals the case-sensitive string `thinkthen.exe`. This rule rejects subfolders, directory entries, slashes, backslashes, rooted paths, drive names, alternate streams, traversal, different case, duplicates and all extras. Accept only a regular-file Unix type or an unspecified Unix type with no DOS directory or reparse bits. Reject links and other special types. An encrypted or unsupported member must fail closed. Check declared compressed and expanded lengths against the limits; stream through a counted buffer and require exactly the declared expanded length. Never use `Expand-Archive`, `ExtractToDirectory` or an entry-provided output path.

Read the bounded entry into memory before materializing an executable. Require the existing slice A header conditions: `MZ`, an in-bounds unsigned PE offset, `PE\0\0`, machine `0x8664`, optional magic `0x20b`, executable flag set and DLL flag clear. Check optional-header length and all reads against the actual bytes. These checks identify the target; they do not establish publisher identity or prove that arbitrary executable code is safe. After all checks, write only those bytes to a create-new stage path chosen by the installer. Rehash the stage before execution.

Run only the stage's absolute path with `--version`, without a shell. Give it a finite timeout and bounded captured output. Require exit 0, empty standard error and precisely one `thinkthen VERSION` line, allowing the normal LF or CRLF terminator. Remove inherited `THINKTHEN_*` settings and `*_API_KEY` variables from the child's environment. Do not run a question, contact a backend or change configuration. A wrong version, launch failure, timeout or excessive output preserves the existing executable and receipt.

## Private paths and ownership

Default to `%LOCALAPPDATA%\Programs\thinkthen`. A custom directory must be an absolute local path on NTFS. Refuse UNC paths, device paths, alternate streams, relative paths and unsupported filesystems. Inspect every existing ancestor and the target without following reparse points; reject junctions, symbolic links and other reparse points. Check again at each mutation boundary. Reject directories where an ordinary other user can replace an ancestor and redirect the target. These checks protect against other unprivileged users; the installer does not claim protection from administrators, SYSTEM or a malicious process running as the installing user.

Create missing installer directories with a protected access list and owner equal to the current user SID. Allow inherited file and directory access only to that SID and SYSTEM. Apply access rules at creation, before writing any downloaded or executable content. Verify existing install targets satisfy the same private contract; reject insecure targets with advice to choose a new directory. Do not change an existing folder's access rules. The runtime configuration, cache and usage folders retain their existing paths and receive no installer changes.

Create a unique private scratch subdirectory named `.thinkthen-install.GUID` under the install target, so stage files and replacements stay on the same volume. Never reuse an existing scratch path. Keep the exact created path in an ownership set. Every delete checks exact ownership, containment and reparse attributes first. Cleanup enumerates without following reparse points and rejects an injected link. The target, its ancestors, any lane and any caller-supplied path are never recursive cleanup targets. Cleanup warnings preserve the primary failure and nonzero exit. Successful installation may warn about leftover owned scratch; it must never falsely report that installation failed after the installed receipt committed.

Serialize installers using a persistent `.thinkthen-install.lock` file opened without sharing inside the private target. Validate its attributes and access rules before opening it. Leave the harmless lock file in place; closing the handle releases the lock even after a crash. This avoids a delete-and-recreate lock race. Refuse a concurrent invocation before receipt or executable replacement.

## Receipt and replacement contract

Use `thinkthen.install.json` beside `thinkthen.exe`, with the Unix schema's `schema_version`, `state`, `executable_path`, `version`, `old_sha256` and `new_sha256` fields. Generate JSON with a serializer so Windows backslashes, spaces and Unicode remain valid. Bound existing receipts at 16 KiB. Reject malformed receipts, unknown schemas or states, invalid versions or digests, a path naming another executable, and nonregular or reparse executable, receipt and lock paths. Before reading or hashing an existing executable or receipt, require its owner to equal the current user SID and its explicit and inherited access rules to allow access only to that SID and SYSTEM. Apply this file contract to stage files, receipt candidates, snapshots and replacement backups too. A private parent does not establish a child's privacy. Reject an insecure file without changing its access rules; advise inspection or a new install directory. Recheck owner and access rules before every replacement. Require a valid installed receipt's new digest to match the current executable. Permit an earlier private regular executable without a receipt, as the Unix installer does, and hash it without running it, unless prior installer scratch names indicate an interrupted receipt replacement.

Prepare and flush both pending and installed receipt candidates before changing either destination. Keep byte-for-byte snapshots of the old executable and receipt in uniquely named private scratch files when they exist. Flush and verify each snapshot against the original digest before the first commit attempt; record original absence separately. Recheck destination identity, hashes and private path checks immediately before commit. Commit pending receipt first, replace the executable second, commit installed receipt last. Replace existing files with `System.IO.File.Replace` on the same NTFS volume. Always provide a unique, initially absent backup path inside the current scratch directory, separate from the verified original snapshots, and do not ignore metadata errors. Use a nonoverwriting rename for an absent destination. Never delete a destination as preparation for replacement. A running executable or sharing violation fails; restore the old command if the operation changed it.

Preparation failures before the first commit attempt leave an existing command and receipt byte-for-byte unchanged. A replacement exception does not establish that its destination stayed unchanged. Windows replacement error 1176 retains the original names when a backup was supplied; without a backup it can remove the old destination. Error 1177 can leave the destination renamed to its backup even when a backup was supplied. After every replacement exception, including receipt replacement and rollback, inspect the actual destination, stage and backup attributes, access rules and digests before deciding what succeeded. Preserve the first exception as the primary error. A caught commit failure attempts to restore the original command first, including original absence, from the verified snapshot. Restore the original receipt only after command restoration succeeds and its digest is verified. If restoration cannot complete, retain or restore the pending receipt when possible, retain the verified original snapshots and other recovery artifacts, print their paths and fail. If the receipt is absent and cannot be restored, report that absence explicitly. Never restore an installed receipt whose digest differs from the command remaining on disk. Cleanup must retain these recovery artifacts. Do not claim a two-file atomic transaction or durability across power loss.

A process interruption before caught-error rollback can leave a pending receipt with an old command, a new command or an absent command, including during upgrade. Receipt replacement can also leave the receipt absent. On the next run, under the lock, validate any pending receipt's path and digests. Continue only if the command matches old or new, or both the command and old digest are absent. An absent command with a nonempty old digest requires refusal and manual recovery from inspected snapshots. An absent receipt with any prior `.thinkthen-install.GUID` name also requires refusal and manual inspection; do not infer an intact earlier manual installation or overwrite it. Check names without opening or following prior scratch entries. Refuse every other mismatched state without overwriting anything. A valid pending state can complete a new verified installation. Never follow receipt-provided scratch paths, automatically restore prior snapshots or delete artifacts created by a prior invocation. Recovery leftovers may require manual removal after inspection. Crash recovery and caught-error rollback are separate proof cases.

After installed receipt commit, return success and print the absolute executable path and installed version. If the target is absent from PATH, print a safely quoted PowerShell command that changes only the current session and plain instructions to add the directory through Windows environment settings. Make no automatic PATH, profile, registry, execution-policy or runtime configuration edits. Explain removal of the executable, receipt and harmless lock file without supplying recursive deletion of the parent directory.

## Proof plan

| Risk | Required evidence |
| --- | --- |
| Wrong release selection | Exact requested URL for explicit versions; latest skips missing ZIP or sidecar, draft, prerelease and 0.1; no available Windows release fails clearly; malformed input sends zero requests |
| Wrong or excessive download | Missing, duplicate, malformed and wrong-name checksum records; mismatch; partial and oversize streaming responses; redirect transport refusal; preserved old command and receipt |
| Archive escape or bomb | Exact inventory rejects duplicate, directory, extra, traversal, rooted, drive, backslash and alternate-stream names; Unix link and special type, DOS reparse bit, malformed or encrypted ZIP; declared and actual byte limits |
| Wrong executable | Truncated DOS/PE/optional headers, overflowing or outside offsets, ARM64, x86, DLL, wrong optional magic; no stage execution before all checks; wrong version, nonzero exit, timeout and excessive output |
| Unsafe target | Linked ancestor, junction, linked executable/receipt/lock, insecure target access rules, writable foreign ancestor, UNC and device paths, non-NTFS; under a private parent, executable and receipt foreign-write access rules or foreign ownership refuse before reading, hashing or replacing; Unicode and spaces succeed; rejected cases preserve destination bytes and access rules |
| Replacement damage | First install and upgrade; original receipt absence; locked executable; faults at each receipt and executable commit; plant 1176/1177 partial states with absent or renamed destinations and absent receipts, rather than only exceptions before operations; inspect each replacement and rollback exception; exact snapshot and restored byte preservation, backup isolation and primary error; rollback failure retains verified recovery artifacts |
| Interrupted replacement | Pending old/new/absent-first-install states recover; interruption after partial replacement and before rollback leaves absent-upgrade command or absent receipt and prior scratch, which refuse unchanged with manual recovery advice; pending foreign path, unknown schema/state, wrong digest and malformed JSON refuse unchanged; two concurrent installers cannot interleave |
| Cleanup escape | Before first real cleanup, pass the actual lane path and an unowned sibling; both refuse without deletion; injected reparse child refuses; cleanup fault keeps primary failure; successful cleanup leaves only executable, receipt and lock |
| PATH or backend side effects | PATH, profile, registry, execution-policy and runtime configuration sentinels remain unchanged; staged version probe and installed replay send zero backend requests; print useful session and persistent manual PATH advice |
| Unix regression | Existing `installer-test` remains green with unchanged `install.sh` and site copy; Windows packer self-test, workflow self-tests and strict docs proof remain green when relevant files change |

The fixture must execute the real PowerShell script, not a Python reimplementation of its policy. Linux may generate ZIP and HTTP cases and verify fixture construction without running a PE executable. Such checks count as fixture proof only. Windows-only filesystem, ACL, sharing, PowerShell host and real executable proofs must run on `windows-2025` under both supported PowerShell hosts. Skip output must explicitly say that Windows installer execution was not proved. Wire the full boundary suite and real packed-command installer smoke into the Windows job only after coordinator clearance; offline workflow checks verify that wiring.

## Primary API references

Microsoft documents [private directory creation](https://learn.microsoft.com/en-us/dotnet/api/system.io.directoryinfo.create?view=netframework-4.8.1), including the .NET Core extension equivalent. Its [ZIP entry API](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.ziparchiveentry) exposes inventory attributes and lengths. Its [PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) defines the target header fields. Its [file replacement guide](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files) describes replacement and backup behavior. The [ReplaceFile API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) documents partial failure states 1176 and 1177 and preservation of destination access rules. These APIs support the proposed boundaries; fixtures must prove actual PowerShell host behavior and replacement failure states.
