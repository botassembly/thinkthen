# Quick Fix: detailed answer field guide

Source pin: `ticket/qf-result-answer-guide` from main `2c5ac772`, 2026-09-29. This fixes [new-user stumble row 16](../issues/2026-09-20-new-user-stumble-register.md): a script copied `answer.probability` from `decide --details` and broke on `choose --details`. The normative [result reference](../../specification/result.md#--details) had the right shapes, but separated their examples. The issue's old request for three side-by-side shapes is updated here to all five current kinds. Root owns the issue-row update at landing; this branch does not edit the issue.

At the start of `--details`, one table now maps command, `answer.kind`, actual `answer` fields and `value`. Its literal field evidence is the existing five [normative examples](../../specification/result.md#five-answer-kinds), the tagged `yes_no`/`choice`/`tag`/`score` serializer in `crates/thinkthen/src/core/answer.rs`, the `find` serializer in `crates/thinkthen/src/core/find.rs`, and the existing [typed details corpus](../../specification/fixtures/types/corpus.json). `yes_no` alone has singular `probability`; `choice`, `tag`, `score` and `find` have `probabilities`; optional `confidence` is confined to the eligible kinds and backend reports. `value` remains the judgment to use, while a `pick` can lead without clearing a cut or tie. Plain `rank` keeps its `value: null` and sorts by the yes probability. The table explicitly excludes the outer shapes of aggregate `annotate`, `recognize` and `relate`, whose existing reference prose remains authoritative.

No runtime type, result schema, serializer, option, help, site, SQL or DataFrame behavior changed. No new test was added for a text-only comparison of existing examples. Focused `pages`, `tickets` and `git diff --check` validate the edit; no provider, SDK, compile or full rung ran. Other new-user stumbles and the launch intake remain open under their current owners.

## What the build taught us

The old row named three shapes, but the current contract has five. A first-screen comparison can make the field distinction visible without copying the long examples or changing output. `find`'s optional `confidence` comes from its own serializer, while `tag` has no such field; the table follows those actual paths. Aggregate results need an explicit scope sentence so the discriminator guidance is not overgeneralized.
