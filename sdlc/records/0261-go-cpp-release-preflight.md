## Current file paths and gap

`sdlc/scripts/release-pack` reads the root version and `rustc` host target, makes a fresh stage, and emits adjacent SHA-256 files through `pack`. Its `part_c` builds `libraries/c` in release mode unless `--reuse`, then stages the public header, static archive, shared library/soname and relocatable pkg-config file. On Linux the wrapper-visible archive is `thinkthen-c-$V-$TARGET.tar.gz`. The default list and dispatch have no `go` or `cpp` part. `--reuse` copies `libraries/c/target/debug` outputs; it has no build-source receipt. A header hash or mtime cannot show that those bytes include the current engine dependency tree. For the first pilot, require a fresh non-reuse C build in the same invocation and leave reused Go/C++ output unsupported.

`sdlc/scripts/release-smoke` verifies each file's adjacent checksum, scans unpacked bytes for the builder's home and panic marker, routes recognized files through `THINKTHEN_ARTIFACT`, treats exit 77 as failure, and requires its nine established surface/file families. Its general command archive pattern currently follows C/SQL cases; new Go/C++ patterns must precede it. `sdlc/scripts/installed.sh::installed_unpack` makes a fresh scratch folder, but the Go/C++ checks do not yet call it. Those checks currently build the C debug library, take the C header from the checkout and use `target/go` or `target/cpp`. Existing `release-smoke` cannot tell whether a new wrapper archive and a C archive came from the same build.

The product Go module name is `github.com/botassembly/thinkthen/libraries/go`. `libraries/go/check.sh` builds debug C and creates a local native pkg-config root. `fixtures/run_matrix.py` copies the checkout package into four local consumers, runs its 39-body source matrix and one external module call per consumer, and points shared/static-C modes at that root. The C++ `CMakeLists.txt` copies the caller-supplied C header and libraries into its install, and exports shared/static interface targets. `libraries/cpp/check.sh` builds debug C, installs the checkout CMake package and runs its shared, static, multilib and Clang consumer variants. `fixtures/run.py` counts complete backend bodies for each executable. `fixtures/abi.py` and `fixtures/exports.py` derive their symbol lists from the header rather than a historical fixed count. The accepted 0249 build and fresh review already cover these checkout-source routes. An installed branch must select unpacked source/native paths explicitly; setting `THINKTHEN_ARTIFACT` while still rebuilding or copying the checkout would be false installed proof.

## Concrete package boundary

Go's shipping source is `LICENSE`, `README.md`, `go.mod`, `thinkthen.go`, `thinkthen_test.go`, `recovery_test.go` and `examples/decide/main.go`. C++ ships `LICENSE`, `README.md`, `CMakeLists.txt`, `cmake/ThinkThenCppConfig.cmake.in`, and `include/thinkthen/{door,json}.hpp`. Their `check.sh`, fixtures, ratchets and target outputs are test-side files. Keep the existing C archive separate, because both bindings consume it and C's installed check already proves its own pkg-config slide. A strict generated manifest inside each wrapper says `source_commit`, `target`, `version`, `c_archive`, `c_sha256`. The packer calculates its C digest after building the file. A private `sdlc/scripts/release-go-cpp-pair DIR` preflight verifies outer checksums and strict manifest equality to the actual C bytes. The actual smoke calls it before either wrapper consumer. The helper derives the selected version and target, treats each manifest as fixed data, and requires exactly one expected C, Go and C++ archive and one matching checksum per archive. It rejects duplicate or extra family entries, including another target/version, before unpacking consumers. Then the installed checks derive exports from the unpacked header and compare copied members. This catches accidental cross-pin combinations without inventing an ABI query. A deliberately rewritten manifest and archive checksum could forge consistency; the reviewed build commit and artifact hashes, not a signature, establish provenance.

The clean-tree prerequisite means the packer can name one committed source tree. `git archive HEAD` in the existing Linux release container also uses a committed tree, but that container does not install Go or the C++ consumer tools and its current `release-pack` call names only old parts. Ticket 0261 does not change it. Existing C release packaging supports all four targets, but these two product source gates currently refuse a host other than Linux x86-64. The pilot therefore qualifies only local Linux x86-64 packaging and consumer calls; no other-host or actual runner inference follows.

## Smallest distinguishing proof and limits

Use a committed candidate with clean status and `release-pack x86_64-unknown-linux-gnu OUT c go cpp`. Save the exact command, source SHA, tool versions, C member and all outer archive hashes. The precise passing baseline is `sh sdlc/scripts/release-go-cpp-pair OUT` on only those three expected archives and their checksum files, followed by the installed Go external module and C++ shared `find_package` consumer in unrelated temporary roots. Pin output, process exits and one full loopback request body each. Include one static-C link witness in each route without repeating all 39/16 source matrices. Make three copies of that passing OUT: remove C++ and its checksum; corrupt a Go archive byte while leaving its checksum; substitute a different valid C archive and checksum. Invoke the same preflight for each and pin its missing-file, outer-checksum or wrapper-to-C-digest diagnostic and nonzero exit before either consumer starts or sends. A fourth copy adds another family archive/checksum and must fail exact inventory. `release-smoke` itself still needs all nine older families; the three-file directory is deliberately not its passing baseline. Its source calls the same preflight before any wrapper dispatch, so the focused proof exercises the exact file validation used by full-bundle smoke. The existing source gates retain broader parser, cancellation, J1 and exact-matrix checks. Run them again only if their tested inputs change.

The C archive binds header, shared and static bytes as one file but does not prove runtime ABI identity. The installed checks still derive exports and compare unpacked installed bytes before use. The source SHA in a manifest is a build assertion, not an attestation. The original Go and C++ issues still require final release commit rebuild, actual Ubuntu 24.04 Actions proof, checksummed distribution and direct installation, while their other-platform limits remain open. No registry or workflow choice is decided here.

Design checks: `release-pack` has 160 nonblank lines and `release-smoke` 81 under `awk 'NF && $1 !~ /^#/ {n++}'`; the private helpers already handle staging, checksums and scratch. No enforced script ceiling was found in `sdlc/scripts/lint` or the root Rust ratchet. A future builder should measure touched fixture ratchets before raising one and describe any test consolidation. The local tool receipts are Go 1.22.2, CMake 3.28.3, GCC 13.3, Clang 18.1.3, Python 3.12 and Rust 1.95.0 in [0249 preflight](0249-go-cpp-preflight.md); the installed pilot must record its actual versions. Go/C++ experiments have no universal `inputs/toolchain.json` to reuse.

Design correction after first review: the direct installed selectors alone would have skipped the smoke pair/digest path, and a three-file `release-smoke` run would fail for unrelated old-family absence. The shared callable preflight gives one passing three-file baseline and one validation path for actual smoke. Exact family cardinality prevents an additional archive from being silently ignored. These two changes add no second test framework or new runtime ABI claim.
