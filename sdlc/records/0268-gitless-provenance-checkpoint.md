## What the build taught us

The missing `.git` failure starts before legacy part selection because `release-pack` read HEAD unconditionally. Moving that read under the wrapper branch repairs the generic route without touching any SQL package operation. A copied wrapper alone would leave the C/Rust source unverified; checking every archived source member before `part_c` closes that gap. The same Git tar gives a checked commit identifier and exact wrapper member bytes, so the later Go/C++ mode need not infer source from a caller's SHA text. Synthetic Cargo/Docker outputs are enough to exercise this identity and refusal logic; they cannot qualify C, manylinux or the runner.
