## Focused proof if a deletion earns its place

Run the exact proposed replacement tests before and after a small source deletion, under the fixed shared lock and with the real API key unset. The initial comparison commands are `cargo test --locked -p thinkthen --lib engine::deadline_tests::cancellation_is_observed_before_a_spent_deadline -- --exact` and `cargo test --locked -p thinkthen --lib engine::deadline_tests::schedule::a_spent_deadline_over_empty_bulk_input_stops_before_reading -- --exact`. If the former ever earns deletion, only the latter remains a post-deletion selection; verify that it runs one test, not zero. Use the particular retained test's exact filter for a different candidate. A selected CLI/API boundary, if it supplies the stronger proof, needs its own exact test command and listener request assertions. Check `cargo fmt --all -- --check`, the relevant policy/file-size check, `node sdlc/scripts/ratchet.mjs`, and `git diff --check`. Do not run `sdlc/scripts/test`, `spec`, `surfaces`, a mutation census, or timing repetitions for this preparation. If a targeted deliberate break is needed, bound it to the claimed test's product seam, name the expected failing assertion, restore it immediately, and report the actual result; no such plant has run here.

An implementation record must name each deleted test, the assertion-by-assertion stronger replacement, the specific credible regression, measured test-line and function changes, and the ratchet delta. An unproven equivalence is a reason to retain a test, not a reason to infer coverage from a score. The fresh reviewer should inspect the exact diff and replacement proof before the coordinator lands it.
