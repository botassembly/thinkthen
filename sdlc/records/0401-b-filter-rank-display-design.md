## Arguments and refusals

Add one flattened display argument type to FilterArguments and RankArguments: `-n`/`--line-number` as a boolean, `--scores` as a boolean and `--around N` as optional text. Do not add these to Common or expose them on the other verbs. Parse around into usize only when every byte is an ASCII digit. Zero is valid; empty text, a sign, decimals, Unicode digits and overflow are usage errors. A negative value must reach this refusal rather than become a filename.

Retain the existing quiet/raw refusal order and filter top/rank threshold rules. Resolve the saved question and framing before validating display against framing. Any of the three text flags with --details refuses at exit 2 with `text display flags cannot accompany --details`. Any with CSV/TSV refuses at exit 2 with `text display flags need lines or JSONL, not CSV or TSV`. Invalid around refuses at exit 2 with `--around takes an ASCII whole number of at least 0`. These are accepted exact diagnostic bodies; the existing diagnostic layer adds its normal prefix and newline. All refusals occur before any request. --around 0 counts as present for conflicts and snapshot preparation.

JSONL and resolved --field/saved on remain supported by display. Prefix the complete original JSONL row, rather than the selected evidence fragment. --window keeps A's existing framing and pointer refusals. --plan performs the same display validation and snapshot bound check, then retains its ordinary plan output. It does not print display groups. Neighbor display does not affect provider --context.

## Exact output bytes

With no new flag, keep the current printed string and edge::write_line path exactly. Existing --details remains unchanged, including ordinary rank value:null, saved score value, positions and cached answer metadata.

Without --around, emit one ordinary selected record with an optional prefix. --scores contributes the ordering number followed by one ASCII space. -n contributes `FIRST:` for stdin or one named source; several named sources contribute `FILE:FIRST:`. Put the score before that location. There is no space after the colon. For example, the row `alpha` at line 7 with score 0.8 prints `alpha\n`, `7:alpha\n`, `0.8 alpha\n`, `0.8 7:alpha\n` or `0.8 a.txt:7:alpha\n`, according to the flags. A window gets this prefix on its first physical line; its remaining record bytes retain their current internal line feeds and carriage returns. JSONL spacing and trailing spaces survive. A filename appears only when -n is present and more than one source argument was named, including repeated arguments naming the same path. Paths use A's lossy display conversion and are not escaped in the text view.

With --around, every selected record starts an independent group. Its first line is `--\n`, or `-- SCORE\n` with --scores. Scores do not repeat on the physical lines. Print the physical lines in the inclusive interval from first minus N, clamped to one, through last plus N, clamped to that source's final physical line. Use checked or saturating arithmetic. With -n, prefix each selected physical line with `LINE:` and each neighbor with `LINE-`. Several named sources add `FILE:` before either location. Without -n, physical lines have no prefix. Every physical line inside a selected window is selected; blank lines inside it use the selected separator. Blank neighbor lines remain visible. Remove each physical line's terminating LF and its preceding CR, then emit LF. Preserve all other bytes. No extra empty line follows a group's final LF, and a file's trailing LF does not create a phantom line.

For input `before\nhit\nafter\n`, a passing line 2 with -n --around 1 --scores and probability 0.8 prints exactly `-- 0.8\n1-before\n2:hit\n3-after\n`. --around 0 still prints `-- 0.8\n2:hit\n`. A two-line selected window at lines 2–3 marks both with colons. Independently selected adjacent or overlapping ranges each print their own delimiter and repeated physical lines. Never merge groups or suppress repeated neighbors. Filter groups follow the existing selected input order; rank groups follow the existing stable ranked order after --top.

Use the existing finite f64 ordering value with its shortest round-trip Rust Display representation. Do not round to fixed decimal places. For filter this is answer.yes(); for decide rank it is that same yes probability; for saved score rank it is Value::Score, the weighted level value. Read these from Judgment/order_value on cache hits and replay too. Do not derive a score from the details value or request counts. The numeric label expresses the accepted meaning and makes no calibration promise.

## Snapshot and identity

When --around is absent, preserve A's lazy intake. -n and --scores impose no whole-input byte cap. When --around is present, prepare the snapshot from every source handle opened by A before starting the pipeline, including stdin when no file is named. Open all named sources first. Then read all original bytes with one remaining combined budget and one overflow-detection byte. Count LF, CR, blank lines and all source bytes before any decoding or trimming. Exactly MAX_RECORD_BYTES, 16,777,216 bytes, is accepted; one additional byte refuses at exit 2 with `--around reads at most 16 MiB across all input sources`. Do not inspect metadata length as proof of the bound. Empty sources count zero. Repeated source arguments count each occurrence. A read error preserves Failure::Input exit 5; open errors and directories retain A's existing safe classification. These snapshot preparation failures print no selected output and send nothing.

Store each source's bytes once in shared immutable memory and feed A's existing Chunks/Reading through cursors over those same bytes. Do not reread paths to render output and do not spool. A named file changed after the first request cannot change either later framed items or displayed neighbors. Full stdin consumption before the first send is deliberate for this view. This preparation validates the combined byte bound, not every future record's content; retain the ordinary record parsing and failure path after preparation.

Give each source occurrence an internal ordinal independent of its display pathname. Extend Position with a serialization-skipped source ordinal, or carry an equivalent private companion through Item, Held and RowContext. A repeated pathname is not a unique source identity. Keep position.file/first/last JSON unchanged. Keep Item.at and Held.at as A's global pipeline identities; never substitute file-local first. Keep A's blank-window skips, per-file window boundaries and final short windows. Clamp neighbors to the matching source occurrence.

Avoid a usize offset table per physical line: a 16 MiB file of newlines would make that table much larger than its byte snapshot. Scan the bounded source bytes for a requested line interval with constant extra index state. Hold the selected Position and score with a judged row. Render groups at the output boundary, rather than constructing and retaining one expanded group per ranked candidate. --top still holds at most N winner rows plus the existing bounded in-flight pipeline state. The immutable snapshot is at most 16 MiB of original bytes, plus bounded reading buffers and source descriptors. Existing selected row and pipeline storage retain their documented bounds. The snapshot cap is not a promise that the process's total allocation is 16 MiB.

Neighbor lines are a byte view, not additional parsed records. Write their snapshot bytes without introducing UTF-8 decoding or JSON validation. A malformed neighboring row cannot become a new candidate or enter evidence. The ordinary intake still refuses that row when it reaches it. Use the output writer's existing broken-pipe and I/O error behavior for both delimiters and physical lines; stop after a broken pipe. Never include snapshot text or filenames in Debug output.
