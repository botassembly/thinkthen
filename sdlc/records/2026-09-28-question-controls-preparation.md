For each, state whether the requested uncertainty means an answer value, an omitted record, an exit class, or just a threshold on details. Then review any proposed question-file key against [the closed grammar and schema](../../specification/question-file.md), parser, shared corpus and digest rules. One exact command case per new distinct behavior is enough after a reviewed design; use a rejected boundary and a no-send invalid-file case where the grammar changes. This work is a separate ticket from 0223.

For annotate options, trace the current `QuestionSet::parse` to `QuestionFile::parse` and `resolve`, then group evidence, batch planning, request digest and output. Existing direct list library and SQL forms should be checked for the stated mapping but should not trigger a new cross-surface campaign. `--dry-run` reads only the first record, so it cannot establish later pointer behavior.
