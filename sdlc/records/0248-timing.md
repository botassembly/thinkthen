Five measured invocations per binary and condition were alternated within each round. Values are milliseconds from Python `perf_counter_ns` around the complete process, including startup, loopback, writer completion and exit. Successful `strace` invocations were warmups and are excluded.

The median differences are 14.170 ms and 14.515 ms in this small, same-host debug-build comparison. A successful positive-sidecar `strace` warmup observed baseline 4 renames and 8 `fsync` calls, including two `.retry.tmp` replacements, versus accepted 2 renames and 4 `fsync` calls, with no retry replacement. The accepted clean warmup observed two base renames, no retry rename, and 6 `fsync` calls including first-directory/lock setup. A **successful baseline clean syscall trace was not obtained**, so the failed route-preflight trace must not be used as a matched syscall count. The successful call's two base writes reflect separately flushed request and token deltas in this setup; writer coalescing can change that count.

## Artifacts, preflight correction and limits

The executed script is ignored `target/codex-builds/0248/timing/artifacts/compare.py`, SHA-256 `eb81df6ae25996977e564ec6a4de2da73cee63d91636e651e77ee03c02977bac`. Its `samples-final.jsonl` SHA-256 is `e125d5516b9c488f426b9d12e9196fad9e2962a41a7978cf0c055b73ed848356`; per-run private folders under `runs-final/` retain base/sidecar files and successful warmup syscall traces. `baseline-build.log` and `accepted-build.log` SHA-256 values are `6f6d44fe5d6be312fbfcb9cdbc70cfded61f3f903bf755e66e2b04fed06b2747` and `6a4b7a203a2eb76b1fb79be8eea7cbd882c3e0af55b9ce61816a04cb290a41e0`.

Two initial **failed** baseline-clean warmup rows remain in `samples.jsonl` and `samples-corrected.jsonl`, with their own folders/traces. The first fake checked both path and body availability before returning 400, so that row alone does not identify the cause. The second recorded the actual path `/v1/systemone/systemone`, revealing that the CLI appends `/systemone` to the supplied base. Both failed commands sent one request, returned status 400/exit 4, and were excluded from timing. The final script uses base `/v1` and exact observed path `/v1/systemone`; it skips another baseline-clean warmup. Thus the final JSONL has **23 successful rows: 20 measured and 3 traced warmups**. Its final print string incorrectly says “24 invocations”; the row count and per-run artifacts are authoritative. No failed response was copied into a successful sample.

The result directly proves this implementation omits redundant sidecar replacements in both conditions and shows lower complete-process time in this bounded setup. It does **not** isolate the absolute time of a usage write, establish a release-build or four-at-once gain, or verify the original older-build 50 ms attribution. The base still syncs, all months still scan, and the writer still joins before command exit. Ordinary multi-record use may amortize process overhead but does not remove it. Disposition after independent review: close the original Asked criterion with accepted 0248 and this bounded comparison. Redundant sidecar writes are skipped without losing counts, and base persistence stays synchronous. Isolating every remaining cost or qualifying a release build would add a requirement not present in that criterion. Do not infer that base sync can be deferred or removed without losing previously durable counts.
