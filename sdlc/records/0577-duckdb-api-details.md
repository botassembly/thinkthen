# DuckDB host API details

The adapter keeps one SQL surface and one Rust request path. DuckDB 2.0 changes the host C++ API, so `databases/duckdb/cpp/src/duckdb_api.hpp` owns the version boundary. It adapts scalar bind inputs, bound-expression data/names, null handling, parameter types, typed identifiers, table column names, macro schema qualification and query-result value access. Each caller uses the same admission and execution body under either host. Ian can overturn these API details.

The 2.0 scalar callback receives `BindScalarFunctionInput`; its client context, original function name and argument expressions map to the adapter's existing binder inputs. The 1.5 callback keeps its original three inputs. The nested binder retains its foldability/NULL checks and constant-argument admission. Bound data remains immutable during scalar execution, with the same weak session context and statement owner.

DuckDB 2.0 stores function definitions through shared pointers and exposes parameter types through `FunctionSignature`. Its overload mutations use `GetParameter(index).SetType`; 1.5 retains its public argument vector. Native scalar null handling remains special handling for every retained signature. Typed identifiers retain the authored function names. New table column-name vectors use identifiers with the same literal names.

DuckDB 2.0 `Connection::Query` returns the unified `QueryResult`. Its blocking `ClientContext::Query` completes the result before returning, preserving the separate relate connection's materialized execution. Values come from its chunk collection; 1.5 keeps `MaterializedQueryResult::GetValue`. Temporary-table diagnosis still asks the executing caller's catalog, using qualified names in 2.0. The committed-table, read-only transaction, holding-row bound, cancellation, connection lease and search-path logic remain in their existing owners.

Root CMake selects `DONT_LINK` only when `duckdb_extension_statically_link` is absent. DuckDB 2.0 rejects that old flag and links only explicitly selected extensions. Both branches therefore build this extension for dynamic loading through the standard local repository.

The checked ownership slice is `duckdb_api.hpp`, `descriptions.hpp`, `complete.cpp`, `files.cpp`, `find.cpp`, `images.cpp`, `nested.cpp`, `plan.cpp`, `portable.cpp`, `relate.cpp`, `relate_query.cpp`, `removed.cpp` and `usage.cpp`, all under `databases/duckdb/cpp/src`. The coordinator confirmed no concurrent DuckDB edits before the repair.
