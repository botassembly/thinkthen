## Cold entry versus functional proof

The preparation's **pre-change** direct `python3 -S types.py` probe had no `runpy`, `PYTHONWARNINGS`, stdlib preimport or safe-path override. All five showed the local `types.py` recursion before J1 logic; the first five-output probe used `head`, so its pipeline status was not claimed as five script exit codes. A complete C# pre-change command exited 1 at `ImportError: cannot import name 'MappingProxyType' from partially initialized module 'types'`. These are cold diagnostics, **not** five observed failures from default `check.sh` under `env -i`.

After rename, each **actual script file** was invoked with `/usr/bin/python3 -S path/to/public_types.py`, retaining its sibling directory on `sys.path`. `PYTHONPATH=/usr/lib/python3/dist-packages` supplied the distro `jsonschema` package hidden by `-S`; it did not preload stdlib `types`. Other inputs were explicit: minimal `PATH`/`HOME`, offline Cargo homes/wrappers/jobs 2, lane lock name, and selected host SDK/native paths. There was no provider call. This is a stricter direct-entry J1 check, not an unmodified whole `check.sh` run.

The first post-rename `-S` probes without that dependency path reached the shared helper and stopped at missing `jsonschema` on four hosts; JVM reached its sibling `toolchains` selector and stopped at missing Kotlin under the minimal `PATH`. ## Checks, size and lessons

All five renamed Python files passed `py_compile`, all five `check.sh` scripts passed `sh -n`, and the five live gate references name `public_types.py`. Configured Python ratchets stayed exact without edits: C# 549, JVM 614, Ada 535, Swift 484 nonblank lines. Dart config measures `.dart` sources only and has no Python ratchet; no product counter changed. Focused offline `policy.py`, `pages`, `tickets` and staged `git diff --check` were run. The previous Objective-C/Zig ratchet and receipts remained unchanged.

Preparation saved a second false warm-gate conclusion: the real shell invokes each Python file directly, so changing cwd or importing it through another module would have missed the shadow. It also correctly found only the live `check.sh` references; no package member list needed a fix. It did not establish that all host artifacts were warm in this lane: C# needed a targeted TypeCase build, Swift needed its type-case product, Ada used a source-matched copied door, and Dart needed a writable offline pub cache. The JVM Java case 41 is a separate functional failure found only after the startup fix allowed the corpus to run. Do not weaken the J1 oracle or infer a passing JVM package gate from this candidate.

The coordinator filed the observed Java case41 failure separately as `2026-09-29-jvm-j1-recognize-offset-case-fails.md`. No pre-change reproduction establishes when that failure began. The cold-entry correction closes only its own criteria.
