# 0222 DuckDB batching design review handoff

Status: proposed B13c design, awaiting fresh independent review. Owner: Codex. Main source snapshot `e99da4a1`; accepted Rust B12a source design `14cbd4b5` remains unbuilt. This branch changes only the [ticket](../tickets/0222-duckdb-record-batching.md), [preflight](0222-duckdb-batching-preflight.md) and this handoff. No runtime, installed-host proof or paid call is claimed.

Review exact C++ registrations and overload compatibility first. The proposal adds context after an existing deadline on normal/listed scalars, rather than adding a same-arity VARCHAR overload that could disturb an untyped `NULL` deadline; warm takes its new third context. Check `NULL` context as absent, ordinary `NULL` inputs, try-details' nullable deadline and safe row failures, bind-time question/member validation, and execution-time caller settings. The accepted B0 final-context rule and vector-edge packing supply public authority; flag only a genuine new choice.

Follow a vector from `thinkthen.cpp::{Decide,Listed}` through `bridge/src/ffi/scalar/ffi.rs`, `ffi/listed.rs`, `src/engines.rs` and B12a's future many-record returns. A batch key needs complete ordered options and context, full encoded size, first-seen rows and original output slots. The draft keeps try-details row-isolated because its recoverable failures are independent values and later good rows must still run; assess this explicit eligibility exception against B0 rather than assuming a success-only many-record iterator preserves it. Warm's sorted `std::set` must become first-seen owned state without relaxing its one-question-per-aggregate refusal. Inspect `StatementOwner` and `SendBudget` together: query expiry spans vectors, a scalar deadline spans its own call, and actual retries/413 halves count as sends. No pre-send row truncation may stand in for attempt admission.

Check the [count inventory](0222-duckdb-batching-preflight.md#existing-count-assertions-and-smallest-installed-host-proof), 500-line headroom including headers/parent modules, and the smallest stock-host proof. The total-one case accepts either independently pinned packed body as transport's one arrival; output order is not send order. Current main has Linux x86-64 C++ session settings, while Linux ARM64 and both macOS packages retain the C API and need 0201/0149/0157 migration and their own host checks. B12a and 0203 final sources need a narrow refresh before runtime claims. Review acceptance of this design would not close B13c or any platform remainder.
