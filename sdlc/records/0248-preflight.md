# 0248 preflight: unchanged retry sidecar

Notes only on `origin/main` `6fd7b1709e87a6f4d8aee80eb00df4a8363acf6d` (2026-09-28). [The reviewed usage-cost preflight](2026-09-28-usage-write-cost-preflight.md) found the candidate. The original [issue](../issues/closed/2026-09-28-usage-file-write-adds-50-ms-per-command.md) asks to measure per-process usage-write cost and decide whether a process can skip or defer work without losing counts. Its 18/4/57/50 ms observations are whole-command medians on older named builds; this preflight measured no current latency and proposes no latency promise.

`engine/usage/storage.rs::update` already scans and validates all recognized months and sidecars under the stable lock, then checks current-month and aggregate additions before any month or sidecar mutation. It may create the private directory and `.lock` before those arithmetic checks. It migrates every contaminated month, sidecar-first, then projects a five-member legacy base. Ordinary writes always replace the base and retry sidecar, even when `next.retries == old.retries`. `scan` accepts an absent sidecar as zero **only** for a clean legacy month; a contaminated month with a sidecar requires matching counts. `replace` syncs its temp file, renames, and syncs the directory. `usage.rs` coalesces pending deltas opportunistically and `cli/mod.rs` finishes/joins before exit. A cache-only hit persists `cache_answers` but creates no retry; explicit replay may queue no usage delta. A first-call saving is possible only with no retry and no required migration sidecar write.

The narrow design changes the ordinary-write branch after validation, checked arithmetic and migration: always replace the base; call `write_retry` **only when `next.retries != old.retries`**. If no sidecar existed for a clean zero-retry month, keep it absent. If a validated sidecar already exists with an unchanged retry total, keep its bytes and inode. A contaminated current or prior month still gets its required migration, even when this delta has no retry. A retry-only delta (possible to `update` even if normal callers pair retry and request counts) still takes the changed-retry path and base-first order. The lock prevents cooperating old and new writers from interleaving inside the operation; an old writer after unlock rereads/adds the base and leaves the sidecar alone. A later new writer rereads both. No new parser, schema, setting or sidecar repair mode is implied.

Existing `engine/usage/tests.rs` is **480/500 nonblank lines** and assumes zero-retry updates create a sidecar: its read-directory count, migration setup `remove_file`s, overflow fixtures, strict-sidecar corruption setup and generic `Stage::RetryWrite` loop all need review. Do not replace those with absent assertions that no longer trigger their named boundary. Seed a real retry where sidecar identity/corruption/failure matters; remove an obsolete `remove_file` only where a clean absent sidecar is the intended fixture; preserve exact overflow bytes and failure categories. Add the new inode/absence proof in a small private child of `usage/tests.rs` if needed; it has no existing file-cap pressure. `storage.rs` is **282/500** and `usage.rs` **412/500**. Measure the root source ratchet after code, and keep changes local to `storage.rs`, affected existing usage tests, and a private test child. No CLI, public docs or new dependency is needed for this optimization.

Proof must distinguish skipped write from an identical rewrite. On Unix, compare `(dev, ino)` of a validated positive-retry sidecar across a no-retry update while asserting base counters increase and sidecar bytes/count stay exact; atomic rename would change the inode while the old file still exists. For a clean first no-retry write, assert no sidecar exists, then send a retry delta and assert it appears with exact total. Run the real pinned old reader/writer sequence from experiments 346/347 in isolated 0700/0600 `XDG_CACHE_HOME`: 100 requests/7 retries → current 101/7 → old 102/7, old `status` reading the five-field base and new `status` retaining seven. Reuse the accepted migration, aggregate/current overflow, malformed/symlink/mode, base and sidecar failure tests. A sidecar fault must be injected on a **changed-retry** update; on a no-retry update it must remain unvisited. No test-only production hook is needed. Do not mutate the real usage folder or repeat the external experiment broadly.

The candidate removes an unnecessary sidecar replacement, not the base sync, all-month scan or normal final writer join. A bounded isolated before/after short-command observation may follow correctness and must report the exact source/binary, fixture state, cache condition and actual operations. If the base sync, history scan or lock contention dominates, the issue's broader timing criterion remains open for attribution or a separate durability choice. This design does not reopen ticket 0235's accepted retry-under-count-on-interruption limit or touch the paid live ledger.
