This proposal applies ticket 0516 to source revision `7b1254a3b94e0f063b3d5e4c3720548390b20551`. [ADR 0129](adr/0129-owned-json-sessions.md) owns native lifetime and packet semantics. [The binding decision](../decisions/2026-10-09-thin-first-class-bindings.md) owns the single public API. [The package decision](../decisions/2026-10-09-native-package-design.md) owns distribution targets. Ian can overturn the host names and wait interval.

## Caller API

`Engine.Open()` uses native environment defaults. The configured overload takes generated engine settings. The ten named `DecideAsync`, `ChooseAsync`, `TagAsync`, `ScoreAsync`, `FilterAsync`, `RankAsync`, `FindAsync`, `AnnotateAsync`, `RecognizeAsync` and `RelateAsync` methods take generated question, input and options values plus `CancellationToken`. Each creates a canonical Request and calls `thinkthen_session_new`. No method calls an older judgment export or wraps blocking execution in a Task.

Atomic and annotation calls return `Call<T>` with owned generated rows, ordered generated observation values and the actual generated terminal packet. Rank and recognition retain their aggregate lists; find and relate retain their single generated aggregate values. `Call<T>` is host collection and lifetime idiom, without a copied facts model. Native execution failure throws a host exception containing the generated `CallError` and completed packet prefix. Immediate admission failure uses the native error code and safe session diagnostic. Cancellation throws `OperationCanceledException` without reporting invented final facts.

`Engine.StartSession` admits a generated Request and returns a disposable session. The session exposes `ReadAsync`, `PushAsync`, `Finish`, `Cancel` and `Dispose`. Generated descriptors carry feed items and optional native locations. `PushAsync` retries the same descriptor after Full and reports Closed without taking another item. One producer and one reader may operate concurrently. Concurrent reads or concurrent producers refuse as host lifecycle misuse. A caller can supply its own asynchronous enumerable, advance it only after acceptance and stop after Closed or cancellation. The host takes no ownership of an arbitrary blocking foreign iterator.

An explicit session retains its receiver after `Cancel`, so `ReadAsync` with a fresh token can drain completed packets and eventual actual terminal facts. A named convenience call disposes its session on cancellation and relinquishes unread packets. Disposal never promises that native settlement finished.

## Waiting and ownership

Every native session operation is nonblocking with respect to providers and queue readiness. Read waits with cancellable `Task.Delay` only after Pending. Push waits with the same delay only after Full. Use a private shared interval of ten milliseconds. An active session has at most one read delay and one producer delay; it owns no host worker thread, blocking wait or queued result history. Timer wakeups cost at most one readiness probe per interval per waiting direction. Completed packets are read immediately until Pending; each consumer controls how many values it retains. This is bounded timer polling, with no spin loop. Every await uses `ConfigureAwait(false)`.

Engine, session and result owners use `SafeHandle`. P/Invoke accepts the corresponding handle parameter so the runtime pins that owner throughout each call. Session cancellation registration calls a short helper which obtains a SafeHandle reference before signaling native cancellation. If disposal has already closed ownership, the callback does nothing. Disposal signals cancellation before closing the SafeHandle. In-flight pins postpone native free until their calls return; native free closes the receiver and does not join the worker. Register disposal waits only for that short callback. No callback receives a raw unpinned handle.

Read transfers the result into a result SafeHandle. Borrow its JSON, copy the full byte extent to managed storage while that handle is pinned, parse through generated `SessionPacket.Read`, then release the result owner. The generated value clones its backing document and retains nested unknown members and missing versus explicit null. Neither the engine nor session is needed after that copy. Finalization releases abandoned session ownership through the same native free door.

## Generated inputs and source gaps

The canonical `specification/request.schema.json` already contains Request, the ten RequestCall alternatives, typed authored questions, input selectors, controls and RequestSessionDescriptor. The existing Rust-derived complete schema and C# reference already include observation, row, aggregate and terminal packets. The installed generated C header supplies every session door and independent packet JSON ownership. Generated C views belong to 0505 and are unnecessary for this migration.

Extend `sdlc/generators/results/generate.py` and its existing C# target rather than create another generator. Derive input constructors and writers from the existing Request graph. Input writers emit the schema's literals and member names, with native scalar and collection types and explicit presence where admitted. They perform no native grammar, default, threshold or route validation. Authored unions need writable generated alternatives; overlapping schemas require no host discriminator because the caller selects the alternative before serialization. Arbitrary authored JSON remains an explicitly arbitrary value at its native schema edge.

The existing source has no derived schema for the engine-settings object, the legacy plan input or session reader failure. `libraries/c/src/settings.rs` applies a dynamic map after `EngineBuilder::validate_settings_json`; `libraries/c/src/plan.rs` declares the plan transport privately. The Request schema defines descriptor locations but does not define the finish failure enum. Copying these field inventories into C# would recreate the structural defect this ticket removes. The native owner must expose these graphs through the existing schema pipeline, or the coordinator must approve an explicit narrower first slice. No new handwritten settings mirror, host validator or unsupported plan transport is proposed.

## Package and loader

Keep `Botassembly.ThinkThen` and `net8.0`. Pack the managed assembly at `ref/net8.0/ThinkThen.dll` and `runtimes/any/lib/net8.0/ThinkThen.dll`. Pack version-matched assets under the five portable RID native directories specified by the package decision. Local Linux proof builds one Linux package with the actual native library and loader identity alias as separate files. It qualifies only that installed RID; other platform assets require their owning authorized build route.

`NativeLoader.cs` checks the supported OS and architecture before engine construction and initializes imports using the logical name `thinkthen`. Ordinary .NET native probing resolves the package asset. It accepts no caller pathname, environment override, working-directory search, download or native build. Package creation takes already-built native assets and verifies their native version through the existing package checks. Missing or mismatched assets refuse packaging or engine creation rather than falling back to a source tree.

Change `libraries/csharp/ThinkThen.csproj`, `Botassembly.ThinkThen.nuspec`, `README.md` and `check.sh`; migrate `tests/source/NativeChecks.cs`, `Installed.cs`, the existing source consumer files and their existing Python runners where API calls or package paths change. Remove `NativeAbi*.cs`, `NativeReaders*.cs`, old detail and batch readers, copied complete carrier models and old request models after their consumers use generated values. Keep the old-to-new mapping in the README.

First generate typed Request inputs and compile a real typed consumer. Next implement session ownership and waiting, then move the named calls and existing caller cases. Finally assemble the local native NuGet package and run installed parity. Each coherent implementation step commits and pushes independently. The developer does not land or change native sources.

## Acceptance evidence

Use the existing shared conformance runner and a fresh local NuGet install without native path variables. Extend the existing installed boundary cases with a held loopback provider: unrelated asynchronous work advances, caller cancellation returns with the host cancellation exception and disposal returns before provider release. Check completed output ownership after result/session release, explicit drain terminal facts, Full retry of the same descriptor, Closed stopping the caller's reader, cancellation racing disposal and native failure facts. Reuse native session coverage for the underlying terminal and backpressure matrix. No paid call, runtime network acquisition, candidate, Windows qualification or publication follows from this local pilot.
