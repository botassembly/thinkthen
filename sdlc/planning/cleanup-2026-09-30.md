# Cleanup phase, from 2026-09-29 night

Status: active. Claude owns the thinkthen queue for this phase, on Ian's ruling of 2026-09-29. Codex is stopped for the night. This page is the status authority while the phase runs. It replaces `work-plan-2026-09-27.md` for new work; that page stays as the record of the earlier batches.

## Goal

Make thinkthen thinner, lighter, and faster to test, then burn down the issue list. One engine owns batching, caching, and types. Every surface is a thin layer over it.

## Ian's rulings, 2026-09-29

Ian can overturn each ruling.

1. Claude owns the queue and the cleanup phase. Claude drives the work through fresh subagents.
2. The cache stores one backend question, not one request. The key is the model, the backend address, the shared context (`state`), and one question as sent. A batch reply is split and each answer is stored alone. A later batch sends only the questions the cache lacks.
3. An answer may differ slightly when asked beside other records. That difference is acceptable. This overturns ADR 0048 item 5.
4. The cache is keyed on the three System One question kinds (`noul`, `choice`, `score`), not on the ten functions. The ten functions build those questions. `recognize` and `relate` cache their backend questions the same way: context, question, model.
5. Each cache entry records when it was taken. Clearing comes later.
6. For test recordings, do whatever is simpler.
7. Rust owns every type. Surfaces read results as JSON described by one schema generated from Rust. Ports stay thin. Ports add only named outcome and error codes and a null that cannot be mistaken for a failure. The other type-review recommendations wait.
8. Remove pedantry in code and process. Prefer less code, fewer checks that only police wording, and shorter records.

## Ian's rulings, 2026-09-30

9. Batching may change answer quality. That is accepted. People who want consistent answers should not batch. The per-record form stays; experiment 275's choose/tag gap needs no remeasure.
10. No public release before 0.1, and 0.1 waits for every surface and binding. Local and internal releases are fine. Ticket 0319's command-only release slice is dropped.
11. Merged branches may be deleted.
12. Installing packages the checks need is authorized, including pandas. Pandas stays an optional Python dependency; a user without pandas does not get it installed.
13. Paid calls through `sdlc/scripts/live` are authorized, under a token cap. New dependencies are allowed when needed.
14. No requests-per-minute pacing by default at any address. A rate is set per backend in the configuration file's `backends` object, built-in or added, with `THINKTHEN_REQUESTS_PER_MINUTE` above it. Ian's words: "Just make it configurable. There shouldn't be throttling at first. You set it or don't set it, and it can be done per backend in your configuration. There shouldn't be a default number for liquid. Everything should get the same configuration, and it should be in the settings file, not in the backend." Ticket 0343 builds it.
15. 0.1 publishes to every registry. Go publishes by tag through proxy.golang.org; Zig, Swift, Ada, COBOL and Objective-C install from GitHub Releases. Ticket 0355 adds the missing publish jobs.

## Order of work

1. **Green main.** Fix the failing tests of `cargo test --workspace`. Run the full suite before each landing. Ticket 0303.
2. **One question cache and one batching path.** Design first, with a fresh review, then build. ADR 0111 and ticket 0304.
   - Every function quotes each record inside its own question. `choose`, `tag`, and `score` stop sending all records as the shared context.
   - One cache store with a taken-at time. A converter turns request-level recordings into question entries.
   - Cache lookup happens before packing. Only misses are packed and sent. Partial replies store their good answers.
   - The requests-per-minute limit lives in the same scheduler.
   - Content-cut batching goes away if the design no longer needs it.
3. **Move every function and surface onto the one path.** Delete the duplicate batching code in `cli/asking`, `cli/annotate`, `public/batch`, `public/native_batch`, and the facade.
4. **Remove hacks.** One-millisecond sleep loops, process-wide statics, tuple packing to pass lint, and upward imports from `core` and `engine` into `public`. One folder-permission rule.
5. **Tests.** Measure the suite. Keep exact-output tests at the command line. Surfaces replay one shared case set from `conformance/`. Delete duplicates. Ticket 0305 measures first.
6. **Lighter.** Audit dependencies and the Polars feature weight.
7. **Types.** Generate the result schema from Rust. Ports get named outcome and error codes and the null-versus-failure rule.
8. **Issue list.** Release blockers first: panic payload secrecy, the requests-per-minute pacer, the token cap, the nine package gates, the PostgreSQL shared cache.

## Lessons for builders, 2026-09-30

Each builder and reviewer reads this list first.

1. Check the premise on main before building. Ticket 0321's check already existed, and 0327 repeated 0326.
2. Run every check the change can reach, and compare each red with main. A change to the engine, the public API or the batching shape reaches Polars, the C door, every binding, the native hosts over the C door, and the three SQL extensions. `sdlc/scripts/test` skips all of these. Skipping them left four hidden reds on main today, and slice 3a broke the SQLite extension at runtime.
3. Run `lint` in a clean checkout, or with build copies removed. A lane that has run a check holds ignored files that can hide a failure; 0332 passed lint in its lane and failed on main.
4. Use only your lane's heavy lock. Borrowing another lane's lock made four surface checks fail falsely.
5. Tests that share a file write it to a new name and rename it. Nextest runs tests as separate processes, and a half-written file failed one run in 60.
6. A merged or deleted test names the regression it kept. Review caught three proposed merges that would have dropped secrecy, invalid-input or cancellation cases.
7. Look before installing. The pinned Ruby, Dart and Flutter were already built under `~/.local/opt`.
8. Check the real names of key variables by listing names only. Liquid's key is `LIQUIDAI_API_KEY`; the wrong name caused a false 401.
9. File an upstream bug with the condition for removing its workaround, as the Zig 0.15.2 linker issue does.
10. File debt as an issue with `Kind: debt` and `Pay when:`, per `sdlc/issues/README.md` "Debt". Name the issue in a code comment, never a `TODO`.
11. Stop only process IDs your lane started. Never run `pkill` or `killall` by name: on 2026-09-30 one lane's `pkill` killed two other lanes' surface runs, including the checkpoint sweep.
