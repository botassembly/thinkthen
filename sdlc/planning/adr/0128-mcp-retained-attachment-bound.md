# ADR 0128: Bound retained MCP attachments and refuse nonregular selectors

Proposed for ticket 0481. The coordinator must accept this ADR after design review before changing the settled MCP contract. Ian can overturn the support boundary below.

## Authority and evidence

Ticket 0481 authorizes bounded aggregate attachment retention and selector liveness. [The specification rules](../../../specification/README.md) require an ADR for changes to a settled section. [The MCP contract](../../../specification/mcp.md) already bounds incoming frames through `mcp::protocol::MAX_MESSAGE`, while native images retain the separate admission in [ADR 0121](0121-native-image-input-and-route-admission.md).

At source `ab6dd644528b9eae3d3e2bfeaa6e7a5b5348bf6b`, `mcp/composition.rs::records` eagerly collects all explicit descriptors. `mcp/inputs.rs::compose` reads each attachment separately before complete native admission. Each file read is capped by the native per-image ceiling, but retained rows have no aggregate attachment ceiling. Default record count is unlimited. Repeating a small valid file therefore retains one new compressed buffer per occurrence despite a small protocol frame. Native immutable handle clones share their buffers; separate file reads create distinct buffers.

The owned [reproduction](../../../specification/fixtures/mcp-input-bounds/reproduce.py) constructs a valid synthetic PNG, repeats its path across individually valid image-only descriptors, then names an absent file. It reaches that last file after the retained originals exceed the framing ceiling. The failure sends no backend request. This establishes eager retention before execution; it does not measure a maximum process-memory bound.

`public/question_file.rs::read_question_file` opens the selected path before checking its kind. Its byte cap cannot prevent FIFO open from blocking or `/dev/stdin` from reading the protocol pipe. The same fixture leaves the FIFO selector's tool worker occupied while ping remains responsive and another tool call receives busy. The stdin selector either leaves the worker occupied or competes with the protocol reader for the next frame. Protocol responsiveness does not establish tool completion, cancellation or worker joining. The fixture separately observes shutdown and kills and reaps every remaining child.

## Decision

Reuse `mcp::protocol::MAX_MESSAGE` as a ceiling on the aggregate original compressed attachment bytes retained for one MCP call. Keep the incoming frame bound independent: frame bytes and attachment bytes each have their existing transport ceiling, rather than subtracting protocol syntax or captions from attachment allowance. Define no new setting, record-count cap or native SDK ceiling. Empty/text-only collections do not consume attachment allowance.

Charge every ordered attachment occurrence across the complete call. Preserve duplicates and order; do not deduplicate repeated paths, skip images, truncate bytes or use cache identity to evade admission. Charge a retained original once when composition clones the same immutable handle internally. Count caller-supplied repeated entries independently even if their bytes match. A call exactly at the aggregate ceiling may proceed only if all native checks also succeed.

One checked remaining-byte budget follows explicit top-level images, every `inputs` descriptor and inline image value through composition, and image sources through native reading. Legacy MCP descriptors currently expose file attachments rather than inline image bytes. The shared Request owner supplies future typed inline bytes under ADR 0125; this ticket does not edit Request or add a new MCP spelling. Any inline byte path adopted by MCP must use the same budget before retaining an additional decoded original. Existing encoded input already remains subject to framing admission.

Bound a file read by the smaller of the remaining transport allowance and the native image ceiling, plus one detection byte. Refuse before pixel decoding or copying an over-budget original. Use checked subtraction; consume allowance only for admitted originals. Once exhaustion is established, stop before opening later attachment or evidence paths. A detection byte and bounded decoder scratch are transient overhead, not retained originals. A metadata size check may refuse early but cannot replace the bounded read because files can change. A corrupt earlier image may still fail native validation first. Keep stricter attachment-count, per-image, per-question, pixel, route and encoded-body admission.

Explicit finite collections retain whole-call preflight and zero sends for any failed item. Do not introduce incremental sends to reduce retention. Source reading retains its native ordered iterator and existing admitted-prefix semantics; a later source failure may follow earlier sends. Apply the remaining budget cumulatively as that iterator advances, even when earlier source buffers have been released. This conservative per-call accounting prevents path-count-dependent allowance and adds no scheduler. Diagnostics use existing safe Usage mapping for attachment admission and reveal no caller contents.

The transport ceiling may refuse an MCP attachment or complete attachment collection that the native SDK otherwise admits. MCP's local bounded stdio worker is the reason for that narrower support boundary. The native per-image ceiling continues to describe native admission, not a promise that every transport can admit it. Callers needing larger collections can make separate bounded calls or use the native interface. No automatic splitting changes the requested call. This support ruling must appear in the MCP specification after acceptance.

The shared capped question/plan reader checks followed path metadata for a regular file before opening it and rechecks the opened handle before reading. Map a nonregular selection to the existing unreadable-file error without adding a public error variant. Preserve ordinary files, named lookup, working-directory reference precedence and symlinks whose target is a regular file. Reject directories, FIFOs, devices and stdin aliases before a blocking open or protocol read. The same reader serves question files, question sets and plan files; adapters must not duplicate file-kind checks.

A pre-open metadata check and post-open handle check do not close a hostile path-replacement race between metadata and open. This change protects stable caller-selected nonregular paths. It does not claim adversarial filesystem confinement or nonblocking open for every raced object. Preserve this limitation explicitly; introduce no platform-specific unsafe opener, new dependency or general file-security design. Linux owns the FIFO/stdin reproduction. Portable regular-file checks and existing Windows MCP cancellation tests remain required; this fixture does not qualify Windows device paths.

## Implementation and acceptance

After acceptance, amend the settled MCP specification, pass the one budget through composition and a narrow bounded native image-reader entry point, and add the file-kind check in the existing shared question reader. Keep the transport constant as the source of truth. Coordinate any shared Request integration with its owner; change neither its types nor its contract here.

Use outside-in regressions for many individually valid rows under unlimited default records, rather than a single oversized descriptor or configured record cap. Cover explicit paths, typed inline bytes when available, source-backed images and ordered repeated entries. Establish refusal before a later owned path and count loopback requests for finite preflight zero sends. Below the bound, retain normal files, named question references, regular-file symlinks and image ordering. Owned FIFO and stdin selectors must refuse promptly, allow a subsequent framed tool request to finish, and preserve cancellation/shutdown. Existing installed MCP and cancellation checks remain the owners of those contracts. Run focused checks and policy, then one fresh memory/liveness source review. Add no benchmark, receipt, fingerprint or new proof runner.

The structural risks are duplicated admission and unbounded retained state. One remaining budget and the existing shared readers address them. This bound covers originals, not total process RSS: protocol carriers, row metadata, pixel scratch, base64 and equivalent output representations have separate costs and existing limits.
