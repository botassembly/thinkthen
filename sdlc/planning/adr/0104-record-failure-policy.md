# ADR 0104: Continue past an isolated annotate input failure

- Status: Proposed for fresh Medium design review. The coordinator may accept this routine CLI choice within the four recorded failure outcomes; Ian can overturn it.

## Decision

Keep ordered-prefix stop as the default. Add `--on-error continue` only to `annotate --jsonl --details --batch 1` on a record stream. The flag is annotate-specific, not a member of shared `Common`: other verbs refuse it as an unknown option. Refuse `--on-error continue` without all three companion options, on one document, or with `--dry-run`, at usage exit 2 before reading input or sending a request. Refuse any value besides `continue` by clap at exit 2. This is a narrow opt-in view for a JSONL pipeline with a distinct versioned result carrier; it does not claim that a filtered, sorted, or packed output can preserve one row per input.

Only `RecordError::Missed(pointer)` while preparing one record is recoverable in this first slice. It sends no request for that record. The scheduler emits exactly one compact error JSON line in input order and then processes later records. Its complete schema is `{"schema":"thinkthen.record-error/1","at":2,"failure":{"kind":"usage","cause":"missing_pointer","pointer":"/body"}}`. `kind:"usage"` reuses the settled six-kind failure vocabulary of ADR 0082 and `specification/types.md`; `cause:"missing_pointer"` is a narrower reason for this row, not a new failure kind or an annotate failed-question cause. `at` is the one-based record ordinal after JSONL framing, not a user id or physical line number; JSONL has no skipped blank lines. The pointer is the user-supplied `on` pointer already named by the current diagnostic. The row has no `value`, `answer`, `input`, `meta`, request, backend body, key, status or token count. A consumer distinguishes `thinkthen.result/1` from `thinkthen.record-error/1` by `schema`, not by null. Do not serialize `Failure::Display` or `Debug` into it. A future recoverable cause requires a separately reviewed schema/example and classification; malformed JSON, oversized input, invalid UTF-8, table framing, question/set faults and output failures remain terminal now.

When the run reaches end of input with one or more error rows, print exactly `thinkthen: 1 record skipped\n` for one skip or `thinkthen: N records skipped\n` for N on standard error and exit 7. No skip and no failed logical answer exits 0. An otherwise completed run with failed logical annotate questions and no skips keeps exit 6 and no diagnostic; if it has both failed-question markers and skipped rows, exit 7 wins and the markers remain in their completed rows. A later terminal failure retains its existing code, cause diagnostic and stop boundary even after skips. Print the skip-count line once before the terminal diagnostic; `--facts`, when asked, stays the final standard-error line. This count is the number of error rows emitted, not the number of attempted requests. A stop is never converted into success by this policy.

For `--facts`, `records` counts completed input positions, including emitted error rows, so a good/bad/good stream reports three finished records. `requests_sent`, retries and cache answers remain actual process counters. A skipped local record contributes no send and no token count. Existing token fields remain absent unless every live reply that arrived reported usage; never synthesize zero for an unreported failed request. Exit 7 is a completed run and has no `stopped`; a later terminal failure retains its existing `stopped` shape. The existing `thinkthen.run/1` schema needs no new member for the skip count because the explicit standard-error line reports it.

## Separate annotate outcomes

In `--details`, a question name may match an input object member: the original input stays under `input`, while named judgments stay under `value` and `answers`. Exempt that mode, including its first-record dry run, from the current `AnnotationCollision` check. Without `--details`, keep the exact collision refusal and zero-send behavior. This exemption is independent of continuation; it completes register 65 without turning a collision into an error row.

Keep the established grouping rule: questions with the same normalized `on` share a request; one failed logical question beside a good answer prints a completed row and exit 6. A wholly unusable reply for any group remains terminal exit 4, even if a sibling group answered. Its partially assembled sibling answers are not published as a successful or error row. Under `--batch 1`, no other record shares that request, but the record can still have several groups or profile chunks and already dispatched work may have been sent. A failed multi-record batch under the default setting remains the existing range stop; it cannot identify one poisoned member without isolation requests. Cancellation, deadline, replay miss, transport/status/reply failure, model mismatch, defect and write failure remain terminal under the flag. A later terminal cause outranks an earlier exit-6 marker or skip exit 7. The annotate page must state the request economy and the different costs of shared partial versus wholly failed lone groups, plus the cost of editing/rerunning a group. This completes register 68 as its own documentation criterion.

## Scope and remaining criteria

This first slice gives register 66 its scattered missing-`on` pointer outcome and gives register 43 one bounded poison-record path. Register 43 remains **open** for malformed records, other record verbs, and backend failures including a whole failed batch. Do not call a failed group or batch one poisoned record, and do not close the broader register on this ticket. The existing `--cache` resume how-to remains valid for default stop and for terminal failures. An additional continuation ticket needs a separate supported-verb and batch-isolation decision based on real request and cost evidence, not an automatic extension of this flag.

## Normative updates and proof

Amend settled `specification/{annotate,channels,records,result,roadmap,types}.md` and the narrow `specification/settings.md` inventory row in the implementation landing. `annotate.md` owns flag combinations, failure grouping and output examples. `result.md` owns the exact distinct error envelope and facts count. `channels.md` assigns exit 7. `records.md` states the bounded exception to default stop. `roadmap.md` retains the broader hold with this shipped subset identified. `types.md` names this CLI-only row under the existing six-kind vocabulary. Add a **named** `recordError` definition to `specification/result.schema.json` with a schema-only valid and malformed control in `specification/fixtures/types/corpus.json`. Keep that schema's root `$ref` on successful `thinkthen.result/1` detailed rows and its current `failure` definition on failed annotate questions; the new envelope is neither one. The corpus checker already supports response-only schema cases without calling the C door. In addition to structural controls, an outside-in CLI case must assert the exact emitted row and a consumer must route good and error rows by `schema`, rejecting any unknown schema before applying policy. No C-door or binding result shape changes. Update CLI help in the same landing. No site source changes belong here.

One outside-in JSONL case uses `{"id":"a","body":"first"}\n{"id":"b"}\n{"id":"c","body":"third"}\n` and a one-question set with `on:/body`. Two pinned loopback replies return valid yes/no answers for `first` and `third`. Assert three complete output objects in order: the existing exact detailed `thinkthen.result/1` rows for a and c, with expected digests computed from **independently fixed request bodies** and the listener URL, and the literal error object above between them. Assert exact standard error, exit 7, and exactly two captured request bodies equal to the fixed first/third bodies; inspect bodies, not just digests. The default command against the same inputs must retain one detailed row, its existing two-line pointer/stop diagnostic, exit 2 and one send. A second one-record collision case pins the exact detailed row and preserved `input` with one send, plus bare-mode exit 2/empty stdout/one old diagnostic/zero sends; dry run checks the details exemption with zero sends. Retain existing partial-reply tests for exit 6 and terminal group failure; add a compact flag-on terminal group case only if the flag changes that path. Include a no-key/canary check for error stdout, stderr and `Debug`-free serialization. Do not run a provider or broad build for this design.
