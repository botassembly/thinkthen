# ADR 0099: Inspect a key before an empty folder's first binding

Status: **Proposed**, pending fresh Medium design review and coordinator decision. [Ticket 0228](../../tickets/0228-cache-first-use-binding.md) and its [preflight](../../records/0228-cache-binding-preflight.md) give the source proof at `76a3bc7c`. This ADR changes no settled contract until accepted. Ian may overturn the admission policy.

## Problem and existing ruling

Ticket 0065 and settled `specification/recording.md` require a new or empty write-capable folder to publish its adapter-and-URL marker **before key lookup or send**. `request::ask_prepared` currently prepares the recorder before invoking the key closure. A nonloopback command with a missing key can therefore create the default cache, its marker and lock artifacts, send nothing, and leave that folder bound to an address it never used. The marker hashes adapter and canonical URL, excludes model, and does not retain the bound URL as printable text. Existing mismatched and legacy folders must still refuse before key lookup. An exact replay or cache hit must still work with no key.

## Proposed narrow exception to ticket 0065

Before writable preparation, perform one **read-only admission probe** for a write-capable folder. A path that does not exist, or an existing private empty folder with no marker and no digest-shaped final entry, qualifies. Probe errors are local storage failures. A folder with a marker, including a malformed one, or a legacy digest-shaped entry follows the original gate path first; it keeps the established mismatch, storage and legacy refusal precedence. Strict replay is unchanged. The probe neither publishes a marker nor sets the recorder's checked state.

For a qualifying folder, observe cancellation and invoke the existing key closure once. If it yields a usable key, retain that value, then run the original writable preparation and send path. The preparation gate remains the **only** binding authority: it rechecks identity, publishes the same complete marker before any send, and preserves the digest lock and first-writer rule. A competing writer can bind between the read-only probe and this gate. A different-address winner refuses the loser before it sends; a same-address winner may yield a replayed hit. An early key lookup in that race is permitted even when the final answer is replayed. A previously bound hit and strict replay continue to bypass key lookup entirely.

If the early key lookup fails, probe read-only **again** before returning the key error. If a cooperating writer has meanwhile published a marker, enter the original gate/entry path: a matching in-progress writer can finish under its digest lock and supply a keyless hit; a mismatched marker gives the original mismatch refusal. If no such hit results, cancel any live permit and return the saved key error. If both probes observe an unbound empty folder, return the key error without creating folder, marker, lock or temporary entry. A legacy entry that appears between probes receives the original legacy refusal. This second observation protects the common concurrent keyless-hit case. It cannot promise an atomic snapshot: a writer that publishes **after** the second probe may produce an entry after this caller has returned the missing-key error. That caller did not observe a hit; a later call may replay it. External mutation/removal of a marker is outside cooperating-writer guarantees, and the authoritative gate still validates before a send.

Keep the existing count of at most one key inspection per request, HTTP attempt and usage accounting, cancellation/deadline checkpoints, send reservation and output shapes. A cancelled call that has already prepared writable state or an HTTP budget refusal may still leave a marker. This is a missing-key first-use correction, **not** a rule that every zero-send call has no filesystem effect. A later reviewed design would be required for register 10's full zero-send criterion.

## Alternatives and cost

- Moving the marker to entry installation would allow different-address first writers to send before either marker wins. It would weaken ticket 0065's protection against an unintended paid request, and it would need a wider shared-state protocol. Do not choose it here.
- Reading the key before every cache lookup would make cached and strict replay answers require a key. Do not choose it.
- A single early probe without the post-error observation can return `NoKey` while a cooperating writer has just bound and is about to install a matching hit. The second observation costs one extra read-only inspection on the missing-key edge and retains that ordinary keyless wait when it is visible. There is no polling, lifecycle framework or contention campaign.
- Storing a recoverable bound URL would change the closed marker schema and migration of existing folders. Generic mismatch wording would remain unable to name both addresses and would discard the current useful requested-address cue. Neither diagnostic alternative belongs to this admission change.

The source slice would touch the private recorder and identity files, `engine/request.rs` after ticket 0212 transfers its hold, one outside-in cache-identity test table, the settled recording paragraph, and the derived ratchet. It adds no public API, dependency, model field, marker version or replay entry change. The test must pin the first no-key exit and unchanged folder names, then a successful second-address first use; retained mismatch, concurrent-first-writer, bound-hit, strict-replay and legacy cases protect the other outcomes. No runtime work starts on this proposed ADR.
