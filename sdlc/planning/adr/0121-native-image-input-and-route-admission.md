# 0121: Native image inputs and bounded route admission

Decision: accepted input/source/route design in tickets 0447/0448, implemented by the native lane for coordinator review. Ian may change supported formats, SDK bounds or route admission; unknown local profiles remain refused.

Keep existing scalar signatures, text request bytes, ReaderOptions and SourceRecord. Add immutable ImageInput, ordered ImageEvidence and QuestionInput. InputEvidence adds typed batch inputs without widening the old text Evidence trait. Core receives validated originals and dimensions, never decoders or filesystem access. The existing reader manifest and question scheduler remain shared. JPEG and single-frame PNG are the initial formats; WebP, GIF and animation refuse.

At the edge, pin image 0.25.10 with defaults disabled and PNG only, jpeg-decoder 0.3.2 with defaults disabled, and base64 0.22.1. Rust std has no compressed JPEG/PNG pixel or DEFLATE decoder. The rejected zune-jpeg 0.5.15 panics on the shared progressive one-component APP14 transform2 fixture even in strict mode; jpeg-decoder handles its component count before Adobe color transform and returns a safe error for that fixture. jpeg-decoder recovers some missing entropy by filling zero bits, so decoded-pixel validation is not a strict JPEG encoding certificate. No custom JPEG parser or global panic handling is added. Actual feature resolution includes image's moxcms SIMD and PNG's miniz backend; disabling top-level defaults does not imply a std-only graph.

SDK bounds: eight images, 24 MiB compressed bytes per question in total, 16 MiB ancillary text, each side at most 8192 and at most 16,777,216 pixels per image. Decode one image at a time and discard pixels. Decoder allocation/output limits are 128 MiB; JPEG coefficient and scratch allocations also depend on dimensions, so this is not a total RSS guarantee. Memory risk is High. These limits admit realistic inputs beyond the spike's 32 KB and 64 KB caps. Original bytes, media, order and duplicates remain intact; no resizing/re-encoding occurs.

Identity uses the existing State and question keys with a typed compact envelope: `{"schema":"thinkthen.image-state/1","text":ORIGINAL_JSON_OR_STRING,"images":[{"media":CANONICAL_MIME,"base64":CANONICAL_ORIGINAL_BYTES},...]}`. Filenames remain outside state. 0444 owns cache/2 migration; this change creates no new cache and invents no result/2 identifiers.

Image state SHA-256 prefixes the compact envelope with `thinkthen.image-state/1\n`; image question keys prefix the existing five-part construction with `thinkthen.image-question/1\n`. Ordinary text/JSON state and question hashes remain byte-identical. The shared store/fixture parser distinguishes image entries by the state hash domain, never by guessing that an ordinary JSON schema marker means an image. 0444 must retain these constituents when migrating the native image slice.

Native SQLite image hits read the answer and referenced state in one query snapshot. The stored envelope must equal the canonical serialization of the current edge-validated input, including version, ancillary text, every ordered media/base64 byte and duplicates. Validate its stored state digest and rebuild the image question key from the stored URL/model/question before accepting the answer. Missing references or corruption refuse locally, including strict replay, with no sends or writes. The existing JSONL parser checks state digests and all question-key constituents before serving a fixture. These protections ship in the native slice before future migration.

Liquid's explicitly selected decision route and literal d1 use ordered top-level data URLs. Enforce JSON below 4,500,000 decimal bytes, eight images, at most 10,000 total ceil32 patches and aspect ratio at most 100:1. d1:free refuses images. Its per-question image estimate is ceil(3*patches/2) per image.

Perplexity's explicitly selected decisions route and literal pplx-decider-v1-27b use state array text/JSON plus ordered image_url parts; no top-level images. Enforce 32 MiB body, 128 questions and 2048 nearest32 tiles per image. Upward half ties and at least one tile are conservative SDK rounding choices. Eight images is an SDK bound, not a published vendor count. The SDK image estimate uses ceil(3*tiles/2) per image plus the existing text-byte estimate, repeated per question. This is not exact admission to the vendor's under262144-token context. Returned usage stays authoritative. Explicit caller request bytes and backend profiles may narrow image admission; the default text packing target is soft.

Unknown local runtimes, projectors and physical-batch budgets refuse before transport. A model string or provider badge cannot establish capability. OpenRouter, TypeSafe, Ollama, MLX and unnamed routes refuse images while text remains supported. Direct model override keeps endpoint/key/API type and rechecks the literal model. Splits partition complete questions; every child and retry carries every attachment.

CLI repeatable --image forms one comparison input with optional stdin text. It cannot mix with --input, media/unit controls, pointers or record framing. --input paths --unit file --media image reads separate located images in existing enumeration order. Image locations omit all text line ranges. Scalar attachment failure sends nothing; later reader failure retains earlier completed rows. Seven text-only functions return `FUNCTION accepts text only; images are unsupported`, CLI exit2, before opening inputs or sending.
