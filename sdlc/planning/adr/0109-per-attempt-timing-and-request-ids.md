# ADR 0109: Scoped live attempt observations

- Status: **accepted**, 2026-09-29. Fresh High design/API/secrecy review accepted `7b7cc5f8ac39bce7cb42900391859599a66945ef`; the queue owner approves the bounded implementation within Ian's pre-release API outcome. Runtime implementation and remaining issue criteria are still open.
- Opens: the in-memory part of [backend time and request IDs](../../issues/2026-09-23-record-the-backends-own-time-for-each-call.md). Implementation route: [ticket 0302](../../tickets/0302-per-attempt-timing-and-request-ids.md).

## Decision

Keep `Facts.seconds` as elapsed wall time for the whole public call and `thinkthen.run/1.seconds` as elapsed wall time for the command. Offer an **opt-in, in-memory observation of each live HTTP attempt**. One public Rust Call has its own scope; one CLI command has a separate run scope. Each scope starts its ordinal at 1. Allocate the ordinal at `engine/http.rs::post_marked_with_retry` after the final stop, reservation and usage mark, beside `cancel.sent()` and before `send`. Ordinary requests, retries and split children share that scope. The ordinal records the engine's send-mark order, not socket arrival or completion order. Identical uncached bodies and retries can have the same recording digest yet different ordinals. No durable or process-global attempt ID is claimed.

One observation has `ordinal` (positive `u64`), `request_sha256` (the existing prepared body digest), `wall_ms` (nonnegative integer), `outcome` (`ok`, `status`, or `transport`), optional `status` (`u16` HTTP response status for both 2xx and non-2xx), optional `server_ms`, and optional `request_id`. Measure `wall_ms` using a monotone clock from immediately before the HTTP send through bounded response-body read or transport error, rounded up to whole milliseconds so a completed short exchange is not misreported as zero. It excludes queueing, width/backoff waits, response decoding, caller scheduling and final call completion. A successful HTTP status can precede a logical answer failure; `outcome=ok` describes the HTTP attempt alone. Durations of overlapping attempts must not be summed and called call latency, command time or network time. `server_ms` is a backend-reported interval, not proven model-only time; its difference from `wall_ms` is not calibrated network latency.

For the currently compiled System One adapter, read only response `x-envoy-upstream-service-time` and `x-typesafe-request-id`, on success and status-error responses before body consumption. Inspect `response.headers().get_all(name)` for each allowlisted name: **exactly one** value permits parsing; zero or two or more values omit that optional field, regardless of whether one value is valid. Do not inherit `get`'s first-value behavior. The time is ASCII decimal digits only, checked as `u64` milliseconds, including zero; whitespace, signs, fractions and overflow mean absent. The ID is 1–128 ASCII bytes from `[A-Za-z0-9._-]`; empty, longer, non-ASCII or other characters mean absent. Missing, duplicated or malformed optional headers never fail a judgment. A transport error has wall time but no response status, server time or ID. Do not retain a header map, address, request body, response body or key in the observation.

At the boundary that makes a request ID public, omit it if it equals or contains the nonempty configured key, or if it appears verbatim in the request URL or body; compare without retaining those inputs. A syntactically valid ID is not automatically safe: a server may echo a secret. `Debug` for the observation withholds the ID. Test both a fixed forbidden-header sentinel and an allowlisted header containing the active **test** key; neither may appear in result, diagnostic, recording or `Debug`. No real key is used. Other response headers are never copied, including a printable one with the sentinel. A backend without either named header leaves the optional members absent. Adding another adapter requires an explicit allowlist mapping and proof, not a generic header reader.

Rust exposes `CallOptions::observe_attempt(&callback)` as an optional separate callback receiving an owned, small `AttemptObservation`; no event list enters `Facts` or `Call`. Deliver it on the caller thread using the existing bounded worker handoff and join-before-unwind behavior of `observe`, including terminal attempts. Do not call a host callback on a worker or change `RecordObservation`'s exhaustive variants. Events may be delivered in completion order; consumers sort by `ordinal` for start order. Callback data is a snapshot owned by the receiver. No observer means no retained list; a lazy stream retains only its existing bounded in-flight work. If callback panic stops the call, workers join before the panic resumes. Cache and replay emit zero **current live** observations and never resurrect historical header data.

The first CLI slice supports `--details` on **decide, choose, filter, rank, score and tag only**. `cli/judge.rs` sends all six through `asking::run` and `asking/row.rs::row_of`, including the batched record path. Add optional `meta.attempts` to each printed detailed result, sorted by ordinal, for its live requests. It is absent for cache/replay and when no attempt belongs to the row. A packed attempt can appear in multiple rows with the same ordinal; it is one send. In `asking/batched.rs::split_answered`, retain a live refused parent's event locally when a 413 or token-limit response causes a split. Copy that parent event into **every printed child row** represented by the split, before that row's own child event. For a parent ordinal 1 and children 2 and 3, left rows show `[1,2]` and right rows `[1,3]`; sort and deduplicate by ordinal within each row, and count distinct ordinals only once per run. Keep the parent only through the bounded split assembly and row serialization; release it afterward. A replayed refused parent has no current live event. Existing answer, cache, recording and `requests_sent` sharing rules stay unchanged.

`find` (`cli/find.rs`), `recognize` (`cli/recognize.rs`), `relate` (`cli/relate/result.rs`) and `annotate` (`cli/annotate/aggregation.rs`, which uses `AnnotateMeta` rather than `Meta`) have separate output pipelines and receive no CLI attempt member in this slice. Preserve one result per row and the settled stdout/stderr channels; `--facts` remains one terminal `thinkthen.run/1` line without an unbounded attempt array. Filtered-out rows and terminal failures with no printed row have no CLI attempt-detail result in this slice; existing typed errors and facts remain. The original issue stays open for these pipelines and a separately justified failed-run presentation, rather than treating `--details` as a complete run trace.

C's frozen typed symbols and owned facts JSON remain unchanged. The direct C JSON door gains an opt-in top-level `"attempts":true` request member for any of its ten verbs. Its existing `libraries/c/src/call.rs::answer` passes `CallOptions` through every route, including `door::recognize` and `door::relate`; the opt-in edge supplies the Rust attempt callback and collects owned events only until this one call returns. A successful response adds an outer `"attempts":[...]` alongside unchanged `value` and `facts`, including an empty list for no live send. This is distinct from the existing `details:true` answer-value request. No `attempts` member in default responses, no new C ABI symbol and no second native operation. On a failed C JSON call, the existing NULL/error/facts route remains and has no attempt array; the Rust callback is the first complete failure witness. The direct C consumer proof is `libraries/c/tests/c/driver.c` through `libraries/c/tests/door/batching.rs`, using `thinkthen_call` and freeing its returned string. It proves that direct JSON contract only, not a typed wrapper's attempt support.

`meta.attempts` and the C outer attempt member are opt-in schema additions, not fields of the closed `facts` definition. Detailed result `meta` is open in the current schema, whereas C `callSuccess` is closed and must name its new member explicitly. Normal result/facts bytes remain unchanged. Objective-C's existing `libraries/objective-c/Sources/TTJSON.c::tt_json_call_value` requires **exactly two outer members**, so it rejects the opted-in three-member success; no Objective-C support is claimed now. Ada and COBOL close **facts** members, a different boundary, and the new attempt member does not enter facts. An updated schema does not update any installed validator. Defer matching typed-wrapper exposure and copied-consumer migration to separately claimed work coordinated with ADR 0108's priced-facts rollout; do not re-migrate all wrappers merely for timing. The first consumer slice is Rust, six ordinary CLI verbs and direct C JSON only. This conditional pre-0.1 opt-in reader break must be documented, not called universally additive.

Recording files keep body-only bytes and their current digest. No sidecar or historical timing on replay. `command_ms` from the old issue is deferred: overlapping intervals cannot be subtracted as a simple sum, and the remainder would not be CPU time. A sidecar needs a separate privacy, permissions, retention and durability decision. This ADR does not close those original criteria.
