# 0082: One type contract for every surface

Status: accepted 2026-09-27 by the Codex queue owner after fresh read-only review at `target/codex-reviews/0204-design/REVIEW.md`. The type-contract issue and Batch J are the authority. Ian can overturn any ruling below.

## Decision

ADR 0112 amends this decision: a unit test generates `specification/result.schema.json` from the Rust types, and `doorRequest` moved to the question-file schema.

Publish `specification/types.md` as the cross-surface type contract and a hand-written Draft 2020-12 `specification/result.schema.json` for result values, detailed results, failure markers, and the C JSON door request. Keep `specification/question-file.schema.json`, landed by ticket 0069, as the input grammar. The result schema names separate definitions for each bare verb, record wrapper, detailed result, usage result, and door request; one broad root union would accept the wrong kind for a verb. The C door continues to take and return JSON, without new ABI structs or description arrays. The schema captures structure; production parsers retain semantic checks such as thresholds, known labels, offsets, and request limits. A release may add fields to `thinkthen.result/1`; readers ignore unknown fields under the existing compatibility rule.

Use a small shared corpus under `specification/fixtures/types/` with explicit request, expected answer, and valid or invalid structural verdict. Its self-test checks the schema with the existing test-only `jsonschema` dependency and calls the real C JSON door against the offline conformance backend for selected valid and invalid requests. It compares expected values and error kinds independently of the schema. The test rung invokes the self-test. Each later port integration runs that same corpus through its public binding and its own conformance cases. J1 changes the test-rung hook as well as specification files; a corpus with no gate hook is not parity proof.

Reuse shared conformance case `41-offsets-past-an-accent-and-an-emoji`, whose text is `Le café 😀 Maria Chen arrived.` and whose scalar-value span for `Maria Chen` is `[10,20)`. Do not copy its captured exchanges. Rust, C, and Python count code points, TypeScript counts UTF-16 units (`[11,21)`), and R reports one-based inclusive positions (`11..20`). Keep the existing `start`, `end`, and `length` names. Every entity API page states its unit, and each port's conformance run checks this one case.

## Mappings and follow-on work

The contract says `null` means unresolved and never failure. A failed annotate member is a separate `{"failed":{"kind","cause"}}` marker or a native failure variant. Score remains numeric. Tag's empty list is a successful answer. The six call-error kinds are `usage`, `backend`, `deadline`, `local`, `cancelled`, and `defect`; the C codes 1 through 6 stay at the ABI edge. Retryability and a message accompany a call error. Descriptions affect the question sent, so a surface that accepts strings also accepts structured `{what, not_for, examples}` descriptions and does not discard them. Ordered label sets preserve their order.

J2 stabilizes pandas, Polars, and Rust Polars frame columns by question kind. One companion `failed` column holds a map from question name to failure marker, or null; a question named `failed` is refused. J3 gives TypeScript ordered label maps and structured descriptions. J4 gives Rust `choices!` variant descriptions; its `Choice` and `Annotated::Failed` already exist. J5 keeps Python's core on the standard library, adds `Enum` and `Literal` forms and sharper stubs, and offers Pydantic only through `thinkthen[pydantic]`, imported when used. An enum member's docstring or `description` is the default; an explicit map overrides that label alone, and an unknown label is a usage error. The optional Pydantic layer accepts model or `Annotated[..., Field(description=...)]` metadata and offers `row_model(question_set)` with typed annotate fields and `Failed`.

J6 verifies Ruby and R maps, structured descriptions, failure markers, and named error kinds before fixing confirmed gaps. J7 writes one plain-SQL answer-column constraint recipe per database: PostgreSQL `CHECK` or `DOMAIN`, DuckDB `ENUM` cast, SQLite `CHECK`. A DuckDB function returning `ENUM` is a separate decision after ticket 0201; this ADR adds none. J8 gates each port's integration on named outcomes and six error kinds, distinct null and failure, descriptions in at least map form, and the shared corpus. Enum-derived sets may follow in a port's next ticket. Use the language's ordered idiom described in the issue: Python list, dict, `Enum`, or `Literal`; TypeScript array, ordered map, or readonly tuple; Ruby array or hash; R character or named character vector; Go ordered `Label` slice; Java/Kotlin list, linked map, or annotated enum; Scala `LabelSet`; C# array, dictionary, or annotated enum; Swift array, `KeyValuePairs`, or described `CaseIterable`; PHP list, ordered array, or backed enum; Zig label slice or enum table; Ada label set; COBOL label table with a count. A plain Go map is unordered and is refused as an ordered label set.

These J2–J8 mappings are decisions for their own tickets, not implementation in J1. Existing tickets remain unchanged. The issue's recommendation can be overturned by Ian; a change to the result wire contract needs a new reviewed ADR rather than a silent schema edit.

## Evidence and cost

The issue was corrected against main `7a1ba6cc`. Current main already has the 0069 question schema and corpus, the JSON C ABI with descriptions, Rust `Choice` and `Annotated`, TypeScript output unions, and Python's `py.typed` stub. The missing shared answer/request contract and per-surface input gaps are recorded in `sdlc/issues/closed/2026-09-27-one-type-contract-for-every-surface.md`. Ticket 0204 delivers the contract first. A hand-written schema and its corpus cost review and upkeep when the result evolves; they avoid a new generator and runtime dependency. The test-only checker reuses `jsonschema`, already checked by the install rung. The existing question schema has 390 lines, its corpus 468, and its self-test 55. Keep the new schema under the repository's 500-nonblank-line file limit and the parity corpus focused on distinct shapes and failure boundaries.
