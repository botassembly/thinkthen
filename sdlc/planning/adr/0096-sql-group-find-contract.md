# ADR 0096: One ordered SQL set enters one find call

- Status: Technically accepted at `e648e35f` by independent review; proposed outward SQL spelling awaits Ian's choice. No SQL function or Rust change is built.
- Context: [issue: SQL find is missing](../../issues/2026-09-27-sql-find-is-missing-from-three-databases.md), [ticket 0224](../../tickets/0224-sql-group-find.md), and settled [find](../../../specification/find.md).

## Proposed decision

`thinkthen_find` is one volatile, direct SQL scalar over an already ordered collection. It invokes the existing public `Engine::find_with` once; it never judges each unit separately. The question is nonblank plain text, passed to `Question::find`; a true `none` argument calls `offering_none`. No `@file`, question-file JSON, threshold, per-question model or profile is invented: the current public find constructors do not offer those paths. `@` in the question is literal text. Engine environment and each host's existing model, profile, cache, replay, request-total and deadline settings retain their authority. The command's `--none` behavior, generated `u001`…`u255` identities and selection rule remain with the public find core.

| Host | Proposed call | Ordered input and native result |
| --- | --- | --- |
| SQLite 3.50.0 | `thinkthen_find(question TEXT, units_json TEXT[, none INTEGER[, deadline_ms INTEGER]])` | A JSON array of strings; `none` defaults to `0` and otherwise is exactly `0` or `1`. Return one JSON text object. A caller can form the array with `json_group_array(unit ORDER BY ordinal)` on the pinned host. The fourth argument uses the existing scalar deadline grammar. |
| PostgreSQL 16.15 | `thinkthen_find(question text, units text[][, none boolean]) RETURNS jsonb` | `array_agg(unit ORDER BY ordinal)` supplies positions, including duplicates. `none` defaults to false. No new per-call deadline: the backend's `thinkthen.deadline_ms` and statement cancellation apply. Mark the function `PARALLEL RESTRICTED`. |
| DuckDB v1.5.5 | `thinkthen_find(question VARCHAR, units VARCHAR[][, none BOOLEAN[, deadline_ms BIGINT]]) RETURNS STRUCT` | `list(unit ORDER BY ordinal)` supplies positions, including duplicates. `none` defaults to false. Return the typed struct below. The fourth argument uses the existing scalar deadline grammar and `StatementOwner::Remaining` bounds it. |

The object/struct has fields `index` (zero-based BIGINT or null), `value` (the selected original string or null), `probability` (DOUBLE), and `candidates` (ordered list of `{index, probability}` pairs; the offered `none` candidate is last with a null index). PostgreSQL uses `jsonb`, SQLite JSON text, and DuckDB `STRUCT(index BIGINT, value VARCHAR, probability DOUBLE, candidates LIST<STRUCT(index BIGINT, probability DOUBLE)>)`. When `none` wins or ties for the highest probability, `index` and `value` are null and `probability` is the `none` candidate's probability. With no `none` offer, equal leaders select the first input index. The non-null result distinguishes model-selected none from a SQL NULL for no input. This is the proposed public shape; Ian may overturn it after technical review.

A SQL NULL in any top-level argument returns SQL NULL before a send. A valid empty collection also returns SQL NULL with zero sends, following the command's successful empty input. One unit, an excess over 255 (254 with `none`), a NULL element, a non-string JSON member, malformed JSON, an invalid SQLite `none`, blank question, or more than 16 MiB of combined UTF-8 unit text is Usage before a send. PostgreSQL and DuckDB reject wrong SQL types at binding; SQLite rejects their dynamic types at the function edge. Keep duplicates as separate units and candidates. Do not sort, deduplicate, or drop a NULL member. Preserve the host's established error-kind mapping for backend, local, cancellation, deadline and defect; a failed find never returns a partial winner.

A small private `Indexed { position, text }` implementing public `Evidence` passes each original unit to `Engine::find_with`. `Found::selected()` then returns its original position and value, and `Found::candidates()` supplies probabilities in input order. This avoids a new public Rust accessor, a second request, or copying the private find planner. A binding converts only the result into its native SQL value. The current public `Question::from_json` accepts decide/choose/tag/score, **not** find, so the shared conformance corpus's `question.find`, `question.none` and `question.units` fields are test inputs, not a serialized SQL question file.

The SQL result contains no request body or digest. Installed proof for shared cases 18/19 therefore uses the existing shared loopback backend's bounded `capture` command on `/case/ID/capture/v1`, after extending its opt-in selector to those cases. SQLite's current test backend already reads capture; PostgreSQL's installed conformance step needs a small reader beside `bcount()`; DuckDB's installed conformance step needs a small `Backend.capture()` method. Each host compares the observed complete body with the pinned corpus request and derives its observed digest from that body and the actual served URL, then compares with the expected digest independently computed from corpus bytes and the same URL. One listener send and native result fields are checked separately. No SQL diagnostic, product test hook or second HTTP harness is introduced. An expired SQLite connection budget uses the accepted `thinkthen_budget_ms(0)` no-send case; refused `thinkthen_max_requests_total(0)` is a separate request-total setting.

## Alternatives and authority

A custom row aggregate could accept `unit ORDER BY ordinal`, but SQLite's existing `warm` aggregate, PostgreSQL's text transition state and DuckDB's combine callback do not establish a stable original order or distinguish a duplicate without new index state. Empty groups and parallel combine add separate behavior. The pinned hosts already have ordered collection constructors; DuckDB v1.5.5's installed CLI returned `[first, second, second]` for `list(x ORDER BY i)`. PostgreSQL's repo examples already use `array_agg(body ORDER BY id)`. SQLite's pinned 3.50.0 amalgamation contains `json_group_array`; its ordered form needs an installed-host assertion before a runtime claim. A scalar `ORDER BY probability LIMIT 1` sends independent requests and cannot offer none over one shared set.

This design creates three new outward SQL signatures and one common result meaning. The independent reviewer accepted the technical design and installed capture proof at `e648e35f`; Ian may still approve or overturn the outward names and result types. Host syntax, NULL/empty/duplicate/tie representation, cancellation, settings and every platform still require implementation proof. Ticket 0222's proposed public recoverable-details method and the unbuilt B12a shared split adapter are separate; grouped find uses today's public `Engine::find_with` and has no dependency on them.
