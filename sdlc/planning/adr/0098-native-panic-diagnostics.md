# ADR 0098: Scope caught native panic diagnostics to the owning binding

- Status: Proposed for fresh independent High design review. No runtime source is accepted or built.
- Context: [ticket 0226](../../tickets/0226-native-panic-diagnostics.md), the [panic-diagnostics issue](../../issues/2026-09-27-panic-diagnostics-can-copy-payloads-across-host-boundaries.md), and accepted ADR 0081's engine and Linux C++ bridge scopes.

## Proposed decision

For the remaining C, SQLite and older DuckDB C API routes, install one private delegating Rust panic hook per binding before owned work can panic. It calls the previous hook for unrelated threads and suppresses that hook only while thread-local binding depth is nonzero. An RAII depth guard restores the prior value through nesting, return and unwind. Scope encloses `catch_unwind`, fixed Defect mapping and disposal of the caught payload. Workers enter their own scope; caller thread-local state is not inherited. The hook's code must remain resident for the process lifetime. No global hook is taken or set for each call, and no public fault switch or shared framework is introduced.

C `failures::guard`, SQLite `lib::guard`, and old DuckDB `errors::guarded` stop extracting a string from the caught payload. Each returns its existing Defect classification and a fixed safe message. C's nested `built` catch already has fixed text and remains inside the outer scope. SQLite's `worker::spawn` already calls its shared guard on the worker thread. Its exported `sqlite3_thinkthen_init` also needs to invoke that **same** guard around `Connection::extension_init2`: pinned rusqlite 0.40.2 does not catch there. Only an unexpected load panic maps to fixed safe `SQLITE_ERROR`; ordinary load errors retain their existing mapping. The old DuckDB `worker::run_typed` must use `errors::guarded` around its work on that thread, then convert the fixed caught defect to `RowError` without changing ordinary engine errors. This preserves its source check's one-catch rule. No edit to the accepted root engine hook or Linux C++ bridge hook is proposed.

The hook chain is cooperative, not exclusive. ADR 0081's root and bridge hooks may nest with these local hooks; a marked binding-owned panic must not leak to a previous hook, while an unrelated host thread still reaches it. A host that replaces the global hook after installation or races another installation can bypass this wrapper. Rust gives this binding no ownership over later host hook operations. The design makes no absolute claim under that condition. Current C calls accept pointers rather than Rust callbacks, SQLite's interrupt predicate is a C API function, and the old DuckDB SIGINT predicate is atomic. If implementation finds a Rust host callback inside a marked region, it must leave the binding depth for that callback and retain its own panic policy, as ADR 0081 does for direct engine host checks. C++ exceptions remain on the C++ side.

A hook must not point into an unloaded library. SQLite already pins its loadable extension through `ffi.rs::pin`, but it does so after registration; make the pin fallible and move it before installing the hook, including the failure path. The C release has both a static archive, resident with its host, and a shared library that a host may `dlclose`. The dynamic library needs a retained self-reference before hook installation; a small platform loader call through the already locked `libc` crate is the proposed mechanism, with a reviewed direct C dependency and Linux/macOS proof. Stop if safe self-retain cannot be established. Pinned DuckDB v1.5.5 `extension_load.cpp` uses `dlopen` for the old C API package and has no `dlclose` call in its extension source tree; verify that target host and archive instead of inferring lifetime from Linux C++ tests. This intentional process residency costs a small mapped library lifetime and is required by a persistent global hook.

A private child-process synthetic-marker case for each affected binding checks the exact fixed non-retryable Defect, absence of the marker from returned error and both streams, later-call recovery, and previous-hook delivery for an unrelated host thread. SQLite and old DuckDB each add their distinct detached-worker entry in that same selected child. C dynamic release and SQLite failed-load witnesses check hook residency. Replace stale unit tests that expected payload text. Installed C/SQLite smoke and actual old DuckDB target-package checks remain separate. Source inspection or a Linux C++ package run cannot close an old C API route.

## Alternatives and limits

Changing only the caught error string leaves the default hook's earlier stderr print. Taking and restoring the process hook around each call can erase a host or another extension's hook and races concurrent calls. A public test-only panic switch would expose a new product path merely for proof. The proposed private scope follows the reviewed ADR 0081 pattern with one bounded child per binding. It does not settle the separately observed R payload copy or the other binding hook paths; those need their own routing and evidence before any repository-wide secrecy claim.
