# ADR 0102: Publish an audit-tuned candidate at a new path

- Status: Accepted by the coordinator after fresh Medium design review of `4061dabd3b8e54f4f965c30c76c180cb4731f463`. Ian can overturn this additive choice.

## Decision

`thinkthen audit RESULTS KEY --write QUESTIONS --write-to OUTPUT` grades the saved lines against `QUESTIONS` exactly as current `--write` does, then creates a reusable tuned question file or question set at `OUTPUT`. It never writes `QUESTIONS`. `--write-to` requires `--write`; both paths must name files rather than `-`. A run that suggests no new bar still creates an exact copy of the validated source. The existing `--write QUESTIONS` form remains in-place, still writes only when bytes change, and keeps its current byte splice, digest check, report, error precedence and crash semantics. No default changes.

The new final destination must be absent. An existing file including an empty one, directory, final symlink including dangling, hard-link alias or the source itself is refused rather than overwritten. After all input, grading and digest checks pass, create a regular temporary file in the output's parent directory, write and close its full contents, then publish it at the final name with an atomic no-replace hard link. Remove the temporary name after either outcome. A competing creator of the final name wins or loses at that link, with no partial final file. An unsupported hard-link filesystem fails safely; there is no fallback to a visible partial write. Source bytes remain unchanged on every new-destination path. This is a narrow exception to the settled page's rule against a temporary file for **in-place** `--write`; it does not retrofit atomic replacement onto that old form.

An output-path failure before publication returns a fixed exit-5 diagnostic without printing a path or question text. If temporary cleanup also fails, say so in that error. If publication succeeds but temporary cleanup fails, keep success because the complete output exists and append a fixed warning about the leftover temporary name. Never report a published candidate as absent. The new form retains ordinary audit standard output and the same per-bar standard-error lines as `--write`, aside from that cleanup warning. `--write-to` without `--write`, or `--write-to -`, exits 2 before reading inputs. The existing saved-question digest refusal remains exit 2 before publication.

The guarantee is complete atomic visibility and no replacement at the final name under ordinary filesystem behavior. It is not a promise of fsync or power-loss durability, nor a defense against a hostile process replacing the parent directory or staged temporary pathname. The command still reads no API key, configuration or cache, starts no request and sends nothing. The temporary file is an internal, normally removed artifact of the explicitly named output; it is not a new user-selectable storage tier.
