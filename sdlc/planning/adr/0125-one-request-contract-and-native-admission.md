# ADR 0125: One versioned request and one native admission path

Accepted by the queue owner after fresh design review for ticket 0491 on 2026-10-08. Implementation follows per-record context ticket 0489. Ian can overturn the version marker, tags, optional-field rules and compatibility boundary below.

## Authority and evidence

The PM ruling of 2026-10-08 in `repos/agents/inbox/thinkthen/2026-10-08-pm-thinkthen-binding-architecture-one-request-contract-generated-header-and-types.md`, asks 2, 5 and 6, authorizes one Rust request contract and every language in 0.2. Ticket 0491 includes CLI construction and admission before input reads. Tickets 0478 and 0479 own the recognition controls. ADRs 0112, 0119, 0120 and 0121 retain schema generation, one configured route, result compatibility and image admission.

At main `900a8a660`, `libraries/c/src/call.rs::split` parses a `BTreeMap<String, Box<RawValue>>`, separates envelope members from the existing question grammar and dispatches ten functions. MCP independently defines closed `Arguments`, `Options` and descriptors in `crates/thinkthen/src/mcp/{admission,inputs}.rs`. CLI checks combinations in `cli/args/common.rs`; `cli/intake/images.rs` prepares readers and loads attachments later. `public/input_files.rs::read_inputs` enumerates paths before the iterator opens content. Request admission must precede enumeration as well as content access.

## Decision

Define `public::Request` at the input edge. Its wire marker is `"schema":"thinkthen.request/1"`. Its closed `call` member is a Rust enum tagged by `function` with exactly decide, choose, tag, score, filter, rank, find, annotate, recognize and relate variants. Each variant carries its typed question selector, typed input and applicable options. Reject unknown version markers, functions and members. Reject duplicate members in canonical request objects, including nested control objects. Authored JSON evidence, descriptions and declared context objects keep their existing data grammar and authored order; closing a request object never closes caller data.

For example:

```json
{"schema":"thinkthen.request/1","call":{"function":"decide","question":{"kind":"text","text":"Does the writer request a refund?"},"input":{"kind":"text","text":"Please refund my order."},"options":{}}}
```

Question selection is a closed enum tagged by `kind`: `text`, `definition`, `file`, `name` or `reference`. The definition variant carries the existing authored question or question-set grammar through typed edge values. File, name and reference remain explicit selectors. Literal text beginning with @ stays literal. Native callers can construct a definition from existing typed questions through direct conversion. They never serialize a question to make a Request.

Input selection uses a closed enum tagged by `kind`: `text`, `json`, `records`, `units`, `entities`, `source` or `feed`. A records entry is a closed item descriptor containing one original text or JSON value, optional context, optional ordered choose options and optional images. A source holds ordered explicit paths and typed reader settings. A feed names runtime input supplied by the caller; it carries framing and projection settings but no handle or iterator in JSON. CLI stdin and bounded native streams use this variant. The execution environment supplies its reader or iterator after admission, so native streams need no collection or JSON conversion. A JSON caller that supplies no required feed receives a usage error before execution.

Image attachments are ordered closed descriptors tagged by `kind`: `file` with a path and optional declared JPEG/PNG media, or `bytes` with media and original bytes. JSON represents bytes as canonical base64; native callers construct the bytes variant directly. Attachments augment one text/JSON item or form an images-only item with absent original text. Whole-file source images remain separate items. Preserve duplicates, caller order, byte limits, provenance and the existing decide/choose/score restriction. Header admission rejects bad media, empty paths, invalid counts, incompatible framing and unsupported functions before opening files. Decode and validate bytes afterward, before sends; route admission uses the configured endpoint, API type and explicit model under ADR 0121.

Options use typed existing values for threshold, model, reader settings, projections, batch, deadline and request budget. Keep caller controls such as attempts, find none, rank top and filter files_only in their applicable variants. Per-item choose options replace the entire ordered shortlist and retain descriptions. Explicit per-item context/options conflict with projection pointers as today. Keys, environment lookup, output destinations, callbacks and cancellation handles belong to the execution environment. They do not enter serialized Request or cache identity. Admit direct model overrides against the engine's one configured route. Add no routing policy.

Absence means use the existing default or fallback. Present null is rejected for selectors, paths, media, numeric controls, per-item context and option lists. Present empty context text suppresses shared fallback. Authored true/false readings and descriptions retain present null as data, distinct from absence. Raw JSON evidence may itself be null when the existing record grammar admits it. Use an explicit presence decoder where serde's ordinary `Option<T>` would erase that distinction. Defaults and nullability appear in the generated deserialization schema and in the shared cases.

Expose one pure `Request::admit` operation producing an admitted invocation. It validates typed selectors, function/input compatibility, controls and all available inline question declarations without opening files or constructing an engine. For file/name/reference questions, header admission precedes the question read; definition admission follows loading and precedes evidence reads. Check every supplied descriptor before opening the first input. Then native execution resolves sources and uses existing typed engine methods, scheduling and results. Runtime item validation still occurs as bounded feeds advance and retains existing partial-result behavior. Preserve every valid CLI spelling, scalar output, exit code and file order. CLI parses flags directly into Request and calls shared admission; it performs no JSON round trip and keeps no second semantic validator. Transport syntax and output rendering stay at their respective edges.

The edge type owns serde decoding and schema derives. Convert admitted values directly into existing core types. Core imports no Request, CLI, MCP, filesystem reader, decoder or runtime handle. Existing core serde use remains governed by its current purity and dynamic-JSON bans. Request debug output withholds evidence, descriptions, context and paths where they contain caller data.

## Frozen C compatibility boundary

`thinkthen_call` selects the canonical decoder only when a request carries the new schema marker. Its unversioned request path remains the accepted 0.1 grammar, including later accepted additive controls. Keep the legacy question-file parser and a small legacy envelope translator. Translate accepted legacy values into the same admitted native invocation. The new request schema describes only versioned Request. Keep legacy `doorRequest` in the question-file schema until a separately authorized compatibility change.

Do not deserialize the unversioned envelope with canonical `deny_unknown_fields`. The current BTreeMap decoder keeps the last value of a repeated object key; preserve that behavior at the legacy boundary. The legacy envelope excludes recognize from the functions accepting records. Preserve its usage refusal and diagnostic `recognize takes no records key` when records accompanies recognize, including when evidence is also present. Preserve usage-only requests outside the ten-function Request, details true/false, attempts present only as true, call restrictions and each accepted question grammar. Invalid legacy requests retain their established error kind and diagnostics. Counted no-send safety checks still apply to both paths.

## Recognition extension and schema generation

0478 and 0479 add typed fields to the recognize variant after their specifications settle stage names, precedence, mode and proposal output. Use a typed stage-context object and a typed recognition mode; reserve no arbitrary extension map. Until those tickets define the fields, unknown recognition controls refuse. Whole-call defaults preserve existing request/cache identity. Later per-stage context changes only affected stages. Identical boundary questions may reuse saved question answers across modes; resolved mode separates complete answer identity and typed value, even when whole recognition sends no later questions. A boundary result cannot replay as a complete whole result. This ADR does not settle stage precedence or invent classifications for skipped stages.

Derive `Serialize`, `Deserialize` and test-only `schemars::JsonSchema` from Request and its edge members. Generate Draft 2020-12 `specification/request.schema.json` using deserialization settings. Reuse pinned `schemars =1.2.2` with raw_value, already a dev dependency; add no runtime schema validator, generator binary or dependency. Follow `src/schema_tests.rs`: compare committed bytes, permit an explicit rewrite and fail after rewriting until a comparison passes. Use typed conversion and focused schema overrides for existing custom representations; verify overrides against actual decoding cases. Run generation and gates offline with the lock unchanged. A missing cached dependency is a prerequisite failure, never permission to fetch.

Keep results under their existing contracts. Result readers ignore unknown members under ADR 0112; request closure does not authorize closing result objects. Preserve absent facts, unresolved null and failure markers, and coordinate 0468 usage-write facts through the result owner.

## Acceptance evidence

Use shared cases for all ten functions through named native methods, canonical Request, frozen C requests and valid CLI commands. Assert answers, facts, exact outgoing bodies and identity where defaults must remain unchanged. Pin absence, explicit null, empty context, ordered options/images, source/attachment conflicts and unknown input members. Include the legacy repeated-key example above and the established refusal for recognize with records. Independently check generated schema acceptance against real canonical decoding; semantic validation remains in admission. For invalid selectors/media/controls, count file-reader and enumeration access and loopback requests and assert all are zero. Keep tests for loaded-question admission separately because inspecting a saved definition necessarily reads that definition. Do not treat a plan output as proof of no sends.
