# ADR 0101: Owned facts for typed C calls

- Status: Proposed for fresh High design review. No API or legacy exception is approved by this draft.
- Date: 2026-09-28

## Context and constraint

Ian's original outcome says library results carry `facts` on every call, with no setting and no second call. ADR 0089 implements immutable Rust `Call<T>` facts and final `Batch::facts()`. Ticket 0230 puts `value` and `facts` in each successful C JSON-door reply and keeps started-failure facts in `thinkthen_error_facts_json`. The four typed C families, each with plain and `_opts` spelling, still discard success facts. The 0.1 C ABI freezes the two-field `thinkthen_answer`, exported argument types and six error codes. Existing C, Zig, Swift and Objective-C consumers call typed symbols, so changing those symbols in place would break real callers.

## Alternatives and proposed interpretation

| Route | Benefit | Limit |
| --- | --- | --- |
| Add eight `*_with_facts` symbols with caller-owned JSON facts outputs | The judgment and final facts come back from one asking call. Existing binaries and header consumers keep the old exports. No new result struct crosses the ABI. | The eight old names remain bare. This needs an explicit legacy compatibility exception to the literal “every call” wording; new examples should prefer the new names. |
| Add a borrowed `thinkthen_last_success_facts_json` accessor | Minimal new asking signatures, and no second provider request. | It requires another C getter, mutable engine/thread “last result” state, stale-value clearing after failures and a new borrowed lifetime promise. It does not make the result own facts. |
| Route typed callers through the existing `thinkthen_call` JSON door | Already returns call-owned facts in one call; flexible callers can use it now. | Requires input JSON construction, response parsing and consumer migration. It is not a drop-in typed hot path or a fix for existing typed symbols. |
| Grow `thinkthen_answer` or append parameters to the old exports | Direct results on the old names. | Breaks compiled callers and the frozen struct/signature ABI. Declined. |

**Recommend for review:** add the owned-output symbols and state the legacy exception explicitly. The exception is limited to the eight pre-0.1 typed exports retained for binary compatibility; it is not a finding that the original every-call criterion is fully met. An issue owner must accept the compatibility interpretation before closing the typed C portion. If the reviewer rejects it, keep the issue open and return the API trade-off; do not silently use a process total or borrowed last-result accessor as equivalent.

## Proposed public contract

Add `thinkthen_decide_with_facts`, `thinkthen_decide_with_facts_opts`, `thinkthen_decide_many_with_facts`, `thinkthen_decide_many_with_facts_opts`, `thinkthen_recognize_with_facts`, `thinkthen_recognize_with_facts_opts`, `thinkthen_relate_with_facts`, and `thinkthen_relate_with_facts_opts`. Each keeps its existing counterpart's arguments and result outputs, followed by `char **facts_json, size_t *facts_len`. A plain spelling delegates to its `_opts` twin with `THINKTHEN_NO_DEADLINE` and a null token. The new outputs are required even for an empty successful batch; its `facts.records` is zero and it sends nothing. The result and facts strings, where returned, are independent owned NUL-terminated allocations. Their byte lengths exclude the terminator. The caller frees every returned string exactly once with `thinkthen_free_string`. No borrowed pointer crosses a successful return.

`facts_json` is the same closed JSON object serialized by the existing `failures::facts_json`: required `records`, `requests_sent`, `cache_answers`, `seconds`, and optional `input_tokens`, `output_tokens`, `model`. It holds final call facts, not an answer-row sum or process usage. Tokens absent from a live reply remain absent from a mixed call's final facts. `decide_many` takes facts only after its Rust `Batch` exhausts or stops and joins; a successful call has all rows in input order. Request counts are actual starts, not logical answers. No price, request ID, server time, key or evidence enters facts.

Every output slot must be non-null before planning or sending. For `decide_many`, a null answer array is allowed only at count zero, as today. Exact equality of result/facts pointer slots is a Usage refusal before any send. Apart from those testable cases, the caller must supply live, properly aligned writable slots, a result array of `count` elements, and output storage disjoint from other outputs and input bytes. The library cannot safely discover arbitrary invalid or partially overlapping C pointer ranges. A null or invalid input keeps the current Usage and UTF-8 rules. On **any** nonzero return, including a post-reply publication defect, every caller output retains its original value and no result or facts string is transferred. Convert the result and facts to owned C strings and finish all other fallible work before publishing either output. The guarded commit writes only validated slots; a panic before commit drops temporary allocations and maps to the existing defect kind. No panic may unwind through the C ABI.

The six existing error codes, retryability, cancellation, deadline, same-thread error message and `thinkthen_error_facts_json` lifetime stay unchanged. A started failure freezes its facts only in that existing failure accessor; a pre-start Usage refusal has no facts. A complete successful result does not clear or overwrite another thread's last failure, and no new success slot is introduced. A failure after a complete reply but before output publication must attach that call's final facts to the recorded failure. Neither a partial `decide_many` array nor one of the two JSON output strings may escape. Existing plain typed names retain their bare outputs and behavior; all new documentation/examples after landing should recommend `*_with_facts` for typed work and name the old exports as compatibility forms. Existing compiled consumers are not silently migrated.

## Implementation and proof boundary

Reuse `door.rs`'s existing Rust calls, `Call::facts`, `Batch::facts` and `failures::facts_json`. Have a private shared typed path return value plus owned `Facts`; old FFI writers ignore the facts and new writers serialize them. `recognize` and `relate` already return tuples. Keep the unsafe exported pointer edge in an allowed `ffi.rs` basename; the current parent `libraries/c/src/ffi.rs` is 497 nonblank lines under the 500-line policy, so a coherent nested `src/ffi/typed_facts/ffi.rs` is expected. A shared publication helper converts and validates before the final non-fallible writes. Do not create eight independent schedulers or a second facts schema.

One installed-header C driver under the existing soname/ASan harness should cover all four plain/options pairs, exact listener requests with `batch 1` for the many-count case, returned JSON facts and owned frees, null/duplicate output slots with zero sends, unchanged sentinels on started and pre-start failures, two callers on one engine, and a missing-usage reply. Existing 0230 JSON-door, C plain/options parity, failure-slot, symbol/header and C/CLI byte proofs remain in force. New exported symbols require the exact header-symbol check and a rebuilt C archive on each claimed release target; a Linux installed proof does not qualify macOS or ARM64 packages. No broad matrix or paid call is part of this design.
