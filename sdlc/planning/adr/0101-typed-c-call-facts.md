# ADR 0101: Owned facts for typed C calls

- Status: Accepted by the coordinator after fresh High design review of `d97f27350a9487c3e63e2438629b051f9b6e861f`. Ian can overturn this routine compatible API choice before release.
- Date: 2026-09-28

## Context and constraint

Ian's original outcome says library results carry `facts` on every call, with no setting and no second call. ADR 0089 implements immutable Rust `Call<T>` facts and final `Batch::facts()`. Ticket 0230 puts `value` and `facts` in each successful C JSON-door reply and keeps started-failure facts in `thinkthen_error_facts_json`. The four typed C families, each with plain and `_opts` spelling, still discard success facts. The 0.1 C ABI freezes the two-field `thinkthen_answer`, exported argument types and six error codes. Existing C, Zig, Swift and Objective-C consumers call typed symbols, so changing those symbols in place would break real callers.

## Alternatives and decision

| Route | Benefit | Limit |
| --- | --- | --- |
| Add eight `*_with_facts` symbols with caller-owned JSON facts outputs | The judgment and final facts come back from one asking call. Existing binaries and header consumers keep the old exports. No new result struct crosses the ABI. | The eight old names remain bare. This needs an explicit legacy compatibility exception to the literal “every call” wording; new examples should prefer the new names. |
| Add a borrowed `thinkthen_last_success_facts_json` accessor | Minimal new asking signatures, and no second provider request. | It requires another C getter, mutable engine/thread “last result” state, stale-value clearing after failures and a new borrowed lifetime promise. It does not make the result own facts. |
| Route typed callers through the existing `thinkthen_call` JSON door | Already returns call-owned facts in one call; flexible callers can use it now. | Requires input JSON construction, response parsing and consumer migration. It is not a drop-in typed hot path or a fix for existing typed symbols. |
| Grow `thinkthen_answer` or append parameters to the old exports | Direct results on the old names. | Breaks compiled callers and the frozen struct/signature ABI. Declined. |

**Decision:** add the owned-output symbols and explicitly retain the old eight symbols as bare compatibility forms. The coordinator accepts that narrow legacy exception, as recorded below. It is not a claim that old calls satisfy the literal every-call criterion. The original broader issue retains its other unmatched criteria; a process total or borrowed last-result accessor is not an equivalent substitute.

## Public contract

Add `thinkthen_decide_with_facts`, `thinkthen_decide_with_facts_opts`, `thinkthen_decide_many_with_facts`, `thinkthen_decide_many_with_facts_opts`, `thinkthen_recognize_with_facts`, `thinkthen_recognize_with_facts_opts`, `thinkthen_relate_with_facts`, and `thinkthen_relate_with_facts_opts`. Each keeps its existing counterpart's arguments and result outputs, followed by `char **facts_json, size_t *facts_len`. A plain spelling delegates to its `_opts` twin with `THINKTHEN_NO_DEADLINE` and a null token. The new outputs are required even for an empty successful batch; its `facts.records` is zero and it sends nothing. The result and facts strings, where returned, are independent owned NUL-terminated allocations. Their byte lengths exclude the terminator. The caller frees every returned string exactly once with `thinkthen_free_string`. No borrowed pointer crosses a successful return.

`facts_json` is the same closed JSON object serialized by the existing `failures::facts_json`: required `records`, `requests_sent`, `cache_answers`, `seconds`, and optional `input_tokens`, `output_tokens`, `model`. It holds final call facts, not an answer-row sum or process usage. Tokens absent from a live reply remain absent from a mixed call's final facts. `decide_many` takes facts only after its Rust `Batch` exhausts or stops and joins; a successful call has all rows in input order. Request counts are actual starts, not logical answers. No price, request ID, server time, key or evidence enters facts.

Every required output slot must be non-null before planning or sending. For `decide_many`, a null answer array is allowed only at count zero, as today. Compare the addresses of **every pair** of non-null output slots, including `out`, `out_len`, `facts_json` and `facts_len` on the JSON-value families and each length slot against every other slot; an exact equal address is a Usage refusal before a send. A new bulk call first checks `count * sizeof(char *)`, `count * sizeof(size_t)` and `count * sizeof(thinkthen_answer)` with checked arithmetic against `PTRDIFF_MAX` / Rust `isize::MAX`, as applicable to its input pointer array, length array and output judgment array. It also refuses each individual `text_len > isize::MAX` before making a Rust slice or using pointer addition. The scalar byte length gets the same check. These are representability checks, not pointer-validity checks. The caller still owes live, properly aligned readable input arrays and text bytes, a writable output array of `count` answers, live output slots, and input/output and output/output ranges that do not partially overlap. A C library cannot safely discover arbitrary invalid pointers or partly overlapping allocations. Count zero retains its current null-array allowance, while the facts pointer and length slots remain required. A null or invalid input keeps the current Usage and UTF-8 rules. On **any** nonzero return, including a post-reply publication defect, every caller output retains its original value and no result or facts string is transferred. Convert the result and facts to owned C strings and finish all other fallible work before publishing either output. The final commit writes only validated slots and performs no fallible work. No panic may unwind through the C ABI.

The six existing error codes, retryability, cancellation, deadline, same-thread error message and `thinkthen_error_facts_json` lifetime stay unchanged. A started failure freezes its facts only in that existing failure accessor; a pre-start Usage refusal has no facts. A complete successful result does not clear or overwrite another thread's last failure, and no new success slot is introduced. A failure after a complete reply but before output publication must attach that call's final facts to the recorded failure. Neither a partial `decide_many` array nor one of the two JSON output strings may escape. Existing plain typed names retain their bare outputs and behavior; all new documentation/examples after landing should recommend `*_with_facts` for typed work and name the old exports as compatibility forms. Existing compiled consumers are not silently migrated.

The current `ffi::typed` settles the asking result before its writer runs, and the current outer `failures::guard` records a factless defect on panic. The new path must retain completed `Facts` **before** value conversion, row-count validation and C-string construction. For a completed `Call`, capture its facts while the `Call` still owns them; for `decide_many`, exhaust and join the `Batch`, take `Batch::facts()`, then compare row count. Ordinary conversion errors, including a count mismatch or CString failure after a complete reply, become a defect with those final facts in the existing failure slot. A plausible private implementation is a typed-with-facts guard built in `failures.rs` on its existing `in_door` and `catch_unwind`: it owns an `Option<Facts>` outside the guarded conversion closure, receives the completed facts before that closure formats values, and on unwind records the same safe defect plus the held facts. It must retain the existing hook suppression and payload-disposal behavior and return the fallback code. A panic before completed facts exist retains today's factless defect limit; no facts can be manufactured from an unfinished call. A panic after completed facts exist but before the final non-fallible output commit records those facts. The implementation must not move or drop that guard value early. This is a source-level exceptional-path rule, not a request for a public or test-only panic switch.

## Implementation and proof boundary

Reuse `door.rs`'s existing Rust calls, `Call::facts`, `Batch::facts` and `failures::facts_json`. Have a private shared typed path retain owned `Facts` before it converts a completed value; old FFI writers may ignore facts and new writers serialize them. `recognize` and `relate` already return tuples on their current ordinary path, but the new guarded path must make the facts available before fallible formatting. Keep the unsafe exported pointer edge in an allowed `ffi.rs` basename; the current parent `libraries/c/src/ffi.rs` is 497 nonblank lines under the 500-line policy, so a coherent nested `src/ffi/typed_facts/ffi.rs` is expected. A shared publication helper converts and validates before the final non-fallible writes. Do not create eight independent schedulers or a second facts schema.

One installed-header C driver under the existing soname/ASan harness should cover all four plain/options pairs, exact listener requests with `batch 1` for the many-count case, returned JSON facts and owned frees, null/duplicate output slots with zero sends, unchanged sentinels on started and pre-start failures, two callers on one engine, and a missing-usage reply. Existing 0230 JSON-door, C plain/options parity, failure-slot, symbol/header and C/CLI byte proofs remain in force. New exported symbols require the exact header-symbol check and a rebuilt C archive on each claimed release target; a Linux installed proof does not qualify macOS or ARM64 packages. No broad matrix or paid call is part of this design.

## Coordinator ruling

Preserve compiled C consumers and the frozen ABI. Implement the eight additive facts-returning exports as the recommended typed C API. Retain the existing eight bare symbols as explicitly documented compatibility forms. This is the narrow exception to the original every-call wording; old calls do not acquire facts, and the record must not claim otherwise. The owned outputs satisfy the same-call requirement for the new API without a second provider operation or a mutable last-success slot. Changing old signatures would break existing consumers, while the borrowed accessor would weaken ownership. The broader every-surface-facts issue remains open for its other criteria. Required queue-owned C documentation and examples land with the implementation; site remains marketing-owned.
