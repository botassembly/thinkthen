# ADR 0108: Caller-priced call cost

- Status: **proposed** 2026-09-29 for fresh High design/API review. The coordinator may accept routine details within Ian's approved useful pre-release API outcome; this document does not itself change the product.
- Opens: the cost criterion of [every-surface facts](../../issues/2026-09-26-every-surface-should-give-back-run-facts.md). Implementation route: [ticket 0300](../../tickets/0300-caller-priced-call-cost.md).

## Decision

An engine may hold one caller-supplied pair of USD prices per million **input** and **output** tokens. Its calls, including failures with started-call facts, return an optional `estimated_cost_usd` beside existing facts. The CLI reads the same pair from its configuration and emits the same optional field only in an opted-in `--facts` final run line. No pair means no money field or price guess. There is no price per model, vendor lookup, bill guarantee or money admission limit; a caller choosing a different backend/model tariff must select a different engine pair. Cache and replay have no new spend. `facts.seconds` stays elapsed wall time.

The pair is `usd_per_million_input` and `usd_per_million_output`, both decimal strings in `thinkthen.config/1` and closed native settings JSON. Rust `EngineBuilder::prices_usd_per_million(input: &str, output: &str)` sets both atomically. There is no CLI price flag, environment key or per-call setting. Missing both means disabled; exactly one, explicit null, non-string or invalid decimal is Usage before send. Accept ASCII digits with optional dot followed by one to six digits, no whitespace/sign/exponent, at least one integer digit, range 0 through 1,000,000 inclusive USD per million. Parse once to integer micro-USD per million; no floating point in price or multiplication. The canonical result is a six-decimal USD string, rounded half up once after summing checked `u128` products and dividing by one million. At the allowed maxima and `u64` token totals the arithmetic fits `u128`; an impossible internal overflow is a defect, never saturated money. A tiny positive estimate may round to `"0.000000"`; this is a display precision, not proof of no send or no vendor charge. Host stream/tally adapters must aggregate complete, checked raw usage under one selected pair and round once, never sum rounded per-call strings. `Engine::estimate_reported_cost(input_tokens, output_tokens)` is the one arithmetic-only bridge for separately compiled Rust hosts; it returns `Option<String>` for the selected price pair but does not certify usage completeness. Hosts gate the call on their own validity state.

Cost is present only if all actual started attempts supplied complete input **and** output usage **and** every token addition remained exact. Response completeness and arithmetic validity are separate predicates. `CallFacts.requests_sent` versus its live reply accounting and its latched checked-sum validity decide the library predicate. The CLI separately compares `RunSnapshot.counts.requests_sent` to usage-bearing replies and reads a private `token_sum_valid` latch from `engine/usage/facts.rs::State`; `Counters::tokens`/`Counters::add` sets it false when a token delta is not committed to process totals. Keep its current response-presence rule, but derive `usage_known=false` if token arithmetic is invalid and omit stale CLI token fields rather than inventing zero. Cost additionally requires all started attempts to be accounted for, independently of token-field presence. A durable writer failure after a successful process addition is not itself token invalidity. A status or transport failure with no usage makes the cost absent even if later replies provide token totals and today's CLI `usage_known` is true. Two usage-complete replies whose sum overflows `u64` omit CLI token fields and cost; stale or wrapped totals never become a public complete token total or money. Each call/run scope starts with valid arithmetic, and a clean later call/command can price normally. Existing partial token facts stay as they are. A priced call/run with no live sends has known `"0.000000"`; unpriced no-work still omits money. A started logical failure can carry cost if all started attempts supplied complete usage; a pre-start refusal has no facts. Output is a caller-priced estimate of reported usage, never a provider charge.

## Pre-freeze compatibility ruling for review

Choose an **in-place optional member** of the existing closed facts object and CLI `thinkthen.run/1` line. Keep existing members, outer C `{"value","facts"}` envelope, C typed symbols/signatures, and unknown-field refusal. Add only `estimated_cost_usd` as an optional string in `specification/result.schema.json::$defs.facts`, Rust `Facts`, owned C JSON and copied host facts. With pricing off, preserve prior serialized bytes. With pricing on, older strict Ada/Objective-C/COBOL and schema validators reject the new member; tolerant older readers can silently discard it. That is an intentional **conditional pre-0.1 compatibility break** to disclose and test. A schema edit does not upgrade an installed binary. Newly built priced-capable packages must ship a matching strict decoder and copied-consumer receipt. Strict hosts continue to refuse every other unknown facts key; they do not become open maps.

A separate `facts/2` envelope or C success accessor would avoid rejection by some old validators but create a parallel result and migration path, and a new C symbol would disturb the frozen ABI without a need. Defer that route. This ruling does not promise universal backward compatibility. Preserve the five-member `thinkthen.usage/1` monthly format and retries sidecar; neither stores price, model or cost.

## Boundaries and follow-through

The first implementation slice is Rust core/CLI/C with one pure decimal parser accessed through the public builder bridge; the C crate cannot import private core. Migrate strict and other host decoders in disjoint batches before those packages advertise priced support. Ticket 0283's shared settings bridge is a prerequisite for the implementation; 0289's tally/request work collides in usage/facade and must be merged before editing, but cost arithmetic does not use its admission rule. Ticket 0299 remains separate. Timing headers, request IDs, non-CLI persistent status and SQL/frame per-call facts need their own decisions and proof.

The implementation updates the owning result/settings specifications and the existing cost demo with a priced `--facts` example. One loopback proof must distinguish full usage from a failed attempt followed by a usage-bearing reply in **both** call and CLI run facts, then prove two complete replies with a `u64` token overflow suppress money in both despite matching send/reply counts, and that a fresh scope prices normally. Python frame accumulation also needs a checked two-call overflow witness; R retains its checked, pre-commit exact-range defect. Preserve exact sends and copied failure behavior. Each strict host needs a selected copied-consumer compatibility receipt. Root owns implementation claims and issue closure after fresh review.
