# 0399: Backend paths and complete yes-or-no criteria

Status: proposed, 2026-10-04. Ticket 0399 owns the outcome. Fresh independent review must accept this design before implementation. The coordinator owns the two already authorized manual checks. This record changes no runtime code and starts no paid call.

## Retained behavior

The unnamed path continues to post to `systemone`. Existing built-ins retain their address, model, key selection, descriptions and request bytes. Backend selection keeps ADR 0114's tiers. Host guarding runs before credential lookup and compares normalized hosts independently of path. The transport continues to receive one resolved URL. Cache, recording and request-rate identities continue to use that URL and the existing encoded body. No backend name or wire-form label enters those identities.

## Path construction

Keep `Backend::resolve(url, base, model)` as the existing default-path entry point. Add a private resolver that accepts the path and applies the existing address validation before joining it. `resolve` delegates with `ENDPOINT_PATH`. Named resolution supplies `Named`'s path; the built-in table supplies its own path. A configured entry defaults to `ENDPOINT_PATH` when `path` is absent. Existing `Named::new` callers may keep that default and use an internal setter for a validated configured path.

Validate configured paths at the configuration boundary with the ticket's exact grammar and value-free refusals. The path is a relative suffix, so it cannot provide a scheme, authority, query or fragment. Preserve a base's existing prefix and append exactly one slash and the suffix. Permit `@` only inside a segment. Reject percent encoding and dot-only segments before joining. Built-in paths are static adapter constants and receive the same grammar check in a small table assertion. Do not add a CLI path flag or public Rust setter.

`Backend::is_built_in` still means the default TypeSafe posting URL. The new Perplexity path does not broaden it. Named rate overrides match the named backend's resolved posting URL. Unnamed rate lookup still resolves each rated built-in at its own path before comparing URLs; an unnamed Perplexity base posting to `systemone` must not inherit the rate for `decisions`. The existing host guard may resolve default paths when it needs only the host; either route must preserve its exact refusal order and normalized-host comparison.

## Description form

Add `Descriptions::BothSides` to the existing per-backend form carried into plans and check probes. OpenRouter uses it. Preserve authored strings, objects and arrays. For a yes-or-no question, omit `criteria` when both sides are absent or null. When one side remains, keep that side and encode `{}` for the other. Apply this rule to both decide and described tag labels. Keep choice and score bytes unchanged. `Text` remains the only form that drops detail or prints its workaround warning.

The request encoder remains the sole owner of this transformation. Do not rewrite user descriptions, question files or saved recordings. The bytes sent determine cache sharing: an OpenRouter described decide separates from the authored form at the same URL and model; a decide without descriptions still shares when its bytes match. Replays keep the existing decoder and admit OpenRouter's extra reply members without a new reply shape.
