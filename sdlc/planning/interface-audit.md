Ticket 0017 closes the gaps, and `ten-use-cases.md` sits beside this page.

History note, 2026-09-25, by ticket 0126: rows 31, 32, 38, and 66 and items 1 to 5 of the gaps list describe the binary of 2026-09-19 and no longer hold. Ticket 0017 sends `criteria.true` and `criteria.false` from `--true` and `--false`, and it sends one description per option from `--option LABEL=DESCRIPTION`. Those close items 1 and 3. `annotate` is built, and one request carries several questions, which closes item 2. Commit `b0cba964` reads `Retry-After`, and ticket 0064 bounds that wait by `--timeout`. That closes item 4. Several `--field` pointers send one JSON object as `state`, which closes item 5. Item 6 stays open, because the binary has no `models` command. Each was checked against the binary on 2026-09-25. The other rows stand as written.

Read-only audit. No file in the tool's repository was changed, no request was made to the vendor, and no key or `.env` value was read or printed.

The paths below were written before ticket 0020 moved the adapter. `crates/thinkthen-core/src/systemone.rs` and `systemone/` now sit under `crates/thinkthen-core/src/adapters/`, and the default model moved from `backend.rs` into the adapter's own module. Line numbers were a snapshot of the day and have drifted since.

Sources are cited three ways. `wheel:<path>:<line>` is the vendor's published Python client, unpacked but not installed; its `_schemas/models.py` is generated from the vendor's own `openapi.json` and is the most exact source there is. `docs:<file>:<line>` is the saved copy of the vendor's documentation. Paths with no prefix are files in the tool's repository. One private third-party caller is cited as `caller:<file>:<line>`.

One fact governs the whole "question file" column. No question file and no question set parser exists in the code. `crates/thinkthen/src/main.rs:45-47` wires exactly three subcommands: `decide`, `choose`, `score`. The verbs `annotate`, `filter`, `rank`, and `find` are specification text only. So every "question file home" below is a proposed shape, not a behavior.

A second fact governs several rows. The tool sends exactly one question per request. `crates/thinkthen/src/judge.rs:294` builds every plan with `vec![question.clone()]`.

## (a) The gaps, ordered by how much a user loses

1. **The yes/no question's true and false texts.** The vendor's `noul` question takes `criteria.true` and `criteria.false`. The tool sends neither, has no spelling for either, and no decision record ever considered them. This is the one gap with three independent proofs: the generated schema, the documentation, and a real third-party caller. Command line: `--true TEXT` and `--false TEXT` on `decide`. Question file: `true` and `false` beside `decide`.
2. **Several questions in one request.** The vendor measured twelve times cheaper on thirteen questions. Only `annotate` would use it, and `annotate` is not built. This also blocks the line-search shape that `find` was designed around. Command line: no new option. Question file: the `questions` map that `annotate` already specifies. The fix is to build `annotate`.
3. **A description per option on a pick.** The tool's own contract already spells a map from label to description, and the wire code writes `null` for every value. Command line: `--option LABEL=DESCRIPTION`, repeatable, beside the positional form. Question file: the `options` map that already exists in the specification.
4. **The `retry-after` header.** The server asks for a wait and the tool ignores it, doubling from one second instead. Command line: no new option, inside `--max-retries`. Question file: none.
5. **Structured state.** Evidence built from several pointers goes out as a JSON string rather than a JSON object, which the vendor accepts. Command line: no new option. Question file: none.
6. **Listing the models.** No way to see or pin a model version from the shell. Command line: `thinkthen models`. Question file: none.

The spelling stays regular by using the same word in both places: `true`, `false`, `option`.

## (b) What the tool exposes that the vendor does not support, or gets wrong

- **A confidence on a yes/no answer.** `specification/result.md:25` shows a `yes_no` answer carrying `"confidence":0.88`. The vendor never sends one. `wheel:typesafe_sdk/_schemas/models.py:73-80` gives `NoulAnswer` only `type` and `noul`, and `docs:confidence.md:11` and `docs:primitives/noul.md:302` say so in words. The repository's own recorded response fixture for a yes/no question carries no `confidence` either. The code is right, reading only `noul`. The specification is wrong, and it documents a field that cannot appear.
- **A phrase for status 402.** `crates/thinkthen/src/failure.rs:18` and `specification/backends.md:46` give 402 the phrase "the account has no credit". The vendor documents no 402 anywhere.
- **Retrying 500, 502, 503, and 504.** `crates/thinkthen/src/http.rs:20` retries six statuses. The vendor names only 429 and 529 (`docs:api.md:318-319`). Harmless, but not backed by the vendor.
- **A floor of two options on a pick.** Stricter than the generated schema, which sets no minimum on the criteria map. Defensible, since one option is not a choice.

## (c) What could not be settled from these sources

Each of these would need one live call, and none was made.

1. Does the endpoint accept a `noul` question carrying `criteria.true` and `criteria.false`, and does the returned `noul` value change when they are supplied against when they are left out, with the same `state` and the same `instructions`?
2. Does a `choice` question whose criteria values are real descriptions return different `probabilities` than the same options with `null` values? This is exactly what the serializer throws away today.
3. Which token budget is real: one budget of about 32,000 tokens for the whole request, or 64,000 for the request with 32,000 for the state plus the longest question? A request sized between the two settles it.
4. What is the real ceiling on the number of questions in one request, and which status and which `detail[].loc` come back when it is passed?

One further tension is about meaning rather than wire shape, so no call would settle it. The vendor warns against reading a score as an interpolated magnitude (`docs:model-jaggedness/jev-1.13.md:76`), while the vendor's own `score` field is defined as the probability-weighted average of the levels and may fall between them (`wheel:typesafe_sdk/_schemas/models.py:109-114`). That average is what the tool computes locally. The tool and the vendor's field agree; the vendor's guidance page disagrees with both.
