The tested guides describe the current result API. Read your language’s upgrade section before changing a caller.

## Results and errors

An SDK’s separate one-message call fails at the call if that message could not be judged. A successful call returns answered or not sure; reading an unsure answer fails loudly. Collection calls keep failed results beside the other answers, even with one input. State checks, printing and saving remain safe.

The SDKs that offer a separate one-message annotate call fail it only for a failed parent form. An answered form can contain failed questions; check each answer you use, or explicitly check the form for failed entries. That explicit check includes children and never treats not sure as failure.

The concrete failure exception is now named after the failed state, such as Python’s `Failed` and Java’s `FailedException`. General call errors retain their own classifications. Follow your SDK’s error table rather than renaming every error.

[pandas](/sdks/pandas/) and [Polars](/sdks/polars/) have dedicated guides. They remain Python extras and keep their collection behavior, native missing values and details columns. R, SQL and the command retain their existing failure behavior.

Filter takes one bar and yields the original messages it keeps. Use decide collections for a result about every input, including not sure. The command’s filter has no JSON view. Produced failed results make the command exit 6, including a service outage affecting every message.

## Command upgrade


The baseline is the [published 0.1.2 crate’s command source](https://static.crates.io/crates/thinkthen/thinkthen-0.1.2.crate). Every result now prints, `--check` turns the answer into the exit code, and several options have new names. That release already has `--field` and `--backend`.

| 0.1 | Now |
| --- | --- |
| `--true`, `--false` | `--yes-means`, `--no-means` |
| `--threshold 0.2:0.8` | `--low 0.2 --high 0.8` |
| `--lines` | `--from lines` |
| `--details` on a plain call | `--json` |
| `--option billing`, `--option 'billing=charges'` | `--choice billing`, and `--describe 'billing=charges'` |
| `--label 'billing=charges'` | `--label billing`, and `--describe 'billing=charges'` |
| find picked one message out of many | find picks one line inside each message. Send the candidates as one message, one per line |
| Answers were cached between runs | Each run asks the service again. Save the results to reuse them |

## Language requirements

Go requires 1.27 or later. C++ requires C++20 with GCC 13/libstdc++, Clang 20/libc++20, or the documented Windows compiler route. Swift requires 6.3; arrays passed to one-message functions are refused before any request, with the diagnostic naming the collection form.

See the [command guide](/command-line/guide/), [Python](/sdks/python/#upgrading-from-01), [TypeScript](/sdks/typescript/#upgrading-from-01), [Go](/sdks/go/#upgrading-from-01) and the other SDK guides for their exact migration steps.

## Known limits

| Limit | What happens | What to do |
| --- | --- | --- |
| Unsigned macOS files | Apple hasn't notarized them, so macOS can block them after a browser download. | Check the download against `SHA256SUMS`, then run `xattr -dr com.apple.quarantine thinkthen-0.2.0` on the folder you extracted. Do this only for a download that passed the check. |
| Unsigned Windows files | They carry no signature, so Windows can block them. | Check the zip against `SHA256SUMS`, then run `Unblock-File .\thinkthen-0.2.0-windows-x86_64.zip` before you extract it. Windows policy can still block it. [Installation](/install/) shows both checks. |
| Cancelling any run | Cancellation does not refund sent requests. Saved stream output and retained file-recovery artifacts can preserve completed answers; unreceived answers can be lost. SQL statement rollback can discard its results. | Save stream output, export retained files with `thinkthen recover FILE`, or commit separately saved SQL chunks. Export does not resume a run; a plain rerun can send again. |
| Running a database query again | A fresh invocation can send the questions again and incur new charges. | Save the answers in a table, then query the table. |
| SQLite joins | Changed correlated arguments perform new work. An unchanged invocation can reuse answers within the statement, but this is not a persistent answer cache. | Save one ThinkThen query in a temporary table, then join the table. [SQLite](/sdks/sqlite/) shows how. |
| PostgreSQL LATERAL joins | A correlated invocation can send requests for each outer argument set. An uncorrelated invocation can reuse its answers without repeating requests. | Save one ThinkThen query in a table, then join its answers. |
| PostgreSQL LIMIT | PostgreSQL answers every input before it applies LIMIT, so LIMIT 1 can pay for them all. | Limit the input inside a subquery, before the ThinkThen function. |
| DuckDB LIMIT | An outer LIMIT can wait for other questions and pay for answers it never returns. | Put LIMIT inside the input subquery. |
| Cancelling a database query | Cancellation can discard the current statement's results, and does not refund sent requests. Earlier committed chunks remain saved. | Commit each chunk's answers and completed-range marker in the same transaction before starting the next chunk. |
| Swift arrays in one-message calls | Swift’s generic `Encodable & Sendable` constraint also accepts arrays. The call refuses them before any request. | Use the `records:` form for a collection; keep arrays inside a message when they are part of its data. |
| DuckDB version | The extension loads only into DuckDB 2.0.0, with unsigned extensions allowed. | Start DuckDB with `duckdb -unsigned`. [DuckDB](/sdks/duckdb/) shows the steps. |
| Toolbox shell steps | A toolbox can run programs on your machine. | ThinkThen runs them only with `--allow-shell`, and passes your key only to a step whose `env` names it. Run only toolboxes you have read. |
| Slow memory leaks | Releases are not tested for memory over long runs on any platform. Each release runs one short engine leak check, and the engine has a check that later calls start no new threads. A slow leak in one SDK or database extension that shows only after hours of use can go uncaught. Older measurements on Linux left memory growth unresolved for C#, Java and TypeScript. | Keep long-running programs bounded, restart them from time to time and watch their memory. The [resource observations](https://github.com/botassembly/thinkthen/blob/v0.2.0/docs/resource-observations.md) hold the older measurements. |
| Full disk during a write | A full disk can interrupt writing output. | Keep the input, check the error and treat incomplete output as unsaved work. |
| Hard termination | A hard kill can leave an empty temporary file. | Treat empty temporary files as incomplete, and keep the original input. A rerun may send requests again. |
| Temporary-file access lists | A newly created empty temporary file has a brief interval before its final access list is applied. | Use a private working folder for sensitive inputs and outputs. |
