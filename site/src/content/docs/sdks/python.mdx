## When decide is not sure

Give decide a low and a high bar, and a text that falls between them is not sure. Using a not-sure answer as yes or no raises `tt.Unsure`, so it can't pass for a no. This message lands between the bars:

<Example id="sdk-python-unsure" />

Send not sure to a person. To branch without the exception, check `is_refund.unsure` first. Comparing a not-sure answer, as in `is_refund == True`, raises `tt.Unsure` too.

## When a call fails

Blank text raises `tt.RecordError` at once, and nothing is sent:

<Example id="sdk-python-failure" />

Any other failure, such as the service being down, comes back as a result with `failed` set to `True`. Using it as an answer raises `tt.RecordError`, whose `code` names the problem. Call `result.raise_for_error()` to raise it sooner. A wrong argument raises `tt.UsageError`. [Troubleshooting](/reference/troubleshooting/) lists each code and its fix.

## pandas

`import thinkthen.pandas` adds a `.thinkthen` accessor to every Series and DataFrame. A column goes in, and an answer column comes out on the same index. Install it with `python -m pip install "thinkthen[pandas]==0.2.0"`.

<Example id="functions/decide/pandas" />

Not sure is `<NA>`. A mask that holds `<NA>` leaves those messages out, as if they were a no, so take the not-sure messages out first:

<Example id="sdk-pandas-unsure" />

A missing cell fails and sends nothing. The accessor answers every other message, then raises `tt.RecordError`. Its `outcomes` holds every message's result, on the input's index:

<Example id="sdk-pandas-failure" />

To keep going past a failure, pass `errors="coerce"`. The answers stay a plain column with `<NA>` for not sure and for a failure, the call warns once with `tt.FailedRowsWarning`, and `.thinkthen.failures()` lists each failure, so you can tell it from not sure:

```python
is_refund = frame.thinkthen.decide(
    "Does the customer request a refund?",
    field="/text",
    threshold=(0.2, 0.8),
    errors="coerce",
)
failed_messages = is_refund.thinkthen.failures()
print(failed_messages[["position", "error_code"]])
```

`failures()` gives each failure's place in your input, counted from 1, its code and its message. An answer with no failure gives no warning and an empty table. `filter` and annotate work the same way.

Call `failures()` on the object the call returned. pandas keeps the list in that object's `.attrs`. A subset keeps the whole list, including failures outside the subset. `pd.concat` keeps it only when every input's `.attrs` are identical and not empty. `frame.assign(is_refund=is_refund)` loses it, because the list sits on the answer column and not on `frame`. Where the list was lost, `failures()` gives zero rows, so an empty table there does not mean the call had no failures.

An `id` column with a gap holds floats in pandas. Each whole number, such as `3.0`, is read as `3`, and the row with the gap fails with `record.invalid`, as any null or fractional `id` does.

## Polars

`import thinkthen.polars` adds a `.thinkthen` namespace to every Series and DataFrame. A column goes in, and a native Polars column comes out in the same order. Install it with `python -m pip install "thinkthen[polars]==0.2.0"`.

<Example id="functions/decide/polars" />

Not sure is `null`. Polars `filter` drops null entries along with the false ones, so take the not-sure messages out first:

<Example id="sdk-polars-unsure" />

A missing cell fails and sends nothing. The namespace answers every other message, then raises `tt.RecordError`. Its `outcomes` holds every message's result as a struct column:

<Example id="sdk-polars-failure" />

`errors="coerce"` works as it does in pandas: `null` for not sure and for a failure, one `tt.FailedRowsWarning`, and `.thinkthen.failures()` for the list, as a Polars DataFrame. On older Polars, such as 1.0, a missing `find` or annotate answer reads back as a struct of nulls, so check with `is_null()`, which works on every supported version. Polars has no place to keep the list, so call `failures()` on the object the call returned: every Polars operation that makes a new object loses it. Then `failures()` gives zero rows, so an empty table there does not mean the call had no failures.

## When to make a client

Each call above uses one shared client, made on the first call and closed when Python exits. It reads the `THINKTHEN_` variables when it is made, so set them before the first call. Make your own client when it needs settings of its own, such as `model=`, `backend=`, `url=` or `retry=` ([Configuration](/configuration/) lists the settings), or when you want to close it yourself. This one retries a failed request up to five times:

<Example id="sdk-python-client" />

A client has the same calls as the module, and the `with` block closes it. To make the plain calls such as `tt.decide` use it, pass it to `tt.set_default_client(client)`.

## Async

`thinkthen.aio` has the same calls, to use with `await`:

<Example id="sdk-python-async" />

Each running event loop gets its own shared client. `asyncio.gather` runs many calls at once, and `tt.AsyncClient` takes the same settings as `tt.Client`.

To make the `aio` calls use a client with settings of its own, pass it to `aio.set_default_client(client)` inside your main coroutine:

```python
import asyncio

import thinkthen as tt
import thinkthen.aio as aio


async def main() -> None:
    retry = tt.RetryPolicy(max_retries=5)
    aio.set_default_client(tt.AsyncClient(retry=retry))
    is_refund = await aio.decide(
        "Does the customer request a refund?",
        "Please refund my order.",
    )
    print(is_refund)
    await aio.aclose_default_client()


asyncio.run(main())
```

The default belongs to the running event loop, so the next `asyncio.run` starts fresh, and a call outside a running loop raises `RuntimeError`. Setting a new default leaves the old one open. `aio.aclose_default_client()` closes the one that is set.
