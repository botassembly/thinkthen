## Add an answer column to a CSV file

A CSV file is a table of text with a header line. Name the column to judge with `--column`, and the new answer column with `--into`.

<ExampleFile id="decide-csv" file="messages.csv" />

<Example id="decide-csv" />

The same table comes back with an `is_refund` column. Excel reads `TRUE` and `FALSE` as yes and no. A not sure answer, or a row that failed, leaves the cell empty, so it never reads as a no. Each failed row is named on standard error, and the command exits 6 ([Exit codes](/command-line/exit-codes/)).

Where the new table goes depends on how you give the file:

| You give | The new table goes to |
| --- | --- |
| `--from csv < messages.csv` | the screen, as above |
| `messages.csv` | a new file beside it, `messages.thinkthen.csv`, and the command prints that name |
| `messages.csv --output reviewed.csv` | `reviewed.csv` |
| `messages.csv --in-place` | `messages.csv` itself, after it keeps the original as `messages.backup.csv`. If filter fails on any row, `messages.csv` stays as it was and the command exits 6 |

Empty lines at the end of a CSV or TSV file are ignored, and the new table leaves them out. An empty line with more rows after it stops the command before any question is asked, and the error names the line, so no row goes unjudged. Delete the line and run again.

ThinkThen never overwrites an output file. If `messages.thinkthen.csv` already exists, the command stops with exit code 2; choose a new `--output` name or remove the old file. Repeat `--column` to judge several columns of each row together. `--details` adds five more columns for each answer, such as its status and probability.

## Add an answer column to an Excel file

An Excel file (`.xlsx`) works by name, never from a pipe. This workbook holds one worksheet, `Messages`:

<ExampleFile id="files-xlsx" file="messages.xlsx" />

<Example id="files-xlsx" />

The command writes `messages.thinkthen.xlsx` beside the input and prints its name. Its `is_refund` column holds real `TRUE` and `FALSE` cells, and `#N/A` for not sure or a failed message, so an Excel formula can't mistake either for a no.

Every other worksheet, style and formula stays as it was. When a workbook holds more than one worksheet, name one with `--sheet Messages`. Formula cells are read from their saved values and never recalculated. Older `.xls` files, macro-enabled workbooks and signed workbooks are refused; save an unsigned `.xlsx` copy first. A worksheet row larger than 64 MiB, counting the text of every cell, is refused, as a CSV record of that size is.

ThinkThen loads a workbook's whole shared-string table, where Excel keeps its text, into memory. A table larger than 512 MiB is refused. So is a record larger than 64 MiB in plain text, lines, CSV, TSV or JSON Lines, and an Excel row larger than 64 MiB. A record may be up to 64 MiB, but the text sent for judging, with its question, must fit the 96,000-byte request limit: a longer judged text fails that row with `record.too-large`, and the rest of the file completes.

In one run with the stub backend on a Linux build machine (x86_64, glibc 2.43, 12 cores, 27.6 GiB of memory), a 100,000-row workbook with a shared-string table just under the limit peaked at 515.7 MiB of memory. A table with a 64 MiB record peaked at 135.6 MiB, or 263.2 MiB when the record was the judged text.

## How ThinkThen picks the type

A file's ending picks its type: `.csv`, `.tsv`, `.xlsx` and `.jsonl`. Anything else, and a pipe, is plain text. `--from` names the type outright: `text`, `lines`, `jsonl`, `csv`, `tsv` or `xlsx`. In a script, say `--from` so the type never depends on a file's name. [JSON Lines](/command-line/json-lines/) covers `.jsonl` files.
