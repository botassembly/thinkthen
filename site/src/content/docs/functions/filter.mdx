filter keeps original messages that answer yes, using one bar.

<Example id="functions/filter/command" />

<ExampleFile id="functions/filter/command" file="messages.txt" />

filter means "give me the yeses". It prints your own messages, in order.

```bash
thinkthen filter 'Does the customer request a refund?' messages.txt |
  while IFS= read -r refund_request; do
    echo "refund queue: $refund_request"
  done
```

filter takes one bar, so every message is a yes or a no and none is left out for being not sure. `--threshold 0.7` moves the bar. `--low` and `--high` are refused with exit code 2 and a message that names `thinkthen decide`: when you want not sure, use decide over the same file, as in the section above.

If a message fails, you still get every kept message. filter names each failed message on standard error, with its position and `id`, and exits 6 after the last message.

```bash
status=0
thinkthen filter \
  'Does the customer request a refund?' \
  messages.txt > refunds.txt || status=$?

if [ "$status" -eq 6 ]; then
  echo "try again later: some messages could not be judged"
fi
```

filter prints your messages and nothing else, so it has no `--json`. To get each failed message back with its error code, run `thinkthen decide --json` over the same file.

With `--check`, filter answers "did any message say yes", as `grep -q` does: 0 when one did, 1 when none did, 6 when a message failed.
