# Recording and replay

Status: **Settled** for version one, by an agent under ADR 0005. Ian has not read it, and he can overturn it cheaply until demos depend on it. Every token count and probability in an example here is illustrative.

A recording is a folder of stored answers, one for each question a backend answered. It lets a command run again with no network, no required key, and the same answer. A replay inspects an optional configured key to reject a collision with the resolved address before it reads the folder. Demos and tests replay recordings, so no gate ever reaches a backend.

## The options

| Option | Meaning |
| --- | --- |
| `--record DIR` | Send every question, even one already held in `DIR`, then store each answer, replacing a held one. `DIR` is created when absent |
| `--replay DIR` | Answer from `DIR` alone. Open no connection and require no key. Inspect an optional key for an address collision before opening `DIR`. A question that `DIR` lacks is a local failure, exit code 5, and the message names the missing question key and says what forms it |
| Both, with the same `DIR` | A cache. A held answer is replayed for a pinned model. A request naming `jev-latest` instead refreshes it. A question with no held answer goes to the backend, and its good answer is stored |
| `--cache DIR` | The row above, written once. It stands beside neither `--record` nor `--replay`, because one run keeps one folder |
| `--refresh-cache` | With an enabled answer cache, send every planned question live and replace each held answer. The flag stands beside neither `--record`, `--replay` nor `--no-cache` |

Giving both options with two different folders is a usage error. So is giving either option beside `--plan`, because a plan sends nothing and reads no recording folder. It only inspects the optional configured key for an address collision.

`--record` alone does not reuse a held answer. Recording the same question into a used folder sends it to the backend again and may incur another charge, and the new answer replaces the old one. For a pinned model, use `--cache DIR` or both `--record DIR --replay DIR` to reuse held answers. For a deliberate new measurement, copy the old folder for safekeeping, then direct the new run to another empty folder. In this example, neither destination exists yet:

```sh
cp -a runs/first runs/first-backup
thinkthen decide 'Does this need review?' --record runs/second < case.txt
```

The command creates `runs/second`.

A request naming the mutable `jev-latest` model refreshes automatically in a write-capable answer cache, including an explicit same-folder record/replay pair. Before a CLI run can send, a fixed warning says each planned cache question may incur a charge. No extra probe is sent. `--refresh-cache` applies the same live replacement to another model in an enabled named or default answer cache. A disabled default cache requires `--cache DIR` for this flag. A good live answer replaces the held one in the same transaction that stores it. A refused or failed answer leaves the held answer untouched, and that run never serves it silently. `--replay` remains keyless, read-only history and never checks where an alias points today.

With none of these options, normal commands use the platform answer cache: `$XDG_CACHE_HOME/thinkthen`, then `$HOME/.cache/thinkthen` on Linux, and `$HOME/Library/Caches/thinkthen` on macOS. `THINKTHEN_CACHE` selects another folder. The SQL extensions never use the platform folder; they cache only in a folder `THINKTHEN_CACHE` or their own cache setting names. `--no-cache` disables answer-cache lookup and writing for one run. Explicit `--record` or `--replay` suppresses the default cache. Dry runs, help, version, `status`, `check`, and `cache prune` create no default cache.

`thinkthen status` is read-only and opens no connection. It reports the version, resolved configuration with provenance, key presence, the answer count of the cache's `thinkthen.sqlite` as `cache_entries`, that file's allocated bytes as `cache_bytes`, the count of old digest-named entries beside it as `cache_old_entries`, the prune target as `cache_prune_target_bytes` with its source as `cache_prune_target_source`, and local usage for the current UTC month and all months. `status --json` emits the same facts as one closed `thinkthen.status/2` object. `status --backend NAME` reports that backend. The human form prints `backend NAME` or `backend none` and `key_variable NAME`, the first variable the key would be read from; `api_key_set` reports that variable. The JSON `backend` object carries `name` (a string or null) and `key_variable`, and `url_source` and `model_source` read `backend` when a named backend supplied the value (ADR 0114). JSON names the three cache counts `cache.entries`, `cache.bytes` and `cache.old_entries`, and an absent cache path makes each null. Version 2 moves no field: `.usage.total.requests_sent`, `.usage.total.input_tokens`, and every other kept version-1 path stay where they were. It drops `cache.binding`, `cache.bad_entries`, `cache.temporary_entries` and `cache.temporary_bytes`, because ADR 0111 section 10 retires the folder marker, bad entries and temporary entry files they counted. Status opens `thinkthen.sqlite` read-only and exits 5 when it is not a question store. No line holds a key. It shows one combined total of what every surface sent (ADR 0113). The command and every engine built from the environment, which covers each library, the C door, the data frames and the three SQL extensions, add their counts to the same files. `EngineBuilder::new()` keeps its counts in memory. A SQL extension writes its counts when its process exits; a crash loses the last ones. A PostgreSQL backend writes to the usage folder of the server's operating-system user, so `status` run as that user sums every backend. Each SQL extension's request total is per process: PostgreSQL counts it per connection, so a pool of N connections can spend N times it. Every attempt, a retry included, reserves its unit atomically, so calls running at the same time cannot pass the total together. Status accepts no judgment overrides.

Usage lives at `$XDG_CACHE_HOME/thinkthen-usage`, then `$HOME/.cache/thinkthen-usage` on Linux, and `$HOME/Library/Caches/thinkthen-usage` on macOS. `THINKTHEN_CACHE` never moves it, and `--no-cache` never disables it. One private `YYYY-MM.json` file holds checked aggregates for requests sent, input tokens, output tokens, and cache answers in the five-member, four-counter `thinkthen.usage/1` shape older binaries read. A private `retries-YYYY-MM.json` sidecar holds retries and is ignored by older readers. A stable private `.lock` serializes writes across processes. Every replacement syncs its temporary file, renames it, then syncs the directory. A new writer migrates older retry-extended monthly files under that lock before its next usage write, including prior months. `status` reads them without changing files. The files contain no request, response, address, model, price, or key.

Every HTTP attempt counts immediately before it is sent, including a retry or failed attempt. `retries` counts the retry subset of `requests_sent`; an old usage file without a retry sidecar reads as zero retries. `status` reports monthly and total retries. A completed usage write syncs the legacy monthly file before the retry sidecar. A crash between them can leave the advisory retry total low while keeping the last durable monthly total. A detected sidecar write failure prints the usual usage warning and stops later persistence in that process. Validated provider token counts count once for each successful live response, including a response whose answer is later refused. Replayed response bytes add no tokens. A decoded hit in the platform cache, `THINKTHEN_CACHE`, or `--cache` counts as a cache answer. Explicit replay and an explicit record/replay pair do not. Packed `annotate` groups count as their actual exchanges.

Usage persistence is best effort. Its first failure disables later updates in that process and prints one fixed warning after ordered results. It never changes a judgment, output order, or exit meaning. Counting never holds back a request. The command waits for its usage writer after its result. From that finish point, the writer allows one second in total for any remaining attempts to acquire another process's usage lock. If the lock stays held, the writer abandons unwritten counts and prints the same fixed warning before final `--facts`. Other filesystem operations can still delay exit. ADR 0097 amends ADR 0049 item 3's unlimited lock wait. A crash can undercount the requests and tokens counted after the last write that finished. These totals describe local observations and are not a provider bill. A missing month stays absent until a complete replacement is installed. A zero-byte or otherwise malformed recognized month is refused by `status` and the writer; neither silently resets it or guesses its lost totals. Their diagnostics name only its generated filename and a fixed error category.

An XDG home or `HOME` participates in these paths only when it is absolute. A relative or blank home is unusable and never resolves below the working directory.

The default cache folder is created only when a run first opens its store. A rejected record or invalid `find` set creates nothing. Replay of a missing explicit directory reports the question's normal replay miss and creates no directory. Replay of an existing read-only directory changes no file or directory metadata.

The optional read-only configuration file is `$XDG_CONFIG_HOME/thinkthen/config.json`, then `$HOME/.config/thinkthen/config.json` on Linux, and `$HOME/Library/Application Support/thinkthen/config.json` on macOS. It has schema `thinkthen.config/1` and optional `url`, `model`, `cache`, positive `cache_bytes`, `usd_per_million_input` and `usd_per_million_output`, `backend`, and `backends` fields. `backend` names the default backend and `backends` adds named backends, each with `url`, `key_env`, `model`, and an optional `requests_per_minute`, and may give a built-in a `requests_per_minute` alone. That rate holds within one process, and separate processes each get the full rate; [the proxy service](../sdlc/issues/2026-09-30-proxy-service-for-shared-limits-and-traces.md) and [the batch command](../sdlc/issues/2026-09-30-batch-command-runs-many-questions-in-one-process.md) are the future answers for a limit across processes; the file names key variables and never a key ([backends.md](backends.md#named-backends)). Unknown fields are refused. Each refusal names the field, never a value, and exits 5. The default is cache enabled, and `cache_bytes` defaults to 100,000,000 allocated bytes. `cache_bytes` is the target `cache prune` trims to. Nothing trims the cache on its own. It grows, and keeps the judged text, until the user runs `cache prune`. The tool never creates or edits this file.

A recording directory argument that names a regular file is a local failure at exit 5. The diagnostic says to choose another path or remove the file. It repeats neither the path nor an operating-system error.

Answers from two addresses never mix, because the address is part of every question key. A cache pointed at a new address misses and sends again, and the folder then holds both addresses' answers. ADR 0111 section 3 retired the backend marker `.thinkthen-backend.json`, the `.locks` folder and the folder gate. A marker or lock a former version left is ignored and kept.

Both options on one folder are also the resume for a record run. A resumed run asks again only the questions whose answer failed, because a store keeps no failed answer. [records.md](records.md) shows it.

## The question store

Every command keeps one answer for each question, by ADR 0111.

A question's key is the SHA-256 of the adapter, the address, the model, the shared state and the wire question as sent. A live store is `thinkthen.sqlite` in the folder that `--cache`, `--record`, `THINKTHEN_CACHE` or the default cache names. A committed fixture is `thinkthen.jsonl` in the same folder, with the same rows. The file uses SQLite's rollback journal with full sync and secure delete, and it is created with mode `0600`. Network filesystems are unsupported, because SQLite's locks are not reliable there.

The default cache and an explicit recording use this same key. For one-document text, `hello\n` and `hello\r\n` put different line endings in the quoted evidence and make different keys. The literal text `{"a":1}` and `{"a":1.0}` likewise differs when sent as text. A replay of one spelling misses the other, and a cache sends a new request. The rule applies to the encoded question bytes, not every original file byte: `--lines` strips a record terminator, and JSONL or a selected JSON value can be parsed and re-encoded before the request is built. Use recordings made with the same question, backend, request settings, and encoded evidence when transferring a run; do not expect a cosmetic text change to replay.

| Mode | Look up | Send | Write |
| --- | --- | --- | --- |
| `--replay DIR` | yes | nothing; a miss exits 5 | no |
| `--record DIR` | no | every question | yes, replacing |
| `--cache DIR`, both options on one folder, `THINKTHEN_CACHE`, the default cache | yes | misses | yes |
| A cache with `--refresh-cache`, or the model `jev-latest` | no | every question | yes, replacing |
| `--no-cache` | no | every question | no |

A run packs only the questions no stored answer covers. A longer run over the same records therefore sends only the new records' questions. Within one run, a question already on its way is not sent again, and every record that needs it waits for that answer. Two processes may write one store at once. A write waits for the other's commit, and every wait is limited to 30 seconds in all.

`--replay DIR` loads `thinkthen.jsonl` when it exists, and otherwise opens `thinkthen.sqlite` read-only. A question the folder lacks exits 5 with ``the replay folder holds no answer for question `KEY`; the key is the SHA-256 of the adapter, address, model, shared state and question as sent``. A folder that holds both files exits 5 with ``the replay folder holds both thinkthen.jsonl and thinkthen.sqlite; run `thinkthen cache convert DIR` to merge them into thinkthen.jsonl``. A read-only replay that meets a write that did not finish exits 5 and says to open the folder once with write access. A stored answer that no longer decodes is a miss under a cache and a local failure under `--replay`.

A partial reply stores its good answers. Its failed question fails its record, as before, and is never stored, so the next run under the same folder asks only that question. A replay of that question is a miss at exit 5. A too-large request that halves stores both halves' answers. The refused whole request stores nothing.

Each stored answer keeps its share of its request's reported usage, split evenly over the request's questions with the remainder to the earliest. A row's usage sums its questions' shares, live or stored. A row whose answers all came from the store reports `meta.cached: true` and zero requests sent. `meta.requests` lists the row's question keys in answer order. `--facts` counts `cache_answers` as questions answered from the store.

The repository commits no `thinkthen.sqlite`. A new live recording goes to a scratch folder with `--record`, and `thinkthen cache convert` merges it into the fixture. An old cache of digest entries is ignored by these commands until `cache convert` runs on it. The repository's committed folders hold only their fixtures; the finished probes keep their old entries as history.

- A stored answer holds the question and the reply's answer, never a header. No key can reach a recording.
- Live attempt timings and screened response request IDs stay in opt-in memory or current detailed output. Recording and replay keep no header or timing history; replay emits no current attempt event.
- A cache or recording answer is trusted for its answer. Whoever can write a folder that `--cache`, `--record`, `--replay` or `THINKTHEN_CACHE` names decides the answers read from it, and a changed answer replays with no sign. Keep such a folder private to the people whose answers it holds. Do not restore a shared cache across a trust boundary.
- On Unix, a command warns once before using an existing named cache or recording folder when another user owns it or its other write bit is set. A group write bit alone stays quiet, as it does for the configuration file, because the usual 002 umask sets it. A group-writable folder is trusted to its whole group, so a cache shared within a group that should not trust every member uses mode 0700. The warning names no path or answer and does not authenticate an answer. Newly created owner-private folders stay quiet. On non-Unix systems this permission check is unavailable; keep named folders private to trusted writers.
- The SQL extensions for PostgreSQL, DuckDB and SQLite apply the same ownership and other-write rule as a refusal, because a SQL call has no warning line. A named cache, record or replay folder that fails it when the extension builds its engine is a usage failure before any request, and the sentence names no path. They use no platform default cache, so an answer cache runs only in a folder that `THINKTHEN_CACHE` or the extension's cache setting names. In PostgreSQL every role runs as the server's one operating-system user, so every role whose calls reach a named folder shares its answers and bypasses row-level security. Ticket 0318.
- No refusal repeats a stored field. A fixture line that does not parse is refused with its line number and never its text, because every field under `DIR` is untrusted text: it is unbounded, it can carry a control byte, and it can quote the evidence back.
- A stored answer keeps the address the request went to, its path included, so a token must never sit in the path of a base. A base carrying user information, a query, or a fragment is refused for the same reason.
- A `DIR` the tool creates is readable by its owner alone, and so is `thinkthen.sqlite`, because a recording holds the evidence. On Unix that is mode `0700` for the folder and `0600` for the file, whatever the umask says. A `DIR` that already exists keeps the mode it has.

Every recording storage failure exits 5 and prints `thinkthen: the recording folder could not be read or written; check its permissions and free space`. The platform default cache is the folder no option or `THINKTHEN_CACHE` names. When it fails, the command prints `thinkthen: the default cache folder could not be read or written; check its permissions and free space, use --no-cache, or set THINKTHEN_CACHE to another folder` instead. The message carries no path, entry bytes, evidence, credential, or operating-system error. On Unix the process safely handles `SIGXFSZ`, so a file-size limit reaches this failure and its normal rollback instead of terminating the process. The command installs that handler before it reads input. The engine library installs no signal handler, so an embedding host keeps the disposition it chose. A later disk-full or sync failure can still discard an answer the backend already returned.

A successful `--record` run can replay the answers it printed. A refreshed answer cache is working state: if one question refreshes twice to different answers during one run, later replay reads the last replacement rather than an earlier printed answer. A repeated trial that wants another backend answer uses a fresh folder.

The same request can return another probability. Experiment 212 sent 100 messages twice on `jev-1.13.0`. Where an answer moved, the mean move was 0.02. Answers away from the middle moved by at most 0.03, and borderline answers, 0.33 to 0.67, moved by up to 0.08. That sample was one question on one day, and half of it was picked as borderline. The offline [0163 drift record](../sdlc/records/0163-answer-drift.md) found 4,075 differing digests among 5,111 repeats in the pinned benchmark recordings; 310 had a gap above 0.1, 430 crossed 0.5, and the largest gap was 0.45. The repository probes had no repeats, and its other recordings had three repeats with no probability gap. A borderline answer can cross the cut from one call to the next. The not-sure band in [threshold.md](threshold.md) marks where a second look pays. ADR 0010's amendment of 2026-09-25 withdraws the earlier claim that repeats match.

## What replay changes in a result

`meta.cached` is `true` when every answer came from the store and `false` when a backend answered. It is always present. `meta.requests` lists the row's question keys, the same keys that name its stored answers. Replay and live execution therefore report one identity. Everything else in the result is what the stored answers yield, their usage shares included. A later token ledger counts only answers that a backend gave.

A store installs no failed answer, so a replay of a question the backend failed is a miss at exit 5, and a cached run asks it again. ADR 0111 section 6 rules it. To retry a failed question, run the same command again under a cache. This includes `relate` edges.

## A recording holds the evidence

The request body carries the evidence. A recording is as private as the input it was made from. Record only what may be kept, and keep a recording of private input out of version control.

## Pruning a cache

`thinkthen cache prune DIR` is the only answer removal surface, and `DIR` is always explicit. It trims `DIR/thinkthen.sqlite` and never touches a fixture, an old digest-named entry or any other file. A folder with no `thinkthen.sqlite` has nothing to prune. Bare prune commits immediately; `--dry-run` opens the file read-only and previews the same selection without changing a byte. Both forms take the same selectors. `--older-than Nd|Nh|Nm|Ns` and `--answered-by-other-than MODEL` select a union. `--older-than` compares each answer's `taken_at` second with the current time. MODEL is matched byte for byte against the model each reply names. When some answer asked for MODEL and no reply names it, MODEL is the alias, and prune exits 2 before it deletes anything with ``--answered-by-other-than names the model the requests asked for, and no reply names it, so prune removed nothing; name the version a result's meta.model shows, not the alias passed to --model``. When the store holds an answer and no reply names MODEL, as with a typo or a newer version that has not answered yet, prune exits 2 before it deletes anything with ``--answered-by-other-than names a model no reply in the folder names, so prune removed nothing; name the version a result's meta.model shows, or delete the folder to remove every answer``. The alias sentence above wins when some answer asked for MODEL. A newer version that has answered at least once removes every older answer.

`--max-size BYTES` sets a separate target; without it, the configuration target applies. Selected answers leave first. Then the oldest `taken_at` leaves, equal times sorted by question key, until the kept answers fit the target. Prune reckons an answer's share of the file by the length of its stored text: the kept share is the file's allocated bytes times the kept answers' text over all answers' text. A cache hit does not refresh `taken_at`, so a frequently read old answer can leave before a newer one that was never read. Commit deletes the chosen answers and every stored state no answer uses in one transaction. Then it runs `PRAGMA incremental_vacuum`, which gives the freed pages back to the file system. The file's fixed pages stay, so a small target can leave the file above it. Committed prune prints `removed N answers and B bytes; K answers and C bytes remain`. B is how much the file shrank, and C is its allocated bytes afterwards. Preview prints `selected N answers and B bytes; K answers and C bytes unselected`, followed by `selected KEY` in deletion order for each chosen answer. There C is the kept share, and B is the rest of the file. A preview is a snapshot, not a promise that a later commit will remove the same answers. Prune waits up to 30 seconds for another process's write, as a run does.

`thinkthen cache unused DIR --used KEYS` reads an existing explicit folder. It reports the question keys the folder holds that a caller-supplied complete list lacks. KEYS is a UTF-8 file with one lowercase 64-character question key per nonblank line. Duplicates and blank lines are ignored, and an empty file reports every answer as unused from the supplied list. An invalid line is refused before DIR opens. The command reads `thinkthen.jsonl` as a replay reads it, and otherwise opens `thinkthen.sqlite` read-only. A folder holding both files is refused as a replay refuses it. A fixture line that does not parse refuses the whole report without partial output. The report prints `unused from supplied keys: N`, then `unused KEY` in lexical order. A replay's `meta.requests` lists the keys a run used. The command creates no cache, usage state or answer. It neither proves the supplied list covers a suite nor removes answers.

## Converting a folder to the question fixture

`thinkthen cache convert DIR [--quote]` writes `DIR/thinkthen.jsonl`, the question fixture of ADR 0111, from the union of what `DIR` holds: an existing `thinkthen.jsonl`, a `thinkthen.sqlite`, and every old `DIGEST.json` entry of schema `thinkthen.recording/1`. It reads them in that order, and the old entries in name order. When two sources hold one question key, the newer `taken_at` wins, and a tie keeps the entry read first, so a fixture keeps its own entries. It opens `thinkthen.sqlite` read-only.

Each old entry is decoded against its own request. The request's state, model and each question are written again as compact JSON. They must join back into the recorded body byte for byte, and each key hashes those bytes. An entry that does not rejoin is skipped with ``thinkthen: cache convert: skipped `NAME`; its request does not rejoin byte for byte from its parts``, and an entry whose reply holds no answer that decodes is skipped the same way. Only good answers are written. A failed answer is left out, so the next run asks it again. Each written answer keeps the reply's model as `answered_by` and its even share of the reply's usage, the remainder to the earliest question. Every converted answer takes `taken_at` 0 and `origin` `converted`. An entry whose envelope carries `"quoted": true` gets `origin` `quoted`. A `{"records":[…]}` exchange is written under the state `Each question quotes the text it asks about.`, because its questions already quote their records. With `--quote`, a single-record exchange is also written in the quoted form: the state becomes that sentence, each string instruction becomes `The text is `, the record's compact JSON, `. ` and the instruction, and `origin` is `quoted`. An exchange with a JSON instruction, or one whose instructions already begin `The text is `, is not quoted again.

The fixture is written through a temporary file in `DIR` and renamed into place. Then `thinkthen.sqlite` is removed, because `--replay` refuses a folder holding both files. The command waits for the file's write lock and holds it from its read to its removal. Run it only when no live writer has the folder open: a process that holds the file open keeps writing to the removed file, and those answers are lost. Old entries stay in place, so the command can run again, and converting the same folder twice writes the same bytes. It prints `thinkthen: cache convert: wrote N answers to thinkthen.jsonl, M from old entries; skipped K entries` on standard error and exits 0. A missing `DIR` exits 5 with `cache convert takes an existing folder, and the one named is missing or not a folder`. A digest-named file that cannot be read or is no recording entry, a fixture that does not parse, or a live file that cannot be read exits 5 before anything is written.
