# C# API

The `ThinkThen` namespace targets .NET 10. Create `ThinkThenClient` with `ThinkThenOptions`, or register a singleton with `services.AddThinkThen(options => ...)`. The client snapshots settings and serializer options. Dispose it with `await using`. An optional `ILogger<ThinkThenClient>` receives lifecycle events without request bodies, settings or credentials.

Settings use nullable `Backend`, `Model`, `Url`, `ApiKey`, `Batch`, `Retry` and `Json`. When `Backend` is absent, the client reads `THINKTHEN_BACKEND`; without either, the engine selects its default. An explicit backend takes precedence. Construct a direct key with `ApiKey.From(value)`. Diagnostics and serialized settings redact the key. Settings JSON admits keys through the engine. `RetryOptions` uses `MaxRetries`, `InitialBackoff` and `AttemptTimeout`. Durations must represent whole milliseconds.

Single calls return `Task<Row<TAnswer,TDetail>>`. Streams take `IAsyncEnumerable<TRecord>` and return `IAsyncEnumerable<Row<TAnswer,TDetail>>`. Each operation accepts an optional execution `name` and a final `CancellationToken`. `WithCancellation` also reaches the input enumerator and native operation.

`DecideAsync`, `ChooseAsync`, `TagAsync`, `ScoreAsync`, `FindAsync`, `RecognizeAsync`, `RelateAsync` and `AnnotateAsync` have matching `StreamAsync` methods. Choose requires choices; tag requires labels; score and rank require levels; recognize requires kinds; relate requires relation rules. Recognize and relate take their domains without an invented question prompt. Each function has its own options record. Decide and filter options accept `YesMeans` and `NoMeans`; choose, tag, score and rank accept `Descriptions`, mapping domain names to descriptions. Names not present in the domain are refused during conversion. Field uses `Pointer.From(value)`. Decide, choose and filter accept `Threshold.Cut(value)` or `Threshold.Band(low,high)`; the numeric-only functions accept `Cut.From(value)`.

Each method accepts either convenience arguments or its admitted typed question. For example, `ChooseQuestion.Create(question, choices, options)` snapshots the choices and options. Typed question overloads accept the question and records without replacement options. Questions are plain sealed classes, retain native resources until disposed, and cannot be copied with a record `with` expression. Questions and result unions are closed to external derivation.

`Row<TAnswer,TDetail>` has three cases:

- `Answered<TAnswer,TDetail>` exposes `Answer`, optional `Probability` and typed `Detail`.
- `Unsure<TAnswer,TDetail>` exposes `Probability` and typed `Detail`; reading `Answer` throws `UnsureException`.
- `Failed<TAnswer,TDetail>` exposes `Error`; reading `Answer` throws its `ThinkThenException`.

Every row converts implicitly to `TAnswer` through the same throwing `Answer` access. `IsAnswered`, `IsUnsure`, `IsFailed` and `TryGetAnswer` inspect the outcome without throwing. Comparisons with an answer use value equality; unsure and failed rows compare unequal to every answer. `Probability` is nullable on the base row. `UnsureException` extends `InvalidOperationException`, carries `Probability`, and is not a `ThinkThenException`. Every row exposes `Function`, `Position`, optional `RecordId`, `Source` and `Status`. IDs preserve strings and signed or unsigned 64-bit integers. Source identifies the attempted question, backend, model and optional execution name. Supplying a name changes question identity while preserving the answer. Toolbox selection supplies no execution name. Rows own their data after a call or client closes. Serialization preserves the shared row shape, full probability precision and exact IDs.

Collection answers and details use immutable `ValueList<T>` and `ValueMap<TKey,TValue>`. Their equality and hashes compare contents, with list order preserved and map insertion order ignored. Rows and detail records have structural value equality as well. Details use immutable `LabelsDetail`, `LevelsDetail`, `RecognizeDetail` or `RelateDetail`. Entity and relation endpoints use `Mention` and `TextSpan`. Span offsets count UTF-16 units with an exclusive end. Annotate returns an immutable map of typed `AnnotationEntry` cases. Their `EntryOutcome<TAnswer,TDetail>` contains answered, unsure or failed entry data without outer row metadata. Both typed entries and their outcomes expose throwing `Answer` access. A base `AnnotationEntry` exposes `Answer` as an object and implicit conversions to bool, string and double; concrete entries expose typed answers. Entry comparisons do not throw for uncertainty or failure.

`FilterAsync` yields only original records whose filter answer is true. Uncertain records are omitted. After yielding all kept records, it throws the first record failure as a `ThinkThenException` with every failed row attached in `FailedRows`. `FilterStreamAsync` yields `FilterItem<TRecord>` for every input row without raising record failures; `Item` preserves the original managed item and `Kept` is true only for an answered true. `RankAsync` yields `RankedItem<TRecord>` in engine order. Its `Item` is an equal JSON snapshot read back as `TRecord`; the type must support JSON reading and writing without changing its JSON value. Rank checks the first record before any backend request and throws `JsonException` with the target type and conversion cause if read-back fails. Filter retains the caller’s exact managed object. Its row's rank answer remains distinct from its original input position. `RankOptions.Top` restricts successful rows while retaining failures.

`Toolbox.FromJson(json)` admits the saved `entries` format, and `ToJson()` writes it. `Toolbox.Parse(json)` delegates the flat question map to engine admission. Typed selectors return admitted questions with their required lists. `Toolbox.Create` accepts named `ToolboxQuestion` values, including rank. `AnnotationQuestions` accepts the narrower `AnnotationQuestion` union. Use it with `AnnotateAsync`, `AnnotateStreamAsync` or `client.Toolbox(questions)`. A general toolbox and rank cannot enter annotation through the typed API.

Record strings remain raw text; structured values use the snapshotted `JsonSerializerOptions`. Every record-taking method has a distinct `WithMetadataAsync` form accepting `JsonTypeInfo<TRecord>`, including `DecideWithMetadataAsync`, `DecideStreamWithMetadataAsync` and `FilterStreamWithMetadataAsync`. This keeps positional null options unambiguous. A trimmed or Native AOT application supplies generated metadata or a generated resolver. Reflection serialization overloads carry the corresponding trimming and dynamic-code annotations.

One-record methods refuse lists, arrays and streams with `UsageRecordKind` and a stream-method hint. Blank input raises `RecordEmpty` from a one-record call; inside a stream it is a failed row and later records continue. Null host arguments raise `ArgumentNullException`, while a null record remains data and produces `RecordMissing`. Other record and backend failures return failed rows. Null records use the engine's missing-record operation. Usage, setup and internal failures throw `ThinkThenException` with typed `ErrorCode`, optional HTTP status and an original host cause when available. The `Family()` extension exposes each code's family. `RowError.Code` and `ThinkThenException.Code` expose the canonical string, such as `record.missing`, alongside the enum `ErrorCode`. Cancellation throws `OperationCanceledException`. Disposing the client cancels active operations, waits for native work to finish and rejects new admission. A paused stream cannot retain a native allocation after disposal. An uncooperative input advance remains observed and disposes after it returns.

`ThinkThenModelFactory.Answered<TAnswer,TDetail>`, `Unsure<TAnswer,TDetail>` and `Failed<TAnswer,TDetail>` construct rows without a client or native engine. These rows support the same answer operations, structural equality and row JSON serialization. XML reference comments are included beside the managed assembly.

`RelationRule.Name` and `Relation.Name` use the same public name; their shared JSON field remains `relation`. `new AnnotationQuestions { { "name", admittedQuestion }, ... }` and typed `Add(name, question)` calls build a form without annotation wrappers. The form snapshots each definition, keeps ownership of supplied questions with the caller, and freezes at its first admission. Rank has no Add overload.
