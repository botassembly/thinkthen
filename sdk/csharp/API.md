# C# API

Use .NET 10 and C# 14. `ThinkThenClient` owns the engine and supports `await using`. Every call is asynchronous: one-record calls return `Task<Row<TAnswer,TRecord>>`, and many-record calls return `IAsyncEnumerable`.

Awaiting a scalar call throws `FailedException` when its own parent row failed; blank or missing input sends no request. A returned scalar row is answered or unsure. The same `Row<TAnswer,TRecord>` type also retains failed bulk rows and form entries. `Answer` is the one loud read. It throws `UnsureException` or `FailedException` when no answer exists. `IsAnswered`, `IsUnsure`, `IsFailed`, `Probability` and `Detail` are always safe. `Detail` is an abstract record and is null when absent. Only `Failed` has `Error`.

Every result retains the exact original record as `Item`, including failures and rank results. Ranking holds all original records until it finishes, including when `Top` is set. Equality and hashing use function, status, answer, probability, error, position, id, source and detail only; mutable original records never participate. A form's entries follow the same rule. `IRow` and `IFailed` provide non-generic metadata views.

`ThrowIfFailed()` returns the same row, or throws for the parent or a failed form entry. Unsure entries are not failures. `NoAnswerException` covers `UnsureException` and `FailedException`. The latter carries `Code`, `HttpStatus` and failed `Rows`. `FailedException` inherits `NoAnswerException`, not `ThinkThenException`. Other engine call errors retain `ThinkThenException`: `UsageException`, `SetupException` and `InternalException`; argument and cancellation errors keep their standard .NET classes.

Decide rows alone support `if`, `?:` and `!`, through C# 14 extension operators. There is no implicit answer conversion, bare-answer equality operator or `TryGetAnswer`. Read `Answer` to store a boolean or combine conditions with `&&`. State switches use `Status`; promote CS8509 to an error and suppress CS8524 to check named enum cases.

Choose and tag accept lists of strings or enum members. Enum names become lowercase words using `JsonNamingPolicy.SnakeCaseLower` with underscores replaced by spaces. Typed choices return enum members, and tags return `ValueList<T>`. Score and rank accept explicit ordered level lists, including enum lists, and return numbers. The supplied list defines order; enum numeric ordering never replaces it. Typed options carry descriptions keyed by the same members.

Each one-record function has a corresponding `StreamAsync` method. A one-item stream remains many-record and retains its failed row. Many-record calls accept either `IEnumerable<T>` or `IAsyncEnumerable<T>`. Filter returns kept original records and throws one `FailedException` after yielding every kept record if any failed. Its `Rows` contains failed results with their originals. `FilterOptions.Threshold` takes a `Cut`, and saved filter bands are refused with guidance to `DecideStreamAsync`. Filter and rank are many-record functions and cannot be form entries.

A form is `Row<Annotations<TRecord>,TRecord>`. Scalar annotate promotes only a failed parent; it returns answered parents with one, several or all entries failed. The explicit recursive helper remains available. Read `form.Answer`, then `Decide(name)`, `Choose<T>(name)`, `Tag<T>(name)`, `Score(name)` and the other function selectors. Every entry is an ordinary row. Missing names or a wrong function produce `UsageException`; typed selectors also refuse incompatible enum words. Check each consumed entry before reading its answer.

Questions, `AnnotationQuestions` and `Toolbox` are plain values with no native resource to dispose. `Toolbox.Load(path)` reads a saved file and uses the ordinary .NET file exceptions. Its typed selectors return admitted questions or throw `UsageException`. `Toolbox.Parse` admits bare definitions, and `FromJson` reads saved toolboxes. The reference-only `client.Toolbox(questions)` view remains available.

`TextSpan.Start` and `End`, recognized name offsets and relation endpoint offsets are UTF-16 indexes for slicing .NET strings. Recognized names expose `Kind`, `Text`, `Start`, `End` and `Probability`; `FoundRelation` exposes `Source`, `Target`, `Relation`, `Probability` and `Either`. JSON serialization saves canonical character offsets and omits `Item`, including on detached entries. Admitted identifiers use `StringId`, `SignedId` or `UnsignedId`. A rejected identifier leaves `Id` absent; the original invalid input remains available through `Item`.

Printing a row uses the command's words and separators. Carriage return, newline and tab inside each printed leaf become spaces. Bare answers and saved JSON retain their original text. `JsonSerializer.Serialize(row)` supports native and model-factory rows without reflecting over the original record.

`ThinkThenOptions` supplies backend, endpoint, model, key, batch, `RetryPolicy` and record `JsonSerializerOptions`. The client snapshots these settings. An explicit backend takes precedence over `THINKTHEN_BACKEND`. Credentials have no public value getter and are excluded from diagnostics. `Usage` remains available after disposal. The reference-only `MaxRequests`, execution `name`, `WithMetadataAsync` methods, dependency injection registration, `ThinkThenModelFactory` and `ErrorCode` enum remain supported.

Pass a `CancellationToken` to any call. Leaving an `await foreach` early also closes its call. Disposing a client cancels active work and waits for native owners to finish. Native driver completions run caller continuations asynchronously; custom record conversion runs outside the native driver. `WithMetadataAsync` methods accept `JsonTypeInfo<T>` for trimmed and Native AOT callers without requiring an inverse record converter for rank.
