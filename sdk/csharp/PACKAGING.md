# C# packaging

Ship one `Botassembly.ThinkThen` NuGet package containing `ThinkThen.dll`, the README, the repository license and the matching `thinkthen_ffi` native asset from the same build. Use one SDK-style project with `net10.0`, nullable reference types and warnings as errors. Use the .NET runtime's JSON, interop and async-stream APIs; use the options, dependency injection and logging abstractions referenced by the project. The framework choice follows Microsoft's current [support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core). Earlier frameworks are unsupported. Trimming and Native AOT use explicit record metadata; single-file applications load the packaged native asset beside the executable.

The project accepts Linux x64 glibc at `runtimes/linux-x64/native/libthinkthen_ffi.so`, Linux arm64 glibc at `runtimes/linux-arm64/native/libthinkthen_ffi.so`, macOS arm64 at `runtimes/osx-arm64/native/libthinkthen_ffi.dylib` and Windows x64 at `runtimes/win-x64/native/thinkthen_ffi.dll`. Each package includes the supplied native assets and requires at least one. Installed-package tests must prove each included RID before claiming support. Other RIDs require a built native asset and an installed consumer check before the package lists them. Packaging fails when its required native asset is missing; a managed-only package is not the deliverable.

Register one P/Invoke resolver for the managed assembly. Load only the package's exact supported RID native asset, using an absolute path rooted at `AppContext.BaseDirectory`, including a single-file publish's application directory. Use the known asset filename and directory structure; a basename P/Invoke search is not a fallback. An unsupported RID, including Linux musl, fails with the ordinary .NET loader exception before opening a client. Keep its native handle rooted for process lifetime. Do not search the working directory, arbitrary environment paths or a global native installation. Check the engine ABI requirement before client admission. Client and call SafeHandles may close independently of the process-wide loader.

Pack from the ticket revision using native assets with the same Rust sources, dependency closure, features and release profile. Paired platform preparation builds those assets once. The offline gate consumes them through the build-only `THINKTHEN_CSHARP_NATIVE_ASSETS` directory, with subdirectories named for the supported RIDs. `THINKTHEN_CSHARP_OUTPUT` retains the checked package and installed consumer for a later manual live check. Neither setting exists in the consumer library. Coverage runs substitute an instrumented current-host native build and do not publish that package. Install the resulting nupkg into an empty consumer with an isolated NuGet configuration and no source-tree references. Its tests consume the shared construction cases through the public API, exercise coded admission/backend failures, source failure, early enumeration disposal, cancellation while an asynchronous producer is held, and event-driven cancellation of a held loopback request. Producer checks include an advance that ignores its token: cancellation must release the native operation and return before the producer is released, after which its completion is observed and its enumerator disposed once. Synchronization events establish each state; no sleep establishes readiness. The driver translates shared cases; it contains no stub math or engine expected-output logic. Separate dependency preparation from network-free package checks. The release milestone sets the package's 0.x version. No publication occurs during implementation.
