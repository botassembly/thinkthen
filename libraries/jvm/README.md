# ThinkThen JVM bindings

This Linux x86_64 package builds Java, Kotlin, and Scala JARs from the same source checkout as the separate ThinkThen C library. Maven Central holds the JARs as `io.github.botassembly:thinkthen-jvm:0.1.1`, with Kotlin and Scala classifiers. The C library comes from `thinkthen-c-0.1.1-x86_64-unknown-linux-gnu.tar.gz` on the same GitHub release. `sh libraries/jvm/build.sh` builds `thinkthen-door.jar`, `thinkthen-kotlin.jar`, and `thinkthen-scala.jar` under `target/jars/`.

Run `sh libraries/jvm/check.sh` with JDK 21, Kotlin 2.4.20, Scala 3.9.0, Rust, and an offline Cargo cache. The SDK homes resolve from `javac`, `kotlinc`, and `scalac` on `PATH`, or from `THINKTHEN_JDK_HOME`, `THINKTHEN_KOTLIN_HOME`, and `THINKTHEN_SCALA_HOME`. Each home must contain its compiler and runtime JARs. The check builds the current C library, verifies the header-derived exports, builds the JARs, runs isolated installed-JAR consumers for each language with 60 exact backend arrivals, and drives the shared J1 corpus through each public facade. Generated artifacts and receipts stay under `target/`.

Java 21's Foreign Function and Memory API is a preview. Compile with `javac --enable-preview --release 21` and run with `java --enable-preview --enable-native-access=ALL-UNNAMED -Dthinkthen.library=/absolute/path/to/libthinkthen.so`. Put the door JAR on every classpath; add the Kotlin or Scala JAR and its matching standard library for those languages. Build and install the native shared library separately from the same source revision. These JARs neither fetch nor bundle it.

`Door` owns its native engine. Close it after active callers join. Concurrent `close()` and a call are unsupported. A token is one-shot after it fires, must stay alive through the call, and may be fired from another thread. Java `decide`, `decideMany`, `recognize`, and `relate` return `Door.TypedResult<T>`: the value, and that call's facts object as a `Map`, as `specification/result.schema.json` describes it. `recognize` and `relate` values are maps too. Kotlin and Scala `decide` and their async handles forward that shape. The JVM has no JSON library, so `thinkthen.Json` keeps the smallest reader the door needs: `Json.parse` returns maps in member order, lists, strings, `BigDecimal` numbers, booleans and null, and ignores members it does not know. `Door.field` reads one annotate member as `Unresolved` (JSON null), `Answered` with its value, or `Failed` with its kind and cause. `Door.plan(verb, question, input, settingsJson)` previews a decide, choose, score or tag call through `thinkthen_plan_json` and returns the plan object; it needs no key and sends nothing. Every call that sends has an overload with `deadlineMs` and a token. `max_requests_total` and other engine settings pass through `new Door(settingsJson)`. The door copies owned outputs and borrowed error facts on the native calling thread. Java 21 virtual threads can change carriers between calls; the door pins the carrier across a native call and error copy with `synchronized(Thread.currentThread())`. Many blocked virtual calls can exhaust carrier capacity. C-string arguments reject interior NUL, while counted evidence preserves embedded NUL bytes. JSON calls have a one-MiB result scan limit and refuse longer un-terminated native strings. The public `FailureKind` names the six native error classes. `Door.call` and each facade's `call` retain the full JSON result envelope containing `value` and `facts`.

The installed-consumer proof covers Linux x86_64 only. The release ships a checksummed `thinkthen-jvm-<version>-<target>.tar.gz` beside the matching `thinkthen-c-<version>-<target>.tar.gz`; the JVM archive contains three freshly built JARs, metadata and a fixed input manifest. The bounded installed selector compiles one test consumer per language against those JARs and loads the separately unpacked C library. Other hosts remain separate work.
