# ThinkThen JVM bindings

## Stable owned-session development slice

The `session/` implementation uses the released JDK 22 foreign-function API. It supplies `thinkthen.Engine`, ten named `CompletableFuture` calls, an `AutoCloseable` session, and generated `Results` classes over the shared Rust result graph. The Kotlin classifier supplies `thinkthen.kotlin.KotlinEngine` suspend functions; the Scala classifier supplies `thinkthen.scala.ScalaEngine` Future handles with explicit cancellation. Both use the Java session owner. Java sessions identify their caller as `java`; `KotlinEngine` and `ScalaEngine` identify their callers as `kotlin` and `scala`. The shared owner passes this routing metadata to the native session constructor. Native code validates it without changing the request grammar, answers, or cache identity. A completed call retains its ordered packets and the actual terminal, including failure facts. `Presence` distinguishes missing, null, and a value. Cancelling a future stops native intake and closes that session; manual sessions retain explicit cancellation and drain operations.

Build this bounded development package with `python3 libraries/jvm/build-session.py --out /absolute/empty/output --native /absolute/matching/libthinkthen.so --target x86_64-unknown-linux-gnu`. Set `THINKTHEN_JDK_HOME`, `THINKTHEN_KOTLIN_HOME`, and `THINKTHEN_SCALA_HOME` to the compiler installations. The output includes the three host JARs, the inventory-selected native classifier JAR, and the actual product inventory. Loading uses the packaged resource and a private extraction directory. Consumers need `--enable-native-access=ALL-UNNAMED`; they need no preview flag, library path, Rust compiler, or separate C archive. Kotlin coroutines use `org.jetbrains.kotlinx:kotlinx-coroutines-core-jvm:1.8.0`, the Apache-2.0 dependency bundled with the pinned compiler. Kotlin and Scala retain their normal language runtime libraries.

The builder also writes versioned Maven artifacts under `output/maven/io/github/botassembly/thinkthen-jvm/<version>/`. The Java artifact has no classifier; Kotlin and Scala use `kotlin` and `scala`. The POM declares all five same-version native classifiers from the [package design](../../sdlc/decisions/2026-10-09-native-package-design.md), and the builder checks them against the shared product inventory. Java callers declare `io.github.botassembly:thinkthen-jvm:<version>`; Kotlin and Scala callers add their facade classifier and standard runtime dependencies. Kotlin also needs the coroutine dependency above. Final distribution assembly must supply every native classifier before an ordinary Maven dependency can resolve. A local build contains only the native target supplied to the builder; it does not establish Maven resolution or qualification on the other hosts.

Run `libraries/jvm/tests/session_installed.py --jars /absolute/output/jars --out /absolute/owned/check-output` with those compiler homes. The check compiles consumers against the built JARs, runs them in isolated namespaces with explicit environments, and counts loopback sends. It covers the ten Java functions and each language's held-provider cancellation. This slice proves Linux x86-64. The [package design](../../sdlc/decisions/2026-10-09-native-package-design.md) defines the intended distribution targets.

Add `--maven` to consume the assembled versioned Maven files in that installed check. This checks the supplied local artifacts without running a Maven resolver or contacting a registry.

The old `Door.decideComplete` family maps to the corresponding `Engine.decide` family and its generated session packet classes. The recommended calls accept generated `Inputs.RequestQuestion`, `Inputs.RequestInput`, `Inputs.RequestOptions` and `Inputs.EngineSettings` builders. The shared Request schema supplies question selectors, authored definitions, sources, images, records and controls. Native code supplies defaults and rejects invalid grammar. Setting a member to null preserves explicit null; `omitMember()` removes it. Ordered lists and originals retain their values. Java and Kotlin use their ordinary lists and maps for original JSON data; Scala converts typed list arguments with `asJava`, and the facade converts nested Scala originals and numeric values. Map overloads retain compatibility during the migration. Kotlin and Scala result representations, default build routing, and removal of the old facades remain in the 0.2 migration.

```java
try (var engine = new thinkthen.Engine(new thinkthen.Inputs.EngineSettings())) {
    var call = engine.decide(
        new thinkthen.Inputs.RequestQuestionText().text("Does the writer ask for a refund?"),
        new thinkthen.Inputs.RequestInputText().text("Please refund my order."));
    var complete = call.join();
    // Inspect generated Results packets and terminal facts, or cancel call.
}
``` The existing build and gate below still exercise the older API; this development slice does not certify the completed migration or an ordinary one-dependency Maven install.

This Linux x86_64 package builds Java, Kotlin, and Scala JARs from the same source checkout as the separate ThinkThen C library. Maven Central holds the JARs as `io.github.botassembly:thinkthen-jvm:0.1.2`, with Kotlin and Scala classifiers. The C library comes from `thinkthen-c-0.1.2-x86_64-unknown-linux-gnu.tar.gz` on the same GitHub release. `sh libraries/jvm/build.sh` builds `thinkthen-door.jar`, `thinkthen-kotlin.jar`, and `thinkthen-scala.jar` under `target/jars/`.

Run `sh libraries/jvm/check.sh` with JDK 21, Kotlin 2.4.20, Scala 3.9.0, Rust, and an offline Cargo cache. The SDK homes resolve from `javac`, `kotlinc`, and `scalac` on `PATH`, or from `THINKTHEN_JDK_HOME`, `THINKTHEN_KOTLIN_HOME`, and `THINKTHEN_SCALA_HOME`. Each home must contain its compiler and runtime JARs. The check builds the current C library, verifies the header-derived exports, builds the JARs, runs isolated installed-JAR consumers for each language with 60 exact backend arrivals, and drives the shared J1 corpus through each public facade. Generated artifacts and receipts stay under `target/`.

Java 21's Foreign Function and Memory API is a preview. Compile with `javac --enable-preview --release 21` and run with `java --enable-preview --enable-native-access=ALL-UNNAMED -Dthinkthen.library=/absolute/path/to/libthinkthen.so`. Put the door JAR on every classpath; add the Kotlin or Scala JAR and its matching standard library for those languages. Build and install the native shared library separately from the same source revision. These JARs neither fetch nor bundle it.

`Door` owns its native engine. Close it after active callers join. Concurrent `close()` and a call are unsupported. A token is one-shot after it fires, must stay alive through the call, and may be fired from another thread. Java `decide`, `decideMany`, `recognize`, and `relate` return `Door.TypedResult<T>`: the value, and that call's facts object as a `Map`, as `specification/result.schema.json` describes it. `recognize` and `relate` values are maps too. Kotlin and Scala `decide` and their async handles forward that shape. The JVM has no JSON library, so `thinkthen.Json` keeps the smallest reader the door needs: `Json.parse` returns maps in member order, lists, strings, `BigDecimal` numbers, booleans and null, and ignores members it does not know. `Door.field` reads one annotate member as `Unresolved` (JSON null), `Answered` with its value, or `Failed` with its kind and cause. `Door.plan(verb, question, input, settingsJson)` previews a decide, choose, score or tag call through `thinkthen_plan_json` and returns the plan object; it needs no key and sends nothing. Every call that sends has an overload with `deadlineMs` and a token. `max_requests_total` and other engine settings pass through `new Door(settingsJson)`. The door copies owned outputs and borrowed error facts on the native calling thread. Java 21 virtual threads can change carriers between calls; the door pins the carrier across a native call and error copy with `synchronized(Thread.currentThread())`. Many blocked virtual calls can exhaust carrier capacity. C-string arguments reject interior NUL, while counted evidence preserves embedded NUL bytes. JSON calls have a one-MiB result scan limit and refuse longer un-terminated native strings. The public `FailureKind` names the six native error classes. `Door.call` and each facade's `call` retain the full JSON result envelope containing `value` and `facts`.

The installed-consumer proof covers Linux x86_64 only. The release ships a checksummed `thinkthen-jvm-<version>-<target>.tar.gz` beside the matching `thinkthen-c-<version>-<target>.tar.gz`; the JVM archive contains three freshly built JARs, metadata and a fixed input manifest. The bounded installed selector compiles one test consumer per language against those JARs and loads the separately unpacked C library. Other hosts remain separate work.

Java `new Door(settingsJson)`, Kotlin `Door(settingsJson)` and Scala `new Door(settingsJson)` accepts `{"backend":"local"}` to select the `local` entry in the read-only ThinkThen configuration. Use `{"base_url":"http://localhost:11434/v1"}` for a direct address instead. A named backend supplies its address, model, wire settings and key environment variable; explicit constructor settings take precedence. Omitting `backend` preserves ordinary environment/default selection. A missing or invalid name fails before sending.

Explicit files and folders use the [library reader contract](../files.md), with line, window or whole-file units and located results. Existing text, record and column methods retain their arguments.

`Door` implements `CompleteEngine`: its ten `*Complete` methods use native counted constructors and complete result readers. `KotlinComplete` and `ScalaComplete` expose their own named methods and native surface tokens over that same Java boundary. Results retain typed probabilities, details, author declarations, spans, endpoints, observations, identities and final facts. `QuestionInput.savedQuestion`, `namedQuestion` and `questionReference` use explicit native grammar roles. Known output fields are typed; arbitrary caller originals may remain JSON.

The six `*Batch` methods retain their engine and run all native batch operations on one dedicated creating thread. Close the batch before its engine. `next` returns null at the end; `facts` retains joined final facts and typed failures. Copied rows remain usable after close. `NativeFailure.complete` supplies typed started-failure metadata. File sources include lines/windows/files, images and JSONL. The existing family gate separately compiles and executes Java, Kotlin and Scala consumers for all 247 required shared cases each, including all 24 image-admission recipes, with counted loopback sends and zero-send replay checks. Whole-family review and landing remain with [ticket 0427](../../sdlc/tickets/0427-go-csharp-jvm-typed-parity.md).

Rank-set rows retain every member in saved declaration order. Each member exposes its native positive rank position, probability, answer identity, author declarations and complete details. Details preserve independently reported token dimensions and source batch sizes. Parent and member metadata overlap; read final call facts for invocation usage.
