# ThinkThen JVM bindings

## Stable owned-session package

The `session/` implementation uses the released JDK 22 foreign-function API. It supplies `thinkthen.Engine`, ten named `CompletableFuture` calls, an `AutoCloseable` session, and generated `Results` classes over the shared Rust result graph. The Kotlin classifier supplies `thinkthen.kotlin.KotlinEngine` suspend functions; the Scala classifier supplies `thinkthen.scala.ScalaEngine` Future handles with explicit cancellation. Both use the Java session owner. Java sessions identify their caller as `java`; `KotlinEngine` and `ScalaEngine` identify their callers as `kotlin` and `scala`. The shared owner passes this routing metadata to the native session constructor. Native code validates it without changing the request grammar, answers, or cache identity. A completed call retains its ordered packets and the actual terminal, including failure facts. `Presence` distinguishes missing, null, and a value. Cancelling a future stops native intake and closes that session; manual sessions retain explicit cancellation and drain operations.

Build with `sh libraries/jvm/build.sh --out /absolute/empty/output --native /absolute/matching/libthinkthen.so --target x86_64-unknown-linux-gnu`. The ordinary builder uses the existing stable package assembler. Without arguments it writes `target/session/`, uses the local C debug library and the Rust host target; `THINKTHEN_JVM_OUT`, `THINKTHEN_JVM_NATIVE` and `THINKTHEN_JVM_TARGET` override those defaults. Output must be empty. Both compiler and runtime require JDK 22 or later. An older JDK fails before output creation; it never enables preview features. Set `THINKTHEN_JDK_HOME`, `THINKTHEN_KOTLIN_HOME`, and `THINKTHEN_SCALA_HOME` to the compiler installations. The output includes the three host JARs, the inventory-selected native classifier JAR, and the actual product inventory. Loading uses the packaged resource and a private extraction directory. Consumers need `--enable-native-access=ALL-UNNAMED`; they need no preview flag, library path, Rust compiler, or separate C archive. Kotlin coroutines use `org.jetbrains.kotlinx:kotlinx-coroutines-core-jvm:1.8.0`, the Apache-2.0 dependency bundled with the pinned compiler. Kotlin and Scala retain their normal language runtime libraries.

The builder also writes versioned Maven artifacts under `output/maven/io/github/botassembly/thinkthen-jvm/<version>/`. The Java artifact has no classifier; Kotlin and Scala use `kotlin` and `scala`. The POM declares all five same-version native classifiers from the [package design](../../sdlc/decisions/2026-10-09-native-package-design.md), and the builder checks them against the shared product inventory. Java callers declare `io.github.botassembly:thinkthen-jvm:<version>`; Kotlin and Scala callers select the `kotlin` or `scala` classifier on that one SDK dependency and retain their standard runtime dependencies. Each facade classifier includes the shared compiled Java classes and product inventory, so it needs no separate Java SDK dependency. Kotlin also needs the coroutine dependency above. Final distribution assembly must supply every native classifier before an ordinary Maven dependency can resolve. A local build contains only the native target supplied to the builder; it does not establish Maven resolution or qualification on the other hosts.

Run `libraries/jvm/tests/session_installed.py --jars /absolute/output/jars --out /absolute/owned/check-output` with those compiler homes. The check compiles consumers against the built JARs, runs them in isolated namespaces with explicit environments, and counts loopback sends. It covers the ten Java functions and each language's held-provider cancellation. This slice proves Linux x86-64. The [package design](../../sdlc/decisions/2026-10-09-native-package-design.md) defines the intended distribution targets.

Add `--maven` to consume the assembled versioned Maven files in that installed check. This checks the supplied local artifacts without running a Maven resolver or contacting a registry.

The ten functions share one typed API in each language. The recommended calls accept generated `Inputs.RequestQuestion`, `Inputs.RequestInput`, `Inputs.RequestOptions` and `Inputs.EngineSettings` builders. The shared Request schema supplies question selectors, authored definitions, sources, images, records and controls. Native code supplies defaults and rejects invalid grammar. Setting a member to null preserves explicit null; `omitMember()` removes it. Ordered lists and originals retain their values. Java and Kotlin use their ordinary lists and maps for original JSON data; Scala converts typed list arguments with `asJava`, for every nested original value. Kotlin and Scala return their own call results with native collections and nullable or optional scalar answers. Calls and engine settings accept only generated input carriers; arbitrary original JSON still accepts ordinary language values.

```java
try (var engine = new thinkthen.Engine(new thinkthen.Inputs.EngineSettings())) {
    var call = engine.decide(
        new thinkthen.Inputs.RequestQuestionText().text("Does the writer ask for a refund?"),
        new thinkthen.Inputs.RequestInputText().text("Please refund my order."));
    var answer = call.join().decide();
}
```

The shipped `examples/` sources call all ten functions with typed questions and read one answer from each completed call. Java shares the question builders; Kotlin uses suspend functions and Scala waits for Future handles. Relation examples read `sourceName()` and `targetName()` directly. The installed routine check compiles and replays these exact sources.

Run `sh libraries/jvm/check.sh` for the focused stable installed consumers. It builds the package through the ordinary builder and checks all three languages with counted loopback requests. `THINKTHEN_JVM_NATIVE` supplies an existing matching native library; otherwise the check builds the C library offline. `THINKTHEN_ARTIFACT` selects an already built stable archive. `THINKTHEN_TEST_PROFILE=full` additionally runs every required shared case through the installed named Java, Kotlin and Scala calls; `THINKTHEN_PORTABLE_BATCH=1` also selects them. This full campaign belongs to the release suite. For a focused development check, run `python3 libraries/jvm/tests/public_types.py --jars /absolute/built/jars --out /absolute/scratch --case CASE_ID`; selectors name existing shared cases and report only that subset. Final platform and distribution qualification remain required.

Kotlin suspend functions and Scala Future handles return their own `OwnedCall` wrappers. Their answer methods return Kotlin lists and nullable answers or Scala lists and `Option` answers. Detailed `Results` getters and `Presence` retain omission, explicit null and values. Rank returns original zero-based indexes; filter returns original inputs, including explicit JSON null. `Questions` builds small authored questions and ordered description options. Native packet and error views are copied into independent values before their owners are freed. Both facades offer `plan`, `execute`, caller-owned sessions and explicit cancellation.

Java, Kotlin and Scala provide `startSession(Inputs.Request)` for caller-owned feeds. One executor per engine handles blocking native work and remains alive until its last owned session closes. `push` waits for native input room on a platform worker. `nextPacket` blocks for one owned packet; `nextPacket(true)` drains final facts after cancellation. `tryRead` separates a pending read from explicit end. `waitReady` observes readiness without consuming a packet, using bounded native waits on the same worker until readiness or cancellation. Scala feed execution accepts an ordinary Scala iterable. `finish` closes intake or records a typed reader failure. `close` cancels and releases the owner after outstanding native calls return. `execute(request, feed)` transfers descriptors while the reader drains packets.

Use typed input builders. They preserve omission, explicit null and arbitrary authored values; native admission validates the question grammar. Java `BigInteger` and `BigDecimal` retain their exact values.

Each ordinary engine exposes `usagePersistence()` and `finishUsageStatus()`. Both return an immutable `UsagePersistence` with a native state and optional copied safe advice. Java uses a nullable `String`, Kotlin uses `String?`, and Scala uses `Option[String]`. The observation describes this engine’s current deltas. `finishUsageStatus()` waits for the writer; only usage-lock acquisition has a deadline, and other filesystem work can take longer. Persistence failure leaves valid answers and in-memory call facts intact. Retained observations remain readable after engine cleanup. Both methods reject a closed engine. The state meanings and native advice ownership follow the [C header](../c/include/thinkthen.h).
