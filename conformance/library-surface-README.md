The host surface contract comes from the Rust-derived request and result schemas. `library-surface.json` records native naming, declaration containers, lifecycle and error categories, helper choices and the Python dataframe and pydantic exception. It does not keep a second function, option or settings inventory. MCP remains outside this host helper contract.

Run `python3 conformance/library-surface.py --library python` for one host, or omit `--library` for every host. Repeat the option for several hosts. `--json` returns deterministic findings; exit 0 means no discrepancy, 1 means a missing or unlisted surface, and 2 means invalid invocation or unreadable input. The command reads source declarations and exports. It does not install packages or establish runtime or platform parity.

Request controls and engine settings must be declared in their native containers. Generic keyword arguments, index signatures, comments and names elsewhere cannot satisfy a missing member. Generated declarations are compared with the existing renderers over the authoritative schemas. Native C, Ada and COBOL declarations use their existing source or compiler declaration generators; no host package is built. Kotlin and Scala declarations belong to the JVM family. Dart follows the actual export and part declarations, including `show` restrictions.

C keeps the approved shared native layer: its typed session constructor dispatches the canonical functions, and generated selector, item and source records supply its builders. Zig checks the public engine, authored and session modules alongside every registered generated declaration, including calls and native result readers. Its private native and blocking implementation modules do not add exports. The finite wrapper entries name ownership fields, cleanup methods, failure accessors and module aliases from those public declarations. TypeScript's image and item fields derive from the request schema; its recognition and relation builders and Ruby's frozen result and error accessors remain explicit native adapters.

Run `python3 conformance/library-surface-test.py` for the focused contract fixtures. The CLI fixture proves missing controls, missing settings, missing helpers, missing generated result members and extra exports refuse. The declaration syntax table covers each host form and excludes private fields.

Ruby source declarations use the standard Ripper lexer through `RUBY` when set, otherwise `ruby` on `PATH`. The child receives an isolated environment and never evaluates the source or loads the native library. A missing Ruby executable refuses with exit 2; a lexer failure reports a declaration error. No gem or parser package is required.

The checker is a source contract check. Language owners must settle reported naming and representation differences and finish missing surfaces before a coordinator connects it to a global gate. Adding a schema field automatically adds a requirement. A new native alias belongs in the native adapter, while shared semantic logic and generated declaration changes belong to Rust and the generator.
